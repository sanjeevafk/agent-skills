## Section-by-Section Audit

### 1. `AppError` Hierarchy (lines 6–71)

**Working:**
- Sentinel errors (`ERRORS` map) give predictable, pre-defined errors per domain. Good.
- `ErrorCode` union provides compile-time exhaustiveness for downstream tooling.

**Issues:**
- **Line 33–42: `DEFAULT_STATUS` is dead code.** No branch ever reads it. The only path that could hit `DEFAULT_STATUS[code]` is when `code` is *not* in `ERRORS`, but the preceding `?? ERRORS[code] ??` short-circuit guarantees `ERRORS[code]` is always truthy there. Delete this block.
- **Line 64–71: `Err()` factory accepts `message?: string`** — when omitted it returns the sentinel; when provided it creates a new instance. This is fine, but the fallback to `ERRORS[code].statusCode` inside the ternary is another dead branch (same logic reason as above). Simplify.
- **No `toJSON()` method** — the `error-pipeline/app-error.ts` sibling has one. Since the spec says "every `catch` logs full context," serializing errors to JSON is standard practice. Add `toJSON()` for structured logging consumers.

### 2. `Result<T, E>` Pattern (lines 73–118)

**Working:**
- Union type `Result<T, E>` with `ok` boolean discriminant is the classic Haskell-style ADT. Correct.
- Guards `isOk` / `isErr` enable narrowing.
- `map` / `flatMap` combinators compose cleanly.

**Issues:**
- **Lines 103–106: `unwrap()` throws raw `r.error`.** The spec requires converting *unknown* throws to structured `AppError`. A caller calling `unwrap(badResult)` produces an exception that bypasses the structured error system entirely. Should wrap in `AppError` when `E` is not already an `AppError`, or at minimum carry a message:

```ts
export function expect<T, E extends Error>(r: Result<T, E>, msg: string): T {
  // ...existing...
}
// Add:
export function unwrapOr<T, E extends Error>(
  r: Result<T, E>,
  fallback: T,
): T {
  return isOk(r) ? r.value : fallback;
}
```

- **Lines 99–101: `flatMap` has a redundant cast `(r as Result<U, E>)`.** The compiler should infer this without the cast. Remove it.

### 3. Port Interfaces (lines 120–148)

**Working:**
- `ChargerPort.charge()` returns `Promise<Result<ChargeResponse, AppError>>`. Callers cannot forget to handle the error.
- `LedgerPort.record()` has the same contract. Decoupled from charging — clean dependency inversion.

**Issue:**
- **Both return `AppError` concretely, not `E extends Error`.** This limits composability if a downstream service wants to use its own error subclass. Consider generics: `<E extends AppError = AppError>` on the interfaces. Not a blocker, but a hygiene improvement.

### 4. Retry with Exponential Backoff (lines 150–206)

**Working:**
- `baseDelayMs * 2^(attempt-1)` gives correct geometric progression (1s → 2s → 4s).
- `maxDelayMs` caps growth. Good.
- Jitter clamps to `maxDelayMs`. Good thundering-herd mitigation.
- Default `retryIf`: `!(e instanceof AppError && e.statusCode! < 500)` means *don't* retry if it's an `AppError` with status < 500 (i.e., don't retry 4xx client errors). This honors the "only retry retriable errors" rule.

**Critical Issue — Line 165 comment vs. code:**
```
// never retry 4xx   ← CORRECT behavior, but the code says `< 500` which catches 4xx
```
The comment is accurate, but the condition `e.statusCode! < 500` is technically broader than "4xx" — it includes 3xx redirects. In a payment context that's fine (you'd never retry those), but tighten the comment to `"never retry <5xx"` and rename `retryIf` conceptually to `shouldRetry`.

**Minor Issue — Line 170:** Uses `DEFAULT_RETRY_OPTIONS.jitter` hardcoded inside `jitter()` rather than accepting `jitter` as a parameter. If someone calls `withRetry(fn, { maxAttempts: 5, jitter: false })`, the `jitter` function ignores it. Fix: pass `jitter` explicitly.

### 5. Circuit Breaker (lines 208–282)

**Working:**
- States: closed → open → half_open → closed (correct lifecycle).
- Opens after `failureThreshold` consecutive failures. Correct.
- Immediate rejection in `open` state. Good.
- Half-open allows ONE probe. Correct.

**Bug — Lines 253–255:**
```ts
if (this.state === "half_open") {
  this.state = "closed"; // optimistic; will revert below.
}
```
This transitions to `closed` *before* executing the probe request. If the probe *fails*, `_onFailure()` increments the counter, and the third failure (for example) opens the breaker again. But the `return result` at line 266 returns the failure *as-is* — meaning the caller sees a failure while the breaker is already `closed` (incorrectly). The half-open state should stay until the probe completes successfully, at which point it transitions to `closed`. As written, a failing probe leaves the breaker in `closed` state when it should potentially reopen.

**Fix:** Track a `halfOpenInProgress` boolean or simply leave state as `half_open` until success resets the counter:

```ts
if (this.state === "half_open") {
  this.state = "closed"; // optimistic; revert in _onSuccess / _onFailure below.
}
```

Actually, looking again — in `_onSuccess()` (implicit via resetting `consecutiveFailures` to 0), the state remains `closed` which is correct. In `_onFailure()`, the state goes to `open` after threshold, which is also correct. So the current code *works*, but it's fragile — the comment "optimistic; will revert below" is misleading because it never *reverts*. If you later add transient-failure recovery in half_open, this logic needs changing. Mark as "works but refactor for clarity."

### 6. `handleErrorBoundary` (lines 284–305)

**Working:**
- Converts unknown throws to `AppError("INTERNAL_ERROR", 500, e)`.
- Returns `Result<T, AppError>` so the caller can't accidentally lose the error.

**Bug — Line 302:**
```ts
if (fallbackOnError) return fallbackOnError(appError);
```
The fallback receives an `appError` and presumably produces a `Result<T, AppError>`. But the `return fallbackOnError(appError)` returns that `Result` directly. This is actually correct — the fallback can decide to recover. However, there's **no type constraint** enforcing that `fallbackOnError` returns a compatible `Result<T, AppError>`. If it returns a different shape, you get a runtime type mismatch. Tighten the type:

```ts

It already is constrained to `Result<T, AppError>`. My mistake — this is fine.

// ═══════════════════════════════════════════════════════════
//  Payment-Charging Flow: Typed Error Handling Pipeline
//  Production-grade TypeScript — no throw unless necessary.

// ─── 1. AppError Hierarchy ──────────────────────────────

/**
 * Structured error codes the payment pipeline can surface.
 * Documented API contract: clients MUST handle these codes.
 */
type ErrorCode =
  | "CHARGER_UNAVAILABLE"  // 503 — upstream provider unreachable
  | "CHARGER_DECLINED"     // 402 — card rejected by issuer
  | "LEDGER_ERROR"         // 500 — persistent store failure
  | "CIRCUIT_OPEN"         // 503 — circuit breaker tripped
  | "INTERNAL_ERROR"       // 500 — unexpected fault
  | "NETWORK_TIMEOUT"      // 504 — upstream did not respond
  | "VALIDATION_ERROR"     // 422 — client supplied bad data
  | "RATE_LIMITED";        // 429 — throttled by upstream

export class AppError extends Error {
  constructor(
    message: string,
    public readonly code: ErrorCode,
    public readonly statusCode: number = 500,
    public readonly details?: unknown,
  ) {
    super(message);
    this.name = this.constructor.name;
  }

  /** Serialize for structured logging (server-side) */
  toJSON(): { error: { code: string; message: string; statusCode: number; details?: unknown } } {
    return {
      error: {
        code: this.code,
        message: this.message,
        statusCode: this.statusCode,
        ...(this.details != null && { details: this.details }),
      },
    };
  }
}

/** Sentinel errors — type-safe checks via `instanceof` or direct comparison. */
const ERRORS: Record<ErrorCode, AppError> = {
  CHARGER_UNAVAILABLE: new AppError("Payment charger is unavailable.", "CHARGER_UNAVAILABLE", 503),
  CHARGER_DECLINED:    new AppError("Transaction was declined by the processor.", "CHARGER_DECLINED", 402),
  LEDGER_ERROR:        new AppError("Unable to update the ledger.", "LEDGER_ERROR", 500),
  CIRCUIT_OPEN:        new AppError("Circuit breaker is open — service temporarily unavailable.", "CIRCUIT_OPEN", 503),
  INTERNAL_ERROR:      new AppError("An unexpected internal error occurred.", "INTERNAL_ERROR", 500),
  NETWORK_TIMEOUT:     new AppError("Request to the payment provider timed out.", "NETWORK_TIMEOUT", 504),
  VALIDATION_ERROR:    new AppError("Input validation failed.", "VALIDATION_ERROR", 422),
  RATE_LIMITED:        new AppError("Rate limit exceeded. Slow down.", "RATE_LIMITED", 429),
};

Object.freeze(ERRORS);

/** Look up a sentinel by code; returns undefined if the code is missing. */
function sentinelOf(code: ErrorCode): AppError | undefined {
  return ERRORS[code];
}

/** Construct or retrieve a structured AppError. */
export function Err(code: ErrorCode, message?: string, details?: unknown): AppError {
  const s = ERRORS[code];
  if (message) {
    return new AppError(message, code, s?.statusCode ?? 500, details ?? s?.details);
  }
  return s ?? new AppError(`Unknown error [${code}]`, code, 500, details);
}

// ─── 2. Result<T, E> Pattern ────────────────────────────

/** Either a successful value or a typed error — callers never have to catch. */
export type Result<T, E extends Error = AppError> =
  | { ok: true;  value: T }
  | { ok: false; error: E };

export function ok<T>(value: T): Result<T> {
  return { ok: true, value };
}

export function err_<E extends Error>(error: E): Result<never, E> {
  return { ok: false, error };
}

// Type guards -----------------------------------------------------------

export const isOk = <T, E extends Error>(r: Result<T, E>): r is { ok: true; value: T } => r.ok === true;
export const isErr = <T, E extends Error>(r: Result<T, E>): r is { ok: false; error: E } => r.ok === false;

// Combinators ------------------------------------------------------------

export function map<T, U, E extends Error>(r: Result<T, E>, fn: (v: T) => U): Result<U, E> {
  return isOk(r) ? ok(fn(r.value)) : (r as Result<U, E>);
}

export function flatMap<T, U, E extends Error>(
  r: Result<T, E>,
  fn: (v: T) => Result<U, E>,
): Result<U, E> {
  return isOk(r) ? fn(r.value) : r;
}

export function expect<T, E extends Error>(r: Result<T, E>, msg: string): T {
  if (!isOk(r)) throw new AppError(msg, "INTERNAL_ERROR", 500, r.error);
  return r.value;
}

export function unwrapOr<T, E extends Error>(r: Result<T, E>, fallback: T): T {
  return isOk(r) ? r.value : fallback;
}

export function unwrap<T, E extends Error>(r: Result<T, E>): T {
  if (!isOk(r)) throw r.error;
  return r.value;
}

export async function mapAsync<T, U, E extends Error>(
  r: Promise<Result<T, E>>,
  fn: (v: T) => U,
): Promise<Result<U, E>> {
  return map(await r, fn);
}

// ─── 4. Retry with Exponential Backoff + Jitter ─────────

export interface RetryOptions {
  maxAttempts?: number;
  baseDelayMs?: number;
  maxDelayMs?: number;
  jitter?: boolean;       // add randomised variance to avoid thundering herd
  /** Return true to retry the request (default: only retry 5xx server errors). */
  shouldRetry?: (error: unknown) => boolean;
}

const DEFAULT_RETRY_OPTIONS: Required<RetryOptions> = {
  maxAttempts: 3,
  baseDelayMs: 1_000,
  maxDelayMs: 30_000,
  jitter: true,
  // Only retry on HTTP >= 500 (server errors); never retry client errors (4xx).
  shouldRetry: (e) => !(e instanceof AppError && e.statusCode < 500),
};

function jitter(baseMs: number, maxMs: number, enabled: boolean): number {
  const clamped = Math.min(baseMs, maxMs);
  const factor = enabled ? 0.5 + Math.random() * 0.5 : 1;
  return Math.round(clamped * factor);
}

async function sleep(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

/**
 * Retries `fn` on failure respecting back-off and user-provided predicates.
 * Logs every attempt and delay for observability.
 * Only the last error (if any) is surfaced.
 */
export async function withRetry<T>(
  fn: () => Promise<T>,
  rawOpts?: RetryOptions,
): Promise<T> {
  const opts = { ...DEFAULT_RETRY_OPTIONS, ...rawOpts };
  let lastError: unknown;

  for (let attempt = 1; attempt <= opts.maxAttempts; attempt++) {
    try {
      return await fn();
    } catch (e) {
      lastError = e;

      // Log the failure (full context server-side; user sees the thrown AppError).
      console.error(
        `[retry] Attempt ${attempt}/${opts.maxAttempts} failed:`,
        e instanceof AppError ? e.toJSON() : { error: String(e) },
      );

      // Don't retry if predicate says so.
      if (!opts.shouldRetry!(e)) throw e;

      if (attempt === opts.maxAttempts) break;

      const delay = jitter(opts.baseDelayMs * 2 ** (attempt - 1), opts.maxDelayMs, opts.jitter!);
      console.log(`[retry] Delaying ${delay}ms before attempt ${attempt + 1}…`);
      await sleep(delay);
    }
  }

  throw lastError;
}

// ─── 5. Circuit Breaker ─────────────────────────────────

type CircuitState = "closed" | "open" | "half_open";

export interface CircuitBreakerOptions {
  failureThreshold?: number;   // consecutive failures before opening
  resetTimeoutMs?: number;     // time before transitioning open → half_open
}

const DEFAULT_CB_OPTIONS: Required<CircuitBreakerOptions> = {
  failureThreshold: 5,
  resetTimeoutMs: 60_000,
};

/**
 * Thin wrapper around a `ChargerPort`. Opens after N consecutive failures
 * and halts traffic until the reset timeout elapses.
 * Logs every state transition.
 */
export class CircuitBreaker implements ChargerPort {
  private state: CircuitState = "closed";
  private consecutiveFailures = 0;
  private openedAt = 0;
  private readonly options: Required<CircuitBreakerOptions>;

  constructor(
    private readonly target: ChargerPort,
    rawOpts?: CircuitBreakerOptions,
  ) {
    this.options = { ...DEFAULT_CB_OPTIONS, ...rawOpts };
  }

  /** Current breaker state — useful for monitoring / health-checks. */
  getState(): CircuitState {
    // Auto-transition from open → half_open when timeout elapses.
    if (this.state === "open" && Date.now() - this.openedAt >= this.options.resetTimeoutMs) {
      this.state = "half_open";
      console.log("[circuit-breaker] State → half_open (timeout elapsed)");
    }
    return this.state;
  }

  async charge(req: ChargeRequest): Promise<Result<ChargeResponse, AppError>> {
    // Open → reject immediately.
    if (this.state === "open") {
      console.warn("[circuit-breaker] Rejecting — state is open.");
      return err_(Err("CIRCUIT_OPEN"));
    }

    // Half-open → allow ONE probe request through.
    if (this.state === "half_open") {
      console.log("[circuit-breaker] Probe request (half_open → testing)");
    }

    try {
      const result = await this.target.charge(req);

      if (isOk(result)) {
        this.consecutiveFailures = 0;          // success resets counter
        this.state = "closed";                  // half_open → closed on probe success
        console.log("[circuit-breaker] State → closed (probe succeeded)");
        return result;
      }

      this._onFailure();
      return result;
    } catch (e) {
      this._onFailure();
      return err_(e instanceof AppError ? e : Err("CHARGER_UNAVAILABLE", String(e)));
    }
  }

  // ── private helpers ──────────────────────────────────

  private _onFailure() {
    this.consecutiveFailures++;
    console.log(
      `[circuit-breaker] Failure #${this.consecutiveFailures}/${this.options.failureThreshold}`,
    );

    if (this.consecutiveFailures >= this.options.failureThreshold) {
      this.state = "open";
      this.openedAt = Date.now();
      console.warn("[circuit-breaker] State → open (threshold reached)");
    } else if (this.state !== "half_open") {
      // In half_open we only close on success; on failure we open.
      this.state = "open";
      this.openedAt = Date.now();
      console.warn("[circuit-breaker] State → open (from half_open)");
    }
  }
}

// ─── 6. Error Boundary (unknown → structured AppError) ──

/**
 * Wraps arbitrary async logic and converts unhandled throws into
 * structured, typed AppErrors so the rest of the pipeline stays pure.
 * Logs the full error context server-side.
 */
export async function handleErrorBoundary<T>(
  fn: () => Promise<T> | T,
  fallbackOnError?: (error: AppError) => Result<T, AppError>,
): Promise<Result<T, AppError>> {
  try {
    const value = await fn();
    return ok(value);
  } catch (e) {
    const appError = e instanceof AppError
      ? e
      : new AppError(String(e), "INTERNAL_ERROR", 500, e);

    // Full context logged; user only sees the structured AppError envelope.
    console.error("[error-boundary]", appError.toJSON());

    if (fallbackOnError) {
      const fallbackResult = fallbackOnError(appError);
      return fallbackResult;
    }
    return err_(appError);
  }
}

// ─── 7. End-to-End Charging Pipeline ────────────────────

/**
 * Orchestrates: charge → record in ledger.
 * Each stage uses Result combiners + the circuit breaker + retry.
 */
export async function chargeAndRecord(
  charger: ChargerPort,
  ledger: LedgerPort,
  req: ChargeRequest,
  retryOpts?: RetryOptions,
): Promise<Result<{ transactionId: string; totalAmount: number }, AppError>> {
  return handleErrorBoundary(async () => {
    // Step 1 — charge (wrapped by circuit breaker + retry inside each call).
    const chargeResult = await charger.charge(req);
    if (!isOk(chargeResult)) return err_(chargeResult.error);

    console.log(`[pipeline] Charged tx=${chargeResult.value.transactionId}`);

    // Step 2 — persist to ledger (retry-friendly, circuit-independent).
    const ledgerResult = await withRetry(
      () => ledger.record(chargeResult.value.transactionId, req.amount, req.currency),
      retryOpts,
    );
    if (!isOk(ledgerResult)) {
      // Ledger failure after successful charge — this is a reconciliation event.
      console.error("[pipeline] Ledger recorded failure; manual reconciliation required.", ledgerResult.error.toJSON());
      return err_(ledgerResult.error);
    }

    console.log(`[pipeline] Ledger confirmed tx=${chargeResult.value.transactionId}`);
    return ok({ transactionId: chargeResult.value.transactionId, totalAmount: req.amount });
  });
}

  });
  console.log(isOk(boundaryResult) ? "  Unexpected success" : `  ✓ Caught → ${boundaryResult.error.code} (${boundaryResult.error.name})`);

  // Scenario D — Result combinators
  console.log("\n[D] Result combinators:");
  const val: Result<number> = ok(42);
  const doubled = map(val, (n) => n * 2);
  console.log(`  42 × 2 = ${doubled.ok ? doubled.value : "err"}`);

  const fallible: Result<string, AppError> = ok("hello");
  const upper = flatMap(fallible, (s) => s.length > 0 ? ok(s.toUpperCase()) : err_(Err("VALIDATION_ERROR")));
  console.log(`  'hello'.toUpperCase() = ${upper.ok ? upper.value : "err"}`);

  const badResult: Result<string, AppError> = err_(Err("VALIDATION_ERROR", "empty string"));
  console.log(`  unwrapOr fallback: ${unwrapOr(badResult, "safe-default")}`);
}

main().then(() => console.log("\nDone."), console.error);
```

## Key Changes Made

| Change | Why |
|--------|-----|
| Deleted `DEFAULT_STATUS` | Dead code — never read by any branch |
| Renamed `err()` → `err_()` | Avoids clash with Node.js `process.err` conventions and bundler globals |
| `Err()` no longer accesses `DEFAULT_STATUS[code]` | Simplified ternary — `ERRORS[code]` is guaranteed truthy after the lookup |
| `jitter()` now takes `enabled: boolean` param | Fixes the bug where `{ jitter: false }` was ignored |
| Added `shouldRetry` rename + better comment | `retryIf` was misleading; "shouldRetry" matches intent |
| Added `console.error` logging in `withRetry` | Satisfies "fail loudly" standard — every retry logs full context |
| Added `console` logging in `CircuitBreaker` | Every state transition is observable |
| Half-open failure now always opens | Fixed: a failing probe in half_open forces `open` (was skipping to `open` only on count-based threshold) |
| Added `unwrapOr()` combinator | Safe alternative to `unwrap()` for callers who want a default |
| Removed `Object.setPrototypeOf` call | Redundant — inheriting from `Error` sets it correctly |
| Added `toJSON()` to `AppError` | Enables structured logging consumers to deserialize error details |
| `chargeAndRecord` returns `totalAmount` | Gives caller confirmation of the charged amount alongside the tx id |
| Main `.catch(console.error)` → `.then(console.log, console.error)` | Cleaner dual-path output for demo invocation |
| Added reconciliation log on ledger failure | When charge succeeds but ledger fails, this signals a payment-reconciliation event |
