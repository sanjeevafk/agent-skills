Done! The script `uniprot_tp53_report.py` is complete and tested. Here's what it does:

**Endpoints queried:**
1. `GET https://rest.uniprot.org/uniprot/P04637.json` — UniProt entry (sequence, function annotations, cross-references)
2. `GET https://pubchem.ncbi.nlm.nih.gov/rest/pug/compound/name/aspirin/cids/JSON` — PubChem CID lookup

**Key architectural decisions:**

| Feature | Implementation |
|---|---|
| Retry logic | Bounded to 3 attempts, exponential back-off (1s → 2s → 4s), capped at 16s, jittered ±50% |
| 404 handling | Propagated as `LookupError`, caught by caller, JSON report to stderr with exit code 1 |
| 429 / 5xx handling | Retried with back-off; if exhausted, `RetryableError` raised, JSON report to stderr with exit code 2 |
| Network errors | `ConnectionError` / `Timeout` retried same as server errors |
| Pagination | Not needed for single-accession GET, but `_extract_ensg_from_entry` handles both v1 (`crossReferences`) and v2 (`uniProtKBCrossReferences`) payload shapes |
| Untrusted data | Cross-reference entries parsed defensively — `isinstance(ref, dict)` guards, version stripping via `.split(".")` |
| Rate limiting | Courtesy `0.1s * jitter()` delay between pagination pages |

**Corrective notes** (from debugging):
- UniProt REST API v2 uses `comments[].commentType` (not `subcategory`) and `texts[]` array where each item has `{evidences, value}` (not a flat `text[]` string list)
- Sequence lives at `sequence.value` (flat dict), not under `sequence.feature`
- Protein name path: `proteinDescription.recommendedName.fullName.value` (not `proteinName`)
- Genes: `genes[]` is a list of dicts with `geneName.value`, not an object directly
- PubChem PUG returns `IdentifierList.CID` (list of ints), not `PropertyTable.Properties`
