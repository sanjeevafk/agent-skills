## Subscription Billing FSM — Complete Analysis

### State Machine (`billing/state_machine.py`)

**Core types:**

| Type | Purpose |
|------|---------|
| `Status(Enum)` | Five states: DRAFT → PENDING → ACTIVE → PAST_DUE → CANCELED |
| `Event(frozen dataclass)` | Immutable domain event recording a single transition |
| `TransitionError(Exception)` | Raised when an event cannot advance the FSM |

**Valid transitions (defined via `_TRANSITIONS` lookup table):**

```
DRAFT ──payment_info_collected──► PENDING
PENDING ──activate──────────────► ACTIVE
PENDING ──cancel────────────────► CANCELED
ACTIVE  ──payment_failure───────► PAST_DUE
ACTIVE  ──cancel────────────────► CANCELED
PAST_DUE──restore───────────────► ACTIVE
PAST_DUE──cancel────────────────► CANCELED
```

**Key design decisions:**

1. **Thread-safe**: Every public method wraps in `threading.Lock` — `apply_event`, `trigger_timeout`, and all property getters. The concurrent tests (Slice 5) verify exactly this: 10 threads racing on the same state machine, only 1 succeeds, rest get `TransitionError`, and no corruption occurs.

2. **Timeout handling**: `pending_timeout` defaults to 3600s (1 hour). `trigger_timeout()` checks `time.monotonic()` elapsed time against the configured window. It auto-transitions PENDING → ACTIVE and logs a `timeout_activate` event. Rejects if called from any other status or before timeout elapses.

3. **Immutable events**: `Event` uses `frozen=True` dataclass so the event log can never be modified after recording.

4. **Clean properties**: `current_status`, `last_event`, `event_log` are read-only property accessors that lock before returning — callers never interact with internal mutable state.
