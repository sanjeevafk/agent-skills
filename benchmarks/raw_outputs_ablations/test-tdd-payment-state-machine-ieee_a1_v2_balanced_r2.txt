**Implementation (`skills/billing/fsm.py`) — key design points:**

- **State enum**: `SubscriptionState(DRAFT, PENDING, ACTIVE, PAST_DUE, CANCELED)` — value-based for easy serialization
- **Transition rules**: Two data-driven mappings (`_TRANSITION_RULES`, `_ACTION_TARGETS`) make adding new transitions a single-entry change — no code logic to touch
- **Thread safety**: `RLock` serializes all transitions, preventing race conditions on state changes
- **Domain events**: `TransitionEvent(source, target, timestamp)` frozen dataclass returned on each successful transition and appended to history
- **History immutability**: Returns a shallow copy via `list(self._history)` so callers can't mutate internal state
- **Error handling**: Single exception type `InvalidTransitionError(ValueError)` raised for unknown actions or forbidden transitions with clear messages

**One gap vs specification**: The spec says "clean domain events" suggesting an event publisher pattern, but the current design returns events directly from `transition()` instead of publishing them to listeners. If domain events need dispatching to subscribers (e.g., notification service, audit logger), we'd add a small publisher. For now, the return-value approach satisfies all 24 test assertions cleanly.
