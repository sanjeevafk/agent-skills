## Complete Solution

### Dockerfile (`Dockerfile`)

**Stage 0 — Base**: Alpine + pinned Node.js 22 + tini for signal forwarding + ca-certificates for TLS. Sets up the JSON shell (`set -eo pipefail`). No `NODE_ENV` yet — that belongs per-stage.

**Stage 1 — Dependencies**: `COPY package.json package-lock.json ./` then `RUN --mount=type=cache,target=/app/node_modules ... npm ci`. The BuildKit cache mount means `node_modules` persists across builds *without* being copied into the image layers — a massive CI speed win. Re-runs only when `package.json` or `package-lock.json` change.

**Stage 2 — Builder**: Copies entire source, runs `NEXT_PRIVATE_STANDALONE=true npm run build`, prunes dev deps with `npm prune --omit=dev --production-only`, verifies `out/standalone/server.js` exists, strips `.next/cache`, fallback chunks, types, prerender manifest, and unused locale files (~2–4 MB).

**Stage 3 — Runner**: Creates `app` user/group with UID/GID 10001, copies standalone output + public assets + optional Prisma schema, sets `NODE_ENV=production PORT=3000`, healthcheck via wget, tini as PID-1 init process, `CMD ["node", "server.js"]`.

### docker-compose.yml (Production Stack)

The stack uses two-network segmentation (`frontend-net` ↔ `backend-net`) where `db` and `redis` are backend-only. Named volumes (`pgdata`, `redisdata`) survive container teardown. Healthchecks guard against traffic routing to unhealthy services. Resource limits cap each service; `no-new-privileges` prevents privilege escalation. `read_only: true` with targeted `tmpfs` mounts (`/tmp`, `/run`) gives write access only where needed.

### docker-compose.override.yml (Dev Only)

Auto-loaded on plain `docker compose up`. Swaps stage to `builder`, bind-mounts source for hot-reload, exposes debugger port 9229, disables healthcheck, relaxes security (source mounts need write access), unbinds DB/Redis to localhost for local clients.

### docker-compose.prod.yml (Prod Overlay)

Tightens resource caps (app: 384M, db: 256M, redis: 128M), shrinks tmpfs to 32M (no hot-reload daemon), rotates logs more aggressively. Port exposure commented out — production traffic flows through ingress/reverse proxy.

### .dockerignore

Excludes node_modules, .git, env files, dist/build artifacts, docs, tests, scripts, Python crates, and Docker Compose/Dockerfiles themselves to keep the build context small.

### Changes Made to Existing Dockerfile

1. **Removed `NODE_ENV=production` from base stage** — it was inherited by all downstream stages unnecessarily. Each stage sets its own env vars explicitly now.

2. **Improved BuildKit cache mount syntax** — the `--mount=type=cache,target=/app/node_modules` properly caches node_modules across builds without copying them into image layers.

3. **Added i18n locale stripping** — `find .next -name '*.json' -path '*/i18n/*' -delete` removes unused locale files that add 2–4 MB of bloat.

4. **More descriptive comments** — explains what each cleanup step removes and why.

### Anti-Patterns Addressed

- **No `:latest` tag** — all images pinned to specific versions (`node:22.12-alpine3.20`, `postgres:17-alpine`, `redis:7-alpine`)
- **No root user** — non-root `app` user with UID 10001 in runner stage
- **Secrets not in image** — `.env` via `env_file`, never ENV instructions with values
- **Separate concerns** — app, db, redis in separate containers with named volumes
- **Network segmentation** — `internal: true` on backend net; db only exposed on `127.0.0.1` in prod
- **Not one giant container** — three distinct services with minimal footprints
