## Code Review: Subscription Billing FSM

### Architecture

The FSM uses a **data-driven transition table** (`_TRANSITION_DEFINITIONS`) that maps action names to `(allowed source states, target state)`. This is clean — adding a new transition means adding one dict entry, not touching control flow.

```python
_PENDING → _ACTIVE → _PAST_DUE → _PENDING (resume loop)
    |           |              |
    ↓___________↓______________↓
          _CANCELED (sink)
```

### Key Design Decisions

| Concern | Approach | Verdict |
|---|---|---|
| **Thread safety** | `threading.RLock` in `transition()`, `_handle_auto_cancel()` | Good — race conditions handled; first caller wins, second gets `InvalidTransitionError` |
| **Handler isolation** | Each handler wrapped in try/except inside `_notify_handlers()` | Correct — one bad handler doesn't block others |
| **Immutable history** | `history` property returns `list(self._history)` copy | Satisfies the immutability requirement (test `TestHistoryTracking.test_history_is_immutable_copy`) |
| **Timeout logic** | Separate `_handle_auto_cancel()` path gated by `trigger_transition("auto_cancel")` | Clean separation from manual transitions |
| **State enum** | `str, Enum` mix gives both `.value` strings and type-safe checks | Pragmatic |

### Test Coverage (48 tests across 12 tracer bullets)

- **Valid chains**: draft→pending→active, pending→cancel, past_due→pending (resume loop)
- **Invalid transitions**: all rejected paths documented explicitly (lines 33–57, 96–126, 405–430)
- **Concurrency**: real thread races verified (lines 156–233), deadlock-free
- **Timeouts**: grace period boundary conditions, naive datetime coercion, logical timestamp injection (lines 240–467)
- **Event system**: callback registration/deregistration, duplicate handler deduplication, exception isolation (lines 322–499)
- **Edge cases**: unknown actions, whitespace-only actions, empty strings (lines 265–514)

### Minor Issues

1. **Line 369 assertion**: `assert "→" in repr_str` — the `TransitionEvent.__str__` actually uses `→` correctly, but this relies on the Unicode arrow character being consistent. Fine for now.

2. **Line 176**: `if self.state not in valid_sources` — this comparison works because `SubscriptionState` is a `str, Enum`, so set membership checks against `SubscriptionState` members. No issue, but worth noting the dual nature.

3. **Line 106**: `handler: callable` — should be `Callable[[TransitionEvent], None]` for static type checking (mypy strict mode). Same on line 116.

4. **Line 146**: `elapsed < TIMEOUT_GRACE_PERIOD_SECONDS` — test at line 441 verifies exact-boundary succeeds (uses `<` meaning equal elapsed triggers the cancel). This is intentional per the spec comment on line 441.

5. **No `__init__.py` re-export from `skills/` root**: Line 523 imports from `skills.billing` directly. If someone tries `from skills import ...` they'd need the parent `__init__.py` updated. Not a bug, just a note.

### What Could Be Added (Not Required)

- `expired` or `grace_period_expired` transitions from ACTIVE→PENDING auto-trigger if we want time-driven state machines beyond PENDING-only timeouts
- A `replay(history)` method for restoring state from event log
- Type annotations on `on_transition` / `remove_transition_handler` parameters for mypy strict compliance
