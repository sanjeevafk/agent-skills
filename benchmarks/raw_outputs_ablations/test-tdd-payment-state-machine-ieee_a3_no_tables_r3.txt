### Minor Issues Found

1. **Dead variables in `test_timeout_respects_configured_seconds`** (line 191, 199): `elapsed_short` and `elapsed_long` are computed but never asserted. Cosmetic only.

2. **Thread-safe list in concurrency tests** (lines 231, 255): `outcomes.append()` and `results.append()` from multiple threads without synchronization. Works in CPython due to the GIL but isn't formally thread-safe. For production-critical code, a `threading.Lock` around the shared lists would be more robust. (Again, this is a test artifact, not production code.)

3. **Parametrize indirection**: `TestInvalidTransitions` uses string status names ("DRAFT") converted back via `getattr(Status, start)` instead of parametrizing with `Status.DRAFT` directly. Slightly less readable than using the enum members directly.

4. **`TestInitialization.test_canceled_is_terminal_no_outgoing_events`** only tests 5 specific event names. If a future developer adds a new domain event (e.g., `"subscription_reactivated"`), this test won't catch that canceled still rejects it unless updated. A more robust version would assert against the set of all valid outgoing events for each state.
