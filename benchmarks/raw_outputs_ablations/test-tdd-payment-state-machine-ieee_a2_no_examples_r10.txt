Here's my full review of the subscription billing FSM:

## Result: 48/48 tests pass, implementation is solid

### What works well

| Area | Assessment |
|---|---|
| **State machine logic** | Clean `SubscriptionStateMachine` dataclass with RLock-protected transitions. All 5 states (DRAFT→PENDING→ACTIVE→PAST_DUE→CANCELED) with correct transition rules. CANCELED is a proper sink state. |
| **Domain events** | Frozen `TransitionEvent` dataclass — immutable by design. `__repr__` uses arrow notation (`draft→pending`). Timestamp defaults to UTC. `extra` dict supports reason metadata (e.g. `"grace_period_expired"`). |
| **Concurrent access** | `RLock` ensures serialized transitions. Tests verify exactly one thread wins race conditions and no deadlocks occur. Handler isolation prevents one bad handler from breaking others. |
| **Timeout triggers** | `trigger_transition("auto_cancel", now=dt)` with strict grace period check (`elapsed < TIMEOUT_GRACE_PERIOD_SECONDS`), naive-datetime coercion to UTC, and logical timestamp passthrough. Boundary at exactly 86400s succeeds correctly. |
| **Test quality** | 48 tests across 13 tracer bullet suites. Tests exercise public APIs (`transition()`, `history`, `current_state`) not internals. Covers invalid transitions, happy paths, concurrency, edge cases (whitespace, empty string), event handlers with pytest-mock, and configuration exports. |
| **Error messages** | Consistent `InvalidTransitionError` (subclass of `ValueError`) with human-readable messages including state names, action names, and seconds remaining for timeouts. |

### Changes I made during review

1. **Fixed type annotation** — replaced `callable[[TransitionEvent], None]` with proper `Callable[[TransitionEvent], None]` from `typing` on lines 74 and 81. The old form wasn't valid Python even with `from __future__ import annotations`.

2. **Consolidated configuration** — merged `_TRANSITION_RULES` + `_ACTION_TARGETS` into single `_TRANSITION_DEFINITIONS` dict. Each entry is `(valid_sources: frozenset, target: str)`. This eliminates duplication and makes adding new transitions a single edit rather than two synchronized edits.

### Architecture notes

- **Design aligns with engineering standards**: Tests verify *behavior* through public interfaces (state changes, history, callbacks), not internal data structures. Renaming `_lock` or `_handlers` wouldn't break any test.
- **Deep modules pattern**: `_TRANSITION_DEFINITIONS` provides a tiny interface (dict lookup) over complex validation rules. `_notify_handlers` hides exception isolation logic behind a private method.
- **One gap vs strict TDD**: The test file was pre-written (untracked in git alongside an empty `fsm.py`). While the tests themselves are excellent spec-level behavior tests, they weren't discovered incrementally via red-green-refactor cycles. That said, the resulting code quality is production-grade regardless.
