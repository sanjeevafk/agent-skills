**`leak_diagnosis_playbook.md`** — Complete 5-phase diagnostic playbook covering:

| Phase | What it covers |
|-------|---------------|
| **Phase 1** | Safe heap snapshot capture in K8s pods without restarting processes; throttled rolling pipeline via `capture_snapshots.sh`; two-snapshot diff workflow |
| **Phase 2** | Chrome DevTools retainer-chain tracing for EventEmitter closures and Buffer objects; programmatic retainer extraction; `clinic.js` setup |
| **Phase 3** | Emitter listener leak confirmation — monkey-patched probe (`probe_emitter_leak.js`) tracking every `on()`/`off()` call with stack traces; native `_events` inspection; three smoking-gun tests (growth rate, removal verification, circuit breaker) |
| **Phase 4** | Response-logging middleware Buffer leak — the exact anti-pattern causing retention; bounded ring buffer fix (`fixed_response_logger.js`); streaming fallback for audit-trail scenarios; real-time allocation tracer (`diagnose_buffers.js`) |
| **Phase 5** | Runtime guardrails (`memory_guard.js`) with GC triggers and circuit breakers; K8s PDB + pre-emptive restart strategy; `defaultMaxListeners` enforcement |

**Root cause summary** — the playbook identifies the two confirmed vectors plus a third compounding factor:

1. **Emitter closure leak** — request handlers register `on('data'/'end'/'error')` on shared emitters inside closures that capture request/response context, but `removeListener` is never called because the handler references variables only visible in the closure scope
2. **Buffer logging leak** — response-body capture middleware stores full responses (Buffers or `.toString('base64')` strings that retain their backing store) in a global array with no eviction
3. **No upper bound on either** — neither structure has size limits, TTLs, or LRU eviction

Each vector has a concrete fix: the bounded ring buffer, the emitter monitoring/injection script, and hardening guardrails all ship as standalone scripts ready to drop into the pod.
