### Structural Improvement: Outbox Lazy Loading

The `outbox/__init__.py` previously bundled pure-Python `OutboxEvent`/`OutboxRepository` alongside SQLAlchemy models at module level, causing `ModuleNotFoundError` when importing domain-layer code without SQLAlchemy installed.

I split it into:
- **`outbox/events.py`** — Pure Python (`OutboxEvent`, `OutboxRepository` ABC, `emit_event()`). Always importable.
- **`outbox/_orm.py`** — SQLAlchemy `OutboxModel` only loaded via `__getattr__` lazy dispatch.
- **`outbox/__init__.py`** — Re-exports from `events.py`; lazily loads ORM when accessed.

This means static analysis tools (mypy, ruff) and unit tests can import `OutboxEvent` without needing SQLAlchemy.

**Dependency direction flows inward**: infrastructure layers depend on port abstractions; domain logic depends on nothing external. This makes every adapter mockable without touching business rules.

## Complete Component Listing

### Domain Layer (`domain/`) — Pure Python, zero coupling

```python
# domain/errors.py
class DomainError(Exception): ...
class ValidationError(DomainError): ...       # Bad input
class BusinessRuleError(DomainError): ...     # Violates invariant
class ResourceNotFoundError(DomainError): ... # Not in DB

# domain/entities.py
@dataclass(frozen=True, slots=True)
class Money:                                  # Immutable value object
    amount: int                                 # cents/pence
    currency: str = "USD"
    def from_decimal(cls, dollars: float, ...) → Money   # exact: 9.99→999
    def add(self, other: Money) → Money
    def sub(self, other: Money) → Money

@dataclass(slots=True)
class LineItem:                               # product snapshot
    product_id: str; description: str
    unit_price: Money; quantity: int
    @property total → Money

@dataclass(slots=True)
class Order:                                  # Aggregate root
    id: UUID; customer_email: str; items: list[LineItem]
    status: str = "DRAFT"                     # State machine enforced
    total_amount: Money; created_at: datetime
    payment_record: TransactionRecord | None

    # State transitions (guarded by current status)
    def confirm() → DRAFT → CONFIRMED
    def pay(txn_id) → CONFIRMED → PAID
    def ship() → PAID → SHIPPED
    def cancel() → anything except SHIPPED → CANCELLED
    def requires_refund() → bool                # paid + has record
```

State machine: `DRAFT → CONFIRMED → PAID → SHIPPED | CANCELLED`

### Use Cases (`usecases.py`) — Workflow Orchestration

Each use case takes the 4 port dependencies via its constructor and defines a single `execute(cmd)` coroutine:

```python
class CreateOrder(UseCaseBase):
    async execute(cmd):
        for item_data in cmd.items:
            stock = await self.inventory_repo.get_stock(item.product_id)
            if stock < qty: raise BusinessRuleError("Insufficient stock")
            order.add_item(LineItem(...))
        order.confirm()                       # DRAFT → CONFIRMED
        saved = await self.order_repo.save(order)
        await self.email_notifier.send_order_confirmation(...)
        return saved

class GetOrder(UseCaseBase):
    async execute(cmd):
        return await self.order_repo.get_by_id(UUID(cmd.order_id))

class CapturePayment(UseCaseBase):
    async execute(cmd):
        order = await self.order_repo.get_by_id(...)
        result = await self.payment_gateway.capture(order.total_amount.amount, ...)
        order.pay(result["transaction_id"])   # CONFIRMED → PAID
        return await self.order_repo.save(order)

class CancelOrder(UseCaseBase):
    async execute(cmd):
        order = await self.order_repo.get_by_id(...)
        order.cancel()
        for item in order.items: await self.inventory_repo.release(...)
        if order.requires_refund():
            await self.payment_gateway.refund(order.payment_record.transaction_id, ...)
        return await self.order_repo.save(order)
```

### Outbox Pattern (`outbox/`)

```python
@dataclass(frozen=True, slots=True) class OutboxEvent:
    event_id: UUID; event_type: str; payload: dict; aggregate_id: UUID
    created_at: datetime; delivered_at: datetime | None

class OutboxRepository(ABC):
    async publish(event_type, payload, aggregate_id) → OutboxEvent
    async mark_delivered(event_id) → None          # idempotent
    async fetch_pending(limit=100) → list[OutboxEvent]
    async delete_old_delivered(before) → int        # purge keeper
```

Usage: write order + outbox event in one DB transaction. Background worker polls PENDING events, publishes externally, marks DELIVERED. Crash-safe because re-execution of `mark_delivered` is safe.

## Key Design Decisions

1. **Single `Money` type everywhere** — smallest currency unit (cents), immutable, with `from_decimal()` for float↔int conversion that round-trips exactly (`Money.from_decimal(9.99).to_decimal() == 9.99`).

2. **Domain entities own their state machine** — no external validator needed. Each method on `Order` guards transitions with the current `status` field.

3. **Port contracts defined before implementation** — `ports/outgoing.py` lists every method a concrete adapter must implement. Tests verify this with AST analysis (`test_ports_modules_define_only_protocols`).

4. **Lazy framework imports** — stripe, sendgrid, sqlalchemy each imported inside methods or via `__getattr__`, never at module load time. Enables running domain/use-case tests without infrastructure dependencies.

5. **Typed dependency container** — `Container` is a `@dataclass` so IDE autocomplete and static type checkers see all fields and their types immediately. No more `dict[str, Any]` soup.
