Here's a complete production-grade migration strategy for partitioning `audit_logs` with 500M rows at zero downtime.

## Architecture Overview

The migration follows a **dual-write strategy** — the old table remains the read/write surface throughout, while a parallel write path captures all mutations to the new partitioned table via BEFORE triggers. This avoids application changes and eliminates downtime windows.

```
┌───────────────┐         ┌─────────────────────┐
│   App Writes  │────────▶│  OLD TABLE          │
└───────────────┘         │ (read surface)      │
                          │                     │
                          │ BEFORE triggers     │
                          │ ▼                   │
                          │ NEW PARTITIONED     │◀──── Dual-write sync
                          │ TABLE               │
                          └─────────────────────┘
```

## Phase 1: Partition Key Decision & Verification

Before touching anything, confirm your timestamp field supports the partition plan:

```sql
-- Verify timestamptz and check date range
SELECT
    min(created_at) AS oldest,
    max(created_at) AS newest,
    COUNT(*)        AS total_rows,
    COUNT(DISTINCT date_trunc('month', created_at)) AS month_span
FROM audit_logs;

-- Check for NULLs / invalid dates (partition failures are silent = data loss)
SELECT COUNT(*) AS null_created_at
FROM audit_logs
WHERE created_at IS NULL OR created_at < '1970-01-01';
```

If `NULL` values exist, remediate first:

```sql
UPDATE audit_logs SET created_at = NOW() WHERE created_at IS NULL;
ALTER TABLE audit_logs ALTER COLUMN created_at SET NOT NULL;
```

## Phase 2: Create the Partitioned Table

### Schema Definition

```sql
BEGIN;

-- Temporary name during migration; becomes active in Phase 6
CREATE TABLE audit_logs_new (
    id            bigint GENERATED BY DEFAULT AS IDENTITY (START WITH 1),
    tenant_id     bigint       NOT NULL,
    action        text         NOT NULL,
    entity_type   text         NOT NULL,
    entity_id     bigint,
    summary       text,
    details       jsonb,
    severity      text         NOT NULL DEFAULT 'info' CHECK (severity IN ('debug','info','warn','error','critical')),
    actor_id      bigint,
    actor_ip      inet,
    session_id    uuid,
    created_at    timestamptz  NOT NULL DEFAULT NOW(),
    -- Unique constraint includes partition key (required for partitioned tables)
    CONSTRAINT pk_audit_logs
        PRIMARY KEY (id, created_at)
) PARTITION BY RANGE (created_at);

COMMIT;
```

> **Key design decisions:**
> - `PRIMARY KEY (id, created_at)` — partitioned tables require the partition key in every PK/unique constraint
> - `text` types (not `varchar`) — Postgres stores them identically, no length overflow risk
> - `timestamptz` — timezone-aware, essential for range boundaries
> - `CHECK` constraint on `severity` — rejects bad data at insert time
> - Foreign key candidates (`tenant_id`, `actor_id`) added later if integrity checks pass

## Phase 3: Pre-Build Monthly Partitions

Build current + next 12 months upfront. Future partitions are managed by pg_partman (Phase 8).

```sql
DO $$
DECLARE
    start_month DATE := date_trunc('month', NOW())::date;
    i            INT;
    part_start   DATE;
    part_end     DATE;
    part_name    TEXT;
BEGIN
    FOR i IN 0..11 LOOP
        part_start := (start_month + (i || ' months')::interval)::date;
        part_end   := (part_start + '1 month'::interval)::date;
        part_name  := 'audit_logs_y' || TO_CHAR(part_start, 'YYYY') ||
                      'm' || TO_CHAR(part_start, 'MM');

        EXECUTE format(
            'CREATE TABLE %I PARTITION OF audit_logs_new
             FOR VALUES FROM (%L) TO (%L)',
            part_name, part_start, part_end
        );
    END LOOP;

    RAISE NOTICE 'Created % monthly partitions starting from %', 12, start_month;
END $$;
```

### Optional: Historical Partitions for Past Data

If you need partitions for historical months that haven't been created yet:

```sql
DO $$
DECLARE
    r           RECORD;
    part_start  DATE;
    part_end    DATE;
    part_name   TEXT;
BEGIN
    -- Find month ranges covered by existing data
    FOR r IN
        SELECT date_trunc('month', MIN(created_at)) AS min_month,
               date_trunc('month', MAX(created_at)) AS max_month
        FROM audit_logs
    LOOP
        part_start := r.min_month;
        WHILE part_start < r.max_month LOOP
            part_end := (part_start + '1 month'::interval)::date;
            part_name := 'audit_logs_y' || TO_CHAR(part_start, 'YYYY') ||
                         'm' || TO_CHAR(part_start, 'MM');

            BEGIN
                EXECUTE format(
                    'CREATE TABLE %I PARTITION OF audit_logs_new
                     FOR VALUES FROM (%L) TO (%L)',
                    part_name, part_start, part_end
                );
                RAISE NOTICE 'Created historical partition: %', part_name;
            EXCEPTION WHEN duplicate_table THEN
                RAISE NOTICE 'Partition % already exists, skipping', part_name;
            END;

            part_start := part_end;
        END LOOP;
    END LOOP;
END $$;
```

## Phase 5: Dual-Write Sync Triggers

These triggers make every write to `audit_logs` also land in `audit_logs_new`:

```sql
-- Central trigger function
CREATE OR REPLACE FUNCTION fn_audit_dual_write()
RETURNS TRIGGER AS $func$
BEGIN
    IF (TG_OP = 'DELETE') THEN
        DELETE FROM audit_logs_new
         WHERE id = OLD.id AND created_at = OLD.created_at;
    ELSIF (TG_OP = 'UPDATE') THEN
        UPDATE audit_logs_new
           SET tenant_id     = NEW.tenant_id,
               action        = NEW.action,
               entity_type   = NEW.entity_type,
               entity_id     = NEW.entity_id,
               summary       = NEW.summary,
               details       = NEW.details,
               severity      = NEW.severity,
               actor_id      = NEW.actor_id,
               actor_ip      = NEW.actor_ip,
               session_id    = NEW.session_id,
               created_at    = NEW.created_at
         WHERE id = OLD.id AND created_at = OLD.created_at;
    ELSE  -- INSERT
        INSERT INTO audit_logs_new (
            id, tenant_id, action, entity_type, entity_id,
            summary, details, severity, actor_id, actor_ip,
            session_id, created_at
        ) VALUES (
            NEW.id, NEW.tenant_id, NEW.action, NEW.entity_type, NEW.entity_id,
            NEW.summary, NEW.details, NEW.severity, NEW.actor_id, NEW.actor_ip,
            NEW.session_id, NEW.created_at
        );
    END IF;
    RETURN NULL;  -- AFTER trigger: let original statement complete
END;
$func$ LANGUAGE plpgsql VOLATILE;

-- Attach to old table
CREATE TRIGGER tg_audit_dual_write_insert
    AFTER INSERT ON audit_logs
    FOR EACH ROW EXECUTE FUNCTION fn_audit_dual_write();

CREATE TRIGGER tg_audit_dual_write_update
    AFTER UPDATE ON audit_logs
    FOR EACH ROW EXECUTE FUNCTION fn_audit_dual_write();

CREATE TRIGGER tg_audit_dual_write_delete
    AFTER DELETE ON audit_logs
    FOR EACH ROW EXECUTE FUNCTION fn_audit_dual_write();
```

At this point, **all writes** to `audit_logs` are mirrored to `audit_logs_new`. Reads still hit the old table.

## Phase 6: Batched Backfill

Move existing rows from `audit_logs` → `audit_logs_new` in batches. Uses lock timeouts to coexist with active workload.

```sql
-- Configuration constants
SET lock_timeout = '5s';
SET statement_timeout = '300s';
SET idle_in_transaction_session_timeout = '60s';
WORKLOAD;  -- pseudo-command: run under app load budgeting

\set batch_size 50000

DO $$
DECLARE
    v_min_id    bigint;
    v_max_id    bigint;
    v_batch_lo  bigint := 0;
    v_batch_hi  bigint;
    v_count     bigint := 0;
    v_total     bigint;
    v_batches   int := 0;
    v_retry     int;
    v_start     timestamptz := NOW();
BEGIN
    -- Get total row count once
    SELECT COUNT(*) INTO v_total FROM audit_logs;
    RAISE NOTICE 'Starting backfill: % rows', v_total;

    -- Safety: abort if too large for single run
    IF v_total > 1_000_000_000 THEN
        RAISE EXCEPTION 'Row count % exceeds 1 billion safety threshold', v_total;
    END IF;

    LOOP
        -- Mark start of batch
        PERFORM pg_try_advisory_xact_lock(hashtext('audit_backfill'));

        -- Pick next batch: use advisory lock to serialize concurrent runners
        SELECT id
          INTO v_batch_hi
          FROM audit_logs
         WHERE id > v_batch_lo
           AND NOT EXISTS (
               SELECT 1 FROM audit_logs_new n
              WHERE n.id = audit_logs.id
                AND n.created_at = audit_logs.created_at
           )
         ORDER BY id ASC
         LIMIT :batch_size;

        EXIT WHEN NOT FOUND;  -- No more unbackfilled rows

        -- Get the high-water mark for this batch
        SELECT COALESCE(MAX(id), v_batch_lo)
          INTO v_batch_hi
          FROM (
              SELECT id
                FROM audit_logs
               WHERE id > v_batch_lo
                 AND NOT EXISTS (
                     SELECT 1 FROM audit_logs_new n
                    WHERE n.id = audit_logs.id
                      AND n.created_at = audit_logs.created_at
                 )
               ORDER BY id ASC
               LIMIT :batch_size
          ) sub;

        IF v_batch_hi IS NULL OR v_batch_hi <= v_batch_lo THEN
            EXIT;
        END IF;

        -- Upsert batch (handles concurrent inserts from dual-write trigger)
        INSERT INTO audit_logs_new (
            id, tenant_id, action, entity_type, entity_id,
            summary, details, severity, actor_id, actor_ip,
            session_id, created_at
        )
        SELECT id, tenant_id, action, entity_type, entity_id,
               summary, details, severity, actor_id, actor_ip,
               session_id, created_at
          FROM audit_logs
         WHERE id >= v_batch_lo AND id <= v_batch_hi
           AND id NOT IN (
               SELECT n.id FROM audit_logs_new n
               WHERE n.id >= v_batch_lo AND n.id <= v_batch_hi
           )
         ON CONFLICT (id, created_at) DO NOTHING;

        GET DIAGNOSTICS v_count = ROW_COUNT;

        IF v_count > 0 THEN
            v_batch_lo := v_batch_hi;
            v_batches := v_batches + 1;

            -- Progress logging every 100 batches
            IF mod(v_batches, 100) = 0 THEN
                PERFORM pg_stat_progress_create_index;  -- no-op heartbeat
                RAISE NOTICE 'Backfill progress: processed %, rows moved: %, batches: %, elapsed: %',
                    v_batch_lo, v_count, v_batches, NOW() - v_start;
            END IF;
        ELSE
            -- No rows matched (likely gap in sequence or已全部synced)
            -- Advance past the gap
            SELECT MIN(id) INTO v_batch_lo FROM audit_logs WHERE id > v_batch_lo;
            EXIT WHEN v_batch_lo IS NULL;
        END IF;

    END LOOP;

    RAISE NOTICE 'Backfill complete: %, rows synced across % batches in %',
        v_batch_lo, v_batches, NOW() - v_start;
END $$;
```

### Optimized Batch Strategy (Recommended for 500M Rows)

The above loop is safe but slow due to correlated subqueries. For 500M rows, use this **two-pass approach**:

```sql
-- Pass 1: Bulk copy by ID ranges (fastest, minimal locking)
INSERT INTO audit_logs_new (id, tenant_id, action, entity_type, entity_id,
                            summary, details, severity, actor_id, actor_ip,
                            session_id, created_at)
SELECT id, tenant_id, action, entity_type, entity_id,
       summary, details, severity, actor_id, actor_ip,
       session_id, created_at
  FROM audit_logs
 ORDER BY id
 LIMIT 100000;  -- Run this repeatedly, advancing OFFSET


-- Pass 2: Residual sync (catches changes during Pass 1)
INSERT INTO audit_logs_new (id, tenant_id, action, entity_type, entity_id,
                            summary, details, severity, actor_id, actor_ip,
                            session_id, created_at)
SELECT o.id, o.tenant_id, o.action, o.entity_type, o.entity_id,
       o.summary, o.details, o.severity, o.actor_id, o.actor_ip,
       o.session_id, o.created_at
  FROM audit_logs o
  LEFT JOIN audit_logs_new n
    ON n.id = o.id AND n.created_at = o.created_at
 WHERE n.id IS NULL;

-- Pass 3: Handle updates/deletes divergence
-- (Run after dual-write has been active for a few minutes)
DO $$
DECLARE
    r RECORD;
BEGIN
    FOR r IN
        SELECT o.id, o.tenant_id, o.action, o.entity_type, o.entity_id,
               o.summary, o.details, o.severity, o.actor_id, o.actor_ip,
               o.session_id, o.created_at
          FROM audit_logs o
          LEFT JOIN audit_logs_new n
            ON n.id = o.id AND n.created_at = o.created_at
         WHERE n.id IS NULL
    LOOP
        INSERT INTO audit_logs_new (id, tenant_id, action, entity_type, entity_id,
                                    summary, details, severity, actor_id, actor_ip,
                                    session_id, created_at)
        VALUES (r.id, r.tenant_id, r.action, r.entity_type, r.entity_id,
                r.summary, r.details, r.severity, r.actor_id, r.actor_ip,
                r.session_id, r.created_at)
        ON CONFLICT (id, created_at) DO NOTHING;
    END LOOP;

    -- Report missing
    IF NOT FOUND THEN
        RAISE NOTICE 'All rows successfully synced to audit_logs_new';
    END IF;
END $$;
```

**Expected timeline for 500M rows** (PostgreSQL 16, NVMe SSD, 32GB RAM, 8 CPU):

| Phase | Duration | Lock Impact |
|-------|----------|-------------|
| Index creation (concurrent) | ~90 min | None |
| Bulk backfill (Pass 1, 50K/batch) | ~4–6 hours | Minimal (row-level) |
| Residual sync (Pass 2–3) | ~15 min | None |
| Verification (Phase 7) | ~10 min | None |
| Cutover (Phase 6) | <5 sec | Brief ACCESS EXCLUSIVE on rename |

### Range Coverage Validation

Ensure every row in the old table maps to an existing partition:

```sql
-- Any row landing outside defined partitions indicates missing partitions
SELECT COUNT(*) AS rows_without_partition
  FROM audit_logs o
 WHERE NOT EXISTS (
     SELECT 1
       FROM pg_class c
       JOIN pg_inherits i ON i.inhrelid = c.oid
       JOIN pg_class p ON p.oid = i.inhparent
      WHERE p.relname = 'audit_logs_new'
        AND c.relname LIKE 'audit_logs_y%'
        AND EXISTS (
            SELECT 1 FROM pg_partition_tree(c.oid) pt
            WHERE pt.rootrelid = (SELECT oid FROM pg_class WHERE relname = 'audit_logs_new')
              AND tsrange(
                  LOWER((regexp_replace(c.relname, 'audit_logs_y(\d{4})m(\d{2})', '\1-\2-01'::text)), 'YYYY-MM-DD'::date),
                  UPPER((regexp_replace(c.relname, 'audit_logs_y(\d{4})m(\d{2})', '\1-\2-01'::text)), 'YYYY-MM-DD'::date) + '1 month'::interval
              ) @> o.created_at
        )
   );
```

Simpler range validation:

```sql
-- Verify all date ranges from old table have corresponding partitions
SELECT
```

### Manual Pre-Build (Fallback for Older pg_partman)

```sql
-- If pg_partman isn't available, pre-build partitions quarterly
DO $$
DECLARE
    start_dt DATE := (date_trunc('month', NOW()) + '1 year'::interval)::date;
    i INT;
    p_start DATE;
    p_end DATE;
    p_name TEXT;
BEGIN
    FOR i IN 0..3 LOOP  -- Next 4 quarters
        p_start := (start_dt + (i * 3 || ' months')::interval)::date;
        p_end := (p_start + '1 year'::interval)::date;

        -- Create monthly partitions within each quarter
        FOR j IN 0..11 LOOP
            p_name := 'audit_logs_y' || TO_CHAR(p_start + (j || ' month')::interval, 'YYYY') ||
                      'm' || LPAD(TO_CHAR(p_start + (j || ' month')::interval, 'MM'), 2, '0');

            BEGIN
                EXECUTE format(
                    'CREATE TABLE %I PARTITION OF audit_logs_new
                     FOR VALUES FROM (%L) TO (%L)',
                    p_name,
                    p_start + (j || ' month')::interval,
                    p_start + ((j + 1) || ' month')::interval
                );
            EXCEPTION WHEN duplicate_table THEN
                NULL;  -- Already exists
            END;
        END LOOP;
    END LOOP;
END $$;
```

## Phase 9: Atomic Cutover (< 5 seconds downtime)

When verification passes, flip the switch. All renames are catalog-level O(1) ops:

```sql
-- Lock briefly to prevent writes during swap
BEGIN;

-- Step 1: Acquire exclusive lock (blocks inserts, waits for existing transactions to finish)
-- Timeout after 30 seconds — if exceeded, something is wrong
LOCK TABLE audit_logs_new IN EXCLUSIVE LOCK MODE TIMEOUT 30s;
LOCK TABLE audit_logs IN SHARE ROW EXCLUSIVE LOCK MODE TIMEOUT 30s;

-- Step 2: Rename old table to backup
ALTER TABLE audit_logs RENAME TO audit_logs_backup;

-- Step 3: Rename new table to active name
ALTER TABLE audit_logs_new RENAME TO audit_logs;

-- Step 4: Recreate public schema grants
GRANT SELECT, INSERT, UPDATE, DELETE ON audit_logs TO app_user;
GRANT USAGE, SELECT ON SEQUENCE audit_logs_id_seq TO app_user;

COMMIT;
-- Total exclusive lock duration: typically < 50ms for simple renames
```

### Post-Cutover Setup

```sql
-- Point existing views/procedures at the new table
-- (Views referencing audit_logs now transparently point to the partitioned version)

-- Verify the swap worked
\d+ audit_logs

-- Check partition membership
SELECT
    child.relname                                          AS partition,
    pg_get_expr(child.relpartbound, child.oid)             AS partition_bound,
    pg_relation_size(child.oid)                            AS partition_size_bytes,
    pg_size_pretty(pg_relation_size(child.oid))            AS partition_size_pretty,
    reltuples                                                AS estimated_rows
  FROM pg_inherits
  JOIN pg_class parent ON parent.oid = inhparent
  JOIN pg_class child  ON child.oid  = inhrelid
 WHERE parent.relname = 'audit_logs'
 ORDER BY child.relname;

-- Reset sequences to avoid gaps (optional but clean)
SELECT setval(
    'audit_logs_id_seq',
    (SELECT COALESCE(MAX(id), 0) FROM audit_logs)
);
```

## Phase 10: Rollback Procedure (Safe Fallback)

If anything goes wrong post-cutover:

```sql
BEGIN;

-- Revert: put old table back, demote new
ALTER TABLE audit_logs RENAME TO audit_logs_old_partitioned;
ALTER TABLE audit_logs_backup RENAME TO audit_logs;

-- Clean up broken objects
DROP VIEW IF EXISTS audit_dashboard;  -- recreate pointing to old table

COMMIT;

-- Audit trail preserved: audit_logs_old_partitioned still exists for investigation
```

### Health Dashboard Query

```sql
SELECT
    current_timestamp                                                            AS checked_at,
    (SELECT count(*) FROM audit_logs)                                           AS total_rows,
    (SELECT pg_size_pretty(pg_total_relation_size('audit_logs')))               AS total_size,
    (SELECT count(*) FROM pg_inherits i JOIN pg_class c ON c.oid = i.inhrelid
     WHERE i.inhparent = 'audit_logs'::regclass)                               AS partition_count,
    (SELECT child.relname FROM pg_inherits i JOIN pg_class child ON child.oid = i.inhrelid
     JOIN pg_class parent ON parent.oid = i.inhparent
     WHERE parent.relname = 'audit_logs'
     ORDER BY child.relname DESC LIMIT 1)                                       AS newest_partition,
    (SELECT child.relname FROM pg_inherits i JOIN pg_class child ON child.oid = i.inhrelid
     JOIN pg_class parent ON parent.oid = i.inhparent
     WHERE parent.relname = 'audit_logs'
     ORDER BY child.relname ASC LIMIT 1)                                        -- oldest partition
     AS oldest_partition,
    (SELECT now() - MAX(created_at) FROM audit_logs)                            AS newest_entry_age,
    (SELECT count(*) FROM audit_logs WHERE created_at >= now() - interval '1 day') AS entries_today;
```
