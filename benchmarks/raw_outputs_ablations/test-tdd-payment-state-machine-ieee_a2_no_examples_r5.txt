## Subscription FSM — TDD Review

### Architecture Summary

The state machine enforces the strict transition graph:
```
DRAFT →(pending)→ PENDING →(activate)→ ACTIVE →(past_due)→ PAST_DUE
                                          ↓              →(cancel)→ CANCELED [sink]
                                          ↓
                                   ←(resume)───┘
                                           ↑
                              (cancel)─────┘
```

Key properties:
- **CANCELED is a true sink** — no outgoing transitions
- **Active → Cancelled requires PastDue intermediate** (explicit business rule)
- **Resume goes back to PENDING**, not Active — payment verification required

### Domain Model (`skills/billing/fsm.py`)

**Core types:**
- `SubscriptionState(str, Enum)` — frozen domain enum with `.value` strings
- `TransitionEvent(frozen dataclass)` — immutable event with source, target, timestamp, extra metadata
- `InvalidTransitionError(ValueError)` — raised for illegal transitions

**FSM implementation details:**
- Uses `threading.RLock` for thread-safety (reentrant so `_handle_auto_cancel` can call within the same thread context)
- Configuration-driven via `_TRANSITION_RULES` and `_ACTION_TARGETS` dicts — clean separation between state machine logic and transition table
- History exposed as immutable copy (`list(self._history)`) preventing external mutation
- Handlers isolated — exceptions in one handler don't cascade; logged at ERROR level

### Strengths

1. **Configuration-driven design** — adding a new state or transition only requires updating the two dicts, no code logic changes
2. **Vertical slice test organization** — each tracer bullet builds incrementally; tests describe *what* (behavior), not *how* (internal structure)
3. **Concurrent safety** — RLock ensures serialized access; the implementation acknowledges the window where two threads might both see the same state and lets the second receive `InvalidTransitionError` when it tries to apply a now-invalid transition
4. **Handler isolation** — bad handlers can't crash the FSM or block other callbacks
5. **Logical time injection** — `trigger_transition(..., now=...)` enables deterministic testing without real-time sleeps

### Minor Observations

- The `dataclass` definition uses bare `callable` for handler types — in Python 3.9+ this is technically `collections.abc.Callable`, but the runtime works fine since Python treats `callable` as a built-in function name
- Test group names (e.g., `TestTimeoutTriggers`) overlap somewhat with `TestTimeoutTriggersNew` — consider consolidating them into a single `TestTimeoutAutoCancel` class since they test the same `auto_cancel` mechanism
