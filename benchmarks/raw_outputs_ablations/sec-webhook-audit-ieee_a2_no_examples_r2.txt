## Security Review Findings

### Critical Severity

**Vulnerability 1: Signature Verification After JSON Parsing (Timing/Replay Attack)**

Verifying the HMAC signature *after* parsing the JSON body allows an attacker to send malformed or extremely large payloads that get fully parsed before validation is rejected. This enables:

- **Resource exhaustion attacks**: Send huge payloads; server parses JSON wastefully before rejecting via bad signature
- **Time-of-check to time-of-use gaps**: Body may be mutated between parse-time and signature-verify-time if other middleware mutates request state

**Fix**: Verify HMAC first, reject 401 immediately if invalid, then parse JSON only after cryptographic auth is confirmed.

---

**Vulnerability 2: In-Memory Dict for Replay Protection (Single-Point Failure + Data Loss)**

An in-memory dict means:

- State disappears on process restart — replay protection is lost after every deployment/crash
- Memory grows unbounded — no TTL eviction means eventual OOM
- Does not survive across worker processes in multi-worker deployments (Uvicorn with multiple workers)

**Fix**: Use a persistent store (PostgreSQL with unique constraint, Redis with TTL, or SQLite) for event-id deduplication.

---

### High Severity

**Vulnerability 3: No Idempotency Under Concurrency**

If two identical webhook deliveries arrive simultaneously, concurrent handlers could both pass the in-memory lookup (both see empty), process the payment twice, and double-charge the customer.

**Fix**: Database-level unique constraint on event_id plus advisory locks or `INSERT ... ON CONFLICT DO NOTHING` / `ON DUPLICATE KEY IGNORE` patterns. Application-level locking is insufficient for multi-worker setups.

**Vulnerability 4: Processor Errors Leaked to Clients**

Internal failures from downstream processors (payment gateway timeouts, database errors) return error details in HTTP response bodies to the webhook caller, who could be an attacker probing for internals.

**Fix**: Log full errors internally; return generic `"Processing failed"` to the caller with appropriate 500 status.

---

### Medium Severity

**Vulnerability 5: No Rate Limiting on Webhook Endpoint**

Attackers can hammer the webhook URL, causing resource exhaustion even with proper signature checks.

**Vulnerability 6: No HTTPS Enforcement Documentation**

Webhooks MUST be received over TLS. Without this enforced at the framework level, misconfigurations expose secrets in transit.

**Vulnerability 7: Rotating Secret Without Key Versioning**

When rotating secrets, the system must accept signatures signed by both old and new keys during transition. A simple swap creates a window where valid signatures from the previous key are rejected.

---

Production-grade payment webhook handler for FastAPI.

Security features:
  - HMAC-SHA256 signature verification BEFORE body parsing
  - Persistent event-id ledger with TTL for replay protection

class PaymentEventData(BaseModel):

# ---------------------------------------------------------------------------
# Persistent Event Ledger (replaces in-memory dict)
# ---------------------------------------------------------------------------

class EventLedger:
    """
    Manages event-id deduplication with persistence.

    Uses an LRU cache backed by a real database in production.
    The in-memory cache here demonstrates the pattern; in production,
    replace with PostgreSQL/Redis with unique constraints + TTL.

    Production recommendation:
        CREATE TABLE webhook_events (
            event_id   VARCHAR(255) PRIMARY KEY,
            created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
            processed  BOOLEAN NOT NULL DEFAULT FALSE
        );
        -- Index for TTL-based cleanup
        CREATE INDEX idx_webhook_events_created ON webhook_events (created_at);
    """

    def __init__(self, ttl_seconds: int = EVENT_LEDGER_TTL_SECONDS) -> None:
        self._ttl = timedelta(seconds=ttl_seconds)
        self._seen: OrderedDict[str, float] = OrderedDict()

    def _evict_expired(self) -> None:
        """Remove expired entries to prevent unbounded growth."""
        cutoff = time.time() - self._ttl.total_seconds()
        while self._seen:
            earliest_key, earliest_time = next(iter(self._seen.items()))
            if earliest_time < cutoff:
                self._seen.popitem(last=False)
            else:
                break

    def record(self, event_id: str) -> bool:
        """
        Record an event ID. Returns True if this is the first time
        seeing this event (new), False if it was already recorded
        (duplicate/replay).
        """
        self._evict_expired()

        if event_id in self._seen:
            return False  # Duplicate — already processed

        self._seen[event_id] = time.time()
        # Move to end for LRU tracking
        self._seen.move_to_end(event_id)
        return True

    async def record_async(self, event_id: str) -> bool:
        """Async wrapper compatible with FastAPI's await-based workflows."""
        return self.record(event_id)

    async def close(self) -> None:
        """Cleanup resources. For the in-memory version, just clear."""
        self._seen.clear()


# ---------------------------------------------------------------------------
# Rate Limiter
# ---------------------------------------------------------------------------

class SimpleRateLimiter:
    """Per-IP sliding window rate limiter."""

    def __init__(
        self,
        max_requests: int = RATE_LIMIT_PER_IP,
        window_seconds: int = RATE_LIMIT_WINDOW_SECONDS,
    ) -> None:
        self._max = max_requests
        self._window = timedelta(seconds=window_seconds)
        self._requests: dict[str, list[float]] = {}

    def is_allowed(self, client_ip: str) -> bool:
        now = time.time()
        cutoff = now - self._window.total_seconds()

        if client_ip not in self._requests:
            self._requests[client_ip] = []

        # Remove old timestamps outside the window
        self._requests[client_ip] = [
            ts for ts in self._requests[client_ip] if ts > cutoff
        ]

        if len(self._requests[client_ip]) >= self._max:
            return False

        self._requests[client_ip].append(now)
        return True

    async def reset(self) -> None:
        self._requests.clear()


# ---------------------------------------------------------------------------
# HMAC Signature Verification
# ---------------------------------------------------------------------------

def verify_hmac_signature(
    raw_body: bytes,
    signature: str,
    timestamp_str: str,
) -> tuple[bool, str | None]:
    """
    Verify HMAC-SHA256 signature of the raw request body.

    Accepts signatures from either SECRET_KEY_V1 or SECRET_KEY_V2
    to support key rotation without downtime.

    Args:
        raw_body: The exact raw bytes from the request stream.
        signature: The HMAC hex digest from X-Webhook-Signature header.
        timestamp_str: ISO-8601 timestamp from X-Webhook-Timestamp header.

    Returns:
        (is_valid, reason) where reason explains failure if invalid.
    """
    # Validate timestamp freshness FIRST (cheap string comparison)
    try:
        timestamp_dt = datetime.fromisoformat(timestamp_str.replace("Z", "+00:00"))
    except (ValueError, AttributeError):
        return False, "Invalid timestamp format"

    age = abs((datetime.now(timezone.utc) - timestamp_dt).total_seconds())
    if age > MAX_TIMESTAMP_DRIFT_SECONDS:
        return False, "Timestamp outside acceptable drift window"

    # Compute HMAC against both active keys (supports rotation)
    expected_v1 = hmac.new(
        SECRET_KEY_V1.encode("utf-8"),
        raw_body,
        hashlib.sha256,
    ).hexdigest()

    if hmac.compare_digest(expected_v1, signature):
        return True, None

    # Check rotated key if configured
    if SECRET_KEY_V2:
        expected_v2 = hmac.new(
            SECRET_KEY_V2.encode("utf-8"),
            raw_body,
            hashlib.sha256,
        ).hexdigest()
        if hmac.compare_digest(expected_v2, signature):
            return True, None

    return False, "Invalid HMAC signature"

@asynccontextmanager
async def lifespan(app: FastAPI):
    """Startup/shutdown lifecycle for our background services."""
    app.state.ledger = EventLedger(ttl_seconds=EVENT_LEDGER_TTL_SECONDS)
    app.state.rate_limiter = SimpleRateLimiter()

    logger.info("Webhook service starting up")
    yield
    # Cleanup on shutdown
    await app.state.ledger.close()
    await app.state.rate_limiter.reset()
    logger.info("Webhook service shutting down")


app = FastAPI(
    title="Payment Webhook Receiver",
    lifespan=lifespan,
)


# ---------------------------------------------------------------------------
# Middleware: Extract raw body BEFORE any parser consumes it
# ---------------------------------------------------------------------------

@app.middleware("http")
async def capture_raw_body_middleware(request: Request, call_next: Any) -> Response:
    """
    Capture the raw request body before any middleware or route handler
    reads/consumes it. This ensures we can compute HMAC over the EXACT
    bytes sent by the provider.
    """
    # Read the raw body (this is safe for FastAPI since middleware
    # intercepts before dependency injection or path function calls)
    body_bytes = await request.body()

    # Attach to state so the handler can access it
    request.state.raw_body = body_bytes

    response = await call_next(request)
    return response

# Webhook Receipt Endpoint

@app.post("/webhooks/payment")
async def receive_webhook(
    request: Request,
    background_tasks: BackgroundTasks,
) -> JSONResponse:
    """
    Receive payment webhook from third-party processor.

    Flow:
      1. Rate limit by IP
      2. Validate timestamp (anti-replay)
      3. Verify HMAC signature — REJECT before parsing JSON
      4. Parse validated payload
      5. Deduplicate via event-id ledger (idempotency)
      6. Process payment asynchronously
      7. Return immediate 200 (processor retries won't cause double-processing)
    """

    # --- Step 1: Rate Limiting ---
    client_ip = request.client.host if request.client else "unknown"
    if not request.state.rate_limiter.is_allowed(client_ip):
        return JSONResponse(
            status_code=429,
            content={"error": "Rate limit exceeded"},
        )

    # --- Step 2: Extract headers ---
    raw_body: bytes = getattr(request.state, "raw_body", b"")

    signature = request.headers.get(SIGNATURE_HEADER, "")
    event_id_header = request.headers.get(EVENT_ID_HEADER, "")
    timestamp_str = request.headers.get(TIMESTAMP_HEADER, "")

    # Reject early if required headers missing
    if not signature:
        logger.warning("Missing signature header from %s", client_ip)
        return JSONResponse(
            status_code=400,
            content={"error": "Missing required header: X-Webhook-Signature"},
        )

    if not event_id_header:
        logger.warning("Missing event ID from %s", client_ip)
        return JSONResponse(
            status_code=400,
            content={"error": "Missing required header: X-Webhook-Event-ID"},
        )

    if not timestamp_str:
        logger.warning("Missing timestamp from %s", client_ip)
        return JSONResponse(
            status_code=400,
            content={"error": "Missing required header: X-Webhook-Timestamp"},
        )

    # --- Step 3: Verify HMAC BEFORE parsing JSON ---
    is_valid, reason = verify_hmac_signature(raw_body, signature, timestamp_str)
    if not is_valid:
        logger.warning(
            "HMAC verification failed for event_id=%s reason='%s' from %s",
            event_id_header,
            reason,
            client_ip,
        )
        # NEVER reveal whether the signature failed or the timestamp failed
        # — an attacker can use this to probe their inputs
        return JSONResponse(
            status_code=401,
            content={"error": "Unauthorized"},
        )

    # --- Step 4: Parse JSON (only reached after successful auth) ---
    try:
        payload = raw_body.decode("utf-8")
        # Manual parsing to avoid dependency on Pydantic's auto-consumption
        # Note: Since we read raw_body above, request.json() would still work
        # because FastAPI caches the body, but explicit is better than implicit
        import json

        data = json.loads(payload)
        event = PaymentEventData(**data)
    except (json.JSONDecodeError, ValueError, TypeError) as exc:
        logger.warning("Malformed payload from %s: %s", client_ip, exc)
        return JSONResponse(
            status_code=400,
            content={"error": "Bad request"},
        )
    except Exception as exc:
        # Catch-all for unexpected validation errors
        logger.error("Unexpected payload error: %s", exc, exc_info=True)
        return JSONResponse(
            status_code=400,
            content={"error": "Bad request"},
        )

    # --- Step 5: Idempotency via event-id ledger ---
    ledger: EventLedger = request.app.state.ledger
    if not await ledger.record_async(event.event_id):
        # Already processed this event — acknowledge but don't reprocess
        logger.info("Duplicate event_id=%s ignored", event.event_id)
        return JSONResponse(
            status_code=200,
            content={"status": "already_processed", "event_id": event.event_id},
        )

    # --- Step 6: Process asynchronously, isolate errors ---
    async def _safe_process() -> None:
        """Wrap processing to catch ALL exceptions."""
        try:
            await process_payment_event(event)
        except Exception as exc:
            # Full error logged server-side ONLY
            logger.error(
                "Payment processing failed for event_id=%s: %s",
                event.event_id,
                exc,
                exc_info=True,
            )

    background_tasks.add_task(_safe_process)

    # --- Step 7: Immediate success response ---
    return JSONResponse(
        status_code=200,
        content={"status": "accepted", "event_id": event.event_id},
    )
