## Final Implementation

### `skills/billing/fsm.py` — FSM + Domain Events

**States:** `DRAFT → PENDING → ACTIVE → PAST_DUE → CANCELED` (plus `PAST_DUE → CANCELED` and `PENDING → CANCELED`)

**New capabilities added:**

| Feature | Description |
|---|---|
| `created_at` | Timestamp when the FSM is constructed, used for timeout calculations |
| `TIMEOUT_GRACE_PERIOD_SECONDS` | Module-level constant (24 hours) controlling auto-cancel window |
| `trigger_transition(action, now=...)` | Extended dispatcher; `"auto_cancel"` checks grace period before transitioning PENDING→CANCELED |
| `on_transition(handler)` / `remove_transition_handler(handler)` | Observer pattern — handlers receive every `TransitionEvent`, thread-safe |
| `TransitionEvent.extra` | Dict field on domain events (e.g., `{"reason": "grace_period_expired"}`) |

**Architecture highlights:**
- Transition rules stored in module-level dicts (`_TRANSITION_RULES`, `_ACTION_TARGETS`) — deep module with a simple public interface (`transition()`)
- Reentrant lock (`threading.RLock`) serializes concurrent access; race conditions produce `InvalidTransitionError` for the loser
- `_notify_handlers()` copies handler list under lock, then calls each with the event
- History returns a shallow copy (immutable from caller perspective)
