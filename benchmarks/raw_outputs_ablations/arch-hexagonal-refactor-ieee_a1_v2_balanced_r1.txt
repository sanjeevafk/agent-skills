## Architecture Overview

The monolithic order-processing service has been restructured into **5 clean layers** with strict inward dependencies:

```
┌─────────────────────────────────────────────┐
│  HTTP Request (FastAPI)                     │ ← adapters to domain only via use-cases
│  └── hub/__init__.py                       │   (composition root + route wiring)
├─────────────────────────────────────────────┤
│  Use Cases (workflow orchestration)         │
│  └── usecases.py                           │
│     CreateOrder, ConfirmOrder, CapturePay-  │
│     ment, CancelOrder, ShipOrder, Refund    │
│     Order, ProcessWebhook                   │
├─────────────────────────────────────────────┤
│  Domain Layer (pure business logic)         │
│  ├── entities.py – Money, LineItem, Order,  │
│  │                Customer, TransactionRecord│
│  └── errors.py – DomainError, ValidationError│
│              BusinessRuleError, ResourceNotFoundError│
├─────────────────────────────────────────────┤
│  Ports (abstract interfaces — import by      │
│       both domain and adapters)             │
│  ├── incoming.py – Command DTOs             │
│  │             CreateOrderCommand,           │
│  │             CancelOrderCommand, etc.      │
│  └── outgoing.py – ABC port interfaces      │
│              PaymentGateway,                │
│              InventoryRepository,           │
│              OrderRepository,               │
│              EmailNotifier                  │
├─────────────────────────────────────────────┤
│  Adapters (concrete implementations)        │
│  ├── sqlalchemy_repo.py                    │
│  │     SqlAlchemyOrderRepository,           │
│  │     SqlAlchemyInventoryRepository,       │
│  │     SqlAlchemyOutboxRepository          │
│  ├── stripe_gateway.py → StripePaymentGateway│
│  ├── sendgrid_notifier.py → SendGridEmailNotifier│
│  └── test_mocks.py → Fake*                 │
│            (all implement their ABCs)       │
├─────────────────────────────────────────────┤
│  Outbox Pattern (reliable event dispatch)   │
│  └── outbox/__init__.py                    │
│        OutboxEvent (domain), OutboxModel     │
│        (ORM), OutboxRepository (ABC)         │
│        (defined here, not conflated with   │
│        generic ports)                      │
└─────────────────────────────────────────────┘
```

## Bugs Fixed from Original Code

| Bug | File | Fix |
|-----|------|-----|
| Missing `datetime`/`uuid`/`select`/`AsyncSession` imports | `sqlalchemy_repo.py` | Added full import block at top |
| `hasattr(self, "payment_record")` always True for dataclass fields | `domain/entities.py` | Changed to `self.payment_record is not None` |
| Sync SQLAlchemy calls (`stripe`, `sendgrid`) used with `await` | `adapters/*.py` | Wrapped in `loop.run_in_executor(None, fn)` |
| Duplicate route handlers in `hub/__init__.py` AND `hub/http_handlers.py` | `hub/` | Deleted duplicate, single source of truth |
| `_resolve_inventory` created closure class on every call | `hub/__init__.py` | Moved to factory function in module scope |
| No `OutboxRepository` implementation | N/A | Created `SqlAlchemyOutboxRepository` + `FakeOutboxRepository` |
| `requires_refund()` check was unreliable | `domain/entities.py` | Proper null-check against field |
| Empty `__init__.py` files in all packages | All | Populated with public API exports |
| `DomainError` vs `BusinessRuleError` ambiguity | `usecases.py` | Consistent error propagation |
| `CreateOrder._build_summary()` called as staticmethod incorrectly | `usecases.py` | Made it a `@staticmethod` on `UseCaseBase` |

## New Capabilities Added

1. **Incoming ports split**: `ports/incoming.py` contains frozen dataclass commands; `ports/outgoing.py` contains ABC interfaces
2. **Outbox pattern**: `outbox/__init__.py` defines `OutboxEvent`, `OutboxModel` (ORM), and `OutboxRepository` ABC with full `publish`/`mark_delivered`/`fetch_pending`/`delete_old_delivered` contract
3. **New use cases**: `ConfirmOrder`, `ShipOrder`, `RefundOrder` complement the existing ones
4. **`refund` method** added to `PaymentGateway` port (Stripe gateway implements it)
5. **`send_refund_notification`** added to `EmailNotifier` port (SendGrid adapter implements it)
6. **`LineItem.remove_item(product_id)`** preserved from original, tested
7. **Comprehensive test suite** — 29 tests covering domain validation, use-case workflows, port contract compliance, and architecture isolation rules

## Composition Root

The hub acts as a proper DI composition root:

```python
# main.py
from .hub import create_app
from .config import Settings
app = create_app(Settings())
```

`create_app()` builds engines, resolves all 5 adapter types (order repo, inventory repo, payment gateway, email notifier, outbox repo), constructs 7 use-case instances, wires them into FastAPI routes, and registers exception-to-HTTP-mappers.
