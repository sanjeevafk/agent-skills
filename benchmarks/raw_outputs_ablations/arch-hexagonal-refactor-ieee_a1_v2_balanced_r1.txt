## Hexagonal Architecture — Order Processing Service

**Created `order_service/` with 20 files organized in 5 layers:**

### Core Layer (Domain)
- **`domain/models.py`** — Pure Python entities with business rules only:
  - `Order` aggregate root — validation (`validate()`), lifecycle transitions (`mark_paid()`, `mark_confirmed()`), computed properties (`subtotal`, `total`)
  - `OrderItem` frozen dataclass — immutable line items with calculated totals
  - `CustomerEntity` — customer lookup result with free-shipping eligibility logic
  - `PaymentResult` — outcome object with `is_success`/`is_failure` helpers
  - Enums: `OrderStatus`, `ChargeStatus`

### Application Layer
- **`app/use_cases.py`** — Three self-contained use-case classes (`CreateAndValidateOrder`, `ProcessPayment`, `ConfirmOrder`), each holding injected ports and exposing `execute(payload)`
- **`app/service.py`** — `OrderProcessingService` orchestrates the three-step flow: validate → pay → confirm, returning structured results

### Port Layer (Abstract Contracts)
- **`ports/port_interfaces.py`** — Five `@runtime_checkable Protocol` classes that inner layers depend on but outer adapters implement:
  - `OrderRepositoryPort` — persist/retrieve orders
  - `CustomerPort` — look up customers by email
  - `InventoryPort` — check stock levels
  - `PaymentPort` — charge customers via Stripe
  - `EmailPort` — send transactional emails

### Adapter Layer (Concrete Implementations)
- **`adapters/stripe_payment.py`** — Real `StripePaymentAdapter` wrapping the Stripe SDK, raises `PaymentError` on gateway failures
- **`adapters/sendgrid_email.py`** — Real `SendGridEmailAdapter` with HTML order confirmation templates, raises `NotificationError` on SMTP failures
- **`adapters/inventory_check.py`** — `InventoryCheckAdapter` with optional seedable catalog, raises `InventoryError` on insufficient stock or unknown SKUs
- **`adapters/repository_adapters.py`** — Thread-safe `InMemoryOrderRepository` and `InMemoryCustomerRepository` (demo/test replacements for production SQLAlchemy)

### Composition Root
- **`compose.py`** — `build_application()` wires all concrete adapters into the service; accepts optional keys/catalogs for overriding individual adapters without touching downstream code. Also includes `build_demo_graph()` pre-seeded with sample customers and inventory.

### Edge (FastAPI)
- **`app_module.py`** — FastAPI app at the boundary: minimal route handlers delegating entirely to `OrderProcessingService`, translating domain exceptions into proper HTTP status codes (400, 402, 422, 502, 500). Pydantic DTOs for request/response schema validation.

### Tests
- **`tests/test_app.py`** — Full suite with mocked ports: successful order flow, inventory shortage rejection (400), payment failure handling, email failure non-rollback pattern, repository CRUD, inventory edge cases, composition root wiring verification. Zero network calls.
