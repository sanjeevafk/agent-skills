## Design Decisions & How It Fits Together

### 1. `Result<T, E>` — The Foundation

Every function that can fail returns `Result<T, E>` — callers are forced at compile time to handle both branches. No unchecked exceptions escape.

**Combinators provided:**
- `ok(value)` / `err(error)` — constructors
- `map(result, fn)` — transforms success values, passes errors through
- `flatMap(result, fn)` — chains Result-returning operations; short-circuits on first Err
- `chain = flatMap` — alias for sequencing clarity
- `unwrapOr(result, fallback)` — extract value with default
- `unwrapOrElse(result, recover)` — extract value with recovery function
- `isOk(result)` / `isErr(result)` — type guards

### 2. `AppError` Hierarchy

Base class provides:
- **`code`** — machine-readable ErrorCodeType (routed by alerts, metrics, retry logic)
- **`message`** — human-friendly, safe for end-user display
- **`context`** — structured diagnostics (never surfaced raw to clients)
- **`toJSON()`** — strips internals for API envelopes (no stack traces)
- **`toJSONFull()`** — includes stack trace for server-side logging

**Concrete errors defined (all extend `AppError`):**
| Error Class | Code | When To Use |
|---|---|---|
| `PaymentFailedError` | PAYMENT_FAILED | Generic payment failure |
| `ChargeDeniedError` | CHARGE_DENIED | Policy/rule violation |
| `InsufficientFundsError` | INSUFFICIENT_FUNDS | Source lacks funds |
| `CardExpiredError` | CARD_EXPIRED | Payment source expired |
| `CardDeclinedError` | CARD_DECLINED | Issuer declined |
| `LedgerDuplicateError` | LEDGER_DUPLICATE | Idempotency violation |
| `LedgerNotFoundError` | LEDGER_NOT_FOUND | Entry not found |
| `CircuitOpenError` | CIRCUIT_OPEN | Service unavailable |
| `RetryExhaustedError` | RETRY_EXHAUSTED | All retries used up |
| `GatewayTimeoutError` | GATEWAY_TIMEOUT | Timeout exceeded |
| `RateLimitedError` | RATE_LIMITED | Rate limit hit |
| `UnknownAppError` | UNKNOWN | Wraps unexpected throwables |

### 3. Port Interfaces

**ChargerPort** — contract for external payment providers (Stripe, PayPal, etc.)
```typescript
interface ChargeRequest {
  amount: number               // smallest unit (e.g., cents)
  currency: string             // ISO 4217
  sourceToken: string          // tokenised payment source
  customerId: string
  metadata?: Record<string, string>
}

interface ChargeResponse {
  transactionId: string
  status: 'succeeded' | 'failed' | 'pending'
  amountCaptured: number
  currency: string
  processorReference: string
  fees: number
}

interface ChargerPort {
  charge(request: ChargeRequest): Promise<Result<ChargeResponse, AppError>>
}
```

**LedgerPort** — contract for financial ledger persistence
```typescript
interface LedgerPort {
  create(input: Omit<CreateTransactionInput, 'createdAt'>): Promise<Result<TransactionRecord, AppError>>
  getById(id: string): Promise<Result<TransactionRecord, AppError>>
}
```

Both return `Promise<Result<T, AppError>>` — callers never have to guess whether a function throws unexpectedly.

### 4. `retryWithBackoff` — Exponential Backoff + Jitter

```typescript
interface RetryOptions {
  maxAttempts: number              // total attempts incl. first call
  baseDelayMs: number              // delay = baseDelay × 2^(attempt-1)
  jitter: boolean                  // random offset [0, baseDelay] to prevent thundering herd
  retriableErrorCodes: Set<string> // codes worth retrying; others fail immediately
}
```

**Key behaviors:**
- **Fails fast** on non-retriable errors (CARD_EXPIRED, CARD_DECLINED, etc.) — no wasted time
- Only retries transient errors (GATEWAY_TIMEOUT, RATE_LIMITED, NETWORK_UNAVAILABLE)
- Delay formula: `baseDelay × 2^attempt + random_jitter`
- Catches sync throws inside the operation via try/catch
- On exhaustion, wraps the last error in `RetryExhaustedError`

Default retriable codes: `GATEWAY_TIMEOUT`, `RATE_LIMITED`, `NETWORK_UNAVAILABLE`

### 5. `CircuitBreaker` — Three-State Machine

```
CLOSED ──failureThreshold failures──→ OPEN ──recoveryTimeout──→ HALF_OPEN
   ↑                                      │                      │
   │               success                │ failure              │ success
   └──────────────────────────────────────┴──────────────────────┘
```

**State transitions:**
- **CLOSED → OPEN**: After `failureThreshold` consecutive failures
- **OPEN → HALF_OPEN**: After `recoveryTimeoutMs` elapses (automatic timer)
- **HALF_OPEN → CLOSED**: One successful probe request proves service recovered
- **HALF_OPEN → OPEN**: Any failure reopens immediately
- **CLOSED → CLOSED**: Success resets `consecutiveFailures` counter

**Public API:**
- `call(operation)` — gates the operation through the breaker
- `getState()` — returns current state (auto-transitions OPEN→HALF_OPEN)
- `getMetrics()` — observability: state, counts, timestamps
- `reset()` — manual reset to initial CLOSED state

**Engineering win:** When OPEN, calls fail immediately with `CircuitOpenError` — no wasted network round-trips or retry delays during an outage.

### 6. Error Boundary — Last Line of Defence

Two exports for different layers:

**`handleBoundary<T>(handler, options?)`** — wraps async handlers
```typescript
// Usage:
const env = await handleBoundary(async () => {
  return await chargingService.processCharge(request)
}, { requestId: 'req_abc123' })

// Returns typed envelope:
type ApiResponseEnvelope<T> = 
  | { success: true; data: T }
  | { success: false; error: { code: string; message: string; requestId?: string } }
```

Guarantees:
- User-facing payloads NEVER contain stack traces or internal details
- Full context logged server-side via `console.error('[error-boundary]', appError.toJSONFull())`
- Every path returns a typed `ApiResponseEnvelope` — callers pattern-match on `success`

**`ErrorBoundary` (React)** — catches render-phase errors
```tsx
<ErrorBoundary fallback={(error) => <ErrorUI error={error} />}>
  <Dashboard />
</ErrorBoundary>
```

### 7. Complete Workflow (from the example)

The `PaymentChargingService.processCharge()` method demonstrates the full pipeline:

```
User Request
    │
    ▼
processCharge(ChargeRequest)
    │
    ├── Attempt Charge
    │   ├── CircuitBreaker.call()     ← fails fast if OPEN
    │   │   └── ChargerPort.charge()   ← actual payment gateway
    │   └── retryWithBackoff()         ← retries transient errors
    │
    ├── If charge succeeded:
    │   └── LedgerPort.create()        ← record transaction
    │
    └── Return Result<TransactionRecord, AppError>
```

The example runs 5 test scenarios demonstrating happy paths, permanent failures, transient retry behavior, circuit breaker tripping, and the error boundary catching unexpected exceptions.

That's the full implementation. Each component respects the engineering standards: typed errors over strings, fail-fast, user messages separated from developer logs, never swallow errors, and every error code documented in the registry.
