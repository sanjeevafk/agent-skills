## Code Review: Subscription Billing FSM

### Architecture Overview

The implementation is a strict finite-state machine (`SubscriptionStateMachine`) with five states: `DRAFT → PENDING → ACTIVE → PAST_DUE → CANCELED`. It uses data-driven transition rules, immutable domain events, and thread-safe locking.

### Strengths

| Area | What's Good |
|------|-------------|
| **Test coverage** | 34 tests across 9 behavioral groups, exercising valid/invalid transitions, full lifecycle chains, concurrent races, timeouts, handlers, and edge cases |
| **Deep modules** | External API is minimal: `transition(action)`, `trigger_transition()`, `on_transition(handler)`, `history` property — everything else is internal |
| **Domain events** | `TransitionEvent` is a frozen dataclass with source/target/timestamp/extra — pure value object, no mutation |
| **Concurrency** | `threading.RLock` serializes all transitions; race conditions result in the first writer winning and subsequent writers getting `InvalidTransitionError` |
| **Rule-based design** | `_TRANSITION_RULES` + `_ACTION_TARGETS` make adding/removing transitions a one-line config change, not a logic change |

### Design Details

**State Transition Graph:**
```
DRAFT ──pending──→ PENDING ──activate──→ ACTIVE ──past_due──→ PAST_DUE ──resume──→ PENDING
                                          ↑                ↓
                                   cancel from PENDING/PAST_DUE → CANCELED (terminal)
```

**Key decisions:**
- Active cannot cancel directly — must go through `PAST_DUE` first (prevents accidental cancellation)
- `auto_cancel` only applies to `PENDING` subscriptions after 24h grace period
- History returns a defensive copy (immutable read-only view)
- Handlers are notified synchronously within the lock (simple but blocks other threads)

### Minor Issues

1. **Type annotation redundancy** (`fsm.py:86-88`): String annotations like `"callable[[TransitionEvent], None]"` are unnecessary — these resolve fine without quotes. Could use `collections.abc.Callable` for clarity.

2. **Duplicate import** (`test_subscriptions_fsm.py:313`): `import datetime` inside `test_detailed_timeout_error_message` shadows the module-level `from datetime import ...`. Works but redundant.

3. **Handler notification under lock** (`_notify_handlers` called inside `_lock`): In practice fine for sync handlers, but if a handler ever needs to call back into the FSM, it would re-acquire the RLock (which works since it's reentrant). Worth a docstring note if handlers become async.

4. **Grace period is absolute** (`created_at` comparison): Subscriptions entering `PENDING` via `resume` from `PAST_DUE` don't reset the timer. If that's desired, it should be tracked per-entry rather than globally. As-is, resuming a stale subscription still times out based on original creation time — either correct or a bug depending on business requirements.

### Verdict

Production-grade implementation. All 34 tests pass, concurrency is handled, domain events are clean, and the interface design is tight. Ready for integration.
