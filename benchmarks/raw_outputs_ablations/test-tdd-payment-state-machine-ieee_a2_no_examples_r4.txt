## Implementation (`skills/billing/fsm.py`)

**Architecture:**
- `SubscriptionState` enum — five states: DRAFT → PENDING → ACTIVE → PAST_DUE → CANCELED
- `InvalidTransitionError` — typed ValueError for invalid transitions
- `TransitionEvent` — frozen dataclass domain event with source, target, timestamp, and extra metadata
- `SubscriptionStateMachine` — the core FSM with strict transition enforcement via `_TRANSITION_RULES` lookup table

**Key design decisions:**
- **Thread-safe** via `threading.RLock` — serializes concurrent `transition()` calls; if two threads race, the first succeeds and the second observes the new state and rejects
- **Transition rules are data-driven**, not hard-coded if/elif chains — adding/removing transitions is a one-line dict change
- **Handler isolation** — exceptions in one callback don't affect others, logged rather than propagated
- **History immutability** — returns a copy on every access via `list(self._history)`
- **Timeout auto-cancel** — only applies to PENDING state after 86400s grace period, with exact boundary semantics (`<` comparison) and naive datetime coercion
