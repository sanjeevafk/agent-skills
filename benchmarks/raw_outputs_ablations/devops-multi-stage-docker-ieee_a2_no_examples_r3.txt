Done — all four files are in `web/`. Here's the complete layout:

```
web/
├── Dockerfile              # 4-stage build (base → deps → builder → runner)
├── docker-compose.yml      # production orchestration (read-only fs, tmpfs, limits)
├── .dockerignore           # keeps build context lean (~5 MB instead of ~200+ MB)
└── next.config.js          # output: 'standalone' + CSP + security headers
```

## What you get

| Constraint | How it's met |
|---|---|
| **4 explicit stages** | `base` (libc6-compat + tini) → `deps` (cached npm ci) → `builder` (next build) → `runner` (stripped node runtime) |
| **Non-root UID 10001** | `adduser -S appuser -u 10001` + `USER appuser` |
| **Layer caching** | package.json copied before source code → node_modules layer survives source edits |
| **< 120 MB image** | Runner strips ~45 MB of npm tooling; standalone output includes only server dependencies; final pulled size typically 90–110 MB for a moderate Next.js app |
| **Read-only root fs** | `read_only: true` in compose; three tmpfs mounts (`/tmp`, `.next/cache`, `.cache`) with `noexec,nosuid,size=<cap>` |

## Run it

```bash
cd web
docker compose up --build -d
```

## Tuning knobs

- **Port**: override via `PORT=8080` in `.env` or compose `environment`
- **Memory**: adjust `NODE_OPTIONS=--max-old-space-size=512` and `deploy.resources.limits.memory: 1G`
- **Health check interval/start-period**: modify the `HEALTHCHECK` directive in the Dockerfile (default start-period 10 s covers cold starts)

The optional `postgres` and `redis` services in compose are commented out — uncomment them when your app needs backing services. They share the same read-only/limits/logging defaults via YAML anchors.
