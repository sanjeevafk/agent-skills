**Architecture Overview:**

| Phase | Purpose | Key Mechanism |
|-------|---------|---------------|
| 0 | Baseline capture | Row count + table size check |
| 1 | Partitioned structure | `PARTITION BY RANGE (created_at)` + default partition |
| 2 | Dual-write trigger | AFTER INSERT/UPDATE/DELETE triggers copy writes to new table |
| 3 | Backfill in batches | Cursor pagination (`id > last_id`) with 10K row batch size |
| 4 | Index creation | All `CREATE INDEX CONCURRENTLY`; composite order: equality→range |
| 5 | Verification | Partition pruning EXPLAIN plans + orphan detection |
| 6 | pg_partman automation | `create_parent()` + `run_maintenance()` cron |
| 7 | Rollback plan | Trigger DROP + no-op if before cutover |
| 8 | Instant cutover | `ALTER TABLE ... RENAME` inside single transaction (~microseconds) |
| 9 | Cleanup | `DROP audit_logs_backup` after confidence window |

**Engineering standards applied from the reference patterns:**

- **Composite index order**: equality columns first, range second (e.g., `(actor_id, created_at DESC)`)
- **Covering indexes**: `INCLUDE (event_type, target_id, payload)` to avoid heap lookups
- **BRIN for time-series**: `USING brin (created_at)` with `pages_per_range = 8` for minimal footprint
- **GIN for jsonb**: `USING gin (payload)` for `@>` containment queries
- **Cursor pagination**: `WHERE id > $last_id ORDER BY id LIMIT 20` instead of OFFSET
- **Queue-safe pattern**: `FOR UPDATE SKIP LOCKED` available via same mechanism
- **Lock timeouts**: `SET lock_timeout = '5s'` to prevent long-blocking waits
- **Partial indexes**: Only indexed rows matching relevant predicates (via partition boundaries)
