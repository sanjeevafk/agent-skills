## Security Review: FastAPI Payment Webhook

### Vulnerabilities (Ordered by Severity)

**CRITICAL: Signature Verification After JSON Parsing**
The current code parses the body before verifying the signature. An attacker can send crafted payloads that get deserialized, potentially triggering resource exhaustion, prototype pollution in Pydantic models, or logic bugs in the parser. The fix is to verify the signature on the raw bytes first, then parse only if valid.

**CRITICAL: In-Memory Replay Store**
Using a dict means replay protection vanishes on restart, doesn't scale across instances, and leaks memory indefinitely. This needs a persistent, shared store like Redis with TTL-based expiration.

**HIGH: No Concurrency Control for Idempotency**
Without locking, two simultaneous requests with the same event-id can both pass the "not seen" check before either writes, causing double processing. A distributed lock tied to the event-id prevents this race condition.

**HIGH: Error Leaking**
Unhandled exceptions return stack traces to the client, which exposes internal paths and library versions—valuable reconnaissance for attackers.

**MEDIUM: No Timestamp Validation**
Without checking the message timestamp, old signed payloads can be replayed forever. Adding a timestamp field and rejecting messages older than a threshold (like 5 minutes) closes this window.

**MEDIUM: No Request Size Limit**
An attacker could send multi-megabyte payloads to exhaust memory before signature verification even runs.

```python
# webhook.py
import hashlib
import hmac
import time
import logging
from typing import Optional

from fastapi import FastAPI, Request, HTTPException, status
from fastapi.responses import JSONResponse
from pydantic import BaseModel, Field, ValidationError
import redis

logger = logging.getLogger(__name__)

app = FastAPI()

# Configuration - secrets from environment, never hardcoded
WEBHOOK_SECRET_CURRENT = "current_secret_from_env"  # os.environ["WEBHOOK_SECRET_CURRENT"]
WEBHOOK_SECRET_PREVIOUS = "previous_secret_from_env"  # os.environ["WEBHOOK_SECRET_PREVIOUS"] (for rotation)
MAX_TIMESTAMP_AGE_SECONDS = 300  # 5 minutes
MAX_BODY_SIZE = 1_000_000  # 1MB max payload

# Redis for replay protection and distributed locking
redis_client = redis.Redis(host='localhost', port=6379, db=0, decode_responses=True)
REPLAY_TTL = 86400 * 7  # 7 days retention for replay IDs
LOCK_TTL = 30  # 30 seconds max processing time per event


class WebhookPayload(BaseModel):
    """Validated payload structure - only after signature verification."""
    event_id: str = Field(..., min_length=1, max_length=128)
    event_type: str = Field(..., min_length=1, max_length=64)
    timestamp: int  # Unix timestamp from processor
    data: dict = Field(default_factory=dict)


class WebhookResponse(BaseModel):
    status: str
    event_id: str


def verify_signature(raw_body: bytes, signature: str) -> bool:
    """
    Verify HMAC-SHA256 signature against raw bytes.
    Tries current secret first, then previous secret for rotation window.
    """
    if not signature:
        return False

    for secret in [WEBHOOK_SECRET_CURRENT, WEBHOOK_SECRET_PREVIOUS]:
        expected = hmac.new(
            secret.encode('utf-8'),
            raw_body,
            hashlib.sha256
        ).hexdigest()

        if hmac.compare_digest(expected, signature):
            return True

    return False


def is_replay(event_id: str) -> bool:
    """Check if event_id has been seen before using Redis."""
    return redis_client.exists(f"replay:{event_id}") == 1


def mark_processed(event_id: str) -> None:
    """Mark event_id as processed with TTL."""
    redis_client.setex(f"replay:{event_id}", REPLAY_TTL, "1")


def acquire_processing_lock(event_id: str) -> Optional[str]:
    """
    Acquire distributed lock for concurrent idempotency.
    Returns lock token if acquired, None if already locked.
    """
    lock_token = f"lock:{event_id}:{time.time()}"
    acquired = redis_client.set(
        f"processing:{event_id}",
        lock_token,
        nx=True,  # Only set if not exists
        ex=LOCK_TTL
    )
    return lock_token if acquired else None


def release_processing_lock(event_id: str, lock_token: str) -> None:
    """Release lock only if we still own it (prevent releasing another's lock)."""
    lock_key = f"processing:{event_id}"
    # Lua script for atomic check-and-delete
    release_script = """
    if redis.call("get", KEYS[1]) == ARGV[1] then
        return redis.call("del", KEYS[1])
    else
        return 0
    end
    """
    redis_client.eval(release_script, 1, lock_key, lock_token)


def validate_timestamp(timestamp: int) -> bool:
    """Reject messages older than MAX_TIMESTAMP_AGE_SECONDS."""
    now = int(time.time())
    age = abs(now - timestamp)
    return age <= MAX_TIMESTAMP_AGE_SECONDS


def process_webhook(payload: WebhookPayload) -> None:
    """
    Idempotent business logic for the webhook.
    This function must be safe to call multiple times with the same event_id.
    """
    # Your idempotent processing logic here
    # Example: upsert payment record keyed by event_id
    logger.info(f"Processing webhook: {payload.event_id} type={payload.event_type}")


@app.post("/webhooks/payment")
async def payment_webhook(request: Request):
    """
    Secure payment webhook endpoint.
    
    Security properties:
    1. Signature verified on raw bytes BEFORE any parsing
    2. Timestamp validation prevents indefinite replay window
    3. Redis-backed replay protection survives restarts and scales horizontally
    4. Distributed lock prevents concurrent duplicate processing
    5. Generic error responses leak no internal details
    """
    # Step 1: Read raw body with size limit
    try:
        raw_body = await request.body()
    except Exception:
        raise HTTPException(status_code=413, detail="Payload too large")

    if len(raw_body) > MAX_BODY_SIZE:
        raise HTTPException(status_code=413, detail="Payload too large")

    # Step 2: Extract and verify signature on RAW bytes (before parsing)
    signature = request.headers.get("X-Signature", "")
    if not verify_signature(raw_body, signature):
        logger.warning("Invalid signature received")
        raise HTTPException(status_code=401, detail="Invalid signature")

    # Step 3: Only NOW parse the JSON body (after signature verified)
    try:
        json_data = await request.json()
    except Exception:
        raise HTTPException(status_code=400, detail="Invalid JSON")

    # Step 4: Validate payload structure
    try:
        payload = WebhookPayload(**json_data)
    except ValidationError as e:
        logger.warning(f"Payload validation failed: {e}")
        raise HTTPException(status_code=422, detail="Invalid payload structure")

    # Step 5: Validate timestamp (prevent replay of old signed messages)
    if not validate_timestamp(payload.timestamp):
        logger.warning(f"Stale timestamp for event {payload.event_id}")
        raise HTTPException(status_code=400, detail="Request expired")

    # Step 6: Check replay (Redis-backed, survives restarts)
    if is_replay(payload.event_id):
        logger.info(f"Duplicate event received: {payload.event_id}")
        return JSONResponse(
            status_code=200,
            content={"status": "already_processed", "event_id": payload.event_id}
        )

    # Step 7: Acquire distributed lock for concurrent idempotency
    lock_token = acquire_processing_lock(payload.event_id)
    if lock_token is None:
        # Another instance is processing this event - return success
        logger.info(f"Event {payload.event_id} already being processed")
        return JSONResponse(
            status_code=200,
            content={"status": "processing", "event_id": payload.event_id}
        )

    try:
        # Step 8: Double-check replay after acquiring lock (race condition guard)
        if is_replay(payload.event_id):
            return JSONResponse(
                status_code=200,
                content={"status": "already_processed", "event_id": payload.event_id}
            )

        # Step 9: Process the webhook (idempotent business logic)
        process_webhook(payload)

        # Step 10: Mark as processed
        mark_processed(payload.event_id)

        return WebhookResponse(status="processed", event_id=payload.event_id)

    except Exception as e:
        # Log full error internally, return generic message externally
        logger.error(f"Error processing webhook {payload.event_id}: {repr(e)}", exc_info=True)
        raise HTTPException(
            status_code=500,
            detail="Internal processing error"
        )
    finally:
        # Always release the lock
        release_processing_lock(payload.event_id, lock_token)


@app.exception_handler(Exception)
async def generic_exception_handler(request: Request, exc: Exception):
    """Catch-all to prevent any unhandled exception from leaking details."""
    if isinstance(exc, HTTPException):
        return JSONResponse(status_code=exc.status_code, content={"detail": exc.detail})
    logger.error(f"Unhandled exception: {repr(exc)}", exc_info=True)
    return JSONResponse(
        status_code=500,
        content={"detail": "Internal server error"}
    )
```

### Key Security Fixes Applied

| Vulnerability | Fix |
|---|---|
| Signature after parsing | Verify HMAC on raw bytes **before** `request.json()` |
| In-memory replay store | Redis with 7-day TTL, survives restarts, shared across instances |
| Concurrent duplicates | Distributed lock via `SET NX` with Lua-based safe release |
| Error leaking | Generic 500 response, full details only in server logs |
| No timestamp validation | Reject messages older than 5 minutes |
| No size limit | 1MB cap on raw body before any processing |
| Secret rotation | Tries current + previous secret in verification |

### Deployment Notes

- Store secrets in environment variables or a secrets manager (Vault, AWS Secrets Manager), never in code
- Run Redis with persistence enabled (AOF or RNS) for replay protection durability
- Set up monitoring on 401 rates (signature failures) to detect attacks
- The `process_webhook` function must be idempotent—design it to safely handle being called multiple times with the same `event_id`
