### Critical Enhancements from v1

| Enhancement | Rationale |
|-------------|-----------|
| **Full DML trigger** (INSERT+UPDATE+DELETE) | v1 only captured INSERTs — updates/deletes during backfill would be lost |
| **Lock timeout error handling** | Backfill procedure now catches `lock_not_available`, waits, retries (3x max) |
| **Identity sequence sync** | Prevents ID collisions after rename by calling `setval()` on the sequence |
| **Partition-wise operations** | `enable_partitionwise_join/aggregate` — crucial for cross-partition query performance |
| **BRIN index** | Tiny index (~1000x smaller than B-tree) for time-range scans on chronologically-ordered data |
| **Pre-flight checks** | Backfill runner validates connectivity, control table, and current status before starting |
| **Real-time monitoring views** | `v_migration_progress`, `v_partition_health`, `v_partition_index_usage` |

### Index Strategy (Per Engineering Standards)

```sql
-- Composite: equality-first, range-second
(idx_audit_logs_new_user_id_occurred_at) ON (user_id, occurred_at DESC)

-- Covering: INCLUDE for index-only scans
(idx_audit_logs_new_covering) ON (occurred_at, user_id, action)
    INCLUDE (resource_type, resource_id, severity)

-- Partial: smaller, targeted
(idx_audit_logs_new_severity_error) ON (occurred_at DESC)
    WHERE severity IN ('error', 'critical')

-- GIN: JSONB containment (@>, ?, ?&)
(idx_audit_logs_new_details_gin) USING gin (details jsonb_path_ops)

-- BRIN: time-series ranges (naturally ordered)
(idx_audit_logs_new_occurred_at_brin) USING brin (occurred_at)
```
