All four files already exist with comprehensive implementations. Here's the complete zero-downtime migration strategy:

## Migration Architecture

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        ZERO-DOWNTIME PARTITION MIGRATION                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  Phase 1-2: Create partitioned shadow table + initial partitions            │
│  Phase 3:    Install dual-write trigger (captures live changes)             │
│  Phase 4:    Batch backfill with lock timeouts (resumable)                  │
│  Phase 5:    Run backfill via shell script (parallel sessions)               │
│  Phase 6:    Create indexes CONCURRENTLY                                    │
│  Phase 7:    Data validation                                                │
│  Phase 8:    Atomic swap (brief lock, ~seconds)                             │
│  Phase 9:    Configure pg_partman for automated management                  │
│  Phase 10:   Post-migration cleanup                                         │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## Key Files

| File | Purpose |
|------|---------|
| `scripts/partition_migration.sql` | Main DDL: shadow table, trigger, backfill procedure, atomic swap |
| `scripts/run_backfill.sh` | Shell runner: concurrent batches, logging, resumable |
| `scripts/verify_pruning.sql` | 10 pruning tests + index usage + performance baselines |
| `scripts/pg_partman_maintenance.sql` | Automated future partitions + monitoring + alerting |

## Execution Steps

```bash
# 1. Run migration DDL (creates shadow table + trigger)
psql -f scripts/partition_migration.sql

# 2. Run backfill in parallel (4 sessions for 500M rows)
# Session 1:
BATCH_SIZE=50000 START_ID=1 END_ID=125000000 SESSION_ID=s1 \
  ./scripts/run_backfill.sh

# Session 2:
BATCH_SIZE=50000 START_ID=125000001 END_ID=250000000 SESSION_ID=s2 \
  ./scripts/run_backfill.sh

# Session 3:
BATCH_SIZE=50000 START_ID=250000001 END_ID=375000000 SESSION_ID=s3 \
  ./scripts/run_backfill.sh

# Session 4:
BATCH_SIZE=50000 START_ID=375000001 END_ID=500000000 SESSION_ID=s4 \
  ./scripts/run_backfill.sh

# 3. Verify pruning works
psql -f scripts/verify_pruning.sql

# 4. Run pg_partman maintenance setup
psql -f scripts/pg_partman_maintenance.sql
```

## Key Design Decisions

1. **Shadow table approach** - Original table stays live during entire backfill
2. **Dual-write trigger** - Captures INSERTs during backfill, zero data loss
3. **Keyset pagination** - `WHERE id > last_id` for O(1) batch processing (no OFFSET)
4. **Lock timeouts** - `SET lock_timeout = 5ms` prevents blocking production
5. **ON CONFLICT DO NOTHING** - Idempotent batches, safe to retry
6. **Atomic swap** - Brief ACCESS EXCLUSIVE lock only during rename (~seconds)
7. **pg_partman** - Automated future partition creation + retention enforcement
