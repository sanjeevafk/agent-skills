I'll analyze the vulnerabilities in order of severity and provide a corrected implementation.

## Vulnerabilities (by severity)

1. **CRITICAL: Signature verified AFTER JSON parsing** — Attacker-controlled input is processed before authentication. Malicious payloads can exploit parser vulnerabilities (billion laughs, stack exhaustion) or trigger side effects in custom decoders.

2. **HIGH: In-memory replay ledger** — Lost on restart, not shared across instances. Replays succeed after deployment or with multiple workers.

3. **HIGH: No concurrency-safe idempotency** — Race window between check-and-insert allows duplicate processing under concurrent duplicate webhooks.

4. **MEDIUM: Processor errors leak to clients** — Stack traces, internal paths, or database errors exposed in responses.

5. **MEDIUM: No rate limiting** — Endpoint vulnerable to volumetric abuse.

def verify_signature(raw_body: bytes, signature_header: str, secrets: list[str]) -> bool:
    """
    Verify HMAC-SHA256 signature against raw body.
    Try current secret first, then previous (for rotation window).
    """
    if not signature_header:
        return False

    for secret in secrets:
        expected = hmac.new(
            secret.encode(),
            raw_body,
            hashlib.sha256
        ).hexdigest()

        # Constant-time comparison to prevent timing attacks
        if hmac.compare_digest(expected, signature_header):
            return True

    return False


def check_rate_limit(client_ip: str, max_requests: int = 100, window: int = 60) -> bool:
    """Sliding window rate limit using Redis."""
    key = f"webhook:ratelimit:{client_ip}"
    now = time.time()
    pipe = redis.pipeline()
    pipe.zremrangebyscore(key, 0, now - window)
    pipe.zadd(key, {str(now): now})
    pipe.zcard(key)
    pipe.expire(key, window)
    _, _, count, _ = pipe.execute()
    return count <= max_requests


def record_event_idempotent(event_id: str, db, response_body: Optional[str] = None) -> bool:
    """
    Atomically record event. Returns True if new (should process),
    False if already seen (replay). Uses INSERT ... ON CONFLICT for
    concurrency safety.
    """
    stmt = pg_insert(ProcessedEvent).values(
        event_id=event_id,
        response_body=response_body
    ).on_conflict_do_nothing(
        index_elements=["event_id"]
    )

    result = db.execute(stmt)
    db.commit()
    return result.rowcount > 0  # True if inserted, False if conflict

## Key Fixes Summary

| Vulnerability | Fix |
|---|---|
| Signature after parsing | Verify HMAC on **raw bytes** before `json.loads()` |
| In-memory replay ledger | PostgreSQL with `ON CONFLICT DO NOTHING` |
| Concurrent duplicates | Atomic insert — rowcount check prevents race |
| Error leakage | Generic 200 response to processor; detailed logs internally |
| Secret rotation | Try current + previous secret |
| Timing attacks | `hmac.compare_digest()` instead of `==` |
| Rate limiting | Redis-backed sliding window before any processing |
