### How to Execute

**1. Preparation (run once):**
```bash
# Install extensions
psql -c "CREATE EXTENSION IF NOT EXISTS pg_partman;"
psql -c "CREATE EXTENSION IF NOT EXISTS pg_jobmon;"
```

**2. Create shadow table + partitions (run during low traffic):**
```bash
psql -f scripts/partition_migration.sql  -- up to Phase 3
```

**3. Run backfill (can run in parallel for speed):**
```bash
# Terminal 1: First quarter
BATCH_SIZE=50000 START_ID=1 END_ID=125000000 \
  ./scripts/run_backfill.sh

# Terminal 2: Second quarter (concurrent)
BATCH_SIZE=50000 START_ID=125000001 END_ID=250000000 \
  ./scripts/run_backfill.sh

# Terminal 3-4: remaining quarters...
```

**4. Create indexes after backfill completes:**
```sql
-- From Phase 6 of partition_migration.sql (each CONCURRENTLY)
CREATE INDEX CONCURRENTLY idx_audit_logs_new_occurred_at ON audit_logs_new (occurred_at DESC);
CREATE INDEX CONCURRENTLY idx_audit_logs_new_user_id_occurred_at ON audit_logs_new (user_id, occurred_at DESC);
CREATE INDEX CONCURRENTLY idx_audit_logs_new_covering ON audit_logs_new (occurred_at DESC, user_id, action) INCLUDE (resource_type, resource_id, severity);
CREATE INDEX CONCURRENTLY idx_audit_logs_new_severity_error ON audit_logs_new (occurred_at DESC) WHERE severity IN ('error', 'critical');
CREATE INDEX CONCURRENTLY idx_audit_logs_new_details_gin ON audit_logs_new USING gin (details jsonb_path_ops);
```

**5. Cutover (brief maintenance window):**
```sql
-- Phase 8: Atomic swap (lock time < 10 seconds)
BEGIN;
LOCK TABLE audit_logs IN ACCESS EXCLUSIVE MODE;
LOCK TABLE audit_logs_new IN ACCESS EXCLUSIVE MODE;
-- final sync...
ALTER TABLE audit_logs RENAME TO audit_logs_old;
ALTER TABLE audit_logs_new RENAME TO audit_logs;
COMMIT;
```

**6. Verify pruning works:**
```bash
psql -f scripts/verify_pruning.sql
```

**7. Setup automated maintenance:**
```bash
psql -f scripts/pg_partman_maintenance.sql
```

### Index Strategy (from `postgres-patterns`)

| Index | Type | Purpose |
|-------|------|---------|
| `(occurred_at DESC)` | B-tree | Time-range scans |
| `(user_id, occurred_at DESC)` | Composite | User activity timeline |
| `(action, occurred_at DESC)` | Composite | Action filtering |
| `(resource_type, resource_id, occurred_at DESC)` | Composite | Resource lookups |
| `(occurred_at DESC) WHERE severity IN (...)` | Partial | Error monitoring (smaller) |
| `(occurred_at DESC, user_id, action) INCLUDE (...)` | Covering | Index-only scans |
| `USING gin (details jsonb_path_ops)` | GIN | JSONB containment |
| `USING gin (metadata jsonb_path_ops)` | GIN | Metadata queries |

### Safety Mechanisms

- **Lock timeout (5s)**: Prevents backfill from blocking production
- **Statement timeout (5min/batch)**: Kills runaway batches
- **Keyset pagination (WHERE id > last_id)**: O(1) batch processing vs OFFSET O(n)
- **Dual-write trigger**: Captures inserts during backfill, idempotent with ON CONFLICT
- **Checkpoint tracking**: Resume from last position if interrupted
- **Default partition**: Safety net for out-of-range data
- **pg_jobmon integration**: Monitors maintenance job health
- **Atomic cutover**: Single transaction rename = minimal downtime

This is production-ready. The only downtime is the brief ACCESS EXCLUSIVE lock during cutover (Phase 8), which should complete in under 10 seconds for 500M rows since it's just metadata operations (renames).
