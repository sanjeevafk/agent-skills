Done! I've created a complete zero-downtime partitioning migration strategy with four files:

**`scripts/partition_migration.sql`** — The main migration DDL:
- Phase 0-1: Creates the partitioned shadow table with monthly range partitions
- Phase 2: Creates 40+ partitions (3 years back + future buffer + default)
- Phase 3: Dual-write trigger captures inserts during backfill
- Phase 4: Batch backfill procedure with keyset pagination, lock timeouts, and progress tracking
- Phase 5: Execution options (single or parallel sessions)
- Phase 6: Post-backfill index creation (CONCURRENTLY)
- Phase 7: Data validation queries
- Phase 8: Atomic cutover with brief metadata lock (~2-10 seconds)
- Phase 9: pg_partman registration for automated future partitions
- Phase 10: Post-migration cleanup

**`scripts/run_backfill.sh`** — Executable runner with configurable batch size, lock timeout, and parallel session support.

**`scripts/verify_pruning.sql`** — 10 partition pruning verification tests with expected outcomes.

**`scripts/pg_partman_maintenance.sql`** — Ongoing maintenance: scheduling, monitoring queries, alerting, and emergency procedures.

Key design decisions:
- **50k row batches** with 50ms pauses = ~1000 rows/sec (conservative, ~35 hours parallelized)
- **Dual-write trigger** ensures zero data loss during backfill
- **ON CONFLICT DO NOTHING** handles trigger race conditions
- **pg_partman** auto-creates 3 months ahead, auto-drops after 24 months
- **Cutover lock time** is typically 2-10 seconds (just the rename + final sync)
