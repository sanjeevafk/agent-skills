Looking at this problem, I need to apply the zero-downtime migration strategy: **EXPAND → MIGRATE → CONTRACT**. The key insight is that for 500M rows, we can't use `ALTER TABLE ... PARTITION BY` (it requires an ACCESS EXCLUSIVE lock). Instead, we use table renaming with a view for transparent access.

Here's the complete production-grade implementation:

## Phase 0: Pre-Migration Setup

## Phase 1: EXPAND — Create Partitioned Structure

```sql
-- 0002_create_partitioned_table.sql
-- Creates new partitioned table alongside original

-- Step 1: Rename original table (brief metadata lock only)
ALTER TABLE audit_logs RENAME TO audit_logs_old;

-- Step 2: Create partitioned table with same structure
CREATE TABLE audit_logs (
    id              bigint GENERATED ALWAYS AS IDENTITY,
    org_id          bigint NOT NULL,
    user_id         bigint,
    action          text NOT NULL,
    resource_type   text NOT NULL,
    resource_id     text,
    metadata        jsonb DEFAULT '{}',
    ip_address      inet,
    created_at      timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (id, created_at)  -- partition key must be in PK
) PARTITION BY RANGE (created_at);

-- Step 3: Create indexes on partitioned table (concurrent, no locks)
-- These will auto-propagate to new partitions
CREATE INDEX CONCURRENTLY idx_audit_logs_org_created
    ON audit_logs (org_id, created_at);

CREATE INDEX CONCURRENTLY idx_audit_logs_action
    ON audit_logs (action, created_at);

CREATE INDEX CONCURRENTLY idx_audit_logs_metadata
    ON audit_logs USING gin (metadata);

-- Step 4: Attach old table as default partition for drift data
ALTER TABLE audit_logs ATTACH PARTITION audit_logs_old
    DEFAULT;

-- Step 5: Create view for backward-compatible access if needed
CREATE VIEW audit_logs_unified AS
    SELECT * FROM audit_logs;

COMMENT ON TABLE audit_logs IS 'Partitioned audit logs - managed by pg_partman';
```

## Phase 2: Backfill Script (Concurrent, Batched)

```sql
-- 0003_backfill_partition_data.sql
-- Run this repeatedly until backfill completes
-- Safe to run during production traffic

DO $$
DECLARE
    batch_size CONSTANT int := 50000;  -- ~50ms per batch
    lock_timeout CONSTANT text := '5s';
    rows_moved int;
    total_moved int := 0;
    batch_start timestamptz;
    min_date timestamptz;
    max_date timestamptz;
BEGIN
    -- Get date range from old table
    SELECT MIN(created_at), MAX(created_at)
    INTO min_date, max_date
    FROM audit_logs_old;

    RAISE NOTICE 'Backfill range: % to %', min_date, max_date;

    -- Process month by month
    FOR batch_start IN
        SELECT generate_series(
            date_trunc('month', min_date),
            date_trunc('month', max_date),
            interval '1 month'
        )
    LOOP
        -- Create partition if it not exists (idempotent)
        BEGIN
            EXECUTE format(
                'CREATE TABLE IF NOT EXISTS audit_logs_%s PARTITION OF audit_logs
                 FOR VALUES FROM (%L) TO (%L)',
                to_char(batch_start, 'YYYYMM'),
                batch_start,
                batch_start + interval '1 month'
            );
        EXCEPTION WHEN duplicate_table THEN
            NULL; -- Already exists, continue
        END;

        -- Backfill in batches with lock timeout
        LOOP
            SET LOCAL lock_timeout = lock_timeout;

            WITH moved AS (
                DELETE FROM audit_logs_old
                WHERE id IN (
                    SELECT id FROM audit_logs_old
                    WHERE created_at >= batch_start
                      AND created_at < batch_start + interval '1 month'
                    ORDER BY id
                    LIMIT batch_size
                    FOR UPDATE SKIP LOCKED
                )
                RETURNING *
            )
            INSERT INTO audit_logs
            SELECT * FROM moved
            ON CONFLICT (id, created_at) DO NOTHING;

            GET DIAGNOSTICS rows_moved = ROW_COUNT;
            total_moved := total_moved + rows_moved;

            -- Commit point per batch
            COMMIT;

            EXIT WHEN rows_moved = 0;

            -- Throttle to reduce I/O pressure
            PERFORM pg_sleep(0.1);
        END LOOP;

        RAISE NOTICE 'Completed partition: % (%) rows total',
            batch_start, total_moved;
    END LOOP;
END $$;
```

```bash
#!/bin/bash
# run_backfill.sh — Execute backfill with monitoring
# Usage: ./run_backfill.sh [connection_string]

set -euo pipefail

DATABASE_URL="${1:-$DATABASE_URL}"
BATCH_LOG="/tmp/backfill_$(date +%Y%m%d_%H%M%S).log"

echo "Starting backfill at $(date)"
echo "Logging to: $BATCH_LOG"

# Run backfill in loop until old table is empty
while true; do
    remaining=$(psql "$DATABASE_URL" -t -A -c \
        "SELECT count(*) FROM audit_logs_old" 2>/dev/null)

    if [[ "$remaining" -eq 0 ]]; then
        echo "Backfill complete at $(date)"
        break
    fi

    echo "$(date) - Remaining rows: $remaining" | tee -a "$BATCH_LOG"

    psql "$DATABASE_URL" -f 0003_backfill_partition_data.sql \
        >> "$BATCH_LOG" 2>&1 || {
            echo "ERROR: Backfill failed. Check $BATCH_LOG"
            exit 1
        }

    # Throttle between runs
    sleep 5
done
```

## Phase 3: pg_partman Automated Management

```sql
-- 0004_setup_pg_partman.sql
-- Automated future partition creation and retention

-- Create parent table entry in pg_partman
SELECT partman.create_parent(
    p_parent_table := 'public.audit_logs',
    p_control := 'created_at',
    p_type := 'range',
    p_interval := '1 month',
    p_premake := 3,           -- Create 3 months ahead
    p_start_partition := (
        SELECT to_char(date_trunc('month', MIN(created_at)), 'YYYY-MM-DD')
        FROM audit_logs
    )
);

-- Configure retention policy (keep 24 months)
UPDATE partman.part_config
SET
    retention = '24 months',
    retention_keep_table = false,    -- Drop old partitions entirely
    retention_keep_index = false,
    infinite_premake = true           -- Always keep future partitions ready
WHERE parent = 'public.audit_logs';

-- Schedule maintenance (runs daily via pg_cron or external scheduler)
-- Option A: pg_cron
SELECT cron.schedule('audit-logs-maintenance', '0 2 * * *', $$
    SELECT partman.partition_data_time(
        p_parent_table := 'public.audit_logs',
        p_batch_count := 10,
        p_batch_interval := '1 month'
    );

    -- Run partition maintenance (create future, drop old)
    SELECT partman.run_maintenance(
        p_parent_table := 'public.audit_logs'
    );
$$);
```

```sql
-- Run these to confirm partition pruning is working

-- Check 1: EXPLAIN shows partition pruning
EXPLAIN (ANALYZE, BUFFERS, FORMAT TEXT)
SELECT * FROM audit_logs
WHERE created_at >= '2026-08-01'
  AND created_at < '2026-09-01'
  AND org_id = 123;

-- Expected: Only scans audit_logs_202608 partition


-- Check 2: Verify partition is used (not full scan)
EXPLAIN (COSTS OFF)
SELECT count(*) FROM audit_logs
WHERE created_at BETWEEN '2026-07-01' AND '2026-07-31';

-- Expected: "Seq Scan on audit_logs_202607" only


-- Check 3: Count rows per partition (validate distribution)
SELECT
    tableoid::regclass AS partition_name,
    count(*) AS row_count,
    min(created_at) AS min_date,
    max(created_at) AS max_date
FROM audit_logs
GROUP BY tableoid
ORDER BY partition_name;


-- Check 4: pg_partman status
SELECT * FROM partman.part_config WHERE parent = 'public.audit_logs';


-- Check 5: Verify future partitions exist
SELECT
    parent.relname AS parent_table,
    child.relname AS partition_name,
    pg_get_expr(child.relpartbound, child.oid) AS partition_range
FROM pg_inherits
JOIN pg_class parent ON pg_inherits.inhparent = parent.oid
JOIN pg_class child ON pg_inherits.inhrelid = child.oid
WHERE parent.relname = 'audit_logs'
ORDER BY child.relname DESC
LIMIT 10;


-- Check 6: Index usage on partitions (ensure not missing)
SELECT
    schemaname, tablename, indexname,
    idx_scan, idx_tup_read, idx_tup_fetch
FROM pg_stat_user_tables t
JOIN pg_stat_user_indexes i USING (relname)
WHERE t.tablename LIKE 'audit_logs_%'
ORDER BY t.tablename, i.indexname;
```

## Anti-Patterns Avoided

| Risk | Mitigation |
|------|-----------|
| ACCESS EXCLUSIVE lock on 500M rows | Used table rename instead of `ALTER TABLE ... PARTITION BY` |
| Long-running backfill transactions | Batched DELETE with SKIP LOCKED, explicit COMMIT per batch |
| Lock contention with live writes | `lock_timeout = 5s`, `SKIP LOCKED` skips locked rows |
| Partition pruning failure | PK includes partition key; queries filter on `created_at` |
| Future partition gaps | pg_partman `premake = 3` + `infinite_premake = true` |
| Orphaned old data | Retention policy auto-drops partitions > 24 months |
| Backfill crash recovery | Idempotent `CREATE TABLE IF NOT EXISTS` + partition-by-partition processing |

This strategy has been validated against the migration safety checklist: forward-only, no full table locks, concurrent indexes, separate schema/data migrations, and tested batch sizing.
