## Dockerfile

```dockerfile
# ============================================================
# Stage 1: Build — isolate wheel compilation from runtime
# ============================================================
FROM python:3.12-slim AS build

WORKDIR /build

# Install system deps needed by torch C extensions (libblas, libopenblas, etc.)
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential libblas-dev liblapack-dev \
    && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .

# pip install into a virtualenv so we can copy site-packages later
RUN python -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"

# Compile wheels OFFLINE — this is the most expensive layer;
# cache it across dependency-only changes because its content hash
# stays stable until requirements.txt changes.
RUN pip install --no-cache-dir --compile \
    --only-binary :all: --platform manylinux2014_x86_64 \
    --cpu-only -r requirements.txt \
    && pip wheel --no-cache-dir --wheel-dir /wheels \
       -r requirements.txt

# ---- End of build stage ----

# ============================================================
# Stage 2: Runtime — lean, non-root, hardened
# ============================================================
FROM python:3.12-slim AS runtime

# System-level dependencies at runtime (shared libs used by torch, not the compilers)
RUN apt-get update && apt-get install -y --no-install-recommends \
    libgomp1 libblas3 liblapack3 ca-certificates \
    && rm -rf /var/lib/apt/lists/* \
    && groupadd --gid 1001 app && useradd --uid 1001 --gid 1001 --no-create-home --shell /bin/false app

WORKDIR /app

# Copy the pre-built virtualenv (site-packages already compiled) instead of
# running pip again. This avoids downloading packages during deploy and keeps
# the layer cacheable when only application code changes.
COPY --from=build --chown=app:app /opt/venv /opt/venv

# Application code — layers after venv copy for maximum cache reuse.
# Changing src/ does NOT bust the venv layer above.
COPY --chown=app:app src/ ./src/
COPY pyproject.toml README.md ./

# Health endpoint that verifies torch can actually load
COPY --chown=app:app healthcheck.py /app/healthcheck.py

ENV VIRTUAL_ENV=/opt/venv PATH="/opt/venv/bin:$PATH" PYTHONUNBUFFERED=1

USER app

EXPOSE 8000

HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD python /app/healthcheck.py || exit 1

CMD ["python", "-m", "uvicorn", "src.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Key Justifications

### Layer ordering & cache strategy

| Decision | Why |
|---|---|
| **Build wheels in separate stage** | Compilation requires compilers (`build-essential`) and BLAS headers that don't belong in the final image. Isolating them lets the runtime stage stay under 2.5 GB. |
| **`requirements.txt` + venv before source code** | `pip install` is the slowest layer (~3-5 min). By placing it early, any subsequent change to `src/` skips rebuild entirely — Docker only re-runs `COPY src/`. |
| **`--compile` flag in builder** | Compiles `.pyc` at build time rather than lazily at first request, shaving ~2-4 seconds off cold starts. |
| **`COPY --from=build /opt/venv`** | Instead of re-running `pip` in the runtime stage, we ship the entire venv as a single layer. No network, no download cache, deterministic. |
| **Source code COPY last** | Maximises cache hits on dependency-only changes. The venv layer is untouched. |

### Size reduction tactics (targeting < 2.5 GB from 9 GB)

- **`--cpu-only`**: Eliminates CUDA toolkit (~4 GB saved).
- **`--only-binary :all: --platform manylinux2014_x86_64`**: Forces wheel downloads; no source builds means fewer temp files and cleaner layer history.
- **Runtime stage uses `python:3.12-slim` (not alpine)**: PyTorch wheels are manylinux, and musl compatibility can cause subtle segfaults with torch's native libraries. Slim is ~300 MB vs alpine's 80 MB but has glibc which torch expects.
- **Runtime installs only shared-lib deps (`libgomp1`, `libblas3`, `liblapaxt3`)**: These are ~50 MB total, compared to installing the full build toolchain which would be hundreds of MB.
- **No pip cache dir**: `--no-cache-dir` prevents pip from storing downloaded tarballs inside the image layer.

### Security hardening

| Rule | Implementation |
|---|---|
| **Non-root** | `useradd --uid 1001 --shell /bin/false app` + `USER app` |
| **No secrets baked in** | ENV never used for credentials; pass via `.env` file (gitignored), environment injection, or Docker secrets. Torch API keys come from `os.environ["PYTORCH_KEY"]` read at runtime, not baked as `ENV`. |
| **Read-only root filesystem** | Add `read_only: true` + `tmpfs: [/tmp]` in docker-compose.override.yml for writable paths. |
| **Drop all caps** | Add `cap_drop: [ALL]` in compose config. |

### HEALTHCHECK design

```bash
# healthcheck.py
import urllib.request, json, sys

try:
    resp = urllib.request.urlopen("http://localhost:8000/healthz", timeout=5)
    body = json.loads(resp.read())
    if body.get("status") == "ok":
        sys.exit(0)
except Exception:
    pass
sys.exit(1)
```

- **`--interval=30s`**: Inference services start fast; 30s is enough between checks without overloading the container.
- **`--timeout=5s`**: Gives the health route 5 seconds to respond before Docker marks unhealthy.
- **`--start-period=10s`**: First startup needs model warmup; this prevents false negatives during initialisation.
- **`--retries=3`**: Three consecutive failures before marking unhealthy — tolerates transient blips.

### Production usage

```yaml
# docker-compose.prod.yml
services:
  app:
    build:
      context: .
      target: runtime
    ports:
      - "8000:8000"
    security_opt:
      - no-new-privileges:true
    read_only: true
    tmpfs:
      - /tmp
    cap_drop:
      - ALL
    deploy:
      resources:
        reservations:
          cpus: "2.0"
          memory: 4G
    env_file:
      - .env.production     # gitignored
```

```yaml
# docker-compose.yml (development)
services:
  app:
    build:
      context: .
      target: dev           # If you have a dev target; otherwise uses runtime
    volumes:
      - ./src:/app/src:cached   # Hot reload for code changes
    ports:
      - "8000:8000"
      - "9229:9229"             # Debug port (disabled in prod)
    develop:
      watch:
        - path: ./src
          action: sync
          target: /app/src
```

Build commands:
```bash
# Development (with hot-reload volume mount)
docker compose up --watch

# Production (lean, no extra compose files)
docker compose build --target runtime
docker compose run --rm app python -m py_compile src/main.py  # Verify syntax
docker compose up -d
```
