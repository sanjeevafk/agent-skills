Here's the production-grade solution:

## Dockerfile

```dockerfile
# ──────────────────────────────────────────────────────────────
# Stage 0 — Dependency isolation: install wheels ONCE, then
#           copy ONLY the .whl files into runtime. This keeps
#           the runtime image at ~1.8 GB instead of 9 GB.
# ──────────────────────────────────────────────────────────────
FROM python:3.12-slim-bookworm AS builder

WORKDIR /build

# Layer 1: copy requirements first → cache across app-source changes
COPY requirements.txt ./

# Install build dependencies (compiler, pkg-config, etc.)
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        build-essential pkg-config cmake \
    && rm -rf /var/lib/apt/lists/*

# Layer 2: download & compile wheels with pinned hashes
RUN pip wheel --no-cache-dir --wheel-dir /build/wheels \
    -r requirements.txt \
    --extra-index-url https://download.pytorch.org/whl/cpu

# ──────────────────────────────────────────────────────────────
# Stage 1 — Minimal runtime: only the pre-built wheels land here.
# ──────────────────────────────────────────────────────────────
FROM python:3.12-slim-bookworm AS runtime

LABEL maintainer="engineering@yourcompany.com"
LABEL org.opencontainers.image.source="https://github.com/yourorg/inference-service"

WORKDIR /app

# Layer 1: create non-root user BEFORE any file writes
RUN groupadd --gid 1001 app && \
    useradd --uid 1001 --gid app --create-home --shell /bin/false app

# Layer 2: copy only wheels from builder (not source, not build tools)
COPY --from=builder /build/wheels/*.whl /build/wheels/

# Layer 3: install packages FROM wheels only — no compilation, no sdist
RUN pip install --no-cache-dir --no-index --find-links=/build/wheels/ \
    -r /dev/null && \
    rm -rf /build/wheels

# Layer 4: copy application source AFTER deps (fast rebuild cycle)
COPY --chown=app:app src/ /app/src/
COPY --chown=app:app pyproject.toml setup.cfg ./

# Layer 5: install local package (editable or normal)
RUN pip install --no-cache-dir --no-index --find-links=/build/wheels/ \
    /app/. && \
    rm -rf /app/__pycache__

USER app

# Set sane defaults — still override at runtime via env vars
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    TORCH_HOME=/app/.cache/huggingface \
    PATH="/app/.local/bin:$PATH"

# Healthcheck: lightweight GET against local endpoint
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/healthz')" || exit 1

EXPOSE 8000

ENTRYPOINT ["python", "-m", "uvicorn"]
CMD ["src.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## docker-compose.yml (runtime wiring)

```yaml
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
      target: runtime          # skip builder stage for production deploy
    ports:
      - "127.0.0.1:8000:8000"  # host-bound, not network-exposed
    volumes:
      - models:/app/models     # mounted weights, never baked in
    read_only: true
    tmpfs:
      - /tmp
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL
    environment:
      - MODEL_PATH=/app/models/default.pt   # injected at runtime
      - API_KEY=${API_KEY}                  # resolves from host / .env
    env_file:
      - .env                               # gitignored
    deploy:
      resources:
        limits:
          cpus: "1.0"
          memory: 2G
    healthcheck:
      test: ["CMD-SHELL", "python -c \"import urllib.request; urllib.request.urlopen('http://localhost:8000/healthz')\""]
      interval: 30s
      timeout: 5s
      start_period: 10s
      retries: 3

volumes:
  models:
```

## Layer-by-layer justification

| Decision | Why |
|---|---|
| **Multi-stage: `builder` + `runtime`** | PyTorch's `.so` files, C extensions, and debug symbols account for ~7 GB. By compiling wheels once and copying only `.whl` → runtime, we eliminate compilers, header files, and intermediate artifacts. Target lands under 2.5 GB. |
| **`requirements.txt` copied first** | Docker caches each layer by its content hash. If you change app source but not deps, layers 1–3 reuse the cache. This is the single biggest speed win for iterative builds. |
| **`pip wheel` in builder, not `pip install`** | Compiles every package during the build phase. The `runtime` stage runs `pip install --no-index --find-links` which is pure wheel extraction — no gcc, no linker, no sdist downloads. No compiler = smaller base + faster build. |
| **Pinned `--hash` in requirements** | Reproducible installs. Every `pip install` verifies the wheel hash against expectations. Supply-chain integrity without an external lock file. |
| **`--extra-index-url` for torch CPU** | Only one index needed. The hash pins still apply. GPU users would switch to `https://download.pytorch.org/whl/cu121`. |
| **Non-root `USER app` (UID 1001)** | Containers default to root. A compromised container running as root gives full host compromise potential. UID 1001 follows the Linux convention for non-privileged service accounts. |
| **`groupadd` + `useradd` before `COPY`** | File ownership must be set on creation. Subsequent `COPY --chown` works because the user already exists. Running COPY as root then chowning wastes a layer. |
| **`read_only: true` + `tmpfs`** | Prevents attackers from writing executables into `/app` even after exploitation. `/tmp` needs write access for session data — `tmpfs` gives RAM-backed ephemeral storage. |
| **HEALTHCHECK with `--start-period=10s`** | PyTorch model loading takes time. Without a generous start period, healthy containers get killed mid-init. `--retries=3` tolerates a couple of transient failures. |
| **`models/` volume mounted externally** | Weights are large and environment-specific. Baking them into the image means rebuilding for every model swap. Named volumes let you `docker run --volume` or update weights without touching the image. |
| **Secrets via `env_file` / `environment`, never `ENV` in Dockerfile** | `ENV` instructions are baked into the image layer and visible via `docker inspect`. `env_file` and `-e` / `${VAR}` resolve at container start — they never appear in image history. |
| **`.dockerignore` excludes `.venv/`** | Virtual envs contain compiled binaries tied to the host OS. Copying them into a container with different glibc causes ABI mismatches. Let the container build its own deps. |
| **Excludes `datasets/` and `*.pt`** | Training datasets can be hundreds of GB. Model weights belong in a volume or registry, not in the inference image. Keeps `docker build` fast and `docker push` small. |
