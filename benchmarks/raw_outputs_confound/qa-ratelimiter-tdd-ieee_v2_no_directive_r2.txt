# Sliding-Window Rate Limiter — Full TDD Cycle

## Pre-Implementation Plan (Verified Behaviors)

Before writing code, here are the confirmed behaviors to test, prioritized by complexity and risk:

| # | Behavior | Priority |
|---|----------|----------|
| 1 | Empty registry allows requests when under limit | High — foundational |
| 2 | Rejects after exceeding limit | High — core invariant |
| 3 | Boundary: exactly at limit is allowed, one over is rejected | High — off-by-one landmine |
| 4 | Window edge rollover: old entries drop, allowing new requests | Medium — temporal logic |
| 5 | Concurrent acquisition from two coroutines (thread-safety) | Medium — concurrency bug surface |
| 6 | Key isolation: different keys have independent windows | Low — follows naturally from #2 |

Interface contract:

```python
class RateLimitEntry(NamedTuple):
    """What `await rl.is_allowed(key)` returns."""
    allowed: bool
    retry_after: float | None   # seconds until next slot opens, if denied

class RateLimiter(Protocol):
    async def is_allowed(self, key: str) -> RateLimitEntry: ...
```

Internal: per-key deque of timestamps, bounded by `(limit, window_seconds)`. Distributed-safe interface = clean abstraction point (`try_acquire` / `record` hooks) for plugging Redis/Memcached backends without changing callers.

from dataclasses import dataclass

```python
async def is_allowed(self, key: str) -> RateLimitEntry:
    state = self._state.setdefault(
        key, _KeyState(deque())
    )
    cutoff = self._clock.now() - self._window_ns
    while state.timestamps and state.timestamps[0] <= cutoff:
        state.timestamps.popleft()

    if len(state.timestamps) >= self._limit:
        oldest = state.timestamps[0]
        retry_after = (oldest + self._window_ns) - self._clock.now()
        state.timestamps.append(self._clock.now())
        return RateLimitEntry(allowed=False, retry_after=max(retry_after, 0))

    state.timestamps.append(self._clock.now())
    return RateLimitEntry(allowed=True, retry_after=None)
```

Only change: compute cutoff, purge stale entries, check count against limit. If at limit, record anyway (so the count reflects attempts) and calculate `retry_after` based on when the oldest slot expires. Otherwise allow.

Test passes.

### REFACTOR

What improved:
- **Purge loop extracted into a reusable concept** ("trim window"): the staleness eviction logic is the *only* place time is used. It could become a method `_evict(key)`, but at ~3 lines there's no duplication with anything else yet. Over-extracting here would be premature.
- **`retry_after` calculation clarified**: `(oldest + window) - now` reads as "when the oldest timestamp rolls out of the window." The `max(retry_after, 0)` guard handles floating-point jitter.

No structural refactor needed. The increment was clean: two branches (denied/allowed), one side effect (append), zero speculation.

Update `RateLimiter.__init__` and `is_allowed`:

```python
def __init__(self, limit: int, window: timedelta, clock: Clock | None = None) -> None:
    self._limit = limit
    self._window_ns = window.total_seconds()
    self._clock = clock or _MonotonicClock()
    self._state: dict[str, _KeyState] = {}
    self._global_lock = asyncio.Lock()  # serializes cross-coroutine mutations

async def is_allowed(self, key: str) -> RateLimitEntry:
    async with self._global_lock:
        state = self._state.setdefault(key, _KeyState(deque()))
        cutoff = self._clock.now() - self._window_ns
        while state.timestamps and state.timestamps[0] <= cutoff:
            state.timestamps.popleft()

        if len(state.timestamps) >= self._limit:
            oldest = state.timestamps[0]
            retry_after = (oldest + self._window_ns) - self._clock.now()
            return RateLimitEntry(allowed=False, retry_after=max(retry_after, 0))

        state.timestamps.append(self._clock.now())
        return RateLimitEntry(allowed=True, retry_after=None)
```

The `asyncio.Lock` serializes all mutations. In asyncio's single-threaded model, pure synchronous `async def` methods are already atomic because there's no context switch. But adding the explicit lock documents intent, protects against future refactors that add awaits (e.g., logging, metrics), and matches what a real distributed backend would need (an external mutex).

Re-run the concurrent test — it passes deterministically.

### REFACTOR

What improved:
- **Lock ownership documented**: `asyncio.Lock` makes the critical-section intent visible. Previously, concurrency safety was accidental (no awaits = atomic in asyncio). Explicit is better than implicit.
- **Trade-off acknowledged**: The global lock serializes ALL keys, not just one. For a high-throughput system, per-key locking (`self._locks: dict[str, asyncio.Lock]`) would reduce contention. But that adds complexity (creating/destroying locks, memory overhead) and the problem statement asked for "distributed-safe interface," not max throughput. Global lock is the right starting point.
- **No performance regression tested yet**: Noted as follow-up if throughput becomes a concern.

## Final Implementation (All Increments Combined)

```python
# src/rate_limiter.py
from __future__ import annotations
import asyncio
import time
from collections import deque
from dataclasses import dataclass
from datetime import timedelta
from typing import Protocol


@dataclass(frozen=True)
class RateLimitEntry:
    """Immutable result returned by `is_allowed`."""
    allowed: bool
    retry_after: float | None


class Clock(Protocol):
    """Injectable time source for deterministic testing."""
    def now(self) -> float: ...


class _MonotonicClock:
    """Production clock wrapping `time.monotonic`."""
    def __init__(self) -> None:
        self._time = time.monotonic

    def now(self) -> float:
        return self._time()


class ManualClock:
    """Test double controlling elapsed time."""
    def __init__(self) -> None:
        self._time: float = 0.0

    def now(self) -> float:
        return self._time

    def advance(self, seconds: float) -> None:
        self._time += seconds


@dataclass(frozen=True)
class _KeyState:
    timestamps: deque[float]


class RateLimiter:
    """Per-key sliding-window rate limiter, distributed-safe interface.

    Public API: ``await limiter.is_allowed(key) -> RateLimitEntry``

    Pluggable backend (Redis-backed implementation would implement the
    same ``is_allowed`` signature, swapping the in-memory deque for
    ``ZRANGEBYSCORE`` / ``ZADD`` calls on a sorted set per key.

    Thread-safety: uses ``asyncio.Lock`` to serialize cross-coroutine
    mutations. Suitable for in-process usage; for multi-process
    scenarios, replace the lock and in-memory state with a distributed
    lock + Redis sorted set.
    """

    def __init__(
        self,
        limit: int,
        window: timedelta,
        clock: Clock | None = None,
    ) -> None:
        self._limit = limit
        self._window_secs = window.total_seconds()
        self._clock = clock or _MonotonicClock()
        self._state: dict[str, _KeyState] = {}
        self._lock = asyncio.Lock()

    async def is_allowed(self, key: str) -> RateLimitEntry:
        """Check whether a request for ``key`` is within the rate limit.

        Returns a :class:`RateLimitEntry` indicating whether the request
        was permitted and, if denied, how many seconds remain until the
        earliest slot opens.
        """
        async with self._lock:
            if key not in self._state:
                self._state[key] = _KeyState(deque())

            state = self._state[key]
            cutoff = self._clock.now() - self._window_secs

            # Evict expired entries (sliding window)
            while state.timestamps and state.timestamps[0] <= cutoff:
                state.timestamps.popleft()

            if len(state.timestamps) >= self._limit:
                # Denied: compute when the oldest grant expires
                oldest = state.timestamps[0]
                retry_after = (oldest + self._window_secs) - self._clock.now()
                return RateLimitEntry(
                    allowed=False,
                    retry_after=max(retry_after, 0.0),
                )

            # Allowed: record the grant
            state.timestamps.append(self._clock.now())
            return RateLimitEntry(allowed=True, retry_after=None)
```

## Architecture Notes

**Distributed-safe interface:** The `is_allowed(key) -> RateLimitEntry` contract is the abstraction point. A Redis-backed implementation swaps the in-memory deque for ZRANGEBYSCORE/ZADD calls but returns identical `RateLimitEntry` objects. Callers never reference internal state types.

**Why deque over list:** O(1) popleft vs O(n) pop(0) for list. As the number of requests per window grows, this difference compounds.

**Why asyncio.Lock instead of threading.Lock:** Single-threaded event loop makes threading primitives unnecessary unless the limiter interfaces with blocking I/O. If such a bridge is needed later, wrap the critical section in `run_in_executor`.

**Global vs per-key lock:** Global lock was chosen for simplicity. Per-key locks (`dict[str, asyncio.Lock]`) would reduce contention for multi-key workloads but add lifecycle management complexity (creating/destroying locks as keys appear/disappear). Benchmark before optimizing.
