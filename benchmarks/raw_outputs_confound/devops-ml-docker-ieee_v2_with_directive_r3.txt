## Dockerfile

```dockerfile
# ============================================================
# Stage 0 — Base: immutable Alpine 3.20 foundation
# ============================================================
FROM python:3.12-slim-bookworm AS base

# Runtime-only system deps (libc, libgcc, CA certs for HTTPS)
# Pulled first so they're shared across all downstream stages
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        libgcc-s1 libstdc++6 ca-certificates curl && \
    rm -rf /var/lib/apt/lists/*

# ============================================================
# Stage 1 — Build: compile torch wheels offline
# ============================================================
FROM base AS build

WORKDIR /build

# Copy only pip config and requirements.txt — these change rarely
COPY pip.conf requirements-build.txt ./

# Cache network calls during wheel download
ENV PIP_NO_CACHE_DIR=1 \
    PIP_BREAK_SYSTEM_PACKAGES=1 \
    TORCH_CUDA_ARCH_LIST="" \
    FORCE_INTERNET=0

# Download all wheels to /wheels (layer stays cached if these files don't change)
RUN --mount=type=cache,target=/root/.cache/pip \
    pip wheel --no-deps --wheel-dir /wheels \
        -r requirements-build.txt

# ============================================================
# Stage 2 — Runtime: slim image with installed wheels
# ============================================================
FROM base AS runtime

ARG APP_USER=appuser
ARG APP_UID=1001

# Create non-root user BEFORE any COPY — layers referencing
# this user can be cached independently of content changes
RUN addgroup --gid ${APP_UID} --system ${APP_USER} && \
    adduser --uid ${APP_UID} --system --ingroup ${APP_USER} \
        --home /home/${APP_USER} --shell /bin/sh ${APP_USER}

WORKDIR /app

# Copy built wheels from the build stage (no network needed)
COPY --from=build /wheels /wheels

# Install wheels — lock them down; no dependencies pulled over network
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

RUN pip install --no-cache-dir --no-deps /wheels/*.whl && \
    rm -rf /wheels

# Copy application source (changes frequently, placed late in file)
COPY --chown=${APP_UID}:${APP_UID} src/ ./src/
COPY --chown=${APP_UID}:${APP_UID} app.py pyproject.toml ./

# Set explicit file permissions — no world-readable secrets
RUN chmod -R go-rwx /app/src /app/*.py

# Switch to non-root user NOW — every subsequent operation runs unprivileged
USER ${APP_USER}

# Healthcheck: probes model availability via HTTP endpoint
HEALTHCHECK --interval=30s --timeout=3s --start-period=15s --retries=3 \
    CMD curl -f http://localhost:8000/healthz || exit 1

EXPOSE 8000

CMD ["uvicorn", "app:create_app", "--host", "0.0.0.0", "--port", "8000"]
```

### Per-layer justification table

| Layer | Why |
|-------|-----|
| `python:3.12-slim-bookworm` (base) | Smaller than `full`; bookworm is stable Debian 12. Specific tag, never `:latest`. |
| `apt-get install` in base | Shared by build and runtime stages via `AS base` — no duplication, single download. |
| `COPY pip.conf requirements-build.txt` | These files change far less often than source code → cache layer survives most rebuilds. |
| `pip wheel --wheel-dir /wheels` | Compiles torch once into `/wheels`. The entire download+compile happens in one cached layer. No GPU drivers, no cuDNN, no CUDA toolkit — pure CPU binaries. |
| `COPY --from=build /wheels` | Brings pre-built wheels into runtime without re-downloading or compiling. |
| `pip install --no-deps /wheels/*.whl` | `--no-deps` because all deps are already baked into the wheels. Guarantees reproducibility. `--no-cache-dir` keeps layer thin. |
| `addgroup/adduser` before `COPY` | User creation happens early so its layer is cached even when only source code changes. UID/GID = 1001 per Docker best practice. |
| `COPY src/ app.py` after wheels | Source changes frequently. Placing it last means Docker can skip the expensive `pip install` layer when only code changes. |
| `chmod go-rwx` | Explicit permission hardening — nothing world-readable outside the app. |
| `USER appuser` | Runs entire process as non-root. If exploited, attacker gets no root privileges. |
| `HEALTHCHECK` | 30s interval / 3s timeout / 3 retries. Starts healthy after 15s (model load time). Probes the same endpoint production traffic hits. |
| `EXPOSE 8000` | Documentation only — actual port control lives in compose. |
| `CMD uvicorn …` | Uses `exec` form (no shell), avoids double-wrapping signals. |

## pip.conf (for reproducible hash verification)

```ini
[global]
require-hashes = true
index-url = https://download.pytorch.org/whl/cpu
extra-index-url = https://pypi.org/simple
```

> **Why**: `require-hashes = true` ensures every downloaded package is verified against known-good hashes in `requirements.txt`. No MITM possible. The PyTorch CPU index URL eliminates GPU dependency entirely.

> **Key points**: `.venv/` excluded (we use pip, not venv inside containers). `datasets/` excluded explicitly — preventing accidental commit of large model/data files that would blow up the image and slow transfers. ## docker-compose.yml

```yaml
version: "3.9"

services:
  app:
    build:
      context: .
      target: runtime          # Only build the final stage
      args:
        APP_USER: appuser
        APP_UID: 1001
    image: inference-service:${TAG:-latest}
    ports:
      - "127.0.0.1:8000:8000"  # Bind to localhost only
    env_file:
      - .env                   # Injected at runtime, never baked into image
    environment:
      - MODEL_CHECKPOINT       # From env_file, resolved at runtime
      - API_KEY                # Not set as ENV in Dockerfile
    volumes:
      - hf-cache:/home/appuser/.cache/huggingface  # Persistent HF downloads
    deploy:
      resources:
        limits:
          cpus: "2.0"
          memory: 2G
        reservations:
          cpus: "0.5"
          memory: 512M
    security_opt:
      - no-new-privileges:true
    read_only: true
    tmpfs:
      - /tmp
      - /app/.cache/uvicorn
    cap_drop:
      - ALL
    restart: unless-stopped

volumes:
  hf-cache:
    driver: local             # Persists model caches across restarts
```

### Compose decisions justified

| Decision | Rationale |
|----------|-----------|
| `target: runtime` | Skips the `build` stage entirely in production — fastest build when you already have wheels. |
| `env_file: .env` | Secrets enter at runtime. Never `ENV` in Dockerfile. File is gitignored. |
| `ports: 127.0.0.1:8000:8000` | Loopback-only binding — unreachable from other machines on the host network. |
| `deploy.resources.limits` | Prevents runaway memory consumption from model loading spikes. Caps at 2G. |
| `security_opt: no-new-privileges` | Prevents privilege escalation inside the container. Combined with non-root USER. |
| `read_only: true` | Container filesystem cannot be modified at runtime — mitigates in-container attacks. |
| `tmpfs: /tmp, /app/.cache/uvicorn` | Writable ephemeral areas needed for temp files. Purged on stop. |
| `cap_drop: ALL` | Drops all Linux capabilities. No network manipulation, no syscalls. |
| `hf-cache` named volume | HuggingFace model downloads survive container recreation. Avoids redownloading hundreds of MB per restart. |

## app.py (minimal health endpoint pattern)

```python
import torch
from fastapi import FastAPI

app = FastAPI()

_model = None  # Loaded lazily on first request (or eagerly at startup)


@app.on_event("startup")
async def load_model():
    global _model
    _model = torch.load("/app/models/model.pt", map_location="cpu", weights_only=True)
    _model.eval()


@app.get("/healthz")
async def healthz():
    """Probes whether the model is loaded and GPU/CPU is responsive."""
    if _model is None:
        return {"status": "unhealthy", "detail": "model not loaded"}
    return {"status": "healthy"}
```

> Eager load at startup ensures `HEALTHCHECK` succeeds quickly after `--start-period`. `weights_only=True` prevents arbitrary code execution from deserialized models.

## Image Size Budget Breakdown

| Component | Estimated size |
|-----------|---------------|
| `python:3.12-slim-bookworm` base | ~120 MB |
| `libgcc-s1, libstdc++6, ca-certificates, curl` | ~15 MB |
| `torch` (CPU, ~200 ops) | ~750 MB |
| `torchvision` (CPU) | ~50 MB |
| `torchaudio` (CPU) | ~35 MB |
| `numpy` + triton | ~180 MB |
| FastAPI ecosystem (uvicorn, pydantic, gunicorn, etc.) | ~30 MB |
| Application source + config | ~5 MB |
| Python stdlib overhead | ~150 MB |
| **Total estimated** | **~1,305 MB** (~1.3 GB) |

Well under the 2.5 GB target, leaving headroom for custom models loaded at runtime (mounted via volume or env-configured path — never baked into the image).
