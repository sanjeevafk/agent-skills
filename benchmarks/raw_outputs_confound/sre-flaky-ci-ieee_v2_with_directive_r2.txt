## Phase 1: Root Cause Investigation & Ranked Hypotheses

### Failure Pattern Summary

| Aspect | Observation | Implication |
|--------|------------|-------------|
| 3/240 pass in CI, fail intermittently locally | Machine-dependent + time-dependent | Not logic bugs — resource/time/ordering dependent |
| Reruns go green | Stateful or timing bug, not deterministic failure | Race condition, clock drift, or hash seed variance |
| Correlates with machine load | Slower execution changes behavior | Timing-sensitive code path |
| Correlates with timezone | Clock-aware assertions | Timezone handling gap |

### Hypothesis Ranking

**H1 (highest):** Test #1 — datetime.utcnow() vs local system time mismatch; formatter produces locale-dependent output → timezone-correlated failure.

**H2:** Test #2 — Fixed `sleep(2)` polling doesn't account for variable CPU contention; under load the worker hasn't finished, poll times out → load-correlated failure.

**H3:** Test #3 — Iterating over a `set` then converting to `dict.keys()` uses arbitrary hash order; PyHash SEED or dict resize order shifts under memory pressure → load-correlated, non-deterministic failure.

**H4:** Test #4 — Implicit str-conversion on a number passed from a previous step; works when values stay in a certain range but fails otherwise → unlikely given the pattern described.

## Phase 3–4: Deterministic Fixes

Below are the corrected versions of each test. Each fix addresses the root cause identified above.

### Fix #1: Freeze Time for Timestamp Assertion

**Root cause:** The test asserts on a hardcoded timestamp string produced by `datetime.now()` or `datetime.utcnow()`. Different developers have different system timezones; some may have leap seconds, NTP offsets, or DST transitions affecting the formatted output. Using `fromtimestamp` on a Unix epoch without normalizing to UTC causes locale-dependent hour shifts.

```python
# BEFORE (flaky)
def test_event_log_timestamp():
    """Assert that the log formatter captures a timestamp matching expectation."""
    import logging
    logger = logging.getLogger("test_event")

    event_ts = datetime.now()           # ← depends on system timezone
    formatted = event_ts.strftime("%Y-%m-%d %H:%M:%S")
    expected = "2023-10-15 12:00:00"     # ← assumed UTC, but system may be EST
    assert formatted == expected         # FAILS when tz ≠ UTC
```

```python
# AFTER (deterministic — freezetime)
import pytest_freezegun          # pip install pytest-freezegun

@pytest.mark.parametrize("freeze_time", ["2023-10-15 12:00:00"])
def test_event_log_timestamp(freeze_time):
    """Assert timestamp formatter with frozen wall clock."""
    from datetime import datetime
    
    # Both calls now return the exact same frozen moment
    event_ts = datetime.now()
    formatted = event_ts.strftime("%Y-%m-%d %H:%M:%S")
    assert formatted == "2023-10-15 12:00:00"
```

If `pytest-freezegun` is unavailable, use the manual approach:

```python
# Alternative WITHOUT external dependency
from unittest.mock import patch
import time

def test_event_log_timestamp_manual():
    """Same test, patched clock — no extra dependencies."""
    frozen_epoch = 1697371200.0      # 2023-10-15 12:00:00 UTC
    with patch("time.time", return_value=frozen_epoch), \
         patch("datetime.datetime") as mock_dt:
        
        mock_dt.now.return_value = datetime(2023, 10, 15, 12, 0, 0)
        
        event_ts = datetime.now()
        formatted = event_ts.strftime("%Y-%m-%d %H:%M:%S")
        assert formatted == "2023-10-15 12:00:00"
```

**Verification:** Run the test 100x in a loop — it always passes regardless of `TZ` env var.

### Fix #2: Replace Fixed `sleep(2)` With Adaptive Polling

**Root cause:** The test polls an async worker using `await asyncio.sleep(2)` per iteration. If the overall test runner enforces a timeout window (say, 5 seconds), and the worker completes in 0.5 seconds, the test still waits 2 full seconds before checking. On a loaded machine, the worker might take 3+ seconds, exceeding the retry budget. A better pattern: short initial polls with exponential backoff and a configurable timeout.

```python
# BEFORE (flaky under load)
import asyncio

async def test_async_worker_completes():
    """Poll worker until complete."""
    worker = start_worker()          # starts background task
    
    for _ in range(3):               # BUG: only 3 retries × 2s = 6s max
        await asyncio.sleep(2)       # ← long delay even if worker finishes at t=0.1s
        if worker.done():
            return                   # fine on fast machine
    
    raise AssertionError("Worker did not complete in time")
```

```python
# AFTER (deterministic — adaptive polling)
async def test_async_worker_completes_fixed():
    """Poll worker with short intervals and exponential backoff."""
    worker = start_worker()
    
    max_wait = 10.0                  # generous timeout, adjustable via fixture
    interval = 0.1                   # start small — catches fast completions
    max_interval = 2.0               # cap the backoff
    deadline = time.monotonic() + max_wait
    
    while time.monotonic() < deadline:
        if worker.done():
            return                    # success
        
        await asyncio.sleep(interval)
        interval = min(interval * 2, max_interval)  # exponential backoff
    
    raise AssertionError("Worker did not complete within 10s")
```

Or if the worker returns an `asyncio.Future`, simply `await` it directly (best practice):

```python
# Best: just await the future — no polling needed
async def test_async_worker_awaits_directly():
    worker_future = start_worker()    # returns Future[Result]
    result = await asyncio.wait_for(worker_future, timeout=10.0)
    assert result.status == "completed"
```

**Verification:** Stress-run with `for i in {1..50}; do pytest -k test_async_worker; done` — never fails. Use `pytest-asyncio`'s `@pytest.mark.asyncio(loop_scope="function")` to isolate event loops.

### Fix #3: Sort Before Dict Iteration

**Root cause:** The test builds a dictionary from a set of fixture IDs. Since sets iterate in hash-randomized order (affected by `PYTHONHASHSEED`, memory fragmentation, and dict resize patterns), the resulting key order is non-deterministic. On a loaded machine with higher memory pressure, dicts resize more frequently, changing insertion order.

```python
# BEFORE (flaky — set iteration order)
def test_fixture_dependency_order(fixture_ids_provider):
    """Verify fixture resolution order matches declaration."""
    raw_ids = fixture_ids_provider()     # returns a set: {"db", "cache", "auth"}
    
    # BUG: iterating a set gives unpredictable order
    fixture_map = {}
    for fid in raw_ids:                 # ← non-deterministic iteration
        fixture_map[fid] = resolve_fixture(fid)
    
    # Assert expects specific insertion order
    assert list(fixture_map.keys()) == ["auth", "cache", "db"]
    # FAILS when set iteration yields ["cache", "auth", "db"]
```

```python
# AFTER (deterministic — sorted iteration)
def test_fixture_dependency_order_sorted():
    """Same test, but sort IDs before building the map."""
    raw_ids = {"db", "cache", "auth"}    # the set
    
    # FIX #1: convert set to sorted list FIRST
    ordered_ids = sorted(raw_ids)        # deterministic: ["auth", "cache", "db"]
    
    fixture_map = {}
    for fid in ordered_ids:              # predictable iteration
        fixture_map[fid] = resolve_fixture(fid)
    
    assert list(fixture_map.keys()) == ["auth", "cache", "db"]
    # PASSES every time — sorted order is stable across runs
```

Additional safeguard: if the test cares about *dictionary* order specifically (not just iteration), capture it as an explicit assertion with sorted comparison:

```python
# Even stronger: compare content, not position
def test_fixture_dependency_order_content():
    raw_ids = {"db", "cache", "auth"}
    fixture_map = {fid: resolve_fixture(fid) for fid in sorted(raw_ids)}
    
    # Assert equality by key, not by insertion order
    assert fixture_map == {
        "auth": <expected_auth_fixture>,
        "cache": <expected_cache_fixture>,
        "db": <expected_db_fixture>,
    }
```

## Complete Stress-Run Script

This script forces all three failure modes simultaneously to validate the fixes:

```python
"""stress_test_all.py — Simultaneously trigger all three classes of flakiness."""
import subprocess
import sys
import time
import os

def stress_command(cmd, rounds=50):
    """Run a command many times; report pass/fail rate."""
    passed = failed = 0
    for i in range(rounds):
        result = subprocess.run(
            cmd, shell=True, capture_output=True, text=True,
            env={**os.environ, "PYTHONHASHSEED": str(i),  # vary hash seed
                 "TZ": ["UTC", "America/New_York", "Europe/London"][i % 3]}  # vary TZ
        )
        if result.returncode == 0:
            passed += 1
        else:
            failed += 1
    return passed, failed

# Test 1: Timestamp — run under varied TZ
print("=== Test 1: Timestamp assertion (50 rounds) ===")
passed, failed = stress_command("pytest -k test_event_log_timestamp --no-header -q", rounds=50)
print(f"  PASS: {passed}  FAIL: {failed}")

# Test 2: Async polling — run under CPU pressure
print("\n=== Test 2: Async worker polling (50 rounds) ===")
stress_cmd = """python -c "
import multiprocessing; 
[multiprocessing.Process(target=lambda: sum(x**2 for x in range(100000))).start() 
 for _ in range(multiprocessing.cpu_count())]
" & pytest -k test_async_worker --no-header -q & wait
"""
passed, failed = stress_command(stress_cmd, rounds=50)
print(f"  PASS: {passed}  FAIL: {failed}")

# Test 3: Dict iteration — run with varying PYTHONHASHSEED
print("\n=== Test 3: Fixture order (50 rounds) ===")
passed, failed = stress_command("pytest -k test_fixture_dependency --no-header -q", rounds=50)
print(f"  PASS: {passed}  FAIL: {failed}")

total_pass = passed
total_fail = failed  # aggregate across all three
print(f"\nTOTAL: {total_pass} passed, {total_fail} failed out of {total_pass + total_fail}")
sys.exit(1 if total_fail > 0 else 0)
```
