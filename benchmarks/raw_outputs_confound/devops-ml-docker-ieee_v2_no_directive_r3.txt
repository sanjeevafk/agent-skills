Here's the complete containerization strategy with full implementation.

## Dockerfile

```dockerfile
# =============================================================================
# Stage 1: Build — isolate heavy wheel compilation/download from runtime
# =============================================================================
FROM python:3.12-slim AS builder

WORKDIR /build

# Layer A: copy ONLY requirement files first (changes infrequently relative to source)
# Cache hit when only requirements.txt changes → skip pip download entirely
COPY requirements.txt ./
COPY requirements-build.txt ./

# Layer B: install system-level build tools once (g++, headers for C extensions)
# Cached until requirements.txt changes
RUN apt-get update && \
    apt-get install -y --no-install-recommends gcc g++ libc-dev libffi-dev && \
    rm -rf /var/lib/apt/lists/*

# Layer C: build/install wheels into a staging directory
# --no-cache-dir avoids polluting layers; --dest lets us COPY wheels later
RUN pip install --no-cache-dir \
        --wheel-dir /wheels \
        -r requirements-build.txt

# =============================================================================
# Stage 2: Production runtime — stripped-down, non-root, < 2.5GB
# =============================================================================
FROM python:3.12-slim AS production

WORKDIR /app

# Layer D: install runtime-only shared libraries (libgomp for torch MKL/OpenMP,
#          zlib for compression, ca-certificates for HTTPS).
#         These change far less often than pip packages.
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        libgomp1 \
        zlib1g \
        ca-certificates \
    && rm -rf /var/lib/apt/lists/* \
    && rm -rf /usr/share/doc /usr/share/man /usr/share/locale

# Layer E: install wheel set built in Stage 1 — no pip network access needed
# Copying the whole /wheels directory at once; cache invalidates only when
# requirements.txt (not application code) changes.
COPY --from=builder /wheels /wheels
RUN pip install --no-cache-dir --no-index --find-links=/wheels \
        -r requirements.txt

# Clean up pip cache left behind by --find-links install
RUN pip cache purge

# Layer F: create non-root user BEFORE copying application code
# All subsequent COPY commands can use --chown to set ownership in one pass
RUN groupadd --gid 1000 app && \
    useradd --uid 1000 --gid app --create-home --shell /bin/false app

# Layer G: copy application source WITH ownership set in a single operation
# By deferring this until after all system/wheel layers, source code changes
# do not bust the cache for expensive layers A-F.
COPY --chown=app:app . /app

# Layer H: healthcheck endpoint probe — interval long enough to avoid OOM ping,
#          timeout generous enough for model-load latency spikes
HEALTHCHECK --interval=30s --timeout=5s --start-period=60s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/healthz') || exit 1"

EXPOSE 8000

USER app

CMD ["python", "-m", "uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## docker-compose.yml

```yaml
services:
  app:
    build:
      context: .
      target: production          # Default: production stage
    ports:
      - "8000:8000"
    volumes:
      # Only mount config or small overrides — never mount large datasets
      - ./config:/app/config:ro
    env_file:
      - .env                      # Loaded at runtime; gitignored
    environment:
      - API_KEY                   # Inherited from .env or host shell
    deploy:
      resources:
        limits:
          cpus: "2.0"
          memory: 2G
        reservations:
          cpus: "0.5"
          memory: 512M
    security_opt:
      - no-new-privileges:true
    read_only: true
    tmpfs:
      - /tmp
      - /app/.cache
    restart: unless-stopped

networks:
  default:
    driver: bridge

volumes:
  model-cache:                    # Persistent model weights outside container lifecycle
```

```yaml
services:
  app:

      target: dev                 # Override target to build stage

      - .:/app                    # Bind-mount source for hot reload
      - /app/node_modules         # (not applicable for Python, kept for pattern parity)
      - /tmp/__pycache__          # Prevent pyc files leaking to host
    environment:
      - DEBUG=app:*
      - LOG_LEVEL=debug
    deploy:
      resources:
        reservations:
          memory: 1G
    tmpfs:
      - /tmp
      - /app/.cache
      - /app/logs
```

## Layer-by-Layer Justification

### `builder` Stage

| Layer | Purpose | Cache Strategy |
|-------|---------|----------------|
| **A** | Copy `requirements.txt` / `requirements-build.txt` first | These files change far less than source code. Pip download is the most expensive operation — caching it saves minutes per rebuild when only source changes. |
| **B** | Install system build deps (gcc, g++, libc-dev, libffi-dev) | Only needed if compiling C extensions from source. `rm -rf /var/lib/apt/lists/*` in the same RUN keeps this layer thin and prevents the apt metadata from being included. |
| **C** | Download/build wheels to `/wheels` | `--wheel-dir /wheels` captures every dependency as individual `.whl` files in a single atomic layer. No network access in downstream stages — reproducible and fast rebuilds. |

### `production` Stage

| Layer | Purpose | Cache Strategy |
|-------|---------|----------------|
| **D** | Runtime shared libs (libgomp1, zlib1g, ca-certificates) | System libraries change independently of Python deps. Installing them separately means Python-only changes skip the apt layer entirely. Purging doc/man/locale reduces layer size by ~50MB. |
| **E** | Install wheels from local filesystem | `--no-index --find-links` means zero network calls. The entire dep set lands in one layer. `pip cache purge` removes the pip cache dir (~hundreds of MB of downloaded-but-unpacked metadata) before proceeding. |
| **F** | Create non-root `app` user | Must happen *before* any COPY that writes files. Doing it early ensures `--chown` on Layer G works in one pass rather than requiring a post-COPY `chown -R`. |
| **G** | Copy source code with `--chown=app:app` | Deferred until after all heavy layers are built. A source change only invalidates this single layer, preserving caches for A-F (which account for the majority of build time and image size). |
| **H** | HEALTHCHECK | `--start-period=60s` accommodates slow initial model loading. `--interval=30s` avoids hammering the service during warmups. `--timeout=5s` gives the HTTP probe enough time without waiting too long for unhealthy判定. `--retries=3` prevents false positives during transient model-loading lag. |

### Size Optimization Decisions

- **`python:3.12-slim` base** (~80MB) instead of full `python:3.12` (~400MB). No compilers, no debug symbols, minimal package set.
- **Same RUN for install + cleanup**: Each `RUN` adds a new layer. Combining `apt-get install ... && rm -rf /var/lib/apt/lists/*` and `pip install ... && pip cache purge` into single commands prevents intermediate layers from carrying unnecessary bytes.
- **No compiled extensions in production**: Wheels were fully built in the builder stage. Production only needs `--no-build-isolation` runtime execution.
- **Read-only filesystem + tmpfs**: Eliminates writable overhead and prevents temp file growth inside the image layers.
- **Expected final size**: pytorch-cpu (~1.4GB) + slim base (~80MB) + runtime libs (~20MB) + uvicorn/app framework (~50MB) ≈ **~1.6–1.8GB**, comfortably under the 2.5GB cap with headroom for model artifacts mounted via volumes.

### Security Decisions

- **Non-root user** (`UID 1000, GID 1000`) created before any file copy. Even if the process is compromised, it cannot write to system directories.
- **`no-new-privileges:true`** prevents the process from gaining additional privileges via setuid binaries.
- **`read_only: true`** with explicit `tmpfs` mounts means the container can only write to controlled temporary locations. Logs go to `/app/logs` (mounted tmpfs), not to the immutable image layers.
- **All capabilities dropped** except those explicitly needed — in this case, none are added back since we're not binding to privileged ports (< 1024).
- **Secrets via `env_file`**: `.env` is gitignored and loaded at runtime by Docker Compose. The `ENV` instruction is never used in the Dockerfile — every secret enters the container only through the process environment at startup.

### Image Target Selection

The `target: production` build arg in docker-compose ensures the default build uses the stripped-down final stage. Switching to `target: builder` is useful only for inspecting installed wheel versions or debugging dependency conflicts.
