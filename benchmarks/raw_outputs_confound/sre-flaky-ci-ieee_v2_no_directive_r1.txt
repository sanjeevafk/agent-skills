## Systematic Debugging Analysis: 3 Intermittent Test Failures

### Phase 1: Root Cause Investigation

Before jumping to fixes, I need to establish the root cause for each failure pattern. Here are the data flows:

**Test A — Timestamp formatting assertion**
```
Clock.now() → strftime("%Y-%m-%d %H:%M:%S") → assert equals "expected"
```
The assertion implicitly assumes the local timezone of the dev machine matches whatever format/zone was expected. Correlation with timezone = smoking gun.

**Test B — Async worker polling with sleep(2)**
```
start_worker() → sleep(2) → poll(worker.ready) → assert ready
```
Under CPU/memory pressure, context switches delay the worker thread/process. If the worker takes 2.3s to become ready, the poll fires at t=2.0 and fails. CI machines are consistently fast; dev machines fluctuate.

**Test C — Dict iteration order over set of fixture IDs**
```
ids = {"a", "b", "c"}  # frozenset used as pytest.fixture ids param
for id_val in ids:       # dict insertion order depends on hash seed
    yield f"test-{id_val}"
```
Python 3.3+ randomizes `PYTHONHASHSEED` by default. The order of iteration over a `set` changes per-process and per-invocation. Dict keys inherit this non-deterministic insertion order.

### Hypotheses Ranked by Likelihood

| Rank | Test | Hypothesis | Evidence |
|------|------|-----------|----------|
| 1 | C | `PYTHONHASHSEED` randomization causing non-deterministic iteration order | Python default since 3.3; correlation with machine (different Python versions/builds set different seeds); 50% chance of wrong order on any run |
| 2 | A | Test expects a timezone-anchored format but reads local clock without normalizing | Direct correlation with developer timezone; CI likely runs UTC |
| 3 | B | Fixed `sleep(2)` undershoots worst-case startup latency under load | Correlates with machine load; reruns green because subsequent runs start faster (cached warm state) |

#### Reproducing Test B: Async worker polling with insufficient sleep

```python
"""Reproduce: async worker readiness check too aggressive."""
import asyncio
import threading
import time

class SlowWorker:
    def __init__(self):
        self._ready = False
        self._thread = None

    def start(self):
        """Background 'initialization' that sometimes takes > 2s."""
        self._thread = threading.Thread(target=self._init, daemon=True)
        self._thread.start()

    def _init(self):
        # Simulate variable initialization time (e.g., loading model weights,
        # opening connections, reading config)
        import random
        time.sleep(random.uniform(1.5, 3.5))  # sometimes > 2s
        self._ready = True

    @property
    def ready(self):
        return self._ready

def test_buggy():
    """Pattern: fire-and-sleep-check. FAILS ~30% of the time."""
    worker = SlowWorker()
    worker.start()
    time.sleep(2)  # THE BUG: fixed sleep doesn't account for variability
    if not worker.ready:
        raise AssertionError(f"Worker not ready after sleep(2) at {time.time()}")
    return "ok"

def test_fixed_polling():
    """Fix 1: bounded polling with exponential backoff."""
    worker = SlowWorker()
    worker.start()
    deadline = time.monotonic() + 30  # 30s timeout
    attempt = 0
    while not worker.ready:
        if time.monotonic() > deadline:
            raise TimeoutError("Worker did not start within 30s")
        attempt += 1
        time.sleep(min(0.5 * (2 ** min(attempt, 3)), 4))  # cap at 4s
    return "ok"

def test_fixed_event():
    """Fix 2 (better): use asyncio.Event or threading.Event for signaling."""
    import concurrent.futures
    future = concurrent.futures.Future()

    def wrapped_init():
        SlowWorker()._init_with_future(future)
    w = SlowWorker()
    t = threading.Thread(target=wrapped_init, daemon=True)
    t.start()
    try:
        future.result(timeout=30)  # blocks until signaled
    except concurrent.futures.TimeoutError:
        raise TimeoutError("Worker init timed out")
    return "ok"

SlowWorker._init_with_future = lambda self, fut: (
    __import__('random').uniform(1.5, 3.5),
    setattr(self, '_ready', True),
    fut.set_result(True)
)[2]

if __name__ == "__main__":
    import random
    random.seed(42)
    failed = sum(1 for _ in range(30) if test_buggy() != "ok")
    print(f"Buggy pattern: {failed}/30 failed")

    random.seed(42)
    failed = sum(1 for _ in range(30) if test_fixed_polling() != "ok")
    print(f"Fixed polling: {failed}/30 failed")
```

### Deterministic Fixes

#### Fix A — Freeze time for timestamp assertions

```python
# BEFORE (buggy):
def test_timestamp_format():
    result = format_timestamp(datetime.now())  # uses live clock
    assert result == "2026-10-10 12:00:00 UTC"  # brittle to TZ/dst

# AFTER (deterministic):
from freezegun import freeze_time

@freeze_time("2026-10-10 12:00:00 UTC")
def test_timestamp_format():
    result = format_timestamp(datetime.now(timezone.utc))
    assert result == "2026-10-10 12:00:00 UTC"

# Alternative without freezegun: inject a fixed datetime instead of calling now().
```

Key principle: **never use wall-clock time in assertions unless you control or mock the clock**. Replace `datetime.now()` with an injected parameter or a frozen context.

#### Fix B — Replace `sleep(2)` with event-driven readiness

```python
# BEFORE (buggy):
async def test_worker_start():
    handle = await start_async_worker()
    await asyncio.sleep(2)  # arbitrary duration
    assert handle.ready

# AFTER (event-driven):
async def test_worker_start():
    handle = await start_async_worker()
    ready = asyncio.Event()
    handle.on_ready(ready.set)  # callback-based signaling
    await asyncio.wait_for(ready.wait(), timeout=30.0)
    assert handle.ready

# Or using a sentinel queue:
import asyncio
sentinel = asyncio.Queue()
handle = await start_async_worker(notify_queue=sentinel)
await asyncio.wait_for(sentinel.get(), timeout=30.0)
assert handle.ready
```

Key principle: **polling with fixed sleep couples test speed to machine speed**. Event-driven waits decouple both — no artificial delay under light load, robust under heavy load.

#### Fix C — Use a sorted collection instead of a frozenset/set

```python
# BEFORE (buggy):
@pytest.fixture(params=frozenset({"alpha", "beta", "gamma"}), scope="module")
def my_fixture(request):  # iteration order non-deterministic
    ...

def test_something(my_fixture):
    order = [my_fixture for _ in range(3)]  # unpredictable
    assert order == ["alpha", "beta", "gamma"]  # flaky

# AFTER (sorted list):
@pytest.fixture(
    params=["alpha", "beta", "gamma"],  # list preserves insertion order
    scope="module"
)
def my_fixture(request):
    ...

def test_something(my_fixture):
    ...
```

If you can't change the fixture definition (e.g., third-party plugin demands a set), enforce ordering in the test itself:

```python
# Inconvenient workaround if params must stay as set:
@pytest.fixture(params=sorted(frozenset({"alpha", "beta", "gamma"})))
def my_fixture(request):
    ...
```

Key principle: **sets and frozensets have no guaranteed iteration order** — even though CPython dicts preserve insertion order since 3.7, the hash seed randomization means two runs produce different insertion sequences. Sort explicitly.

### Summary Table

| Test | Root Cause | Why It Flakes | Deterministic Fix |
|------|-----------|---------------|-------------------|
| **Timestamp** | Live clock + implicit TZ assumption | Different devs = different local TZ; DST shifts; CI runs UTC | `@freeze_time(...)` with explicit UTC datetime |
| **Async poller** | Fixed `sleep(2)` < worst-case startup time | Machine load → longer context switches → missed deadline | `Event.wait(timeout=30)` — signal-based, not time-based |
| **Set iteration** | `PYTHONHASHSEED` randomization scrambles iteration order | Every Python process gets a different seed | `sorted(frozenset(...))` → deterministic list order |

All three failures share one underlying pattern: **they rely on unstated assumptions about external state** (wall clock, wall-clock-relative timing, memory layout). Pinning those states to controlled values eliminates the non-determinism entirely.
