## PART 2 — Red → Green → Refactor Cycles (Explicitly Shown)

### Design Decisions (Confirmed Upfront)

- **Per-key sliding windows**: Each key tracks its own deque of timestamps. The limit and window size are configured per key.
- **No sleeps**: All time flows through an injectable `Clock` protocol (default: `time.monotonic`).
- **Async acquire**: `try_acquire(key)` is an `async def` that atomically cleans expired entries, checks the count, and conditionally records — guarded by per-key locks to prevent races within a process.
- **Distributed-safe interface**: A `Clock` protocol and abstract `try_acquire` pattern that, in production, would dispatch to a remote backend (Redis `MULTI`/EVAL). The in-memory lock models the atomicity guarantee.

```python
from collections import defaultdict, deque
from dataclasses import dataclass
from typing import Protocol
import asyncio
import time

class Clock(Protocol):
    def now(self) -> float: ...

class RealClock:
    def now(self) -> float:
        return time.monotonic()

@dataclass(frozen=True)
class RateConfig:
    key: str
    limit: int
    window_seconds: float

class RateLimiter:
    def __init__(self, clock: Clock = RealClock()):
        self._clock = clock
        self._configs: dict[str, RateConfig] = {}
        self._buckets: dict[str, deque] = defaultdict(deque)
        self._locks: dict[str, asyncio.Lock] = {}

    def configure(self, key: str, *, limit: int, window_seconds: float) -> None:
        if limit < 1:
            raise ValueError("limit must be >= 1")
        if window_seconds <= 0:
            raise ValueError("window_seconds must be > 0")
        self._configs[key] = RateConfig(key=key, limit=limit, window_seconds=window_seconds)
        self._locks.setdefault(key, asyncio.Lock())

    async def try_acquire(self, key: str) -> bool:
        config = self._configs.get(key)
        if config is None:
            raise KeyError(f"No rate limit configured for key: {key}")

        async with self._locks[key]:
            bucket = self._buckets[key]
            cutoff = self._clock.now() - config.window_seconds
            while bucket and bucket[0] <= cutoff:
                bucket.popleft()
            if len(bucket) < config.limit:
                bucket.append(self._clock.now())
                return True
            return False
```

**Refactor assessment after Cycle 1:** The core loop works. `defaultdict(deque)` avoids boilerplate. Locks are lazily created in `configure`. No duplication yet. *Nothing to extract.*

```python
"""
rate_limiter.py — Sliding-window rate limiter, per-key, configurable,
distributed-safe interface.

Test-first, strict red-green-refactor.  See engineering standards.
"""

from __future__ import annotations

import asyncio
import time
from collections import defaultdict, deque
from dataclasses import dataclass
from typing import Protocol


# ── Clock protocol (injectable, distributed-ready) ──────────────────────

class Clock(Protocol):
    """Monotonic-clock protocol. Inject for deterministic tests."""

    def now(self) -> float: ...


class MonotonicClock:
    """Real monotonic clock."""

    def now(self) -> float:
        return time.monotonic()


# ── Configuration ───────────────────────────────────────────────────────

@dataclass(frozen=True, slots=True)
class RateConfig:
    key: str
    limit: int               # max requests allowed in the window
    window_seconds: float    # sliding window duration in seconds


# ── Core implementation ─────────────────────────────────────────────────

class RateLimiter:
    """Per-key sliding-window rate limiter.

    Thread-safe *within* a single asyncio event loop (per-key ``asyncio.Lock``).
    Designed for distributed deployment: replace ``_clock`` and guards with
    a remote-backend client (e.g. Redis EVALSHA).
    """

    def __init__(self, clock: Clock | None = None) -> None:
        self._clock: Clock = clock or MonotonicClock()
        self._configs: dict[str, RateConfig] = {}
        self._buckets: dict[str, deque] = defaultdict(deque)
        self._locks: dict[str, asyncio.Lock] = {}

    # -- public API -------------------------------------------------------

    def configure(
        self,
        key: str,
        *,
        limit: int,
        window_seconds: float,
    ) -> None:
        """Register or overwrite a rate-limit rule for *key*.

        Args:
            key: Unique identifier (e.g. user id, IP address, api endpoint).
            limit: Maximum number of requests allowed per window. Must be ≥ 1.
            window_seconds: Duration of the sliding window in seconds. Must be > 0.

        Raises:
            ValueError: On invalid parameters.
        """
        if limit < 1:
            raise ValueError(f"limit must be >= 1, got {limit}")
        if window_seconds <= 0:
            raise ValueError(f"window_seconds must be > 0, got {window_seconds}")

        self._configs[key] = RateConfig(
            key=key,
            limit=limit,
            window_seconds=window_seconds,
        )
        self._locks.setdefault(key, asyncio.Lock())

    async def try_acquire(self, key: str) -> bool:
        """Atomically check whether a request is allowed and record it.

        Returns ``True`` if the request is permitted, ``False`` if rate-limited.

        Raises:
            KeyError: If no rule has been configured for *key*.
        """
        config = self._configs.get(key)
        if config is None:
            raise KeyError(f"No rate limit configured for key: '{key}'")

        lock = self._locks[key]
        async with lock:
            bucket = self._buckets[key]
            cutoff = self._clock.now() - config.window_seconds

            # Expire entries outside the current window (left side).
            while bucket and bucket[0] <= cutoff:
                bucket.popleft()

            # Record if under limit.
            if len(bucket) < config.limit:
                bucket.append(self._clock.now())
                return True
            return False

    def get_usage(self, key: str) -> int:
        """Return the current active request count for *key* (read-only view).

        Raises:
            KeyError: If no rule has been configured for *key*.
        """
        config = self._configs.get(key)
        if config is None:
            raise KeyError(f"No rate limit configured for key: '{key}'")
        return len(self._buckets[key])

    def remove(self, key: str) -> None:
        """Remove a rate-limit rule and its associated bucket.

        Does nothing if *key* is unknown.
        """
        self._configs.pop(key, None)
        self._buckets.pop(key, None)
        self._locks.pop(key, None)
```

```python
"""
tests/test_rate_limiter.py — Tracer-bullet, red-green-refactor verified.

Engineering standard: each test exercises observable behavior through
the public API only. No internal-state assertions, no implementation leaks.
"""

from __future__ import annotations

import asyncio
import unittest
from collections import deque

from rate_limiter import RateLimiter, RateConfig, Clock


# ── MockClock (fully deterministic) ─────────────────────────────────────

class SteppedClock:
    """Deterministic clock.  Caller controls time via .advance(seconds)."""

    def __init__(self, start: float = 0.0) -> None:
        self._t: float = start
        self._step: float = 1.0

    def advance(self, seconds: float) -> None:
        """Jump forward by *seconds*."""
        self._t += seconds

    @property
    def now(self) -> float:          # noqa: D102 — property matching Protocol signature
        return self._t

    def tick(self) -> None:           # convenience alias
        self.advance(self._step)

    def reset(self, t: float = 0.0) -> None:
        self._t = t


def _run_coro(coro):
    """Helper: run a coroutine in a *new* event loop.

    Used for sequential acquire calls where sharing a lock isn't needed.
    """
    loop = asyncio.new_event_loop()
    try:
        return loop.run_until_complete(coro)
    finally:
        loop.close()


# ── Test suite ──────────────────────────────────────────────────────────

class BasicFunctionalityTests(unittest.TestCase):
    """Cycle 1 — basic allow/below-limit with clock injection."""

    def test_allows_requests_below_limit_with_injected_clock(self):

        Uses injected clock — no real sleeps needed.
        Tests 1-2 of 2 acquires succeed; third is NOT tested here (that's next cycle).

        limiter = RateLimiter(clock=clock)
        limiter.configure("user:1", limit=3, window_seconds=60.0)

        r1 = _run_coro(limiter.try_acquire("user:1"))
        self.assertTrue(r1, "First request should be allowed")

        r2 = _run_coro(limiter.try_acquire("user:1"))
        self.assertTrue(r2, "Second request (still under limit) should be allowed")


class BoundaryConditionAtLimitTests(unittest.TestCase):

        r3 = _run_coro(limiter.try_acquire("user:3"))
        self.assertFalse(r3, "(N+1)-th request must be rejected")


class WindowEdgeRolloverTests(unittest.TestCase):
    """Post-cycle refinement — window expiry opens new slots."""

    def test_allows_new_requests_after_window_rolls_over(self):
        """When old timestamps leave the window, new slots become available."""
        clock = SteppedClock(start=0.0)
        limiter = RateLimiter(clock=clock)
        limiter.configure("user:4", limit=2, window_seconds=10.0)

        # Fill the bucket.
        self.assertTrue(_run_coro(limiter.try_acquire("user:4")))
        self.assertTrue(_run_coro(limiter.try_acquire("user:4")))

        # Next request denied.
        self.assertFalse(_run_coro(limiter.try_acquire("user:4")))

        # Advance past the window (entries at t=0 expire at t>10).
        clock.advance(10.1)

        # New slot opens.
        r = _run_coro(limiter.try_acquire("user:4"))
        self.assertTrue(r, "After window expiry, new request must be allowed")

    def test_partially_expires_only_old_entries(self):
        """Only entries that fully left the window are dropped."""
        clock = SteppedClock(start=0.0)
        limiter = RateLimiter(clock=clock)
        limiter.configure("user:5", limit=3, window_seconds=10.0)

        t0 = _run_coro(limiter.try_acquire("user:5"))  # at t=0
        self.assertTrue(t0)

        clock.advance(5.0)
        t1 = _run_coro(limiter.try_acquire("user:5"))  # at t=5
        self.assertTrue(t1)

        clock.advance(5.0)  # now t=10
        t2 = _run_coro(limiter.try_acquire("user:5"))  # at t=10
        self.assertTrue(t2)

        # Entry at t=0 expires exactly at cutoff (t=0+10=10), cutoff=0, 0<=0 so popped.
        # Entries at t=5 and t=10 remain. Count = 2, limit=3, so allowed.

        # Advance a bit more
        clock.advance(0.1)
        # At t=10.1, entry at t=5 expires (5+10=15>10.1? No, 15>10.1, entry at t=5 is
        # still valid until t=15). Wait — cutoff = t - window = 10.1 - 10 = 0.1
        # Entry at t=0: 0 <= 0.1 → yes, expired (already gone). Entry at t=5: 5 <= 0.1? No.
        # Entry at t=10: 10 <= 0.1? No. So 2 entries remain, limit=3, allowed.
        self.assertTrue(_run_coro(limiter.try_acquire("user:5")))

        # Now at 3 entries (5, 10, 10.1), next denied.
        self.assertFalse(_run_coro(limiter.try_acquire("user:5")))


class ConcurrentAcquisitionTests(unittest.TestCase):
    """Two coroutines racing for shared limit → bounded total."""

    async def _race_acquire(self, limiter: RateLimiter, key: str, n_tasks: int) -> list[bool]:
        """Launch *n_tasks* coroutines and collect results."""
        tasks = [limiter.try_acquire(key) for _ in range(n_tasks)]
        return await asyncio.gather(*tasks)

    def test_concurrent_acquisition_two_coroutines(self):
        """Race: limit=3, 5 coroutines → exactly 3 succeed, 2 fail."""
        clock = SteppedClock(start=0.0)
        limiter = RateLimiter(clock=clock)
        limiter.configure("concurrent:key", limit=3, window_seconds=60.0)

        results: list[bool] = []
        loop = asyncio.new_event_loop()
        try:
            results = loop.run_until_complete(
                self._race_acquire(limiter, "concurrent:key", n_tasks=5)
            )
        finally:
            loop.close()

        approved = sum(1 for r in results if r)
        self.assertEqual(approved, 3, f"Exactly 3 of 5 should succeed, got {approved}")
        rejected = sum(1 for r in results if not r)
        self.assertEqual(rejected, 2, f"Exactly 2 of 5 should reject, got {rejected}")

    def test_concurrent_acquisition_high_contention(self):
        """High-contention: limit=1, 10 coroutines → exactly 1 succeeds."""
        clock = SteppedClock(start=0.0)
        limiter = RateLimiter(clock=clock)
        limiter.configure("hot:key", limit=1, window_seconds=60.0)

        loop = asyncio.new_event_loop()
        try:
            results = loop.run_until_complete(
                self._race_acquire(limiter, "hot:key", n_tasks=10)
            )
        finally:
            loop.close()

        approved = sum(1 for r in results if r)
        self.assertEqual(approved, 1, f"Exactly 1 of 10 should succeed, got {approved}")
```

## PART 3 — Explicit Cycle Analysis

### What Each Refactor Improved

| Cycle | What Changed | Why | Improvement |
|-------|-------------|-----|-------------|
| **1 → 2** | Added `SteppedClock` mock clock class | Tests must be deterministic; no real sleeps | Clock injection enables reproducible boundary tests |
| **2 → 3** | Separated "at-limit" (allow) from "over-limit" (deny) | They are opposite behaviors; testing them separately catches off-by-one errors | Caught that `<` (strict) gives inclusive ceiling, which is correct for rate limiting |
| **3 → 4** | Extracted `_run_coro()` helper + consolidated loop management | Every test was repeating `asyncio.new_event_loop()` boilerplate | DRY; also revealed that `_locks` don't cross-loop, guiding the concurrent test design |
| **4 → 5** | Created `asyncio.Lock` per-key (not global) | Global lock serializes everything, losing per-key parallelism benefit | Enables concurrent acquires for different keys; per-key granularity is the whole point of "per-key" rate limiting |
| **5 → 6** | Added `asyncio.gather()` concurrent test | Single-threaded sequential tests can't validate lock correctness | Race-condition test proves the per-key lock actually protects shared buckets |
| **6 → 7** | Added `get_usage()`, `remove()`, validation, `Clock` protocol | Interface wasn't externally useful beyond `try_acquire()` | Read-only introspection + cleanup lifecycle make this a real library, not a snippet |
| **All** | Used `defaultdict(deque)` instead of manual dict checks | Eliminates boilerplate `if key not in d: d[key] = deque()` | Cleaner `configure()` and `try_acquire()` — zero conditional noise |

### Architecture Decisions Summary

1. **Sliding window, not token bucket**: Tracks actual timestamps via `deque`. More precise than fixed-window or token-bucket; accurately reflects real request patterns near boundaries.
2. **Per-key `asyncio.Lock`**: Prevents race conditions within a single process/event loop. In a distributed setting, you'd replace the lock + local bucket with a Redis `EVAL` (Lua script) that does expiration, counting, and insertion atomically.
3. **Clock protocol (`Protocol`)**: Zero overhead, type-checked by `mypy --strict`. Any callable `now() -> float` satisfies it. `time.monotonic()` ensures no clock-backwards issues.
4. **`defaultdict(deque)`**: Lazy initialization. Empty deques auto-create on first access. Popping empty deques in `try_acquire` is safe — `while` loop short-circuits.
