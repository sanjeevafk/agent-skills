### INCREMENT 1 — First failing test → Minimal green

**RED:** Test imports failed — module didn't exist. The very first test:

```python
def test_allow_when_empty(self) -> None:
    clock = FakeClock(start=100.0)
    limiter = RateLimiter(limit=3, window=10.0, clock=clock)
    allowed, info = limiter.allow("user:1")
    assert allowed is True
    assert info.current_count == 1
```

**GREEN (minimal code):** Wrote `RateLimiter.__init__`, `allow()`, and `RateInfo` dataclass with an empty `OrderedDict` store. One path: if `len(store) < limit`, insert and return `(True, RateInfo(...))`.

**Key insight from this cycle:** The Clock Protocol + FakeClock became part of the interface immediately because the second test also needed it. Better to design the dependency upfront.

---

### INCREMENT 2 — Boundary conditions reveal a bug

**RED:** Added two tests: `test_reject_at_limit` (N requests fill the bucket, N+1th rejected) and `test_over_limit_one` (partial time advancement, verify `retry_after`).

**FIRE:** Both tests FAILED — duplicate timestamps overwrote each other in `OrderedDict[float, None]`. Same timestamp → same key → overwrite. After 3 calls at t=100, only 1 entry existed.

**GREEN (fix):** Switched from `OrderedDict[float, None]` to `OrderedDict[int, tuple[float, int]]`. Keys are sequence numbers (monotonically increasing, always unique). Values hold `(timestamp, sequence)` pairs. This fixed all three boundary tests simultaneously.

**What this revealed:** Testing at the exact boundary exposed an implementation detail that "wouldn't matter in production" (real clocks rarely return identical nanosecond ticks). But correctness requires handling it.

---

### INCREMENT 3 — Window rollover & clock injection

**RED:** Two new tests:
- `test_window_rollover`: Fill bucket, reject, advance clock past window, verify allow again
- `test_clock_injection`: Demonstrate FakeClock makes no real-time waits necessary

**GREEN (already passing):** The existing `_prune()` method already handled both correctly — it evicts entries where `timestamp < cutoff` on every `allow()` call. No code change needed; the tests validated the existing behavior was correct.

This is the ideal TDD outcome: incremental tests confirming behavior without unnecessary rewrites.

### INCREMENT 4 — Concurrency

**RED:** `test_concurrent_from_two_coroutines` — 5 coroutines × 3 attempts on a limit=2 key. Assert exactly 2 allowed, 13 denied.

**GREEN (already passing):** Per-key `asyncio.Lock` in `allow_async()` protected the shared state. The lock acquisition serialized concurrent access to the same key's store.

Again, tests validated existing design rather than driving new code.

---

### INCREMENT 5 — Key isolation

**RED:** Two tests verifying keys don't interfere: one where A is exhausted but B still works, another with 3 independent keys each getting exactly 1 request before rejection.

**GREEN (already passing):** The `_stores: dict[str, OrderedDict[...]]` naturally provides per-key isolation since each key gets its own `OrderedDict`.

### REFACTOR Step — What changed, what stayed the same

After all 9 tests passed, I refactored the implementation:

| Change | Before | After | Why |
|--------|--------|-------|-----|
| Store type | `OrderedDict[float, None]` with manual seq tracking | `OrderedDict[int, tuple[float, int]]` | Sequence derived from `len(store)` instead of separate counter; simpler |
| `_get_store` | Had dead `self._global_lock = asyncio.Lock()` assignment | Removed global lock, just creates store + lock per key | Global lock was never used |
| `_prune` signature | `_prune(store, now)` computed cutoff internally | `_prune(store, cutoff)` takes cutoff directly | Cleaner separation of concerns; caller controls cutoff computation |
| `_prune` body | Iterated `.values()` then looked up key | Directly accesses `store[next(iter(store))][0]` | Fewer lookups, clearer intent |
| Docstring | Multi-line EPy style | Simplified; added example usage | Reduced boilerplate while preserving information |
| `_real_clock` | Inline class | Unchanged | Already clean |

**What stayed the same:** Every public method signature, return type, and behavioral contract. All 9 tests passed unchanged through the refactor — proving they test **behavior**, not implementation.

**Net improvement:** -15 lines of dead/unnecessary code, +1 docstring example, cleaner internal API surface, no behavioral changes.
