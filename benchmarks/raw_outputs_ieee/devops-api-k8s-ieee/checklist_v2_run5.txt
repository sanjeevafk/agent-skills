### 4. Deployment — Production Template

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
  namespace: api-prod
  labels:
    app: myapp
    version: "1.0.0"
    environment: production
spec:
  replicas: 3
  revisionHistoryLimit: 5
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1           # Kill one at a time during deploy
      maxSurge: 1                 # Create one extra pod above desired count
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
        version: "1.0.0"
        environment: production
      annotations:
        checksum/config: {{ include (print $.Template.BasePath "/configmap.yaml") . | sha256sum }}
        prometheus.io/scrape: "true"
        prometheus.io/port: "8080"
        prometheus.io/path: "/metrics"
    spec:
      # ── ServiceAccount: no token unless the app calls K8s API ──
      serviceAccountName: myapp-sa
      automountServiceAccountToken: false

      terminationGracePeriodSeconds: 45
      dnsPolicy: ClusterFirst

      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
            - weight: 100
              podAffinityTerm:
                labelSelector:
                  matchExpressions:
                    - key: app
                      operator: In
                      values: ["myapp"]
                topologyKey: kubernetes.io/hostname
                # Spreads pods across nodes; helps PDB stay satisfied

      containers:
        - name: myapp
          image: ghcr.io/org/myapp:1.4.2@sha256:<digest>   # Pin to immutable tag
          imagePullPolicy: IfNotPresent
          command: ["/usr/local/bin/myapp"]
          args: ["--config", "/etc/app/config/server.yaml"]

          envFrom:
            - configMapRef:
                name: myapp-config

          # ── Secrets as file mounts (NOT environment variables) ──
          volumeMounts:
            - name: secrets
              mountPath: /etc/secrets
              readOnly: true
            - name: tmp
              mountPath: /tmp
            - name: cache
              mountPath: /var/cache/myapp
              subPath: cache

          resources:
            requests:
              cpu: "250m"
              memory: "256Mi"
            limits:
              cpu: "500m"
              memory: "512Mi"

          # ── Probes ──
          startupProbe:
            httpGet:
              path: /health
              port: 8080
            failureThreshold: 15
            periodSeconds: 5
            # 15 × 5s = 75s max startup window
            # Covers 20s cold-cache warmup + binary load + listener bind (~5–10s)
            # Leaves ~45s headroom for slow networks or heavy cold starts

          livenessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 30
            periodSeconds: 10
            timeoutSeconds: 3
            failureThreshold: 2
            # After startup, check every 10s.
            # 2 failures = dead/unresponsive → restart container
            # Total wait before kill: initialDelay(30) + successCheck + failureWindow(2×10+timeout) ≈ 46s

          readinessProbe:
            httpGet:
              path: /ready
              port: 8080
            initialDelaySeconds: 10
            periodSeconds: 5
            timeoutSeconds: 3
            failureThreshold: 3
            # Starts checking at t=10s but won't pass until /ready returns 200
            # Application must NOT return 200 on /ready until 20s cache warmup completes
            # 3 failures = remove from Service endpoints → stop receiving traffic
            # Max time in endpoint removal before restart: 3 × 5 + timeout = ~18s

          securityContext:
            runAsNonRoot: true
            runAsUser: 1000
            runAsGroup: 1000
            readOnlyRootFilesystem: true
            allowPrivilegeEscalation: false
            capabilities:
              drop:
                - ALL

      volumes:
        - name: secrets
          secret:
            secretName: myapp-secrets
            defaultMode: 0400    # File permissions: read-only by owner
        - name: tmp
          emptyDir: {}
        - name: cache
          emptyDir:
            medium: Memory       # Cache stays in RAM for performance
            sizeLimit: 128Mi
```

## Probe Threshold Arithmetic Explained

### Timing Diagram

```
t=0s         Startup probe starts hitting /health
             Check every 5s → first result at t=5s

t=5s 20s    Cache warmup phase — /ready intentionally returns 503
             /health still returns 200 (process is alive, just warming up)

t=20s       Cache warmup complete — app returns 200 on /ready
             Readiness transitions → pod added to Service endpoints

t=30s       Liveness probe becomes active (initialDelaySeconds: 30)

t=35s       Startup probe last allowed window closes (15 × 5s = 75s from t=0)
```

| Probe | Threshold | Period | Total Window | What It Detects |
|-------|-----------|--------|-------------|-----------------|
| **startupProbe** | `failureThreshold: 15` | `5s` | **75s** | Binary load, listener bind, cold cache warmup (~20s), any other init overhead |
| **livenessProbe** | `failureThreshold: 2` | `10s` (+ timeout 3s) | **~26s after detection** | Deadlock, hung goroutines, OOM soft-fail, unresponsive HTTP handler |
| **readinessProbe** | `failureThreshold: 3` | `5s` (+ timeout 3s) | **~18s** | Temporarily unavailable (DB reconnect, upstream dependency down); removes from Service endpoints without restarting the container |

**Why 75s for startup?**

```
Cold cache warmup:      ~20s
Binary load + listen:   ~5–10s
Network/K8s overhead:   ~5s (worst case)
Headroom for safety:    ~40s
────────────────────────────
Total:                  ~75s (15 checks × 5s)
```

This avoids race conditions where liveness kills the pod *during* cache warmup. Without a `startupProbe`, you'd have to set `initialDelaySeconds: 30` on liveness — arbitrary and fragile. With `startupProbe`, liveness only activates *after* startup succeeds, so it never interferes with initialization.

## Graceful Termination / Zero-Drop Sequence

The critical chain during rolling updates:

```
1. kubelet sends SIGTERM to PID 1 (your Go main process)
2. PreStop hook pauses 25s — gives Kubernetes time to remove this pod from Service endpoints
   (kube proxy already stopped sending new traffic; existing connections drain naturally)
3. Go signal handler catches SIGTERM:
   a. Stop accepting new requests
   b. Wait for in-flight requests to complete (with a separate deadline)
   c. Close database connection pools gracefully
   d. Exit with code 0 within the remaining grace period
```

### Go Shutdown Handler (must be in your code)

```go
package main

import (
    "context"
    "log"
    "net/http"
    "os"
    "os/signal"
    "syscall"
    "time"
)

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("/health", healthHandler)
    mux.HandleFunc("/ready", readyHandler)
    mux.HandleFunc("/", apiHandler)

    srv := &http.Server{
        Addr:         ":8080",
        Handler:      mux,
        ReadTimeout:  10 * time.Second,
        WriteTimeout: 25 * time.Second,
        IdleTimeout:  120 * time.Second,
    }

    // Start server in background
    go func() {
        log.Printf("listening on :8080")
        if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
            log.Fatalf("listen error: %v", err)
        }
    }()

    // Block on OS signals
    quit := make(chan os.Signal, 1)
    signal.Notify(quit, syscall.SIGTERM, syscall.SIGINT)
    sig := <-quit
    log.Printf("received %v, shutting down...", sig)

    // Graceful shutdown with deadline (must fit inside
    // terminationGracePeriodSeconds minus any buffer)
    ctx, cancel := context.WithTimeout(context.Background(), 25*time.Second)
    defer cancel()

    if err := srv.Shutdown(ctx); err != nil {
        log.Printf("forced shutdown: %v", err)
        srv.Close() // Emergency cutoff
    }

    log.Println("shutdown complete")
}
```

### Why Each Number Matters

| Parameter | Value | Reason |
|-----------|-------|--------|
| `terminationGracePeriodSeconds` | **45** | Total window from SIGTERM → forced SIGKILL |
| `preSleep` in PreStop | **25** | Duration for kube-proxy to propagate endpoint removal (the Pod goes NotReady immediately, but iptables/ipvs rules take ~15–20s to flush across nodes) |
| `srv.Shutdown` timeout | **25s** | Must leave headroom below the remaining grace period (45 − 20 ≈ 25s) |
| `maxUnavailable` | **1** | Only one pod dies at a time; PDB guarantees ≥2 stay online |
| PDB `minAvailable` | **2** | Prevents kubelet from evicting when only 3 are running (would violate PDB) |

If you start at 3 replicas: PDB blocks eviction of the 2nd pod until at least 2 remain. So a rolling update proceeds: pod3 → replace → pod4 → replace → old pod3 drained by PDB guard. The rollout never drops below the required minimum.

## Resource Sizing — Avoiding CPU Throttling at p99

```
Requests:  250m CPU  ← guaranteed by scheduler
Limits:    500m CPU  ← hard cap, throttled above this
Ratio:     2× headroom
```

| Rule | Applied Here | Rationale |
|------|-------------|-----------|
| Web API: request 100–250m | ✓ 250m | Go has low baseline CPU; 250m ensures smooth operation under moderate load |
| Limits 2–4× requests | ✓ 2× (500m) | Allows burst during traffic spikes without excessive reservation |
| Memory request ≤ limit | ✓ 256→512Mi | Catch bursty allocations (JSON parsing, batch responses) |
| JVM apps need headroom above `-Xmx` | N/A (Go GC is generational, runs in-background) | Go's GC allocates parallel threads; 2× limit is sufficient vs 4× for JVM |

**p99 CPU throttling safeguard:**

At 3 replicas, total guaranteed CPU = `3 × 250m = 750m`. At 10 replicas (max), total = `2.5 CPU`. If your p99 load profile exceeds the ratio of requests to limits (1:2), consider bumping requests to `300m` or increasing node pool capacity rather than lowering the ratio — that would hurt scheduling efficiency and cost.

## Anti-Patterns Specific to This Setup

| Anti-Pattern | Why It Breaks | Fix |
|-------------|---------------|-----|
| `image: myapp:latest` | Non-deterministic; rollback impossible | Pin to `@sha256:...` digest |
| Running as root | Container escape risk | `runAsNonRoot: true`, `runAsUser: 1000` |
| No `readOnlyRootFilesystem` | Compromised container can write binaries | `true` + `emptyDir` for `/tmp` and `/var/cache` |
| Secrets as `env:` | Appears in `kubectl describe pod`, logs, process listing | Volume-mount with `defaultMode: 0400` |
| `initialDelaySeconds` alone for slow startups | Race condition — liveness may kill during warmup | Use `startupProbe`; eliminate bare `initialDelaySeconds` on liveness |
| `gracePeriodSeconds < preStop sleep` | SIGKILL fires mid-shutdown → dropped requests | Keep gap ≥ 20s |
| PDB `minAvailable: 0` | Evictions proceed regardless of replica count | Set meaningful floor |
| `maxUnavailable: 50%` or higher | Can take down half your fleet simultaneously | Cap at `1` or `25%` for web services |
