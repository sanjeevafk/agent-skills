### 0a. Static Dependency Graph

Run a script to extract every dependency edge from the class. Example output structure:

```
┌─────────────────────────────────────────────────────────────┐
│                    ORDER SERVICE                             │
│                     (1,400 LOC)                               │
├──────────┬──────────┬──────────┬──────────┬─────────────────┤
│ Validat- │ Pricing  │ Persis-  │ Comms    │ Audit / Other   │
│ ion      │ & Discount│ tence  │ (Email)  │                 │
│ 450 LOC  │ 300 LOC  │ 350 LOC │ 150 LOC  │ 150 LOC         │
└──────────┴──────────┴──────────┴──────────┴─────────────────┘
```

The script should identify:
- Every `INSERT/UPDATE/DELETE` statement per method
- Every `mail.send()` or SMTP call
- Every `audit.log()` call
- Each field name and its access frequency across methods
- Public method callers and callees within the class

Example extraction script skeleton:

```python
import re
from collections import defaultdict

def map_order_service(filepath: str) -> dict:
    source = open(filepath).read()
    
    dependencies = {
        'sql_calls': [],          # method -> [(statement, line)]
        'email_calls': [],        # method -> [call_description]
        'audit_calls': [],        # method -> [call_description]
        'field_usage': {},        # field_name -> set(method_names)
        'public_methods': [],     # list of public method signatures
        'internal_calls': []      # (caller, callee) pairs
    }
    
    # Extract method boundaries first
    methods = re.finditer(
        r'def\s+(\w+)\s*\(self(?:\s*,[^)]*)?\)\s*:',
        source
    )
    method_ranges = []
    for i, m in enumerate(methods):
        start = m.start()
        next_start = methods[i+1].start() if i+1 < len(list(methods)) else len(source)
        method_ranges.append((m.group(1), start, next_start))
    
    # Now analyze each method body
    for method_name, start, end in method_ranges:
        body = source[start:end]
        
        # SQL patterns
        sql_lines = [(line.strip(), idx + start + line.rfind('\n') + 1)
                      for idx, line in enumerate(body.split('\n'))
                      if re.search(r'(SELECT|INSERT|UPDATE|DELETE|EXEC)', line)]
        dependencies['sql_calls'].extend(sql_lines)
        
        # Email patterns
        email_matches = re.findall(r'self\._?mail\.send[_a-z]*\(', body)
        dependencies['email_calls'].append((method_name, email_matches))
        
        # Audit patterns
        audit_matches = re.findall(r'self\._?audit\.(log|record|track)[_a-z]*\(', body)
        dependencies['audit_calls'].append((method_name, audit_matches))
        
        # Field usage
        fields = re.findall(r'self\.(\w{2,})\b', body)
        for f in fields:
            dependencies['field_usage'].setdefault(f, set()).add(method_name)
        
        # Internal calls
        internal_calls = re.findall(r'self\.(\w+)\(', body)
        for call in internal_calls:
            if call.startswith('_'):
                dependencies['internal_calls'].append((method_name, call))
    
    return dependencies
```

### 0b. Identify the "Seams" — Entry Points for Extraction

Not all seams are equal. Rank them by ease of isolation:

| Seam | Why It's Good First Target | Risk |
|------|--------------------------|------|
| **Persistence layer** | Highest cohesion, clearest boundary | Medium (SQL integration) |
| **Email notification** | Loose coupling target exists | Low |
| **Audit logging** | Pure side-effect, easy to swap | Low |
| **Validation rules** | Business logic, harder to separate early | High |
| **Pricing/discount engine** | Complex domain logic, depends on persistence | Very high |

**Priority order**: Persistence → Email → Audit → Validation → Pricing. Here's why:

1. **Persistence** first because it removes `self.connection`, `self.cursor`, raw SQL from EVERY other seam. Once data access is encapsulated in a repository interface, every subsequent refactor gains a clean contract.
2. **Email** second because it's pure side-effect with an obvious external collaborator. A `Notifier` interface is trivial to introduce.
3. **Audit** third — same as email but even simpler. A `Logger` interface is 10 lines.
4. **Validation** fourth — validation lives close to pricing logic; better to have the infrastructure stable first.
5. **Pricing/discount** last — it depends on both persistence AND validation AND complex tax calculations. By this point the scaffolding will support it cleanly.

```python
import json
from pathlib import Path

def assert_golden_match(actual: dict, golden_path: Path):
    """
    First run: writes golden file.
    Subsequent runs: compares against stored golden.
    """
    if not golden_path.exists():
        golden_path.parent.mkdir(parents=True, exist_ok=True)
        golden_path.write_text(json.dumps(actual, indent=2, sort_keys=True))
        print(f"[FIRST RUN] Written golden to {golden_path}")
        return
    
    expected = json.loads(golden_path.read_text())
    
    # Deep compare with helpful diff
    assert actual == expected, (
        f"\n=== GOLDEN MASTER FAILURE ===\n"
        f"Differences found between current execution and stored golden.\n"
        f"This indicates BEHAVIOR CHANGE.\n\n"
        f"If behavior change is intentional, update the golden:\n"
        f"  rm {golden_path}\n"
        f"  python -m pytest {(golden_path.parent / '..').name} --update-golden\n"
    )
```

### Step 1: Extract Persistence Layer

**Goal**: Remove ALL direct SQL from OrderService. Introduce repository interfaces.

#### 1a. Define the Interfaces

```python
# domains/order/repositories.py
from abc import ABC, abstractmethod
from typing import Optional, List
from dataclasses import dataclass

@dataclass(frozen=True)
class OrderDTO:
    id: int
    customer_id: int
    items: List[dict]
    total: float
    discount_pct: float
    tax_amount: float
    shipping_address: dict
    status: str

@dataclass(frozen=True)
class CustomerDTO:
    id: int
    name: str
    email: str
    loyalty_tier: str

class OrderRepository(ABC):
    @abstractmethod
    def save(self, dto: OrderDTO) -> OrderDTO:
        """Persist order and return persisted DTO with generated ID."""
        ...
    
    @abstractmethod
    def find_by_id(self, order_id: int) -> Optional[OrderDTO]:
        ...
    
    @abstractmethod
    def find_active_orders_for_customer(self, customer_id: int) -> List[OrderDTO]:
        ...
    
    @abstractmethod
    def update_status(self, order_id: int, new_status: str) -> bool:
        """Returns True if row was found and updated."""
        ...
    
    @abstractmethod
    def upsert_items(self, order_id: int, items: List[dict]) -> None:
        ...

class CustomerRepository(ABC):
    @abstractmethod
    def find_by_id(self, customer_id: int) -> Optional[CustomerDTO]:
        ...

class ProductRepository(ABC):
    @abstractmethod
    def find_by_code(self, product_code: str) -> Optional[dict]:
        """Returns {'price': float, 'tax_category': str}."""
        ...
    
    @abstractmethod
    def find_by_codes(self, codes: List[str]) -> List[dict]:
        ...
```

```python
# infra/persistence/sql/order_repo.py
from domains.order.repositories import OrderRepository, OrderDTO
import psycopg2  # or your actual DB driver

class SQLOrderRepository(OrderRepository):
    def __init__(self, connection_pool):
        self.pool = connection_pool
    
    def save(self, dto: OrderDTO) -> OrderDTO:
        with self.pool.acquire() as conn:
            cursor = conn.cursor()
            
            # INSERT order header
            cursor.execute("""
                INSERT INTO orders (customer_id, total, discount_pct, tax_amount, 
                                   status, shipping_address)
                VALUES (%s, %s, %s, %s, %s, %s)
                RETURNING id
            """, (dto.customer_id, dto.total, dto.discount_pct, 
                  dto.tax_amount, dto.status, json.dumps(dto.shipping_address)))
            
            order_id = cursor.fetchone()[0]
            
            # INSERT order items
            for item in dto.items:
                cursor.execute("""
                    INSERT INTO order_items (order_id, product_code, quantity, unit_price)
                    VALUES (%s, %s, %s, %s)
                """, (order_id, item["product_code"], item["quantity"], item["unit_price"]))
            
            conn.commit()
            return OrderDTO(id=order_id, ...)
    
    def find_by_id(self, order_id: int) -> Optional[OrderDTO]:
        with self.pool.acquire() as conn:
            cursor = conn.cursor()
            cursor.execute("""
                SELECT o.*, oi.product_code, oi.quantity, oi.unit_price
                FROM orders o
                LEFT JOIN order_items oi ON o.id = oi.order_id
                WHERE o.id = %s
            """, (order_id,))
            
            rows = cursor.fetchall()
            if not rows:
                return None
            
            # Reconstruct nested DTO from flat rows
            order = rows[0]
            items = [{
                "product_code": r[7], "quantity": r[8], "unit_price": r[9]
            } for r in rows]
            
            return OrderDTO(
                id=order[0], customer_id=order[1], total=order[2],
                discount_pct=order[3], tax_amount=order[4],
                shipping_address=json.loads(order[6]), status=order[5],
                items=items
            )
    
    # ... other abstract methods
```

```python
@dataclass
class OrderCreatedEvent:
    order_id: int
    customer_email: str
    total: float
    items_summary: str

class OrderNotifier(ABC):
    @abstractmethod
    def notify_order_created(self, event: OrderCreatedEvent) -> None:
        ...
    
    @abstractmethod
    def notify_order_confirmed(self, event: OrderCreatedEvent) -> None:
        ...
    
    @abstractmethod
    def notify_order_shipped(self, event: OrderCreatedEvent) -> None:
        ...

class SMTPNotifier(OrderNotifier):
    def __init__(self, smtp_config: SMTPConfig, template_renderer: TemplateRenderer):
        self.smtp = SMTPConnection(smtp_config.host, smtp_config.port)
        self.renderer = template_renderer
    
    def notify_order_created(self, event: OrderCreatedEvent) -> None:
        subject = f"Order #{event.order_id} Received"
        body = self.renderer.render("order_created.html", event=event)
        self.smtp.send(event.customer_email, subject, body)
```

```python
# domains/order/validation.py
from abc import ABC, abstractmethod
from typing import Protocol

class ValidationError(Exception):
    def __init__(self, field: str, message: str):
        self.field = field
        self.message = message
        super().__init__(f"{field}: {message}")

class OrderValidationRule(Protocol):
    def validate(self, order_data: dict) -> list[ValidationError]:
        ...

class RequiredFieldsRule:
    def validate(self, data: dict) -> list[ValidationError]:
        errors = []
        for field in ["customer_id", "items", "shipping_address"]:
            if not data.get(field):
                errors.append(ValidationError(field, f"is required"))
        return errors

class ItemCountRule:
    def __init__(self, max_items: int = 100):
        self.max_items = max_items
    
    def validate(self, data: dict) -> list[ValidationError]:
        if len(data.get("items", [])) > self.max_items:
            return [ValidationError("items", f"Exceeds maximum of {self.max_items}")]
        return []

class PositivePriceRule:
    def validate(self, data: dict) -> list[ValidationError]:
        errors = []
        for i, item in enumerate(data.get("items", [])):
            if item.get("unit_price", 0) <= 0:
                errors.append(ValidationError(f"items[{i}].unit_price", "must be positive"))
        return errors

# Pipeline composition
class OrderValidator:
    def __init__(self, rules: list[OrderValidationRule]):
        self.rules = rules
    
    def validate(self, data: dict) -> list[ValidationError]:
        all_errors = []
        for rule in self.rules:
            all_errors.extend(rule.validate(data))
        return all_errors
    
    def assert_valid(self, data: dict) -> None:
        errors = self.validate(data)
        if errors:
            raise ValidationErrorCollection(errors)
```

Replace inline `if len(order_data["items"]) > 100:` checks and similar validation scattered throughout OrderService with:


### Step 5: Extract Pricing & Tax Engine

This is the domain-heavy part. Decouple from OrderService completely:

```python
# domains/order/pricing.py
class LineItem:
    def __init__(self, product_code: str, quantity: int, unit_price: float):
        self.product_code = product_code
        self.quantity = quantity
        self.unit_price = unit_price

class OrderTotalCalculation:
    subtotal: float
    discount_percent: float
    discount_amount: float
    tax_base: float
    tax_amount: float
    grand_total: float

class PricingEngine:
    def calculate(self, line_items: List[LineItem], discount_pct: float = 0) -> OrderTotalCalculation:
        subtotal = sum(li.quantity * li.unit_price for li in line_items)
        discount_amount = subtotal * (discount_pct / 100)
        tax_base = subtotal - discount_amount
        
        pricing = OrderTotalCalculation(
            subtotal=subtotal,
            discount_percent=discount_pct,
            discount_amount=discount_amount,
            tax_base=tax_base,
            tax_amount=0,  # filled by TaxCalculator
            grand_total=0   # filled by TaxCalculator
        )
        return pricing

class TaxCalculator:
    def apply(self, calculation: OrderTotalCalculation, tax_category_map: dict) -> OrderTotalCalculation:
        # Look up tax rates per product category
        total_tax = 0.0
        for item in line_items:
            rate = tax_category_map.get(item.product_code, 0.05)
            total_tax += item.quantity * item.unit_price * rate
        
        calculation.tax_amount = round(total_tax, 2)
        calculation.grand_total = round(calculation.subtotal - calculation.discount_amount + calculation.tax_amount, 2)
        return calculation
```

### Strangler Implementation Steps

**Step 1 of 4: Wire the interfaces, keep delegation**
```python
# After extracting repositories, notifier, auditor:
class OrderService:
    # NEW constructor signature (backward compatible via defaults)
    def __init__(self, connection=None, mailer=None, auditor=None,
                 # NEW dependencies (injected when available):
                 order_repo=None, notifier=None, auditor_interface=None,
                 validator=None, pricing_engine=None):
        
        # Maintain backward compatibility: if repos not given, build adapters on-the-fly
        self._order_repo = order_repo or self._build_inline_repo(connection)
        self._notifier = notifier or self._build_inline_notifier(mailer)
        self._auditor = auditor_interface or self._build_inline_auditor(auditor)
        self._validator = validator or self._LegacyValidator()  # keeps old validation logic
        self._pricing_engine = pricing_engine or self._LegacyPricingCalculator()
        
        # DELEGATING WRAPPERS (preserve public API)
        def _build_inline_repo(conn):
            """Wraps old SQL calls in new repo interface."""
            return SQLAdapterOnTopOfOldConn(conn)
    
    # PUBLIC METHODS — all routes through NEW interfaces now
    # but the old private implementations are called as fallback
    def create_order(self, order_data):
        # NEW path
        self._validator.assert_valid(order_data)
        line_items = self._convert_to_line_items(order_data["items"])
        calculation = self._pricing_engine.calculate(line_items)
        
        order_dto = self._map_to_dto(order_data, calculation)
        saved = self._order_repo.save(order_dto)
        
        if self._notifier:
            self._notifier.notify_order_created(saved.id)
        if self._auditor:
            self._auditor.log("ORDER_CREATED", saved.id)
        
        return self._map_from_dto(saved)
```

```python
    cursor = self._connection.cursor()

    order = cursor.fetchone()
    if not order:
        raise OrderNotFoundError(order_id)
    
    cursor.execute("UPDATE orders SET status = 'confirmed' WHERE id = %s", (order_id,))
    self._mailer.send(order[3], "Order Confirmed", ...)  # embedded email body
    self._auditor.log("ORDER_CONFIRMED", order_id, notes)

# After:
def confirm_order(self, order_id: int, notes: str = ""):
    order = self._order_repo.find_by_id(order_id)
    if not order:
        raise OrderNotFoundError(order_id)
    
    self._order_repo.update_status(order_id, "confirmed")
    if self._notifier:
        self._notifier.notify_order_confirmed(
            OrderCreatedEvent(order_id, order.customer_email, ...)
        )
    if self._auditor:
        self._auditor.log("ORDER_CONFIRMED", order_id, notes)
```

## Behavior Preservation Verification Strategy

### Commit-by-Commit Gate

Every commit must pass through this gate:

```
git pre-commit hook (or CI check):

1. Run characterization test suite (all golden masters)
   $ pytest tests/goldens/ -q
   ↓
2. If ALL pass → commit accepted
   ↓
3. If ANY fail → commit blocked
   - Golden mismatch detected → behavior changed
   - Compare old golden vs new execution
   - If change was INTENTIONAL: review and update golden
   - If change was UNINTENDED: revert and investigate
```

Pre-commit hook example:

```bash
#!/bin/bash
# .husky/pre-commit or .githooks/pre-commit

echo "Running golden master tests..."
python -m pytest tests/goldens/ --tb=short -q

if [ $? -ne 0 ]; then
    echo ""
    echo "GOLDEN MASTER VIOLATION DETECTED"
    echo "Behavior has changed since baseline."
    echo "If this change is intentional, regenerate golden:"
    echo "  python -m pytest tests/goldens/ --update-golden"
    echo ""
    exit 1
fi

echo "✓ All golden masters passed. Behavior preserved."
```

### Progressive Testing Timeline

| Phase | Test Coverage | Pass Condition |
|-------|--------------|----------------|
| **Phase 1** (Days 2-7) | 100% of public methods covered by golden tests (characterization only) | All characterizations pass against baseline |
| **Phase 2** (Weeks 2-6) | Every extraction step verified by golden tests | Same as above — no behavior drift |
| **Phase 3** (Weeks 3-10) | Golden tests pass + unit tests for NEW code (pricing engine, validators, repos) | Golden tests pass + new unit tests pass |
| **Phase 4** (Weeks 10+) | Delete old OrderService + replace with facade → golden tests still pass + new domain-focused unit tests | Full green |

### Golden Update Discipline

When behavior legitimately needs to change (bug fix):

```
1. Fix the bug in the new code
2. Observe golden test failure
3. Review the diff carefully
4. If change is correct → update the golden:
   rm tests/goldens/<affected>.json
   python -m pytest tests/goldens/ --update-golden
5. Add regression test capturing the corrected behavior
6. Commit with message: "fix X: update golden after correcting [description]"
```

### What Golden Tests Prove vs Don't Prove

| Proves | Does NOT Prove |
|--------|---------------|
| SQL statement sequence is identical | Performance characteristics are unchanged |
| Returned data shapes/values match | Memory consumption is equivalent |
| Email content matches exactly | Notification timing/delays are unchanged |
| Audit trail entries match | Concurrency/race conditions are handled correctly |
| Exceptions thrown match | Error recovery paths (retries) behave the same |

Supplement golden tests with:
- **Integration tests** against real database (for transaction boundaries, isolation levels)
- **Conformance tests** against the domain model contracts (new unit tests for PricingEngine, Validator, etc.)
