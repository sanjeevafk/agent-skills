## Phase 0 — Characterization / Golden-Master Testing

**Goal**: Achieve behavioral equivalence without modifying any production code. Every public method gets an encoded input/expected-output pair before any refactoring touches it.

### Step 0a — Inventory every public method

```python
from api.code_transform import grep_public_methods
methods = grep_public_methods('order_service.py')
# Returns list of {(name, line, args_count), ...}
```

For each public method, the test harness captures **three dimensions of output**:

1. **Return value** — serialized deterministically (sorted dicts/lists)
2. **Database mutations** — snapshot after execution, before rollback
3. **Side effects** — queued emails, audit log entries

### Step 0b — Snapshot database mutations (golden DB snapshots)

```python
import json
import hashlib
from contextlib import contextmanager

@contextmanager
def snapshot_db(session_factory, operations):
    """Run `operations` inside a transaction and return a diff-safe snapshot."""
    conn = session_factory()
    tx = conn.begin()
    try:
        # Capture pre-state for tables touched by the operation
        yield conn
        conn.commit()

        # After commit, serialize the affected tables
        rows = {}
        for table_name in _tables_touched(operations):
            query = f"SELECT * FROM {table_name} ORDER BY id"
            rows[table_name] = [dict(r._mapping) for r in conn.execute(query)]

        # Deterministic hash + JSON blob
        payload = json.dumps(rows, sort_keys=True, default=str).encode()
        snapshot = {"hash": hashlib.sha256(payload).hexdigest(), "payload": json.loads(json.dumps(rows, default=str))}
    finally:
        tx.rollback()
    return snapshot
```

Each public method under test produces a `{method_name -> snapshot}` entry written to `tests/golden/order_snapshots_v1.json`. If behavior changes later, the diff triggers a CI failure.

### Step 0c — Capture email side effects

Don't send real mail during golden capture. Replace the SMTP transport with an in-memory collector behind the same interface:

```python
class InMemoryMailTransport:
    def __init__(self):
        self.sent: list[dict] = []

    async def send(self, to: str, subject: str, body: str):
        self.sent.append({"to": to, "subject": subject, "body": body})

    def clear(self):
        self.sent.clear()
```

Every public method's test records `actual_sent[:]` and compares against expected via deep equality (order-sensitive — email ordering is part of behavior).

### Step 0d — Capture audit-log side effects

Audit logging is likely written to a table or message queue. Same pattern as email: use an in-memory auditor.

```python
class RecordingAuditor:
```

## Phase 1 — Seam Extraction (Interface-first)

The extraction order is dictated by **dependency depth** — isolate the most-coupled collaborator first so later layers have clean interfaces to depend on.

### Seam 1: Persistence Repository (highest dependency density)

Direct SQL scattered throughout methods means every business method depends on `session.execute()`. This is the deepest seam.

**Target**: Extract `OrderRepository` with exactly the CRUD & query signatures used.

```python
# Domain-side interface (no SQLAlchemy imports)
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Optional

@dataclass
class OrderRow:
    id: str
    customer_id: str
    status: str
    total_cents: int
    created_at: str

class OrderRepository(ABC):
    @abstractmethod
    async def save(self, row: OrderRow) -> None: ...
    @abstractmethod
    async def find_by_id(self, order_id: str) -> Optional[OrderRow]: ...
    @abstractmethod
    async def find_by_customer(self, customer_id: str) -> list[OrderRow]: ...
    @abstractmethod
    async def update_status(self, order_id: str, new_status: str) -> None: ...
```

**Refactor step**: Find every `self.session.execute(...)` call in OrderService. Each group of related statements becomes one repository method. Then replace the raw SQL with `await self._repo.save(...)`, etc. One commit per method replaced. After all replaces are done, the commit that removes `self.session` from OrderService is the seam completion.

**Proof of preservation**: Run the golden-master test suite. Return values, DB snapshots, email queue, and audit log must match v1 exactly.

### Seam 2: Pricing Strategy

Once the repository is isolated, pricing logic (which currently likely reads item prices from SQL or external services inline) can be pulled into a `PricingEngine` interface.

```python
class PricingEngine(ABC):
    @abstractmethod
    async def compute_total(self, items: list[dict], coupon_code: Optional[str]) -> int:
        """Returns total in cents."""
        ...
```

Extract the inline math into `PricingStrategy` implementations (`FlatPricing`, `TieredPricing`, `CouponPricing`). Use composition over inheritance — inject the appropriate strategy at construction time.

### Seam 3: Tax Calculator

Similar pattern — pull tax computation out of OrderService into `TaxCalculator`.

```python
class TaxCalculator(ABC):
    @abstractmethod
    async def compute_tax(self, subtotal: int, region: str) -> int:
        """Returns tax amount in cents."""
        ...
```

### Seam 4: Email Notification Service

```python
class NotificationService(ABC):

        ...
    @abstractmethod
    async def notify_order_cancelled(self, order_id: str, customer_email: str):
```

Replace direct SMTP calls with `await self._notifier.notify_order_created(...)`.

## Behavior Preservation — How You Prove It at Every Commit

### 1. Golden-Master Assertions (mandatory pre-merge)

```python
"""tests/golden/test_behavior_preservation.py"""
import json, pytest

GOLDEN_FILE = "tests/golden/order_snapshots_v1.json"

@pytest.mark.parametrize("method_name,expected", 
    load_golden_cases(GOLDEN_FILE).items())
def test_no_regression(method_name: str, expected: dict):
    """Run method against fixtures and compare snapshots byte-for-byte."""
    actual = execute_method_and_capture(method_name)
    
    assert actual["return_value"] == expected["return_value"], \
        f"{method_name} return value changed"
    assert actual["db_snapshot"]["hash"] == expected["db_snapshot"]["hash"], \
        f"{method_name} DB state changed"
    assert actual["emails_sent"] == expected["emails_sent"], \
        f"{method_name} emails sent differ"
    assert actual["audit_entries"] == expected["audit_entries"], \
        f"{method_name} audit log differs"
```

This runs as a required CI check. Any change in behavior fails the build. To update the baseline (intentional behavior change), someone must update `tests/golden/order_snapshots_v1.json` explicitly and document what changed.

### 2. Contract Tests on Public Signatures

```python
import inspect
from src.order_service import OrderService

PUBLIC_METHODS = {
    "create_order": ("request_dict",),
    "cancel_order": ("order_id", "actor"),
    "apply_discount": ("order_id", "coupon_code"),
    # ... every public method + its arg signature
}

def test_public_api_signature_unchanged():
    """Regression guard: no one renames or reshapes public methods."""
    svc = OrderService.__new__(OrderService)  # avoid instantiation issues
    for method_name, expected_args in PUBLIC_METHODS.items():
        assert hasattr(svc, method_name), f"Missing public method: {method_name}"
        sig = inspect.signature(getattr(OrderService, method_name))
        actual = tuple(p.name for p in sig.parameters.values() if p.default == inspect.Parameter.empty)
        assert actual == expected_args, f"{method_name} signature changed from {expected_args} to {actual}"
```

## Risk Mitigation

| Risk | Mitigation |
|---|---|
| Golden snapshot mismatch after refactor | Run golden suite **before** and **after** each commit; fix before merging |
| Interface evolution breaks consumers | All consumers are internal — single codebase. Change interface + usage atomically in one commit |
| SQL dialect differences between environments | Adapter layer accepts raw SQL from repo impl — environment-specific dialects stay localized |
| Email timing affects downstream systems | Captured in memory; comparison is content-only, not timestamp-dependent |
| Audit log ordering matters | Recorded in insertion order; compared list-equality |
