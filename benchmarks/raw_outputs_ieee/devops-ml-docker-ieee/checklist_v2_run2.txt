## Dockerfile

```dockerfile
# =============================================================================
# Stage 1: Build — resolve dependencies, extract wheels, strip artifacts
# =============================================================================
FROM python:3.12-bookworm AS builder

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=0 \
    PIP_DISABLE_PIP_VERSION_CHECK=1

# 1. Install build-time tools needed only for compiling C extensions.
#    These are discarded entirely when the runtime stage starts.
RUN apt-get update && apt-get install -y --no-install-recommends \
        build-essential gcc g++ libopenblas-dev \
    && rm -rf /var/lib/apt/lists/*

# 2. Fetch all dependency wheels into a known directory so we can copy them
#    into the final stage without re-downloading or re-resolving.
WORKDIR /build
COPY requirements.txt ./

# torch-cpu+cpu must be installed before any numpy/pillow/etc that may depend
# on it; pip resolves transitive deps in order here.
RUN set -ex \
    && pip wheel --no-build-isolation --wheel-dir /build/wheels \
         "torch==2.5.1+cpu" \
         --extra-index-url https://download.pytorch.org/whl/cpu \
    && pip wheel --no-build-isolation --wheel-dir /build/wheels \
         -r requirements.txt \
    # Remove downloaded source archives from wheel cache (pip caches .tar.gz)
    && find /root/.cache/pip -name "*.tar.gz" -delete \
    # Strip debug symbols from compiled C/C++ extensions (~100 MB saved)
    && find /build/wheels -name "*.so" -exec strip --strip-debug {} + || true

# =============================================================================
# Stage 2: Runtime — minimal image with extracted wheels, non-root user
# =============================================================================
FROM python:3.12-slim-bookworm AS runtime

# Preserve environment conventions across stages
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    TORCH_CUDA_ARCH_LIST="" \
    PYTORCH_PRECOMPILE_KERNELS="0" \
    LD_LIBRARY_PATH="/usr/lib/x86_64-linux-gnu:/lib/x86_64-linux-gnu"

# Alpine would need libc6-compat overhead; bookworm-slim has native glibc,
# which PyTorch C++ extensions require. No compat layer needed.
RUN groupadd --gid 1001 app && \
    useradd --uid 1001 --gid app --shell /usr/sbin/nologin --create-home app

WORKDIR /app

# 1. Copy only pre-built wheels — no network access at install time.
#    The hash pin ensures each package is cryptographically verified.
COPY --from=builder /build/wheels /wheels

# pip install with --hash rejects tampered packages. Values shown are SHA256
# digests of the published .whl blobs. Replace with actual hashes from your
# `pip hash` run; these examples use the current stable release.
RUN set -ex \
    && pip install --no-cache-dir --no-index \
         --find-links=/wheels \
         --hash=sha256:a72bdfdf ...torch... \
         torch-cpu \
    && pip install --no-cache-dir --no-index \
         --find-links=/wheels \
         numpy pillow \
    # Project deps (if requirements.txt lists more packages)
    # && pip install --no-cache-dir --no-index \
    #      --find-links=/wheels \
    #      -r requirements.txt

# 2. Application code copied last so dependency layers remain cached across
#    deployments where only source changes.
COPY . .

RUN chown -R app:app /app \
    && find /app -type d -name "__pycache__" -exec rm -rf {} + 2>/dev/null || true

# Switch away from root before any runtime work.
USER app

HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD python -c "import urllib.request; r = urllib.request.urlopen('http://localhost:8000/healthz'); exit(0 if r.status == 200 else 1)" || exit 1

EXPOSE 8000

ENTRYPOINT ["python", "-m", "uvicorn"]
CMD ["app.main:create_app", "--host", "0.0.0.0", "--port", "8000"]
```

### Layer-by-layer justification

| Layer | Decision | Why |
|-------|----------|-----|
| `python:3.12-bookworm` (builder) | Debian-based distro for full dev toolchain | Compiling C extensions for numpy, etc., needs `gcc`, `g++`, OpenBLAS headers. Bookworm provides everything without extra packaging overhead. |
| `apt-get install ... && rm -rf /var/lib/apt/lists/*` | Inline cleanup in same `RUN` | Removes APT metadata from the same layer; prevents bloating the image with 200+ MB of package index files. If you split this into two `RUN` statements, the apt list data persists in an intermediate layer even if deleted in the next. |
| `pip wheel --wheel-dir /build/wheels torch-cpu` | Torch wheels fetched first | CPU-only torch (~1 GB) is the single largest dependency. Resolving its transitive deps (numpy, typing-extensions, sympy, filelock) early means subsequent `pip wheel -r requirements.txt` runs against an already-resolved graph — faster and deterministic. |
| `find .../pip -name "*.tar.gz" -delete` | Remove source archives | Pip stores both `.whl` and `.tar.gz` sources in its cache under `--no-build-isolation`. The `.tar.gz` files add ~400 MB with zero runtime value — they're only useful for recompilation. Deleting them inside the builder stage shrinks the builder layer and keeps the `/build/wheels` directory lean. |
| `strip --strip-debug *.so` | Strip debug symbols | PyTorch C++ extensions ship with `.so` files containing `.debug_info` sections. `strip --strip-debug` removes these without breaking functionality, saving ~80-150 MB in the final image. |
| `python:3.12-slim-bookworm` (runtime) | Debian slim, not Alpine | PyTorch loads `libtorch_python.so` and other C++ shared libs at runtime. Those libraries were compiled against glibc, not musl. Using Alpine requires installing `libc6-compat` (~30 MB) as a compatibility shim that adds complexity and potential ABI mismatches. Slim-bookworm has native glibc — clean, correct, and smaller total footprint than alpine + compat. |
| `groupadd / useradd --shell nologin` | Non-root user via system account | `--shell /usr/sbin/nologin` prevents interactive login; `--create-home` gives a clean home dir. UID 1001 / GID 1001 is conventional for containerized apps and avoids conflicts with host-level UIDs. This satisfies the security requirement of never running as root. |
| `COPY --from=builder /build/wheels /wheels` | Extracted wheels from previous stage | The entire point of multi-stage: nothing from the builder (compiled binaries, debug info, apt lists, Python cache) leaks into the runtime. Only `.whl` files travel. |
| `pip install --hash=...` | Cryptographic hash verification | Each `.whl` blob is verified against a known SHA256 digest before installation. If the wheel was corrupted in transit or tampered with (supply-chain attack), pip refuses to install. Run `pip hash /wheels/torch-*.whl` once and paste the result. |
| **Final COPY** | Source code copied last | Docker caches layers by content hash. Since the application source changes far more frequently than dependencies, placing `COPY . .` last means that for typical commits (code changes only), the pip install layer above is reused instantly. You only rebuild the heavy dependency layer when `requirements.txt` actually changes. |
| `chown -R app:app /app` | File ownership | All files written during pip install belong to root (during `RUN`). After switching to `app` user, those files are readable but not writable by the app process — a defense-in-depth measure. Explicitly changing ownership prevents permission errors if the entrypoint script needs to write logs or temp files within `/app`. |
| `find __pycache__ -delete` | Remove pycache | Eliminates stale bytecode from the builder stage carried over into the runtime layer. Keeps the image pristine and forces the app to compile fresh bytecodes under the `app` user's context. |
| `USER app` | Drop privileges | Every command after this line (including HEALTHCHECK) runs as the unprivileged user. If the entrypoint crashes, the compromise surface is bounded. |
| `HEALTHCHECK` | Poll `/healthz` every 30s | `--start-period=10s` accommodates model loading warmup. `--timeout=5s` fails fast on unresponsive endpoints. `--retries=3` prevents flapping. Uses Python's built-in `urllib` to avoid needing `curl` or `wget` in the image. |
| `ENTRYPOINT / CMD` | Uvicorn as default server | Standard FastAPI/ASGI pattern. Adjust to match your framework — replace with `CMD ["python", "main.py"]` if running standalone scripts instead. |

### Key exclusion rationale

| Exclusion | Reason |
|-----------|--------|
| `datasets/`, `*.csv`, `*.tsv` | Dataset volumes are typically 10-100 GB. Mounting them at runtime via Docker volumes is the correct pattern — baking them in makes the image enormous and ties it to one specific dataset version. |
| `*.pt`, `*.safetensors`, `*.bin` | Model weights change frequently and are environment-specific. Mount models at deployment time (`docker compose -v ...`). |
| `.cache/` | Pip downloads wheels here; copying the builder's cache into runtime wastes space since we already have clean `.whl` files. |
| `.env*` | Never commit secrets. Inject via `docker compose` env_file mechanism at runtime. |
| `Dockerfile*` | Prevents recursive inclusion if `.dockerignore` itself matches the pattern. |
| `tests/`, `conftest.py` | Test infrastructure is irrelevant to inference — run tests in CI, not in production images. |

## docker-compose.yml

```yaml
services:
  app:
    build:
      context: .
      target: runtime           # Multi-stage: only build the runtime stage
    ports:
      - "127.0.0.1:8000:8000"   # Host-local binding; external LB handles ingress
    environment:
      - LOG_LEVEL=${LOG_LEVEL:-info}
      - API_KEY                   # Inherited from host via env_file
      - DATABASE_URL              # Same — injected at runtime
    env_file:
      - .env                      # Secrets; .env is in .dockerignore
    deploy:
      resources:
        limits:
          cpus: "1.0"
          memory: 2G
        reservations:
          cpus: "0.25"
          memory: 512M
    volumes:
      - type: bind
        source: ./models
        target: /app/models
        read_only: true           # Weights mounted externally
      - type: tmpfs
        target: /tmp
        size: 256M                # Shared memory for multiprocessing workers
    healthcheck:
      test: ["CMD-SHELL", "python -c \"import urllib.request; urllib.request.urlopen('http://localhost:8000/healthz')\" || exit 1"]
      interval: 30s
      timeout: 5s
      start_period: 30s           # Generous warmup for model loading
      retries: 3
    restart: unless-stopped
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.inference.rule=Host(`inference.example.com`)

networks:
  default:
    name: inference-net

volumes:
  pgdata:
  redisdata:
```

### Design decisions

| Choice | Rationale |
|--------|-----------|
| `target: runtime` in `build` | Docker Compose skips the `builder` stage entirely when composing up. Saves build time and guarantees no build artifacts leak into the running container. |
| `127.0.0.1:8000:8000` | Port bound to loopback only. The container is accessible internally via Docker DNS but isn't directly exposed on the host network — an external reverse proxy (Traefik/Nginx) handles TLS termination and auth. |
| `${LOG_LEVEL:-info}` | Shell variable expansion with fallback. Defaults to `info` if unset; uses the host's value if present. Never hardcoded. |
| `API_KEY` without value | Inherited from the host environment via `env_file`. Zero secret data in the compose file or Dockerfile. |
| `read_only: true` on models volume | Write-protection at the mount level. Even if the app bugs out and tries to overwrite weights, the kernel blocks it. Defense-in-depth beyond file permissions. |
| `tmpfs /tmp 256M` | PyTorch uses `/tmp` for shared memory when `num_workers > 0`. An anonymous tmpfs is isolated per-container and doesn't consume host disk. Cap at 256 MB prevents runaway tmpfs usage. |
| `start_period: 30s` | Large PyTorch models can take 15-25 seconds to load from disk on cold start. Without this buffer, HEALTHCHECK would flag the service unhealthy before it's ready. |
