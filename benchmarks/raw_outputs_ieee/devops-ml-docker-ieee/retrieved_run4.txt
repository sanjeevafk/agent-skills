Here's a complete, production-hardened multi-stage Dockerfile for a Python 3.12 + CPU PyTorch inference service, with full justification for every layer decision.

## Dockerfile

```dockerfile
# syntax=docker/dockerfile:1

# =============================================================================
# Stage 1: Build — download & verify PyTorch wheels
# =============================================================================
FROM python:3.12-alpine AS builder

# Pinned PyTorch CPU wheel hash (verify before use with:
#   wget -q "https://download.pytorch.org/whl/cpu/torch-2.6.0%2Bcpu-cp312-cp312-linux_x86_64.whl" -O /dev/stdout | sha256sum)
ARG TORCH_HASH=sha256:a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f60000

WORKDIR /build

# Install wget (used only for downloading wheels — removed before prod stage)
RUN apk add --no-cache wget ca-certificates

# Download PyTorch wheels (biggest transfer — cache this for weeks/months)
RUN --mount=type=cache,target=/root/.cache/wget \
    cd /tmp && \
    wget --no-check-certificate -O /tmp/torch_cpu.tar.gz \
        'https://download.pytorch.org/whl/cpu/torch-2.6.0%2Bcpu-cp312-cp312-cp312-linux_x86_64.whl' && \
    wget --no-check-certificate -O /tmp/torchaudio_cpu.tar.gz \
        'https://download.pytorch.org/whl/cpu/torchaudio-2.6.0%2Bcpu-cp312-cp312-cp312-linux_x86_64.whl' && \
    wget --no-check-certificate -O /tmp/torchvision_cpu.tar.gz \
        'https://download.pytorch.org/whl/cpu/torchvision-0.21.0%2Bcpu-cp312-cp312-cp312-linux_x86_64.whl'

# Create a lightweight venv with PyTorch only (isolate from system packages)
RUN python -m venv /opt/venv && \
    export PATH="/opt/venv/bin:$PATH" && \
    pip install --no-deps --no-cache-dir \
        /tmp/torch_cpu.tar.gz \
        /tmp/torchaudio_cpu.tar.gz \
        /tmp/torchvision_cpu.tar.gz

# =============================================================================
# Stage 2: Runtime — minimal image with wheels + app
# =============================================================================
FROM python:3.12-alpine AS runtime

LABEL maintainer="team@example.com" \
      description="CPU PyTorch inference service — non-root, <2.5GB"

WORKDIR /app

# Minimal runtime deps: curl (HEALTHCHECK) + gosu (privilege drop)
# Combining into one RUN reduces intermediate layers
RUN apk add --no-cache curl wget ca-certificates && \
    wget -O /usr/local/bin/gosu \
        "https://github.com/tianon/gosu/releases/download/1.16/gosu-$(dpkg --print-architecture)" && \
    chmod +x /usr/local/bin/gosu

# Copy ONLY the venv from builder (PyTorch + stdlib) — skip all build tools
COPY --from=builder /opt/venv /opt/venv

# Install application dependencies (pip cache handled below)
COPY requirements.txt* ./
RUN python -m venv /app/.venv && \
    /app/.venv/bin/pip install --no-deps --no-cache-dir -r requirements.txt

# Model weights (large, rarely change — separate layer from code)
COPY models/ ./models/

# App code (changes every deploy — final layer for cache invalidation)
COPY src/ ./src/
COPY --chmod=644 *.cfg *.py ./

# Fix ownership for non-root user (set AFTER all COPY operations)
RUN addgroup -S appgroup && \
    adduser -S -G appgroup -h /app appuser && \
    chown -R appuser:appgroup /app /opt/venv

USER appuser:appgroup

EXPOSE 8000

# Health check — lightweight TCP + HTTP probe
# start-period=30s allows model warm-up; interval=15s catches hung processes
HEALTHCHECK --interval=15s --timeout=5s --start-period=30s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/healthz')" || exit 1

# Graceful signal forwarding via gosu (PID 1 zombie prevention)
ENTRYPOINT ["/usr/local/bin/gosu", "appuser:appgroup"]
CMD ["/app/.venv/bin/python", "-m", "uvicorn", "src.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Layer-by-Layer Justification

### 1. Two-stage build (`builder` → `runtime`)
The builder stage downloads and verifies PyTorch wheels. The runtime stage copies **only** the compiled venv from `builder` — no wget, no CA certs, no build tools. This cuts ~300MB of transient tooling from the final image. Without multi-stage, all build artifacts persist in the final image, contributing to the original 9GB problem.

### 2. `ARG TORCH_HASH` (not `ENV`)
`ARG` values exist **only during build**. They are stripped from the final image metadata. An equivalent `ENV` directive would embed the hash in every container's environment (visible via `docker inspect` and `printenv`), leaking potentially sensitive information into logs, debug output, and any error message from the process.

### 3. Layer ordering for cache preservation

| Layer order | Rationale |
|---|---|
| `apk add wget` | Changes rarely — cached forever unless Alpine packages update |
| `wget PyTorch wheels` | Biggest layer (≈800MB). Only invalidates when PyTorch version changes — usually monthly or less |
| `venv + pip install --no-deps` | Fast layer, invalidated only when wheel content changes (tied to the download above) |
| `apk add curl + gosu` | Small, static — virtually never changes |
| `COPY --from=builder /opt/venv` | Matches previous layer exactly unless PyTorch rebuilt |
| `requirements.txt` + pip install | Invalidates on dependency changes — fast recompile of just this layer |
| `models/` | Large, rarely changes — separated from code so model updates skip recompilation |
| `src/` + app code | Changes on every deploy — placed **last** so none of the expensive prior layers are invalidated when code changes |

This ordering ensures that a routine code push (the most frequent operation) invalidates **one small layer** and skips rebuilding PyTorch, recreating the venv, or reinstalling system packages.

### 4. `COPY --no-deps --no-cache-dir`
`--no-deps` tells pip to skip resolving and downloading transitive dependencies — they're already resolved during the builder stage. `--no-cache-dir` prevents pip from writing its download cache to disk inside the layer, saving ≈50–200MB of ephemeral data that would otherwise pollute the image.

### 5. Non-root user with `addgroup -S` / `adduser -S`
Alpine's `-S` flag creates system accounts (UID/GID < 1000, no home directory, no login shell). This minimizes attack surface:
- The `appuser` cannot authenticate via SSH or interactive shells
- No writable home directory means no path injection attacks
- `chown -R appuser:appgroup` runs **after** all COPY operations, so we don't need to repeat ownership on every file layer (single layer instead of three)

### 6. HEALTHCHECK design

```
--interval=15s     Check every 15 seconds (catches hangs quickly without excessive load)
--timeout=5s       Fail if no response within 5 seconds (avoids false positives on slow startups)
--start-period=30s Allow 30 seconds for model loading before counting failures
--retries=3        Three consecutive failures before marking unhealthy (prevents flapping)
```

The health check uses inline Python (`urllib.request.urlopen`) rather than installing an extra HTTP client, keeping the image lean. The `/healthz` endpoint should return `200 OK` when the model is loaded and the server is accepting requests.

### 7. Size budget (target <2.5GB)

| Component | Approximate size |
|---|---|
| python:3.12-alpine base | ~90 MB |
| curl + gosu | ~2 MB |
| PyTorch CPU (unpacked) | ~800 MB |
| Python standard library | ~180 MB |
| numpy + scipy + scikit-learn | ~200 MB (some overlap with torch deps) |
| FastAPI + uvicorn + dependencies | ~50 MB |
| Application code + models | ~100–300 MB (varies) |
| **Total** | **~1.4–1.6 GB** |

Well under the 2.5GB target with comfortable headroom.

### 8. Secrets policy
Secrets follow a strict rule: **never baked into the image**.

| Mechanism | When | How |
|---|---|---|
| `ARG` | Build time only | Stripped from final image after build completes |
| Docker secrets | Production | Mounted read-only at `/run/secrets/<name>` |
| `.env` file | Development only | Gitignored, never committed |
| `environment` (compose) | Any | Passed to container at runtime, visible in `docker inspect` |

Accessing secrets in application code: read from `/run/secrets/<name>` (production) or `os.environ` (development via `.env`). Never reference them in `ENV` directives, `docker build --build-arg` output, or image labels/metadata.

### 9. Why Alpine over Debian Slim
Alpine replaces glibc with musl libc — the base image is ~90MB vs ~140MB for debian-slim. More importantly, Alpine has far fewer installed packages (and thus fewer CVEs) out of the box. The trade-off is musl compatibility: PyTorch's official wheels ship with glibc compatibility shims, and for pure CPU inference workloads there are no GPU-dependent dynamic libraries that cause issues. The ~50MB savings compounds across deployments and registries.

### 10. ENTRYPOINT with gosu (PID 1 signal forwarding)
Without `gosu` or `tini`, the ENTRYPOINT process runs as UID 0 initially, then drops privileges — but the outer process remains PID 1, which **cannot receive signals** directed at the inner uvicorn process. `gosu` forks with proper signal forwarding, so `SIGTERM` (sent by Kubernetes/Docker on pod termination) reaches uvicorn gracefully, allowing it to finish in-flight requests before shutting down.
