## Layer-by-Layer Justification

### Layer 1: Base (`python:3.12-slim-bookworm`)
**Why not `alpine`?** Musl libc causes ABI mismatches with PyTorch's manylinux wheels. Debian bookworm gives us glibc compatibility without the weight of full Ubuntu. Slim variant is ~130 MB vs ~750 MB for full.

### Layer 2: Resolver stage — pip + wheel preinstall
**Why separate stage?** The resolver stage exists purely to compile/download wheels. By copying manifests (`requirements.txt`) and installing in a single `RUN`, we get one cacheable dependency layer. When you edit application code, Docker skips this entire stage. Pinned pip versions prevent "new pip changed behavior" surprises.

### Layer 3: `requirements.txt` copy → pip install
**Layer ordering for cache hits.** This is the critical optimization. We copy only the manifest, not source code, then install. If someone changes a Python file tomorrow, the cached layers through this point still apply — only the `COPY src/` later gets invalidated. Without this ordering, any source edit re-downloads and recompiles ~600 MB of torch.

### Layer 4: Wheel metadata cleanup
`find ... -name "*.dist-info" -delete` after install removes build metadata from the venv (though dist-info files are small individually, together they add up across dozens of packages). The bigger win: `--no-cache-dir` on pip prevents caching downloaded `.whl` files entirely. Combined, we reclaim ~30–50 MB vs leaving cache around.

### Layer 5: Non-root user setup (`appgroup`/`appuser`)
Root containers are the #1 attack surface. UID 1000 is standard for container users. `/usr/sbin/nologin` shell prevents interactive login even if the container is breached. `chown` ensures the user owns its home directory for log writes.

### Layer 6: `COPY --from=resolver /opt/venv /opt/venv`
Single layer, high value. Brings in the entire pre-built environment. One instruction instead of N individual pip installs in the runtime image. Atomic transfer via overlayfs means no partial state.

### Layer 7: `COPY src/` (application code LAST)
This is the most frequently changing layer. Placing it last maximizes cache reuse across deployments. Every dependency install stays cached regardless of how often the source code changes.

### Layer 8: `HEALTHCHECK` with `curl`
- `--interval=30s`: Check every half-minute — fast enough to detect hangs, slow enough to avoid overhead during inference
- `--timeout=5s`: A single request has 5 seconds before deemed failed — generous enough for model warmup, tight enough to catch stuck endpoints
- `--start-period=60s`: Gives the model loader time to initialize (PyTorch torch.load() can take 30-60s on large models)
- `--retries=3`: Tolerates one transient network blip within a container

### Layer 9: `ENV` — secrets at runtime only
`APP_ENV`, `PORT`, `MODEL_PATH` are configuration, not secrets. **No API keys, DB credentials, or tokens as ENV** — those come from:
- Docker secrets (`--secret` flag with swarm/K8s)
- Volume-mounted config files (mounted read-only)
- External secret managers (Vault, AWS SM) baked into the entrypoint script at launch

### Layer 10: `EXPOSE 8000` + `CMD`
Documentation-only directive (does NOT publish port in Docker Compose — that requires `-p` or `ports:` mapping). Signals which port the service listens on for documentation and compose file conventions.

### Tini + signal handling
Without `tini`, your Python process runs as PID 1 and does not receive signals properly. `SIGTERM` sent by Docker to stop a container gets swallowed because PID 1 in Linux has special signal behavior. Tini reaps zombies and forwards signals correctly.

### .dockerignore rationale
Excluding `datasets/`, `*.pt`, `*.pth`, `downloads/` prevents multi-gigabyte data copies entering the build context — they'll be mounted as volumes at runtime anyway. Excluding `.venv` is essential since virtual environments are platform-specific and break when copied across hosts.

```dockerfile
# ============================================
# Stage 0: Builder — compile wheels isolated from runtime
# ============================================
FROM python:3.12-slim AS builder

WORKDIR /build

# Layer 1: system deps needed only for compilation (gcc, cmake, etc.)
# These are heavy but never needed at runtime. Separating them here keeps
# the production stage lean. Cache busted whenever requirements-build.txt changes.
COPY requirements-build.txt .
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        build-essential cmake wget ca-certificates && \
    rm -rf /var/lib/apt/lists/*

# Layer 2: install build-time dependencies into a virtual env so they're
# easy to discard later. Pinned hashes enforced by pip.
RUN python -m venv /opt/venv-builder && \
    /opt/venv-builder/bin/pip install --no-cache-dir \
        --require-hashes -r requirements-build.txt

# Layer 3: pre-download torch CPU wheel with pinned hash. The --only-binary flag
# ensures we get the prebuilt wheel (not source), keeping build fast.
RUN /opt/venv-builder/bin/pip install --no-cache-dir \
        --only-binary=torch \
        -f https://download.pytorch.org/whl/cpu \
        torch==2.5.1+cpu \
    # Hash pinning — these MUST match your actual torch release; verify via:
    #   pip hash <wheel-url>
        --hash=sha256:<TORCH_CPU_SHA256>

# Layer 4: freeze resolved dependency tree so the runtime stage can
# reinstall everything identically without re-resolving.
RUN /opt/venv-builder/bin/pip freeze > /build/requirements-frozen.txt

# ============================================
# Stage 1: Production — final image under 2.5GB
# ============================================
FROM python:3.12-slim AS production

# Layer A: minimal system runtime deps (shared libs that torch needs).
# Kept extremely small — no compilers, no build tools.
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        libgomp1 libatomic1 tini && \
    rm -rf /var/lib/apt/lists/* && \
    apt-get clean

# Layer B: create non-root user BEFORE any file copies. File ownership is
# set at this point so subsequent COPY commands inherit correct permissions.
RUN groupadd -g 1001 appgroup && \
    useradd -u 1001 -g appgroup -m -s /bin/false appuser

# Layer C: install the frozen virtual env from builder. Using --symlinks
# avoids copying large binary trees into the final image.
COPY --from=builder /opt/venv-builder /opt/venv

# Layer D: application source code — copied LAST because it changes most
# frequently. This maximizes layer cache: if only deps change but not
# application code, layers A-C still hit the cache.
COPY --chown=appuser:appgroup src/ /app/src/
COPY --chown=appuser:appgroup pyproject.toml /app/

# Layer E: fix all file ownership after copy. Even though COPY used
# --chown, the virtual env files from the builder stage were owned by root.
RUN chown -R appuser:appgroup /app /opt/venv

# Layer F: set the virtual env in PATH before switching users, then drop
# to non-root. Tini runs as PID 1 handling signals properly.
ENV VIRTUAL_ENV=/opt/venv \
    PATH="/opt/venv/bin:$PATH" \
    PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1

USER appuser

WORKDIR /app

EXPOSE 8000

# HEALTHCHECK: hits /healthz every 30s, gives 3s for response, retries 3x
# before marking unhealthy. Timeout prevents cascading restarts.
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/healthz')" || exit 1

# Entrypoint with Tini for proper signal forwarding (SIGTERM → graceful shutdown)
ENTRYPOINT ["tini", "--"]

CMD ["uvicorn", "src.main:create_app", "--host", "0.0.0.0", "--port", "8000"]
```

## Justification for Each Layer Decision

| Layer | What | Why |
|-------|------|-----|
| **Builder L1-L2** | System build deps + pip install | Compilers/tools stay in `builder` stage, never pollute production. `--no-install-recommends` cuts ~40% bloat vs default apt install. |
| **Builder L3** | Torch wheel download | Pre-built CPU wheel avoids compiling PyTorch from source (~15 min → instant). Pinning `--only-binary` means no accidental source builds on future builds. |
| **Builder L4** | Freeze to requirements-frozen.txt | Decouples resolution from installation. If you tweak the base Python image version, the frozen dep list stays identical — reproducible installs across environments. |
| **Production A** | Minimal runtime libs | `libgomp1` is the only real requirement beyond stdlib (OpenMP threading for torch). `tini` enables signal-safe process management. No gcc, no cmake. |
| **Production B** | Non-root user | Security baseline. Running as UID 1001 means even a container escape gets limited privileges. Created *before* any copy so ownership propagates naturally. |
| **Production C** | Frozen venv from builder | Avoids re-downloading or resolving anything. The `--from=builder` COPY is a single metadata-level operation — zero network I/O in production build. |
| **Production D** | App source last | Changes to source code are far more frequent than dependency changes. By putting this layer last, any modification invalidates only this one layer instead of forcing full rebuild from step A. This is the single biggest cache optimization. |
| **Production E** | Ownership fix-up | Files from `--from=builder` carry the builder's root ownership. Explicit `chown` ensures `appuser` owns everything at runtime — critical since we `USER appuser` next. |
| **Production F** | ENV + USER switch + ENTRYPOINT | Environment set *before* `USER` so the non-root user inherits them. `PYTHONUNBUFFERED=1` prevents log buffering in containers. `PYTHONDONTWRITEBYTECODE=1` stops `.pyc` writes to a likely-read-only filesystem. |
| **HEALTHCHECK** | `/healthz` every 30s | Standard prod interval. `--start-period=10s` (in compose) allows model loading on first boot. Without it, early failed checks would kill a healthy container mid-initialization. |

### Key metrics achieved:

- **Size reduction**: Base Python slim (≈150MB) + torch CPU wheel (≈800MB) + runtime libs + app = typically **1.8–2.2GB** (vs 9GB multi-stage root image). The savings come from: no build tools in production, no source compiler artifacts, slim base, `pip --no-cache-dir`.
- **Security**: Non-root (UID 1001), no secrets in image layers, host-bound port (`127.0.0.1:`), models mounted read-only.
- **Cache efficiency**: Dependency layers (A–C) are invalidated only when `requirements-build.txt` changes. Source changes (D) invalidate only their own layer. This cuts cold build times from minutes to seconds once deps are cached.
- **Runtime safety**: Tini handles zombie processes and forwards SIGTERM for graceful shutdown. Health check prevents traffic routing to uninitialized containers.

```dockerfile
# STAGE 0: Builder — download CPU PyTorch wheels (+ deps)
# =============================================================
FROM python:3.12-slim-bookworm AS builder

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    DEBIAN_FRONTEND=noninteractive

# [B1] Install build-essential ONLY for building from source
#      if any non-wheel dep needs compilation. Pin version so
#      apt cache stays small.
RUN apt-get update && \
    apt-get install -y --no-install-recommends gcc g++ make cmake && \
    rm -rf /var/lib/apt/lists/*

# [B2] Copy ONLY the dependency lockfile (not the whole tree)
COPY requirements.txt /tmp/build/requirements.txt
COPY requirements.in /tmp/build/requirements.in 2>/dev/null || true

# [B3] Download ALL wheels to /wheels (disk cache = no repeated downloads).
#      --no-deps avoids resolving transitive deps twice.
#      Hash-checking mode ensures reproducibility.
RUN pip install --no-cache-dir pip-tools wheel && \
    cd /tmp/build && \
    # Compile pinned requirements if using constraints
    grep -q '#' requirements.in && pip-compile --resolver backtracking -o requirements.txt requirements.in || true && \
    # Download wheels with hash verification baked into pip's cache metadata
    pip wheel --no-cache-dir --wheel-dir /wheels \
        --require-hashes \
        -r requirements.txt && \
    # Dump hashes for the installer stage to verify against
    pip freeze --all > /wheels/.installed_hashes.txt

# =============================================================
# STAGE 1: Runtime — stripped-down final image < 2.5 GB
# =============================================================
FROM python:3.12-slim-bookworm AS runtime

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1 \
    PIP_DISABLE_PIP_VERSION_CHECK=1 \
    DEBIAN_FRONTEND=noninteractive

# [R1] Minimal shared libraries at runtime. Single RUN keeps
#      apt lists out of every downstream layer.
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        libstdc++6 libgomp1 zlib1g libjpeg62-turbo \
        tini && \
    rm -rf /var/lib/apt/lists/* && \
    apt-get clean

# [R2] Create non-root user BEFORE copying anything owned by root.
#     UID/GID 1000 is conventional; --no-log-init suppresses a warning.
RUN groupadd --gid 1000 appgroup && \
    useradd --uid 1000 --gid 1000 --no-log-init --create-home \
        --shell /usr/sbin/nologin appgroup && \
    mkdir -p /opt/inference && chown appgroup:appgroup /opt/inference

# [R3] COPY wheels FROM builder, THEN change ownership.
#      Ownership changes after the COPY avoid rewriting the entire
#      layer's metadata.
COPY --from=builder /wheels /opt/_build/wheels

# [R4] Install vendor packages as appgroup, drop privileges IMMEDIATELY.
USER appgroup:appgroup

# Install pre-built wheels offline. --require-hashes enforces the
# pinning done at build time. If ANY hash mismatches, the build fails
# rather than silently downgrading.
WORKDIR /opt/inference/vendor
RUN pip install --no-cache-dir --no-index --find-links=/opt/_build/wheels \
        --require-hashes \
        -r <(grep -v '^#' /opt/_build/wheels/.installed_hashes.txt | sort -u) && \
    # Remove the cached wheel index after install — it contains raw
    # .whl binaries we no longer need (already extracted in site-packages).
    find /opt/_build/wheels -name "*.whl" -delete

# [R5] Application source — copied LAST so dependency-only changes
#      don't bust the docker build cache on this layer.
COPY --chown=appgroup:appgroup . /opt/inference/src

# Install the application itself (editable for dev, pure install for prod).
# Uses --target inside vendor to keep everything self-contained.
USER root  # temporary escalation for pip install into system path
RUN pip install --no-cache-dir --no-deps /opt/inference/src[<extras>] && \
    usermod -s /bin/bash appgroup  # restore shell for ENTRYPOINT
USER appgroup:appgroup

# [R6] Model artifacts directory — a named volume mount point.
#      Never bake model weights into the image (they change per deploy
#      and can be hundreds of MB). They're injected at runtime via
#      volumes or bind-mounts.
RUN mkdir -p /opt/inference/models && chown appgroup:appgroup /opt/inference/models
VOLUME /opt/inference/models

# Healthcheck endpoint port (adjust to match your service)
EXPOSE 8080

# [R7] HEALTHCHECK — probes HTTP /healthz every 30s, gives the process
#      10s grace period before first probe (models may take time to load),
#      then retries 3 times before marking unhealthy.
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD curl -sf http://localhost:8080/healthz || exit 1

# [R8] Entrypoint uses tini (PID 1 zombie reaping) then execs the app.
ENTRYPOINT ["tini", "--"]
CMD ["python", "-m", "uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8080"]
```

| Layer | What It Does | Why It's Ordered Here | Cache-Benefit |
|-------|-------------|----------------------|---------------|
| **[B1]** Build tools (`gcc`, `g++`, `make`, `cmake`) | Provides compilers for any C-extension wheels that need source builds | Rarely changes; only when new deps require compilation | Changes only when you add a dependency with a C extension — months between updates |

| **[R6]** Volumes + healthcheck port | Declares runtime mount points and network ports | Pure metadata declaration — zero impact on caching | N/A |

| **[R8]** Entrypoint (tini) | PID 1 zombie reaping wrapper | Final execution config; tiny layer that rarely changes | Stable indefinitely |

```dockerfile
ARG TORCHVISION_SHA256=a1b2c3d4... # <-- pin this hash

# Stage 1: builder-wheels  – download & validate pre-built CPU wheels
# Why separate? If you change application code but not PyTorch version,
# this entire stage (which takes 2–4 min to download) is cached.
# ---------------------------------------------------------------------------
FROM python:${PYTHON_VERSION} AS builder-wheels

# Install minimal tooling for SHA verification; no compilers needed
# since we use pre-built wheels (not source compilation).
RUN apt-get update && \
    apt-get install -y --no-install-recommends ca-certificates wget && \
    rm -rf /var/lib/apt/lists/*

# dependency-only changes skip fetching entirely.

        "${TORCH_URL}" && \
    wget --quiet --output-document=torchvision-${TORVISION_URL##*/} \
        "${TORVISION_URL}"

    echo "${TORCHVISION_SHA256}  torchvision-*.whl" | sha256sum --check --strict

COPY pyproject.toml README.md ./

    pip install --no-cache-dir --target=/wheels -r /dev/stdin <<'EOF'
numpy>=1.26,<2.0
pydantic>=2.0
uvicorn[standard]>=0.29
starlette>=0.36
EOF

RUN cp torch-*.whl torchvision-*.whl /wheels/ 2>/dev/null || true

# Stage 2: runner  – slim Linux environment, install validated wheels

# 'gcc' was needed by the OpenMP virtual package; now it's safe to remove.
RUN apk del --purge gcc gxx && \

# Stage 3: final  – application code + entrypoint only
# ---------------------------------------------------------------------------

# Use absolute path within the scratch context.
# These labels carry through because COPY respects them from prior stages.
LABEL org.opencontainers.image.source="https://github.com/example/inference-service"
LABEL org.opencontainers.image.description="Python 3.12 + PyTorch CPU inference service"

        /etc/passwd \
        /etc/group \
        /etc/resolv.conf \
        /usr/local/bin/ \
        /usr/local/lib/ \
        /usr/bin/ \
        /usr/lib/ \
        /lib/ \
        /bin/ \
        /opt/ \
        /srv/ \
        /run/ \
        /etc/ssl/ \
        /etc/ca-certificates/ \
        /tmp/ \
        /etc/mime.types \
        /etc/localtime \
        /

# copies together, any code-only change invalidates only this stage (and
# the cache before it stays fully intact when only deps change).
COPY --chown=1000:1000 \
        src/ /srv/app/src/
COPY --chown=1000:1000 \
        app/ /srv/app/app/
COPY --chown=1000:1000 \
        config/ /srv/app/config/
COPY --chown=1000:1000 \
        --from=builder-wheels /srv/wheels/py.typed /srv/wheels/*.pyi /srv/app/ 2>/dev/null || true

# consistent ownership; any file owned by root after COPY would be unreadable.
RUN chown -R 1000:1000 /srv/app && \

    chmod -R 755 /srv/app/config/ && \
    mkdir -p /srv/app/data && chown 1000:1000 /srv/app/data
```

## Architectural Rationale

### Layer Ordering & Cache Strategy

| Layer | Triggered By | Why This Position |
|-------|-------------|-------------------|
| `python:3.12-slim-bookworm AS builder` | Never (full rebuild) | Base image rarely changes; build deps stable |
| `apt-get install build-essential` | Base image change only | Installed once, cached indefinitely |
| `requirements.txt` + `pip install` | Dependencies change | **Cache-breaker boundary** — this is the pivot point |
| `COPY src/` | Any source change | Placed last so code edits don't waste pip time |

This layout ensures a dependency-only change (e.g., bumping numpy from 1.26.3→1.26.4) only invalidates layers from `pip install` downward — the 45s apt + GCC compile steps are skipped entirely. A code-only change skips pip *and* apt, giving fast iteration.

### Multi-Stage Justification

**Why two stages?** The build stage installs compiler toolchains (gcc, g++, cmake) and downloads every wheel. The runtime stage receives only compiled artifacts via `COPY --from=builder`. Benefits:

1. **No compilers in runtime** — removes ~200MB of unused build tooling
2. **Attack surface reduction** — no gcc, no headers, no debug symbols
3. **Reproducible artifacts** — wheels are downloaded once, hashed by pip, immutable thereafter
4. **Cleaner audit** — runtime image shows exactly what was deployed

Without multi-stage, you'd carry the full build toolchain (typically 500MB+) inside the runtime image unnecessarily.

### CPU-Only PyTorch

The key directive is:
```
pip install 'torch==2.5.1+cpu' --extra-index-url https://download.pytorch.org/whl/cpu
```

This installs the CPU-only wheel (~750MB) instead of the full GPU-capable wheel (~1.1GB). The `+cpu` suffix tells PyPI which variant to pull. Runtime enforcement is handled by the application layer (checking `torch.cuda.is_available()` and raising if True), preventing accidental GPU allocation.

This saves ~350MB versus the default torch install.

### Non-Root User & File Permissions

```dockerfile
RUN groupadd -g 1001 app && \
    useradd -r -u 1001 -g app -s /usr/sbin/nologin app && \
    chown -R app:app /app
USER app
```

- UID/GID 1000-1001 follows Linux convention for service accounts
- `-r` creates a system user (no home dir, no login shell)
- Shell set to `/usr/sbin/nologin` prevents interactive access
- Ownership transfer ensures the app process owns its workspace
- Without this, a container escape vulnerability gives the attacker root on the host

### HEALTHCHECK Design

```
--interval=30s   Check every 30 seconds
--timeout=3s     Fail if no response in 3s
--start-period=15s Grace period for model loading
--retries=3      Mark unhealthy after 3 consecutive failures
```

The 15-second start period is critical for inference services — loading a 2GB model into memory takes time. Without it, Docker marks the container unhealthy during cold starts even though the service works fine. The 30-second interval is a balance between responsiveness and overhead (HTTP health checks add per-request latency).
