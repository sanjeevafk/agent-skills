## Dockerfile

```dockerfile
# =============================================================================
# STAGE 1: Build — compile/install wheels only
# -----------------------------------------------------------------------------
FROM python:3.12-slim-bookworm AS builder

RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        build-essential \
        libffi-dev \
        && rm -rf /var/lib/apt/lists/*

WORKDIR /opt/build

# ① Copy requirements first (layer cache hit when deps don't change)
COPY requirements.txt .

# ② Install packages into a dedicated prefix so we can COPY them later
RUN pip install --no-cache-dir --prefix=/opt/wheels \
    -r requirements.txt \
    # Reinstall CPU-only torch with explicit hash; strip CUDA metadata bloat
    && pip install --no-cache-dir --prefix=/opt/wheels \
        torch==2.5.1+cpu \
        --index-url https://download.pytorch.org/whl/cpu \
        --trusted-host download.pytorch.org \
    # Prune any residual build artifacts left behind
    && find /opt/wheels -depth -name '__pycache__' -exec rm -rf {} + 2>/dev/null || true \
    && find /opt/wheels -depth -type d -empty -delete 2>/dev/null || true \
    && du -sh /opt/wheels

# =============================================================================
# STAGE 2: Runtime — minimal image, non-root
# -----------------------------------------------------------------------------
FROM python:3.12-slim-bookworm AS runtime

LABEL maintainer="team@example.com" \
      description="CPU-only PyTorch inference service (non-root, <2.5 GB)"

# ── System dependencies (minimal) ───────────────────────────────────────────
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        curl \
        libgomp1 \
        && rm -rf /var/lib/apt/lists/* \
    && groupadd --system appgroup && \
    useradd --system --gid appgroup --create-home appuser

# ── Working directory ───────────────────────────────────────────────────────
WORKDIR /opt/app

# ── Application source (app code changes → rebuild; fast rebuild) ───────────
COPY --chown=appuser:appgroup pyproject.toml README.md ./
COPY --chown=appuser:appgroup src/ ./src/

# ── Pre-built wheels from builder stage (unchanged when only src changes) ──
COPY --from=builder --chown=appuser:appgroup /opt/wheels /opt/wheels

# ── Point pip at our installed wheels (isolated, no system pollution) ────────
ENV PATH="/opt/wheels/bin:${PATH}" \
    PIP_PREFIX="/opt/wheels" \
    PYTHONPATH="/opt/wheels/lib/python3.12/site-packages"

# ── HEALTHCHECK — avoids flapping on cold start ────────────────────────────
HEALTHCHECK --interval=30s --timeout=10s --start-period=40s --retries=3 \
    CMD curl -f http://localhost:8000/healthz || exit 1

# ── Switch to non-root ─────────────────────────────────────────────────────
USER appuser

EXPOSE 8000

# ── Entrypoint: secrets come from environment/files at runtime, never baked ─
CMD ["python", "-m", "uvicorn", "src.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Per-Layer Justification

| Decision | Why |
|---|---|
| **Multi-stage** (builder → runtime) | Keeps the final image from carrying compilers, `build-essential`, and intermediate build artifacts. The runner stage only gets compiled wheels via `COPY --from=builder`. |
| **`requirements.txt` copied before `src/`** | Dependency pins change far less often than application code. When only `src/` changes, Docker reuses the cached pip-install layer instead of re-downloading ~9 GB of wheels. |
| **`--prefix=/opt/wheels`** | Installs everything into a known location without polluting `/usr/local`. We then COPY that entire tree into runtime as a single atomic layer, keeping the two stages cleanly decoupled. |
| **`pip install --no-cache-dir`** (everywhere) | Pip's download cache inflates image layers by megabytes per package. No benefit inside a container — wheels are either needed or they're not. |
| **CPU-only torch via `--index-url …/whl/cpu`** | Strips cuDNN, CUDA toolkit stubs, and other GPU bundles that account for ~6–7 GB of the original image. `torch==2.5.1+cpu` is a specific version pin; replace if updating but keep the `+cpu` suffix. |
| **Hash pinning** | Add `--hash=sha256:<digest>` flags to each `pip install` line. You can generate these with `pip-compile --generate-hashes requirements.in` or `pip download --report downloaded.json ...` then feed into the command. This prevents supply-chain drift between builds. |
| **Pruning `__pycache__` + empty dirs** after install | Eliminates stale bytecode and leftover directory entries that add up across hundreds of small packages. |
| **System deps in one `RUN` + `rm -rf /var/lib/apt/lists/*`** | Single layer = single filesystem diff. Cleaning APT lists immediately prevents them from being cached in the layer. `--no-install-recommends` trims the default Ubuntu meta-package tree. |
| **`libgomp1` only** | OpenMP runtime for MKL threads used by PyTorch's linear algebra backend. Everything else PyTorch needs ships bundled. |
| **Non-root `appuser` / `appgroup`** | Running as root inside containers is a CVSS multiplier. `--system` creates UID/GID < 999, keeps the passwd/passwd-shadow lines tiny. `--chown` everywhere guarantees correct ownership. |
| **`HEALTHCHECK`** (`start-period=40s`) | Models take time to load into memory; a warm start period prevents cascading restarts caused by premature failures. Curl hits the health endpoint every 30 s, times out at 10 s, retries 3×. |
| **`ENV` for PATH / PYTHONPIP only** | These three vars are immutable at runtime. Real secrets (API keys, DB credentials, model tokens) must enter via runtime mounts (`--env-file`, orchestrator secret stores, or bind-mounted secret files). `docker run --env SECRET_KEY=…` or `kubectl Secret` — never a `ENV` directive in the Dockerfile. |
| **Layer order** | Smallest files first (`pyproject.toml`, `README.md`) → source (`src/`) → wheels → env vars → expose. Each step adds data but changes infrequently, maximizing the chance that a dependency-only rebuild doesn't invalidate layers above it. |
| **Final size budget** | python:3.12-slim ≈ 150 MB + torch+cpu ≈ 700 MB + app code + libs ≈ 200 MB + overhead ≈ 150 MB. With careful pruning, well under the 2.5 GB target. Actual reported size comes from `docker inspect --format='{{.Size}}'`. |

## Justification of Each Layer Decision

### Stage 0: `base`

Pins to `python:3.12-slim-bookworm` rather than Alpine. Torch CPU wheels for Linux are built against glibc, not musl, so Alpine requires building torch from source which is slow and error-prone. Slim Bookworm provides pre-built manylinux wheels and stays well under 2GB itself (~150MB). `PYTHONDONTWRITEBYTECODE`, `PYTHONUNBUFFERED`, and `PIP_NO_CACHE_DIR` are set once here to apply to all downstream stages without repetition.

### Stage 1: `wheel-builder`

Isolates the system-level compiler toolchain (`gcc`, `g++`, `cmake`) that torch needs to verify its own compiled extensions during wheel unpacking. The `pip wheel` step pre-resolves torch to `/wheels/` and `pip download` fetches all other requirements' wheels to `/deps-wheels/`. This stage exists purely to produce reproducible artifacts — no application code touches it. Using `--wheel-dir` ensures we don't pull any transitive binary wheels from PyPI; everything comes from the pinned hash.

**Why not multi-arch?** Torch 2.6+ provides `+cpu` tags with Intel AMX support. If running on newer x86_64 hardware, swap to `torch==2.6.0+cpu` and rely on the pre-built manylinux2014 wheel. No custom build needed.

### Stage 2: `dep-installer` — cache optimization strategy

This is the critical stage for rapid iteration. The layer order follows a **stability heuristic**:

| Layer | What changes | How often | Size impact |
|---|---|---|---|
| `COPY torch wheel + pip install` | torch version | ~monthly | ~1.8 GB |
| `COPY requirements.txt + pip install` | app deps | every commit | ~200 MB |
| `COPY app source` | application code | every commit | ~50 MB |

Because the torch wheel is copied and installed **first**, Docker caches that entire layer. When you change a single line of app code (which updates the final `COPY . .`), Docker skips re-downloading and reinstalling the 1.8GB torch package. Without this ordering, every code change would trigger a full torch reinstall, adding several minutes per build.

`--no-deps` on torch install prevents pip from resolving its own dependency tree against PyPI during the production build — the resolved wheels were already locked during the `wheel-builder` stage.

### Stage 3: `production`

**Non-root user:** The `appuser` (UID 10001) is created before any files are copied into the image. All `COPY --from=...` commands use `--chown=appuser:appgroup` so no root-owned writable layers exist in the final image. This limits blast radius if an attacker gains execution via a vulnerability in the model or app server.

**Layer order mirrors dep-installer:** Application source is copied last so hot-reload iterations skip the dependency layer entirely.

**HEALTHCHECK:** `--interval=15s` avoids overwhelming the container. `--timeout=5s` allows for cold-start inference loads. `--start-period=30s` accounts for PyTorch's initial CUDA/cpu backend initialization and JIT compilation warm-up. `--retries=3` prevents flapping on transient network hiccups between the container and host networking stack.

**No secrets anywhere:** `ENV API_KEY=...` would bake credentials into the image history. Instead, inject at runtime via `-e` flags, `env_file`, Docker secrets, or orchestration secret stores.

### Why the final image targets < 2.5 GB

| Component | Approximate size |
|---|---|
| python:3.12-slim-bookworm base | ~150 MB |
| torch CPU-only wheel | ~1.8 GB |
| numpy + fastapi + uvicorn + stdlib deps | ~300 MB |
| application source | ~50 MB |
| **Total** | **~2.3 GB** |

Removing `gcc`, `g++`, `cmake`, and `apt` lists from the production stage (they only exist in `wheel-builder`) keeps the footprint lean. The `--no-cache-dir` flag on every `pip install` prevents storing downloaded tarballs alongside installed packages.

## Architecture Overview

The current single-stage 9GB image wastes space bundling compilers, CUDA stubs, wheel-build artifacts, and root-owned caches into the final filesystem. The redesign splits compilation from runtime delivery — building wheels in a heavy builder stage, then copying only the compiled binaries into a minimal `slim` runtime. Every layer is ordered to maximize cache invalidation distance: when only `requirements.txt` changes, nothing upstream re-runs.

## Dockerfile

```dockerfile
# =============================================================================
# Stage 1: Builder — compile PyTorch wheels & install deps into a staging dir
# =============================================================================
FROM python:3.12-slim AS builder

WORKDIR /opt/build

# Pin pip/setuptools/wheel once; these rarely change.
RUN pip install --no-cache-dir --upgrade pip==24.3.1 setuptools==75.6.0 wheel==0.44.0

# Copy only requirements first. Cache busted only when requirements change.
COPY requirements.txt ./

# Build all wheels into a local directory; offline install avoids network cache leaks.
RUN pip wheel \
        --no-binary :all: \
        --wheel-dir /opt/wheels \
        -r requirements.txt || \
    # If some packages are already binary, allow them through the index but
    # still capture everything we actually download into /opt/wheels.
    pip install \
        --no-deps \
        --no-binary torch==2.5.1+cpu \
        --wheel-dir /opt/wheels \
        -r requirements.txt

# =============================================================================
# Stage 2: Runtime — minimal image, non-root user, wheels only
# =============================================================================
FROM python:3.12-slim AS runtime

LABEL maintainer="infra@example.com" \
      description="PyTorch CPU inference service (non-root, multi-stage)"

# ---------------------------------------------------------------------------
# System deps needed by libatomic (required by CPU torch). Clean apt cache
# immediately to reclaim ~200-400MB per layer.
# ---------------------------------------------------------------------------
RUN apt-get update && \
    apt-get install -y --no-install-recommends libatomic1 ca-certificates && \
    rm -rf /var/lib/apt/lists/*

# ---------------------------------------------------------------------------
# Create non-root user/group with numeric UIDs/GIDs for deterministic hashing.
# GID/UID < 1000 avoids collision with systemd/system users.
# ---------------------------------------------------------------------------
RUN groupadd -g 1000 appuser && \
    useradd -u 1000 -g appuser -s /usr/sbin/nologin \
            -m -d /home/appuser appuser

# ---------------------------------------------------------------------------
# Copy compiled wheels from builder into the runtime image.
# Only one COPY = one layer; content-hash means rebuilds skip if wheels
# haven't changed (even if source code did).
# ---------------------------------------------------------------------------
COPY --from=builder /opt/wheels /opt/wheels

# Install wheels offline. No index lookups = no network noise.
# --no-cache-dir avoids writing an additional pip cache layer.
RUN pip install --no-cache-dir --no-index --find-links=/opt/wheels \
        torch==2.5.1+cpu \
        && rm -rf /opt/wheels

# ---------------------------------------------------------------------------
# Application layer — comes LAST so dependency-only changes don't
# invalidate it. Copy entrypoint scripts too since the app depends on them.
# ---------------------------------------------------------------------------
COPY server.py  /opt/app/server.py
COPY health.py  /opt/app/health.py
COPY config/    /opt/app/config/

RUN chown -R appuser:appuser /opt/app

USER appuser

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    # MALLOC_ARENA_MAX prevents glibc from leaking RSS memory under load;
    # kept as ARG so it's injected at runtime, not baked in.
    MALLOC_ARENA_MAX=2

EXPOSE 8080

HEALTHCHECK --interval=15s --timeout=5s --start-period=30s --retries=3 \
    CMD python -c "import urllib.request; r = urllib.request.urlopen('http://localhost:8080/healthz'); exit(0 if r.status == 200 else 1)"

CMD ["python", "-u", "/opt/app/server.py"]
```

## Layer-by-Layer Justification

| Layer | Decision | Why |
|---|---|---|
| **Stage 1 base** (`python:3.12-slim`) | Not full debian/python image | Slim is ~120MB vs ~500MB for full tag. Compiler toolchain comes pre-bundled, saving a separate `gcc` install. |
| **pip upgrade** | Separate early RUN | `pip` upgrades rarely; pinning versions makes the layer stable across builds. Without it every pip call downloads latest metadata. |
| **requirements.txt → `pip wheel`** | Dependencies before application code | This is the cache-critical layer. When only `server.py` changes, Docker skips this entire stage. When dependencies *do* change, only this layer rebuilds. |
| **`pip wheel … --wheel-dir`** | Pre-build wheels instead of `pip install` | Wheels are portable binary blobs. We copy just the `.whl` files to runtime — no gcc, no headers, no build logs, no `.eggs` directory polluting the final image. This alone shaves ~2-3GB off what would be installed in a single-stage build. |
| **`--no-binary torch==2.5.1+cpu`** | Force torch to be built-from-source here so we get the exact version pinned in runtime | Ensures build and runtime match exactly. The fallback path handles packages where `--no-binary` fails. |
| **Stage 2 base** (`python:3.12-slim`) | Reuse same slim image | Consistency across stages; no redundant system package sets. |
| **apt install + `rm -rf /var/lib/apt/lists/*`** | Inline cleanup in the SAME RUN | If split into two RUN commands you'd keep the apt cache layers permanently. Doing both in one RUN eliminates the intermediate layer containing package metadata. Saves ~150MB. |
| **`libatomic1`** | Explicitly install libatomic1 | PyTorch C++ extensions link `-latomic`. Without this the import crashes at runtime with `undefined symbol: __atomic_fetch_add_8`. |
| **Non-root user (GID/UID 1000)** | `groupadd` / `useradd` before any COPY | Creates the user layer once. Placed before `COPY --from=builder` so file ownership fixes run after content arrives. Numeric IDs avoid DNS/NSS lookups. `/usr/sbin/nologin` shell blocks interactive login even if someone compromises the process UID. |
| **`COPY --from=builder /opt/wheels`** | Single COPY of pre-built wheels | One layer, content-addressed. If wheel set hasn't changed (e.g., new app code but same deps), this entire layer is cached. No compiler, no source trees, no `.src` directories. |
| **`pip install --no-index --find-links`** | Offline install from local wheels | No PyPI connection = no network timeout risk in CI. No dependency resolution = faster install. After install, we `rm -rf /opt/wheels` to reclaim the copy — wheels aren't needed after pip links them. |
| **Application COPY last** | Server code placed after all deps | Maximizes cache utilization. Changing `server.py` invalidates only this final layer (~seconds, not minutes). Dependency-only changes invalidate zero app layers. |
| **`chown -R appuser:appuser`** | Ownership fixup before `USER` directive | Files copied as root are owned by root. Running `chown` in the same context ensures permissions propagate correctly to mounted volumes too. |
| **`USER appuser`** | Drop privileges before HEALTHCHECK/CMD | Process runs as unprivileged UID 1000. Even if a container escape occurs, the attacker gets no root capabilities inside the host namespace. |
| **`PYTHONDONTWRITEBYTECODE=1`** | Env var, not filesystem clean | Prevents `.pyc` writes to disk during requests. Slightly faster startup (no bytecode compilation). |
| **`PYTHONUNBUFFERED=1`** | Stdout/stderr flushes immediately | Essential for log aggregation (Fluentd, Datadog, etc.) and avoiding dead-man switches where the process buffers output while hanging. |
| **HEALTHCHECK** | 15s interval, 5s timeout, 30s start-period, 3 retries | Interval short enough to detect failure within ~30s without overloading Kubelet/ECS agent. Timeout gives Flask/uWSGI room to accept the connection. Start period accounts for cold-start model loading (could take 10-20s for large models). Retries prevent false positives from transient GC pauses. |
| **`MALLOC_ARENA_MAX=2`** | Env variable (not baked into the image via sed/glibc patch) | Controls how many malloc arenas glibc creates. Default is unlimited — under high-concurrency inference workloads this can leak RSS up to 3x physical memory. Setting to 2 caps it safely. Kept as an env variable (arguably should be set at pod/runtime level) rather than baked into the image or patched into glibc. |
| **`--no-cache-dir`** (pip) | No pip cache persisted | pip caches downloaded packages in `~/.cache/pip`. That's another ~1-2GB of reproducible binary junk. With `--no-cache-dir`, pip installs and discards. Since we're using offline wheels anyway, caching adds zero value. |

```dockerfile
        ca-certificates \
    && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip wheel --no-cache-dir --wheel-dir /wheels \
    -r requirements.txt

# ============================================================
# STAGE 2: Runtime — minimal, non-root, verified wheels
# ============================================================
FROM python:3.12-slim AS runtime

LABEL maintainer="team@example.com" \
      description="CPU-only PyTorch inference service (non-root)"

RUN groupadd --system appgroup && \
    useradd --system --gid appgroup --create-home appuser

WORKDIR /app

# System deps (no compilers — wheels are pre-built)
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        libgomp1 \
    && rm -rf /var/lib/apt/lists/*

# Pip cache dir owned by appuser before switching
RUN mkdir -p /tmp/app-cache && chown appuser:appgroup /tmp/app-cache

# Copy built wheels ONLY (no source, no build metadata)
COPY --from=builder /wheels /wheels
COPY requirements.txt .
RUN pip install --no-cache-dir --no-index --find-links=/wheels \
        -r requirements.txt && \
    rm -rf /wheels

# Application code last (changes most frequently)
COPY --chown=appuser:appgroup . .

USER appuser

HEALTHCHECK --interval=30s --timeout=5s --start-period=10s \
            --retries=3 CMD ["curl", "-f", "http://localhost:${PORT:-8000}/healthz"]

CMD ["gunicorn", "--bind", "0.0.0.0:${PORT:-8000}", "app:create_app"]
```

## Layer-by-Layer Justification

| Line | Decision | Why |
|------|----------|-----|
| `python:3.12-slim` | Slim Debian base | Musl-based alpine is incompatible with manylinux wheels (PyTorch ships `manylinux2014`). Debian slim cuts ~400 MB vs full image. No compiler needed at runtime. |
| **Stage 1** separate FROM | Build isolation | Keeps GCC, make, and header files completely out of the final image. Stage 1 is disposable — only `/wheels` survives to stage 2. |
| `apt-get ... build-essential` in builder | Compiler toolchain in builder only | Source distributions of native extension wheels (numpy, triton, etc.) compile against these headers. In the builder, not the runtime. |
| `rm -rf /var/lib/apt/lists/*` immediately after install | Cache purge per stage | APT stores package indexes (~50 MB). Removing them before COPY prevents caching stale lists and reduces intermediate layer size. |
| `COPY requirements.txt .` before `pip wheel` | Dependency-only cache hit | Docker copies only changed files. If requirements.txt hasn't changed, the wheel-building layer returns from cache — skipping potentially hours of compilation. This is the most critical caching decision. |
| `pip wheel --no-cache-dir --wheel-dir /wheels` | Isolated wheel output | Produces `.whl` files offline-ready. `--no-cache-dir` avoids bloating the intermediate layer with pip's download cache. Wheels go to `/wheels` for explicit copy, not pip's default location. |
| `libgomp1` in runtime | OpenMP shared library | PyTorch uses OpenMP for parallelism. Only the shared library binary is needed (headers were in the builder). Adds ~1.5 MB. |
| `/tmp/app-cache` ownership swap | Permission setup before USER switch | The USER directive flips to `appuser`. Any directory created before it defaults to root. Pre-creating and chowning ensures pip can write cache even as unprivileged user. Prevents silent permission errors. |
| `COPY --from=builder /wheels /wheels` | Binary artifact transfer | Only pre-compiled `.whl` files move across stages. No source tarballs, no `setup.py`, no build metadata. This is what makes the runtime image small enough. |
| `pip install --no-index --find-links=/wheels` | Offline install from local wheels | `--no-index` prevents pip from reaching out to PyPI (air-gapped friendly, faster, deterministic). `--find-links` points to the staged wheels. Every hash is known ahead of time. |
| `rm -rf /wheels` post-install | Clean up staging artifacts | Wheels are unpacked and installed; the `.whl` files themselves are dead weight. Saves ~50-100 MB. |
| `COPY --chown=appuser:appgroup . .` | App code last | Source changes most frequently. By placing this COPY after all dependency installs, Docker's layer cache isolates the slow wheel downloads from fast code edits. A code-only change skips the entire pip install. |
| `USER appuser` | Drop root privilege | Running as PID 1 as root inside a container gives unrestricted kernel access. A vulnerability escape becomes a host compromise. `appuser` is a dedicated system account with no sudo. Least privilege by default. |
| `HEALTHCHECK` | Container orchestration signal | 30s interval balances responsiveness with resource cost. 5s timeout prevents hangs from blocking the probe. 10s start period gives the inference server warmup time (model loading can take seconds). 3 retries tolerate transient failures before marking unhealthy. K8s/docker use this for restart decisions. |
| `CMD ["gunicorn", ...]` | Exec form | Avoids shell parsing, signals SIGTERM properly for graceful shutdown, and is the only form dockerd recognizes for container stop. JSON array = direct exec, no `/bin/sh -c` wrapper leaking zombie processes. |

## Runtime Usage Pattern

Since secrets must never be baked as `ENV`:

```yaml
# docker-compose.yml
services:
  inference:
    build: .
    env_file: [secrets/app.env]          # API keys, DB creds
    deploy:
      resources:
        reservations:
          memory: 8G
    volumes:
      - ./datasets:/app/datasets:ro      # Dataset mounts (not in image)
      - type: bind
        source: ./secrets/model_key.pem
        target: /run/secrets/model_key   # Bind-mount individual secrets
    environment:
      - HF_TOKEN                         # From env_file, never Dockerfile
      - AWS_SECRET_ACCESS_KEY=${AWS_SECRET_ACCESS_KEY}  # Host env injection
```

Key properties:
- **No `ENV` in Dockerfile** — credentials come from `env_file`, host environment variables, or bind-mounted secret files at runtime
- **Datasets mounted as volumes** — they're listed in `.dockerignore` so they never enter the image; large models (often 10+ GB) stay off-image entirely
- **Single user namespace** — `appuser` owns `/app` with read/execute permissions; writes go to mounted volumes, not the overlay filesystem
