## The Dockerfile

```dockerfile
# ─── Stage 1: Build wheels ─────────────────────────────────────────────
FROM python:3.12-slim-bookworm AS builder

RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        build-essential \
        libaio-dev \
        ca-certificates \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /build

COPY requirements.txt .

# CPU-only torch with pinned version and index URL; download wheels only
RUN pip install --no-cache-dir --prefix=/install \
    --index-url https://download.pytorch.org/whl/cpu \
    $(grep -i 'torch' requirements.txt | grep -ivv 'numpy\|packaging') \
    && pip install --no-cache-dir --prefix=/install -r requirements.txt

# ─── Stage 2: Runtime ──────────────────────────────────────────────────
FROM python:3.12-slim-bookworm AS runtime

# Minimal runtime deps; no build tools, no package manager residue
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        libgomp1 \
        curl \
    && rm -rf /var/lib/apt/lists/* \
    && groupadd -r appuser && useradd -r -g appuser -d /app -s /usr/sbin/nologin appuser

WORKDIR /app

# Copy installed packages from builder (preserves ownership for chown later)
COPY --from=builder /install /usr/local

# Application code — changed last so dependency layers cache across dep-only rebuilds
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

# Switch to non-root early; reassign ownership of everything we wrote as root
RUN chown -R appuser:appuser /app

USER appuser

EXPOSE 8000

HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD curl -f http://localhost:8000/healthz || exit 1

CMD ["python", "-m", "uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Layer Decisions, Line by Line

### Stage 1 — Builder (`python:3.12-slim-bookworm`)

| Decision | Rationale |
|---|---|
| **Debian bookworm base** (not Alpine) | PyTorch CPU wheels ship only for glibc; musl builds cause ABI crashes. Debian slim keeps the builder at ~150 MB. |
| **`apt-get` then `pip`** | System libs (`libaio`, `libgomp`) are small, rarely change. Grouping them first ensures they land in one cacheable layer. |
| **Separate `requirements.txt` copy before pip install** | The COPY-invalidate-on-change pattern means if only `requirements.txt` changes, all prior layers (system deps) still hit the Docker cache. |
| **`--prefix=/install` for pip** | Installs wheels into `/install` instead of polluting the global site-packages. This isolates build artifacts cleanly for the next stage's COPY, and keeps the builder container tidy. |
| **`pip install --no-cache-dir`** | Pip caches downloaded wheels inside the image. Skipping avoids storing megabytes of downloaded `.whl` files that aren't needed after installation. |
| **PyTorch pinned via `requirements.txt` entry** like `torch==2.5.1+cpu` | Pinning the exact version with the `+cpu` suffix guarantees deterministic hash resolution from the CPU index. No implicit GPU pulls. |
| **Download index URL specified** | `--index-url https://download.pytorch.org/whl/cpu` ensures only CPU wheels are considered, preventing any accidental GPU package resolution. |

### Stage 2 — Runtime (`python:3.12-slim-bookworm`)

| Decision | Rationale |
|---|---|
| **Second slim base** | Starts fresh from the same distro but strips out compilers, headers, and anything build-related. Cuts bloat from the 9 GB single-stage down to the target. |
| **Only `libgomp1` + `curl` installed** | `libgomp1` is the OpenMP runtime Torch needs for CPU parallelism; `curl` provides the `curl` binary for the HEALTHCHECK. Nothing else runs as root. |
| **`groupadd`/`useradd -r`** | Creates a system-level (low UID/GID) unprivileged user `-r` flags it as non-login. The user has no shell (`nologin`), cannot be used for SSH, and will not own files outside `/app`. |
| **`COPY --from=builder /install /usr/local`** | Brings in only the *installed* Python packages from the builder — no source code, no build cache, no temp files. This is the critical isolation step. |
| **`COPY requirements.txt` then `pip install`** | Re-resolves dependencies in the runtime context (ensures clean site-packages), but again placed before application code so that adding a model checkpoint or changing inference code does not invalidate the dependency layer. |
| **`COPY . .` placed last** | Source code changes (model weights directory metadata, config tweaks, new modules) invalidate only this layer, preserving all upstream layers including pip-installed dependencies. This is the single biggest cache optimization for iterative development. |
| **`chown -R appuser:appuser /app`** | Files copied by Docker default to `root:root`. A final chown gives the non-root user ownership of the application tree. Doing this before `USER` ensures the switch happens to an already-correct owner. |
| **`USER appuser`** | All subsequent commands (HEALTHCHECK CMD, CMD exec) run unprivileged. Process capabilities are dropped by Docker's default seccomp profile — no need for extra security hardening. |
| **`HEALTHCHECK` with 30s interval, 5s timeout, 10s start period, 3 retries** | - `--interval=30s`: polls every half minute, sufficient for inference latency without excessive overhead. <br> - `--timeout=5s`: fails the check if `/healthz` takes more than 5 seconds (catches hung workers). <br> - `--start-period=10s`: allows Torch to load models on first boot without failing the initial checks. <br> - `--retries=3`: requires three consecutive failures before marking unhealthy, avoiding flapping on transient GC pauses. |
| **No `ENV` for credentials** | Sensitive values are passed at runtime via `docker compose` environment variables or Docker Swarm secrets (`secrets:` directive). These never appear in `docker inspect` output or image history. |

### .dockerignore

```
.venv
__pycache__
*.egg-info
datasets/
data/
tests/
*.log
.env
.git
.hypothesis
.mypy_cache
.pytest_cache
.docker-compose.yml
Dockerfile
README.md
```

| Excluded path | Reason |
|---|---|
| `.venv` | Virtualenv can be 1–3 GB; it shadows production installs and wastes bandwidth on every build. |
| `datasets/` | Training data is often tens of GB. Never belongs in an image. Mounted at runtime or loaded from an external store. |
| `tests/`, caches, docs | Not needed for inference. Keeps the COPY layer smaller and faster. |

### Size Breakdown (target < 2.5 GB)

```
python:3.12-slim-bookworm          ~150 MB
├─ libgomp1 + curl                  ~10 MB
├─ torch cpu (pinned)              ~800 MB
├─ transformers + accelerate       ~400 MB
├─ numpy + scipy + packaging        ~100 MB
├─ uvicorn + fastapi + deps         ~50 MB
├─ application code                  ~20 MB
└─ filesystem overhead               ~50 MB
                                         ───────
Total                                ~1580 MB
```

Well under the 2.5 GB cap even after accounting for Docker overlayfs overhead (~10%). The original 9 GB single-stage wasted space on build tools, pip caches, test suites, dataset stubs, and the full `site-packages` cached during install.

### Secrets at Runtime

In `docker-compose.yml`:

```yaml
services:
  inference:
    build:
      context: .
      dockerfile: Dockerfile
    env_file: .env                # host-secret, never committed
    secrets:
      - api_key                   # Swarm secret, injected as file mount
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/healthz"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s

secrets:
  api_key:
    file: ./secrets/api_key.txt
```

The `.env` file maps `API_KEY=mykey` → environment variable visible to the process but absent from the image diff (`docker diff`). Swarm secrets appear as read-only files at `/run/secrets/<name>` — also invisible in the image history. Neither technique ever writes a secret into a layer or an `ENV` instruction.
