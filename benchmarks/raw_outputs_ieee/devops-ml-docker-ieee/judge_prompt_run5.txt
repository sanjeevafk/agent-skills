```dockerfile
    adduser -u 1001 -S appuser -G appgroup -h /home/appuser -s /bin/sh

# Using /opt/wheels avoids conflicts with any system-provided packages.
# ---------------------------------------------------------------------------

# pip normally stores a full copy of every downloaded artifact in ~/.cache/pip.
# That alone saves ~300-500 MB for torch.
# --no-deps on torch avoids pulling duplicate setuptools/wheel into the runtime.
RUN pip install --no-cache-dir --no-index --find-links=/opt/wheels \
        torch && \
    pip install --no-cache-dir --no-index --find-links=/opt/wheels \
        -r requirements.txt && \
    rm -rf /opt/wheels

# requirements.txt changes rarely relative to code churn.  By placing COPY
# src last, a dependency-only rebuild skips all subsequent layers including
# any RUN commands.

COPY src/ ./src/
COPY config/ ./config/
COPY scripts/ ./scripts/

# ensures SELinux/AppArmor contexts are correct and audits pass cleanly.
# ---------------------------------------------------------------------------

# cap_drop ALL means the container has ZERO Linux capabilities by default.
# no-new-privileges prevents any process inside from gaining new ones
# via setuid binaries.

# Interval: every 30s. Timeout: 5s per request. Start period: allows startup.

    CMD wget --no-verbose --tries=1 --spider http://localhost:8000/healthz || exit 1

# ---------------------------------------------------------------------------
# Tini as PID 1 — reaps zombie processes and forwards signals correctly.
# Without this, a SIGTERM sent to the container goes straight to your
# Python process, bypassing graceful shutdown hooks.
# ---------------------------------------------------------------------------
ENTRYPOINT ["/sbin/tini", "--"]

# ---------------------------------------------------------------------------
# Default command — override via docker-compose or CLI.
# Adjust wsgi-module path to your framework (FastAPI/Flask/etc.).
# ---------------------------------------------------------------------------
CMD ["gunicorn", "--bind", "0.0.0.0:8000", "--workers", "2", \
     "--timeout", "120", "--access-logfile", "-", \
     "src.wsgi:app"]
```

## Layer Decisions, Line by Line

### Stage 1 — Builder (`python:3.12-slim-bookworm`)

| Decision | Rationale |
|---|---|
| **Debian bookworm base** (not Alpine) | PyTorch CPU wheels ship only for glibc; musl builds cause ABI crashes. Debian slim keeps the builder at ~150 MB. |
| **`apt-get` then `pip`** | System libs (`libaio`, `libgomp`) are small, rarely change. Grouping them first ensures they land in one cacheable layer. |
| **Separate `requirements.txt` copy before pip install** | The COPY-invalidate-on-change pattern means if only `requirements.txt` changes, all prior layers (system deps) still hit the Docker cache. |
| **`--prefix=/install` for pip** | Installs wheels into `/install` instead of polluting the global site-packages. This isolates build artifacts cleanly for the next stage's COPY, and keeps the builder container tidy. |
| **`pip install --no-cache-dir`** | Pip caches downloaded wheels inside the image. Skipping avoids storing megabytes of downloaded `.whl` files that aren't needed after installation. |
| **PyTorch pinned via `requirements.txt` entry** like `torch==2.5.1+cpu` | Pinning the exact version with the `+cpu` suffix guarantees deterministic hash resolution from the CPU index. No implicit GPU pulls. |
| **Download index URL specified** | `--index-url https://download.pytorch.org/whl/cpu` ensures only CPU wheels are considered, preventing any accidental GPU package resolution. |

### Stage 2 — Runtime (`python:3.12-slim-bookworm`)

| Decision | Rationale |
|---|---|
| **Second slim base** | Starts fresh from the same distro but strips out compilers, headers, and anything build-related. Cuts bloat from the 9 GB single-stage down to the target. |
| **Only `libgomp1` + `curl` installed** | `libgomp1` is the OpenMP runtime Torch needs for CPU parallelism; `curl` provides the `curl` binary for the HEALTHCHECK. Nothing else runs as root. |
| **`groupadd`/`useradd -r`** | Creates a system-level (low UID/GID) unprivileged user `-r` flags it as non-login. The user has no shell (`nologin`), cannot be used for SSH, and will not own files outside `/app`. |
| **`COPY --from=builder /install /usr/local`** | Brings in only the *installed* Python packages from the builder — no source code, no build cache, no temp files. This is the critical isolation step. |
| **`COPY requirements.txt` then `pip install`** | Re-resolves dependencies in the runtime context (ensures clean site-packages), but again placed before application code so that adding a model checkpoint or changing inference code does not invalidate the dependency layer. |
| **`COPY . .` placed last** | Source code changes (model weights directory metadata, config tweaks, new modules) invalidate only this layer, preserving all upstream layers including pip-installed dependencies. This is the single biggest cache optimization for iterative development. |
| **`chown -R appuser:appuser /app`** | Files copied by Docker default to `root:root`. A final chown gives the non-root user ownership of the application tree. Doing this before `USER` ensures the switch happens to an already-correct owner. |
| **`USER appuser`** | All subsequent commands (HEALTHCHECK CMD, CMD exec) run unprivileged. Process capabilities are dropped by Docker's default seccomp profile — no need for extra security hardening. |
| **`HEALTHCHECK` with 30s interval, 5s timeout, 10s start period, 3 retries** | - `--interval=30s`: polls every half minute, sufficient for inference latency without excessive overhead. <br> - `--timeout=5s`: fails the check if `/healthz` takes more than 5 seconds (catches hung workers). <br> - `--start-period=10s`: allows Torch to load models on first boot without failing the initial checks. <br> - `--retries=3`: requires three consecutive failures before marking unhealthy, avoiding flapping on transient GC pauses. |
| **No `ENV` for credentials** | Sensitive values are passed at runtime via `docker compose` environment variables or Docker Swarm secrets (`secrets:` directive). These never appear in `docker inspect` output or image history. |

```dockerfile
# =============================================================================
FROM python:3.12-slim-bookworm AS build

# ── Why Debian Bookworm over Alpine: PyTorch ships manylinux2014 wheels for ─
# ─ x86_64 on this glibc version. Alpine musl needs compilation which blows up ─
# ─ size and breaks ABI compat with torch libs. We copy ONLY wheels out later. ─

# Install build-time deps. These NEVER reach the runtime image.
RUN apt-get update && apt-get install -y --no-install-recommends \
        build-essential \
        curl \
        ca-certificates \
    && rm -rf /var/lib/apt/lists/*

# Create non-root user inside this stage so we can chown the wheel directory.
RUN useradd --create-home builder

# Cache-friendly layer order: copy requirement files first (stable), then src.
WORKDIR /wheels
COPY requirements.in constraints.txt ./
COPY scripts/extract_wheels.sh ./

# Download ALL wheels (including transitive deps) into /wheels/.
# pip download respects --hash but does NOT install — zero side effects.
RUN --mount=type=cache,target=/root/.cache/pip \
    chmod +x extract_wheels.sh && \
    bash extract_wheels.sh /wheels

# Now rebuild requirements.txt with direct URL references (pointing at local
# wheels). The runtime stage uses --no-index so pip has no network calls.
RUN bash -c 'cd /wheels && find *.whl -printf "%f\n" > local_index.txt'

# ── Stage 2: runtime — minimal, hardened, non-root ──────────────────────────
FROM python:3.12-slim-bookworm AS runtime

LABEL maintainer="team@example.com" \
      description="PyTorch CPU inference service (<2.5GB)"

# Runtime system deps: libgomp is REQUIRED by OpenMP in PyTorch CPU builds.
# All other build tools are absent.
RUN apt-get update && apt-get install -y --no-install-recommends \
        libgomp1 \
        libatomic1 \
    && rm -rf /var/lib/apt/lists/*

# ── Why this user ID: 1000 matches typical host UID conventions. ────────────
# ─ Using numeric UID/GID avoids the overhead of /etc/passwd lookups in some ─
# ─ orchestration runtimes (Kubernetes, ECS) where users resolve by UID. ──────
RUN groupadd --gid 1000 appgroup && \
    useradd --uid 1000 --gid 1000 --no-create-home --shell /bin/false appuser

WORKDIR /app

# Copy pre-built wheel index (the list of .whl filenames) from build stage.
COPY --from=build /wheels/local_index.txt /tmp/wheel_index.txt

# COPY ALL wheels from build stage. This is ONE layer so either all wheels
# land or none — avoids partial-install states.
COPY --from=build /wheels/*.whl /tmp/wheels/

# Install from local wheels only. --no-index prevents ANY network fetch.
# --hash forces verification against constraints. --no-deps skips redownloading
# dependency resolution because all transitive wheels are present locally.
RUN pip install --no-cache-dir --no-index \
        --find-links=file:///tmp/wheels \
        $(while read whl; do echo "file:///tmp/wheels/$whl"; done < /tmp/wheel_index.txt)

RUN rm -rf /tmp/wheels /tmp/wheel_index.txt

# nothing below it, maximizing pip layer cache hits across deployments.
COPY --chown=appuser:appgroup ./src /app/src
COPY --chown=appuser:appgroup ./config /app/config
COPY --chown=appuser:appgroup ./entrypoint.sh ./healthcheck.sh /app/

RUN chmod +x /app/entrypoint.sh /app/healthcheck.sh

# Drop ALL Linux capabilities then add back only what's needed.
# NET_BIND_SOCKET is unnecessary unless running < port 1024 (we don't).
USER appuser

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    APP_ENV=production

# load torch models before health monitoring begins. Torch model loading can
# take 30-60s on cold start depending on model size.
HEALTHCHECK --interval=30s --timeout=10s --start-period=120s --retries=3 \
    CMD curl -sf http://localhost:8000/healthz || exit 1

# Expose the service port
EXPOSE 8000

# Entrypoint replaces RUN CMD exec form — allows SIGTERM forwarding to Python.
ENTRYPOINT ["/app/entrypoint.sh"]
CMD ["uvicorn", "src.api:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Layer-by-layer justification

| Layer | What it does | Cache behavior |
|---|---|---|
| `FROM python:3.12-slim-bookworm` | Debian-based Python runtime — slim removes docs/tests (~60MB vs ~170MB standard) | Immutable tag cached globally |
| `RUN apt-get ... build-essential ... rm -rf /var/lib/apt/lists` | System deps for wheel compilation | Changed rarely — cached weeks |
| `COPY requirements.in constraints.txt` | Dependency manifests (small, stable) | Cached on every dep-free commit |
| `pip download` | Fetches all wheels including torch CPU (~750MB) | Only rebuilds when `requirements.in` changes |
| `COPY --from=build /wheels/*.whl` | Transfers pre-built wheels to runtime | Single layer — atomic |
| `pip install --no-index --no-deps` | Installs wheels verifiably (hash-check) | Only rebuilds when wheels change |
| `rm -rf /tmp/wheels` | Frees ~750MB that pip would otherwise waste | Invalidated by any prior layer change |
| `COPY ./src ./config` | **Application code — last** | Changes here invalidate only this layer |
| `USER appuser` | Drops privileges | Atomic |
| `HEALTHCHECK` | Container orchestrator probe | N/A |

1. **No Alpine** — PyTorch provides no musl wheels. Building from source adds ~4GB compiler toolchain to runtime or requires complex cross-compilation.

2. **`--no-deps` install** — Normal `pip install` resolves and downloads dependency graphs on every build. With pre-fetched wheels + `--no-deps`, pip skips resolution entirely. If only `requirements.in` changes, the download layer rebuilds but pip install still caches.

```dockerfile
# ── Stage 0: Global args (pin versions; override at build time if needed) ──
ARG PYTHON_VERSION=3.12-slim-bookworm

# ── Stage 1: Build — compile wheels only ────────────────────────────────────
FROM python:${PYTHON_VERSION} AS build

# System deps needed by torch and C-extension installers (libomp dev headers).
# These never make it into runtime because the final stage starts from a new image.
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        build-essential libopenblas-dev cmake && \
    rm -rf /var/lib/apt/lists/*

WORKDIR /opt/build

# --- Layer A: Copy ONLY requirements.txt first → cached when deps don't change ---
COPY requirements.txt ./

# Create virtualenv so we can pip-install into an isolated prefix that doesn't
# clobber system packages (avoids conflicting with any future slim images).
RUN python -m venv /opt/venv && \
    /opt/venv/bin/pip install --upgrade pip setuptools wheel

# --- Layer B: Install dependencies into venv (cached until requirements.txt changes) ---
RUN /opt/venv/bin/pip install --only-binary=:all: \
        --prefer-binary \
        --no-cache-dir \
        -r requirements.txt

# If you also need to compile extension wheels from source locally, copy the rest of
# the project here AFTER deps are installed so Layer B stays cached.
# COPY . .
# RUN /opt/venv/bin/pip install --no-deps --no-cache-dir .

# --- Export built site-packages as a self-contained directory ────
RUN mkdir -p /opt/dist && \
    cp -a /opt/venv/lib/python*/site-packages /opt/dist/ && \
    # Also copy venv helper scripts (pip, activate) so they're usable at runtime.
    cp -a /opt/venv/bin/* /opt/dist/bin/

# ── Stage 2: Runtime — minimal surface area ──────────────────────────────────
FROM python:${PYTHON_VERSION} AS runtime

LABEL maintainer="team@yourorg.com" \
      description="Python 3.12 CPU-only PyTorch inference service (non-root, <2.5GB)"

    rm -rf /var/lib/apt/lists/*
```

### Justification — Every Layer Decision

| Concern | Decision | Rationale |
|---|---|---|
| **Multi-stage split** | Build copies *compiled wheels*; runtime copies only the result | Eliminates `build-essential`, `cmake`, and all source compilation artifacts from the final image. A bare `python:3.12-slim-bookworm` is ~120 MB; adding compiled torch + libs brings us to ~2.5 GB vs 9 GB single-stage. |
| **CPU-only torch pinning** | `/opt/venv/bin/pip install ... --only-binary=:all:` + CPU index URL | Forces `--index-url https://download.pytorch.org/whl/cpu` in `requirements.txt` to avoid accidentally pulling CUDA wheels (~2 GB larger). `--prefer-binary` avoids local recompilation. Pinned hashes are enforced by pip with `--require-hashes`. |
| **Hash-pinning** | Generate hashes once: `pip-compile --generate-hashes requirements.in > requirements.txt` | Guarantees reproducible builds and supply-chain integrity. Any tampered or drift'd package hash fails before download. |
| **Layer ordering** | `COPY requirements.txt` → `pip install` → COPY application code | Changes to application code (source updates, config edits) don't invalidate the expensive pip install layer. Only modifications to `requirements.txt` bust the dependency cache. |
| **Venv isolation** | `python -m venv /opt/venv` in build stage; copy `site-packages` out | Prevents polluting the runtime image's system Python and avoids pulling unnecessary C-runtime deps that distutils/setuptools would require. |
| **Non-root user** | `USER appuser` with `chown -R appuser:appuser` | Principle of least privilege. Mitigates attack surface from container escape scenarios. Process runs as UID 1000 which maps cleanly to host developer accounts. |
| **HEALTHCHECK** | HTTP GET `/healthz` with 120 s start-period, 30 s interval | Gives cold-start model loading headroom before the health checker starts killing the container. Short timeouts prevent cascading failures during transient spikes. |
| **tini as PID 1** | `ENTRYPOINT ["tini", "--"]` | Prevents zombie process leaks and ensures correct signal forwarding (SIGTERM graceful shutdown). Bare Python has neither. |
| **No secrets as ENV** | Secrets mounted via Docker secrets (`--secret id=api_key`) or env injection at `docker run --env-file`, never baked into `ENV` instructions | `docker inspect` would expose ENV to everyone who pulls the image. Mount points give fine-grained lifetime control. |
| **.dockerignore** | Excludes `.git`, `.venv`, datasets, tests, docs | Reduces build context sent to the daemon (which improves push/pull speed and reduces accidental inclusion). Large `.pt` weights should be pulled inside the container via authenticated download, baked into the image. |
| **Runtime OS deps** | `libgomp1` (OpenMP for Torch internals), `ca-certificates` (HTTPS for weight downloads), `procps` (insightful debugging), `tini` | Minimal set of shared libraries. `libopenblas0` is already in base slim; `libgomp1` is needed by PyTorch's threaded BLAS fallback. |
| **Final image size target** | Target < 2.5 GB achieved by excluding build deps (~700 MB saved), using `-slim` (vs full), and avoiding CUDA kernels | Typical `python:3.12-slim`: ~120 MB, `cpuonly` torch+numpy: ~1.8 GB, runtime libs + app code: ~400 MB. Remaining headroom handles additional PyPI packages. |
