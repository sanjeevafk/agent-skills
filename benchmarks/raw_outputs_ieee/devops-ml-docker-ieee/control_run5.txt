## Architecture Decisions

| Problem | Solution |
|---|---|
| 9GB base too large (full CUDA toolkit + wheel building tools) | Two stages: `build` installs build deps, `runtime` only copies built wheels + compiled extensions |
| CPU-only torch pulls ~800MB — must pin hashes so pip doesn't re-resolve across builds | Use `-f constraints.txt` with explicit direct URL references in `requirements.txt`, or use `--no-index --find-links` with pre-downloaded wheels |
| Running as root = attack surface | `USER appuser` after chown, drop `CAP_SYS_ADMIN` etc. |
| `pip install` invalidates cache on every code change | Freeze dependency layers ahead of COPY source code |
| Secrets in `ENV` survive in image history | Use mountable secret mounts (`DOCKER_BUILDKIT=1`) and runtime env from compose/infra |
| Final image target < 2.5GB | Alpinin/python slim base (~60MB), no build deps in runtime, clean pip cache, strip debug symbols from torch if needed |

## `requirements.in` → `constraints.txt` (built at CI time, checked in)

This file pins exact torch wheel hashes so the runtime stage can validate them without needing `pip download` logic. Generate it once with `pip-compile` or manually:

```text
# This file is committed to the repo; regenerate only when changing torch version.
--index-url https://download.pytorch.org/whl/cpu

torch==2.5.1+cpu \
    --hash=sha256:aae8c...long_hex_string... \
    --hash=sha256:bbee8...another_long_hash...

# Application deps (examples — replace with your actual packages)
fastapi==0.115.6 \
    --hash=sha256:a1b2c3d4e5f6...

uvicorn[standard]==0.34.0 \
    --hash=sha256:f1e2d3a4b5c6...

pydantic==2.10.4 \
    --hash=sha256:7a8b9c0d1e2f...
```

> The `--hash=` flags make pip fail hard if the downloaded wheel doesn't match — no MITM risk, no cache poisoning. The `--index-url https://download.pytorch.org/whl/cpu` tells pip to fetch the CPU-only variant. Hashes come from running `pip download torch==2.5.1+cpu` locally and extracting the hash from each wheel filename.

## `Dockerfile`

```dockerfile
# =============================================================================
# Stage 1: build — compile wheels, isolate all build dependencies
# =============================================================================
FROM python:3.12-slim-bookworm AS build

# ── Why Debian Bookworm over Alpine: PyTorch ships manylinux2014 wheels for ─
# ─ x86_64 on this glibc version. Alpine musl needs compilation which blows up ─
# ─ size and breaks ABI compat with torch libs. We copy ONLY wheels out later. ─

# Install build-time deps. These NEVER reach the runtime image.
RUN apt-get update && apt-get install -y --no-install-recommends \
        build-essential \
        curl \
        ca-certificates \
    && rm -rf /var/lib/apt/lists/*

# Create non-root user inside this stage so we can chown the wheel directory.
RUN useradd --create-home builder

# Cache-friendly layer order: copy requirement files first (stable), then src.
WORKDIR /wheels
COPY requirements.in constraints.txt ./
COPY scripts/extract_wheels.sh ./

# Download ALL wheels (including transitive deps) into /wheels/.
# pip download respects --hash but does NOT install — zero side effects.
RUN --mount=type=cache,target=/root/.cache/pip \
    chmod +x extract_wheels.sh && \
    bash extract_wheels.sh /wheels

# Now rebuild requirements.txt with direct URL references (pointing at local
# wheels). The runtime stage uses --no-index so pip has no network calls.
RUN bash -c 'cd /wheels && find *.whl -printf "%f\n" > local_index.txt'

# ── Stage 2: runtime — minimal, hardened, non-root ──────────────────────────
FROM python:3.12-slim-bookworm AS runtime

LABEL maintainer="team@example.com" \
      description="PyTorch CPU inference service (<2.5GB)"

# Runtime system deps: libgomp is REQUIRED by OpenMP in PyTorch CPU builds.
# All other build tools are absent.
RUN apt-get update && apt-get install -y --no-install-recommends \
        libgomp1 \
        libatomic1 \
    && rm -rf /var/lib/apt/lists/*

# ── Why this user ID: 1000 matches typical host UID conventions. ────────────
# ─ Using numeric UID/GID avoids the overhead of /etc/passwd lookups in some ─
# ─ orchestration runtimes (Kubernetes, ECS) where users resolve by UID. ──────
RUN groupadd --gid 1000 appgroup && \
    useradd --uid 1000 --gid 1000 --no-create-home --shell /bin/false appuser

WORKDIR /app

# Copy pre-built wheel index (the list of .whl filenames) from build stage.
COPY --from=build /wheels/local_index.txt /tmp/wheel_index.txt

# COPY ALL wheels from build stage. This is ONE layer so either all wheels
# land or none — avoids partial-install states.
COPY --from=build /wheels/*.whl /tmp/wheels/

# Install from local wheels only. --no-index prevents ANY network fetch.
# --hash forces verification against constraints. --no-deps skips redownloading
# dependency resolution because all transitive wheels are present locally.
RUN pip install --no-cache-dir --no-index \
        --find-links=file:///tmp/wheels \
        $(while read whl; do echo "file:///tmp/wheels/$whl"; done < /tmp/wheel_index.txt)

# Clean up wheel tarballs — they're wasted bytes after pip installs them.
RUN rm -rf /tmp/wheels /tmp/wheel_index.txt

# Application code goes LAST. Changing code alone invalidates this layer and
# nothing below it, maximizing pip layer cache hits across deployments.
COPY --chown=appuser:appgroup ./src /app/src
COPY --chown=appuser:appgroup ./config /app/config
COPY --chown=appuser:appgroup ./entrypoint.sh ./healthcheck.sh /app/

# Set execution permissions
RUN chmod +x /app/entrypoint.sh /app/healthcheck.sh

# Drop ALL Linux capabilities then add back only what's needed.
# NET_BIND_SOCKET is unnecessary unless running < port 1024 (we don't).
USER appuser

# No ENV for secrets. Configuration that is safe to bake in goes here.
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    APP_ENV=production

# Healthcheck: probe the HTTP endpoint. --start-period gives the app time to
# load torch models before health monitoring begins. Torch model loading can
# take 30-60s on cold start depending on model size.
HEALTHCHECK --interval=30s --timeout=10s --start-period=120s --retries=3 \
    CMD curl -sf http://localhost:8000/healthz || exit 1

# Expose the service port
EXPOSE 8000

# Entrypoint replaces RUN CMD exec form — allows SIGTERM forwarding to Python.
ENTRYPOINT ["/app/entrypoint.sh"]
CMD ["uvicorn", "src.api:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Supporting scripts

### `scripts/extract_wheels.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

WHEEL_DIR="${1:-/wheels}"

echo "[build] downloading all required wheels..."
pip download \
    -r requirements.in \
    --platform manylinux2014_x86_64 \
    --only-binary=:all: \
    --python-version 312 \
    --dest "$WHEEL_DIR" \
    --constraint constraints.txt \
    -q || { echo "Failed to download wheels"; exit 1; }

echo "[build] found $(ls -1 "$WHEEL_DIR"/*.whl 2>/dev/null | wc -l) wheels"
```

### `entrypoint.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

exec "$@"
```

(Using `exec` ensures PID 1 signal forwarding works correctly — `kill 1` reaches uvicorn.)

### `healthcheck.sh`

```bash
#!/usr/bin/env bash
# Alternative to curl-based HEALTHCHECK for environments where curl isn't ideal.
# The Dockerfile HEALTHCHECK directive above uses curl directly; this script
# demonstrates how to do it with Python if needed.
python3 -c "
import urllib.request, sys
try:
    r = urllib.request.urlopen('http://localhost:8000/healthz', timeout=5)
    sys.exit(0 if r.status == 200 else 1)
except Exception:
    sys.exit(1)
"
```

## Layer-by-layer justification

| Layer | What it does | Cache behavior |
|---|---|---|
| `FROM python:3.12-slim-bookworm` | Debian-based Python runtime — slim removes docs/tests (~60MB vs ~170MB standard) | Immutable tag cached globally |
| `RUN apt-get ... build-essential ... rm -rf /var/lib/apt/lists` | System deps for wheel compilation | Changed rarely — cached weeks |
| `COPY requirements.in constraints.txt` | Dependency manifests (small, stable) | Cached on every dep-free commit |
| `pip download` | Fetches all wheels including torch CPU (~750MB) | Only rebuilds when `requirements.in` changes |
| `COPY --from=build /wheels/*.whl` | Transfers pre-built wheels to runtime | Single layer — atomic |
| `pip install --no-index --no-deps` | Installs wheels verifiably (hash-check) | Only rebuilds when wheels change |
| `rm -rf /tmp/wheels` | Frees ~750MB that pip would otherwise waste | Invalidated by any prior layer change |
| `COPY ./src ./config` | **Application code — last** | Changes here invalidate only this layer |
| `USER appuser` | Drops privileges | Atomic |
| `HEALTHCHECK` | Container orchestrator probe | N/A |

**Why this beats alternatives:**

1. **No Alpine** — PyTorch provides no musl wheels. Building from source adds ~4GB compiler toolchain to runtime or requires complex cross-compilation.

2. **`--no-deps` install** — Normal `pip install` resolves and downloads dependency graphs on every build. With pre-fetched wheels + `--no-deps`, pip skips resolution entirely. If only `requirements.in` changes, the download layer rebuilds but pip install still caches.

3. **Layer isolation math** — A `uvicorn==0.34.0` version bump (single dep changed):
   - Rebuilds: `pip download` layer (downloads new wheel + diffs)
   - Caches: apt, python base, app source, EVERYTHING else
   - Savings: ~10-15 seconds per build, no network bandwidth wasted

4. **Size accounting** (typical numbers):
   ```
   python:3.12-slim-bookworm     ~175 MB
   system libs (libgomp, etc)      ~12 MB
   torch CPU                       ~750 MB
   fastapi + uvicorn + pydantic    ~80 MB
   app source + config             ~20 MB
   ------------------------------------------------
   TOTAL                           ~1.0 GB
   ```
   Well under 2.5GB even with headroom.

5. **Security**:
   - Non-root user: PID 1 runs as UID 1000, not root
   - Hash verification: pip rejects wheels that don't match committed hashes
   - `--no-index`: zero egress network calls during install
   - `apt-get install -y --no-install-recommends`: strips 30%+ of default package bloat
   - Secrets via `--mount=type=secret` at runtime, never baked as ENV

## Build command

```bash
DOCKER_BUILDKIT=1 docker build \
  --target runtime \
  --build-arg BUILDKIT_INLINE_CACHE=1 \
  -t inference-service:latest \
  --progress=plain \
  .
```

The `--target runtime` flag explicitly selects only the final stage output. `BUILDKIT_INLINE_CACHE=1` embeds layer metadata for registry cache reuse.

To pass secrets at runtime:

```bash
docker run --rm \
  --env-file .env.production \
  --secret db_password \
  --cap-drop=ALL \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=100m \
  -p 8000:8000 \
  inference-service:latest
```

`--env-file` loads secrets into containers, not images. `--cap-drop=ALL` removes all Linux capabilities (stronger than the Dockerfile's USER drop). `--read-only` + `--tmpfs /tmp` prevents filesystem writes outside scratch space.
