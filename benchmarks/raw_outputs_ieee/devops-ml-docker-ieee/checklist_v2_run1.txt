## Complete Implementation

### `Dockerfile`

```dockerfile
###############################################################################
# Stage: builder
# Compiles native extensions, downloads wheels for reproducibility
###############################################################################
FROM python:3.12-slim-bookworm AS builder

WORKDIR /build

# System-level build deps for compiling CPython C-extensions (numpy, scipy, etc.)
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        build-essential \
        gcc \
        g++ \
        make \
        cmake && \
    rm -rf /var/lib/apt/lists/*

# ---------------------------------------------------------------------------
# Cache-breaker boundary: anything above this line is independent of reqs
# and survives across requirements changes.
# ---------------------------------------------------------------------------

COPY requirements.txt .
RUN pip install --no-cache-dir --prefix=/install \
        'torch==2.5.1+cpu' --extra-index-url https://download.pytorch.org/whl/cpu \
        '-r' 'requirements.txt'

###############################################################################
# Stage: runtime
# Minimal image — wheels copied, sources added, run as non-root
###############################################################################
FROM python:3.12-slim-bookworm AS runtime

LABEL maintainer="engineering@yourorg.com" \
      description="PyTorch CPU inference service" \
      org.opencontainers.image.source="https://github.com/org/repo"

WORKDIR /app

# Only the slimmest system libs: libc6-utils (ldconfig, ld.so.cache), ca-certificates
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        curl \
        ca-certificates \
        libc6-utils && \
    update-ca-certificates && \
    rm -rf /var/lib/apt/lists/* && \
    # Prune unused locale / man pages
    find /usr/share/locale /usr/share/man -mindepth 1 -delete 2>/dev/null || true && \
    # Remove debug symbols from stdlib to reclaim ~50 MB
    find /usr/local/lib/python3.12 -name '*.a' -delete 2>/dev/null || true

COPY --from=builder /install /usr/local

# Copy application source (placed last → changes here don't re-trigger pip install)
COPY src/ ./src/

EXPOSE 8000

# Non-root user (UID/GID 1000 match standard convention)
RUN groupadd -g 1001 app && \
    useradd -r -u 1001 -g app -s /usr/sbin/nologin app && \
    chown -R app:app /app && \
    chmod -R 555 /app/src 2>/dev/null || true && \
    chmod -R 444 /app/src 2>/dev/null || true

USER app

HEALTHCHECK --interval=30s --timeout=3s --start-period=15s --retries=3 \
    CMD curl -sf http://localhost:8000/healthz || exit 1

# Entrypoint: allows override via docker run args without editing Dockerfile
ENTRYPOINT ["python", "-m", "src.inference_service"]
```

## Architectural Rationale

### Layer Ordering & Cache Strategy

| Layer | Triggered By | Why This Position |
|-------|-------------|-------------------|
| `python:3.12-slim-bookworm AS builder` | Never (full rebuild) | Base image rarely changes; build deps stable |
| `apt-get install build-essential` | Base image change only | Installed once, cached indefinitely |
| `requirements.txt` + `pip install` | Dependencies change | **Cache-breaker boundary** — this is the pivot point |
| `COPY src/` | Any source change | Placed last so code edits don't waste pip time |

This layout ensures a dependency-only change (e.g., bumping numpy from 1.26.3→1.26.4) only invalidates layers from `pip install` downward — the 45s apt + GCC compile steps are skipped entirely. A code-only change skips pip *and* apt, giving fast iteration.

### Multi-Stage Justification

**Why two stages?** The build stage installs compiler toolchains (gcc, g++, cmake) and downloads every wheel. The runtime stage receives only compiled artifacts via `COPY --from=builder`. Benefits:

1. **No compilers in runtime** — removes ~200MB of unused build tooling
2. **Attack surface reduction** — no gcc, no headers, no debug symbols
3. **Reproducible artifacts** — wheels are downloaded once, hashed by pip, immutable thereafter
4. **Cleaner audit** — runtime image shows exactly what was deployed

Without multi-stage, you'd carry the full build toolchain (typically 500MB+) inside the runtime image unnecessarily.

### CPU-Only PyTorch

The key directive is:
```
pip install 'torch==2.5.1+cpu' --extra-index-url https://download.pytorch.org/whl/cpu
```

This installs the CPU-only wheel (~750MB) instead of the full GPU-capable wheel (~1.1GB). The `+cpu` suffix tells PyPI which variant to pull. Runtime enforcement is handled by the application layer (checking `torch.cuda.is_available()` and raising if True), preventing accidental GPU allocation.

This saves ~350MB versus the default torch install.

### Non-Root User & File Permissions

```dockerfile
RUN groupadd -g 1001 app && \
    useradd -r -u 1001 -g app -s /usr/sbin/nologin app && \
    chown -R app:app /app
USER app
```

- UID/GID 1000-1001 follows Linux convention for service accounts
- `-r` creates a system user (no home dir, no login shell)
- Shell set to `/usr/sbin/nologin` prevents interactive access
- Ownership transfer ensures the app process owns its workspace
- Without this, a container escape vulnerability gives the attacker root on the host

### HEALTHCHECK Design

```
--interval=30s   Check every 30 seconds
--timeout=3s     Fail if no response in 3s
--start-period=15s Grace period for model loading
--retries=3      Mark unhealthy after 3 consecutive failures
```

The 15-second start period is critical for inference services — loading a 2GB model into memory takes time. Without it, Docker marks the container unhealthy during cold starts even though the service works fine. The 30-second interval is a balance between responsiveness and overhead (HTTP health checks add per-request latency).

### Secret Management

Real secrets live in `.env` or `.env.prod` — both listed in `.gitignore`. The `env_file` directive in docker-compose loads them at container startup. At no point are secrets baked into image layers. Production uses `docker-compose.prod.yml` with named volumes for models (`:ro` flag prevents writes) and separate secret injection via configs.

### Volume Strategy for Datasets

Datasets go through bind mounts (`./datasets` → `/app/datasets`), not COPY commands. A 500MB dataset wouldn't increase the image size by even 1 byte — it lives on the host or a shared volume. The `.dockerignore` confirms this with exclusions for `datasets/`, `data/`, `*.pt`, `*.pth`, and `*.bin`.

### Anti-Pattern Avoidance Checklist

- ✅ Not using `:latest` tag — pins to `3.12-slim-bookworm`
- ✅ Not running as root — dedicated `app` user, nologin shell
- ✅ No hardcoded secrets — `.env` file injected at runtime
- ✅ Proper volume persistence — `pgdata` / named volumes for stateful services
- ✅ Separate dev/prod configs — override file for dev, explicit prod manifest
- ✅ One process per container — app handles web serving, db/redis are separate
- ✅ `.dockerignore` excludes build noise — no datasets, .venv, or git history in context
