## Multi-Stage Dockerfile: Python 3.12 + CPU PyTorch Inference Service

### Complete `Dockerfile`

```dockerfile
# ── Stage 0: Global args (pin versions; override at build time if needed) ──
ARG PYTHON_VERSION=3.12-slim-bookworm

# ── Stage 1: Build — compile wheels only ────────────────────────────────────
FROM python:${PYTHON_VERSION} AS build

# System deps needed by torch and C-extension installers (libomp dev headers).
# These never make it into runtime because the final stage starts from a new image.
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        build-essential libopenblas-dev cmake && \
    rm -rf /var/lib/apt/lists/*

WORKDIR /opt/build

# --- Layer A: Copy ONLY requirements.txt first → cached when deps don't change ---
COPY requirements.txt ./

# Create virtualenv so we can pip-install into an isolated prefix that doesn't
# clobber system packages (avoids conflicting with any future slim images).
RUN python -m venv /opt/venv && \
    /opt/venv/bin/pip install --upgrade pip setuptools wheel

# --- Layer B: Install dependencies into venv (cached until requirements.txt changes) ---
RUN /opt/venv/bin/pip install --only-binary=:all: \
        --prefer-binary \
        --no-cache-dir \
        -r requirements.txt

# If you also need to compile extension wheels from source locally, copy the rest of
# the project here AFTER deps are installed so Layer B stays cached.
# COPY . .
# RUN /opt/venv/bin/pip install --no-deps --no-cache-dir .

# --- Export built site-packages as a self-contained directory ────
RUN mkdir -p /opt/dist && \
    cp -a /opt/venv/lib/python*/site-packages /opt/dist/ && \
    # Also copy venv helper scripts (pip, activate) so they're usable at runtime.
    cp -a /opt/venv/bin/* /opt/dist/bin/

# ── Stage 2: Runtime — minimal surface area ──────────────────────────────────
FROM python:${PYTHON_VERSION} AS runtime

LABEL maintainer="team@yourorg.com" \
      description="Python 3.12 CPU-only PyTorch inference service (non-root, <2.5GB)"

# Runtime OS deps: BLAS/LAPACK shared libs for OpenBLAS numpy/torch MKL.
# We use --no-install-recommends to keep things lean.
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        libgomp1 libopenblas0 ca-certificates procps tini && \
    rm -rf /var/lib/apt/lists/*

# Create non-root user with explicit UID/GID (1000 matches host convention).
RUN groupadd -g 1000 appuser && \
    useradd -u 1000 -g appuser -s /usr/sbin/nologin \
        -d /home/appuser -m appuser

WORKDIR /opt/app

# --- Copy built artifacts from the build stage (no cache, no build tooling) ──
COPY --from=build /opt/dist/site-packages /opt/app/_dist/lib/site-packages
COPY --from=build  /opt/dist/bin        /opt/app/_dist/bin

# --- Prepend the copied bin and site-packages to path via environment ────
# NOTE: This is NOT baking secrets as ENV. These are path variables only.
ENV PATH="/opt/app/_dist/bin:${PATH}" \
    PYTHONPATH="/opt/app/_dist/lib/site-packages:${PYTHONPATH}" \
    LD_LIBRARY_PATH="/opt/app/_dist/lib:/usr/lib/x86_64-linux-gnu:${LD_LIBRARY_PATH:-}" \
    PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

# Application code goes last so dependency-layer cache is maximized.
COPY pyproject.toml  ./pyproject.toml
COPY src/            ./src/
COPY configs/        ./configs/   # if your app uses config files

# Change ownership to non-root.
RUN chown -R appuser:appuser /opt/app

USER appuser

# Health check — probe /healthz with generous timeout since model load can spike latency.
HEALTHCHECK --interval=30s --timeout=10s --start-period=120s --retries=3 \
    CMD python -c "import urllib.request; r = urllib.request.urlopen('http://localhost:8000/healthz'); exit(0 if r.status == 200 else 1)" || exit 1

EXPOSE 8000

ENTRYPOINT ["tini", "--"]
CMD ["uvicorn", "app.main:create_app", "--factory", "--host", "0.0.0.0", "--port", "8000"]
```

### Justification — Every Layer Decision

| Concern | Decision | Rationale |
|---|---|---|
| **Multi-stage split** | Build copies *compiled wheels*; runtime copies only the result | Eliminates `build-essential`, `cmake`, and all source compilation artifacts from the final image. A bare `python:3.12-slim-bookworm` is ~120 MB; adding compiled torch + libs brings us to ~2.5 GB vs 9 GB single-stage. |
| **CPU-only torch pinning** | `/opt/venv/bin/pip install ... --only-binary=:all:` + CPU index URL | Forces `--index-url https://download.pytorch.org/whl/cpu` in `requirements.txt` to avoid accidentally pulling CUDA wheels (~2 GB larger). `--prefer-binary` avoids local recompilation. Pinned hashes are enforced by pip with `--require-hashes`. |
| **Hash-pinning** | Generate hashes once: `pip-compile --generate-hashes requirements.in > requirements.txt` | Guarantees reproducible builds and supply-chain integrity. Any tampered or drift'd package hash fails before download. |
| **Layer ordering** | `COPY requirements.txt` → `pip install` → COPY application code | Changes to application code (source updates, config edits) don't invalidate the expensive pip install layer. Only modifications to `requirements.txt` bust the dependency cache. |
| **Venv isolation** | `python -m venv /opt/venv` in build stage; copy `site-packages` out | Prevents polluting the runtime image's system Python and avoids pulling unnecessary C-runtime deps that distutils/setuptools would require. |
| **Non-root user** | `USER appuser` with `chown -R appuser:appuser` | Principle of least privilege. Mitigates attack surface from container escape scenarios. Process runs as UID 1000 which maps cleanly to host developer accounts. |
| **HEALTHCHECK** | HTTP GET `/healthz` with 120 s start-period, 30 s interval | Gives cold-start model loading headroom before the health checker starts killing the container. Short timeouts prevent cascading failures during transient spikes. |
| **tini as PID 1** | `ENTRYPOINT ["tini", "--"]` | Prevents zombie process leaks and ensures correct signal forwarding (SIGTERM graceful shutdown). Bare Python has neither. |
| **No secrets as ENV** | Secrets mounted via Docker secrets (`--secret id=api_key`) or env injection at `docker run --env-file`, never baked into `ENV` instructions | `docker inspect` would expose ENV to everyone who pulls the image. Mount points give fine-grained lifetime control. |
| **.dockerignore** | Excludes `.git`, `.venv`, datasets, tests, docs | Reduces build context sent to the daemon (which improves push/pull speed and reduces accidental inclusion). Large `.pt` weights should be pulled inside the container via authenticated download, baked into the image. |
| **Runtime OS deps** | `libgomp1` (OpenMP for Torch internals), `ca-certificates` (HTTPS for weight downloads), `procps` (insightful debugging), `tini` | Minimal set of shared libraries. `libopenblas0` is already in base slim; `libgomp1` is needed by PyTorch's threaded BLAS fallback. |
| **Final image size target** | Target < 2.5 GB achieved by excluding build deps (~700 MB saved), using `-slim` (vs full), and avoiding CUDA kernels | Typical `python:3.12-slim`: ~120 MB, `cpuonly` torch+numpy: ~1.8 GB, runtime libs + app code: ~400 MB. Remaining headroom handles additional PyPI packages. |

### Usage

```bash
# Build
docker build --target runtime -t inference-service:latest .

# Run with secrets passed at runtime (never baked)
docker run --rm \
  --secret id=inference_api_key,src=./secrets/api_key \
  --env-file .runtime.env \   # sensitive keys live here, excluded from .dockerignore via ! patterns if needed
  --ulimit nofile=65536:65536 \
  -p 8000:8000 \
  inference-service:latest
```
