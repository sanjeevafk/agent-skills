**Verifying signatures after JSON parsing and using in-memory replay tracking leaves your payment pipeline vulnerable to unauthenticated DoS attacks, cluster-wide double-processing, and timing side-channels.**

### Vulnerability Analysis (Ranked by Severity)

**1 → Critical: In-memory replay storage fails across workers, restarts, and concurrent requests.** A Python `dict` is local to a single process; multiple Uvicorn workers or multi-instance deployments cannot share state. A server restart wipes the ledger entirely, and simultaneous identical requests cause a check-then-act race condition that executes duplicate payouts or double-credits customer balances.

**2 → High: JSON deserialization before signature verification exposes the server to DoS and parser exploits.** Parsing untrusted payloads with Pydantic or `request.json()` consumes CPU and memory before proving authenticity. Attackers can flood the endpoint with deeply nested JSON bombs or malformed payloads that crash the parser before authentication ever runs.

**3 → High: Lack of rotating secret support causes payment dropouts during credential rollover.** Third-party processors rotate secrets by providing both the old and new secrets during a grace window. Enforcing a single static key forces downtime or dropped webhook deliveries during key rotations.

**4 → Medium: Non-constant-time signature comparison leaks HMAC digests via timing attacks.** Using standard `==` string equality terminates comparison on the first mismatched byte, allowing attackers to incrementally deduce valid signatures through microsecond-level response time measurements.

**5 → Medium: Missing timestamp verification permits replay attacks after cache eviction.** If the event ledger relies solely on an event ID with a time-to-live expiration, an attacker can re-send intercepted valid webhooks after the cache entry expires.

**6 → Low: Uncaught internal exceptions leak stack traces and processor internals.** Bubbling raw exceptions up to the HTTP response exposes infrastructure topology, database schema details, and third-party error structures to unauthorized clients.

def verify_hmac_signature(
    raw_body: bytes,
    signature_header: Optional[str],
    secrets: List[str],
    tolerance_seconds: int = 300
) -> bool:
    """
    Validates HMAC signature and timestamp tolerance in constant time.
    Expected header format: t=<timestamp>,v1=<hex_signature>
    """
    if not signature_header:
        return False

    header_parts: Dict[str, str] = {}
    for item in signature_header.split(","):
        if "=" in item:
            k, v = item.strip().split("=", 1)
            header_parts[k] = v

    timestamp_str = header_parts.get("t")
    received_signature = header_parts.get("v1")

    if not timestamp_str or not received_signature:
        return False

    # Prevent replay attacks by checking timestamp drift (5 minutes default)
    try:
        timestamp = int(timestamp_str)
    except ValueError:
        return False

    current_time = int(time.time())
    if abs(current_time - timestamp) > tolerance_seconds:
        logger.warning("Webhook timestamp rejected: drift exceeds tolerance window.")
        return False

    # Compute expected signature over: timestamp.raw_body
    signed_payload = f"{timestamp}.".encode("utf-8") + raw_body

    # Support zero-downtime secret rotation by testing active secrets
    for secret in secrets:
        expected_signature = hmac.new(
            key=secret.encode("utf-8"),
            msg=signed_payload,
            digestmod=hashlib.sha256
        ).hexdigest()

        # Constant-time comparison prevents timing attacks
        if hmac.compare_digest(expected_signature, received_signature):
            return True

    return False

### Key Architectural Fixes Applied

**→ Atomic distributed state ledger.** Replaced the in-memory dictionary with Redis `SET key status NX EX 86400`, resolving both cross-worker memory isolation and concurrent TOCTOU race conditions.

**→ Raw body signature verification.** `await request.body()` runs before JSON parsing, rejecting forged or malicious payloads before computing expensive deserialization logic.

**→ Rotating secret loop.** Supports simultaneous active and grace keys with constant-time `hmac.compare_digest()` to eliminate timing side-channels and prevent downtime during key rollovers.

**→ Enforced timestamp tolerance.** Webhook timestamp headers are bounded to a 300-second window, preventing replayed valid requests even after the cache expires.

**→ Sanitized error boundaries.** Internal exceptions, database connection details, and processor stack traces are logged locally with identifiers only, returning generic JSON errors to the client.
