### Vulnerability Analysis (Ordered by Severity)

**1 → In-memory replay tracking allows double-crediting across workers and restarts.** A standard Python `dict` is isolated per process and wipes on restart, failing across multi-worker deployments (e.g., Uvicorn with multiple workers). It also introduces a **race condition where concurrent duplicate requests** both pass the check before either writes to memory.

**2 → HMAC verification on parsed JSON enables parser DoS and signature mismatches.** Re-serializing parsed JSON alters whitespace, number precision, and key ordering, breaking signatures. Parsing before verification also exposes the JSON parser to **unauthenticated denial-of-service payloads**.

**3 → Single-secret validation breaks zero-downtime secret rotation.** Checking only one secret causes valid in-flight webhooks signed with an outgoing or incoming secret to fail during **key rotation transition windows**.

**4 → Unhandled exceptions leak internal infrastructure and processor details.** Propagating unhandled exceptions back to the client exposes **stack traces, database schemas, and third-party error internals** in HTTP response bodies.

def verify_hmac_signature(raw_body: bytes, signature_header: str | None, secrets: List[str]) -> bool:
    """Verifies HMAC-SHA256 signature using constant-time comparison across active secrets."""
    if not signature_header:
        return False

    # Extract signature if header format is 't=...,v1=hash' or raw hash
    expected_hash = signature_header.split("v1=")[-1] if "v1=" in signature_header else signature_header

    for secret in secrets:
        computed_hash = hmac.new(
            key=secret.encode("utf-8"),
            msg=raw_body,
            digestmod=hashlib.sha256
        ).hexdigest()

        # Constant-time comparison prevents timing attacks
        if hmac.compare_digest(computed_hash, expected_hash):
            return True

    return False
