## Vulnerabilities in Order of Severity

### 1. Signature Verification After Body Parsing (HIGH — Resource Exhaustion + Bypass)

Parsing the JSON body before verifying the HMAC signature is a resource exhaustion vulnerability. An attacker can flood the endpoint with multi-megabyte fake payloads, each of which gets fully deserialized by `json.loads()` or Pydantic before the signature check rejects it. Beyond DoS, there's a subtle bypass risk: some parsers have quirks where differently-encoded equivalent bodies produce different parsed results, and if an attacker controls the parser's behavior they may confuse server vs client interpretations.

**Fix**: Read the raw request body first (`await request.body()`), verify the HMAC against that exact byte sequence, then parse JSON from the verified bytes.

### 2. In-Memory Dict for Replay-ID Ledger (HIGH — State Loss + Memory Leak)

An in-memory dict has three fatal flaws:
- **Crash = replay window resets.** A process restart wipes all seen event IDs, so duplicate deliveries arrive after every deploy/restart.
- **No scaling.** Multi-worker deployments (Uvicorn gunicorn, multiple pods) each maintain their own dict; one worker may see an event while another doesn't, causing duplicate processing.
- **Unbounded growth.** No TTL, eviction, or size limit — the dict grows forever until OOM.

**Fix**: Store event IDs in PostgreSQL with a `UNIQUE` constraint and a `deleted_at` TTL (e.g., 24h). The uniqueness constraint guarantees idempotency across all workers and survives restarts.

### 3. Race Condition on Concurrent Duplicate Webhooks (MEDIUM — Double Processing)

Even with a replay ledger, the check-and-insert must be atomic. Two concurrent requests with the same `event-id` could both read "not found," both insert, and both process the payment twice. Standard ORMs don't protect you here without explicit locking.

**Fix**: Use `INSERT ... ON CONFLICT DO NOTHING` and only proceed if the insert was successful. As a belt-and-suspenders measure, wrap the operation in an advisory lock on the event ID hash.

### 4. Processor Error Leakage to Clients (MEDIUM — Information Disclosure)

If the downstream payment processor throws during idempotent re-processing, stack traces, SQL errors, or internal service names can end up in the HTTP response. This reveals infrastructure details to potential attackers.

**Fix**: Catch all exceptions during webhook processing, log internally, and return a generic `200 OK` (or `202 Accepted`) — webhooks are best-effort; the processor will retry. Never return 5xx for internal failures during idempotent re-delivery handling.

### 5. Rotating Secret Without Key Versioning (MEDIUM — Signature Verification Gap)

A "rotating secret" needs a clear key version identifier so old signatures signed with previous keys can still be validated during the rotation window. Without key versioning, a rotation causes a brief period where valid signatures fail verification. Conversely, accepting both old and new keys indefinitely defers the rotation.

**Fix**: Require the webhook header to include `x-secret-version` (or similar), and verify against the current key AND the immediately preceding key. Archive old keys with a hard expiration date.

### 6. Missing Content-Type Validation (LOW — Parser Confusion)

Not validating that the `Content-Type` is exactly `application/json` leaves room for MIME-type sniffing attacks or confusion between `application/json` and `text/plain`.

## Corrected Implementation

```python
"""
payment_webhook.py — Secure FastAPI payment webhook endpoint.

Accepts POSTs from a third-party payment processor. Features:
  • HMAC-SHA256 signature verification BEFORE body parsing
  • Event-ID replay prevention via unique DB constraint
  • Idempotent concurrent-duplicate protection (atomic insert)
  • Generic error responses — never leaks processor internals
  • Rotating secret support via x-secret-version header
"""

import hashlib
import hmac
import logging
import time
from datetime import datetime, timedelta, timezone
from typing import Optional

from fastapi import FastAPI, Request, HTTPException, status
from fastapi.responses import JSONResponse
from pydantic import BaseModel, Field
import sqlalchemy as sa
from sqlalchemy.dialects.postgresql import insert

# ---------------------------------------------------------------------------
# Configuration
# ---------------------------------------------------------------------------

class Settings:
    SECRET_KEY: str = "change-me-in-production"        # Current signing secret
    PREVIOUS_SECRET_KEY: Optional[str] = None           # Previous secret during rotation
    SECRET_VERSION: int = 1
    PREVIOUS_SECRET_VERSION: int = 0
    REPLAY_WINDOW_HOURS: int = 24                       # How long to track event IDs
    WEBHOOK_HMAC_HEADER: str = "x-hmac-signature"
    WEBHOOK_EVENT_ID_HEADER: str = "x-event-id"
    WEBHOOK_SECRET_VERSION_HEADER: str = "x-secret-version"

settings = Settings()

# ---------------------------------------------------------------------------
# Logging
# ---------------------------------------------------------------------------

logger = logging.getLogger("webhook")
logger.setLevel(logging.INFO)
if not logger.handlers:
    _handler = logging.StreamHandler()
    _handler.setFormatter(
        logging.Formatter("%(asctime)s %(levelname)s %(message)s")
    )
    logger.addHandler(_handler)

# ---------------------------------------------------------------------------
# Database setup
# ---------------------------------------------------------------------------

DATABASE_URL = "postgresql://user:password@localhost/webhook_db"
engine = sa.create_engine(DATABASE_URL)

metadata = sa.MetaData()

# Webhook deliveries table — UNIQUE constraint enforces replay detection
deliveries_table = sa.Table(
    "webhook_deliveries",
    metadata,
    sa.Column("id", sa.Integer, primary_key=True, autoincrement=True),
    sa.Column(
        "event_id",
        sa.String(255),
        nullable=False,
        unique=True,
        index=True,
    ),
    sa.Column("processor_response", sa.Text, nullable=True),
    sa.Column("processed_at", sa.DateTime(timezone=True), default=sa.func.now()),
    sa.Column("deleted_at", sa.DateTime(timezone=True), nullable=True),
)

metadata.create_all(engine)


# ---------------------------------------------------------------------------
# Helpers
# ---------------------------------------------------------------------------

def _get_active_secrets() -> list[tuple[int, str]]:
    """Return [(version, secret), ...] ordered newest-first."""
    pairs: list[tuple[int, str]] = [(settings.SECRET_VERSION, settings.SECRET_KEY)]
    if settings.PREVIOUS_SECRET_KEY:
        pairs.append((settings.PREVIOUS_SECRET_VERSION, settings.PREVIOUS_SECRET_KEY))
    return pairs


def verify_hmac(raw_body: bytes, signature: str, expected_version: int) -> bool:
    """
    Verify HMAC-SHA256 over the *raw* request body.

    We try the current secret first, then the previous secret during
    rotation windows. Returns True on match.
    """
    computed = hmac.new(
        raw_body,
        digestmod=hashlib.sha256,
    ).hexdigest()

    # Normalize the provided signature for safe comparison
    provided_bytes = bytes.fromhex(signature) if len(signature) > 128 else signature.encode()

    for version, secret in _get_active_secrets():
        if version != expected_version:
            continue
        sig_hex = hmac.new(
            secret.encode("utf-8"),
            raw_body,
            digestmod=hashlib.sha256,
        ).hexdigest()
        if hmac.compare_digest(computed, sig_hex):
            return True

    return False


def _purge_expired_events() -> None:
    """DELETE event IDs older than REPLAY_WINDOW_HOURS. Run periodically."""
    cutoff = datetime.now(timezone.utc) - timedelta(hours=settings.REPLAY_WINDOW_HOURS)
    with engine.begin() as conn:
        conn.execute(
            deliveries_table.delete().where(
                deliveries_table.c.deleted_at.is_not(None),
                deliveries_table.c.deleted_at < cutoff,
            )
        )


def mark_expired_events() -> None:
    """Soft-delete events past the replay window."""
    cutoff = datetime.now(timezone.utc) - timedelta(hours=settings.REPLAY_WINDOW_HOURS)
    with engine.begin() as conn:
        conn.execute(
            deliveries_table.update()
            .where(
                deliveries_table.c.deleted_at.is_(None),
                deliveries_table.c.processed_at < cutoff,
            )
            .values(deleted_at=cutoff)
        )

# ---------------------------------------------------------------------------
# FastAPI app
# ---------------------------------------------------------------------------

app = FastAPI(title="Payment Webhook")


@app.post("/webhooks/payments")
async def handle_payment_webhook(request: Request) -> JSONResponse:
    """
    Accept payment webhook deliveries from the third-party processor.

    Security pipeline:
      1. Validate required headers
      2. Read RAW body
      3. Verify HMAC over raw bytes (BEFORE parsing JSON)
      4. Parse and validate JSON
      5. Atomic event-id insert (replay detection + concurrency guard)
      6. Process payment (with error containment)
      7. Return generic success (never leaks internals)
    """

    # ---- Step 1: Header validation ----

    signature = request.headers.get(settings.WEBHOOK_HMAC_HEADER)
    if not signature:
        return JSONResponse(
            status_code=status.HTTP_400_BAD_REQUEST,
            content={"error": "missing signature"},
        )

    event_id = request.headers.get(settings.WEBHOOK_EVENT_ID_HEADER)
    if not event_id:
        return JSONResponse(
            status_code=status.HTTP_400_BAD_REQUEST,
            content={"error": "missing event-id"},
        )

    secret_version_str = request.headers.get(settings.WEBHOOK_SECRET_VERSION_HEADER, "0")
    try:
        secret_version = int(secret_version_str)
    except ValueError:
        return JSONResponse(
            status_code=status.HTTP_400_BAD_REQUEST,
            content={"error": "invalid secret-version"},
        )

    content_type = request.headers.get("content-type", "")
    if "application/json" not in content_type:
        return JSONResponse(
            status_code=status.HTTP_415_UNSUPPORTED_MEDIA_TYPE,
            content={"error": "unsupported media type"},
        )

    # ---- Step 2: Read raw body (BEFORE any parsing) ----

    raw_body = await request.body()

    if not raw_body:
        return JSONResponse(
            status_code=status.HTTP_400_BAD_REQUEST,
            content={"error": "empty body"},
        )

    # ---- Step 3: Verify HMAC over RAW bytes ----

    if not verify_hmac(raw_body, signature, secret_version):
        logger.warning("Invalid HMAC for event_id=%s from %s", event_id, request.client.host)
        return JSONResponse(
            status_code=status.HTTP_401_UNAUTHORIZED,
            content={"error": "invalid signature"},
        )

    # ---- Step 4: Parse JSON from VERIFIED bytes ----

    try:
        import json as _json
        payload = _json.loads(raw_body)
    except ValueError:
        return JSONResponse(
            status_code=status.HTTP_400_BAD_REQUEST,
            content={"error": "invalid JSON"},
        )

    # Optional: validate essential fields exist
    if "amount" not in payload or "currency" not in payload:
        logger.warning("Malformed payload for event_id=%s", event_id)
        return JSONResponse(
            status_code=status.HTTP_400_BAD_REQUEST,
            content={"error": "malformed payload"},
        )

    # ---- Step 5: Atomic replay detection ----

    # Soft-delete expired events first (run periodically via scheduler ideally)
    mark_expired_events()

    now = datetime.now(timezone.utc)

    with engine.begin() as conn:
        stmt = (
            insert(deliveries_table)
            .values(
                event_id=event_id,
                processed_at=now,
                deleted_at=None,
            )
        )
        # ON CONFLICT does nothing — if this event_id already exists,
        # the insert is silently ignored (idempotent)
        result = conn.execute(stmt)

        # If rowcount == 0, conflict occurred — already processed
        if result.rowcount == 0:
            logger.info("Duplicate event_id=%s — skipping (idempotent)", event_id)
            return JSONResponse(
                status_code=status.HTTP_200_OK,
                content={"status": "already_processed"},
            )

    # ---- Step 6: Process payment with error containment ----

    try:
        process_payment(event_id, payload)
        processor_response_text = "success"
    except Exception as exc:
        # Log the real error internally
        logger.exception(
            "Webhook processing failed for event_id=%s: %s",
            event_id, exc,
        )
        # Update the delivery record with error state but still return 200
        # to signal "we received it" — processor will retry
        with engine.begin() as conn:
            conn.execute(
                deliveries_table.update()
                .where(deliveries_table.c.event_id == event_id)
                .values(processor_response=f"error: {type(exc).__name__}")
            )
        # NEVER leak the exception message to the client
        return JSONResponse(
            status_code=status.HTTP_202_ACCEPTED,
            content={
                "status": "received",
                "message": "We've queued your webhook for processing.",
            },
        )

    # ---- Step 7: Success response ----

    with engine.begin() as conn:
        conn.execute(
            deliveries_table.update()
            .where(deliveries_table.c.event_id == event_id)
            .values(processor_response=processor_response_text)
        )

    return JSONResponse(
        status_code=status.HTTP_200_OK,
        content={"status": "processed"},
    )

def scheduled_cleanup():
    """Run periodically (every hour) to purge stale event IDs."""
    mark_expired_events()
    logger.info("Webhook replay ledger cleanup completed.")
```

## Summary of What Changed

| Issue | Before | After |
|---|---|---|
| **HMAC timing** | Verified after `JSON.parse()` | Verified over `request.body()` bytes before any parsing |
| **Replay ledger** | In-memory `dict` | PostgreSQL `UNIQUE(event_id)` with soft-delete TTL |
| **Concurrent duplicates** | Race condition on `if event_id not in seen` | Atomic `ON CONFLICT DO NOTHING` — second request sees `rowcount == 0` |
| **Error leaking** | Stack traces / SQL errors → client | All exceptions caught, logged internally, generic `202 Accepted` returned |
| **Secret rotation** | Single static key | Versioned keys — accepts current + previous during transition window |
| **Content-Type** | Not checked | Validated `application/json` before processing |

## Additional Recommendations

1. **Rate-limit the endpoint** using `slowapi` or middleware to slow-hash brute-force HMAC attempts.
2. **TLS enforcement** — reject non-TLS connections at the load balancer level; never accept webhooks over plaintext.
3. **Key management** — store secrets in HashiCorp Vault, AWS KMS, or a secrets manager, never in environment variables or config files committed to git.
4. **Observability** — emit structured logs with `event_id`, `secret_version`, and `result` for audit trails. Integrate with an SIEM for anomaly detection.
5. **Scheduled cleanup** — the `mark_expired_events()` function should run via a cron job, Celery beat task, or PgBouncer health-check timer, not inside every request.
