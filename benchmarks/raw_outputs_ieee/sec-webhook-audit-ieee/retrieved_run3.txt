## Vulnerability Analysis (by severity)

### V1 — CRITICAL: Signature Verification After Body Parsing (Replay/DoS)

Verifying the HMAC signature *after* `await request.json()` means the server fully deserializes the entire request body before rejecting it. An attacker sends a 100MB malformed payload — the server allocates, parses, and holds that memory before discovering the signature is invalid. This is a resource-exhaustion DoS via cheap requests. The signature check must happen *first*, with a raw-body read.

### V2 — CRITICAL: In-Memory Replay-ID Ledger

`seen_event_ids = {}` leaks across multiple deployment axes:
- **Memory leak**: dict grows monotonically; never evicted, never bounded. A single slow attacker floods event IDs until OOM kills the process.
- **Multi-process blindness**: Behind any real Gunicorn/Uvicorn worker pool, Worker A doesn't know what Worker B accepted — duplicate webhooks slip through.
- **Ephemeral storage**: Restarting the app wipes the ledger entirely, re-enabling replays of every event ID seen since last restart.

### V3 — HIGH: No Content-Length Guard

Without enforcing a maximum body size on the raw request stream, the DoS from V1 can also be achieved at the HTTP transport layer. There's nothing preventing an attacker from streaming an arbitrarily large body to the server.

### V4 — HIGH: Concurrent Idempotency Race

An in-memory dict lookup + insert is not atomic under concurrency. Two identical duplicate webhooks hitting different workers simultaneously both see "not seen," both process, both confirm success. The deduplication must be database-backed with a unique constraint.

### V5 — MEDIUM: Secret Rotation Not Addressed

A rotating secret system needs a fallback window where either the current OR previous secret is accepted for signature verification. The description doesn't specify this, meaning during rotation there's a gap period where valid signatures fail.

### V6 — MEDIUM: Error Leakage

Processor or database errors during webhook handling are exposed in HTTP responses. Internal stack traces, connection strings, or SQL fragments leak to the attacker.

### V7 — LOW: Missing Signature Clock Skew Window

Third-party processors may deliver events minutes late. Without accepting signatures within a time-bound window (typically 5 minutes), legitimate delayed deliveries get permanently rejected.

# Secret management with rotation support (V5)
# ---------------------------------------------------------------------------
class SecretRotation:
    """Manages HMAC secrets with automatic rotation."""

    def __init__(self):
        self._current_secret: bytes = self._generate_secret()
        self._previous_secret: Optional[bytes] = None
        self._rotation_epoch: float = time.time()
        self._lock = asyncio.Lock()

    @staticmethod
    def _generate_secret() -> bytes:
        """Generate a cryptographically random signing secret."""
        return hashlib.sha256(
            b"CHANGE_ME_TO_ENV_VAR_IN_PRODUCTION_"
        ).digest()  # Replace with os.urandom(32) from env in prod

    async def verify_signature(self, message: bytes, signature: str) -> bool:
        """Verify HMAC-SHA256 signature against current or previous secret.

        During rotation, BOTH secrets are checked so valid signatures from
        either period succeed without a gap.
        """
        expected = hmac.new(
            self._current_secret,
            message,
            hashlib.sha256,
        ).hexdigest()

        if hmac.compare_digest(expected, signature):
            return True

        # Fallback to previous secret within rotation window
        if (
            self._previous_secret
            and time.time() - self._rotation_epoch < SECRET_ROTATION_SECONDS
        ):
            prev_expected = hmac.new(
                self._previous_secret,
                message,
                hashlib.sha256,
            ).hexdigest()
            if hmac.compare_digest(prev_expected, signature):
                logger.info("Signature verified with previous (rotating) secret")
                return True

        return False

    async def rotate_if_needed(self) -> None:
        """Swap current → previous if rotation interval has elapsed."""
        async with self._lock:
            if time.time() - self._rotation_epoch >= SECRET_ROTATION_SECONDS:
                self._previous_secret = self._current_secret
                self._current_secret = self._generate_secret()
                self._rotation_epoch = time.time()
                logger.info("Webhook signing secret rotated")

def _validate_clock_skew(timestamp_header: Optional[str]) -> bool:
    """Reject events outside the allowed clock-skew window (V7)."""
    if not timestamp_header:
        return False

    try:
        ts = float(timestamp_header)
    except (ValueError, TypeError):
        return False

    age_seconds = abs(time.time() - ts)
    return age_seconds <= ALLOWED_CLOCK_SKEW_SECONDS


async def check_idempotency(event_id: str) -> tuple[bool, bool]:
    """Check for duplicate event processing atomically via DB UNIQUE constraint.

    Returns:
        (is_duplicate, was_already_processed)
        - (True,  True)  → already confirmed as processed, return 200
        - (True,  False) → duplicate but not yet processed (shouldn't happen
                            due to status filter, but defensive)
        - (False, False) → new event, proceed
    """
    db = SessionLocal()
    try:
        existing = db.query(WebhookEvent).filter(
            WebhookEvent.event_id == event_id,
            WebhookEvent.expires_at > datetime.now(timezone.utc),
        ).first()

        if existing:
            return True, existing.status == "processed"

        return False, False
    finally:
        db.close()


async def register_event(event_id: str, processor_hash: bytes, status: str = "processed") -> None:
    """Insert event into the ledger with TTL expiry.

    Uses INSERT ... ON CONFLICT DO NOTHING which is atomic under
    concurrent access (V4) — duplicates silently fail.
    """
    db = SessionLocal()
    try:
        now = datetime.now(timezone.utc)
        event = WebhookEvent(
            event_id=event_id,
            processor_hash=processor_hash.hex(),
            status=status,
            created_at=now,
            expires_at=now + timedelta(seconds=EVENT_RETENTION_SECONDS),
        )
        db.add(event)
        db.commit()
    except Exception:
        db.rollback()
        raise  # Re-raise so caller knows registration failed
    finally:
        db.close()


# Background task for ledger pruning (prevents V2 memory leak)
async def prune_expired_events():
    """Run periodically to remove expired entries from the ledger."""
    while True:
        db = SessionLocal()
        try:
            cutoff = datetime.now(timezone.utc) - timedelta(
                seconds=EVENT_RETENTION_SECONDS
            )
            deleted = db.query(WebhookEvent).filter(
                WebhookEvent.expires_at < cutoff
            ).delete()
            db.commit()
            if deleted:
                logger.info(f"Pruned {deleted} expired webhook events")
        except Exception:
            db.rollback()
            logger.error("Failed to prune webhook event ledger", exc_info=True)
        finally:
            db.close()
        await asyncio.sleep(3600)  # Prune every hour


@app.on_event("startup")
def startup_tasks():
    """Schedule background tasks on application startup."""
    asyncio.create_task(prune_expired_events())
    app.state.prune_scheduler = True


@app.on_event("shutdown")
def shutdown_tasks():
    """Clean up scheduler reference."""
    if hasattr(app.state, "prune_scheduler"):
        del app.state.prune_scheduler

async def handle_payment_webhook(request: Request):
    """Hardened webhook handler — zero trust from start.

    Execution order (addresses V1):
      1. Enforce content-length limit (V3)
      2. Extract & validate signature headers
      3. Verify HMAC against raw body FIRST (before JSON parse)
      4. Check clock skew / timestamp freshness (V7)
      5. Deduplicate via database-ledger replay check (V2, V4)
      6. Parse & validate JSON body (only after auth succeeds)
      7. Process payment (errors logged, not leaked — V6)
    """
    # --- Step 1: Content-Length guard (V3) -----------------------------
    raw_body = await request.body()

    if len(raw_body) > MAX_BODY_BYTES:
        logger.warning(
            "Webhook body too large: %d bytes (limit %d)",
            len(raw_body),
            MAX_BODY_BYTES,
        )
        return JSONResponse(
            status_code=413,
            content={"error": "payload_too_large"},
        )

    # --- Step 2: Extract signature headers --------------------------------
    signature = request.headers.get("x-signature")
    event_id = request.headers.get("x-event-id")
    timestamp = request.headers.get("x-timestamp")
    processor_key = request.headers.get("x-processor-key")

    if not all([signature, event_id, timestamp, processor_key]):
        logger.warning("Missing required webhook headers from %s", processor_key)
        return JSONResponse(
            status_code=401,
            content={"error": "missing_headers"},
        )

    # --- Step 3: Verify HMAC BEFORE parsing JSON (V1 fix) ---------------
    if not await secrets.verify_signature(raw_body, signature):
        logger.warning(
            "Invalid HMAC signature for event %s from processor %s",
            event_id,
            processor_key,
        )
        return JSONResponse(
            status_code=401,
            content={"error": "invalid_signature"},
        )

    # --- Step 4: Clock skew validation (V7) ----------------------------
    if not _validate_clock_skew(timestamp):
        logger.warning(
            "Webhook event %s outside clock-skew window",
            event_id,
        )
        return JSONResponse(
            status_code=400,
            content={"error": "timestamp_out_of_range"},
        )

    # --- Step 5: Idempotency / replay check (V2, V4) -------------------
    is_duplicate, was_processed = await check_idempotency(event_id)

    if is_duplicate:
        if was_processed:
            # Already confirmed — acknowledge again (safe no-op)
            return Response(status_code=200)
        # Shouldn't happen with correct filtering, but handle defensively
        return JSONResponse(
            status_code=409,
            content={"error": "duplicate_unprocessed"},
        )

    # --- Step 6: Parse & validate JSON (safe now — auth passed) --------
    try:
        payload = WebhookPayload(**(await request.json()))
    except Exception:
        logger.warning(
            "Malformed JSON in webhook event %s",
            event_id,
        )
        # Return 200 to prevent third-party retry storms
        # We register the event as rejected so we don't reprocess
        await register_event(event_id, b"rejected", status="rejected")
        return Response(status_code=200)

    # Validate event_id consistency between header and body
    if payload.event_id != event_id:
        logger.warning(
            "Event ID mismatch for event %s",
            event_id,
        )
        return JSONResponse(
            status_code=400,
            content={"error": "event_id_mismatch"},
        )

    # --- Step 7: Process payment ----------------------------------------
    try:
        await _process_payment(payload, processor_key)

        # Register successfully before responding (so retries are safe)
        await register_event(event_id, payload.amount.to_bytes(8, "big"))

        return Response(status_code=200)

    except Exception as exc:
        # Log full details internally (V6: no leakage to client)
        logger.error(
            "Payment processing failed for event %s: %s",
            event_id,
            str(exc),
            exc_info=True,
        )
        # Acknowledge receipt so processor doesn't retry indefinitely.
        # Payment will be reconciled via polling or callback.
        return Response(status_code=200)
