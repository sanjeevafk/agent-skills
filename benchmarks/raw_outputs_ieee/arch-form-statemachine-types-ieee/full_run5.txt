## BEFORE — The Broken Pattern

```typescript
// ❌ All form data collapses to any — zero shape enforcement
type FormState = any;

// ❌ Any string is a valid "status" — no domain vocabulary encoded
type Status = string;

interface RawAction {
  type: Status;     // could be 'FOOBAR' or 'SUBMIT_STEP_7'
  step: number;     // unlinked from what data should exist
  payload: any;     // accepts garbage
}

function reduce(state: FormState, action: RawAction): FormState {
  // ❌ Hand-wave implementation assembled at runtime
  return { ...state, ...action.payload };
}

// These all compile but crash at runtime:
reduce(undefined, { type: 'RANDOM', step: 99, payload: null });       // ✅ compiles 💥
reduce({ status: 2 }, { type: 'SUBMIT', step: 2, dirty: true });      // ✅ submits incomplete step 2!
dispatch({ type: 'GO_BACK', step: 3 });                                // ✅ retreats past confirmed payment!
```

## AFTER — Exhaustive Type-Safe State Machine

### 1. Branded / Opaque IDs

Uses the `unique symbol` technique to create nominal types on top of primitive bases. `UserId` and `OrderId` share the same runtime representation (`string`) but are structurally incompatible at compile time.

```typescript
declare const UserIdBrand: unique symbol;
declare const OrderIdBrand: unique symbol;

type UserId = string & { readonly [UserIdBrand]: true };
type OrderId = string & { readonly [OrderIdBrand]: true };

const UserId = (s: string): UserId => s as UserId;
const OrderId = (s: string): OrderId => s as OrderId;

// Usage proof: these are NOT interchangeable
function getOrders(userId: UserId): OrderId[] {
  return []; // in real code: fetch orders for this userId
}

getOrders(UserId('u-123'));           // ✅ OK
getOrders(OrderId('o-456'));          // ⛔ TS2345: OrderId is not assignable to UserId
                                        //   "Property '[OrderIdBrand]' is missing in type '[UserIdBrand]'"
```

### 2. Per-Step Data Interfaces

Clean interfaces — one per domain concept. No `any`, no loose typing.

```typescript
interface UserInfo {
  name: string;
  email: string;
  phone?: string;
}

interface ShippingInfo {
  street: string;
  city: string;
  postalCode: string;
  country: string;
}

interface PaymentInfo {
  token: string;            // PCI-compliant token, never raw card data
  lastFour: string;
  brand: 'visa' | 'mastercard' | 'amex';
}

interface OrderSummary {
  items: ReadonlyArray<{ sku: string; qty: number; unitPrice: number }>;
  subtotal: number;
  tax: number;
  total: number;
}
```

### 3. Discriminated Union: The State

Each variant encodes **which step** we're on, **what data is available**, and **what state it's in** (dirty/finalized/locked). This replaces `any` with a finite set of well-defined shapes.

```typescript
type WizardState =
  // ── STEP 1: Collect user info ────────────────────────────────
  | { readonly _t: 'step/user-info';    readonly user: Partial<UserInfo> }

  // ── STEP 2A: Shipping draft (DIRTY — unsaved changes) ────────
  | { readonly _t: 'step/shipping-draft'; readonly user: UserInfo; readonly shipping: null }

  // ── STEP 2B: Shipping committed (clean — safe to proceed) ────
  | { readonly _t: 'step/shipping-done'; readonly user: UserInfo; readonly shipping: ShippingInfo }

  // ── STEP 3A: Payment collecting ──────────────────────────────
  | { readonly _t: 'step/payment-collecting'; readonly user: UserInfo; readonly shipping: ShippingInfo; readonly payment: null }

  // ── STEP 3B: Payment CONFIRMED (⚠️ LOCKED — no retreat allowed) ──
  | { readonly _t: 'step/payment-confirmed'; readonly user: UserInfo; readonly shipping: ShippingInfo; readonly payment: PaymentInfo; readonly paid: true }

  // ── STEP 4: Review & Submit ──────────────────────────────────
  | { readonly _t: 'step/review'; readonly user: UserInfo; readonly shipping: ShippingInfo; readonly payment: PaymentInfo; readonly summary: OrderSummary };
```

Plain-English reading: *The wizard has exactly six mutually exclusive states, tagged by `_t`. Switching on `_t` narrows to one shape with well-defined fields — no more guessing whether `shipping` is `null`, undefined, or populated.*

### 4. Conditional Action Types

This is where the type system enforces **valid transitions only**. Each state variant maps to a specific subset of actions via conditional types. Invalid transitions don't have corresponding action types — they literally cannot be constructed.

```typescript
type Action<S extends WizardState> =
  S extends { readonly _t: 'step/user-info' }
    ?
        | { readonly _a: 'fill-info'; readonly payload: UserInfo }
        | { readonly _a: 'commit-user' }
    : S extends { readonly _t: 'step/shipping-draft' }
      ?
          | { readonly _a: 'fill-shipping'; readonly payload: ShippingInfo }
          | { readonly _a: 'commit-shipping' }
          // ⛔ NO 'advance-to-payment' here — must commit shipping first!
      : S extends { readonly _t: 'step/shipping-done' }
        ?
            | { readonly _a: 'go-back' }
            | { readonly _a: 'advance-to-payment' }
      : S extends { readonly _t: 'step/payment-collecting' }
        ?
            | { readonly _a: 'go-back' }
            | { readonly _a: 'enter-payment'; readonly payload: PaymentInfo }
      : S extends { readonly _t: 'step/payment-confirmed' }
        ?
            | { readonly _a: 'advance-to-review' }
            // ⛔ NO 'go-back' here — payment locked, no retreat!
        : S extends { readonly _t: 'step/review' }
          ?
              | { readonly _a: 'submit-order' }
          : never;
```

Plain-English reading: *"Given current state S, what actions can I dispatch? If S is 'shipping-draft', only fill-shipping and commit-shipping are valid — skip-ahead is impossible. If S is 'payment-confirmed', only advance-to-review is valid — go-back doesn't exist in this branch."*

### 5. Exhaustiveness Enforcement (the `never` check)

Two levels of exhaustiveness: outer switch covers every state tag; inner switch covers every action for that state. The `assertNever` helper catches gaps during development.

```typescript
function assertNever(value: never, msg?: string): never {
  throw new Error(msg ?? `Invariant violated: expected never, got ${value}`);
}

function dispatch<S extends WizardState>(
  state: S,
  action: Action<S>,
): WizardState {
  switch (state._t) {
    case 'step/user-info': {
      switch ((action as { readonly _a: string })._a) {
        case 'fill-info':
          return { _t: state._t, user: { ...state.user, ...action.payload } };
        case 'commit-user': {
          const { name, email } = state.user;
          if (!name || !email) throw new Error('Name and email required');
          return {
            _t: 'step/shipping-draft',
            user: state.user as UserInfo,
            shipping: null,
          };
        }
        default:
          return assertNever(action, `No handler for ${action._a} in user-info`);
      }
    }

    case 'step/shipping-draft': {
      switch ((action as { readonly _a: string })._a) {
        case 'fill-shipping':
          return { _t: state._t, user: state.user, shipping: action.payload };
        case 'commit-shipping': {
          if (!action.payload) throw new Error('Cannot commit empty shipping');
          return {
            _t: 'step/shipping-done',
            user: state.user,
            shipping: action.payload,
          };
        }
        default:
          return assertNever(action, `No handler for ${action._a} in shipping-draft`);
      }
    }

    case 'step/shipping-done': {
      switch ((action as { readonly _a: string })._a) {
        case 'go-back':
          return { _t: 'step/user-info', user: state.user };
        case 'advance-to-payment':
          return {
            _t: 'step/payment-collecting',
            user: state.user,
            shipping: state.shipping,
            payment: null,
          };
        default:
          return assertNever(action, `No handler for ${action._a} in shipping-done`);
      }
    }

    case 'step/payment-collecting': {
      switch ((action as { readonly _a: string })._a) {
        case 'go-back':
          return { _t: 'step/shipping-done', user: state.user, shipping: state.shipping };
        case 'enter-payment':
          return {
            _t: 'step/payment-confirmed',
            user: state.user,
            shipping: state.shipping,
            payment: action.payload,
            paid: true,
          };
        default:
          return assertNever(action, `No handler for ${action._a} in payment-collecting`);
      }
    }

    case 'step/payment-confirmed': {
      switch ((action as { readonly _a: string })._a) {
        case 'advance-to-review':
          return buildReview(state);
        default:
          return assertNever(action, `No handler for ${action._a} in payment-confirmed`);
      }
    }

    case 'step/review': {
      switch ((action as { readonly _a: string })._a) {
        case 'submit-order':
          return finishOrder(state);
        default:
          return assertNever(action, `No handler for ${action._a} in review`);
      }
    }

    default:
      return assertNever(state, `Unreachable state tag: ${(state as { _t: string })._t}`);
  }
}

function buildSummary(s: WizardState & { _t: 'step/payment-confirmed' }): OrderSummary {
  return {
    items: [], // derived from session/cart — pseudo-code
    subtotal: 0,
    tax: 0,
    total: 0,
  };
}

function buildReview(
  s: WizardState & { _t: 'step/payment-confirmed' },
): WizardState['step'] {
  return { _t: 'step/review', user: s.user, shipping: s.shipping, payment: s.payment, summary: buildSummary(s) };
}

function finishOrder(s: WizardState & { _t: 'step/review' }): WizardState {
  return {
    _t: 'step/review',
    user: s.user,
    shipping: s.shipping,
    payment: s.payment,
    summary: s.summary,
    // transition to final state... omitted for brevity
  };
}
```

Plain-English reading: *Every state/action combination has a handler. The `default` clause in each inner switch receives type `never` — if you add a new action without adding a case, TypeScript errors. The final `default` catches any state tags we forgot.*

### 6. Utility Types (using `infer`)

Extract information from the type system for downstream use — validation schemas, API contracts, etc.

```typescript
// Extract payload type from an action using `infer`
type Payload<A> = A extends { readonly payload: infer P } ? P : never;

// Usage: extract what kind of data each action expects
type FillInfoPayload   = Payload<Extract<Action<WizardState>, { readonly _a: 'fill-info' }>>;
// Result: UserInfo ✓

type EnterPaymentPayload = Payload<Extract<Action<WizardState>, { readonly _a: 'enter-payment' }>>;
// Result: PaymentInfo ✓
```

## COMPILE-TIME PROOFS OF INVALID TRANSITIONS

### Proof 1: Cannot submit while Step 2 (shipping) is dirty

```typescript
// Attempt to bypass the commit-shipping gate:
{
  const dirtyShipping: WizardState = {
    _t: 'step/shipping-draft',
    user: { name: 'Alice', email: 'a@b.com' },
    shipping: null,               // DIRTY — no shipping data yet
  };

  // Try to jump straight to payment without committing:
  dispatch(dirtyShipping, { _a: 'advance-to-payment' });
  // ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  //
  // TS2345: Argument of type '{ readonly _a: "advance-to-payment"; }'
  //   is not assignable to parameter of type
  //   '{ readonly _a: "fill-shipping"; readonly payload: ShippingInfo; } |
  //    { readonly _a: "commit-shipping"; }'.
  //
  // Why it fails: Action<S> for the shipping-draft state resolves to
  // fill-shipping | commit-shipping ONLY. The literal type
  // '"advance-to-payment"' does not unify with '"fill-shipping"' or
  // '"commit-shipping"', so the union discriminant rejects it.
  //
  // The type system FORCES the path: ship-draft → fill-shipping →
  // commit-shipping → ship-done → advance-to-payment.
  // There is no action type that represents "skip shipping commitment."
}
```

**Mechanism**: The conditional type `Action<S>` returns a different union for each state branch. When `S` is `'shipping-draft'`, the union contains exactly `{ fill-shipping } | { commit-shipping }`. The value `'advance-to-payment'` is simply not a member of that union — it's absent from the type definition entirely. Not a suppression, not a cast, not a runtime check — a structural absence.

### Proof 2: Cannot retreat after payment confirmed

```typescript
// Attempt to go back once payment is locked:
{
  const paidConfirmed: WizardState = {
    _t: 'step/payment-confirmed',
    user: { name: 'Alice', email: 'a@b.com' },
    shipping: { street: '123 Main', city: 'Boston', postalCode: '02101', country: 'US' },
    payment: { token: 'tok_visa', lastFour: '4242', brand: 'visa' },
    paid: true,                    // LOCKED
  };

  // Try to retreat:
  dispatch(paidConfirmed, { _a: 'go-back' });
  // ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  //
  // TS2322: Type '"go-back"' is not assignable to type '"advance-to-review"'.
  //
  // Why it fails: Action<S> for the payment-confirmed state resolves to
  // { advance-to-review } — a single-element union. The literal '"go-back"'
  // is structurally different from '"advance-to-review"', so assignment fails.
  //
  // Once paid: true flows through the type, retreat is erased from the
  // action space. The consumer has no access to a go-back action in this
  // state, period.
}
```

**Mechanism**: The state `'step/payment-confirmed'` is deliberately given an action set containing only `advance-to-review`. Compare this to `'step/payment-collecting'` which includes `go-back`. The difference is encoded directly in the conditional chain — no boolean flag needed to gate behavior. The type itself tells the story: "this phase is irreversible."

## Techniques Used

| Technique | Where Applied |
|---|---|
| **Conditional Types** | `Action<S>` — branches to different action sets depending on which state variant `S` matches |
| **Discriminated Unions** | `WizardState` — `_t` discriminant ensures compile-time narrowing to one shape with known fields |
| **Branded/Opaque Types** | `UserId`, `OrderId` — `unique symbol` creates nominally distinct types over `string` |
| **`infer` Keyword** | `Payload<A>` — extracts the `payload` type from any action shape |
| **`never` Exhaustiveness** | `assertNever` in every `default:` case — adds a regression guard when new actions/states are introduced |
