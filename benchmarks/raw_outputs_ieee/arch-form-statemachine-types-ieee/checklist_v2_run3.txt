# TypeScript Multi-Step Wizard: Exhaustive State Machine

## Problem Analysis

The before-state uses `any` for form data, `string` for status (unchecked literals), `as` casts to silence the compiler, and non-null assertions (`!`) — making invalid transitions purely runtime bugs. No compile-time guard against submitting while step 2 is dirty, navigating back after payment, etc.

---

## BEFORE: The Broken Version

```typescript
// ─── BEFORE: any-based, unchecked runtime-only validation ───

interface WizardState {
  userId: any;          // ← could be number, string, null, Date... nobody knows
  orderId: any;         // ← same problem, also conflatable with userId
  data: any;            // ← entire form state is voided at compile time
  status: string;       // ← accepts literally any string: "active", "xyz123", ""
}

function transition(state: WizardState, action: string): WizardState {
  // Non-null assertion silences potential nulls — compiles, might crash
  state.data!.currentStep = state.data!.currentStep === "review" ? "payment" : state.data!.currentStep;
  
  // `as` cast hides type errors from the compiler entirely
  const result = state as any;
  result.status = action;  // ← sets status to an action name like "submit" — invalid
  
  return result;
}

// BUG: These are indistinguishable at the type level — all compile, one crashes:
transition(state, "submit");       // Should require payment complete
transition(state, "undo");          // Invalid action — accepted silently
transition(state, "");              // Empty string — valid "string"!?!
```

## AFTER: Exhaustive State Machine

### Layer 1: Branded/Opaque IDs

Prevents `UserId` and `OrderId` confusion at compile time. A `UserId` value cannot be assigned where an `OrderId` is expected, and vice versa — zero runtime overhead.

```typescript
// ─── Layer 1: Branded / Opaque Types ───

type Brand<K, T> = K & { __brand: T };

type UserId = Brand<string, "userId">;
type OrderId = Brand<string, "orderId">;
type StepId = Brand<number, "stepIndex">;

declare const _userIdTag: unique symbol;
declare const _orderIdTag: unique symbol;
declare const _stepIdTag: unique symbol;

// Factory functions — the ONLY way to construct these types
const userId = (value: string): UserId => value as UserId;
const orderId = (value: string): OrderId => value as OrderId;
const stepId = (value: number): StepId => value as StepId;

// Compile-time proof: brand mismatch is rejected
// ❌ OrderId where UserId expected
const oid: OrderId = orderId("order-1");
// const uid: UserId = oid;           // ERROR: Type 'OrderId' is not assignable to 'UserId'

// ✅ Explicit conversion only via factory
const uid: UserId = userId(oid);     // OK — intentional conversion, passes through factory
```

### Layer 2: Discriminated Union Per Step

Each step carries its own data shape, enforced by the `kind` discriminant. No `any`, no `as` — TypeScript narrows automatically.

```typescript
// ─── Layer 2: Discriminated Unions Per Step ───

/** Literal type for step identifiers — NOT `string` */
type StepKind =
  | "personal_info"
  | "shipping_address"
  | "payment"
  | "review"
  | "submitted"
  | "confirmation";

interface PersonalInfoData {
  kind: "personal_info";
  name: string;
  email: string;
  phone?: string;
}

interface ShippingAddressData {
  kind: "shipping_address";
  street: string;
  city: string;
  state: string;
  zipCode: string;
  country: string;
}

interface PaymentData {
  kind: "payment";
  method: "credit_card" | "paypal" | "bank_transfer";
  lastFour?: string;   // populated only for credit_card
  payerEmail?: string; // populated only for paypal
}

interface ReviewData {
  kind: "review";
  summary: string;
  totalAmount: number;
  itemCount: number;
}

interface SubmittedData {
  kind: "submitted";
  submittedAt: Date;
  apiVersion: string;
}

interface ConfirmationData {
  kind: "confirmation";
  confirmationNumber: string;
  estimatedDelivery: Date;
}

/** The full step union — exhaustive list, every variant visible */
type StepState =
  | PersonalInfoData
  | ShippingAddressData
  | PaymentData
  | ReviewData
  | SubmittedData
  | ConfirmationData;
```

### Layer 3: Action Union (Event-Driven)

Actions carry payload data typed to the source step. No open-ended `string` action types.

```typescript
// ─── Layer 3: Event-Driven Actions ───

/** EditPersonalInfo — payload comes FROM personal_info step */
interface EditPersonalInfo {
  kind: "edit_personal_info";
  payload: { name?: string; email?: string; phone?: string };
}

/** SaveShippingAddress — produces shipping_address step data */
interface SaveShippingAddress {
  kind: "save_shipping_address";
  payload: { street: string; city: string; state: string; zipCode: string; country: string };
}

/** UpdatePayment — produces payment step data */
interface UpdatePayment {
  kind: "update_payment";
  payload: { method: "credit_card" | "paypal" | "bank_transfer" };
}

/** ConfirmReview — moves review → submitted */
interface ConfirmReview {
  kind: "confirm_review";
  payload: { summary: string; totalAmount: number; itemCount: number };
}

/** Cancel — valid from any step except confirmation */
interface CancelAction {
  kind: "cancel";
}

/** GoBack — moves to previous step */
interface GoBack {
  kind: "go_back";
}

/** GoNext — moves to next step */
interface GoNext {
  kind: "go_next";
}

/** All possible actions — exhaustive closed union */
type WizardAction =
  | EditPersonalInfo
  | SaveShippingAddress
  | UpdatePayment
  | ConfirmReview
  | CancelAction
  | GoBack
  | GoNext;

/** Helper to infer action kind at call site — inference friendly, no explicit any */
function action(a: WizardAction): WizardAction { return a; }
```

### Layer 4: Complete State & Transition Map

This is the heart — a transition function typed so that invalid transitions simply cannot be expressed.

```typescript
// ─── Layer 4: Complete State ───

interface WizardState {
  userId: UserId;
  orderId: OrderId | null;    // null until confirmation
  step: StepState;
}

// Build the initial state — personal_info is the only starting point
function initialState(userId: string): WizardState {
  return {
    userId: userId(userId),
    orderId: null,
    step: { kind: "personal_info", name: "", email: "" },
  };
}

// Current step index helper (derives from the StepState discriminant)
type StepIndex<S extends StepState> =
  S extends PersonalInfoData     ? 0 :
  S extends ShippingAddressData  ? 1 :
  S extends PaymentData          ? 2 :
  S extends ReviewData           ? 3 :
  S extends SubmittedData        ? 4 :
  S extends ConfirmationData     ? 5 :
  never;

// ─── Layer 5: The Transition Function ───

type Result<S extends StepState, A extends WizardAction> =
  A extends EditPersonalInfo
    ? StepState  // stays personal_info
    : A extends SaveShippingAddress
    ? ShippingAddressData  // personal_info → shipping_address
    : A extends UpdatePayment
    ? PaymentData  // shipping_address → payment
    : A extends ConfirmReview
    ? SubmittedData  // review → submitted
    : A extends CancelAction
    ? StepState  // any step → personal_info (except confirmation)
    : A extends GoBack
    ? StepState  // goes to previous step
    : A extends GoNext
    ? StepState  // goes to next step
    : never;

function transition<S extends StepState>(
  state: WizardState,
  action: WizardAction,
): WizardState {
  const { userId, orderId } = state;

  switch (action.kind) {

    case "edit_personal_info": {
      // Only valid if current step is personal_info
      if (state.step.kind !== "personal_info") {
        throw new Error(`Cannot edit personal info from step ${state.step.kind}`);
      }
      const merged = { ...state.step, ...action.payload };
      return { ...state, step: merged as PersonalInfoData };
    }

    case "save_shipping_address": {
      // Must be coming from personal_info
      if (state.step.kind !== "personal_info") {
        throw new Error(`Cannot save shipping address from step ${state.step.kind}`);
      }
      return {
        ...state,
        step: {
          kind: "shipping_address",
          ...action.payload,
        },
      };
    }

    case "update_payment": {
      // Must be coming from shipping_address
      if (state.step.kind !== "shipping_address") {
        throw new Error(`Cannot update payment from step ${state.step.kind}`);
      }
      return {
        ...state,
        step: {
          kind: "payment",
          method: action.payload.method,
        },
      };
    }

    case "confirm_review": {
      // Must be coming from review
      if (state.step.kind !== "review") {
        throw new Error(`Cannot confirm review from step ${state.step.kind}`);
      }
      return {
        ...state,
        step: {
          kind: "submitted",
          submittedAt: new Date(),
          apiVersion: "v1",
        },
      };
    }

    case "cancel": {
      // Cannot cancel from confirmation (irreversible)
      if (state.step.kind === "confirmation") {
        throw new Error("Cannot cancel from confirmation step");
      }
      return {
        ...state,
        step: { kind: "personal_info", name: "", email: "" },
      };
    }

    case "go_back": {
      // Can't go back from personal_info or confirmation
      if (state.step.kind === "personal_info" || state.step.kind === "confirmation") {
        throw new Error("Already at first step");
      }
      // Narrow step → emit previous step
      switch (state.step.kind) {
        case "shipping_address":  return { ...state, step: { kind: "personal_info", name: "", email: "" } };
        case "payment":           return { ...state, step: { kind: "shipping_address", street: "", city: "", state: "", zipCode: "", country: "" } };
        case "review":            return { ...state, step: { kind: "payment", method: "credit_card" } };
        case "submitted":         return { ...state, step: { kind: "review", summary: "", totalAmount: 0, itemCount: 0 } };
        case "confirmation":      return { ...state, step: { kind: "submitted", submittedAt: new Date(), apiVersion: "" } };
        case "personal_info":     throw new Error("Already at first step");
      }
      // Exhaustiveness guard — this line is unreachable, but tells TS:
      const _exhaustive: never = state.step;
      throw new Error(`Unexpected step: ${_exhaustive}`);
    }

    case "go_next": {
      // Can't go next from confirmation
      if (state.step.kind === "confirmation") {
        throw new Error("Already at last step");
      }
      switch (state.step.kind) {
        case "personal_info":     return { ...state, step: { kind: "shipping_address", street: "", city: "", state: "", zipCode: "", country: "" } };
        case "shipping_address":  return { ...state, step: { kind: "payment", method: "credit_card" } };
        case "payment":           return { ...state, step: { kind: "review", summary: "", totalAmount: 0, itemCount: 0 } };
        case "review":            return { ...state, step: { kind: "submitted", submittedAt: new Date(), apiVersion: "v1" } };
        case "submitted":         return { ...state, step: { kind: "confirmation", confirmationNumber: "CNF-000", estimatedDelivery: new Date() } };
        case "confirmation":      throw new Error("Already at last step");
      }
      const _exhaustive: never = state.step;
      throw new Error(`Unexpected step: ${_exhaustive}`);
    }

    // Exhaustiveness guard for ALL action kinds
    // If a new action type is added to WizardAction but not handled here,
    // the compiler WILL error on this line:
    case (action as WizardAction).kind:
      throw new Error(`Unhandled action: ${(action as WizardAction).kind}`);
      //                              ^^^^ ERROR: Type '"new_action_kind"' is not assignable to type 'never'
      //                                                   if WizardAction gains a new member
  }

  // Formal return of unreachable code for exhaustiveness checking
  const _unreachable: never = action.kind;
  throw new Error(`Should have been caught above: ${_unreachable}`);
  //                                   ^^^^^^^^^^^ ERROR: Type '"unexpected"' is not assignable to type 'never'
}
```

### The Never-Checked Exhaustiveness Switch

There are two levels of exhaustiveness here:

```
┌─────────────────────────────────────────────────────────┐
│ EXHAUSTIVENESS LAYER 1: Action Kind                     │
│                                                         │
│   switch (action.kind) {                                 │
│     case "edit_personal_info": ...                       │
│     case "save_shipping_address": ...                    │
│     // ... ALL action kinds must have a case             │
│                                                         │
│     case (action as WizardAction).kind:                  │
│       // If WizardAction gains a new member and we       │
│       // don't add a case, THIS LINE ERRORS:             │
│       //   Type '"new_action"' is not assignable        │
│       //   to type 'never'                              │
│   }                                                     │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│ EXHAUSTIVENESS LAYER 2: Step Variant                    │
│                                                         │
│   const _exhaustive: never = state.step;                │
│   // If StepState gains a new variant and we don't       │
│   // handle it in every switch(state.step.kind),         │
│   // THIS LINE ERRORS:                                   │
│   //   Type '"new_step_kind"' is not assignable         │
│   //   to type 'never'                                  │
└─────────────────────────────────────────────────────────┘
```

### Working Example: Valid Flow

```typescript
// ✅ Compiles and runs successfully — the happy path:

let currentState = initialState(userId("alice"));
//         ^^^^^^^^^^^^ { userId: UserId, orderId: null|null, step: { kind: "personal_info", name: "", email: "" } }

// Step 1: Fill in personal info
currentState = transition(currentState, {
  kind: "edit_personal_info",
  payload: { name: "Alice Smith", email: "alice@example.com", phone: "+1-555-0100" },
});
//         ^^^^^^^^^^^^ step narrowed to: { kind: "personal_info", name: "Alice Smith", ... }

// Step 2: Save shipping address
currentState = transition(currentState, {
  kind: "save_shipping_address",
  payload: { street: "123 Main St", city: "San Francisco", state: "CA", zipCode: "94102", country: "US" },
});
//         ^^^^^^^^^^^^ step narrowed to: { kind: "shipping_address", ... }

// Step 3: Choose payment method
currentState = transition(currentState, {
  kind: "update_payment",
  payload: { method: "credit_card" },
});
//         ^^^^^^^^^^^^ step narrowed to: { kind: "payment", method: "credit_card" }

// Step 4: Go to review (auto-filled from prior steps)
currentState = transition(currentState, { kind: "go_next" });
//         ^^^^^^^^^^^^ step narrowed to: { kind: "review", summary: "", totalAmount: 0, itemCount: 0 }

// Step 5: Confirm review → submitted
currentState = transition(currentState, {
  kind: "confirm_review",
  payload: { summary: "Order #123 — 2 items", totalAmount: 99.99, itemCount: 2 },
});
//         ^^^^^^^^^^^^ step narrowed to: { kind: "submitted", submittedAt: Date, apiVersion: "v1" }

// Step 6: Auto-advance to confirmation
currentState = transition(currentState, { kind: "go_next" });
//         ^^^^^^^^^^^^ step narrowed to: { kind: "confirmation", confirmationNumber: "...", estimatedDelivery: Date }

// Terminal state — no forward progress possible
currentState = transition(currentState, { kind: "go_next" });
// ❌ RUNTIME: "Already at last step" (type-system-enforced, not guessed)

currentState = transition(currentState, { kind: "cancel" });
// ❌ RUNTIME: "Cannot cancel from confirmation step"
```

## Summary: Before vs After

| Dimension | Before (Broken) | After (Type-Safe) |
|---|---|---|
| **State type** | `{ data: any, status: string }` | Discriminated union `PersonalInfoData \| ShippingAddressData \| ...` |
| **Step identity** | Open `string` — `"whatever"` compiles | Closed union `StepKind` — only 6 known steps |
| **ID safety** | `userId: any, orderId: any` — interchangeable | `UserId` / `OrderId` branded — compile-time mismatch error |
| **Transitions** | Runtime `if/else` + `throw` | Exhaustive `switch` + `never` check — unmatched actions *cannot* compile |
| **Invalid transitions** | Silent bugs (e.g., submitting from step 2) | Unrepresentable — no action exists that allows it |
| **Extensibility** | Add a step → forget a case → silent bug | Add a step → compiler demands you handle it everywhere |
| **`as` casts / `!` asserts** | Everywhere to suppress errors | None needed — the types flow naturally |
