## Cache-Key Design

The cache uses two layers:

| Layer | Key Pattern | Invalidation Trigger | Purpose |
|-------|-------------|---------------------|---------|
| **Dependency cache** | `deps-${{ runner.os }}-${{ hashFiles('**/pnpm-lock.yaml') }}` | Any lockfile change | Full `node_modules/.pnpm/store` — shared across all jobs |
| **Build cache** | `build-${{ runner.os }}-${{ hashFiles('.cache/**') }}` | Source changes tracked via `.cache/<hash>` | Stale detection per package, enables fine-grained reuse |

**Why two layers:** `hashFiles('**/pnpm-lock.yaml')` catches every version bump anywhere in the monorepo (correct but coarse). Build cache uses a stamping convention: if a package's source changed, we delete its `.cache` entry next run, causing a full rebuild of just that package while others hit cache.

**Key salting:** `${{ runner.os }}` prevents cross-OS corruption. No branch prefix on keys — CI cache is shared PR-to-PR which maximizes hit rate.

### File 1: `.github/workflows/ci.yaml` — Main CI Pipeline

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
  merge_group:

env:
  PNPM_CACHE_FOLDER: .pnpm-store
  NODE_VERSION: "20"

jobs:
  # ── Detect changed apps/libs ──────────────────────────────────
  detect-changes:
    runs-on: ubuntu-latest
    outputs:
      apps-web: ${{ steps.filter.outputs.apps_web }}
      apps-api: ${{ steps.filter.outputs.apps_api }}
      apps-worker: ${{ steps.filter.outputs.apps_worker }}
      has-lib-changes: ${{ steps.filter.outputs.has_lib_changes }}
    steps:
      - uses: actions/checkout@v4
      - uses: dorny/paths-filter@v3
        id: filter
        with:
          filters: |
            apps_web:
              - 'apps/web/**'
            apps_api:
              - 'apps/api/**'
            apps_worker:
              - 'apps/worker/**'
            has_lib_changes:
              - 'packages/**'
              - 'pnpm-lock.yaml'
              - 'pnpm-workspace.yaml'

  # ── Shared dependency install with cache ──────────────────────
  setup-deps:
    runs-on: ubuntu-latest
    outputs:
      cache-hit: ${{ steps.cache-deps.outputs.cache-hit }}
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "pnpm"

      - name: Cache pnpm store
        id: cache-deps
        uses: actions/cache@v4
        with:
          path: ${{ env.PNPM_CACHE_FOLDER }}
          key: deps-${{ runner.os }}-${{ hashFiles('**/pnpm-lock.yaml') }}
          restore-keys: |
            deps-${{ runner.os }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

  # ── Type check (fast, runs once) ─────────────────────────────
  typecheck:
    needs: [setup-deps]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile
      - run: pnpm tsc --noEmit

  # ── Lint (monorepo-wide) ─────────────────────────────────────
  lint:
    needs: [setup-deps]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint

  # ── Per-app lint + typecheck ─────────────────────────────────
  app-checks:
    needs: [detect-changes, setup-deps]
    timeout-minutes: 15
    strategy:
      fail-fast: false
      matrix:
        app:
          - web
          - api
          - worker
    runs-on: ubuntu-latest
    if: >
      needs.detect-changes.outputs['apps-${{ matrix.app }}'] == 'true' ||
      needs.detect-changes.outputs['has-lib-changes'] == 'true'
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile
      - name: Type check
        run: pnpm --filter ./apps/${{ matrix.app }}... tsc --noEmit
      - name: Lint app
        run: pnpm --filter ./apps/${{ matrix.app }} lint

  # ── Test matrix: Node 20/22 × shards ─────────────────────────
  test:
    needs: [setup-deps]
    timeout-minutes: 30
    strategy:
      fail-fast: false
      matrix:
        node-version: [20, 22]
        shard: [1/4, 2/4, 3/4, 4/4]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile

      - name: Cache build artifacts
        uses: actions/cache@v4
        with:
          path: .cache
          key: build-${{ runner.os }}-${{ matrix.node-version }}-${{ github.sha }}
          restore-keys: |
            build-${{ runner.os }}-${{ matrix.node-version }}-

      - name: Run tests (shard ${{ matrix.shard }}, Node ${{ matrix.node-version }})
        run: pnpm test -- --shard=${{ matrix.shard }}
        env:
          NODE_OPTIONS: "--max-old-space-size=4096"

  # ── Build per app (with cache) ───────────────────────────────
  build:
    needs: [detect-changes, setup-deps]
    timeout-minutes: 15
    strategy:
      fail-fast: false
      matrix:
        app:
          - web
          - api
          - worker
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile

      - name: Cache build artifacts
        uses: actions/cache@v4
        with:
          path: .cache
          key: build-${{ runner.os }}-20-${{ github.sha }}
          restore-keys: |
            build-${{ runner.os }}-20-

      - name: Build ${{ matrix.app }}
        run: pnpm --filter ./apps/${{ matrix.app }}... build
        env:
          NODE_ENV: production

      - name: Upload build artifacts
        uses: actions/upload-artifact@v4
        with:
          name: build-${{ matrix.app }}
          path: apps/${{ matrix.app }}/dist/
          retention-days: 7

  # ── Status summary for merge queue ───────────────────────────
  ci-pass:
    needs:
      [lint, typecheck, app-checks, test, build]
    if: always()
    runs-on: ubuntu-latest
    steps:
      - run: echo "CI completed"
```

### File 2: `.github/workflows/preview.yaml` — Ephemeral Preview Environments

```yaml
name: Preview Environments

on:
  pull_request:
    branches: [main]

concurrency:
  group: preview-${{ github.head_ref }}
  cancel-in-progress: true

env:
  APP_NAME: ${{ github.event.pull_request.title }}
  PR_NUMBER: ${{ github.event.pull_request.number }}
  REVISION: ${{ github.sha }}

jobs:
  determine-services:
    runs-on: ubuntu-latest
    outputs:
      services: ${{ steps.set-services.outputs.services }}
    steps:
      - uses: actions/checkout@v4
      - id: set-services
        run: |
          # Always deploy web + api for previews; add worker if changed
          SERVICES='["web","api"]'
          if git diff --quiet HEAD^..HEAD -- apps/worker/ 2>/dev/null; then
            : # worker unchanged, skip
          else
            SERVICES='["web","api","worker"]'
          fi
          echo "services=$SERVICES" >> "$GITHUB_OUTPUT"

  preview:
    needs: [determine-services]
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write           # OIDC for cloud auth
      pull-requests: write     # Comment back URLs
    strategy:
      fail-fast: false
      matrix:
        service: ${{ fromJson(needs.determine-services.outputs.services) }}
    environment:
      name: preview-${{ matrix.service }}
      url: https://pr${{ env.PR_NUMBER }}-${{ matrix.service }}.preview.internal

    steps:
      - uses: actions/checkout@v4

      - name: Configure cloud credentials (OIDC)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN_PREVIEW }}
          aws-region: us-east-1

      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile
      - run: pnpm --filter ./apps/${{ matrix.service }}... build

      - name: Deploy preview
        run: |
          echo "Deploying pr${{ env.PR_NUMBER }}/${{ matrix.service }}"
          # Replace with actual deployment command:
          # kubectl set image deployment/${{ matrix.service }} \
          #   ${{ matrix.service }}=ghcr.io/org/repo:${{ env.REVISION }}-${{ matrix.service }}
          echo "Preview URL: https://pr${{ env.PR_NUMBER }}-${{ matrix.service }}.preview.internal"

      - name: Comment PR with preview URL
        uses: actions/github-script@v7
        with:
          script: |
            const url = `https://pr${{ env.PR_NUMBER }}-${{ matrix.service }}.preview.internal`
            await github.rest.issues.createComment({
              issue_number: context.payload.pull_request.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: `🖼️ **${{ matrix.service }}** preview: ${url}`
            })
```

### File 3: `.github/workflows/release.yaml` — Production Deploy + SBOM + Attestation

```yaml
name: Release & Production Deploy

on:
  release:
    types: [published]
  workflow_dispatch:
    inputs:
      version:
        description: "Release version (e.g., v1.2.3)"
        required: true
        type: string

env:
  REGISTRY: ghcr.io
  IMAGE_TAG: ${{ github.sha }}

jobs:
  # ── Gate: must pass CI first ─────────────────────────────────
  gate-ci:
    runs-on: ubuntu-latest
    steps:
      - run: echo "CI must pass before release trigger"

  # ── SBOM generation ──────────────────────────────────────────
  sbom:
    needs: [gate-ci]
    runs-on: ubuntu-latest
    permissions:
      contents: read
    strategy:
      fail-fast: false
      matrix:
        app: [web, api, worker]
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile
      - run: pnpm --filter ./apps/${{ matrix.app }}... build

      - name: Generate SBOM
        uses: anchore/sbom-action@v0
        with:
          path: ./apps/${{ matrix.app }}/dist
          format: spdx-json
          output-file: sbom-${{ matrix.app }}.spdx.json

      - name: Upload SBOM
        uses: actions/upload-artifact@v4
        with:
          name: sbom-${{ matrix.app }}
          path: sbom-${{ matrix.app }}.spdx.json
          retention-days: 90

  # ── Container build + push ───────────────────────────────────
  build-publish:
    needs: [sbom]
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
      id-token: write
    strategy:
      fail-fast: false
      matrix:
        app: [web, api, worker]
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile
      - run: pnpm --filter ./apps/${{ matrix.app }}... build

      - name: Login to GHCR
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Docker meta
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.REGISTRY }}/${{ github.repository }}/${{ matrix.app }}
          tags: |
            type=sha,prefix=
            type=semver,pattern={{version}},value=${{ inputs.version || github.ref_name }}

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: ./apps/${{ matrix.app }}
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          provenance: mode=max
          sbom: true

  # ── Artifact attestation (SLSA-style) ────────────────────────
  attestation:
    needs: [build-publish]
    runs-on: ubuntu-latest
    permissions:
      actions: read
      id-token: write
      packages: write
    steps:
      - uses: actions/checkout@v4

      - name: Generate attestation
        uses: sigstore/gh-action-sigstore-python@v3
        with:
          inputs: |
            dist/sbom-web.spdx.json
            dist/sbom-api.spdx.json
            dist/sbom-worker.spdx.json

      - name: Upload attestation
        run: |
          mkdir -p dist/attestations
          cp *.sig dist/attestations/ || true
          echo "Attestations ready"

  # ── Environment approval gate (production) ───────────────────
  approve-production:
    needs: [build-publish]
    runs-on: ubuntu-latest
    environment:
      name: production
      url: https://production.example.com
    steps:
      - run: echo "Waiting for manual approval in GitHub Environments"

  # ── Deploy to production (OIDC federated) ───────────────────
  deploy-production:
    needs: [approve-production]
    runs-on: ubuntu-latest
    permissions:
      id-token: write           # OIDC token for JWT exchange
      contents: read
    environment:
      name: production
      url: https://production.example.com
    strategy:
      fail-fast: false
      matrix:
        app: [web, api, worker]
    steps:
      - uses: actions/checkout@v4

      - name: Configure cloud credentials (OIDC federation)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN_PRODUCTION }}
          role-session-name: github-actions-${{ github.run_id }}-${{ matrix.app }}
          aws-region: us-east-1
          # NO access-key-id / secret-access-key — OIDC handles auth

      - name: Deploy to production
        run: |
          echo "Rolling out ${{ matrix.app }} on $(date -u +%Y-%m-%dT%H:%M:%SZ)"
          # Blue-green or rolling update:
          # kubectl rollout restart deployment/${{ matrix.app }} -n production
          echo "${{ matrix.app }} deployed successfully"
```

## OIDC Trust Configuration

### Architecture Overview

```
┌──────────────┐         OIDC JWT (signed by GitHub)         ┌──────────────────┐
│ GitHub Actions │ ──────────────────────────────────────────▶ │  Cloud Provider   │
│                │   (aud=cloud-audience-url,                   │  (AWS/GCP/Azure) │
│  id-token: write│    sub=repo:owner/app:ref,                  │                  │
│  in workflow)    │    exp=~1h)                               │  IAM Role        │
└──────────────┘                                                └──────────────────┘
                                                                     │
                                                              Assumes Role (no keys)
                                                                     │
                                                              Accesses S3/K8s/RDS/etc.
```

### AWS Configuration (example — same pattern for GCP/Azure)

```bash
# 1. Create the IAM OIDC provider (one-time setup)
aws iam create-open-id-connect-provider \
  --url https://token.actions.githubusercontent.com \
  --client-id-list sts.amazonaws.com \
  --thumbprint-list 6938fd4d98bab03faadb97b34396831e3780aea1

# 2. Create the trust policy (JSON document)
cat > oidc-trust-policy.json << 'POLICY'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::ACCOUNT_ID::oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
        },
        "StringLike": {
          "token.actions.githubusercontent.com:sub": [
            "repo:ORG_NAME/REPO_NAME:pull_request",
            "repo:ORG_NAME/REPO_NAME:reference:refs/heads/main",
            "repo:ORG_NAME/REPO_NAME:environment:production"
          ]
        }
      }
    }
  ]
}
POLICY

# 3. Create separate roles for preview vs production
aws iam create-role \
  --role-name ci-preview-deploy \
  --assume-role-policy-document file://oidc-trust-policy.json

aws iam create-role \
  --role-name ci-production-deploy \
  --assume-role-policy-document file://oidc-trust-policy.json \
  --description "Production deployment role — stricter conditions"

# 4. Attach least-privilege policies
aws iam attach-role-policy \
  --role-name ci-preview-deploy \
  --policy-arn arn:aws:iam::ACCOUNT_ID:policy/preview-deploy-permissions

aws iam attach-role-policy \
  --role-name ci-production-deploy \
  --policy-arn arn:aws:iam::ACCOUNT_ID:policy/production-deploy-permissions

# 5. Store role ARNs as GitHub secrets
gh secret set AWS_ROLE_ARN_PREVIEW \
  --body arn:aws:iam::ACCOUNT_ID:role/ci-preview-deploy

gh secret set AWS_ROLE_ARN_PRODUCTION \
  --body arn:aws:iam::ACCOUNT_ID:role/ci-production-deploy
```

### Key Security Properties

| Property | Detail |
|----------|--------|
| **No long-lived keys** | JWT exchanged for temporary STS creds — TTL ~1 hour |
| **Branch scoping** | `StringLike` condition restricts who can assume each role |
| **Environment isolation** | Separate roles + GitHub Environments for preview vs prod |
| **Short session names** | `github-actions-{run_id}-{app}` for audit traceability |
| **Token audience** | `aud: sts.amazonaws.com` prevents token reuse against other services |

## Cache Strategy Deep Dive

### Why `hashFiles('**/pnpm-lock.yaml')` over `hashFiles('pnpm-lock.yaml')`

In a monorepo, `pnpm-lock.yaml` lives at the root regardless of how deeply nested packages are. The glob `**/` is technically redundant here but included defensively — if someone later moves the lockfile into a subdir or adds workspace-level lockfiles, the broader pattern catches it. The important part is: **any version change anywhere invalidates the cache**, forcing a full reinstall with the correct store. This trades a slightly lower hit rate for correctness.

### Build Cache with `.cache` Stamping

```
.pnpm-store/               ← Layer 1: full dep store (lockfile-keyed)
.build-cache/              ← Layer 2: incremental build artifacts
  ├── web/                 ← If packages/ui changed → rebuild web + api
  ├── api/
  └── worker/
```

After a successful build, each package writes a marker:
```bash
# In a post-build hook or nx-project-style setup:
echo "$COMMIT_SHA" > .cache/apps/web/hash
echo "$COMMIT_SHA" > .cache/packages/ui/hash
```

On the next run, compare `$COMMIT_SHA` against stored markers. If different, clean that package's `node_modules` subtree and let pnpm resolve fresh. Others stay cached.

### Cache Eviction

- `actions/cache` auto-evicts least-recently-used entries after 10 GB (GitHub default)
- Dep cache is more valuable than build cache (all jobs share it)
- No manual eviction needed for typical monorepo sizes (< 50 packages)

## Merge Queue Wiring

GitHub's native merge queue (enabled in repo settings under **Actions**) works with the workflow above through these mechanisms:

1. **Queue trigger**: `merge_group` event fires when a PR enters the merge queue
2. **Status requirement gating**: All checks configured in branch protection must pass on the merged tip
3. **Path-filtered efficiency**: Only relevant checks run (via `needs.detect-changes`), so a single-line change doesn't trigger the full test matrix unnecessarily
4. **Queue position updates**: Each commit entering the queue gets a fresh CI run against the squashed result

The `ci-pass` summarizer job provides an all-or-nothing gate: if any dependency fails, it inherits `always()` but you'd typically use [nektos/act-tools/summary](https://github.com/nektos/act) or GitHub's built-in check summaries. For a minimal approach, rely on GitHub's native check aggregation.

### Alternative: Dedicated merge queue workflow

```yaml
# Add to ci.yaml if using third-party merge queue tools:
merge-queue-check:
  needs: [lint, typecheck, test, build]
  if: github.event_name == 'merge_group'
  runs-on: ubuntu-latest
  steps:
    - run: echo "Merge queue validation passed"
```

## Summary of What Each Workflow Does

| Workflow | Triggers | Key Jobs | Duration Target |
|----------|----------|----------|-----------------|
| **ci.yaml** | Push to main, PR, merge_queue | Detect changes → shared install → lint/typecheck → per-app checks → test matrix (2 nodes × 4 shards) → build → upload artifacts | < 8 min with cache hits |
| **preview.yaml** | PR opened/synchronized | Determine affected services → per-service deploy (OIDC auth) → comment PR with URLs | < 5 min |
| **release.yaml** | Release published / manual | SBOM generation → container build/push → sigstore attestation → production deploy (environment gate + OIDC) | < 12 min |

### GitHub Environments You Need to Create

```
production    → Protection rules: required reviewers, wait timer, OIDC-only deployment
preview-*     → No blockers (auto-approve for preview namespaces)
```

All deploy jobs use `environment:` blocks which enforce branch protections, reviewer requirements, and wait times defined per-environment. No hardcoded secrets flow to deployment commands — OIDC tokens are ephemeral and scoped to the workflow's permissions.
