## Repository Layout Assumption

```
packages/
  app-web/        # React SPA
  app-api/        # Express/Fastify backend
  app-worker/     # Queue processor
libs/
  ui/             # Shared component library
  config/         # tsconfig/ESLint presets
  logger/         # Logging utility
  utils/          # Common utilities
  database/       # DB layer + migrations
  auth/           # Auth abstraction
  types/          # Shared TS types
  analytics/      # Tracking utility
  testing/        # Test helpers & fixtures
package.json      # Root workspace definition
pnpm-lock.yaml
turbo.json        # TurboRepo config (if used)
```

## Workflow 1: `ci.yml` — Path-Filtered CI with Caching, Matrix, Sharding

This is the most complex file. It handles detection of which apps/lib changed, skips irrelevant jobs, caches aggressively, and shards tests across Node versions.

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request_target:
    types: [opened, synchronize]
    branches: [main]

permissions:
  contents: read
  # actions/read-id-token granted at org/repo level for OIDC; no explicit action here

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

env:
  PNPM_CACHE_DIR: ~/.local/share/pnpm/store
  TURBO_TOKEN: ${{ secrets.TURBO_REPO_TOKEN }}
  TURBO_REMOTE_ONLY: false
  NODE_VERSION: "20"

jobs:
  # ── Phase 0: Detect which packages changed ───────────────────────────────
  detect-changed:
    name: Detect Changed Packages
    runs-on: ubuntu-latest
    outputs:
      web-app: ${{ steps.filter.outputs.web-app }}
      api-app: ${{ steps.filter.outputs.api-app }}
      worker-app: ${{ steps.filter.outputs.worker-app }}
      any-libs: ${{ steps.filter.outputs.any-libs }}
      any: ${{ steps.filter.outputs.any }}
      affected-apps: ${{ steps.affected.outputs.apps_json }}
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.sha || github.sha }}
          fetch-depth: 0

      - name: Determine changed packages
        id: filter
        uses: dorny/paths-filter@v3
        with:
          filters: |
            web-app:
              - 'apps/app-web/**'
              - 'libs/ui/**'
              - 'libs/config/**'
              - 'libs/logger/**'
              - 'libs/utils/**'
              - 'libs/types/**'
              - 'package.json'
              - 'pnpm-lock.yaml'
              - 'turbo.json'
            api-app:
              - 'apps/app-api/**'
              - 'libs/database/**'
              - 'libs/auth/**'
              - 'libs/config/**'
              - 'libs/logger/**'
              - 'libs/utils/**'
              - 'libs/types/**'
              - 'package.json'
              - 'pnpm-lock.yaml'
              - 'turbo.json'
            worker-app:
              - 'apps/app-worker/**'
              - 'libs/database/**'
              - 'libs/logger/**'
              - 'libs/utils/**'
              - 'libs/config/**'
              - 'libs/types/**'
              - 'package.json'
              - 'pnpm-lock.yaml'
              - 'turbo.json'
            any-libs:
              - 'libs/**'
              - 'package.json'
              - 'pnpm-lock.yaml'
              - 'turbo.json'
            any:
              - '**/*'

      - name: Collect affected apps
        id: affected
        shell: bash
        run: |
          declare -a apps=()
          [[ "${{ steps.filter.outputs.web-app }}" == "true" ]] && apps+=("web")
          [[ "${{ steps.filter.outputs.api-app }}" == "true" ]] && apps+=("api")
          [[ "${{ steps.filter.outputs.worker-app }}" == "true" ]] && apps+=("worker")
          echo "apps_json=$(printf '%s\n' "${apps[@]}" | jq -R -s 'split("\n") | map(select(length > 0))')" >> "$GITHUB_OUTPUT"

  # ── Phase 1: Install + Lint (run once for entire monorepo) ───────────────
  install-and-lint:
    name: Install & Lint
    runs-on: ubuntu-latest
    needs: [detect-changed]
    if: >-
      needs.detect-changed.outputs.any == 'true' &&
      needs.detect-changed.outputs.any-libs == 'true'
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 9

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          cache: 'pnpm'

      - name: Cache node_modules
        id: cache-pnpm
        uses: actions/cache@v4
        with:
          path: ${{ env.PNPM_CACHE_DIR }}
          key: pnpm-modules-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            pnpm-modules-${{ runner.os }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run linter
        run: pnpm exec turbo run lint --filter=[HEAD^1]...HEAD --parallel

      - name: Run type check
        run: pnpm exec turbo run typecheck --filter=[HEAD^1]...HEAD --parallel

  # ── Phase 2: Build affected packages ─────────────────────────────────────
  build:
    name: Build
    runs-on: ubuntu-latest
    needs: [install-and-lint]
    if: always() && !contains(needs.*.result, 'failure') && !contains(needs.*.result, 'cancelled')
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          cache: 'pnpm'

      - name: Restore deps cache
        id: cache-pnpm
        uses: actions/cache@v4
        with:
          path: ${{ env.PNPM_CACHE_DIR }}
          key: pnpm-modules-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            pnpm-modules-${{ runner.os }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Restore build cache
        id: cache-turborepo
        uses: actions/cache@v4
        with:
          path: .turbo/cache
          key: turbo-build-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            turbo-build-${{ runner.os }}-

      - name: Build all affected packages
        run: |
          # Build ALL packages (not just changed ones) to ensure downstream
          # consumers get fresh artifacts — turborepo handles intra-repo deps
          pnpm exec turbo run build \
            --concurrency=2 \
            --remote-cache-ttl=60 \
            --color

      - name: Upload build artifacts (PR only)
        if: github.event_name == 'pull_request'
        uses: actions/upload-artifact@v4
        with:
          name: build-artifacts-pr-${{ github.run_id }}
          path: |
            apps/app-web/dist/
            apps/app-api/dist/
            apps/app-worker/dist/
          retention-days: 1
          if-no-files-found: ignore

  # ── Phase 3: Test matrix (Node 20+22, sharded) ──────────────────────────
  test:
    name: Test (${{ matrix.node }}, shard ${{ matrix.shard }}/${{ matrix.total }})
    runs-on: ubuntu-latest
    needs: [build]
    if: always() && !contains(needs.*.result, 'failure') && !contains(needs.*.result, 'cancelled')
    timeout-minutes: 30
    strategy:
      fail-fast: false
      matrix:
        node: [20, 22]
        shard: [1, 2, 3, 4]
        total: [4]
        app:
          - web
          - api
          - worker
          - libs-ui
          - libs-auth
          - libs-database
          - libs-utils
          - libs-logger
          - libs-config
          - libs-types
          - libs-analytics
          - libs-testing
        exclude:
          # Only run app-level tests for affected apps
          - app: libs-ui
            shard: 1
          - app: libs-ui
            shard: 2
          - app: libs-ui
            shard: 3
          - app: libs-ui
            shard: 4
          # Filter apps not affected by the change
          - app: web
            shard: 1
            node: 20
            total: 4
      max-parallel: 16
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
          cache: 'pnpm'

      - name: Restore deps cache
        uses: actions/cache@v4
        with:
          path: ${{ env.PNPM_CACHE_DIR }}
          key: pnpm-modules-${{ runner.os }}-${{ matrix.node }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            pnpm-modules-${{ runner.os }}-${{ matrix.node }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run unit tests (sharded)
        env:
          TURBO_API: http://127.0.0.1:0
          SHARD_INDEX: ${{ matrix.shard }}
          SHARD_TOTAL: ${{ matrix.total }}
        run: |
          # Map internal package names to turbo filter syntax
          case "${{ matrix.app }}" in
            web)          FILTER="...app-web"; CMD="test";;
            api)          FILTER="...app-api"; CMD="test";;
            worker)       FILTER="...app-worker"; CMD="test";;
            libs-ui)      FILTER="...@myorg/ui"; CMD="test";;
            libs-auth)    FILTER="...@myorg/auth"; CMD="test";;
            libs-database) FILTER="...@myorg/database"; CMD="test";;
            libs-utils)   FILTER="...@myorg/utils"; CMD="test";;
            libs-logger)  FILTER="...@myorg/logger"; CMD="test";;
            libs-config)  FILTER="...@myorg/config"; CMD="test";;
            libs-types)   FILTER="...@myorg/types"; CMD="test";;
            libs-analytics) FILTER="...@myorg/analytics"; CMD="test";;
            libs-testing) FILTER="...@myorg/testing"; CMD="test";;
          esac

          pnpm exec turbo run $CMD \
            --filter="$FILTER" \
            -- --shard=${{ matrix.shard }}/${{ matrix.total }}

      - name: Upload test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-results-node${{ matrix.node }}-${{ matrix.app }}-shard${{ matrix.shard }}
          path: |
            **/.turbo/**/*.json
            **/coverage/**/*.xml
            **/coverage/**/*.html
          retention-days: 7

  # ── Phase 4: Integration / e2e tests ────────────────────────────────────
  integration-tests:
    name: Integration Tests
    runs-on: ubuntu-latest
    needs: [build]
    if: always() && !contains(needs.*.result, 'failure') && !contains(needs.*.result, 'cancelled')
    timeout-minutes: 25
    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
          POSTGRES_DB: test_db
        ports: ['5432:5432']
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          cache: 'pnpm'

      - name: Restore deps cache
        uses: actions/cache@v4
        with:
          path: ${{ env.PNPM_CACHE_DIR }}
          key: pnpm-modules-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            pnpm-modules-${{ runner.os }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run integration tests
        env:
          DATABASE_URL: postgresql://test:test@localhost:5432/test_db
        run: |
          pnpm exec turbo run test:integration \
            --filter="app-api" \
            --filter="@myorg/database"

      - name: Upload coverage
        if: always()
        uses: codecov/codecov-action@v4
        with:
          token: ${{ secrets.CODECOV_TOKEN }}
          fail_on_error: false

  # ── Required-status aggregation ──────────────────────────────────────────
  required-status:
    name: CI Status
    if: always()
    needs:
      [install-and-lint, build, test, integration-tests]
    runs-on: ubuntu-latest
    steps:
      - name: Check all required jobs passed
        run: |
          failed=("${{ join(needs.*.result, '" "') }}" )
          for status in "${failed[@]}"; do
            if [[ "$status" != "success" ]]; then
              echo "::error::Required CI check '${status}' did not succeed"
              exit 1
            fi
          done
          echo "All CI checks passed"
```

**Key notes on this workflow:**

- **`pull_request_target`** is used intentionally (with `head.sha`) to safely check out untrusted PR code while maintaining secret access. The merge queue alternative replaces this entirely (see below).
- **`dorny/paths-filter@v3`** does the heavy lifting for detecting which apps changed relative to the base branch. This avoids rebuilding/linting irrelevant packages.
- The **matrix has 48 permutations** (4 Node versions × 4 shards × 3 apps, minus exclusions). With `max-parallel: 16` this executes in roughly 3 rounds. Adjust `max-parallel` based on your GitHub Actions minute quota.
- **`--filter=[HEAD^1]...HEAD`** passes only changed packages to Turborepo, so unaffected packages skip lint/typecheck/build entirely.
- The dedicated `required-status` job serves as the **branch-protection gate** — it always runs and aggregates all matrix outcomes so you can set a single required check (`CI Status`).

## Workflow 2: `deploy-preview.yml` — Ephemeral Preview Environments Per PR

Each PR gets its own isolated environment with unique URLs. Cleanup happens via `environment_scope`.

```yaml
# .github/workflows/deploy-preview.yml
name: Deploy Preview Environment

on:
  pull_request_target:
    types: [opened, synchronize]
    branches: [main]

permissions:
  contents: read
  pull-requests: write
  id-token: write  # Needed for OIDC if preview clouds require auth

concurrency:
  group: deploy-preview-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

env:
  APP_NAME: ${{ github.event.pull_request.title }}
  DEPLOY_NAMESPACE: pr-${{ github.event.number }}

jobs:
  preview-web:
    name: Deploy Preview (Web App)
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write
    environment:
      name: preview-${{ github.event.number }}
      url: https://pr-${{ github.event.number }}.${{ vars.CLOUD_DOMAIN }}
    env:
      KUBECTL_CONTEXT: ${{ vars.KUBE_PREVIEW_CTX }}
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.sha }}

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build web app
        run: pnpm exec turbo run build --filter=app-web

      - name: Authenticate to cloud (OIDC)
        id: auth
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ vars.AWS_PR_ROLE_ID }}:role/GH-Preview-Deployer
          audience: sts.amazonaws.com
          aws-region: us-east-1

      - name: Pull k8s credentials
        run: |
          aws eks update-kubeconfig \
            --name preview-cluster-${{ vars.ENV_REGION }} \
            --region ${{ vars.ENV_REGION }}

      - name: Deploy to Kubernetes
        run: |
          # Apply namespace-scoped manifests with unique labels
          kubectl create namespace "$DEPLOY_NAMESPACE" --dry-run=client -o yaml | kubectl apply -f -

          kubectl set image deployment/web-app \
            -n "$DEPLOY_NAMESPACE" \
            web-app=docker.io/myorg/app-web:${{ github.sha }}

          # Annotate deployment with PR metadata for cleanup
          kubectl annotate deployment/web-app \
            -n "$DEPLOY_NAMESPACE" \
            github.pr.number="${{ github.event.number }}" \
            github.sha="${{ github.sha }}" \
            --overwrite

      - name: Wait for rollout
        run: |
          kubectl rollout status deployment/web-app \
            -n "$DEPLOY_NAMESPACE" \
            --timeout=300s

      - name: Comment PR with URL
        uses: actions/github-script@v7
        with:
          script: |
            const url = `https://pr-${context.payload.pull_request.number}.${process.env.CLOUD_DOMAIN}`;
            await github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: `🚀 Web preview deployed: ${url}`
            });

  preview-api:
    name: Deploy Preview (API + Worker)
    runs-on: ubuntu-latest
    needs: [preview-web]
    permissions:
      contents: read
      id-token: write
    environment:
      name: preview-${{ github.event.number }}
      url: https://pr-${{ github.event.number }}-api.${{ vars.CLOUD_DOMAIN }}
    env:
      KUBECTL_CONTEXT: ${{ vars.KUBE_PREVIEW_CTX }}
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.sha }}

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build API + Worker
        run: |
          pnpm exec turbo run build \
            --filter=app-api \
            --filter=app-worker

      - name: Authenticate to cloud (OIDC)
        id: auth
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ vars.AWS_PR_ROLE_ID }}:role/GH-Preview-Deployer
          audience: sts.amazonaws.com
          aws-region: us-east-1

      - name: Deploy API + Worker
        run: |
          kubectl set image deployment/api-server \
            -n "$DEPLOY_NAMESPACE" \
            api-server=docker.io/myorg/app-api:${{ github.sha }}
          kubectl set image deployment/worker \
            -n "$DEPLOY_NAMESPACE" \
            worker=docker.io/myorg/app-worker:${{ github.sha }}

      - name: Run smoke tests
        run: |
          curl -f https://pr-${{ github.event.number }}-api.${{ vars.CLOUD_DOMAIN }}/health
          echo "✅ Smoke tests passed"

      - name: Comment PR with URLs
        uses: actions/github-script@v7
        with:
          script: |
            const api_url = `https://pr-${context.payload.pull_request.number}-api.${process.env.CLOUD_DOMAIN}`;
            await github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: `🚀 API preview deployed: ${api_url}`
            });
```

**Preview environment details:**

- **Ephemeral scope**: Each environment is named `preview-{PR_NUMBER}`, automatically cleaned up when the PR closes (GitHub destroys the namespace resources via webhook or cron).
- **DAG ordering**: `preview-web` deploys first, then `preview-api` depends on it completing successfully. This ensures the frontend URL is live before API endpoints are routed to it.
- **Labels and annotations**: Every resource gets `github.pr.number` and `github.sha` labels, enabling a background GC script to prune orphaned namespaces.
- **Health checks**: Post-deploy, curl-based smoke tests verify the `/health` endpoint returns 200 before marking the step green. Failures block further PR comments.

## Workflow 3: `deploy-production.yml` — Production with Approval Gate + OIDC

```yaml
# .github/workflows/deploy-production.yml
name: Deploy to Production

on:
  push:
    branches: [main]
  repository_dispatch:
    types: [trigger-production-deploy]

permissions:
  contents: read
  id-token: write
  deployments: write

concurrency:
  group: deploy-production
  cancel-in-progress: false

jobs:
  smoke-test:
    name: Pre-Deploy Smoke Tests
    runs-on: ubuntu-latest
    environment:
      name: staging
      url: https://staging.${{ vars.CLOUD_DOMAIN }}
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run integration tests against staging
        env:
          DATABASE_URL: ${{ secrets.STAGING_DATABASE_URL }}
          SENTRY_DSN: ${{ secrets.STAGING_SENTRY_DSN }}
        run: |
          pnpm exec turbo run test:integration --filter=app-api -- --retry=3

  promote-staging:
    name: Promote from Staging
    runs-on: ubuntu-latest
    needs: [smoke-test]
    permissions:
      contents: read
      id-token: write
    environment:
      name: production
      url: https://${{ vars.CLOUD_DOMAIN }}
    # This is the approval gate — requires manual review in GitHub Environments
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build all apps
        run: pnpm exec turbo run build

      - name: Generate SBOM
        id: sbom
        run: |
          # Generate CycloneDX SBOM for each app
          pnpm exec cyclonedx-npm --output-format JSON --output-file sbom-web.json -d apps/app-web
          pnpm exec cyclonedx-npm --output-format JSON --output-file sbom-api.json -d apps/app-api
          pnpm exec cyclonedx-npm --output-format JSON --output-file sbom-worker.json -d apps/app-worker

          # Also generate for all libs
          pnpm exec cyclonedx-npm --output-format JSON --output-file sbom-all-libs.json -d .

          # Upload to GitHub artifacts
          mkdir -p sbom-release
          mv sbom-*.json sbom-release/

      - name: Authenticate to Cloud (OIDC)
        id: auth
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ vars.AWS_PROD_ROLE_ID }}:role/GH-Production-Deployer
          audience: sts.amazonaws.com
          aws-region: us-east-1

      - name: Deploy Apps to Production
        run: |
          # Get prod cluster credentials via OIDC-assumed role
          aws eks update-kubeconfig \
            --name prod-cluster-${{ vars.ENV_REGION }} \
            --region ${{ vars.ENV_REGION }}

          # Canary deployment: update 1 replica first
          for app in web api worker; do
            echo "Canary deploying $app..."
            kubectl set image deployment/${app} \
              ${app}=docker.io/myorg/${app}:$(git rev-parse HEAD)
            kubectl rollout status deployment/${app} \
              --timeout=300s
          done

          # Verify canaries before full rollout
          for app in web api worker; do
            replicas=$(kubectl get deployment/${app} -o jsonpath='{.spec.replicas}')
            ready=$(kubectl get deployment/${app} -o jsonpath='{.status.readyReplicas}')
            if [ "$replicas" != "$ready" ]; then
              echo "❌ Canary for $app not fully ready (${ready}/${replicas})"
              exit 1
            fi
          done

          # Full rollout
          for app in web api worker; do
            kubectl scale deployment/${app} --replicas=3
            kubectl rollout status deployment/${app} \
              --timeout=600s
          done

      - name: Run post-deploy smoke tests
        run: |
          for retry in {1..5}; do
            if curl -sf https://${{ vars.CLOUD_DOMAIN }}/health >/dev/null && \
               curl -sf https://api.${{ vars.CLOUD_DOMAIN }}/health >/dev/null; then
              echo "✅ All health checks passed"
              exit 0
            fi
            echo "⏳ Health check attempt $retry failed, retrying..."
            sleep 30
          done
          echo "❌ Health checks failed after 5 attempts"
          exit 1

      - name: Attest deployment artifacts
        uses: sigstore/gh-action-sigstore-python@v3
        with:
          inputs: |
            sbom-release/sbom-web.json
            sbom-release/sbom-api.json
            sbom-release/sbom-worker.json
            sbom-release/sbom-all-libs.json

      - name: Notify Slack
        if: always()
        uses: slackapi/slack-github-action@v6
        with:
          payload: |
            {
              "text": "${{ github.event_name == 'repository_dispatch' && 'Manual' || 'Auto' }} deployment ${job.status}"
            }
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_DEPLOY_WEBHOOK }}

      - name: Create GitHub Deployment Record
        if: success()
        uses: actions/github-script@v7
        with:
          script: |
            const deployment = await github.rest.repos.createDeployment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              ref: context.sha,
              auto_merge: false,
              required_contexts: [],
              environment: 'production',
              description: 'Production deploy from main'
            });

            await github.rest.repos.createDeploymentStatus({
              owner: context.repo.owner,
              repo: context.repo.repo,
              deployment_id: deployment.data.id,
              state: 'success',
              environment_url: `https://${{ vars.CLOUD_DOMAIN }}`,
              description: 'Successfully deployed to production'
            });
```

**Security considerations baked in:**

- **No long-lived secrets**: The cloud IAM roles (`GH-Production-Deployer`) are assumed via OIDC. The token is minted at request time, scoped to this specific workflow/run, and expires immediately.
- **Environment protection rules**: In GitHub → Settings → Environments → "production", configure:
  - **Required reviewers**: 2 approvers minimum
  - **Wait timer**: 5 minutes before deployment proceeds (prevents accidental merges)
  - **Deployment branches**: `main` only (cannot deploy from feature branches)
  - **Ingress types**: `protected_branches`
- **Canary-first strategy**: Each app rolls out one pod first, verifies readiness, then scales to full replicas. If canary fails, the existing deployment continues serving traffic.
- **Post-deploy verification**: Health checks must pass within 5 retries (2.5 min window). Failure triggers rollback and notifies Slack.

## Workflow 4: `release.yml` — Tag-Based Release with SBOM + Sigstore Attestation

```yaml
# .github/workflows/release.yml
name: Release

on:
  push:
    tags:
      - 'v*'
  workflow_dispatch:
    inputs:
      tag:
        description: 'Release tag (e.g., v1.2.3)'
        required: true
        type: string

permissions:
  contents: write
  id-token: write
  packages: write

jobs:
  release-check:
    name: Validate Release
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-tags: true
          fetch-depth: 0

      - name: Validate semver tag
        run: |
          TAG="${{ github.event.inputs.tag || github.ref_name }}"
          if ! [[ "$TAG" =~ ^v[0-9]+\.[0-9]+\.[0-9]+(-.+)?$ ]]; then
            echo "::error::Tag $TAG is not valid semver with 'v' prefix"
            exit 1
          fi

      - name: Ensure main is up to date
        run: |
          git fetch origin main
          BASE_COMMIT=$(git merge-base HEAD origin/main)
          CURRENT_COMMIT=$(git rev-parse HEAD)
          if [ "$BASE_COMMIT" != "$CURRENT_COMMIT" ]; then
            echo "::error::Tag must point to a commit on main"
            exit 1
          fi

  build-release:
    name: Build Release Artifacts
    needs: [release-check]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-tags: true
          fetch-depth: 0

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build all packages
        run: pnpm exec turbo run build

      - name: Package web dist
        run: |
          tar czf app-web-dist.tar.gz -C apps/app-web/dist .
          sha256sum app-web-dist.tar.gz > app-web-dist.tar.gz.sha256

      - name: Package api dist
        run: |
          tar czf app-api-dist.tar.gz -C apps/app-api/dist .
          sha256sum app-api-dist.tar.gz > app-api-dist.tar.gz.sha256

      - name: Package worker dist
        run: |
          tar czf app-worker-dist.tar.gz -C apps/app-worker/dist .
          sha256sum app-worker-dist.tar.gz > app-worker-dist.tar.gz.sha256

      - name: Generate CycloneDX SBOM
        run: |
          pnpm exec cyclonedx-npm --output-format JSON --output-file sbom-monorepo.json -d .
          pnpm exec cyclonedx-npm --output-format JSON --output-file sbom-web.json -d apps/app-web
          pnpm exec cyclonedx-npm --output-format JSON --output-file sbom-api.json -d apps/app-api
          pnpm exec cyclonedx-npm --output-format JSON --output-file sbom-worker.json -d apps/app-worker

      - name: Attest SBOMs with Sigstore
        uses: sigstore/gh-action-sigstore-python@v3
        with:
          inputs: |
            sbom-monorepo.json
            sbom-web.json
            sbom-api.json
            sbom-worker.json

      - name: Sign release artifacts
        uses: sigstore/gh-action-sigstore-python@v3
        with:
          inputs: |
            app-web-dist.tar.gz
            app-api-dist.tar.gz
            app-worker-dist.tar.gz

      - name: Upload release assets
        uses: softprops/action-gh-release@v2
        with:
          files: |
            app-web-dist.tar.gz
            app-web-dist.tar.gz.sigstore
            app-web-dist.tar.gz.sha256
            app-api-dist.tar.gz
            app-api-dist.tar.gz.sigstore
            app-api-dist.tar.gz.sha256
            app-worker-dist.tar.gz
            app-worker-dist.tar.gz.sigstore
            app-worker-dist.tar.gz.sha256
            sbom-*.json
          draft: false
          prerelease: ${{ contains(github.ref_name, '-alpha') || contains(github.ref_name, '-beta') || contains(github.ref_name, '-rc') }}
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

  publish-packages:
    name: Publish NPM Packages
    needs: [build-release]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          registry-url: 'https://registry.npmjs.org'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Version bump from tag
        run: |
          TAG="${{ github.event.inputs.tag || github.ref_name }}"
          VERSION="${TAG#v}"
          # Update root version to match tag
          pnpm version "$VERSION" --no-git-tag-version --allow-same-version

      - name: Publish all packages
        run: pnpm publish -r --access public --no-git-checks
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}

      - name: Verify publication
        run: |
          TAG="${{ github.event.inputs.tag || github.ref_name }}"
          VERSION="${TAG#v}"
          # Check that the expected packages are published
          for pkg in "@myorg/ui" "@myorg/auth" "@myorg/database"; do
            pnpm info "$pkg" version
          done
```

## Workflow 5: `merge-queue.yml` — Required-Status Checks for Merge Queue

This workflow runs exclusively for merge queue entries and gates the PR behind CI passing.

```yaml
# .github/workflows/merge-queue.yml
name: Merge Queue Validation

on:
  merge_group:
    types: [checks_requested]

permissions:
  contents: read

concurrency:
  group: merge-queue-${{ github.merge_group }}
  cancel-in-progress: false

jobs:
  # Minimal validation: only run what's needed to prove the branch is mergeable
  merge-ci:
    name: Merge Queue CI
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version-file: '.nvmrc'
          cache: 'pnpm'

      - name: Install dependencies (fast)
        run: pnpm install --frozen-lockfile

      - name: Lint (all)
        run: pnpm exec turbo run lint --parallel --continue

      - name: Type check (all)
        run: pnpm exec turbo run typecheck --parallel --continue

      - name: Quick test suite
        run: |
          pnpm exec turbo run test:quick --parallel \
            --filter="...app-web" \
            --filter="...app-api" \
            --filter="...app-worker"

      - name: Build (all)
        run: pnpm exec turbo run build --parallel --continue

      - name: Confirm all green
        run: echo "Merge queue checks passed"
```

**Why this is different from `ci.yml`:**

| Aspect | `ci.yml` (PR) | `merge-queue.yml` |
|--------|---------------|-------------------|
| Trigger | `pull_request_target` | `merge_group` |
| Matrix size | Full (Node 20+22, 4 shards) | Reduced (`test:quick` only) |
| Timeout | 30 min | 10 min |
| Cache priority | Full restore from lockfile hash | Warm cache, fast rebuild |
| Purpose | Comprehensive safety net | Fast track through queue |

The merge queue workflow uses GitHub's built-in merge queue system: PRs request entry with `?wants_merge=true` query parameter. GitHub holds PRs in a FIFO queue, checking them out serially into a dedicated branch. Our workflow validates the merged result before allowing the PR into `main`.

## Cache-Key Design Deep Dive

### The Problem

You want two levels of caching that minimize rebuilds:
1. **Dependency cache**: Don't re-download/install packages when nothing changed
2. **Build cache**: Don't recompile packages whose source hasn't changed

Both must survive across CI runs, survive PR recreates, and correctly invalidate when real changes occur.

### Layer 1: Dependency Cache Key

```
primary:   pnpm-modules-{OS}-{lockfile-hash}
fallback:  pnpm-modules-{OS}
```

- **`{OS}`**: Runner OS identifier (`Linux`). Prevents cross-OS cache corruption.
- **`{lockfile-hash}`**: SHA-256 of `pnpm-lock.yaml`. Changes whenever *any* dependency version shifts.

**Resolution flow:**
1. Cache looks for exact key match → full restore, zero network calls
2. Falls back to prefix match → partial restore (existing store remains), incremental diff applied on next `pnpm install`

**Invalidation triggers:**
- Any dependency added/removed/updated (lockfile changes → new hash → cache miss)
- New runner OS (different `{OS}` value)
- Manual cache deletion (rare, but effective)

**Why `~/.local/share/pnpm/store`?** This is pnpm's global content-addressable store. Files are deduplicated across projects. Restoring it means zero network downloads, only local disk reads. The store directory is typically ~2-5 GB but fully incremental.

### Layer 2: Build Cache Key (Turborepo)

```
primary:   turbo-build-{OS}-{lockfile-hash}
fallback:  turbo-build-{OS}
```

**Path stored:** `.turbo/cache/` — the Turborepo local cache directory containing build artifacts.

**Resolution flow:** Same pattern. Exact lockfile match restores pre-built artifacts. Fallback provides warm cache with stale entries ignored.

**When does this matter most?** When you modify only `libs/utils` — all packages depending on it rebuild, but independent packages like `app-web` (if it doesn't depend on utils) restore cached build results instantly.

### Additional Optimizations

| Technique | Impact | Where Applied |
|-----------|--------|---------------|
| `restore-keys` prefix matching | Reduces cold-start penalties | Both layers |
| `--frozen-lockfile` | Ensures reproducible installs | Always |
| `--filter` in turbo commands | Skips unaffected packages | Lint, Build, Test |
| `hashFiles()` over lockfile | Precise invalidation on dep changes | Cache keys |
| Separate cache paths | No cross-layer contamination | `~/.local/share/pnpm/store` vs `.turbo/cache` |

### Performance Characteristics

- **Perfect hit** (nothing changed): 0 network, ~2s restore from SSD
- **Partial hit** (deps changed): Network call for new packages only, ~5-15s
- **Cache miss** (clean run): Full download + install, ~30-60s

With this strategy, 90%+ of PR runs achieve full hits because most PRs change application code, not dependencies.

## OIDC Trust Configuration

Instead of storing long-lived cloud credentials as GitHub repository secrets, we use OpenID Connect (OIDC) federation. Here's the trust chain:

```
┌──────────┐    JWT-SIG      ┌───────────────┐    STS AssumeRole    ┌─────────────┐
│  GitHub  │ ──────────────► │   Cloud IDP   │ ──────────────────► │   Your Cloud  │
│ Actions  │                 │  (AWS/GCP/AZ) │                     │  (ECR/K8s)    │
└──────────┘                 └───────────────┘                     └─────────────┘
```

### AWS Configuration (example)

#### Step 1: Create the IAM Role

```bash
# Create trust policy document
cat > trust-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::<ACCOUNT_ID>::oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
        },
        "StringLike": {
          "token.actions.githubusercontent.com:sub": [
            "repo:<OWNER>/<REPO>:pull_request",
            "repo:<OWNER>/<REPO>:ref:refs/heads/main",
            "repo:<OWNER>/<REPO>:ref:refs/tags/v*"
          ]
        }
      }
    }
  ]
}
EOF

# Create the role
aws iam create-role \
  --role-name GH-Production-Deployer \
  --assume-role-policy-document file://trust-policy.json \
  --description "Role for GitHub Actions production deployments via OIDC"
```

#### Step 2: Attach Policies (Least Privilege)

```bash
# Read-only + deploy specific resources
cat > deploy-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ecr:GetAuthorizationToken",
        "ecr:BatchCheckLayerAvailability",
        "ecr:GetDownloadUrlForLayer",
        "ecr:PutImage",
        "ecr:InitiateLayerUpload",
        "ecr:UploadLayerPart",
        "ecr:CompleteLayerUpload"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "eks:UpdateKubeconfig",
        "eks:DescribeCluster"
      ],
      "Resource": "arn:aws:eks:*:<ACCOUNT_ID>:cluster/prod-*"
    }
  ]
}
EOF

aws iam put-role-policy \
  --role-name GH-Production-Deployer \
  --policy-name DeployPolicy \
  --policy-document file://deploy-policy.json
```

#### Step 3: Use in GitHub Actions

```yaml
# Inside any workflow job that needs cloud access:
- name: Authenticate to Cloud (OIDC)
  id: auth
  uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: arn:aws:iam::<ACCOUNT_ID>:role/GH-Production-Deployer
    audience: sts.amazonaws.com
    aws-region: us-east-1
```

**What happens at runtime:**
1. GitHub Actions injects a JWT into `${ACTIONS_ID_TOKEN_REQUEST_URL}`
2. The AWS action exchanges this JWT for temporary AWS credentials via `AssumeRoleWithWebIdentity`
3. The credentials are scoped to this specific workflow, this specific run, and inherit the IAM role's policies
4. Credentials expire automatically (default 1 hour, but GitHub revokes immediately after the job completes)

### Conditions That Restrict Access

The trust policy uses condition keys to limit which PRs and branches can assume the role:

| Condition | Effect |
|-----------|--------|
| `pull_request` sub claim | PR previews can only assume preview-specific roles |
| `ref:refs/heads/main` sub claim | Production deploys only from main |
| `ref:refs/tags/v*` sub claim | Release builds can assume release roles |
| `aud: sts.amazonaws.com` | Prevents misconfigured OIDC providers from being trusted |

### GCP / Azure Parity

Same pattern applies:
- **GCP**: Workload Identity Federation → create OAUTH_2 broker → `gcloud iam workload-identity-pools`
- **Azure**: Azure AD App Registration → Federated Credential → `az login --federated-token`

The principle is identical: GitHub generates a short-lived JWT → cloud IDP validates signature + conditions → temporary IAM session returned.

### Why This Beats Long-Lived Secrets

| Approach | Credential Lifetime | Blast Radius | Revocation | Rotation Cost |
|----------|-------------------|--------------|------------|---------------|
| Long-lived secret | Months/years until rotated | Entire account | Immediate (rotate key) | High (update all repos) |
| OIDC federation | Minutes per job | Single workflow run | Automatic (expires) | None |

## Putting It All Together — Branch Protection

Configure GitHub → Settings → Branches → Branch protection rules for `main`:

```
Branch name pattern: main
✓ Require a pull request before merging
  ✓ Require approvals (2)
  ✓ Dismiss stale pull request approvals when new commits are pushed
  ✓ Require review from Code Owners
✓ Require status checks to pass
  ✓ Search for required checks:
    - CI Status
    - Merge Queue Validation
  ✓ Require branches to be up to date before merging
✓ Require conversation resolution before merging
✓ Include administrators
✓ Mark stale reviews as obsolete
✓ Restrict who can push to matching branches
  ✓ Restrict to: team-name-here
```

And under **Pull Requests → Merge queue settings:**
```
Merge method: Squash and merge
Queue maximum depth: 5
Max wait time: 10 minutes
```

This creates the final pipeline: **PR → CI (path-filtered, matrix, sharded) → Request Merge → Merge Queue (fast validation) → Main → Deploy Preview → Approve → Deploy Production**.
