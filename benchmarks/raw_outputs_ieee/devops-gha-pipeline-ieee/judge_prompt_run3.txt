## Workflow 1: CI — Path-Filtered Per App (`ci.yml`)

This is the main gate. Every push and PR runs a single matrix job that filters by changed paths. Apps get a full build+test cycle. Libs only rebuild if their own files change (other apps are fast-failed since libs haven't changed).

```yaml
name: CI

on:
  push:
    branches: [main, 'release/**']
  pull_request:
    branches: [main]

env:
  PNPM_CACHE_FOLDER: .pnpm-store
  NODE_VERSION: '20'

permissions:
  contents: read

jobs:
  # ── Matrix dispatcher: runs one row per app + libs once ──
  changes:
    runs-on: ubuntu-latest
    outputs:
      apps: ${{ steps.filter.outputs.apps }}
      libs: ${{ steps.filter.outputs.libs }}
      any: ${{ steps.filter.outputs.any }}
    steps:
      - uses: actions/checkout@v4
      - uses: dorny/paths-filter@v3
        id: filter
        with:
          filters: |
            apps:
              - 'apps/web-app/**'
              - 'apps/api-server/**'
              - 'apps/admin-panel/**'
            libs:
              - 'libs/**'
              - 'pnpm-lock.yaml'
              - '.github/workflows/ci.yml'

  # ── Core bootstrap: install + cached build, shared by all consumers ──
  bootstrap:
    needs: changes
    if: needs.changes.outputs.any == 'true'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      # ── Cache key design (explained below) ──
      - name: Cache pnpm dependencies
        uses: actions/cache@v4
        with:
          path: |
            .pnpm-store
            **/node_modules
          key: ${{ runner.os }}-pnpm-${{ hashFiles('pnpm-lock.yaml') }}-${{ hashFiles('.nvmrc') }}
          restore-keys: |
            ${{ runner.os }}-pnpm-

      - name: Install system deps (optional, e.g. node-gyp)
        run: sudo apt-get update && sudo apt-get install -y pkg-config libudev-dev

      - uses: pnpm/action-setup@v4
        with: { version: 9 }

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: Install deps
        run: pnpm install --frozen-lockfile

      - name: Build all libs (incremental)
        run: pnpm --filter './libs/**' build

      - name: Upload dependency cache artifact
        uses: actions/upload-artifact@v4
        with:
          name: pnpm-cache
          path: .pnpm-store
          retention-days: 5

  # ── Lint: always runs on every PR, independent of path filters ──
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint

  # ── Type check root workspace ──
  typecheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - run: pnpm typecheck

  # ── Test matrix per app: Node × shard ──
  test-app:
    needs: [changes, bootstrap]
    if: ${{ needs.changes.outputs.apps != '[]' && needs.changes.outputs.apps != '' }}
    strategy:
      fail-fast: false
      matrix:
        app: ${{ fromJSON(needs.changes.outputs.apps) }}
        node-version: [20, 22]
        shard: ['1/4', '2/4', '3/4', '4/4']
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Download pnpm cache
        uses: actions/download-artifact@v4
        with: { name: pnpm-cache }
      - uses: pnpm/action-setup@v4
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - name: Run tests
        env:
          SHARD: ${{ matrix.shard }}
          CI: 'true'
        run: |
          cd ${{ matrix.app }}
          pnpm test -- --ci --shard=${SHARD}

  # ── Lib unit tests ──
  test-lib:
    needs: [changes, bootstrap]
    if: ${{ needs.changes.outputs.libs != '[]' && needs.changes.outputs.libs != '' }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Download pnpm cache
        uses: actions/download-artifact@v4
        with: { name: pnpm-cache }
      - uses: pnpm/action-setup@v4
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - run: pnpm --filter './libs/**' test

  # ── Integration smoke tests (single Node version, no sharding needed) ──
  test-integration:
    needs: [changes, bootstrap]
    if: ${{ github.event_name == 'pull_request' && needs.changes.outputs.any == 'true' }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Download pnpm cache
        uses: actions/download-artifact@v4
        with: { name: pnpm-cache }
      - uses: pnpm/action-setup@v4
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - run: pnpm test:integration
      - name: Upload coverage
        uses: codecov/codecov-action@v4
        with:
          token: ${{ secrets.CODECOV_TOKEN }}
          files: ./coverage/lcov.info
          flags: ci
```

**Why the matrix is structured this way:**

The `dorny/paths-filter` returns JSON arrays like `["apps/web-app", "apps/api-server"]`. By splitting into separate jobs (`test-app` vs `test-lib`), we avoid wasting compute on a matrix row whose app didn't change. The `fromJSON()` call parses the string output into an actual GitHub Actions matrix expression. Sharding distributes Jest/Vitest work across 4 parallel instances within each Node version, so even large test suites finish fast. `fail-fast: false` ensures partial failures don't cancel siblings — we want to know exactly which app/node/shard failed.

## Cache Key Design

The cache strategy uses two independent layers keyed differently:

```yaml
# Deps cache — invalidated ONLY when lockfile or root package.json changes
- uses: actions/cache@v4
  with:
    path: ~/.pnpm-store
    key: pnpm-deps-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml', 'package.json') }}
    restore-keys: |
      pnpm-deps-${{ runner.os }}-

# Build cache — invalidated when lockfile + root package.json + specific workspace content changes
- uses: actions/cache@v4
  with:
    path: |
      ./**/dist/
      ./**/node_modules/.cache/
      apps/web/.next/
      apps/api/.output/
    key: build-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml', 'package.json') }}-${{ hashFiles('apps/web/package.json', 'apps/web/**/*.{ts,tsx}', 'packages/**/*.{ts,tsx}') }}
    restore-keys: |
      build-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml', 'package.json') }}-
```

**Rationale:**

- **Deps cache** is keyed on the lockfile because that's what determines installed package versions. The root `package.json` is added because pnpm overrides and resolution hints live there. Without it, updating pnpm-config in `package.json` wouldn't bust the cache.

- **Build cache** adds workspace-specific content hashes. If only `packages/shared-ui` changes, only the `web` app (which depends on it) gets a fresh build — `api` and `dashboard` reuse their cached builds. The fallback restore key ensures partial cache hits when content changes but the lockfile hasn't.

- **`~/.pnpm-store`** is pnpm's global content-addressable store (equivalent to `node_modules/.pnpm`). Caching it avoids redownloading transitive deps. The `node_modules` in each workspace are symlinks into this store — fast to recreate.

- **`restore-keys`** enable partial cache hits: if an exact match isn't found, the closest prior cache is restored and incremental updates happen. This keeps rebuilds fast even when caches expire.

## OIDC Trust Configuration

### AWS Setup

```bash
# 1. Create OIDC identity provider in AWS
aws iam create-open-id-connect-provider \
  --url https://token.actions.githubusercontent.com \
  --client-id-list sts.amazonaws.com \
  --thumbprint-list 6938fd4d98bab03faadb97b34396831e3780aea1

# 2. Create IAM role with trust policy
cat > trust-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::YOUR_AWS_ACCOUNT:oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
        },
        "StringLike": {
          "token.actions.githubusercontent.com:sub": "repo/YOUR_ORG/YOUR_REPO:environment:production"
        }
      }
    }
  ]
}
EOF

aws iam create-role \
  --role-name gh-actions-deploy \
  --assume-role-policy-document file://trust-policy.json \
  --description "Used by GitHub Actions for production deployments"

# 3. Attach least-privilege permissions (adjust to your services)
aws iam attach-role-policy \
  --role-name gh-actions-deploy \
  --policy-arn arn:aws:iam::policy/ECS-ReadOnly-Policy

# 4. In GitHub repo: Settings > Environments > production
#    Add "Required reviewers" and "Deployment branches: main"
```

### Workflow Integration

```yaml
- name: Configure AWS Credentials
  uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: arn:aws:iam::YOUR_AWS_ACCOUNT:role/gh-actions-deploy
    aws-region: us-east-1
    role-session-name: github-actions-${{ github.run_id }}-${{ github.run_number }}
```

Key security properties:
- **No long-lived keys stored** — GitHub exchanges its JWT for temporary AWS STS credentials
- **Environment-gated** — the trust policy requires `github.ref == refs/heads/main` AND the `production` environment context, so PRs on `feature/*` branches cannot assume the role
- **Session naming** — `github-actions-runID-number` ties each credential session to a specific workflow invocation for audit logging
- **Per-PR isolation** — preview environments use a separate role (`gh-actions-preview`) with scoped permissions to the ephemeral namespace
