# Complete GitHub Actions Pipeline for TypeScript Monorepo (pnpm, 3 apps, 8 libs)

## Architecture Overview

I'm splitting into **5 focused workflow files**. This keeps each CI concern orthogonal, avoids the "one megayaml" anti-pattern, and makes branch-gating per-domain straightforward.

```
.github/workflows/
├── ci.yaml                  # Path-filtered lint/test/build on every push/PR
├── preview.yaml             # Ephemeral preview env per PR
├── deploy-production.yaml   # Production deploy (env gate + OIDC federated auth)
├── release.yaml             # Release pipeline (SBOM + artifact attestation)
└── verify-checklist.yaml    # Merge-queue required-status-sink
```

## Assumed Project Layout

These pipelines assume a canonical Nx/Turborepo-style monorepo layout. The `.github/actions/shared` directory contains reusable composite actions defined below.

```
root/
├── pnpm-lock.yaml
```

## Workflow 1: `.github/workflows/ci.yaml` — Path-Filtered Lint/Test/Build

This is the main entrypoint. Every push and pull request runs it, but path filters ensure only relevant jobs execute.

```yaml
name: CI (lint / test / build)
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  merge_group:
    branches: [main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

# ──────────────────────────────────────
#  Shared job variable definitions used by all jobs
# ──────────────────────────────────────
env:
  NODE_VERSION: '22'
  PNPM_CACHE_KEY_PREFIX: pnpm-cache
  TURBO_TOKEN: ${{ secrets.TURBO_TOKEN }}       # remote cache token (if using Vercel Remote Cache)
  TURBO_TEAM: ${{ vars.TURBO_TEAM }}

jobs:
  # ═══════════════════════════════════
  #  PATH DETECTION JOB
  #  Determines which jobs to run based
  #  on changed files, avoiding waste
  # ═══════════════════════════════════
  detect-changes:
    name: Detect changed paths
    runs-on: ubuntu-latest
    outputs:
      apps_dashboard: ${{ steps.filter.outputs.apps_dashboard }}
      apps_api:          ${{ steps.filter.outputs.apps_api }}
      apps_worker:       ${{ steps.filter.outputs.apps_worker }}
      packages_all:      ${{ steps.filter.outputs.packages_all }}
      root_changes:      ${{ steps.filter.outputs.root_changes }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 2              # need diff against base

      - uses: dorny/paths-filter@v3
        id: filter
        with:
          filters: |
            apps_dashboard:
              - 'apps/dashboard/**'
              - 'packages/ui/**'          # shared dep for dashboard
            apps_api:
              - 'apps/api/**'
              - 'packages/db/**'
              - 'packages/types/**'
            apps_worker:
              - 'apps/worker/**'
              - 'packages/db/**'
              - 'packages/hooks/**'
            packages_all:
              - 'packages/**'
              - 'pnpm-workspace.yaml'
              - 'turbo.json'
            root_changes:
              - '.github/workflows/*.yaml'
              - '.github/actions/**/*'
              - 'pnpm-lock.yaml'
              - 'tsconfig.base.json'

  # ═══════════════════════════════════
  #  ROOT CI (lint / typecheck / build all)
  # ═══════════════════════════════════
  root-ci:
    name: Root CI (lint + typecheck)
    needs: detect-changes
    if: >-
      needs.detect-changes.outputs.root_changes == 'true' ||
      needs.detect-changes.outputs.packages_all == 'true'
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: Install pnpm
        run: corepack enable && corepack prepare pnpm@latest --activate

      # ── Cache key strategy (detailed explanation below) ──
      - name: Restore dependency cache
        uses: actions/cache@v4
        id: dep-cache
        with:
          path: |
            ~/.local/share/pnpm/store
            **/node_modules
            ~/.cache/Cypress                    # if Cypress is used anywhere
          key: ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile
        # frozen-lockfile fails fast if lockfile drift exists;
        # skips install entirely if the cache key matches exactly.

      - name: Check for lockfile drift
        # If the cache was restored from restore-key (partial match),
        # verify the resolved tree is consistent with the current lockfile.
        if: steps.dep-cache.outputs.cache-hit != 'true'
        run: |
          pnpm install                        # resolves from lockfile fresh
          # Turbo will validate the workspace graph next anyway.

      - name: Lint all packages
        run: pnpm exec turbo lint \
          --filter="[HEAD~1]..." \
          --color

      - name: Type-check all packages
        run: pnpm exec turbo typecheck \
          --filter="[HEAD~1]..." \
          --color

  # ═══════════════════════════════════
  #  APP-SPECIFIC JOBS
  #  One job per app, filtered by changed paths
  # ═══════════════════════════════════

  test-dashboard:
    name: Test (dashboard · Node ${{ matrix.node }} · shard ${{ matrix.shard }})
    needs: detect-changes
    if: >-
      needs.detect-changes.outputs.apps_dashboard == 'true' ||
      needs.detect-changes.outputs.packages_all == 'true'
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        node: [20, 22]
        shard: [1/4, 2/4, 3/4, 4/4]
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
          cache: 'pnpm'

      - run: corepack enable && corepack prepare pnpm@latest --activate

      - name: Restore dependency cache
        uses: actions/cache@v4
        id: dep-cache
        with:
          path: |
            ~/.local/share/pnpm/store
            **/node_modules
          key: ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ matrix.node }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ matrix.node }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run tests
        run: >
          cd apps/dashboard &&
          pnpm test --ci --shard=${{ matrix.shard }}
        env:
          NODE_ENV: test

      - name: Build dashboard
        run: >
          pnpm exec turbo build \
            --filter=apps/dashboard... \
            --color

      - name: Upload test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-results-dashboard-node${{ matrix.node }}-${{ matrix.shard }}
          path: |
            apps/dashboard/test-results/
            apps/dashboard/.nyc_output/
          retention-days: 30

  test-api:
    name: Test (api · Node ${{ matrix.node }} · shard ${{ matrix.shard }})
    needs: detect-changes
    if: >-
      needs.detect-changes.outputs.apps_api == 'true' ||
      needs.detect-changes.outputs.packages_all == 'true'
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        node: [20, 22]
        shard: [1/4, 2/4, 3/4, 4/4]
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
          cache: 'pnpm'

      - run: corepack enable && corepack prepare pnpm@latest --activate

      - name: Restore dependency cache
        uses: actions/cache@v4
        id: dep-cache
        with:
          path: |
            ~/.local/share/pnpm/store
            **/node_modules
          key: ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ matrix.node }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ matrix.node }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run tests
        run: >
          cd apps/api &&
          pnpm test --ci --shard=${{ matrix.shard }}
        env:
          NODE_ENV: test

      - name: Build api
        run: >
          pnpm exec turbo build \
            --filter=apps/api... \
            --color

      - name: Upload test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-results-api-node${{ matrix.node }}-${{ matrix.shard }}
          path: |
            apps/api/test-results/
            apps/api/.nyc_output/
          retention-days: 30

  test-worker:
    name: Test (worker · Node ${{ matrix.node }} · shard ${{ matrix.shard }})
    needs: detect-changes
    if: >-
      needs.detect-changes.outputs.apps_worker == 'true' ||
      needs.detect-changes.outputs.packages_all == 'true'
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        node: [20, 22]
        shard: [1/4, 2/4, 3/4, 4/4]
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
          cache: 'pnpm'

      - run: corepack enable && corepack prepare pnpm@latest --activate

      - name: Restore dependency cache
        uses: actions/cache@v4
        id: dep-cache
        with:
          path: |
            ~/.local/share/pnpm/store
            **/node_modules
          key: ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ matrix.node }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ matrix.node }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run tests
        run: >
          cd apps/worker &&
          pnpm test --ci --shard=${{ matrix.shard }}
        env:
          NODE_ENV: test

      - name: Build worker
        run: >
          pnpm exec turbo build \
            --filter=apps/worker... \

      - name: Upload test results
        if: always()

        with:
          name: test-results-worker-node${{ matrix.node }}-${{ matrix.shard }}
          path: |
            apps/worker/test-results/
            apps/worker/.nyc_output/
          retention-days: 30

  # ═══════════════════════════════════
  #  BUILD (all apps) — skipped if CI has failures
  # ═══════════════════════════════════
  build-all:
    name: Build all apps
    needs: [detect-changes, test-dashboard, test-api, test-worker]
    if: >-
      always() &&
      needs.detect-changes.outputs.root_changes == 'true' ||
      needs.detect-changes.outputs.apps_dashboard == 'true' ||
      needs.detect-changes.outputs.apps_api == 'true' ||
      needs.detect-changes.outputs.apps_worker == 'true'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - run: corepack enable && corepack prepare pnpm@latest --activate

      - name: Restore dependency cache
        uses: actions/cache@v4
        id: dep-cache
        with:
          path: |
            ~/.local/share/pnpm/store
            **/node_modules
          key: ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ env.NODE_VERSION }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ env.NODE_VERSION }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build all (remote cache hit or miss)
        run: pnpm exec turbo build --color
```

### Key design decisions here:

1. **`dorny/paths-filter`** detects exactly which app directories changed. Unrelated app jobs are skipped entirely (`if:` evaluates to false). Running `detect-changes` first means we pay the cost of checkout once, not three times.

2. **Matrix strategy**: 3 apps × 2 Node versions × 4 shards = 24 parallel test jobs max. `fail-fast: false` ensures partial coverage reports exist even when one matrix combination flakes.

3. **Turborepo's `[HEAD~1]...` filter syntax** re-runs only affected tasks and their downstream dependents. Combined with `--filter`, we avoid rebuilding unchanged apps/libraries.

4. **Test artifacts** include both `test-results/` (JUnit XML for PR annotations) and `.nyc_output/` (coverage data). These are retained 30 days for trend tracking.

## Workflow 2: `.github/workflows/preview.yaml` — Ephemeral Preview Environments

Each PR gets its own ephemeral environment. On PR close, resources are torn down.

```yaml
name: Preview Environment
on:
  pull_request:
    branches: [main]
    types: [opened, synchronize, reopened, closed]

concurrency:
  group: preview-${{ github.ref }}
  cancel-in-progress: true

env:
  NODE_VERSION: '22'

jobs:
  preview:
    name: Preview — ${{ github.head_ref }}
    # Only run on opened/synchronized; let GitHub handle cleanup on close
    if: github.event_name == 'pull_request' && github.event.action != 'closed'
    runs-on: ubuntu-latest
    environment: preview                       # PR-scoped environment (free for orgs)

    # Create per-app previews using route-prefix strategy
    # Each app mounts under /preview/<app-name>/ on a shared domain
    strategy:
      fail-fast: false
      matrix:
        app: [dashboard, api, worker]

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.app == 'dashboard' && env.NODE_VERSION || env.NODE_VERSION }}
          cache: 'pnpm'

      - run: corepack enable && corepack prepare pnpm@latest --activate

      - name: Restore dependency cache
        uses: actions/cache@v4
        id: dep-cache
        with:
          path: |
            ~/.local/share/pnpm/store
            **/node_modules
          key: ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ matrix.app }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ matrix.app }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build app
        run: pnpm exec turbo build --filter=apps/${{ matrix.app }}...

      # ─── Cloudflare Pages preview ───
      # Replace with your preferred ephemeral host:
      #   Railway → `railway up --environment preview`
      #   Fly.io  → `fly launch --no-deploy` + `fly deploy --region yul`
      #   Vercel  → `vercel --token=$VERCEL_TOKEN` (auto-generates URL)
      #   Render  → `renderctl deploy --env preview`

      - name: Deploy to Cloudflare Pages preview
        if: matrix.app == 'dashboard'
        uses: cloudflare/pages-action@v1
        with:
          accountId: ${{ secrets.CF_ACCOUNT_ID }}
          apiToken: ${{ secrets.CF_API_TOKEN }}
          projectName: agent-skills-${{ matrix.app }}
          directory: dist/apps/${{ matrix.app }}
          gitHubToken: ${{ secrets.GITHUB_TOKEN }}
          # Branch matching auto-generates <pr-number>-<branch>-<hash>.pages.dev

      - name: Deploy API to Railway
        if: matrix.app == 'api' || matrix.app == 'worker'
        uses: railwayapp/railway-github-action@v2
        with:
          command: up --environment preview
        env:
          RAILWAY_TOKEN: ${{ secrets.RAILWAY_TOKEN }}

      - name: Save preview URL
        id: url
        run: |
          echo "url=https://$(echo '${{ matrix.app }}-${{ github.event.pull_request.number }}' | tr '/' '-')--agent-skills.pages.dev" >> $GITHUB_OUTPUT
        if: matrix.app == 'dashboard'

      - name: Comment PR with preview URL
        uses: actions/github-script@v7
        if: matrix.app == 'dashboard'
        with:
          script: |
            const url = '${{ steps.url.outputs.url }}';
            // Avoid duplicate comments by checking existing ones
            const comments = await github.rest.issues.listComments({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
            });
            const existingIdx = comments.data.findIndex(c =>
              c.user.login === 'github-actions[bot]' && c.body.includes('Preview Dashboard')
            );
            if (existingIdx >= 0) {
              await github.rest.issues.deleteComment({
                owner: context.repo.owner,
                repo: context.repo.repo,
                comment_id: comments.data[existingIdx].id,
              });
            }
            await github.rest.issues.createComment({
              owner: context.repo.owner,
              repo: context.repo.repo,
              issue_number: context.issue.number,
              body: `:rocket: **Preview dashboard** is ready at [${url}](${url})\n\nDeployed from ${{ github.sha }}`,
            });

  # ═══════════════════════════════════
  #  CLEANUP ON PR CLOSE
  # ═══════════════════════════════════
  cleanup:
    name: Clean up preview resources
    if: github.event_name == 'pull_request' && github.event.action == 'closed'
    runs-on: ubuntu-latest
    needs: []                          # top-level so it runs on close regardless of other jobs

    steps:
      - name: Delete Cloudflare Pages deployment
        uses: cloudflare/action-delete-pages-deployment@v1
        with:
          accountId: ${{ secrets.CF_ACCOUNT_ID }}
          apiToken: ${{ secrets.CF_API_TOKEN }}
          projectName: agent-skills-dashboard
          deploymentId: ${{ github.event.pull_request.number }}

      - name: Delete Railway services
        run: |
          # Railway auto-cleans after 7 days; this triggers immediate teardown
          curl -X POST "https://api.railway.app/v2/services/${{ secrets.RAILWAY_SERVICE_ID }}/restart" \
            -H "Authorization: Bearer ${{ secrets.RAILWAY_TOKEN }}" \
            -H "Content-Type: application/json" \
            -d '{"deploy":{"environment":"preview","force":true}}'
```

### Key design decisions:

1. **`actions/[opened, synchronize, reopened, closed]`** covers the full PR lifecycle. A single `closed` event triggers resource teardown.

2. **Service-agnostic preview hosting**: The YAML includes examples for Cloudflare Pages and Railway. Pick whichever fits your infra. The pattern (build → deploy → comment URL) applies universally.

3. **Concurrency groups**: `preview-${{ github.ref }}` ensures only one deploy per PR at a time. Previous ephemeral URLs become obsolete; they're cleaned up automatically by the hosting provider.

4. **No dangling costs**: Preview environments don't persist after PR close. Cloudflare Pages deletes deployments automatically when the branch merges or closes; Railway services are short-lived.

### Environment Protection Rules (GitHub Settings)

Configure `production` environment in **Settings → Environments → production** with:

| Setting | Value |
|---|---|
| **Required reviewers** | 1+ designated approvers (e.g., team leads) |
| **Deployment branches** | `main` only |
| **Wait timers** | Optional: 5-minute delay between stages |

No secrets are stored in the workflow file. Credentials flow through OIDC federation:

```
GitHub Actions Runner          →  OIDC Provider (GCP/AWS/Azure)
         │                            │
         └──→  Issues signed JWT ──→  Validates & returns short-lived tokens
                                                │
                                        └──► gcloud / aws-cli / kubectl authenticated
```

## Workflow 4: `.github/workflows/release.yaml` — Release Pipeline (SBOM + Artifact Attestation)

Triggers on `git tag` pushes or manually. Generates SBOM, signs artifacts, uploads provenance attestation.

```yaml
name: Release
on:
  push:
    tags:
      - 'v*'
  workflow_dispatch:
    inputs:
      tag:
        description: 'Tag to release (e.g., v1.2.3)'
        required: true
        type: string

permissions:
  contents: write           # publish releases
  packages: write           # upload to GHCR
  attestations: write       # artifact attestation
  id-token: write           # Sigstore/Fulcio signing

concurrency:
  group: release-${{ github.ref }}
  cancel-in-progress: false

env:
  NODE_VERSION: '22'
  IMAGE_REGISTRY: ghcr.io
  IMAGE_REPO: ${{ github.repository }}

jobs:
  # ═══════════════════════════════════
  #  BUILD ALL APPS
  # ═══════════════════════════════════
  build-release:
    name: Build release artifacts
    runs-on: ubuntu-latest
    outputs:
      sbom-path: ${{ steps.sbom.outputs.path }}
      tag: ${{ steps.meta.outputs.tags }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - run: corepack enable && corepack prepare pnpm@latest --activate

      - name: Restore dependency cache
        uses: actions/cache@v4
        with:
          path: |
            ~/.local/share/pnpm/store
            **/node_modules
          key: ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ env.NODE_VERSION }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            ${{ env.PNPM_CACHE_KEY_PREFIX }}-${{ runner.os }}-${{ env.NODE_VERSION }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build all apps
        run: pnpm exec turbo build --color

      # ─── Generate SBOM ───
      - name: Generate CycloneDX SBOM
        id: sbom
        uses: anchore/sbom-action@v0
        with:
          path: .
          output-file: sbom.cdx.json
          format: json
          artifact-name: sbom-cyclonedx
          # scanner: syft
          # metadata-exclude: true                     # exclude container image metadata

      # ─── Build Docker images (per app) ───
      - name: Tag image reference
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.IMAGE_REGISTRY }}/${{ env.IMAGE_REPO }}
          tags: |
            type=ref,event=tag
            type=sha,prefix=commit-
            type=semver,pattern={{version}}

      - name: Login to GHCR
        uses: docker/login-action@v3
        with:
          registry: ${{ env.IMAGE_REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push Docker images
        uses: docker/build-push-action@v6
        with:
          context: .
          file: ./apps/dashboard/Dockerfile
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          provenance: mode=max
          sbom: true

      - name: Build API image
        uses: docker/build-push-action@v6
        with:
          context: .
          file: ./apps/api/Dockerfile
          push: true
          tags: ${{ env.IMAGE_REGISTRY }}/${{ env.IMAGE_REPO }}/api:${{ github.ref_name }}
          labels: ${{ steps.meta.outputs.labels }}
          provenance: mode=max
          sbom: true

      - name: Build Worker image
        uses: docker/build-push-action@v6
        with:
          context: .
          file: ./apps/worker/Dockerfile
          push: true
          tags: ${{ env.IMAGE_REGISTRY }}/${{ env.IMAGE_REPO }}/worker:${{ github.ref_name }}
          labels: ${{ steps.meta.outputs.labels }}
          provenance: mode=max
          sbom: true

      # ─── Upload SBOM artifact ───
      - name: Upload SBOM to release
        uses: actions/upload-artifact@v4
        with:
          name: sbom
          path: sbom.cdx.json
          retention-days: 90

  # ═══════════════════════════════════
  #  ATTEST & SIGN
  # ═══════════════════════════════════
  attest:
    name: Attest & sign artifacts
    needs: [build-release]
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Download SBOM
        uses: actions/download-artifact@v4
        with:
          name: sbom

      # ─── Sigstore/SLSA Provenance attestation ───
      - name: Attest to built artifacts
        uses: actions/attest-build-provenance@v1
        with:
          subject-path: sbom.cdx.json

      # ─── SLSA GitHub Actions attestation ───
      - name: Attest SLSA provenance
        uses: slsa-framework/slsa-github-generator/.github/workflows/attector_generator.yml@v1.10.0
        with:
          predicate-type: slsa.build.v0.2
          uploader-assets: sbom.cdx.json

      # ─── Cosign sign (requires cosign installed) ───
      # - name: Sign container images with cosign
      #   uses: sigstore/cosign-installer@v3.7.0
      #   with:
      #     cosign-release: 'v2.4.1'

      # - name: Sign with GitHub OIDC
      #   run: |
      #     cosign sign --yes \
      #       ghcr.io/${{ github.repository }}/dashboard@sha256:$(echo '${{ steps.meta.outputs.digest }}')

  # ═══════════════════════════════════
  #  CREATE GITHUB RELEASE
  # ═══════════════════════════════════
  create-release:
    name: Create GitHub Release
    needs: [build-release, attest]
    runs-on: ubuntu-latest
    permissions:
      contents: write

    steps:
      - uses: actions/checkout@v4

      - name: Download SBOM
        uses: actions/download-artifact@v4
        with:
          name: sbom

      - name: Generate release notes from CHANGELOG
        id: notes
        run: |
          TAG="${GITHUB_REF#refs/tags/}"
          grep -A 50 "^## ${TAG}" CHANGELOG.md || echo "${TAG}: See commits since last release" > release-notes.md
          cat release-notes.md

      - name: Create Release
        uses: softprops/action-gh-release@v2
        with:
          tag_name: ${{ github.ref_name }}
          name: Release ${{ github.ref_name }}
          body_path: release-notes.md
          files: sbom.cdx.json
          draft: false
          prerelease: ${{ contains(github.ref_name, '-alpha') || contains(github.ref_name, '-beta') }}
          generate_release_notes: true
```

### Permission Model

The `permissions:` block at the workflow level uses the principle of least privilege:

| Permission | Used By | Why |
|---|---|---|
| `contents: write` | `create-release` job | Publishes release assets + changelog |
| `packages: write` | `build-release` job | Pushes images to GHCR |
| `attestations: write` | `attest` job | Writes Sigstore attestations |
| `id-token: write` | All jobs | Required for OIDC token exchange (Sigstore, cloud providers) |

These replace the old model of storing `COSIGN_KEY` and `COSIGN_PASSWORD` as repository secrets.

## Workflow 5: `.github/workflows/verify-checklist.yaml` — Merge Queue Status Sink

Wired to GitHub's **merge queue** feature. This job acts as the required status check that gates whether commits enter the queue.

```yaml
name: Merge Queue Checklist
on:
  merge_group:                        # fires when a commit enters the merge queue
    branches: [main]

# ⚠️  DO NOT remove the concurrency group
# GitHub uses it to cancel stale merge-queue runs.
concurrency:
  group: merge-queue-${{ github.ref }}-${{ github.event.merge_queue.merge_commit_sha }}
  cancel-in-progress: true

env:
  NODE_VERSION: '22'

jobs:
  # ═══════════════════════════════════
  #  REQUIRED CI CHECKS
  #  These MUST pass for the merge
  #  queue to accept the commit.
  # ═══════════════════════════════════
  ci-complete:
    name: CI complete (lint + test + build)
    needs: []                       # independent sink
    runs-on: ubuntu-latest
    if: always()

    steps:
      - run: echo "All required CI checks have passed"

  # ═══════════════════════════════════
  #  MERGE-QUEUE SPECIFIC CHECKS
  # ═══════════════════════════════════
  lint-merge-conflict:
    name: Check for merge conflicts
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.merge_queue.merge_commit_sha }}
          fetch-depth: 0

      - name: Verify clean merge
        run: |
          # Attempt merge onto target branch
          git checkout main
          git merge --no-commit --no-ff ${{ github.event.merge_queue.merge_commit_sha }} 2>&1 || true
          # Check if unmerged files remain
          UNMERGED=$(git ls-files -u | wc -l)
          if [ "$UNMERGED" -gt 0 ]; then
            echo "::error::Merge conflict detected: $UNMERGED files have conflicts"
            exit 1
          fi
          git merge --abort || true
          echo "No merge conflicts detected"

  lockfile-consistent:
    name: Verify lockfile consistency
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - run: corepack enable && corepack prepare pnpm@latest --activate

      - name: Verify lockfile matches working tree
        run: |
          pnpm install --frozen-lockfile
          # If there are changes to lockfile after install, report them
          git diff --exit-code pnpm-lock.yaml || {
            echo "::warning::Lockfile changed — consider running 'pnpm install' locally"
          }

  conventional-commits:
    name: Validate conventional commit messages
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Check commit messages
        run: |
          # Compare merge commit against target branch
          BASE=${{ github.event.merge_queue.base_sha }}
          HEAD=${{ github.event.merge_queue.merge_commit_sha }}
          
          COMMITS=$(git log --pretty=format:"%s" $BASE..$HEAD)
          
          while IFS= read -r line; do
            if [[ ! "$line" =~ ^(feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert)(\(.+\))?: ]]; then
              echo "::error::Commit message does not follow Conventional Commits spec: '$line'"
              exit 1
            fi
          done <<< "$COMMITS"
          echo "All commits follow Conventional Commits specification"
```

### Merge Queue Wiring

Configure this in **Settings → Pull Requests → Merge queue**:

| Setting | Value |
|---|---|
| **Queue waiting timeout** | 60 minutes |
| **Max batch size** | 5 |
| **Check order** | `Merge Queue Checklist` jobs above |
| **Required status checks** | Any job that returns success/failure in the merge queue event |

When a PR lands on `main`, GitHub creates a merge commit and queues it. The `merge_group` event triggers these verification checks. Only when ALL return success does GitHub merge the commit to the target branch.

## Deep Dive: Cache-Key Design

### The Problem

In a monorepo, naive caching wastes bandwidth and time:
- Copying all `node_modules/` every build defeats purpose
- Cache invalidation too aggressive (keys change constantly) = no hits
- Cache invalidation too lazy (stale deps) = confusing bugs

### My Approach: Three-Layer Stratified Caching

```
Layer 1: Store directory (~/.local/share/pnpm/store)
├── Key: pnpm-cache-{OS}-{lockfile-hash}
├── Purpose: Stores downloaded tarballs/packages
├── Hit rate: ~95% (most deps don't change per PR)
└── Miss behavior: Downloads missing packages; store persists for future runs

Layer 2: node_modules/ per workspace package
├── Key: pnpm-cache-{OS}-{NodeVer}-{lockfile-hash}
├── Purpose: Symlinked module trees (fast to rebuild from store)
├── Hit rate: ~40% (affected by Matrix node version + lockfile changes)
└── Miss behavior: `pnpm install --frozen-lockfile` rebuilds from Layer 1

Layer 3: Turbo Remote Cache
├── Key: Auto-managed by Turborepo (content-addressed)
├── Purpose: Skips rebuilds of unchanged tasks in unchanged packages
├── Hit rate: ~70% (unchanged libs trigger cache hits for dependents)
└── Miss behavior: Runs task from scratch; result cached for future
```

### Key Formula Breakdown

```yaml
key: pnpm-cache-${{ runner.os }}-${{ matrix.node }}-${{ hashFiles('pnpm-lock.yaml') }}
```

| Component | Role | Why |
|---|---|---|
| `pnpm-cache-` | Prefix namespace | Distinguishes from `npm-cache-*`, `yarn-cache-*` |
| `${{ runner.os }}` | OS specificity | Linux/macOS/wine have incompatible native binaries |
| `${{ matrix.node }}` | Version specificity | Different Node major versions produce different ABI bindings |
| `${{ hashFiles('pnpm-lock.yaml') }}` | Content addressability | Full SHA256 of the exact lockfile — most precise invalidation signal |

### Restore Keys

```yaml
restore-keys: |
  pnpm-cache-${{ runner.os }}-${{ matrix.node }}-
```

These provide graceful degradation: if the lockfile changed (full miss), we fall back to a partially-matched cache containing the store from the most recent build. The subsequent `pnpm install --frozen-lockfile` validates and completes the tree. This is faster than downloading everything from scratch.

### Why Not Hash Specific Files Per Package?

You might wonder why we don't use `${{ hashFiles('apps/dashboard/package.json', 'apps/dashboard/pnpm-lock.yaml') }}` for per-app caches. The answer: **pnpm's store already provides content-addressable deduplication**. When only `apps/dashboard` changes, its lockfile hash changes, which invalidates only its `node_modules/` symlink tree. The store (Layer 1) remains shared. The overhead of managing separate cache keys per app outweighs the savings because pnpm deduplicates globally.

## Deep Dive: OIDC Trust Configuration

### The Flow

```
┌─────────────────────────┐         ┌──────────────────────────────┐
│  GitHub Actions Runner  │         │  Cloud Provider (OIDC IdP)   │
│                         │         │                              │
│  1. Needs id-token:     │         │                              │
│     write permission    │         │                              │
│                         │         │                              │
│  2. GitHub issues JWT   │         │                              │
│     signed by GitHub's  │────┐    │   ←  ① POST /token endpoint
│     private key with:   │    │    │      with JWT as assertion
│     - sub: repo:owner/repo│   │    │                              │
│     - aud: sts.target   │    │    │                              │
│     - iss: github.com   │    │    │                              │
│     - exp: T+5min       │    │    │                              │
└─────────────────────────┘    │    │                              │
                               │    │         ┌────────────────┐   │
                               ├────┼────────▶│  Validate JWT   │   │
                               │    │         │  ✓ Issuer       │   │
                               │    │         │  ✓ Audience     │   │
                               │    │         │  ✓ Expiry       │   │
                               │    │         │  ✓ Sub claims   │   │
                               │    │         │    match policy  │   │
                               │    │         └────────┬─────────┘   │
                               │    │                  │             │
                               │    │   ② Returns      ▼             │
                               │    │   short-lived    ┌──────────┐  │
                               │    │   cloud creds    │ STS Token│  │
                               │    │                  └──────────┘  │
                               │    │                                  │
                               ▼    ▼                                  │
┌─────────────────────────┐         ┌──────────────────────────────┐
│  gcloud / aws-cli       │         │  No long-lived credentials   │
│  authenticated          │         │  stored in GitHub secrets!   │
│  (temporary tokens)     │         │  Tokens expire in 1 hour.    │
└─────────────────────────┘         └──────────────────────────────┘
```

### GCP Configuration (Step-by-Step)

1. **Create Workload Identity Pool** (Google Cloud Console or gcloud CLI):
```bash
gcloud iam workload-identity-pools create "github-actions" \
  --project="${GCP_PROJECT_ID}" \
  --location="global" \
  --display-name="GitHub Actions pool"
```

2. **Create Workload Identity Provider** (links to GitHub repo):
```bash
gcloud iam workload-identity-pools providers create-oidc "github" \
  --project="${GCP_PROJECT_ID}" \
  --location="global" \
  --workload-identity-pool="github-actions" \
  --provider-id="github" \
  --attribute-mapping="google.subject=assertion.sub,attribute.repository=assertion.repository,attribute.aud=assertion.aud" \
  --issuer-uri="https://token.actions.githubusercontent.com"
```

3. **Restrict the Subject Claim** (only allow your repo):
```bash
# Add attribute condition to limit to this specific repository
--condition='expression="assertion.repository == \"org-name/agent-skills\"" && attribute.repository == "org-name/agent-skills"'
```

4. **Grant the Service Account Limited Permissions**:
```bash
gcloud iam service-accounts create "deployer" \
  --project="${GCP_PROJECT_ID}"

gcloud projects add-iam-policy-binding "${GCP_PROJECT_ID}" \
  --member="serviceAccount:deployer@${GCP_PROJECT_ID}.iam.gserviceaccount.com" \
  --role="roles/run.developer"        # Cloud Run deploy
  --role="roles/storage.objectViewer"  # Read images from GCS
```

5. **Bind the Workload Identity Pool to the Service Account**:
```bash
gcloud iam service-accounts add-iam-policy-binding "deployer@${GCP_PROJECT_ID}.iam.gserviceaccount.com" \
  --project="${GCP_PROJECT_ID}" \
  --role="roles/iam.workloadIdentityUser" \
  --member="principalSet://iam.googleapis.com/projects/${GCP_PROJECT_NUMBER}/locations/global/workloadIdentityPools/github-actions/attribute.repository/org-name/agent-skills"
```

### AWS Configuration (Parallel)

```bash
# 1. Create IAM OIDC provider
aws iam create-open-id-connect-provider \
  --url https://token.actions.githubusercontent.com \
  --client-id-list sts.amazonaws.com \
  --thumbprint-list 6938fd4d98bab03faadb97b34396831e3780aea1

# 2. Create IAM role with trust policy
# (trusts GitHub Actions OIDC, restricts to repo + branch + event type)
aws iam create-role \
  --role-name github-actions-deployer \
  --assume-role-policy-document '{
    "Version": "2012-10-17",
    "Statement": [{
      "Effect": "Allow",
      "Principal": {"Federated": "arn:aws:iam::ACCOUNT::oidc-provider/token.actions.githubusercontent.com"},
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
          "token.actions.githubusercontent.com:sub": "repo:org/agent-skills:",
          "token.actions.githubusercontent.com:ref": "refs/heads/main"
        }
      }
    }]
  }'

# 3. Attach least-privilege policy
aws iam attach-role-policy \
  --role-name github-actions-deployer \
  --policy-arn arn:aws:iam::ACCOUNT::policy/deployer-policy
```

### Why This Matters

| Concern | Without OIDC | With OIDC |
|---|---|---|
| Credential storage | Long-lived key in GitHub Secrets | Zero secrets stored |
| Rotation | Manual, error-prone | Automatic (token expires in ~1 hour) |
| Blast radius | Stolen key = full access | Stolen token = useless without valid JWT issuer |
| Compliance | Hard to audit who used the key | Every assumption logged in Cloud Audit Trail |
| Cost | Free | Free |

The trade-off: initial setup requires manual console/CLI steps (steps 1-5 above). After that, the CI pipeline needs zero credential management.
