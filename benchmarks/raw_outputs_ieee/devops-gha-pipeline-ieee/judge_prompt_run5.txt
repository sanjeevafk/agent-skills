## Workflow 1: `ci.yml` — Core CI (lint, build, test, path-filtered)

This is the main pipeline, triggered on push and pull_request. It uses **path filtering** so only changed apps/lib re-run their steps. The global job handles setup once; per-app jobs are parallelized.

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

env:
  PNPM_CACHE_FOLDER: .pnpm-store
  NODE_VERSION: "22"

jobs:
  # ────────────────────────────────────────
  # Phase 0 — Global setup (runs ONCE)
  # ────────────────────────────────────────
  setup:
    name: Setup & Cache
    runs-on: ubuntu-latest
    outputs:
      app-matrix: ${{ steps.filter.outputs.apps }}
      lib-matrix: ${{ steps.filter.outputs.libs }}
      node-version: ${{ env.NODE_VERSION }}
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Compute changed-paths sets
        id: filter
        uses: dorny/paths-filter@v3
        with:
          filters: |
            apps:
              - 'apps/**'
            libs:
              - 'packages/**'
              - 'pnpm-lock.yaml'
              - 'tsconfig.base.json'
              - 'turbo/generators/**'

      - name: Extract app names from pnpm-workspace.yaml
        id: apps
        run: |
          APPS=$(yq '.packages' pnpm-workspace.yaml \
            | jq -Rn '[inputs | select(startswith("apps/"))]' \
            | jq -c '.')
          echo "result=$APPS" >> "$GITHUB_OUTPUT"
          # Fallback if yq isn't available
          if [[ -z "$APPS" || "$APPS" == "null" ]]; then
            echo "result=[\"web\",\"api\",\"worker\"]" >> "$GITHUB_OUTPUT"
          fi

      - name: Set up pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 9

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: "pnpm"

      - name: Install dependencies (with full cache warm)
        run: pnpm install --frozen-lockfile

      - name: Upload base cache
        uses: actions/cache/save@v4
        with:
          key: ci-base-${{ github.run_id }}
          # Cache the entire pnpm store and ~/.cache/Cypress or similar dirs
          path: |\
            ${{ env.PNPM_CACHE_FOLDER }}\
            node_modules/.cache

  # ────────────────────────────────────────
  # Phase 1 — Root-level lint
  # ────────────────────────────────────────
  lint:
    name: Lint
    runs-on: ubuntu-latest
    needs: [setup]
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "${{ env.NODE_VERSION }}"
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile
      - run: pnpm run lint --filter "./packages/*" --filter "./apps/*"
        continue-on-error: false

  # ────────────────────────────────────────
  # Phase 2 — Per-app build (path-filtered, cached)
  # ────────────────────────────────────────
  build:
    name: Build (${{ matrix.app }})
    needs: [setup, lint]
    runs-on: ubuntu-latest
    if: needs.setup.outputs.app-matrix == 'true'
    strategy:
      fail-fast: false
      matrix:
        app: [web, api, worker]
    steps:
      - uses: actions/checkout@v4

      # ── Cache: dependency graph ──
      - name: Setup pnpm
        uses: pnpm/action-setup@v4
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "${{ env.NODE_VERSION }}"
          cache: "pnpm"

      # Key = hash of the lockfile + any workspace changes
      - name: Restore pnpm cache
        uses: actions/cache@v4
        id: pnpm-cache
        with:
          path: ${{ env.PNPM_CACHE_FOLDER }}
          key: pnpm-${{ matrix.app }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            pnpm-${{ matrix.app }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      # Key = hash of source + lockfile + turbo state (for TurboRepo-style builds)
      - name: Restore build cache
        uses: actions/cache@v4
        with:
          path: |\
            apps/${{ matrix.app }}/.turbo\
            apps/${{ matrix.app }}/dist\
            apps/${{ matrix.app }}/**/*.d.ts
          key: build-${{ matrix.app }}-${{ hashFiles('pnpm-lock.yaml', 'apps/${{ matrix.app }}/src/**', 'packages/**') }}
          restore-keys: |
            build-${{ matrix.app }}-

      - name: Build libs this app depends on
        run: pnpm run build --filter="./apps/${{ matrix.app }}..." --log-order=stream

      - name: Build the app itself
        run: pnpm run build --filter="${{ matrix.app }}" --log-order=stream

      - name: Upload build artifacts
        uses: actions/upload-artifact@v4
        with:
          name: dist-${{ matrix.app }}
          path: apps/${{ matrix.app }}/dist/
          retention-days: 5

  # ────────────────────────────────────────
  # Phase 3 — Per-app test (sharded, multi-Node)
  # ────────────────────────────────────────
  test:
    name: Test (${{ matrix.app }} / Node ${{ matrix.node }})
    needs: [build]
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        app: [web, api, worker]
        node: [20, 22]
        shard: [1/4, 2/4, 3/4, 4/4]
        exclude:
          # Example: skip sharding for very small test suites
          - app: worker
            shard: "4/4"
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js ${{ matrix.node }}
        uses: actions/setup-node@v4
        with:
          node-version: "${{ matrix.node }}"
          cache: "pnpm"

      - uses: pnpm/action-setup@v4

      - name: Restore pnpm cache
        uses: actions/cache@v4
        with:
          path: ${{ env.PNPM_CACHE_FOLDER }}
          key: pnpm-${{ matrix.app }}-${{ hashFiles('pnpm-lock.yaml') }}

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Download build artifacts for this app
        uses: actions/download-artifact@v4
        with:
          name: dist-${{ matrix.app }}
          path: apps/${{ matrix.app }}/dist

      - name: Run tests (shard ${{ matrix.shard }})
        env:
          NODE_ENV: test
          SHARD_INDEX: ${{ strsplit(matrix.shard, '/')[0] }}
          SHARD_TOTAL: ${{ strsplit(matrix.shard, '/')[1] }}
        run: |
          pnpm run test \
            --filter="${{ matrix.app }}" \
            --log-order=stream \
            ${SHARD_TOTAL:+--shard=${{ matrix.shard }}}

      - name: Upload test coverage
        if: matrix.node == 22 && matrix.shard == '4/4'
        uses: actions/upload-artifact@v4
        with:
          name: coverage-${{ matrix.app }}-node${{ matrix.node }}
          path: apps/${{ matrix.app }}/coverage/
          retention-days: 5

  # ────────────────────────────────────────
  # Gate: wait for all tests before proceeding
  # ────────────────────────────────────────
  ci-gate:
    name: CI Gate
    needs: [lint, test]
    runs-on: ubuntu-latest
    if: always()
    steps:
      - name: Check results
        run: |
          failed=$(( $(jq -r 'any(.result == "failure")' <<< '$(echo "${{ toJSON(needs.*) }}")') || true ))
          cancelled=$(( $(jq -r 'any(.result == "cancelled")' <<< '$(echo "${{ toJSON(needs.*) }}")') || true ))
          echo "Failed: $failed, Cancelled: $cancelled"
          [[ "$cancelled" == "true" ]] && exit 0
          [[ "$failed" == "true" ]] && exit 1
```

## Cache Key Design — Deep Dive

### Strategy: Two-Layer Independent Caches

```
Layer 1: Global node_modules  ←  shared across ALL jobs/workspaces
Layer 2: Per-workspace dist/  ←  independent invalidation per app/lib
```

#### Why Two Layers?

- **`node_modules`** is hoisted at the workspace root by pnpm. One global cache serves every job. No need to re-download 1 GB of tarballs on every step.
- **`dist/`** artifacts live *inside* each workspace. A change to `packages/db-repositories/src/query.ts` should invalidate only `db-repositories/dist` and downstream consumers, not the other seven libs' dist folders. Keeping them independent is a win.

### Layer 1 — Global Dependency Cache

**Exact key:**

```
deps-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml') }}
```

**Fallback:**

```
deps-${{ runner.os }}
```

**Scope:** `{github.repository}` (default, scoped to this org/repo pair).

**Derivation walkthrough (concrete example):**

```
Cache key = deps-Linux-ba3f9c2e1d            (exact hit)
Restore keys = [deps-Linux-ba3f9c2e1d, deps-Linux]
                                             ↑      ↑
                                    exact match  fallback prefix
```

| Scenario | `hashFiles` result | Lookup outcome | Action |
|---|---|---|---|
| First run on main | `ba3f9c2e…` (new) | Miss → saves after `pnpm install --frozen-lockfile` | ✅ Fast install next time |
| Subsequent run, no dep changes | `ba3f9c2e…` (same) | Exact hit → restore in ~2-5 s | ⚡ No network |
| Feature branch adds dep | new hash `c7e1ab…` | Prefix miss → restores old `ba3f9c2e` | 🟡 Partial (must reinstall) |
| Return to main | `ba3f9c2e…` (restored) | Exact hit again | ✅ Restores saved state |

**Why `runner.os` in the key?** Binaries differ between Linux, macOS, Windows (native modules like `sharp`, `bcrypt`). Pinning to OS ensures correctness; the slight penalty of maintaining three OS-scoped cache entries is negligible compared to a wasted install cycle.

### Layer 2 — Per-Workspace Build Cache

**Exact key:**

```
build-${{ matrix.app }}-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml', '**/*.ts', '**/*.tsx') }}
```

**Fallback:**

```
build-${{ matrix.app }}-${{ runner.os }}
```

**Scope:** Same `{github.repository}`.

**Invalidation matrix for a single lib (`packages/db-repositories`):**

| Change | Lockfile hash | Source hash | Cache outcome |
|---|---|---|---|
| Nothing | `ba3f9c2e` | `d4e5f6a7` | Hit (identical key) |
| Edit `query.ts` | `ba3f9c2e` | `b1c2d3e4` | ❌ Miss → rebuild |
| Add dep to root | `f9e8d7c6` | `d4e5f6a7` | ❌ Miss → rebuild |
| Edit unrelated lib | `ba3f9c2e` | `x7y8z9w0` | ⚠️ Hit (key unchanged) — known limitation |

> **Trade-off note:** The source glob `**/*.ts,**/*.tsx` hashes *all* TypeScript files in the repo, which is slightly broader than strictly necessary. On a repo of this size (~50 ms computation) the cost is negligible. If latency grows, narrow to `${{ github.workspace }}/${{ matrix.app }}/**/*.ts`.

### Key Normalization (Multi-Fork Safety)

We deliberately *do not* include `${{ github.workspace }}` in the key — it resolves to `/home/runner/work/owner/repo`, which differs across forks. Using only OS + lockfile hash guarantees cache portability across forks and CI reruns.

## OIDC Federation Trust Configuration

No long-lived cloud credentials ever leave GitHub's control. Instead, GitHub Actions exchanges an OIDC ID token for short-lived STS tokens. Below is the complete trust chain for both major clouds.

### Trust Policy (GCP)

Apply to your target GCP project (or use Terraform / `gcloud`):

```bash
gcloud iam service-accounts add-iam-policy-binding \
  github-deployer@your-project.iam.gserviceaccount.com \
  --project=your-project \
  --role=roles/iam.workloadIdentityUser \
  --member="principalSet://iam.googleapis.com/projects/123456789012/locations/global/workloadIdentityPools/github-actions/providers/github:\
repo:sanjeevafk/my-monorepo:\
head_ref:main,\
environment:production"
```

**Breakdown of the principal selector:**

| Component | Value | Rationale |
|---|---|---|
| `//iam.googleapis.com/.../workloadIdentityPools/github-actions` | Project numeric ID | Isolates pool per GCP project |
| `providers/github` | Provider name | Human-readable label |
| `repo:sanjeevafk/my-monorepo` | Exact match | Rejects all other repos — `principal` alone is too broad |
| `head_ref:refs/heads/main` | Branch restriction | Only main branch can deploy; PRs, feature branches cannot |
| `environment:production` | Env gate | Matches the `env:` block in the workflow |

This produces a **conditional IAM binding** (`google.resourcemanager.v3.Project.IAMConditionalBinding`) evaluated at token exchange time.

### Trust Policy (AWS)

Equivalent IAM trust policy (attach to a role via Terraform / CDK / console):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::123456789012:oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
          "token.actions.githubusercontent.com:sub": "repo:sanjeevafk/my-monorepo"
        }
      }
    },
    {
      "Effect": "Deny",
      "Principal": "*",
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Resource": "arn:aws:iam::123456789012:oidc-provider/token.actions.githubusercontent.com",
      "Condition": {
        "StringNotEquals": {
          "token.actions.githubusercontent.com:sub": [
            "repo:sanjeevafk/my-monorepo:ref:refs/heads/main",
            "repo:sanjeevafk/my-monorepo:pr:refs/pull/*/merge"
          ]
        }
      }
    }
  ]
}
```

**Subject (`sub`) claim variants matched here:**

| GitHub event | `sub` value | Allowed by policy? |
|---|---|---|
| Push to main | `repo:sanjeevafk/my-monorepo:ref:refs/heads/main` | ✅ Yes |
| PR merge (protected) | `repo:sanjeevafk/my-monorepo:pr:refs/pull/42/merge` | ✅ Yes |
| Fork PR | `repo:fork-owner/my-monorepo:ref:refs/heads/main` | ❌ Denied (`StringNotEquals`) |

### Optional Verification Step

Add this inline script before deployment to log the audience and reject mismatches:

```bash
echo "$ACTIONS_ID_TOKEN_REQUEST_VALUE" | base64 -d | python3 -m json.tool | grep -q '"aud":"sts.amazonaws.com"' \
  || (echo "ERROR: Token aud mismatch" >&2; exit 1)

| Property | GCP | AWS |
|---|---|---|

### Cache-Key Design Explained

**Dependency cache (`deps-{os}-node{ver}-{lockfile-hash}`):**

| Layer | Purpose |
|-------|---------|
| `runner.os` | Binaries differ between Linux/macOS/Windows |
| `node20` / `node22` | Native add-ons compiled per Node major version |
| `hashFiles('pnpm-lock.yaml')` | Canonical fingerprint of the exact resolved dependency tree |
| `restore-keys: deps-${{ runner.os }}-node20-` | Partial fallback — restores even if lockfile changed slightly (e.g., post-CI auto-fix), avoiding a full reinstall |
