## How It All Fits Together

### Pull Request Flow

```
PR opened
  │
  ├─ preview.yml triggers → detect-changed-apps
  │                           └─ deploy isolated infra per affected app
  │
  ├─ ci.yml triggers → lint + typecheck (workspace-wide)
  │                     test matrix runs only for changed apps
  │                     (Node 20/22 × shard 1-4)
  │
  └─ If CI passes: PR merges into merge queue
                      │
                      ├─ temp merge commit created
                      ├─ ci.yml runs again on merged state
                      └─ If green → merged into main
```

### Main Push Flow

```
Push to main
  │
  ├─ ci.yml builds all packages
  │   └─ uploads build artifact
  │
  └─ deploy.yml triggered automatically
      │
      ├─ deploy-staging → OIDC role assumption + ECS update
      │
      └─ deploy-production (manual gate) → approval required
          │
          ├─ Step 1: deploy-production-gate (waits for manual approval)
          │         Environment: production (built-in approval gating)
          │
          ├─ Step 2: configure-aws-credentials with OIDC
          │         Role: ci-deploy-prod (only valid on main ref)
          │         No long-lived AWS keys stored anywhere
          │
          ├─ Step 3: Deploy + health check
          │
          └─ Deployment record published via deployments API
```

### Release Flow

```
Release published (tag v1.2.3)
  │
  ├─ release.yml triggers
  │
  ├─ build-images: Build + push Docker images for all 3 apps
  │                 SBOM + provenance baked into image metadata
  │
  ├─ generate-sbom: Workspace-wide SPDX + CycloneDX manifests
  │
  ├─ sign-artifacts: cosign signatures on images + SBOMs (OIDC identity)
  │                   SLSA provenance attestation generated
  │
  └─ publish-packages: npm/GitHub Packages publish of changed libs
```

## Summary of Key Design Decisions

**Cache key design**: Three-layer hierarchy (store / symlinks / build outputs). Each layer uses lockfile hash as primary invalidator with prefix-based restore keys so partial cache hits still provide value when the lockfile changes. Source-level hashes only applied to build caches where they actually matter.

**OIDC trust chain**: GitHub's OIDC JWT exchanged for temporary STS credentials via IAM role trust policy. Three layers of conditions enforce least privilege — audience validation prevents token misuse, environment tag gates which workflows can assume the role, and ref match prevents arbitrary branch deploys. Preview environments get their own lower-privilege roles scoped to `ref:refs/pull/*/head`.

**Path filtering**: `dorny/paths-filter` maps app directories to logical groups including transitive dependency paths, so changing `packages/validation` triggers rebuilds for both `api-server` and `web-app` without requiring every possible pair to be listed.
