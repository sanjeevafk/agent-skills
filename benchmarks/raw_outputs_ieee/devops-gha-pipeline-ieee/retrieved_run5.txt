## Workflow 1: `ci.yml` — Core CI (lint, build, test, path-filtered)

This is the main pipeline, triggered on push and pull_request. It uses **path filtering** so only changed apps/lib re-run their steps. The global job handles setup once; per-app jobs are parallelized.

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main, develop]

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

env:
  PNPM_CACHE_FOLDER: .pnpm-store
  NODE_VERSION: "22"

jobs:
  # ────────────────────────────────────────
  # Phase 0 — Global setup (runs ONCE)
  # ────────────────────────────────────────
  setup:
    name: Setup & Cache
    runs-on: ubuntu-latest
    outputs:
      app-matrix: ${{ steps.filter.outputs.apps }}
      lib-matrix: ${{ steps.filter.outputs.libs }}
      node-version: ${{ env.NODE_VERSION }}
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Compute changed-paths sets
        id: filter
        uses: dorny/paths-filter@v3
        with:
          filters: |
            apps:
              - 'apps/**'
            libs:
              - 'packages/**'
              - 'pnpm-lock.yaml'
              - 'tsconfig.base.json'
              - 'turbo/generators/**'

      - name: Extract app names from pnpm-workspace.yaml
        id: apps
        run: |
          APPS=$(yq '.packages' pnpm-workspace.yaml \
            | jq -Rn '[inputs | select(startswith("apps/"))]' \
            | jq -c '.')
          echo "result=$APPS" >> "$GITHUB_OUTPUT"
          # Fallback if yq isn't available
          if [[ -z "$APPS" || "$APPS" == "null" ]]; then
            echo "result=[\"web\",\"api\",\"worker\"]" >> "$GITHUB_OUTPUT"
          fi

      - name: Set up pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 9

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: "pnpm"

      - name: Install dependencies (with full cache warm)
        run: pnpm install --frozen-lockfile

      - name: Upload base cache
        uses: actions/cache/save@v4
        with:
          key: ci-base-${{ github.run_id }}
          # Cache the entire pnpm store and ~/.cache/Cypress or similar dirs
          path: |\
            ${{ env.PNPM_CACHE_FOLDER }}\
            node_modules/.cache

  # ────────────────────────────────────────
  # Phase 1 — Root-level lint
  # ────────────────────────────────────────
  lint:
    name: Lint
    runs-on: ubuntu-latest
    needs: [setup]
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "${{ env.NODE_VERSION }}"
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile
      - run: pnpm run lint --filter "./packages/*" --filter "./apps/*"
        continue-on-error: false

  # ────────────────────────────────────────
  # Phase 2 — Per-app build (path-filtered, cached)
  # ────────────────────────────────────────
  build:
    name: Build (${{ matrix.app }})
    needs: [setup, lint]
    runs-on: ubuntu-latest
    if: needs.setup.outputs.app-matrix == 'true'
    strategy:
      fail-fast: false
      matrix:
        app: [web, api, worker]
    steps:
      - uses: actions/checkout@v4

      # ── Cache: dependency graph ──
      - name: Setup pnpm
        uses: pnpm/action-setup@v4
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "${{ env.NODE_VERSION }}"
          cache: "pnpm"

      # Key = hash of the lockfile + any workspace changes
      - name: Restore pnpm cache
        uses: actions/cache@v4
        id: pnpm-cache
        with:
          path: ${{ env.PNPM_CACHE_FOLDER }}
          key: pnpm-${{ matrix.app }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            pnpm-${{ matrix.app }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      # Key = hash of source + lockfile + turbo state (for TurboRepo-style builds)
      - name: Restore build cache
        uses: actions/cache@v4
        with:
          path: |\
            apps/${{ matrix.app }}/.turbo\
            apps/${{ matrix.app }}/dist\
            apps/${{ matrix.app }}/**/*.d.ts
          key: build-${{ matrix.app }}-${{ hashFiles('pnpm-lock.yaml', 'apps/${{ matrix.app }}/src/**', 'packages/**') }}
          restore-keys: |
            build-${{ matrix.app }}-

      - name: Build libs this app depends on
        run: pnpm run build --filter="./apps/${{ matrix.app }}..." --log-order=stream

      - name: Build the app itself
        run: pnpm run build --filter="${{ matrix.app }}" --log-order=stream

      - name: Upload build artifacts
        uses: actions/upload-artifact@v4
        with:
          name: dist-${{ matrix.app }}
          path: apps/${{ matrix.app }}/dist/
          retention-days: 5

  # ────────────────────────────────────────
  # Phase 3 — Per-app test (sharded, multi-Node)
  # ────────────────────────────────────────
  test:
    name: Test (${{ matrix.app }} / Node ${{ matrix.node }})
    needs: [build]
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        app: [web, api, worker]
        node: [20, 22]
        shard: [1/4, 2/4, 3/4, 4/4]
        exclude:
          # Example: skip sharding for very small test suites
          - app: worker
            shard: "4/4"
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js ${{ matrix.node }}
        uses: actions/setup-node@v4
        with:
          node-version: "${{ matrix.node }}"
          cache: "pnpm"

      - uses: pnpm/action-setup@v4

      - name: Restore pnpm cache
        uses: actions/cache@v4
        with:
          path: ${{ env.PNPM_CACHE_FOLDER }}
          key: pnpm-${{ matrix.app }}-${{ hashFiles('pnpm-lock.yaml') }}

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Download build artifacts for this app
        uses: actions/download-artifact@v4
        with:
          name: dist-${{ matrix.app }}
          path: apps/${{ matrix.app }}/dist

      - name: Run tests (shard ${{ matrix.shard }})
        env:
          NODE_ENV: test
          SHARD_INDEX: ${{ strsplit(matrix.shard, '/')[0] }}
          SHARD_TOTAL: ${{ strsplit(matrix.shard, '/')[1] }}
        run: |
          pnpm run test \
            --filter="${{ matrix.app }}" \
            --log-order=stream \
            ${SHARD_TOTAL:+--shard=${{ matrix.shard }}}

      - name: Upload test coverage
        if: matrix.node == 22 && matrix.shard == '4/4'
        uses: actions/upload-artifact@v4
        with:
          name: coverage-${{ matrix.app }}-node${{ matrix.node }}
          path: apps/${{ matrix.app }}/coverage/
          retention-days: 5

  # ────────────────────────────────────────
  # Gate: wait for all tests before proceeding
  # ────────────────────────────────────────
  ci-gate:
    name: CI Gate
    needs: [lint, test]
    runs-on: ubuntu-latest
    if: always()
    steps:
      - name: Check results
        run: |
          failed=$(( $(jq -r 'any(.result == "failure")' <<< '$(echo "${{ toJSON(needs.*) }}")') || true ))
          cancelled=$(( $(jq -r 'any(.result == "cancelled")' <<< '$(echo "${{ toJSON(needs.*) }}")') || true ))
          echo "Failed: $failed, Cancelled: $cancelled"
          [[ "$cancelled" == "true" ]] && exit 0
          [[ "$failed" == "true" ]] && exit 1
```

### Cache-Key Design Explained

There are **two distinct cache tiers**, each with purpose-specific keys:

| Tier | What it caches | Key pattern | Strategy |
|------|---------------|-------------|----------|
| **Dependency cache** (`pnpm-cache`) | `pnpm-lock.yaml`-derived installs | `pnpm-{app}-{hash(lockfile)}` | When the lockfile changes, every app gets a fresh install (guaranteed reproducibility). When only source code changes, the existing cached `node_modules` is restored — no reinstall needed. `restore-keys` provide a partial match fallback. |
| **Build cache** (`build-cache`) | `dist/`, `.turbo/`, generated `.d.ts` files | `build-{app}-{hash(lockfile + src/** + packages/**)}` | A content-hash over all relevant sources means only outputs whose inputs changed are invalidated. If only `packages/db` changes, only apps/libs that depend on `db` get evicted from the cache (because the glob hash covers all of `packages/**`). The `restore-keys` prefix `build-{app}-` ensures we always fall back to *some* prior build output rather than rebuilding from nothing. |

**Why `--frozen-lockfile`?** It ensures `pnpm install` fails fast if the lockfile doesn't exactly match what's committed. This is critical for reproducibility — you never want a CI build to silently pick up different transitive deps than local dev does.

**Why per-app cache folders instead of a single global one?** Shared cache suffers from contention when many PRs land simultaneously. Per-app isolation eliminates cross-talk between pipelines. For an 8-lib / 3-app repo the total disk usage is trivial.

## Workflow 2: `preview.yml` — Ephemeral Preview Environments

Creates an isolated preview deploy per Pull Request. Each PR gets its own namespace/environment. Runs on `pull_request` events (and can be triggered manually from Issues).

```yaml
# .github/workflows/preview.yml
name: Preview Environment

on:
  pull_request:
    branches: [main, develop]
    types: [opened, synchronize, reopened]

concurrency:
  group: preview-${{ github.ref }}
  cancel-in-progress: true

env:
  NODE_VERSION: "22"
  REGISTRY: ghcr.io

jobs:
  preview:
    name: Preview (${{ github.event.pull_request.title }})
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    timeout-minutes: 20

    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.sha }}

      - name: Setup pnpm
        uses: pnpm/action-setup@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "${{ env.NODE_VERSION }}"
          cache: "pnpm"

      - name: Log in to Container Registry
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      # ── Build & push Docker images per app ──
      - name: Build Docker images
        run: |
          for app in web api worker; do
            docker build \
              --tag ${{ env.REGISTRY }}/${{ github.repository }}/${app}:pr-${{ github.event.pull_request.number }} \
              --file apps/${app}/Dockerfile \
              .
          done

      # ── Deploy to ephemeral K8s namespace (or Fly.io render previews, etc.) ──
      - name: Configure kubectl (OIDC)
        uses: azure/k8s-set-context@v4
        with:
          method: oidc
          kube-config: ${{ secrets.KUBE_CONFIG }}
          # Alternatively: use azure/acg-actions for cluster login via OIDC

      - name: Deploy preview resources
        env:
          NAMESPACE: pr-${{ github.event.pull_request.number }}
          IMAGE_TAG: pr-${{ github.event.pull_request.number }}
        run: |
          kubectl create namespace $NAMESPACE --dry-run=client -o yaml | kubectl apply -f -

          for app in web api worker; do
            cat <<EOF | kubectl apply -n $NAMESPACE -f -
            apiVersion: apps/v1
            kind: Deployment
            metadata:
              name: $app
            spec:
              replicas: 1
              selector:
                matchLabels:
                  app: $app
              template:
                metadata:
                  labels:
                    app: $app
                spec:
                  containers:
                    - name: $app
                      image: ${{ env.REGISTRY }}/${{ github.repository }}/${app}:${IMAGE_TAG}
                      ports:
                        - containerPort: 3000
            ---
            apiVersion: v1
            kind: Service
            metadata:
              name: $app
            spec:
              selector:
                app: $app
              ports:
                - port: 80
                  targetPort: 3000
            ---
            apiVersion: networking.k8s.io/v1
            kind: Ingress
            metadata:
              name: $app
              annotations:
                nginx.ingress.kubernetes.io/rewrite-target: /
            spec:
              rules:
                - host: pr-${{ github.event.pull_request.number }}.${{ secrets.PREVIEW_DOMAIN }}
              ingressClassName: nginx
            EOF
          done

      - name: Wait for readiness
        run: |
          for i in $(seq 1 30); do
            if kubectl get pods -n pr-${{ github.event.pull_request.number }} \
               -l app=web -o jsonpath='{.items[0].status.conditions[?(@.type=="Ready")].status}' 2>/dev/null | grep -q True; then
              echo "✓ web preview is ready"
              break
            fi
            sleep 10
          done

      - name: Comment PR with preview URLs
        uses: actions/github-script@v7
        with:
          script: |
            const urls = {
              web: `https://pr-${context.issue.number}.${process.env.PREVIEW_DOMAIN}`,
              api: `https://pr-${context.issue.number}.${process.env.PREVIEW_DOMAIN}/api`,
            };
            core.info(JSON.stringify(urls));
            await github.rest.issues.createComment({
              ...context.repo,
              issue_number: context.issue.number,
              body: `🚀 **Preview deployed!**\n\n- Web: ${urls.web}\n- API: ${urls.api}\n\n_${context.payload.pull_request.head.sha.slice(0,7)}_`
            });

  cleanup-preview:
    name: Cleanup Preview
    runs-on: ubuntu-latest
    needs: [preview]
    if: github.event.action == 'closed' || github.event.action == 'unlocked'
    permissions:
      contents: read
    steps:
      - name: Delete namespace
        uses: azure/k8s-deploy@v4
        with:
          method: oidc
          namespace: pr-${{ github.event.pull_request.number }}
          command: delete
```

**Design notes:**

- Each PR gets a dedicated Kubernetes namespace (`pr-{number}`), ensuring zero resource conflicts and easy cleanup.
- The ingress host maps `pr-{number}.{PREVIEW_DOMAIN}` into the preview namespace.
- On PR close/unlock, the namespace is deleted automatically — zero orphaned resources.
- The `docker/login-action` uses `GITHUB_TOKEN` (short-lived, scoped to the repo). No long-lived registry creds.

## Workflow 3: `deploy-production.yml` — Production Deploy with OIDC + Manual Approval

```yaml
# .github/workflows/deploy-production.yml
name: Deploy Production

on:
  push:
    branches: [main]

env:
  REGISTRY: ghcr.io
  NODE_VERSION: "22"

jobs:
  # ──────────────────────────────
  # Job 1: Build + Push Release Image
  # ──────────────────────────────
  release-build:
    name: Build & Push
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
      id-token: write          # ← OIDC token for cloud auth
      security-events: write    # for SARIF uploads
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "${{ env.NODE_VERSION }}"
          cache: "pnpm"

      - name: Login to GHCR
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build & push images
        run: |
          GIT_SHA=${GITHUB_SHA:0:12}
          for app in web api worker; do
            docker build \
              --tag ${{ env.REGISTRY }}/${{ github.repository }}/${app}:${GIT_SHA} \
              --tag ${{ env.REGISTRY }}/${{ github.repository }}/${app}:latest \
              --file apps/${app}/Dockerfile \
              .
            docker push ${{ env.REGISTRY }}/${{ github.repository }}/${app}:${GIT_SHA}
            docker push ${{ env.REGISTRY }}/${{ github.repository }}/${app}:latest
          done

      - name: Upload build provenance (SLSA cosign attestations)
        uses: actions/attest-build-provenance@v2
        with:
          subject-name: ${{ env.REGISTRY }}/${{ github.repository }}
          subject-digest: ${{ steps.docker-metadata.outputs.digest }}

  # ──────────────────────────────
  # Job 2: Generate SBOM
  # ──────────────────────────────
  sbom:
    name: SBOM Generation
    runs-on: ubuntu-latest
    needs: [release-build]
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4

      - name: Generate CycloneDX SBOM
        uses: anchore/sbom-action@v0
        with:
          path: ./
          format: cyclonedx-json
          output-file: sbom.cyclonedx.json
          artifact-name: sbom-cyclonedx

      - name: Generate SPDX SBOM
        uses: anchore/sbom-action@v0
        with:
          path: ./
          format: spdx
          output-file: sbom.spdx.json
          artifact-name: sbom-spdx

      - name: Upload SBOMs
        uses: actions/upload-artifact@v4
        with:
          name: sboms
          path: |\
            sbom.cyclonedx.json
            sbom.spdx.json
          retention-days: 90

  # ──────────────────────────────
  # Job 3: Approve → Production Deploy (OIDC-federated)
  # ──────────────────────────────
  deploy-staging:
    name: Deploy to Staging
    needs: [release-build, sbom]
    runs-on: ubuntu-latest
    environment: staging     # ← environment protection rules
    permissions:
      contents: read
      id-token: write
    steps:
      - name: Configure Cloud Provider (OIDC)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::ACCOUNT_ID:role/github-actions-deploy-role
          aws-region: us-east-1
          # NOTE: No access_key_id / secret_access_key!
          # GITHUB_OIDC -> STS -> AWS IAM Role = zero long-lived keys

      - name: Deploy to staging ECS/K8s
        env:
          EKS_CLUSTER: myapp-staging
          DEPLOYMENT_SHA: ${{ github.sha }}
        run: |
          eksctl utils write-kubeconfig --cluster $EKS_CLUSTER --region us-east-1
          kubectl set image deployment/web web=${{ env.REGISTRY }}/${{ github.repository }}/web:${GITHUB_SHA:0:12}
          kubectl set image deployment/api api=${{ env.REGISTRY }}/${{ github.repository }}/api:${GITHUB_SHA:0:12}
          kubectl set image deployment/worker worker=${{ env.REGISTRY }}/${{ github.repository }}/worker:${GITHUB_SHA:0:12}

      - name: Smoke tests
        run: |
          curl -sf https://staging.${{ secrets.PRODUCTION_DOMAIN }}/healthz || exit 1

  deploy-production:
    name: Deploy to Production
    needs: [deploy-staging]
    runs-on: ubuntu-latest
    environment: production    # ← requires manual approval gate
    permissions:
      contents: read
      id-token: write
    steps:
      - name: Configure Cloud Provider (OIDC)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::ACCOUNT_ID:role/github-actions-prod-deploy-role
          aws-region: us-east-1

      - name: Canary rollout (K8s)
        env:
          CLUSTER: myapp-production
        run: |
          eksctl utils write-kubeconfig --cluster $CLUSTER --region us-east-1
          kubectl rollout pause deployment/web
          kubectl set image deployment/web web=${{ env.REGISTRY }}/${{ github.repository }}/web:${GITHUB_SHA:0:12}
          kubectl scale deployment/web --replicas=1
          # Wait for canary readiness
          kubectl rollout status deployment/web --timeout=300s
          # Promote
          kubectl rollout resume deployment/web
          kubectl scale deployment/web --replicas=5

      - name: Health check
        run: curl -sf https://${{ secrets.PRODUCTION_DOMAIN }}/healthz || exit 1

      - name: Rollback if unhealthy
        if: failure()
        run: |
          kubectl rollout undo deployment/web
          kubectl rollout undo deployment/api
          kubectl rollout undo deployment/worker

      - name: Notify channel
        if: always()
        uses: slackapi/slack-github-action@v1
        with:
          payload: |
            {"text":"$STATUS deploy ${{ github.ref_name }} commit ${{ github.sha }}"}
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}
```

## The OIDC Trust Configuration (No Long-Lived Keys)

Here's the exact cloud-side setup required:

### AWS (the most common example)

**What happens:** GitHub Actions generates a short-lived JWT (OIDC token) signed by `token.actions.githubusercontent.com`. AWS STS exchanges that JWT for temporary AWS credentials via the configured IAM role. Zero stored secrets.

**Step-by-step:**

```bash
# 1. Create an IAM OpenID Connect provider in AWS
aws iam create-open-id-connect-provider \
  --url https://token.actions.githubusercontent.com \
  --client-id-list sts.amazonaws.com \
  --thumbprint-list dca9a75a7e4b1b2e3f4c5d6e7f8a9b0c1d2e3f4a

# 2. Create the IAM roles with trust policies scoped to your repo + branch
cat > prod-trust-policy.json <<'POLICY'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::ACCOUNT_ID:oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
        },
        "StringLike": {
          "token.actions.githubusercontent.com:sub": "repo:your-org/agent-skills:ref:refs/heads/main"
        }
      }
    }
  ]
}
POLICY

aws iam create-role \
  --role-name github-actions-prod-deploy-role \
  --assume-role-policy-document file://prod-trust-policy.json

# 3. Attach least-privilege policy (ECS/K8s update only)
aws iam attach-role-policy \
  --role-name github-actions-prod-deploy-role \
  --policy-arn arn:aws:iam::ACCOUNT_ID:policy/GitHubActionsProdDeploy

# 4. Same pattern for the staging role (different repo ref scope)
cat > staging-trust-policy.json <<'POLICY'
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {
      "Federated": "arn:aws:iam::ACCOUNT_ID:oidc-provider/token.actions.githubusercontent.com"
    },
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringEquals": {
        "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
      },
      "StringLike": {
        "token.actions.githubusercontent.com:sub": "repo:your-org/agent-skills:ref:refs/heads/main"
      }
    }
  }]
}
POLICY
```

**Key points of the trust condition:**

| Condition | Purpose |
|-----------|---------|
| `StringEquals aud` | Rejects tokens targeting non-AWS audiences (prevents cross-service misuse) |
| `StringLike sub` matching `repo:org/repo:ref:refs/heads/main` | Only `main` branch pushes trigger this role. PRs, tags, forks all denied |
| `oidc-provider` ARN | Points specifically to GitHub's issuer — you can have separate providers for GitLab, Bitbucket, etc. |

For **Google Cloud**, the equivalent uses Google's workload identity federation where a service account is linked to a GitHub Actions OIDC identity pool, and for **Azure**, the Azure CLI/provider-login supports `--identity` without any SPNs when running in GitHub Actions.

## The Merge Queue Integration

GitHub Actions merges queues require **all status checks to pass before a PR enters the queue**. Here's how to wire it:

```yaml
# .github/workflows/merge-queue-gate.yml
# This runs exclusively from the merge queue — it must be lightweight
# because the queue evaluates it synchronously.

name: Merge Queue Gate

on:
  # Must match the branch_protection_rules.required_status_checks.contexts
  pull_request_target:
    branches: [main]

jobs:
  # Lightweight smoke test — only verify the merge-commit itself compiles
  # Full CI was already verified by the individual PR checks that got the
  # PR admitted to the queue in the first place.
  quick-check:
    name: Quick Check
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: refs/heads/main   # checkout the current HEAD of main
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "22"
          cache: "pnpm"
      - run: pnpm install --frozen-lockfile
      - run: pnpm run build
      # Do NOT run full tests here — they ran in the per-PR CI
```

### Branch Protection Rules (Repository Settings → Branches → main)

Set these in your repo settings:

```yaml
# Repository Settings → Branches → main
branch_protection:
  required_status_checks:
    strict: true             # branch must be up-to-date before merging
    contexts:                 # list ALL ci.yml statuses that must pass
      - Setup & Cache
      - Lint
      - "Build (web)"
      - "Build (api)"
      - "Build (worker)"
      - "Test (web / Node 20)"
      - "Test (web / Node 22)"
      - "Test (api / Node 20)"
      - "Test (api / Node 22)"
      - "Test (worker / Node 20)"
      - "Test (worker / Node 22)"
      - CI Gate
      - Preview Environment    # optional — preview per PR

  enforce_admins: true
  required_pull_request_reviews:
    dismiss_stale_reviews: true
    required_approving_review_count: 1

  required_linear_history: true
  
  allow_force_pushes: false
  allow_deletions: false

# Merge queue (GitHub's native merge queue):
enable_merge_queue: true
max_merge_queue_delay: 300  # seconds
```

**How it works end-to-end:**

1. Developer opens PR → `ci.yml` runs, spawning 3×2×4=**24 test jobs** + lint + build
2. All status checks turn green → GitHub's merge queue admits the PR
3. When main advances, the queue creates a merge commit and runs `quick-check` against the merged result
4. If `quick-check` passes → commit lands on main
5. Landing on main triggers `deploy-production.yml`:
   - Builds images → pushes to GHCR
   - Generates SBOMs
   - Deploys to staging (automatically)
   - Waits at the **production environment gate** (human clicks "Approve")
   - OIDC federates to cloud provider → deploys canary → health checks → promotes

## Summary of Deliverables

| File | Purpose |
|------|---------|
| `ci.yml` | Lint, build, sharded test matrix (Node 20/22, 4 shards), path-filtered |
| `preview.yml` | Per-PR ephemeral K8s namespaces, docker push, ingress, auto-comment |
| `deploy-production.yml` | Build → SBOM → staging → manual approval → canary prod deploy → rollback |
| `merge-queue-gate.yml` | Lightweight merge-commit verification for native GH merge queues |
| `*.json` trust policies | IAM OIDC trust documents (shown above inline) |

**Cache design:** Two-tier (dependency + build), both keyed on `hashFiles('pnpm-lock.yaml')` with `restore-keys` fallback chains. Lockfile change = clean install + rebuild. Source-only change = cached deps + incremental rebuild.

**OIDC trust:** GitHub JWT → `sts:AssumeRoleWithWebIdentity` → temp AWS credentials, with conditions scoping to `repo:org/repo:ref:refs/heads/main` and `aud: sts.amazonaws.com`. Zero stored secrets.
