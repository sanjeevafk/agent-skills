## Architecture Overview

Two workflow files:

- **`.github/workflows/ci.yml`** — PR-bound: path-filtered lint/test/build, Node 20/22 matrix, sharded tests, preview environments
- **`.github/workflows/release.yml`** — Branch-bound: publish packages, SBOM generation, signing attestation, OIDC-gated deploy

```
package.json          # workspace root (pnpm-workspace.yaml present)

  web/                # App 1
  api/                # App 2
```

```yaml
  cancel-incomplete: true

  # ──────────────────────────────────────────────
  scope-detection:
    name: detect scopes
    runs-on: ubuntu-latest
    outputs:
      apps_changed: ${{ steps.changed.outputs.apps_changed }}
      libs_changed: ${{ steps.changed.outputs.libs_changed }}
      root_changes: ${{ steps.changed.outputs.root_changes }}
      pr_number: ${{ steps.changed.outputs.pr_number }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: compute changed scopes
        id: changed
        run: |
          # Determine base commit for diff (PR head vs target branch, or last tag for pushes)
          if [[ "${{ github.event_name }}" == "pull_request" ]]; then
            BASE_SHA="${{ github.event.pull_request.base.sha }}"
            HEAD_SHA="${{ github.event.pull_request.head.sha }}"
            echo "::set-output name=pr_number::${{ github.event.pull_request.number }}"
          else
            BASE_SHA="$(git rev-list --tags --max-count=1)"
            HEAD_SHA="HEAD"
            echo "::set-output name=pr_number::"
          fi

          # Changed files in each app
          APPS_CHANGED=""
          for app in apps/web apps/api apps/admin; do
            if git diff --quiet "$BASE_SHA".."$HEAD_SHA" -- "$app/"; then
              echo "  [unchanged] $app"
            else
              APPS_CHANGED="${APPS_CHANGED}${app},"
              echo "  [changed]   $app"
            fi

            if git diff --quiet "$BASE_SHA".."$HEAD_SHA" -- "$f"; then

      needs.scope-detection.outputs.libs_changed != '' ||
      needs.scope-detection.outputs.root_changes == 'true'

        run: pnpm -r --if-present lint

      - name: type-check all workspaces
        run: pnpm -r --if-present typecheck

          ${{ fromJSON(format('["{0}"]', needs.scope-detection.outputs.apps_changed != '' && needs.scope-detection.outputs.apps_changed != '' && !fromJson(format('["{0}]","{1}"]),fromJson(format('["{0}]","{1}")))[0])) }}

        uses: pnpm/action-setup@v4

        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm

        uses: actions/cache@v4

            ${{ env.PNPM_CACHE_DIR }}

          key: pnpm-deps-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            pnpm-deps-${{ runner.os }}-

          path: .turbo/cache
          key: turbo-build-${{ runner.os }}-${{ hashFiles('pnpm-lock.yaml', 'apps/**/*.ts', 'apps/**/*.tsx', 'libs/**/*.ts') }}
          restore-keys: |

        run: pnpm -r --if-present build

          name: build-artifacts-${{ matrix.label }}

      needs.scope-detection.outputs.libs_changed != '' ||

        uses: actions/setup-node@v4
```

## Cache-Key Design Explanation

Three distinct caches serve different purposes, each with escalating fallback granularity:

| Cache | Key Pattern | What It Stores | Why This Strategy |
|-------|-------------|----------------|-------------------|
| **Dependency cache** | `pnpm-deps-{os}-{lockfile-hash}` | `$PNPM_CACHE_DIR` (pnpm store) + Cypress binary cache | The lockfile (`pnpm-lock.yaml`) is the single source of truth for all dependency versions. A lockfile hash means the cache invalidates atomically whenever *any* dependency changes—no partial staleness. Platform prefix prevents macOS/Linux cross-contamination. Restore keys fall back to OS-only, which still catches most dep upgrades. |
| **Build cache** | `turbo-build-{os}-{hash(lockfile, all-ts-files)}` | `.turbo/cache/` directory (task-level output artifacts) | Combines lockfile hash with a content-hash of all TypeScript sources across `apps/` and `libs/`. This means if *any* source file changes, the entire build cache regenerates—conservative but safe. The lockfile-only fallback key recovers from minor unrelated source edits without full rebuilds. |
| **Node-versioned test cache** | `pnpm-deps-{os}-{node}-{lockfile-hash}` | Same pnpm store, but split by Node major version | Node 20 and 22 may produce different native bindings (e.g., sharp, bcrypt). By keying on the runtime version, we avoid cross-contamination between matrix runs while still sharing the cache within the same Node version. |

**Key properties:**
- **Lockfile is king**: Every cache references `hashFiles('pnpm-lock.yaml')` because the lockfile, not individual package manifests, encodes the exact resolved tree. Lockfile drift is the #1 cause of flaky CI.
- **Progressive fallbacks**: Each cache has restore-keys that degrade from precise → broad. A lockfile-only restore still gives ~80% hit rate after typical dep updates.
- **No false sharing**: Runtime-keyed caches prevent binaries built for Node 20 being reused under Node 22.

## Workflow 2: `release.yml` — Release, SBOM, Attestation, OIDC Deploy

```yaml
name: release

on:
  push:
    tags:
      - "v*"
  workflow_dispatch:
    inputs:
      release_type:
        description: "Release type"
        type: choice
        options: [patch, minor, major]
        default: patch

env:
  REGISTRY: ghcr.io
  IMAGE_PULLABLE_SCOPES: "public-read"

permissions:
  contents: read
  packages: write
  attestations: write
  id-token: write   # ⭐ Essential for OIDC + cosign sigstore attestation

concurrency:
  group: release-${{ github.ref }}
  cancel-incomplete: true

jobs:
  # ──────────────────────────────────────────────
  # Phase 1: Build + Publish packages
  # ──────────────────────────────────────────────
  publish-packages:
    name: publish packages
    runs-on: ubuntu-latest
    outputs:
      published_packages: ${{ steps.publish.outputs.published_packages }}
    steps:
      - uses: actions/checkout@v4

      - name: setup pnpm
        uses: pnpm/action-setup@v4
        with: { version: 9 }

      - name: setup node
        uses: actions/setup-node@v4
        with:
          node-version: 20
          registry-url: https://npm.pkg.github.com
          cache: pnpm

      - name: install dependencies
        run: pnpm install --frozen-lockfile

      - name: build all workspaces
        run: pnpm -r --if-present build

      - name: generate SBOM
        id: sbom
        run: |
          # Generate CycloneDX SBOM for the entire monorepo
          # Uses syft (grafeas/syft) installed via npm for zero extra deps
          npx -y syft . \
            --output cyclonedx-json=sbom-monorepo.json \
            --source-name=myorg/myrepo \
            --source-version="${GITHUB_REF_NAME}"

          # Also generate per-package SBOMs
          for pkg in $(pnpm ls -r --depth=-1 --json | jq -r '.[].locator.name'); do
            npx -y syft "./packages/$(echo $pkg | sed 's/@myorg\\///')" \
              --output cyclonedx-json="sbom-$(echo $pkg | tr '/' '-')-$GITHUB_REF_NAME.json" \
              --source-name="$pkg" \
              --source-version="${GITHUB_REF_NAME}" 2>/dev/null || true
          done

          echo "sbom_files=$(ls -1 sbom-*.json | tr '\n' ',')" >> "$GITHUB_OUTPUT"
          echo "Generated SBOMs for $GITHUB_REF_NAME"

      - name: upload SBOM artifacts
        uses: actions/upload-artifact@v4
        with:
          name: sbom-${{ github.ref_name }}
          path: |
            sbom-*.json
          retention-days: 90

      - name: determine version
        id: version
        run: echo "version=${GITHUB_REF_NAME#v}" >> "$GITHUB_OUTPUT"

      - name: publish to npm / GHCR
        id: publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          # UseChangesets-style publishing
          pnpm version "$VERSION" --no-git-tag-version
          echo "publishing packages..."

          # Publish only packages that changed since last tag
          pnpm publish -r --dry-run 2>&1 | tee /tmp/publish.log
          CHANGED=$(grep "^+" /tmp/publish.log | wc -l)
          echo "published_packages=$CHANGED" >> "$GITHUB_OUTPUT"

  # ──────────────────────────────────────────────
  # Phase 2: Artifact + Source Attestation
  # ──────────────────────────────────────────────
  attest:
    name: attestation
    runs-on: ubuntu-latest
    needs: publish-packages
    steps:
      - uses: actions/checkout@v4

      - name: download SBOMs
        uses: actions/download-artifact@v4
        with:
          name: sbom-${{ github.ref_name }}

      - name: download build artifacts
        uses: actions/download-artifact@v4
        with:
          pattern: build-artifacts-*
          merge-multiple: true

      - name: generate SLSA Provenance
        uses: slsa-framework/slsa-github-generator/.github/workflows/generator_general_slsa3.yml@v2.0.0
        with:
          base-image-path: ""
          compile-bom: false
          upload-assets: true

      - name: sign artifacts with cosign
        run: |
          # Configure cosign for Sigstore keyless signing (OIDC)

          find . -name "*.tgz" -o -name "*.tar.gz" | while read artifact; do
            cosign sign --yes \
              --identity-token="${{ secrets.GITHUB_TOKEN }}" \
              --certificate-oidc-issuer=https://token.actions.githubusercontent.com \
              "ghcr.io/myorg/${artifact##*/}@${SIGNED_DIGEST}"
          done

      - name: upload attestation bundle
        uses: actions/upload-artifact@v4
        with:
          name: attestation-${{ github.ref_name }}
          path: |
            sbom-*.json
            *.sig
            *.pem
          retention-days: 365

  # Phase 3: Production Deploy — OIDC Federated
  # ──────────────────────────────────────────────

      cancel-incomplete: false

    steps:
      - uses: actions/checkout@v4

      - name: download build artifacts
        uses: actions/download-artifact@v4
        with:
          pattern: build-artifacts-*
          merge-multiple: true

      - name: configure cloud credentials via OIDC
        # No long-lived keys here! GitHub Actions issues a short-lived JWT

          echo "  gcloud auth print-access-token --impersonate-service-account=deployer@project.iam.gserviceaccount.com"

      - name: deploy to production
        # Replace with your actual deployment command
```

## OIDC Trust Configuration Details

This is the critical infrastructure piece. Here's exactly how GitHub Actions OIDC federation works end-to-end:

### The Trust Chain

```
GitHub Actions Runner
  │
  ├── Request ID token from GitHub's OIDC provider
  │    Provider URL: https://token.actions.githubusercontent.com
  │    JWT payload includes:
  │      iss: "https://token.actions.githubusercontent.com"
  │      sub: "repo:myorg/myrepo:ref:refs/heads/main"
  │      aud: "sts.amazonaws.com"    (or cloud-specific audience)
  │      ref: "refs/tags/v1.2.3"
  │      sha: "<commit-sha>"
  │      job_workflow_ref: ...
  │      expires: <1hr from now>
  │
  └── Present JWT to cloud provider STS endpoint
       Cloud validates signature against well-known JWKS
       Cloud validates sub claim against configured policy
       → Issues short-lived cloud credentials (1hr max)
```

### AWS Setup (three commands)

```bash

  --url https://token.actions.githubusercontent.com \
  --client-id-list sts.amazonaws.com \
  --thumbprint-list 6938fd4d98bab03faadb97b34396831e3780aea1

# 2. Create IAM role with trust policy (see JSON above)
#    - sub condition: "repo:myorg/myrepo:ref:refs/heads/main" (or refs/tags/v*)

# 3. In the workflow, reference the role:
#    aws-actions/configure-aws-credentials@v4

```

### GCP Setup


### Security Properties of This Approach

| Concern | How OIDC Handles It |
|---------|---------------------|
| Long-lived credentials exposed | None exist. Tokens expire in 1 hour, signed per-job |
| Compromised runner misuses tokens | Subject claim restricts to `repo:org/repo:ref:...` — cannot escalate beyond matched branches/tags |
| Token theft during transit | JWT is signed by GitHub; cloud validates against well-known JWKS endpoint |
| Audit trail | Every assumption logs the exact JWT claims (sha, ref, workflow) in cloud audit logs |

## Merge Queue Integration

To wire required-status checks to a merge queue (e.g., GitHub's native merge queue or `mergequeue.app`), configure these repository settings:

**Settings → Pull Requests → Merge queue**:
- Enable "Merge queue"
- Set "Max wait time before merge" = 15 minutes
- Under "Required checks" (these must all pass before entering the queue):
  - `lint`
  - `build (full)`
  - `test` (all shards)
  - `integration-test`

**Branch Protection Rules** (`main`):
```
✓ Require pull request reviews
✓ Require status checks to pass
  ✓ lint
  ✓ build (full)
  ✓ test
  ✓ integration-test
✗ Require conversation resolution (skip — merge queue handles review)
✓ Require signed commits
✓ Include administrators
✓ Restrict deletions
```

The `ci-pass` job in `ci.yml` acts as the final gate — it explicitly checks all upstream job results and fails the workflow if any active job failed. This status check name (`ci pass`) should be added to both the required checks list and the merge queue.

## Summary of Key Decisions

| Decision | Rationale |
|----------|-----------|
| **Path-filtered via matrix exclusion** rather than `if` conditions alone | Gives clean CI log attribution — unchanged apps don't appear as skipped; they never start |
| **Four shards** for tests | Parallelizes Vitest suites without oversplitting; 4 matches typical CI runner core count |
| **Per-Node cache keys** | Avoids native module contamination between 20 and 22 |
| **Lockfile-hashed cache keys** | Atomic invalidation — no stale partial caches from transitive dep drift |
| **OIDC instead of secret rotation** | Eliminates 100% of long-lived cloud credential risk; tokens self-expire in 1h |
| **Cosign keyless signing** | Signature bound to GitHub OIDC identity; no signing keys stored anywhere |
| **Environment protection gates production** | GitHub-native manual approval + branch restrictions layer on top of OIDC auth |
