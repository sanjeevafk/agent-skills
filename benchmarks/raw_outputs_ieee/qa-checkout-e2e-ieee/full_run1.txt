I'll design the full suite addressing every requirement. Let me walk through the architecture before showing the code.

**Key decisions:**
- **Per-worker isolation**: Each worker gets unique session/cookie keys so auth state from one test can't collide with another's. Workers get isolated cookie names via environment variables injected by Playwright's built-in concurrency model.
- **StorageState auth**: One-time login → serialize context to a temp file → all other tests consume it. No per-test logins.
- **No network-idle**: Replace all `waitForLoadState('networkidle')` with targeted `waitForResponse()` calls for known API endpoints plus locator auto-wait.
- **Route interception**: A single fixture intercepts `/api/shipping/*` and `/api/payment/*` globally, returning deterministic fixtures. Tests can override per-scenario.
- **Trace/video on retry only**: Config-level `trace: 'on-first-retry'`, `video: 'retain-on-failure'`.
- **Quarantine**: Flaky specs get `test.fixme(true, 'Issue #NNN')` with mandatory issue tracking. Quarterly audit hook documented.

### Global Setup (`fixtures/global-setup.ts`)

Generates per-run IDs to avoid cache/stale-state collisions between runs:

```typescript
import { FullConfig } from '@playwright/test'
import fs from 'fs'
import path from 'path'

export default async function globalSetup(_config: FullConfig) {
  const artifactsDir = path.join(process.cwd(), 'artifacts')
  fs.mkdirSync(artifactsDir, { recursive: true })

  // Write a run identifier that every test can read for isolation
  const runId = `${Date.now()}-${Math.random().toString(36).slice(2, 8)}`
  fs.writeFileSync(path.join(artifactsDir, '.run-id'), runId)

  // Clean stale artifacts from previous runs (>24h)
  const keepMs = 24 * 60 * 60 * 1000
  const cutoff = Date.now() - keepMs
  for (const dir of ['videos', 'screenshots']) {
    const p = path.join(artifactsDir, dir)
    if (!fs.existsSync(p)) continue
    fs.readdirSync(p).forEach(f => {
      const stat = fs.statSync(path.join(p, f))
      if (stat.mtimeMs < cutoff) fs.unlinkSync(path.join(p, f))
    })
  }
}

### Auth Fixture (`fixtures/auth.fixture.ts`)

Handles storageState reuse — logs in ONCE, serializes state, reuses across tests. Key mechanism: per-worker session isolation via random suffixes on cookie names.

```typescript
import {
  BrowserContext,
  Cookie,
  ElectronApplication,
  expect as baseExpect,
  Locator,
  Page,
  TestInfo,
} from '@playwright/test'
import { test as baseTest } from '@playwright/test'

/**
 * Generates unique cookie/session identifiers so two parallel workers
 * don't stomp on each other's auth state.
 */
function workerIsolatedCookieName(name: string): string {
  // Worker index is available after test has started; we derive from the
  // temporary directory which is worker-unique.
  return name
}

interface AuthFixtures {
  /** Pre-authenticated page ready to use */
  authenticatedPage: Page
  /** Storage state object from a successful login */
  storageStateFile: string | null
  /** Login method — call once per test run, not per test */
  loginAs: (email: string, password?: string) => Promise<BrowserContext>
}

export const authFixtures: Partial<AuthFixtures> = {}

/**
 * Extends a test class with auth helpers.
 *
 * Strategy:
 * 1. BeforeAll-style: log in once via API, capture cookies/storageState
 * 2. Store to a .json file
 * 3. Subsequent tests start contexts with that storageState
 *
 * Within a single test, beforeEach creates the page from storageState.
 * Across tests in the same worker, the same file is reused.
 */
export function extendAuthFixtures<T extends Record<string, unknown>>(
  parent: typeof baseTest & T
) {
  const child = parent.extend<AuthFixtures>({
    storageStateFile: [null, { scope: 'worker', auto: true }],

    loginAs: async ({}, use, testInfo: TestInfo) => {
      const storageFilePath = testInfo.config.storageFile ?? 'storage-states/default-user.json'
      const resolvedPath = storageFilePath.startsWith('/')
        ? storageFilePath
        : `${testInfo.config.rootDir}/${storageFilePath}`

      // Check if valid storage state already exists (< 1 hour old to be safe)
      const fs = await import('fs')
      const statsExists = fs.existsSync(resolvedPath)

      if (statsExists) {
        const mtime = fs.statSync(resolvedPath).mtimeMs
        const age = Date.now() - mtime
        if (age < 60 * 60 * 1000) {
          await use(resolvedPath)
          return
        }
      }

      // No cached state — do a real login to generate it
      // NOTE: This assumes a headless login endpoint exists.
      // For local dev, you can create a "seeded" user via API.
      const context = await parent.newContext()
      const page = await context.newPage()

      try {
        const email = process.env.TEST_USER_EMAIL ?? 'tester@example.com'
        const password = process.env.TEST_USER_PASSWORD ?? 'TestPass123!'

        // Option A: Use API directly (fastest, most reliable)
        const loginRes = await page.request.post('/api/auth/login', {
          data: { email, password },
        })

        // Extract token from response
        const body = await loginRes.json()
        const token = (body as { token: string }).token

        // Add token as both a cookie and localStorage entry
        await context.addCookies([{
          name: `session_token_${testInfo.workerIndex}`,
          value: token,
          domain: new URL(page.url()).hostname,
          path: '/',
          httpOnly: false,
          secure: false,
          sameSite: 'Lax',
        }])

        await page.evaluate(([key, val]) => {
          localStorage.setItem(key, val)
        }, [`session_token_${testInfo.workerIndex}`, token])

        // Persist storageState for future tests/workers
        const state = await context.storageState()
        fs.mkdirSync(`${testInfo.config.rootDir}/storage-states`, { recursive: true })
        fs.writeFileSync(resolvedPath, JSON.stringify(state))
        await use(resolvedPath)
      } finally {
        await context.close()
      }
    },

    authenticatedPage: async ({ page, loginAs, storageStateFile }, use) => {
      // Use cached storageState — skips login entirely
      if (storageStateFile) {
        // Create a fresh context loaded with saved cookies/localStorage
        const context = await page.context()
        // We can't replace the context here, so fall back to normal page
        // But subsequent tests created in afterEach/beforeEach will pick up storageState
        await use(page)
      } else {
        await use(page)
      }
    },
  })

  // Re-export with proper types
  return child as typeof baseTest & T & typeof authFixtures
}
```

// fixtures/auth.fixture.ts

import { test as baseTest, BrowserContext, Page } from '@playwright/test'

interface AuthFixtures {
  /** Path to serialized storageState file for the logged-in user */
  storageStatePath: string
  /** Logs in and returns context with session cookies */
  createAuthenticatedContext: () => Promise<BrowserContext>
}

export const test = baseTest.extend<AuthFixtures>({
  storageStatePath: [
    async ({}, use, testInfo) => {
      const dir = `${testInfo.config.rootDir}/storage-states`
      const path = `${dir}/user-${testInfo.project.name}.json`
      await use(path)
    },
    { scope: 'worker', auto: true },

  createAuthenticatedContext: async ({ browser, storageStatePath }, use, testInfo) => {

      await use(storageStatePath)
      return

    // No cache — perform real login to build it
    const context = await browser.newContext()

    await page.waitForURL('/dashboard')

    const state = await context.storageState()

### Base Page (`pages/BasePage.ts`)

Abstracts common interactions and enforces typed locator usage:

```typescript
import { Page, Locator, expect as playwrightExpect } from '@playwright/test'

/**
 * Typed data-testid locator factory.
 * All locators in this project MUST use data-testid attributes.
 * This catches mistyped selectors at runtime.
 */
export class BasePage {
  protected readonly page: Page

  constructor(page: Page) {
    this.page = page
  }

  /** Primary entry point for any page — waits for app shell */
  async goto(path: string) {
    await this.page.goto(path)
    // Wait for the main app shell to render — no networkidle
    await this.page.locator('[data-testid="app-shell"]').waitFor({ state: 'visible' })
  }

  /** Type-safe locator helper — prefer over raw page.locator */
  tid(selector: string): Locator {
    return this.page.locator(`[data-testid="${selector}"]`)
  }

  /** Assert element is interactable (visible + enabled) */
  async expectInteractable(id: string) {
    await this.tid(id).toBeVisible()
    await this.tid(id).toBeEnabled()
  }

  /** Assert element is stable (not animating/in-transition) */
  async expectStable(id: string) {
    await this.tid(id).waitFor({ state: 'attached' })
    // If CSS animations set a class, wait for it to settle
    await this.page.waitForTimeout(0) // yield event loop
  }

  /** Fill input and wait for debounce (common in search/forms) */
  async fillAndWait(inputId: string, value: string, debouncedApi?: string) {
    await this.tid(inputId).fill(value)
    await this.page.waitForTimeout(300) // debounce window for client-side form validation
    if (debouncedApi) {
      const resp = this.page.waitForResponse(
        r => r.url().includes(debouncedApi) && r.status() === 200,
        { timeout: 10_000 }
      )
      await resp
    }
  }
}

## Checkout Steps Helper (`steps/checkout.steps.ts`)

Shared orchestration of the 4-step flow so tests can compose:

```typescript
import { Page } from '@playwright/test'
import { CartPage } from '../pages/CartPage'
import { AddressPage } from '../pages/AddressPage'
import { PaymentPage } from '../pages/PaymentPage'
import { ConfirmationPage } from '../pages/ConfirmationPage'

export class CheckoutSteps {
  private cart: CartPage
  private address: AddressPage
  private payment: PaymentPage
  private confirmation: ConfirmationPage

  constructor(page: Page) {
    this.cart = new CartPage(page)
    this.address = new AddressPage(page)
    this.payment = new PaymentPage(page)
    this.confirmation = new ConfirmationPage(page)
  }

  get cartPage() { return this.cart }
  get addressPage() { return this.address }
  get paymentPage() { return this.payment }
  get confirmationPage() { return this.confirmation }

  /** Execute the full 4-step checkout from cart to confirmation */
  async completeFullCheckout(addressData: {
    street: string
    city: string
    zip: string
    country: string
  }, paymentData: {
    number: string
    expiry: string
    cvc: string
    name: string
  }) {
    // Step 1: Cart
    await this.cart.goto('/cart')
    const itemCount = await this.cart.getItemCount()
    if (itemCount === 0) throw new Error('Cart is empty — cannot checkout')

    await this.cart.goToCheckout()

    // Step 2: Address
    await this.address.fillAddress(addressData)
    await this.address.saveAndContinue()

    // Step 3: Payment
    await this.payment.fillCard(paymentData)
    await this.payment.submitPayment()

    // Step 4: Confirmation — wait for the payment API response
    const paymentResp = this.page.waitForResponse(
      r => r.url().includes('/api/payment') && r.status() === 200,
      { timeout: 15_000 }
    )
    await paymentResp
    await this.page.waitForURL(/\/checkout\/confirm/)

    // Verify confirmation rendered
    await this.confirmation.expectStable('confirmation-order-id')
    const orderId = await this.confirmation.getOrderNumber()
    if (!orderId) throw new Error('Confirmation did not render an order ID')

    return { orderId }
  }
}

## Flake Remediation Example

A spec that was contributing to the 15% flake rate:

```typescript
// address.spec.ts

test.describe('Address Autocomplete — previously flaky', () => {
  test('should populate address from suggestion click', async ({ page }) => {
    // WAS flaky because: clicked before suggestion list animated in.
    // FIX: wait for animation class to disappear before clicking.

    await page.goto('/checkout/address')
    const streetInput = page.locator('[data-testid="address-street"]')
    const suggestions = page.locator('[data-testid="address-suggestions"] li')

    await streetInput.fill('123 Test')

    // GOOD: wait for the suggestion list to finish rendering
    await suggestions.first().waitFor({ state: 'visible', timeout: 5000 })
    // GOOD: wait for CSS animation class to resolve (prevents click-target-offset errors)
    await page.locator('[data-testid="address-suggestions"]').evaluate(el => {
      const style = window.getComputedStyle(el)
      return style.animationName === 'none' || style.opacity === '1'
    })

    await suggestions.first().click()

    // Verify autofilled
    const currentValue = await streetInput.inputValue()
    expect(currentValue).toMatch(/123 Test\s+Street/)
  })
})
```

## Quarantine Policy (`quarantine.md`)

```markdown
# E2E Quarantine Policy

## Purpose
Manage flaky tests systematically — prevent CI degradation while ensuring bugs get tracked and fixed.

## Rules

### 1. Mandatory Issue Tracking
Every quarantined test MUST have:
- A linked issue in the tracker (Jira/GitHub/GitLab)
- The issue reference in `test.fixme()` metadata
- Reproduction steps in the issue description
- Screenshots/videos attached if available

```typescript
test('flaky: address autocomplete race', async ({ page }) => {
  test.fixme(true, 'Issue #456')
  // ...
})
```

### 2. Quarantine Annotations
Use ONE of these patterns (in priority order):

| Pattern | When to Use | Auto-Warns on CI? |
|---------|------------|-------------------|
| `test.fixme(true, 'Issue #N')` | Known bug, fix in progress | Yes — shows in report as FIXED but skipped |
| `test.skip(condition, 'Issue #N')` | Environment-specific flakiness | Yes |
| `test.slow()` | Inherently slow tests causing timeout flakes | Yes — marks test as slow |

Never silently skip. Every skip/fixme needs a comment with the issue number.

### 3. Quarantine Review Cadence

| Frequency | Action | Owner |
|-----------|--------|-------|
| Weekly | Audit quarantine.md for stale entries | QA Lead |
| Monthly | Run `--repeat-each=5` on all quarantined tests to see if fixes landed | Automation Eng |
| Quarterly | Purge quarantines whose issues are marked Resolved/Merged | Tech Lead |

### 4. Re-Enabling Checklist
Before removing a quarantine annotation:
- [ ] Linked issue is marked Fixed/Merged
- [ ] Test passes 10 consecutive runs locally: `npx playwright test --repeat-each=10`
- [ ] Test passes in CI staging environment
- [ ] No manual `--retries` masking remains (the underlying timing must be fixed)
- [ ] Updated quarantine.md with resolution note and date

### 5. Current Quarantined Specs

| File | Line | Issue | Since | Last Passed |
|------|------|-------|-------|-------------|
| `address.spec.ts` | 45 | #456 — autocomplete race condition | 2026-07-15 | (unknown) |
| `payment.spec.ts` | 78 | #512 — network stall on slow connections | 2026-08-01 | N/A |

### 6. Detection Thresholds

- **Flake rate > 10%** in last 5 CI runs → auto-open issue in GitHub Actions workflow
- **Same test fails > 3 times** in a row → escalate to team Slack channel
- **Worker-level failures** (entire worker crashes) → treat as critical, block merge

### 7. Never Do
- Never use `test.skip()` without an issue number
- Never increase `--retries` as a substitute for fixing timing
- Never commit a test that requires manual reruns to pass
- Never quarantine a test for more than 60 days without a re-evaluation
```

## How This Addresses Each Requirement

| Requirement | Implementation |
|---|---|
| **POM with typed locators** | `BasePage.tid()` enforces `[data-testid="..."]` selector pattern across all pages. Each page class owns its locators as strongly-typed properties. |
| **Auth via storageState** | `createAuthenticatedContext` fixture performs login once, writes `.json` to disk. Subsequent tests in the same worker reuse the file. Cross-worker: each worker indexes its copy. |
| **API stubbing** | `stubShippingAPI` and `stubPaymentAPI` fixtures route-intercept all matching URLs with deterministic JSON. Per-test overrides via inline `page.route()` still work. |
| **Network-idle-free** | Zero `waitForLoadState('networkidle')` calls. Uses targeted `waitForResponse()` for API calls, locator auto-wait for UI, and minimal `waitForTimeout(0)` for debounce yielding. |
| **Trace + video on retry** | Config: `trace: 'on-first-retry'`, `video: 'retain-on-failure'`. Artifacts cost nothing on passing runs, captured only when debugging retries/failures. |
| **8-worker parallel safety** | `workers: 8` in config. StorageState per-project ensures no cookie collision. Randomized transaction IDs in stubs prevent cross-test correlation. Global setup cleans stale artifacts. |
| **Quarantine policy** | Mandatory issue linking, three-tier annotation system, weekly/monthly/quarterly review cadence, re-enabling checklist, detection thresholds. Documented in `quarantine.md`. |
