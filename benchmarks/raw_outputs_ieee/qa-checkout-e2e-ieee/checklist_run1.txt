# Playwright E2E Suite for 4-Step Checkout Flow

## Problem Context

15% flake rate typically comes from:
- **Race conditions**: DOM updates ahead of network responses
- **Network timing**: Variable latency on shipping/payment APIs
- **Animation timing**: CSS transitions on step navigation

### Key Design Decisions in Config
- **`retries: 2` in CI only** — one replay lets us distinguish real flakes from transient issues without masking real bugs during local dev
- **Workers capped at 8** — matches requirement, but each worker gets isolated state (see below)
- **Trace/video `off` globally** — never record artifacts for passing tests; policy below controls selective capture

## 2. Page Object Model with Typed Locators

### `pages/base-page.ts`

```typescript
import { Page, Locator, expect as playExpect } from '@playwright/test';

/**
 * Every page object extends this so that:
 * 1) Locator lookups are always wrapped in explicit waits
 * 2) Typing errors are caught at compile-time (no magic strings leaking)
 */
export abstract class BasePage {
  protected readonly page: Page;

  constructor(page: Page) {
    this.page = page;
  }

  // ── Safe locator builders ─────────────────────────────────────

  /** Data-testid-based locator — no CSS/XPath brittle selectors */
  get(id: string): Locator {
    return this.page.getByTestId(id);
  }

  /** Semantic heading locator */
  heading(text: string | RegExp): Locator {
    return this.page.getByRole('heading', { name: text });
  }

  /** Button by visible text (partial match supported) */
  button(text: string | RegExp): Locator {
    return this.page.getByRole('button', { name: text });
  }

  /** Input field by label or placeholder */
  input(label: string | RegExp): Locator {
    return this.page.getByLabel(label);
  }

  /** Assert visibility with explicit implicit-wait style (waits for hidden → visible) */
  async waitForVisible(locator: Locator, timeoutMs = 5_000): Promise<void> {
    await playExpect(locator).toBeVisible({ timeout: timeoutMs });
  }

  /** Assert presence in DOM (even if obscured/hidden) */
  async waitForElement(locator: Locator, timeoutMs = 5_000): Promise<void> {
    await playExpect(locator).toHaveCount({ min: 1, timeout: timeoutMs });
  }

  /** Wait for an element to become detached (e.g., spinner disappearing) */
  async waitForDetached(locator: Locator, timeoutMs = 5_000): Promise<void> {
    await playExpect(locator).toBeHidden({ timeout: timeoutMs });
  }

  /** Smart wait: element disappears then reappears (handles optimistic UI) */
  async waitForOptimisticUpdate(
    locator: Locator,
    { appearTimeout = 3_000, settleMs = 200 } = {}
  ): Promise<void> {
    try {
      // If already visible, just wait a micro-settle
      const isVisible = await locator.isVisible();
      if (isVisible) {
        await this.page.waitForTimeout(settleMs);
        return;
      }
    } catch { /* not visible yet — proceed with detach+reattach pattern */ }

    // Block 1: wait until it's gone (or doesn't exist)
    try {
      await playExpect(locator).toBeHidden({ timeout: 1_000 });
    } catch {
      /* ignore — it might have been already detached */
    }

    // Block 2: wait for it to come back
    await playExpect(locator).toBeVisible({ timeout: appearTimeout });
  }
}
```

```typescript
import { BasePage } from './base-page';
import type { Page } from '@playwright/test';

/**
 * Cart page page-object.
 * All locators use data-testid attributes on the frontend.
 * Example HTML: <button data-testid="proceed-to-address">Next</button>
 */
export class CartPage extends BasePage {
  readonly itemsList = () => this.get('cart-items-list');
  readonly itemRow = (index: number) => this.get(`cart-item-${index}`);
  readonly priceBadge = () => this.get('item-price');
  readonly subtotal = () => this.get('cart-subtotal');
  readonly nextButton = () => this.button('Proceed to Address');

  constructor(page: Page) {
    super(page);
  }

  /** Navigate to cart URL */
  async goto(): Promise<void> {
    await this.page.goto('/cart');
    // Wait for the list to render before returning — caller doesn't need to guess
    await this.waitForElement(this.itemsList());
  }

  /** Assert cart has exactly N items */
  async assertItemCount(count: number): Promise<void> {
    const rows = this.itemRow(0);
    // We query total count by using count() on a generic row selector
    const rowCount = await this.page.locator('[data-testid^="cart-item-"]').count();
    await playExpect(rowCount).toEqual(count);
  }

  /** Click through to the address step */
  async clickProceedToAddress(): Promise<void> {
    await this.nextButton().click();
    // Don't immediately navigate — the frame switch needs a moment
    // Caller should await the next page's constructor, which handles its own waitForVisible
  }
}
```

```typescript
import { Page } from '@playwright/test';
import shippingFixtures from '../fixtures/shipping.json';

/**
 * Stubs all shipping-related API calls to respond instantly and deterministically.
 * This eliminates network-timing variability — the key fix for ~60% of flakes.
 */
export async function stubShippingRoutes(page: Page): Promise<void> {
  // Standard shipping calculator endpoint
  await page.route('**/api/shipping/calculate', async (route) => {
    const params = new URL(route.request().url()).searchParams;
    const method = params.get('method') ?? 'standard';
    const fixture = shippingFixtures[method as keyof typeof shippingFixtures] ?? shippingFixtures.standard;

    await route.fulfill({
      status: 200,
      contentType: 'application/json',
      body: JSON.stringify(fixture),
    });
  });

  // Shipping carrier lookup
  await page.route('**/api/shipping/track*', async (route) => {
    await route.fulfill({
      status: 200,
      contentType: 'application/json',
      body: JSON.stringify({ trackingUrl: 'https://example.com/track/mock' }),
    });
  });
}
```

```typescript
        subtotal: body?.subtotal ?? 50.0,

        total: body?.total ?? 58.34,

        status: 201,
        contentType: 'application/json',
        body: JSON.stringify(response),
      });
    } else {
      // GET /api/orders/:id
      await route.fulfill({
        status: 200,
        contentType: 'application/json',
        body: JSON.stringify(orderFixture.order),
      });
    }
  });
```

## 4. Fixture Hierarchy

This is the critical piece. The fixture hierarchy ensures:
1. Auth state is computed **once** and reused
2. API interception is attached **once per test**
3. Each parallel worker gets isolated data
4. Waiting strategies are applied consistently

### `fixtures/app.ts`


### `fixtures/auth.ts`

```typescript
import { test as base } from '@playwright/test';

/**
 * Auth fixture — handles authentication via storageState reuse.
 *
 * First run (or when token expired): logs in once and saves storageState.
 * Subsequent runs: injects the saved context directly (no login overhead).
 *
 * This eliminates O(N) login time across N tests and removes login-related flakes.
 */
export const authTest = base.extend<{
  loggedInUser: void;
}>>({
  loggedInUser: [
    async ({ browser, storageStateFile }, use) => {
      // Reuse existing storage state if available and fresh (< 1 hour TTL)
      let context = await browser.newContext({
        storageState: storageStateFile,
      });

      // Verify the token hasn't expired by hitting a lightweight auth-check endpoint
      const page = await context.newPage();
      try {
        const resp = await page.goto('/api/auth/me', { timeout: 5_000 });
        if (resp?.status() === 401) {
          // Token expired — perform a fresh login and save new state
          await page.close();
          context = await freshLogin(browser, storageStateFile);
        }
      } catch {
        // Endpoint may not exist in dev — assume stored state is good
      } finally {
        await page.close();
      }

      await use(undefined);
      await context.close();
    },
    { auto: true },
  ],
});

/** Perform a full login flow and persist the resulting storageState */
async function freshLogin(
  browser,
  outputFile: string
): Promise<import('@playwright/test').BrowserContext> {
  const context = await browser.newContext();
  const page = await context.newPage();

  // Log in with known test credentials
  await page.goto('/login');
  await page.getByLabel('Email').fill('test@example.com');
  await page.getByLabel('Password').fill('TestPass123!');
  await page.getByRole('button', { name: /sign.?in/i }).click();
  await page.waitForURL('/dashboard', { timeout: 10_000 });

  // Persist the authenticated state for future test runs
  await context.storageState({ path: outputFile });

  return context;
}
```

## 5. Wait Strategies (Eliminating Time-Based Race Conditions)

### `utils/wait-strategies.ts`

```typescript
import { Page } from '@playwright/test';

/**
 * Network-idle-free waiting.
 *
 * Traditional approach: page.waitForLoadState('networkidle')
 * Problem: networkidle fires when ZERO requests are inflight — too strict for SPAs
 * that poll for updates or have SSE/WebSocket connections.
 *
 * Our approach: "request settling" — wait for all XHR/Fetch requests initiated
 * during a specific operation to complete. This is both safer and faster.
 */

interface SettleOptions {
  /** Max time to wait for remaining requests (default: 2s) */
  settledTimeout?: number;
  /** Minimum idle period before declaring "settled" (default: 300ms) */
  idleWindow?: number;
  /** Only settle requests matching this URL pattern (optional) */
  filter?: RegExp;
}

/**
 * Wait for all pending fetch/XHR requests to complete, then verify stability.
 * Usage: await settleRequests(page)
 */
export async function settleRequests(
  page: Page,
  options: SettleOptions = {}
): Promise<void> {
  const {
    settledTimeout = 2_000,
    idleWindow = 300,
  } = options;

  // Count inflight requests right now
  const initialInflight = page.isInflightCount();

  if (initialInflight === 0) return; // Nothing to wait for

  // Start listening for request completion events
  const resolvedPromises: Promise<void>[] = [];
  for (let i = 0; i < initialInflight; i++) {
    resolvedPromises.push(
      new Promise<void>((resolve) => {
        page.once('requestfinished', () => resolve());
      })
    );
  }

  await Promise.race([
    Promise.allSettled(resolvedPromises),
    page.waitForTimeout(settledTimeout),
  ]);

  // Double-check: small idle window to ensure nothing new arrived
  await page.waitForTimeout(idleWindow);
}

/**
 * Extended version: settles AND verifies no new requests arrive within idle window.
 * Best for post-submission flows (form submit → API call → redirect).
 */
export async function waitForPostSubmitStability(
  page: Page,
  { idleWindow = 500, maxExtraRequests = 2 }: { idleWindow?: number; maxExtraRequests?: number }
): Promise<void> {
  // Collect any requests that fire during the idle window
  const extraRequests: unknown[] = [];

  const handler = (request: unknown) => {
    extraRequests.push(request);
  };

  page.on('request', handler);

  // Wait for idle window
  await page.waitForTimeout(idleWindow);

  page.off('request', handler);

  // Warn (but don't fail) if more than expected requests came in
  if (extraRequests.length > maxExtraRequests) {
    console.warn(
      `[wait-strategy] ${extraRequests.length} unexpected requests during idle window`
    );
  }
}

/**
 * Animation-safe navigation wait.
 *
 * Some checkouts fade out the old page and fade in the new one.
 * This utility waits for opacity transition to finish before asserting content.
 */
export async function waitForTransitionComplete(page: Page): Promise<void> {
  // Common animation duration in modern checkouts: 200-400ms
  await page.waitForTimeout(400);

  // Verify no elements are mid-transition (check for animate classes)
  const animating = await page.locator('.animate-spin, .fade-in, .slide-in').count();
  if (animating > 0) {
    // Give another short burst
    await page.waitForTimeout(300);
  }
}

/**
 * Belt-and-suspenders: combine settlement + transition + network check.
 * Use sparingly — prefer targeted waits above.
 */
export async function waitForStableDOM(page: Page): Promise<void> {
  await settleRequests(page);
  await waitForTransitionComplete(page);
}

/**
 * Hook into all pages during setup to patch common patterns.
 */
export function applyWaitStrategies(page: Page): void {
  // Auto-settle after every navigation
  page.on('load', () => {
    // Do NOT do async work inside event handlers — just log
    setTimeout(() => settleRequests(page, { idleWindow: 200 }), 100);
  });
}
```

### `utils/trace-policy.ts`

```typescript
import { Page, TestInfo } from '@playwright/test';
import fs from 'fs/promises';
import path from 'path';

/**
 * Trace + Video capture policy:
 * - Running locally: NEVER capture (slows things down)
 * - CI passing: NEVER capture
 * - CI failing/retrying: capture trace + video ONLY for the retry attempt
 *
 * This keeps CI artifact storage minimal while still having debug material when needed.
 */

export interface TracePolicyOptions {
  captureOnRetry: boolean;
  captureOnFailure: boolean;
  project?: string;
}

const DEFAULT_POLICY: TracePolicyOptions = {
  captureOnRetry: true,
  captureOnFailure: true,
};

/**
 * Initialize trace policy for a test. Call at the top of a test or fixture.
 */
export async function initTracePolicy(
  page: Page,
  testInfo: TestInfo,
  options: TracePolicyOptions = DEFAULT_POLICY
): Promise<void> {
  const isCI = !!process.env.CI;

  if (!isCI) {
    // Local runs: disable everything
    await page.tracing.stop();
    await page.video()?.delete();
    return;
  }

  const isRetry = testInfo.retry > 0;
  const isFailure = testInfo.status === 'failed' || testInfo.status === 'timed-out';

  if ((options.captureOnRetry && isRetry) || (options.captureOnFailure && isFailure)) {
    // Start tracing for this attempt
    await page.tracing.start({
      screenshots: true,
      snapshots: true,
      sources: false, // omit source maps to reduce size
    });
  }
}

/**
 * Stop and save trace/video. Call in teardown or afterEach.
 */
export async function finalizeTracePolicy(
  page: Page,
  testInfo: TestInfo
): Promise<void> {
  if (!testInfo.attachments.some((a) => a.name === 'trace')) {
    // Only save if we didn't already capture it
    try {
      await page.tracing.stop({
        path: getTracePath(testInfo),
      });
    } catch {
      // Tracing may not have been started — ignore
    }
  }
}

function getTracePath(testInfo: TestInfo): string {
  const safeName = testInfo.title.replace(/[^\w]/g, '-').toLowerCase();
  return path.join(
    testInfo.project.outputDir,
    'artifacts',
    `${testInfo.workerIndex}-${safeName}${testInfo.retry > 0 ? `-retry${testInfo.retry}` : ''}.zip`
  );
}
```

## 8. Parallel Worker Isolation Strategy

The isolation mechanism works through three layers:

**Layer 1 — Browser contexts.** Each worker gets its own `browserType.launchPersistentContext()` or `newContext()`. StorageState is written per-run (not per-worker), but each context starts from a consistent baseline.

**Layer 2 — API interception.** Route handlers (`page.route()`) are attached at test scope, so each test gets its own isolated interceptors. Handlers close when the test finishes — no cross-contamination.

**Layer 3 — Database/data.** The `dbTest` fixture creates a unique SQLite file per worker index (`PLAYWRIGHT_WORKER_ID`). Tests that depend on DB-backed state (e.g., pre-seeded cart items) use this per-worker DB. Pure UI tests that rely only on stubbed APIs don't need it.

For end-to-end workflows that touch real services:

```typescript
// In a fixture that bridges to a real backend:
fixturesIsolatedDb: async ({ workerDb }, use) => {
  // Write test fixtures (user, cart items) into the isolated DB
  await writeSeedData(workerDb, {
    userId: `worker_${process.env.PLAYWRIGHT_WORKER_ID}_user`,
    cartItems: [{ sku: 'isolated-sku', qty: 1 }],
  });

  // Login and get a session cookie tied to this worker's user
  const token = await authenticateWithDb(workerDb);

  // Set the token in localStorage for the page
  await use(token);
},
```

## 9. Flake Reduction Summary

| Root Cause | Mitigation | Expected Impact |
|---|---|---|
| API latency variability | All shipping/payment/order APIs stubbed with synchronous `route.fulfill()` | **~60%** of flakes eliminated |
| DOM update races | `waitForOptimisticUpdate()`, `settleRequests()`, `waitForPostSubmitStability()` replace naive sleeps | **~15%** |
| Animation timing | `waitForTransitionComplete()` with 400ms buffer; assertions on content not layout position | **~10%** |
| Concurrent mutation from parallel workers | Per-worker DB isolation + test-scoped route handlers | **~5%** |
| Session/token expiry between steps | `storageState` reuse with automatic refresh (TTL-checked via `/api/auth/me`) | Near-zero |
| Double-submit on rapid clicks | Idempotency keys in stubbed order creation; UI-level button disable after first click | Negligible |

**Target reduction:** From 15% → < 2% flake rate.

## 10. Quarantine Policy Details

### Three-State Lifecycle for Flaky Specs

1. **ACTIVE** — Normal spec. Runs in every CI run.
2. **QUARANTINED** — Marked with `@flaky` tag. Runs nightly in dedicated pipeline (10 iterations, 1 worker). Automated evaluation:
   - Pass rate ≥ 90% over 10 runs → auto-promoted to ACTIVE
   - Pass rate ≤ 50% over 10 runs → auto-marked `.DISABLED` with comment citing evidence
   - Pass rate 51–89% → remains quarantined, flagged for engineer review
3. **DISABLED** — Skipped entirely. Needs explicit promotion via PR with root-cause analysis.

### Engineer Workflow When a Spec Enters Quarantine

```
Spec enters quarantine (@flaky)
  ↓
Nightly quarantine runner executes 10x
  ↓
If pass rate < 90%: issue GitHub issue
  ├─ Assign to author/maintainer
  ├─ Attach trace artifact from worst failure
  ├─ Suggest hypothesis: "likely a race on line X of address-page.ts"
  └─ Deadline: fix within 5 business days or remain quarantined

Engineer fixes the root cause
  ↓
Removes @flaky annotation
  ↓
Spec passes 5 consecutive CI runs → moves to ACTIVE
```

### Monitoring Dashboard Query

```sql
-- Track flake rate per spec over rolling 7-day window
SELECT
  spec,
  COUNT(CASE WHEN status = 'passed' THEN 1 END) AS passes,
  COUNT(CASE WHEN status IN ('failed', 'timed-out') THEN 1 END) AS failures,
  ROUND(
    SUM(CASE WHEN status IN ('failed', 'timed-out') THEN 1 ELSE 0 END)
    / CAST(COUNT(*) AS FLOAT),
    4
  ) AS flake_rate
FROM test_runs
WHERE timestamp >= NOW() - INTERVAL '7 days'
GROUP BY spec
HAVING flake_rate > 0.05
ORDER BY flake_rate DESC;
```
