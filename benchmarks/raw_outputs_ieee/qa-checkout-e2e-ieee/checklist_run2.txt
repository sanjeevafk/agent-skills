## Root-Cause Analysis of Typical Flakeness

| Symptom | Root Cause | Fix Applied Here |
|---|---|---|
| Random `TimeoutError` on button click | Race between API response and DOM update | Explicit `expect(locator).toBeVisible()` instead of hardcoded `setTimeout` |
| Tests pass singly, fail 8-wide | Shared localStorage / cart race condition | Per-worker `storageState` isolated in worker-scoped temp dirs |
| Intermittent 404s on `/api/ship` | Async background requests still inflight | Route interception swallows network; page waits on locator, not network |
| Traces grow repo to GBs | Artifacts captured even on first-pass success | Artifacts disabled by default; enabled on `--retries > 0` only |
| CI fails on timing-dependent steps | Animation transitions not finished | CSS `prefers-reduced-motion` forced via browser context; explicit animation-end events |

### Why `getWorkerStoragePath()` matters

Each of the 8 workers gets its own `storageState` JSON file, preventing cross-worker data collisions. Two workers sharing one file would mean Worker A's login state gets wiped by Worker B's teardown.

## File 2: `utils/worker-storage.ts`

```typescript
import { randomUUID } from 'crypto';
import os from 'os';
import path from 'path';

/**
 * Returns a unique .storageState.json path per worker process.
 * Playwright forks workers into separate Node processes, so we can
 * derive identity from PID + a UUID seeded at module load.
 */
let _workerId: string;

if (!_workerId) {
  _workerId = `${process.pid}-${randomUUID().slice(0, 8)}`;
}

export function getWorkerStoragePath(): string {
  const tmpDir = path.join(os.tmpdir(), 'pw-e2e-workers');
  return path.join(tmpDir, `${_workerId}.storageState.json`);
}

/**
 * Generates a worker-scoped order ID so stubbed APIs don't collide
 * on order-number uniqueness within the same test run.
 */
export function generateWorkerOrderPrefix(): string {
  return `_W${_workerId.slice(0, 4)}`;
}
```

## File 5: `pages/page-object.ts` (Base)

```typescript
import { Page, Locator, expect as playExpect } from '@playwright/test';

/**
 * Base page object providing typed helper primitives.
 * Every page class extends this for consistent interaction patterns.
 */
export abstract class BasePage {
  readonly page: Page;

  constructor(page: Page) {
    this.page = page;
  }

  /** Navigate and wait for the next navigation cycle (not networkidle). */
  async goto(path: string, options?: Parameters<Page['goto']>[1]) {
    return this.page.goto(`${path}`, {
      waitUntil: 'domcontentloaded',
      ...options,
    });
  }

  /**
   * Waits for a locator to be visible AND stable (animation settled).
   * Uses elementAtPosition approach internally — avoids the racy
   * waitForElementState('stable') which sometimes fires mid-transition.
   */
  async expectStable(locator: Locator, message?: string) {
    await playExpect(locator).toBeVisible({ timeout: 10_000 });
    // Force CSS transition end by polling offsetHeight stability
    await this.waitForStability(locator);
  }

  private async waitForStability(locator: Locator, frames = 3): Promise<void> {
    for (let i = 0; i < frames; i++) {
      const handle = await locator.elementHandle();
      if (!handle) return;
      const prev = await handle.evaluate(el => el.getBoundingClientRect());
      await this.page.waitForTimeout(50); // minimal frame skip
      const next = await handle.evaluate(el => el.getBoundingClientRect());
      if (prev.top === next.top && prev.left === next.left) return;
    }
  }

  /** Click with auto-wait: actionability check (attached, visible, etc.) */
  async clickWithAutoWait(locator: Locator) {
    await locator.click({ force: false }); // force:false triggers actionability checks
  }

  protected expect = playExpect;
}
```

## File 13: `utils/trace-on-retry.ts`

```typescript
import { TestInfo, FullConfig } from '@playwright/test';

/**
 * Conditionally enables traces/video for a test run.
 * Called from inside test hooks to gate artifact collection.
 */
export function traceOnRetry(testInfo: TestInfo): void {
  if (testInfo.retry === 0) {
    // First pass — disable expensive artifact capture
    // Playwright's default 'retain-on-failure' handles green runs automatically.
    // This function exists as an explicit annotation for readability.
    testInfo.annotations.push({
      type: 'artifact-policy',
      description: 'Traces/video captured only on failure or retry',
    });
    return;
  }

  // On retry — ALWAYS capture full trace for debugging
  testInfo.annotations.push({
    type: 'artifact-policy',
    description: `Retry #${testInfo.retry} — full trace enabled`,
  });
}

/**
 * Programmatic override: forcibly enable trace capture for a given context.
 * Useful when a test decides mid-run it needs diagnostics.
 */
export async function forceTraceCapture(context: { screenshots: boolean; trace: 'on'|'off' }): Promise<void> {
  // Note: Playwright doesn't support toggling trace mid-test after config lock.
  // This function exists as documentation of intent and can be extended if
  // using `context.tracing.start()` manually.
  if (config.trace === 'on' || config.retries > 0) {
    context.trace = 'on';
  }
}

const config: { trace: 'on' | 'off'; retries: number } = {
  trace: 'on', // simplified; actual value comes from playwright.config.ts
  retries: 2,
};
```

```typescript
/*
 * Each test follows this pattern to eliminate flakeness:
 *
 * 1. stub ALL external APIs before navigation
 * 2. navigate to the starting page
 * 3. assert on LOCATOR STATE (not network state)
 * 4. interact with deterministic clicks/fills
 * 5. assert on the NEXT page's locators
 *
 * NO setTimeout. NO waitForLoadState('networkidle'). NO polling loops.
 */

test.describe('4-Step Checkout Flow', () => {
  // Run all API stubs globally for this describe block
  test.beforeEach(async ({
    stubPaymentSuccess,
    stubShippingOptions,
    stubCartData,
    cartPage,
  }) => {
    stubCartData(VALID_CART);
    await stubPaymentSuccess();
    await stubShippingOptions();
  });

  // ── Scenario 1: Happy path ────────────────────────────
  test('completes checkout successfully', async ({
    page,
    cartPage,
    addressPage,
    paymentPage,
    confirmationPage,
    initAuth,
    workerOrderPrefix,
  }) => {
    // Step 0: Authenticate once (state saved to worker-scoped storageState)
    await initAuth();

    // Step 1: Cart
    await cartPage.goto();
    await cartPage.expectCartLoaded(3);
    await cartPage.expectProceedButtonClickable();
```

```typescript
/**

  /** Assert a locator matches expected text with strict mode (exactly one element). */
  text: async (locator: Locator, expected: string) => {
```

## Architecture Summary

### Fixture Hierarchy

```
test (baseTest from @playwright/test)
 └── test (base.fixture.ts)          ← browser → context → page → workerOrderPrefix → initAuth → clearWorkerIsolation
      └── test (api-mock.fixture.ts)  ← stubPaymentSuccess/stubPaymentDecline/stubShippingOptions/stubCartData/interceptAllApiCalls
           └── test (checkout-fixture.ts) ← cartPage | addressPage | paymentPage | confirmationPage
```

Each level composes upward. A test importing from `checkout-fixture.ts` receives **everything**: browser instance, authenticated context, all three page objects, and all four API stubs. No imports required beyond one line.

### Waiting Strategy Comparison

| Old Approach (Flaky) | New Approach (Deterministic) |
|---|---|
| `page.waitForLoadState('networkidle')` | `expectStable(locator)` — asserts DOM state |
| `await page.waitForTimeout(2000)` | Spinner visibility assertion (`expect(spinner).not.toBeVisible()`) |
| `page.click()` without guard | `clickWithAutoWait()` — actionability check embedded |
| Hardcoded delays between steps | Locator-based sequencing — each step waits for its trigger element |
| Relying on CSS transition completion | Forced `prefers-reduced-motion` header + explicit stability poll |

### Parallel Safety Mechanisms

```
Worker 0 ──► .storageState-W0-abc123.json ──► Order prefix: _W0abc
Worker 1 ──► .storageState-W1-def456.json ──► Order prefix: _W1def
...
Worker 7 ──► .storageState-W7-ghi789.json ──► Order prefix: _W7ghi
```

- Each worker gets a unique `storageState` file in OS temp dir — no shared writable state
- Order IDs in stubbed responses carry the worker prefix → confirmation page assertions don't collide
- LocalStorage cleanup between tests strips only checkout-scoped keys; auth tokens persist within a test chain
- `fullyParallel: true` is safe because no two workers read/write the same file or modify the same page

### Quarantine Policy

```
Detection in main suite ──► Fail count ≥ 2 in last 10 runs
         │
         ▼
Rename: checkout.spec.ts → checkout.quarantine.spec.ts
         │
         ▼
Drops into 'quarantine' project: sequential, retries=0, full traces+video
         │
         ▼
Root cause found & fix applied ──► Rename back → checkout.spec.ts
         │
         ▼
Rejoins main 8-worker suite with full retry budget (2 retries)
```

Flaky spec failure counts are excluded from the main-suite pass-rate dashboard — they feed a separate "debt tracker" that tracks which specs have been quarantined and for how long, surfacing aging quarantine candidates for prioritization.
