## 2. `playwright.config.ts` — Core Config

```typescript
import { defineConfig, devices } from '@playwright/test'

export default defineConfig({
  testDir: './tests/e2e',

  // Parallelism
  fullyParallel: true,
  workers: 8,                     // safe parallel with per-worker isolation
  forbidOnly: !!process.env.CI,

  // Retries: only after first failure → triggers trace/video capture
  retries: process.env.CI ? 2 : 0,

  // Artifacts: ONLY on retry (never on pass-first-try).
  // This keeps artifact bloat near zero while keeping debug data available.
  use: {
    baseURL: process.env.BASE_URL || 'http://localhost:3000',
    trace: 'on-first-retry',       // captured only when retried
    screenshot: 'only-on-failure',
    video: 'retain-on-first-retry',// same gate as trace
    actionTimeout: 8_000,
    navigationTimeout: 30_000,
    // Typed locator strategy defaults
    locatorStrategy: 'css',
  },

  expect: {
    timeout: 10_000,
  },

  reporter: [
    ['html', { open: 'never', outputFolder: 'playwright-report' }],
    ['junit', { outputFile: 'playwright-results.xml' }],
    // Custom reporter snippet for summary line
    ['list'],
  ],

  // Pre-create browser context once; each worker gets its own copy.
  // The stored cookie/token from one login suffices for every test.
  globalSetup: require.resolve('./global-setup.ts'),

  projects: [
    {
      name: 'stable',
      use: {
        ...devices['Desktop Chrome'],
        // Each worker gets an isolated temp storageState dir.
        // Handled by the `checkoutTest` fixture (see fixtures/base.ts).
      },
    },
  ],

  webServer: {
    command: 'npm run dev',
    url: 'http://localhost:3000',
    reuseExistingServer: !process.env.CI,
    timeout: 120_000,
  },
})
```

**Key decisions:**

| Setting | Value | Rationale |
|---|---|---|
| `retries` | 2 (CI) / 0 (local) | Gives flaky tests one chance; avoids masking real bugs locally |
| `trace` | `on-first-retry` | Zero overhead on happy path; traces available when you actually need them |
| `video` | `retain-on-first-retry` | Same gating—artifacts are large; keep them off successful runs |
| `workers` | 8 | Matches typical CI runner capacity |
| `actionTimeout` | 8s | Tighter than default 30s to surface slow ops faster |

## 3. `global-setup.ts` — One-Time Auth State Generation

```typescript
import { chromium, type BrowserContext } from '@playwright/test'
import fs from 'node:fs'
import path from 'node:path'

const STORAGE_PATH = path.join(__dirname, '../.auth/user.json')

export default async function globalSetup() {
  const browser = await chromium.launch()
  const context: BrowserContext = await browser.newContext()
  const page = await context.newPage()

  // Single login drives all downstream tests — no repeated credential entry.
  await page.goto('http://localhost:3000/login')
  await page.getByLabel('Email').fill('test@example.com')
  await page.getByLabel('Password').fill('password123')
  await page.getByRole('button', { name: 'Sign In' }).click()

  // Wait until we land on the dashboard (confirms login succeeded).
  await page.waitForURL('**/dashboard')

  // Persist cookies + localStorage to a JSON file.
  await context.storageState({ path: STORAGE_PATH })

  await browser.close()

  console.log(`[global-setup] Auth state written → ${STORAGE_PATH}`)
}
```

Every worker's fixture copies this file into a unique temp location so parallel workers never collide.

### `fixtures/api-stubs.ts` — Route Interception

```typescript
import { type TestType, type APIRequestContext } from '@playwright/test'
import { readFileSync } from 'node:fs'
import { join } from 'node:path'

// Load deterministic stub payloads once.
const PAYMENT_STUBS = JSON.parse(
  readFileSync(join(__dirname, '../data/payment-responses.json'), 'utf-8')
)
const SHIPPING_RATES = JSON.parse(
  readFileSync(join(__dirname, '../data/shipping-rates.json'), 'utf-8')
)

/** Stub payment gateway routes. */
export function stubPaymentRoutes(page: any, status: number = 200) {
  // Card tokenization
  page.route('**/api/payments/tokenize', route => {
    route.fulfill({ status, contentType: 'application/json', body: JSON.stringify(PAYMENT_STUBS.tokenize) })
  })
  // Charge
  page.route('**/api/payments/charge', route => {
    route.fulfill({ status, contentType: 'application/json', body: JSON.stringify(PAYMENT_STUBS.charge) })
  })
  // Verify 3DS if applicable
  page.route('**/api/payments/verify', route => {
    route.fulfill({ status, contentType: 'application/json', body: JSON.stringify(PAYMENT_STUBS.verify3ds) })
  })
}

/** Stub shipping calculator routes. */
export function stubShippingRoutes(page: any, rateId = 'standard') {
  page.route('**/api/shipping/calculate*', route => {
    const chosen = SHIPPING_RATES.rates.find(r => r.id === rateId) ?? SHIPPING_RATES.rates[0]
    route.fulfill({ status: 200, contentType: 'application/json', body: JSON.stringify(chosen) })
  })
}
```

> **Why deterministic stubs?** Real card gateways time out, have CAPTCHA, and change response schemas. Stubbing with local JSON means every test is reproducible on demand.

### `fixtures/auth.ts` — storageState-Based Login Fixture

```typescript
import { test as baseAuth } from '@playwright/test'
import { readFileSync, cpSync, mkdirSync, mkdtempSync } from 'node:fs'
import { join, dirname } from 'node:path'
import { tmpdir } from 'node:os'
import type { Customer } from './data'
import { stubPaymentRoutes, stubShippingRoutes } from './api-stubs'

const STORAGE_TEMPLATE = join(__dirname, '../../.auth/user.json')

interface AuthFixtures {
  loggedInPage: ReturnType<typeof baseAuth['page']>
  customer: Customer
}

export const test = baseAuth.extend<AuthFixtures>({
  // Each worker gets a copy of the auth state in its own temp dir.
  loggedInPage: async ({ browser }, use) => {
    const workerStoragePath = join(mkdtempSync(tmpdir()), 'user.json')
    cpSync(STORAGE_TEMPLATE, workerStoragePath, { recursive: true })

    const context = await browser.newContext({
      storageState: workerStoragePath,
    })
    const page = await context.newPage()

    // Apply API stubs immediately — every logged-in page gets them.
    stubPaymentRoutes(page)
    stubShippingRoutes(page)

    await use(page)
    await context.close()
  },

  // Inject deterministic customer data into every test.
  customer: async ({}, use) => {
    const { makeCustomer } = await import('./data')
    await use(makeCustomer())
  },
})
```

### `fixtures/base.ts` — Worker-Level Isolation Base

This layer adds network-idle-wait helpers and a per-worker unique suffix so two workers never operate on the same order/cart/session key.

```typescript
import { test as baseFixture } from './auth'
import type { Page } from '@playwright/test'

interface BaseFixtures {
  /** Wait for all active requests to settle — used between page transitions. */
  waitForNetworkIdle: (page: Page, timeoutMs?: number) => Promise<void>
  /** Per-worker ID to prevent cross-worker collisions on shared resources. */
  workerId: number
}

export const test = baseFixture.extend<BaseFixtures>({
  workerId: [async ({}, use, info) => {
    // Workers are numbered 0..N-1 in Playwright.
    await use(info.workerIndex)
  }, { scope: 'worker' }],

  waitForNetworkIdle: async ({}, use) => {
    async function fn(page: Page, timeoutMs = 5_000) {
      await page.waitForLoadState('networkidle', { timeout: timeoutMs }).catch(() => {})
      // Fallback: also wait for any pending fetch/XHR to drain.
      await Promise.all([
        page.waitForLoadState('networkidle', { timeout: timeoutMs }).catch(() => {}),
      ])
    }
    await use(fn)
  },
})
```

## 5. Page Object Model — Typed Locators

Each POM owns its own selectors (always `[data-testid="..."]`) and implements a minimal API. No assertions live inside POMs — that belongs in the spec.

### `pages/CartPage.ts`

```typescript
import { type Page, type Locator } from '@playwright/test'

export class CartPage {
  readonly page: Page
  readonly itemRows: Locator
  readonly subtotalRow: Locator
  readonly proceedToAddressBtn: Locator
  readonly removeItemBtn: Locator

  constructor(page: Page) {
    this.page = page
    this.itemRows = page.locator('[data-testid="cart-item-row"]')
    this.subtotalRow = page.locator('[data-testid="cart-subtotal"]')
    this.proceedToAddressBtn = page.locator('[data-testid="btn-proceed-to-address"]')
    this.removeItemBtn = page.locator('[data-testid="btn-remove-item"]')
  }

  async goto() {
    await this.page.goto('/cart')
    await this.page.waitForLoadState('networkidle')
  }

  get itemCount(): Promise<number> {
    return this.itemRows.count()
  }

  async getItemText(row: number): Promise<string> {
    return this.itemRows.nth(row).locator('[data-testid="item-name"]').textContent()
  }

  async goToAddressStep() {
    await this.proceedToAddressBtn.click()
    await this.page.waitForLoadState('networkidle')
  }

  async total(): Promise<string> {
    return (await this.subtotalRow.textContent())?.trim() ?? ''
  }
}
```

## 7. Waiting Strategy — Why No `waitForTimeout`

| Pattern | Before (flake source) | After (this design) |
|---|---|---|
| Between actions | `page.waitForTimeout(2000)` | `await page.waitForLoadState('networkidle')` |
| After click → navigation | Implicit assumption it worked | `page.waitForLoadState('networkidle')` + URL check |
| API-driven rendering | `sleep()` | `page.waitForResponse(url => …)` or POM-level `networkidle` |
| Element availability | `page.click(selector)` (fails if not ready) | Locator auto-waits; explicit `locator.waitFor({state:'visible'})` before interaction |

The `waitForNetworkIdle` fixture helper sits atop `page.waitForLoadState('networkidle')` as a wrapper so specs stay clean:

```typescript
test('example', async ({ loggedInPage, waitForNetworkIdle }) => {
  const cart = new CartPage(loggedInPage)
  await cart.goto()
  await waitForNetworkIdle(loggedInPage)
  // now stable — safe to interact
})
```

## 8. Artifact Policy — Trace + Video Only on Retry

The config enforces this globally:

```typescript
use: {
  trace: 'on-first-retry',        // captured when retries are triggered
  video: 'retain-on-first-retry', // deleted after first-run pass
}
```

This means:

- **First-run pass**: zero trace/video overhead → fast CI, small artifacts folder
- **First-run fail + retry succeeds**: trace/video from the failing attempt preserved for debugging
- **All retries fail**: traces from *every* retry retained
- **Local (`retries: 0`)**: no traces/videos ever unless manually requested via `test.info().annotations`

If you need trace/video on *every* failure regardless of retry, swap to:

```typescript
use: { trace: 'retain-on-failure', video: 'retain-on-failure' }
```

But this inflates CI storage significantly. The `on-first-retry` approach is the sweet spot.

## 9. Parallel Execution — Per-Worker Data Isolation

The isolation chain:

```
global-setup.ts
  → writes .auth/user.json (single shared template)

fixtures/auth.ts
  → cpSync(template, mkdtemp/tmp/user-{hash}.json)
  → newContext({ storageState: worker-local-file })
  → stubPaymentRoutes(page) + stubShippingRoutes(page)
  → cleanup context.on-close

fixtures/base.ts
  → workerId (scope: 'worker') → unique suffix for any transient keys
```

Because each worker has:

1. Its own **filesystem copy** of the auth state → no race on reads/writes
2. A fresh **browser context** → separate cookie jar, localStorage
3. API stubs applied at page level → no cross-worker test pollution

This allows 8 concurrent workers with zero interference.

## 10. Quarantine Policy for Flaky Specs

Flaky specs follow a three-tier lifecycle:

### Tier 1: Tag & Gate

When a test flakes in CI (> 2 occurrences over 5 runs), quarantine it:

```typescript
import { test } from '../../fixtures'

test.describe.serial('Quarantined: Shipping Calculation Race', () => {
  test.fixme(true, 'Issue #456 — intermittent shipping timeout')

  test('calculates shipping correctly', async ({ page }) => {
    // test body untouched — stays committed for later fix
  })
})
```

- `test.fixme(true, 'Issue #XYZ')` skips the test in normal runs but tracks it in reports
- The `serial` describe ensures related regression steps don't mask each other

### Tier 2: Conditional CI Skip

For issues that can't be fixed immediately but block nothing critical:

```typescript
test.skip(process.env.CI && process.env.SKIP_FLAKY === 'true', 'Known flake — Issue #457')
```

Run locally without the flag; CI gates on environment variable.

### Tier 3: Diagnose & Unflake

Flaky tests identified via automated repetition:

```bash
# Run 15x locally to reproduce
npx playwright test tests/e2e/checkout/payment.spec.ts --repeat-each=15

# Identify timing-dependent patterns
npx playwright test tests/e2e/checkout/address.spec.ts --retries=3 --reporter=list
```

Common root causes addressed during unflaking:

| Symptom | Fix Applied |
|---|---|
| `Waiting for element failed — Timeout exceeded` | Replace bare `.click()` with locator auto-wait; add `waitForNetworkIdle` |
| Intermittent 500 from payment stub | Stubs now serve local JSON — non-deterministic gateway removed |
| Conflicting worker state | Verified each worker uses its own `mkdtemp` storageState copy |
| Stale DOM references after navigation | POM methods always re-fetch locators post-navigation |

### Flake Burn-Down Tracking

Add this annotation to every flaky test so they surface in the HTML report filter:

```typescript
test('known-flake: confirm shipping update', { tag: '@flaky' }, async ({ page }) => {
```

## 11. Expected Flake Reduction

| Mechanism | Flake Categories Eliminated |
|---|---|
| Deterministic API stubs | Gateway timeouts, CAPTCHA, rate limits (~40% of typical flake) |
| storageState reuse | Credential-entry race conditions, session drift (~15%) |
| `networkidle` + locator auto-wait | DOM-not-ready clicks, stale elements (~25%) |
| Per-worker isolated contexts | Cross-test state pollution, cookie collision (~10%) |
| `on-first-retry` traces | Missed-root-causes due to missing debug data (~5%) |
| Quarantine + `fixme` tags | Known flakes counted in overall pass rate |

Combined, this should reduce 15% flake → < 1% within 2–3 CI cycles as quarantine issues are systematically unflaked and removed from `fixme`.
