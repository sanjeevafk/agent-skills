# Checkout E2E Suite: Flaky-to-Stable Transformation

## Problem Diagnosis (15% Flake)

Typical checkout flake sources:
1. **Per-test logins** — race conditions between auth API responses and cookie propagation
2. **Arbitrary waits** — `waitForTimeout` / polling that breaks under load variance
3. **Non-deterministic API calls** — real payment/shipping responses with jitter/timing variance
4. **Shared mutable DB state** — multiple workers hitting the same records
5. **Heavy artifact capture** — tracing/video on every run causes disk thrashing, masking real failures

### Key decisions:

| Setting | Rationale |
|---|---|
| `trace: 'off'` (default), `'on-first-retry'` (CI) | First run produces zero traces. Only when a test fails and gets re-run does Playwright capture a trace. This eliminates ~95% of trace disk usage for stable suites while keeping debuggability for genuine flakes. |
| `video: 'off'` (default), `'retain-on-failure'` (CI) | Videos are captured only when a test fails. Passing tests (even retried ones that recover) discard their video. Combined with trace's `on-first-retry`, artifacts only materialize for truly suspect runs. |
| `workers: 8` | Balanced for typical CI runners (8-core machines). Each worker gets isolated `storageState` + stub data via worker-indexed file paths. |
| `retries: 2` | Catches transient timing windows without masking systematic bugs (a bug that fails 2/3 times gets surfaced as failed, not silently passing on retry). |
| Two projects (`checkout-local` / `checkout-ci`) | Clean split: locals get fast feedback (0 retries, 1 worker); CI gets full parallelism + retries + artifact collection. Same test code, different configs. |

```ts
function workerIndex(): number {

function workerStateFile(): string {

/* Type augmentation for the test object                              */

interface AuthState {
  /** True after the first successful login within this worker */
  isLoggedIn: boolean
  /** Raw Playwright storageState object (cookies + origins) */
  raw: Parameters<BrowserContext['storageState']>[0] | null
}

export interface BaseFixtures {
  /** Login the current user and persist cookies to storageState file */
  loginUser: (creds: { email: string; password: string }) => Promise<void>
  /** Accessor for the current auth state object (useful for assertions/debugging) */
  authState: () => AuthState

/* ------------------------------------------------------------------ */
/* Fixture definition                                                 */
/* ------------------------------------------------------------------ */

export const test = baseTest.extend<BaseFixtures>({
  loginUser: async ({ page, context }, use) => {
    const stateFile = workerStateFile()
    let currentState: AuthState = { isLoggedIn: false, raw: null }

    /* Ensure directory exists */
    await fs.mkdir(path.dirname(stateFile), { recursive: true }).catch(() => {})

    // Helper: serialize cookies + origins to the worker-scoped file
    async function persistAuth(cookies: Awaited<ReturnType<typeof context.cookies>>) {
      const origins = [{ origin: page.url().split('/').slice(0, 3).join('/') }]
      const payload = { cookies, origins }
      currentState.raw = payload
      currentState.isLoggedIn = true
      await fs.writeFile(stateFile, JSON.stringify(payload))
    }

    // Helper: attempt a standard login POST and persist whatever cookies come back
    async function performLogin(creds: { email: string; password: string }) {
      // Intercept login response to capture cookies
      const loginRes = await page.evaluate(async (creds) => {
        // Assumes your SPA has a fetch-based login; adjust to your router.
        // The key: after this returns, the browser context has auth cookies.
        await fetch('/api/auth/login', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify(creds),
          credentials: 'include',
        })
        return true
      }, creds)

      if (!loginRes) throw new Error('Login evaluation failed')

      // Collect cookies now that they're set in the browser context
      await persistAuth(await context.cookies())
    }

    await use(async (creds) => {
      // Idempotent: only login once per worker session
      if (currentState.isLoggedIn) return

      // Try loading previously-persisted state first
      try {
        const raw = JSON.parse(await fs.readFile(stateFile, 'utf-8'))
        if (raw.cookies?.length > 0) {
          // Restore cookies into the context (avoids re-authenticating)
          await context.addCookies(raw.cookies)
          // Also restore origins for localStorage/sessionStorage
          if (raw.origins?.length) {
            for (const { origin } of raw.origins) {
              // Playwright doesn't have a direct storageState setter per-origin,
              // but cookies are the critical piece for auth. Origins are used
              // by Playwright internally — we store them for observability.
            }
          }
          currentState.isLoggedIn = true
          currentState.raw = raw
          return
        }
      } catch { /* No persisted state — perform fresh login */ }

      // Fresh login
      await performLogin(creds)
    })
  },

  authState: async ({}, use) => {
    const stateFile = workerStateFile()
    let current: AuthState = { isLoggedIn: false, raw: null }

    // Seed initial state
    try {
      const raw = JSON.parse(await fs.readFile(stateFile, 'utf-8'))
      current.raw = raw
      current.isLoggedIn = raw.cookies?.length > 0
    } catch { /* No state yet */ }

    // Return live accessor
    await use(() => current)
  },
})
```

```ts
import { type Page, Locator } from '@playwright/test'

/** Shared helpers used by every checkout step */
export class BasePage {
  protected readonly page: Page

  constructor(page: Page) {
    this.page = page
  }

  /** Navigate and wait for DOM + associated API calls to settle */
  async goto(pathname: string) {
    await this.page.goto(pathname, { waitUntil: 'commit' })
    await this.page.waitForLoadState('domcontentloaded')
    // Wait for any outstanding XHR/fetch to complete
    await this.page.waitForLoadState('networkidle')
  }

  /** Click a button identified by testID, auto-waiting for stability */
  async clickButton(testId: string) {
    const btn = this.byTestId(testId)
    await btn.waitFor({ state: 'visible', timeout: 8_000 })
    await btn.click()
    // Wait for the resulting navigation/API cycle to settle
    await this.page.waitForLoadState('networkidle')
  }

  /** Fill an input identified by testID */
  async fillInput(testId: string, value: string) {
    const input = this.byTestId(testId)
    await input.waitFor({ state: 'attached', timeout: 8_000 })
    await input.fill(value)
  }

  /** Assert an element is visible */
  async expectVisible(testId: string) {
    await expect(this.byTestId(testId)).toBeVisible({ timeout: 10_000 })
  }

  /** Assert an element is hidden */
  async expectHidden(testId: string) {
    await expect(this.byTestId(testId)).toBeHidden({ timeout: 5_000 })
  }

  /** Assert text content matches (case-insensitive substring) */
  async expectText(testId: string, expected: string | RegExp) {
    await expect(this.byTestId(testId)).toContainText(expected, { timeout: 10_000 })
  }

  /** Get a locator by data-testid attribute */
  byTestId(id: string): Locator {
    return this.page.locator(`[data-testid="${id}"]`)
  }
}
```

```ts
import { CartPage } from './CartPage'
import { AddressPage } from './AddressPage'
import { PaymentPage } from './PaymentPage'
import { ConfirmationPage } from './ConfirmationPage'

/** High-level checkout flow that wires together the 4 step pages */
export class CheckoutFlow {
  private readonly page: Page

  constructor(page: Page) {
    this.page = page
  }

  get cart()    { return new CartPage(this.page) }
  get address() { return new AddressPage(this.page) }
  get payment() { return new PaymentPage(this.page) }
  get confirm() { return new ConfirmationPage(this.page) }

  /**
   * Execute the full happy-path: Cart → Address → Payment → Confirmation.
   * Uses `networkidle` between steps so each transition waits for all
   * pending XHR/fetch to complete before asserting on the next page.
   */
  async complete() {
    // Step 1: Cart
    await this.cart.goToCart()
    expect(await this.cart.itemCount()).toBeGreaterThan(0)
    await this.cart.proceedToCheckout()
    await this.page.waitForLoadState('networkidle')

    // Step 2: Address
    await this.address.goTo()
    await this.address.fill({
      'first-name':     'Jane',
      'last-name':      'Doe',
      email:             'jane.doe@example.com',
      'street-1':       '123 Main Street',
      'street-2':        'Apt 4B',
      city:              'San Francisco',
      state:             'CA',
      zip:               '94102',
      country:           'US',
    })
    await this.address.continueToShipping()
    await this.page.waitForLoadState('networkidle')

    // Step 3: Payment
    await this.payment.goTo()
    await this.payment.fillCard({
      cardNumber:    '4242424242424242',
      expiryMonth:   '12',
      expiryYear:    '2030',
      cvv:           '123',
      cardholderName: 'Jane Doe',
    })
    await this.payment.clickPay()
    await this.page.waitForLoadState('networkidle')

    // Step 4: Confirmation
    await this.confirm.goTo()
    await this.expect(confirm.orderId).toBeVisible()
  }
}
```

## 6. Quarantine Policy

### 6a. Quarantine Tiers

```
Tier 1 — WARN (5-20% flake rate):
  • Test marked with .skip() in CI via conditional flag
  • Logged in quarantine ledger (docs/quarantine-log.md)
  • Owner assigned within 48 hours
  • Review at weekly QA sync

Tier 2 — BLOCK (>20% flake rate OR blocking release):
  • Test marked test.fixme() — shows as skipped in CI but counted
  • Blocked from merging related PRs until fixed
  • Bug filed in issue tracker with severity P1
  • Owner must reproduce locally (--repeat-each=10) within 24h

Tier 3 — RESOLVED:
  • Test passes --repeat-each=5 consecutively
  • Re-enabled in CI, monitored for 7 days
  • If it flakes again → escalates back to Tier 2
```

## 7. Flake Remediation Playbook

| Symptom | Root Cause | Fix |
|---------|-----------|-----|
| `Timed out 5000ms waiting for ...` | Hardcoded `waitForTimeout()` | Replace with locator auto-wait + `page.waitForSelector()` or `waitForLoadState('networkidle')` |
| `element is not visible` | Animations/transitions not settled | Add `await page.waitForTimeout(100)` ONLY if no CSS solution exists, or better: wait for the element's `transform` to stabilize via `page.waitForFunction()` |
| `Cannot click on element` | Overlay/z-index race condition | Wait for overlay to disappear: `await page.locator('.overlay').waitFor({ state: 'hidden' })` |
| Random assertion failures | Non-deterministic API response | Stub the endpoint with deterministic fixtures (`stubs.ts`) — never hit real payment/shipping services |
| Intermittent auth cookie loss | Per-test login races | Use `storageState` persistence (one login per worker, not per-test) |
| Data collision between parallel tests | Shared DB accounts/carts | Worker-indexed suffixes (`worker-0004`) + unique data per worker |

**Principle:** Every wait should be *semantic* (waiting for a specific state the user cares about), not *temporal* (waiting for an arbitrary duration).

---

## 8. Why This Eliminates the 15% Flake Rate

| Flake Source | Old Approach | New Approach | Impact |
|-------------|-------------|--------------|--------|
| Login races | Login in every test, hope cookies propagate | `storageState` file, read once per worker | **Eliminates** |
| Timing waits | `waitForTimeout(3000)` everywhere | `networkidle` + locator auto-wait | **Eliminates** |
| External API jitter | Real payment/shipping endpoints | Deterministic stub fixtures | **Eliminates** |
| Worker data collision | Same cart/account for all workers | Worker-indexed suffixes (`0001`, `0002`, ...) | **Eliminates** |
| Disk thrashing | Trace/video on every test | `'on-first-retry'` / `'retain-on-failure'` | **Reduces noise** |
| Unidentified flakes | Blamed on "timing" with no data | Quarantine ledger + `fixme()` tagging | **Structured resolution** |
