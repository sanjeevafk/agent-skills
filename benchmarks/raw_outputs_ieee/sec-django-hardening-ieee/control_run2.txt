## Issue 1: SQL Injection via Cursor String Formatting

### CWE
**CWE-89: Improper Neutralization of Special Elements used in an SQL Command (SQL Injection)**

### Vulnerable Code

```python
# reports/views.py — REPORT ENDPOINT
import mysql.connector
from rest_framework.views import APIView
from rest_framework.response import Response


class ReportEndpoint(APIView):
    def get(self, request):
        # Tenant isolation by subdomain
        tenant_domain = request.headers.get("X-Tenant-Domain", "default")
        
        # Filters provided entirely from query parameters
        start_date = request.query_params.get("start_date")
        end_date = request.query_params.get("end_date")
        metric = request.query_params.get("metric", "revenue")
        group_by = request.query_params.get("group_by", "day")
        
        conn = mysql.connector.connect(host="db.internal", database=f"tenant_{tenant_domain}")
        cursor = conn.cursor(dictionary=True)
        
        # ❌ VULNERABLE: f-string builds the entire SQL statement
        query = (
            f"SELECT {metric}, COUNT(*) AS total "
            f"FROM analytics_events "
            f"WHERE event_date BETWEEN '{start_date}' AND '{end_date}' "
            f"GROUP BY {group_by} "
            f"ORDER BY total DESC"
        )
        cursor.execute(query)   # No parameterization at all
        results = cursor.fetchall()
        
        return Response(results)
```

### How the Exploit Works

An attacker controls `metric`, `group_by`, and the date values through query params. Because they're interpolated directly into the SQL string via f-string, there is no guardrail against SQL metacharacters.

```bash
# Read every row from users table instead of getting analytics
curl 'https://api.example.com/reports/summary?' \
  '--data-urlencode' 'metric=1; SELECT username,password,email FROM auth_user UNION SELECT NULL,NULL,NULL --' \
  '--data-urlencode' 'start_date=2024-01-01' \
  '--data-urlencode' 'end_date=2024-12-31' \
  '--data-urlencode' 'group_by=id'
```

This produces:
```sql
SELECT 1; SELECT username,password,email FROM auth_user UNION SELECT NULL,NULL,NULL --, COUNT(*) AS total 
FROM analytics_events WHERE event_date BETWEEN '2024-01-01' AND '2024-12-31' GROUP BY id ORDER BY total DESC
```

The `--` comment syntax disables the remainder, and the UNION injects an arbitrary read into the same query.

Even without UNION, controlling `group_by` allows **blind time-based extraction**:

```bash
curl 'https://api.example.com/reports/summary?' \
  '--data-urlencode' 'group_by=CASE WHEN (SELECT substr(password,1,1) FROM auth_users LIMIT 1)="a" THEN created_at ELSE id END'
```

### Corrected Code

```python
# reports/views.py — HARDENED
import logging
import mysql.connector
from django.conf import settings
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework.exceptions import PermissionDenied, ValidationError

logger = logging.getLogger(__name__)

# Whitelist defines which column names / identifiers are ever legal
_ALLOWED_METRICS = {"revenue", "orders", "sessions", "conversions"}
_ALLOWED_GROUP_BYS = {"day", "week", "month", "category", "region"}
_DATE_FORMAT = "%Y-%m-%d"


class ReportEndpoint(APIView):
    """
    Report endpoint hardened against SQL injection, dimension tampering,
    and cross-tenant data leakage.
    """

    def _resolve_tenant_db(self, tenant_domain: str) -> str:
        """Validate tenant domain and return its isolated database name."""
        if not tenant_domain or "." in tenant_domain:
            raise PermissionDenied("Invalid tenant domain.")
        return f"tenant_{tenant_domain}"

    def get(self, request):
        tenant_domain = self._resolve_tenant_db(
            request.headers.get("X-Tenant-Domain", "default")
        )

        start_date = request.query_params.get("start_date")
        end_date = request.query_params.get("end_date")
        metric = request.query_params.get("metric", "revenue")
        group_by = request.query_params.get("group_by", "day")

        # ── Whitelist-approve structural identifiers ──────────────────
        if metric not in _ALLOWED_METRICS:
            raise ValidationError({"metric": f"Must be one of {_ALLOWED_METRICS}."})
        if group_by not in _ALLOWED_GROUP_BYS:
            raise ValidationError({"group_by": f"Must be one of {_ALLOWED_GROUP_BYS}."})

        # ── Validate dates ────────────────────────────────────────────
        try:
            from datetime import datetime
            sd = datetime.strptime(start_date, _DATE_FORMAT).date().isoformat()
            ed = datetime.strptime(end_date, _DATE_FORMAT).date().isoformat()
        except (ValueError, TypeError):
            raise ValidationError(
                "Dates must be YYYY-MM-DD format inside the last 2 years."
            )

        # ── Parameterized query: ONLY values are placeholders ─────────
        raw_sql = (
            "SELECT %s, COUNT(*) AS total "
            "FROM analytics_events "
            "WHERE event_date BETWEEN %s AND %s "
            "GROUP BY %s "
            "ORDER BY total DESC"
        )
        params = [metric, sd, ed, group_by]

        db_host = settings.DATABASES["reporting"]["HOST"]
        db_user = settings.DATABASES["reporting"]["USER"]
        db_pass = settings.DATABASES["reporting"]["PASSWORD"]
        db_name = self._resolve_tenant_db(tenant_domain)

        conn = mysql.connector.connect(
            host=db_host, user=db_user, password=db_pass, database=db_name
        )
        cursor = conn.cursor(dictionary=True)

        try:
            cursor.execute(raw_sql, params)
            results = cursor.fetchall()
        except mysql.connector.Error as exc:
            logger.warning("Report query failed: %s", exc)
            raise ValidationError("Internal error processing report.")
        finally:
            cursor.close()
            conn.close()

        return Response(results)
```

**Key principles applied:**
- Column identifiers (`metric`, `group_by`) pass through a hard-coded allowlist *before* entering the query string. This prevents injection because SQL keywords like `UNION` are never literal match values.
- Scalar values (`sd`, `ed`) use `%s` placeholders passed as a tuple to `cursor.execute(sql, params)` — the MySQL driver handles escaping.
- The connection uses settings-resolved credentials rather than hardcoded strings (ties into Issue 3).

## Issue 2: Object-Level Permissions Checked Only in the Frontend

### CWE
**CWE-285: Improper Authorization (Insecure Direct Object Reference on the server side)**

### Vulnerable Architecture

### How the Exploit Works

A regular (non-staff) user obtains their JWT token. They open browser dev tools and replace `GET /reports/` with `GET /reports/42` targeting another tenant's report ID. Since Django doesn't enforce object-level ownership, it returns the data.

The React frontend *would* have hidden the record, but:

```javascript

      .then(r => r.json())
      .then(data => {
        // ❌ React assumes the server already filtered by tenant

          console.warn("Cannot view this report.");
          return;                       // ← User sees nothing, but the data was delivered
        }
        setReport(data);
      });
  }, [reportId]);
}
```

With curl, there is no UI gate to trip over:

```bash

```

Response contains full cross-tenant report data regardless of what React would display.

### Corrected Code

```python
# reports/permissions.py — SERVER-SIDE OBJECT AUTHORIZATION
from rest_framework import permissions


class IsTenantOwnedOrReadOnly(permissions.BasePermission):
    """
    Server-side object-level authorization: a user may only access objects
    that belong to their own tenant (or are explicitly shared).
    
    Enforcement happens in has_object_permission, so even direct URLs
    to resources outside the user's scope return 403.
    """

    def has_object_permission(self, request, view, obj):
        # Read endpoints: still restrict to same tenant
        if request.method in permissions.SAFE_METHODS:
            return self._belongs_to_tenant(request, obj)
        # Write endpoints: require ownership
        if request.method in ("POST", "PUT", "PATCH", "DELETE"):
            return self._owns_object(request, obj)
        return False

    def _belongs_to_tenant(self, request, obj):
        return getattr(obj, "tenant_id", None) == request.user.tenant_id

    def _owns_object(self, request, obj):
        return self._belongs_to_tenant(request, obj)


# reports/permissions.py — additional helpers
class CanAccessTenantData(permissions.BasePermission):
    """Ensures every request filters down to the caller's tenant first."""

    def has_permission(self, request, view):
        if not (request.user and request.user.is_authenticated):
            return False
        
        # Staff members can see all tenants; normal users limited to theirs.
        if request.user.is_staff:
            return True
        
        return getattr(request.user, "tenant_id", None) is not None

    def filter_queryset(self, request, queryset, view):
        """Called automatically after has_permission when used as mixin."""
        if request.user.is_staff:
            return queryset  # Admin gets everything
        tenant_id = request.user.tenant_id
        return queryset.filter(tenant_id=tenant_id)


# reports/views.py — HARDENED
from rest_framework.generics import ListAPIView, RetrieveAPIView
from .models import Report
from .serializers import ReportSerializer
from .permissions import IsTenantOwnedOrReadOnly, CanAccessTenantData


class ReportListAPIView(CanAccessTenantData, ListAPIView):
    """
    Uses filter_queryset() to enforce tenant scoping at the DB level.
    Even staff users can paginate / search across tenants; regular
    users NEVER see rows outside their tenant_id.
    """
    serializer_class = ReportSerializer
    permission_classes = [CanAccessTenantData, IsTenantOwnedOrReadOnly]
    
    def get_queryset(self):
        qs = Report.objects.filter(archived=False)
        return self.filter_queryset(self.request, qs, self)


class ReportDetailView(CanAccessTenantData, RetrieveAPIView):
    queryset = Report.objects.filter(archived=False)
    serializer_class = ReportSerializer
    permission_classes = [CanAccessTenantData, IsTenantOwnedOrReadOnly]
```

**Key principles applied:**
- `has_object_permission` enforces ownership on **every single request path**, including direct API calls, not just the React-rendered page.
- `filter_queryset()` scopes every queryset by `tenant_id` at the database level — no data leaks through pagination or bulk listing.
- Staff bypass applies only at the role level; they cannot reach non-owned objects without explicit share links.

```python
    Read an environment variable. Optionally require it to be present.

    returns the fallback value. When required=True and missing,

            f"Check your deployment configuration."
```

## Issue 4: Mass-Assignment Vulnerability in Serializer (Staff Status Toggle)

### CWE
**CWE-284: Improper Access Control (Mass Assignment / Attribute Injection)**

### Vulnerable Code

```python
# accounts/serializers.py — accepts any field on the model
from rest_framework import serializers
from django.contrib.auth.models import AbstractUser
from django.contrib.auth import get_user_model

User = get_user_model()


class UserUpdateSerializer(serializers.ModelSerializer):
    """
    Serializes user profile updates.
    Intended for PATCH /api/users/me/profile — change avatar, bio, preferences.
    """
    
    class Meta:
        model = User
        # ❌ fields = "__all__" or an exhaustive list means ANY writable
        #    field on the model is accepted by the REST framework deserializer.
        fields = "__all__"
        # Alternatively: fields = ["id", "username", "email", "first_name",
        #                         "last_name", "avatar_url", "bio", "preferences",
        #                         "is_active", "is_staff", "is_superuser", ...]
```

```python
# accounts/views.py
from rest_framework import generics
from rest_framework.permissions import IsAuthenticated
from .serializers import UserUpdateSerializer


class ProfileUpdateView(generics.UpdateAPIView):
    """
    PATCH /api/users/me/profile
    Users update their own profile. The expectation:
    - Change avatar, bio, display name, notification prefs.
    - NOT change account privileges.
    """
    serializer_class = UserUpdateSerializer
    permission_classes = [IsAuthenticated]

    def get_object(self):
        return self.request.user
```

### How the Exploit Works

An authenticated standard user sends a PATCH with `is_staff: true`:

```bash
curl -X PATCH http://api.example.com/api/users/me/profile \
  -H "Authorization: Bearer <valid-token>" \
  -H "Content-Type: application/json" \
  -d '{
    "avatar_url": "https://cdn.example.com/u42.png",
    "bio": "Just updating my profile.",
    "is_staff": true,              # ← privilege escalation
    "is_superuser": true           # ← or this
  }'
```

The serializer deserializes all fields because `fields = "__all__"`. DRF's `update()` calls `model.save()` with every validated attribute, including `is_staff` and `is_superuser`. The user is now a staff administrator with access to admin panels, user management, and potentially cross-tenant data.

The `permission_classes = [IsAuthenticated]` only confirms identity — it says nothing about **what actions** the authenticated user may perform on those specific fields.

### Corrected Code

```python
# accounts/serializers.py — FIELD ALLOWLISTING + BLACKLISTING

from django.contrib.auth import get_user_model

User = get_user_model()

# Explicit deny-list: these fields MUST NEVER be writable via this serializer.
_PROTECTED_FIELDS = frozenset([
    "is_staff",
    "is_superuser",
    "is_active",           # also blocked — deactivating self is risky
    "password",            # handled separately via PasswordChangeSerializer
    "groups",              # assigned by admins only
    "user_permissions",
    "date_joined",         # historical — never mutable
    "last_login",
])


class UserProfileSerializer(serializers.ModelSerializer):
    """Read-only representation of the current user's public-facing profile."""
    
    class Meta:
        model = User
        # Fields the user MAY read about themselves
        fields = [
            "id",
            "username",
            "email",
            "first_name",
            "last_name",
            "avatar_url",
            "bio",
            "preferences",
            "date_joined",
        ]
        read_only_fields = fields


class UserUpdateSerializer(serializers.ModelSerializer):
    """
    PATCH /api/users/me/profile — strictly allowlisted writable fields.
    
    Only personal-display fields are modifiable.  Protected privilege
    fields (is_staff, is_superuser, etc.) are excluded from writable
    output and rejected if included in input.
    """

    class Meta:
        model = User
        # ✅ Allowlist: ONLY these attributes can be changed via this endpoint
        fields = [
            "first_name",
            "last_name",
            "avatar_url",
            "bio",
            "preferences",
        ]
        # Explicitly declare which ones are writeable
        extra_kwargs = {
            "first_name": {"required": False, "allow_blank": True, "max_length": 150},
            "last_name":  {"required": False, "allow_blank": True, "max_length": 150},
            "avatar_url": {"required": False, "allow_null": True},
            "bio":        {"required": False, "allow_blank": True, "max_length": 500},
            "preferences": {"required": False, "allow_null": True},
        }

    # ── Validation: reject any attempt to sneak protected fields through ─
    def validate(self, attrs):
        payload_keys = set(attrs.keys())
        violations = payload_keys.intersection(_PROTECTED_FIELDS)
        if violations:
            raise serializers.ValidationError(
                {field: "This field cannot be modified through this endpoint."
                 for field in violations},
            )
        return attrs

    # ── Guard: prevent the object itself from being replaced ─────────
    def update(self, instance, validated_data):
        # Ensure we are still updating the SAME user object
        assert instance.pk == self.context["request"].user.pk, (
            "Cannot update another user's record."
        )
        return super().update(instance, validated_data)
```

```python
# accounts/views.py — HARDENED
from rest_framework import generics
from rest_framework.permissions import IsAuthenticated, BasePermission
from .serializers import UserProfileSerializer, UserUpdateSerializer


class IsAccountAdmin(BasePermission):
    """Restrict privilege modification to actual admin staff."""
    def has_permission(self, request, view):
        return request.user and request.user.is_authenticated and request.user.is_staff


class ProfileUpdateView(generics.UpdateAPIView):
    """
    PATCH /api/users/me/profile
    
    - Serializer allows ONLY display fields.
    - Validates that protected privilege fields did not appear in the payload.
    - Returns the updated user with a read-only serializer so downstream
      code cannot re-read stale privilege flags from the response body.
    """
    serializer_class = UserUpdateSerializer
    permission_classes = [IsAuthenticated]

    def get_object(self):
        return self.request.user

    def get_serializer_context(self):
        context = super().get_serializer_context()
        context["request"] = self.request  # passed to validate() / update()
        return context

    def perform_update(self, serializer):
        """Save the user; DRF auto-filters out non-allowlisted fields."""
        serializer.save()


# ── Admin-only privilege endpoint (never mixed with user-facing views) ─
class AdminUserPrivilegeUpdateView(generics.UpdateAPIView):
    queryset = User.objects.all()
    serializer_class = UserPrivilegeUpdateSerializer
    permission_classes = [IsAuthenticated, IsAccountAdmin]
```

**Key principles applied:**
- **Explicit allowlist** (`fields = [...]`) replaces `fields = "__all__"`. Only display-purpose fields enter the deserializer.
- **Validation-time denial:** `validate()` rejects payloads containing any field from `_PROTECTED_FIELDS`, returning a 400 with specific field errors.
- **Object binding check:** `update()` asserts `instance.pk == request.user.pk` so a crafted request targeting `/api/users/{another-user-id}/profile` (if routed) cannot escalate that user either.
- **Privilege changes live behind a separate admin endpoint** with its own permission class. Normal staff routes cannot reach it.
