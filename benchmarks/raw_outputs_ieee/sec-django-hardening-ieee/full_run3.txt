### Issue #1 — SQL Injection via `cursor.execute()` with f-string Concatenation

**CWE:** [CWE-89](https://cwe.mitre.org/data/definitions/89.html) — Improper Neutralization of Special Elements used in an SQL Command ('SQL Injection')

#### Vulnerable Code

```python
# views.py — Report view building dynamic filters
from django.db import connection

class MonthlyReportView(generics.RetrieveAPIView):
    permission_classes = [IsAuthenticated]

    def get(self, request, *args, **kwargs):
        tenant_id = self.kwargs['tenant_id']
        start_date = request.query_params.get('start_date', '2026-01-01')
        end_date = request.query_params.get('end_date', '2026-12-31')
        group_by = request.query_params.get('group_by', 'month')

        query = f"""
            SELECT {group_by} AS period,
                   COUNT(*) AS order_count,
                   SUM(total) AS revenue
            FROM orders
            WHERE tenant_id = '{tenant_id}'
              AND created_at BETWEEN '{start_date}' AND '{end_date}'
            GROUP BY {group_by}
            ORDER BY period;
        """

        with connection.cursor() as cursor:
            cursor.execute(query)  # ← raw interpolation into SQL
            rows = cursor.fetchall()

        return Response({'data': rows})
```

#### Exploit Demonstration

An attacker controls `tenant_id` via URL path or `group_by` via query parameter. No ORM escaping occurs.

```bash
# Attacker extracts all database tables
curl 'https://api.example.com/reports/1/orders/?\
group_by=nonexistent%27%20UNION%20SELECT%20table_name,NULL,NULL%20FROM%20information_schema.tables--'

# Attacker exfiltrates passwords
curl 'https://api.example.com/reports/1/orders/?\
group_by=nonexistent%27%20UNION%20SELECT%20username,password,email,NULL%20FROM%20auth_user--'

# Attacker dumps entire users table across tenants
curl 'https://api.example.com/reports/1/orders/?\
tenant_id=%27%3B%20DELETE%20FROM%20orders%3B%20--'
```

The injected fragment `'; DELETE FROM orders; --` terminates the original statement and wipes data. The `UNION` variant smuggles arbitrary column values back into the report result set.

#### Corrected Code

Replace raw execution entirely with the Django ORM. If raw SQL is unavoidable, use positional parameters.

```python
# views.py — FIXED
from django.db.models import Sum, Count
from datetime import datetime
from apps.orders.models import Order

ALLOWED_GROUP_COLUMNS = {'month', 'day', 'week'}  # Whitelist

class MonthlyReportView(generics.RetrieveAPIView):
    permission_classes = [IsAuthenticated]

    def get(self, request, *args, **kwargs):
        tenant_id = self.kwargs['tenant_id']
        start_date = request.query_params.get('start_date', '2026-01-01')
        end_date = request.query_params.get('end_date', '2026-12-31')
        group_by = request.query_params.get('group_by', 'month')

        # --- Validate against whitelist, reject anything else ---
        if group_by not in ALLOWED_GROUP_COLUMNS:
            raise serializers.ValidationError(
                {'group_by': f'Unsupported grouping: {group_by}'}
            )

        # --- Parse dates defensively ---
        try:
            start = datetime.strptime(start_date, '%Y-%m-%d').date()
            end = datetime.strptime(end_date, '%Y-%m-%d').date()
        except ValueError:
            raise serializers.ValidationError('Dates must be YYYY-MM-DD')

        # --- ORM query: no string interpolation, safe filtering ---
        qs = Order.objects.filter(
            tenant_id=tenant_id,
            created_at__gte=start,
            created_at__lte=end,
        ).values(group_by).annotate(
            order_count=Count('id'),
            revenue=Sum('total'),
        ).order_by(group_by)

        # Convert Decimal to float for JSON serialization
        data = list(qs)
        for row in data:
            if row.get('revenue'):
                row['revenue'] = float(row['revenue'])

        return Response({'data': data})
```

If you **must** keep raw SQL for performance reasons, always parameterize:

```python
# Still using cursor.execute but WITH PARAMETERS
SAFE_RAW_QUERY = """
    SELECT %s AS period,
           COUNT(*) AS order_count,
           COALESCE(SUM(total), 0) AS revenue
    FROM orders
    WHERE tenant_id = %s
      AND created_at BETWEEN %s AND %s
    GROUP BY %s
    ORDER BY period;
"""

def _fetch_report_raw(tenant_id, start, end, group_by):
    # group_by was already validated by the whitelist above
    with connection.cursor() as cursor:
        cursor.execute(
            SAFE_RAW_QUERY,
            [group_by, tenant_id, start, end, group_by],
        )
        return cursor.fetchall()
```

**Key rules:** never interpolate f-strings into SQL; always use ORM `.filter()`, `.values()`, `.annotate()` or, when raw is required, pass variables as the second argument to `cursor.execute(sql, params)`.

### Issue #2 — Object-Level Permissions Checked Only in React

**CWE:** [CWE-862](https://cwe.mitre.org/data/definitions/862.html) — Missing Authorization &nbsp;|&nbsp; [CWE-639](https://cwe.mitre.org/data/definitions/639.html) — Authorization Bypass Through Trusting Endpoint

#### Vulnerable Code

```python
# serializers.py — TenantMemberSerializer
class TenantMemberSerializer(serializers.ModelSerializer):
    class Meta:
        model = TenantMember
        fields = '__all__'  # ← Serializes everything including owner_id

# views.py
class TenantMemberDestroyView(generics.DestroyAPIView):
    lookup_field = 'pk'

    def get_object(self):
        member = super().get_object()
        # ❌ Only check done inside the React component — NO server-side guard
        return member

# React client (fragile trust boundary)
// The frontend checks before rendering the delete button, but a curl call bypasses it.
{canDelete && <button onClick={() => handleDelete(memberId)}>Remove</button>}
```

#### Exploit Demonstration

```bash
# Alice owns Tenant A, Bob is just a viewer on Tenant A.
# Frontend hides the "remove" button for Bob, so he can't see it.
# But the API has no enforcement — Bob can still call:

# Bob deletes Alice from his own tenant (escalation → removes admin)
curl -X DELETE https://api.example.com/members/42/ \
     -H 'Authorization: Bearer bob_token'

# Bob assigns himself owner by manipulating create/update payloads
curl -X PATCH https://api.example.com/members/42/ \
     -H 'Authorization: Bearer bob_token' \
     -H 'Content-Type: application/json' \
     -d '{"role": "admin", "owner_id": 42}'
```

Because `fields = '__all__'` serializes every field and there's no `has_object_permission` override, the API blindly accepts the authenticated user's payload regardless of which object the user actually owns or should control.

#### Corrected Code

Server-side enforcement at both the permission layer and the serializer layer.

```python
# permissions.py
from rest_framework.permissions import BasePermission
from rest_framework.exceptions import PermissionDenied


class IsTenantOwner(BasePermission):
    """Object-level: only the owner can modify/delete a TenantMember."""

    def has_object_permission(self, request, view, obj):
        if not request.user.is_authenticated:
            return False

        # Superusers may do anything
        if request.user.is_superuser:
            return True

        # The user must be the recorded owner of this membership
        return obj.owner == request.user


class CanManageMembers(BasePermission):
    """Object-level: only members whose role grants manage access."""

    ROLE_GRANTS_MANAGE = {'owner', 'admin'}

    def has_object_permission(self, request, view, obj):
        if not request.user.is_authenticated:
            return False

        if request.user.is_superuser:
            return True

        # User must be a member of the SAME tenant
        try:
            user_member = TenantMember.objects.get(
                tenant=obj.tenant,
                user=request.user,
            )
        except TenantMember.DoesNotExist:
            return False

        # Role must grant manage rights
        return user_member.role in self.ROLE_GRANTS_MANAGE


class IsAdminOrReadOnly(BasePermission):
    """GET/HEAD/OPTIONS allowed for any authenticated member."""

    def has_permission(self, request, view):
        if request.method in permissions.SAFE_METHODS:
            return request.user.is_authenticated
        return request.user.is_authenticated

    def has_object_permission(self, request, view, obj):
        if request.method in permissions.SAFE_METHODS:
            return True
        return False
```

```python
# serializers.py — FIXED: explicit allowlist
class TenantMemberSerializer(serializers.ModelSerializer):
    """Only expose writable fields we intend to accept.
    owner_id is WRITE_ONLY hidden from listings but accepted on create."""

    owner_id = serializers.PrimaryKeyRelatedField(
        queryset=User.objects.all(),
        source='owner',
        required=False,
        write_only=True,  # Never appear in response payload
    )

    class Meta:
        model = TenantMember
        # ✅ Explicit allowlist — never '__all__'
        fields = ['id', 'tenant', 'user', 'role', 'is_active', 'owner']
        read_only_fields = ['id', 'tenant', 'owner']  # cannot be altered via API

    def validate_role(self, value):
        if value not in ('owner', 'admin', 'editor', 'viewer'):
            raise serializers.ValidationError('Invalid role.')
        return value

    def validate(self, attrs):
        """Cross-field validation: ensure roles are sensible."""
        user = attrs.get('user')
        tenant = self.instance.tenant if self.instance else self.context['request'].parser_context['kwargs'].get('parent_pk')
        if not tenant:
            raise serializers.ValidationError('Missing parent tenant context.')

        # Prevent assigning owner role unless requester is themselves owner
        if attrs.get('role') == 'owner' and not self._request_is_owner(tenant):
            raise PermissionDenied('Only the current owner can transfer ownership.')
        return attrs

    def _request_is_owner(self, tenant):
        """Check whether the current requestor is the owner of this tenant."""
        try:
            return TenantMember.objects.get(
                tenant_id=tenant,
                user=self.context['request'].user,
                role='owner',
            )
        except (TenantMember.DoesNotExist, AttributeError):
            return False
```

```python
# views.py — FIXED: attach permissions to every endpoint
class TenantMemberViewSet(viewsets.ModelViewSet):
    serializer_class = TenantMemberSerializer
    permission_classes = [IsAdminOrReadOnly, IsTenantOwner | CanManageMembers]

    def get_queryset(self):
        user = self.request.user
        return TenantMember.objects.filter(
            tenant__memberships__user=user
        ).distinct()

    def perform_update(self, serializer):
        serializer.save()

    def perform_destroy(self, instance):
        # Reject removing the sole owner
        if instance.role == 'owner' and TenantMember.objects.filter(
            tenant=instance.tenant, role='owner'
        ).count() <= 1:
            raise PermissionDenied('Cannot remove the last owner of a tenant.')
        super().perform_destroy(instance)
```

**Rule of thumb:** never rely on client-side visibility as an access-control mechanism. Every API action must enforce its own permission in DRF's `permission_classes` and/or `has_object_permission`.

### Issue #4 — Mass Assignment Allows Toggling `is_staff` Through Serializer

**CWE:** [CWE-915](https://cwe.mitre.org/data/definitions/915.html) — Improperly Controlled Modification of Dynamically-Dynamic Object Reference («Mass Assignment») &nbsp;|&nbsp; [CWE-269](https://cwe.mitre.org/data/definitions/269.html) — Privilege Escalation

#### Vulnerable Code

```python
# serializers.py
class UserSerializer(serializers.ModelSerializer):
    class Meta:
        model = User
        fields = '__all__'  # ← includes is_staff, is_superuser, password

# views.py
class UserUpdateView(generics.UpdateAPIView):
    serializer_class = UserSerializer
    permission_classes = [IsAdminUser]

    def get_object(self):
        return User.objects.get(pk=self.kwargs['pk'])
```

Even though the view requires `IsAdminUser` at the HTTP-method level, `fields = '__all__'` means the admin's PATCH body can include **any** field on `User` — including `is_staff`, `is_superuser`, and `password_change`. There's no server-side block on those mutations.

#### Exploit Demonstration

```bash
# An admin accidentally sends a maliciously crafted request (or a compromised
# admin token is used by an attacker) that includes is_staff=true on another user.

# Scenario 1: Admin inadvertently grants themselves staff via cross-site request forgery
# (already authenticated session tricked into sending extra fields)

# Scenario 2: Attacker with stolen admin token escalates a low-privilege user
curl -X PATCH https://api.example.com/users/10/ \
     -H 'Authorization: Bearer stolen_admin_token' \
     -H 'Content-Type: application/json' \
     -d '{"first_name": "Backdoor", "is_staff": true}'
# User 10 now has admin panel access

# Scenario 3: Mass-update sets is_superuser across bulk operation
curl -X PATCH https://api.example.com/users/bulk/ \
     -H 'Authorization: Bearer ...' \
     -d '[{"id": 5, "is_staff": true}, {"id": 7, "is_staff": true}]'
```

#### Corrected Code

Explicit field allowlisting + protected write-only fields + object-level permission on sensitive mutations.

```python
# serializers.py — FIXED: explicit allowlist, protected fields
class UserSerializer(serializers.ModelSerializer):
    """Admin-editable user serializer.
    Sensitive flags (is_staff, is_superuser) require admin approval
    and are NOT included in standard user profiles."""

    profile_picture = serializers.ImageField(required=False, allow_null=True)

    class Meta:
        model = User
        # ✅ Explicit white-list — never '__all__'
        fields = [
            'id',
            'username',
            'email',
            'first_name',
            'last_name',
            'profile_picture',
            'is_active',       # allowed: admins toggle suspend/resume
            # ⛔ is_staff, is_superuser, password — deliberately omitted
        ]
        read_only_fields = ['id', 'username']  # username cannot be changed post-create

    def validate_email(self, value):
        if User.objects.filter(email=value).exclude(pk=self.instance.pk).exists():
            raise serializers.ValidationError('A user with this email already exists.')
        return value

    def update(self, instance, validated_data):
        """Strip out any attempt to sneak in disallowed fields."""
        # Defensive: if serialized data tries to set is_staff somehow, strip it
        validated_data.pop('is_staff', None)
        validated_data.pop('is_superuser', None)
        validated_data.pop('password', None)

        # Handle profile picture
        pp = validated_data.pop('profile_picture', None)
        if pp is not None:
            instance.profile_picture = pp

        for attr, value in validated_data.items():
            setattr(instance, attr, value)
        instance.full_clean()  # triggers model validators
        instance.save()
        return instance


# ── Separate serializer for admin-only privileged operations ─
class AdminUserSerializer(UserSerializer):
    """Extended serializer granting write access to is_staff / is_superuser.
    Only usable by verified superusers on explicitly designated endpoints."""

    class Meta(UserSerializer.Meta):
        fields = UserSerializer.Meta.fields + [
            'is_staff',
            'is_superuser',
        ]
        extra_kwargs = {
            'is_staff': {'write_only': False},  # readable but protected
            'is_superuser': {'write_only': False},
        }
```

```python
# permissions.py
class IsVerifiedSuperuser(BasePermission):
    """Extra guard for privilege-escalation actions."""

    def has_permission(self, request, view):
        return (
            request.user.is_authenticated
            and request.user.is_superuser
        )
```

```python
# views.py — FIXED: two separate endpoints
class UserDetailView(generics.RetrieveUpdateAPIView):
    """Standard admin edit — cannot touch is_staff/is_superuser."""
    queryset = User.objects.all()
    serializer_class = UserSerializer
    permission_classes = [IsAdminUser]

    def get_queryset(self):
        # Admins can only see non-superuser accounts
        return User.objects.filter(is_superuser=False)


class AdminUserDetailView(generics.RetrieveUpdateAPIView):
    """Privileged endpoint — requires confirmed superuser.
    Access is logged for audit."""

    queryset = User.objects.all()
    serializer_class = AdminUserSerializer
    permission_classes = [IsVerifiedSuperuser]

    def retrieve(self, request, *args, **kwargs):
        instance = self.get_object()
        if instance.is_superuser and not request.user.is_superuser:
            raise PermissionDenied('Cannot inspect other superuser details.')
        return super().retrieve(request, *args, **kwargs)

    def update(self, request, *args, **kwargs):
        instance = self.get_object()

        # Prevent superuser from removing their own superuser status
        if request.user.is_superuser and instance.is_superuser:
            data = request.data.copy()
            data.pop('is_superuser', None)
            request._full_data = data

        # Audit log the privilege change
        old_staff = getattr(instance, 'is_staff', False)
        resp = super().update(request, *args, **kwargs)

        if getattr(instance, 'is_staff', False) != old_staff:
            from django.contrib.auth.models import LogEntry
            LogEntry.objects.log_change(
                instance,
                f'is_staff changed: {old_staff} -> {instance.is_staff}',
                actor=request.user,
            )

        return resp
```

```python
# urls.py — route distinction prevents accidental exposure
urlpatterns = [
    path('users/<int:pk>/', UserDetailView.as_view(), name='user-detail'),
    path('admin/users/<int:pk>/', AdminUserDetailView.as_view(), name='admin-user-detail'),
]
```

**Additional hardening layers:**

1. **Audit logging** — log all `is_staff`/`is_superuser` changes (shown above)
2. **Soft confirmation UI** — frontend should require an explicit checkbox for privilege changes
3. **No implicit conversion** — never use `read_only_fields` alone; the serializer field must simply be absent from `Meta.fields`
4. **DRF `extra_kwargs` defense** — mark sensitive fields as `write_only=True` or omit them entirely
