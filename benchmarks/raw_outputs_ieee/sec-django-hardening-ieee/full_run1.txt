## Vulnerability 1: SQL Injection via `cursor.execute()`

**CWE:** 89 (SQL Injection) — Unsanitized input passed directly to database queries through string concatenation/f-string interpolation.

### The Exploit

Given code like this in a report view:

```python
# VULNERABLE — report/views.py
def generate_report(request):
    tenant = request.tenant
    column = request.GET.get('column', 'created_at')
    operator = request.GET.get('operator', '>='')
    value = request.GET.get('value', '')

    query = f"""
        SELECT id, name, status
        FROM {tenant}_orders
        WHERE {column} {operator} %s
    """
    # BUG: column and operator are interpolated from user input;
    # value is parameterized but the other two are not.
    with connection.cursor() as cursor:
        cursor.execute(query, [value])
        rows = cursor.fetchall()
```

An attacker calls:

```
GET /api/reports/generate?column=1;DROP TABLE orders;--&operator=&value=x
```

Or a more targeted blind injection:

```
GET /api/reports/generate?column=name&operator=AND+1=CONCAT((SELECT+password+FROM+admin_users+LIMIT+1),'x')&value=a
```

Because `{column}` and `{operator}` are part of the query structure (not values), `%s` parameterization can't protect them — they're injected at execution time as SQL syntax.

### The Fix

Never interpolate untrusted data into query strings. Use an allowlist for structural elements (table names, column names, operators) and parameterize only actual values. When possible, prefer the ORM:

```python
# HARDENED — report/views.py
from django.db import connection
from django.http import JsonResponse, BadRequest
from django.views.decorators.http import require_http_methods
import logging

logger = logging.getLogger(__name__)

# --- Allowlists (authoritative list, not runtime-checked) ---
SUPPORTED_TABLES = {
    "orders": {"base_table": "{tenant}_orders"},
    "invoices": {"base_table": "{tenant}_invoices"},
    "users": {"base_table": "{tenant}_users"},
}

ALLOWED_COLUMNS = {
    "orders": {"id", "name", "status", "created_at", "updated_at", "total"},
    "invoices": {"id", "order_id", "amount", "issued_at", "status"},
    "users": {"id", "email", "first_name", "last_name", "created_at"},
}

ALLOWED_OPERATORS = {"=", "!=", "<", ">", "<=", ">="}

MAX_QUERY_LENGTH = 2048


def _validate_column(table_group: str, column: str) -> str:
    """Return validated column or raise BadRequest."""
    if table_group not in ALLOWED_COLUMNS:
        logger.warning("Unknown table group: %s", table_group)
        raise BadRequest("Invalid report type.")
    if column not in ALLOWED_COLUMNS[table_group]:
        logger.warning("Column %s disallowed for table group %s", column, table_group)
        raise BadRequest(f"Column '{column}' is not supported for {table_group}.")
    return column


def _validate_operator(operator: str) -> str:
    if operator not in ALLOWED_OPERATORS:
        logger.warning("Operator %s rejected", operator)
        raise BadRequest("Invalid comparison operator.")
    return operator


@require_http_methods(["GET"])
def generate_report(request):
    tenant = getattr(request, "tenant", None)
    if not tenant:
        return JsonResponse({"error": "Tenant context missing."}, status=400)

    report_type = request.GET.get("report", "orders")
    column = request.GET.get("column", "created_at")
    operator = request.GET.get("operator", ">=")
    value = request.GET.get("value", "")

    # Step 1: Validate every user-supplied *structural* element against allowlists
    base_table_template = SUPPORTED_TABLES[report_type]["base_table"]
    validated_column = _validate_column(report_type, column)
    validated_operator = _validate_operator(operator)

    # Step 2: Build the safe query — only the value is parameterized
    sql = (
        f"SELECT id, name, status "
        f"FROM {base_table_template.format(tenant=tenant)} "
        f"WHERE {validated_column} {validated_operator} %s"
    )

    if len(sql) > MAX_QUERY_LENGTH:
        logger.warning("Query length %d exceeds maximum %d", len(sql), MAX_QUERY_LENGTH)
        raise BadRequest("Query too long.")

    try:
        with connection.cursor() as cursor:
            cursor.execute(sql, [value])
            columns = [desc[0] for desc in cursor.description]
            rows = [dict(zip(columns, row)) for row in cursor.fetchall()]
    except Exception as exc:
        logger.error("Report generation failed: %s", exc)
        return JsonResponse({"error": "Internal server error."}, status=500)

    return JsonResponse({"data": rows})
```

Key principles:
1. **Allowlists** control all structural elements — table names, columns, operators. User input can never inject new tokens.
2. **Value parameters** (`%s`) remain parameterized so the DB driver handles escaping.
3. **Query length cap** provides defense-in-depth against DoS-style blow-up.
4. Prefer ORM `.filter(**{f"{column}{operator}": value})` when the pattern allows it — it handles parameterization entirely. Reserve raw SQL for complex aggregation that the ORM can't express.

## Vulnerability 2: Client-Side-Only Object Permissions

**CWE:** 862 (Missing Authorization) — Access control enforced solely in the frontend means any attacker with HTTP tools bypasses it entirely. Server-side authorization is non-negotiable.

### The Exploit

Frontend code:

```jsx
// VULNERABLE — React component
async function fetchOrder(id) {
  // Frontend checks: am I the owner of this order?
  const ownOrders = await api.get("/api/orders/?owner=my_id");
  const isOwned = ownOrders.some(o => o.id === id);
  if (!isOwned) throw new Error("You cannot view this order.");
  return api.get(`/api/orders/${id}/`);  // Only after client-side check
}
```

But API views don't re-check ownership on the server:

```python
# VULNERABLE — order/views.py
class OrderDetailView(generics.RetrieveAPIView):
    queryset = Order.objects.all()          # No filtering by tenant or owner
    serializer_class = OrderSerializer      # Anyone who knows the ID gets it
```

Attacker just sends:

```bash
curl https://api.example.com/api/orders/9999/ \
  -H "Authorization: Bearer <valid_token_for_tenant_A>"
```

Returns tenant B's order because there's zero server-side ownership enforcement. Cross-tenant data leak.

### The Fix

All authorization must be re-evaluated on every request at the server layer:

```python
# HARDENED — order/views.py
from rest_framework import generics, permissions, serializers
from rest_framework.exceptions import NotFound, PermissionDenied
from .models import Order
from .serializers import OrderSerializer


class OwnerPermission(permissions.BasePermission):
    """Object-level permission: only the owner may access the object.
    
    Multi-tenant aware: also restricts to the requesting user's tenant.
    """

    def has_object_permission(self, request, view, obj):
        # Tenant isolation — hard requirement
        if not hasattr(request, "tenant"):
            raise PermissionDenied("No tenant context.")
        if obj.tenant != request.tenant:
            return False
        # Ownership check
        return obj.owner == request.user


class OrderDetailView(generics.RetrieveAPIView):
    """Retrieve a single order — with full server-side authorization."""

    serializer_class = OrderSerializer
    permission_classes = [permissions.IsAuthenticated, OwnerPermission]

    def get_queryset(self):
        """CRITICAL: Filter by tenant AND owner BEFORE fetching.
        
        This prevents mass enumeration even if the permission mixin
        somehow fails to block the request.
        """
        user = self.request.user
        tenant = getattr(self.request, "tenant", None)
        if not tenant:
            return Order.objects.none()
        return Order.objects.filter(tenant=tenant, owner=user).select_related("tenant")

    def retrieve(self, request, *args, **kwargs):
        try:
            return super().retrieve(request, *args, **kwargs)
        except NotFound:
            # Never reveal whether an order exists outside the user's scope
            raise PermissionDenied("This resource cannot be accessed.")
```

For bulk/list operations, the same principle applies:

```python
class OrderListView(generics.ListCreateAPIView):
    serializer_class = OrderSerializer
    permission_classes = [permissions.IsAuthenticated]

    def get_queryset(self):
        user = self.request.user
        tenant = getattr(self.request, "tenant", None)
        if not tenant:
            return Order.objects.none()
        return Order.objects.filter(tenant=tenant, owner=user).select_related("tenant")

    def perform_create(self, serializer):
        serializer.save(owner=self.request.user, tenant=self.request.tenant)
```

And for update/delete:

```python
class OrderUpdateView(generics.UpdateDestroyAPIView):
    serializer_class = OrderSerializer
    permission_classes = [permissions.IsAuthenticated, OwnerPermission]

    def get_queryset(self):
        user = self.request.user
        tenant = getattr(self.request, "tenant", None)
        if not tenant:
            return Order.objects.none()
        return Order.objects.filter(tenant=tenant, owner=user)
```

Key principles:
1. **Filter the queryset first** — `get_queryset()` limits what objects can ever be fetched. This is your primary defense.
2. **Object-level permission class** — double-check ownership in `has_object_permission`. Defense in depth.
3. **Generic messages** — `PermissionDenied` for missing resources rather than `NotFound`, preventing information leakage about record existence.
4. **`perform_create` sets owner/tenant** — the authenticated user and their tenant are set server-side, never trusted from request data.

## Vulnerability 3: Hardcoded Secrets in Settings

**CWE:** 798 (Use of Hard-coded Credentials) — `SECRET_KEY` and database credentials are committed in source code, giving anyone with repo access full system compromise.

### The Exploit

```python
# VULNERABLE — settings.py
SECRET_KEY = "django-insecure-k8#p$z7y!m2q&v4w(9r@l6n*x^j3f"
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": "production_db",
        "USER": "admin",
        "PASSWORD": "SuperSecret123!",
        "HOST": "db.internal.example.com",
        "PORT": "5432",
    }
}
```

An attacker clones the repo, inspects `settings.py`, and gains immediate production database access. Even with `.gitignore`, secrets are often already in the history. A quick `git log --all -p -- settings.py` reveals them to anyone with read access to the repo.

### The Fix

```python
# HARDENED — settings/base.py (NOT committed with real values)
import os
import environ
from pathlib import Path

# Base dir reference
BASE_DIR = Path(__file__).resolve().parent.parent

# Environment variable loader — reads .env file (in .gitignore) and OS env vars

    SECRET_KEY=(str, ""),  # Empty string = will raise below if not set
    DATABASE_URL=(str, ""),
    REDIS_URL=(str, "redis://localhost:6379/0"),
)
environ.Env.read_env(BASE_DIR / ".env")

# ---------------------------------------------------------------------------

    raise ImproperlyConfigured(
        "SECRET_KEY environment variable is required. "

    )

DATABASES = {
    "default": env.db(),  # environ parses DATABASE_URL format
}

REDIS_URL = env("REDIS_URL")

# Production-specific overrides
# ---------------------------------------------------------------------------
if env.bool("DEBUG", False):
    # If DEBUG somehow ends up True in production, warn loudly

        "DEBUG is enabled! Set DEBUG=false immediately."
    )

# Generate a secret key for sessions/cache salt when separate keys are needed
SESSION_COOKIE_SALT = env("SESSION_COOKIE_SALT", default=SECRET_KEY[:16])

AWS_STORAGE_BUCKET_NAME = env("AWS_STORAGE_BUCKET_NAME", default="")
AWS_S3_REGION_NAME = env("AWS_S3_REGION_NAME", default="us-east-1")

# JWT token settings
JWT_SECRET_KEY = env("JWT_SECRET_KEY", default=SECRET_KEY)

# ---------------------------------------------------------------------------

# DATABASE_URL=postgresql://user:password@localhost:5432/mydb
# DEBUG=False
# AWS_ACCESS_KEY_ID=AKIA...
# AWS_SECRET_ACCESS_KEY=...

```


```
.env
.env.local
.env.production
*.key
*.pem
secrets.yml
```

And rotate all exposed secrets immediately if hardcoded values were ever committed:

```bash
# Check if secrets leaked into git history
git log -p --all -S "django-insecure" | head -50

# If found, rewrite history AND rotate ALL credentials
git filter-repo --invert-paths --path-glob '*/settings.py'  # or use bfg-repo-cleaner
```

Key principles:
1. **Fail loudly** — never fall back to a default secret key. Application startup should crash if credentials are missing.
2. **`environ` package** — cleanly parses `DATABASE_URL`, `.env` files, and OS env vars. Far superior to manual `os.environ.get()`.
3. **Separate signing keys** — JWT, session, and CSRF cookies each get independent salts where practical.
4. **Rotate before remediation** — if hardcoded secrets existed in git history, assume compromise and rotate everything before applying this fix.

## Vulnerability 4: Mass Assignment via Underserialized Fields

**CWE:** 915 (Improperly Controlled Modification of Dynamically-Determined Object Attributes) — Serializers that include `fields = "__all__"` or omit explicit `read_only_fields` let attackers modify admin-only fields like `is_staff`, `is_superuser`, or `tenant`.

### The Exploit

```python
# VULNERABLE — user/serializers.py
class UserSerializer(serializers.ModelSerializer):
    class Meta:
        model = User
        fields = "__all__"       # Exposes EVERY field, including sensitive ones
        extra_kwargs = {}        # No special handling
```

API consumer sends:

```bash
curl -X PUT https://api.example.com/api/users/me/ \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"is_staff": true, "is_superuser": true, "role": "admin"}'
```

Elevates their privileges in a single request because the serializer accepts and saves `is_staff`, `is_superuser`, and other admin-controlled fields.

### The Fix

```python
# HARDENED — user/serializers.py
from django.contrib.auth.models import Group
from rest_framework import serializers
from .models import User


class GroupSerializer(serializers.ModelSerializer):
    class Meta:
        model = Group
        fields = ["id", "name"]


class UserRegistrationSerializer(serializers.ModelSerializer):
    """Serializer for user signup — minimal exposure."""

    password = serializers.CharField(write_only=True, min_length=8)
    password_confirm = serializers.CharField(write_only=True, min_length=8)

    class Meta:
        model = User
        fields = ["email", "username", "password", "password_confirm", "first_name", "last_name"]

    def validate(self, attrs):
        if attrs.pop("password") != attrs.pop("password_confirm"):
            raise serializers.ValidationError({"password_confirm": "Passwords do not match."})
        return attrs

    def create(self, validated_data):
        user = User.objects.create_user(
            email=validated_data["email"],
            username=validated_data["username"],
            password=validated_data["password"],
            first_name=validated_data.get("first_name", ""),
            last_name=validated_data.get("last_name", ""),
        )
        return user


class UserSerializer(serializers.ModelSerializer):
    """Full user profile — strictly allowlisted, admin fields excluded."""

    groups = GroupSerializer(many=True, read_only=True)

    class Meta:
        model = User
        # EXPLICIT allowlist — NEVER use "__all__" in production
        fields = [
            "id",
            "email",
            "username",
            "first_name",
            "last_name",
            "phone",
            "date_joined",
            "last_login",
            "is_active",
            # NOTE: intentionally omitted:
            #   - is_staff    (admin privilege — set only by admin API)
            #   - is_superuser (root privilege — set only by admin API)
            #   - is_verified (security-sensitive — set by verification flow)
            #   - role        (RBAC field — set only by admin API)
            #   - password    (write-only, hashed on save)
            "groups",
        ]

        extra_kwargs = {
            "password": {"write_only": True, "required": False},
            "email": {"required": True},
            "is_active": {"read_only": True},  # Users shouldn't deactivate themselves
            "date_joined": {"read_only": True},
            "last_login": {"read_only": True},
            "groups": {"read_only": True},
        }

    def update(self, instance, validated_data):
        """Override to prevent accidental modification of reserved fields."""
        # Strip any admin-only fields that might sneak through
        strip_fields = {"is_staff", "is_superuser", "role", "is_verified", "tenant"}
        for field in strip_fields:
            validated_data.pop(field, None)

        # Handle optional password change
        new_password = validated_data.pop("password", None)
        if new_password:
            instance.set_password(new_password)

        instance.first_name = validated_data.get("first_name", instance.first_name)
        instance.last_name = validated_data.get("last_name", instance.last_name)
        instance.phone = validated_data.get("phone", instance.phone)

        instance.save()
        return instance


class AdminUserSerializer(serializers.ModelSerializer):
    """Only usable by admin/staff users — includes sensitive fields."""

    class Meta:
        model = User
        fields = [
            "id", "email", "username", "password", "first_name", "last_name",
            "phone", "is_active", "is_staff", "is_superuser", "is_verified",
            "role", "groups", "date_joined", "last_login", "tenant",
        ]
        extra_kwargs = {
            "password": {"write_only": True},
            "date_joined": {"read_only": True},
            "last_login": {"read_only": True},
            "tenant": {"read_only": True},
        }

    def create(self, validated_data):
        password = validated_data.pop("password")
        user = User(**validated_data)
        user.set_password(password)
        user.save()
        return user

    def update(self, instance, validated_data):
        password = validated_data.pop("password", None)
        if password:
            instance.set_password(password)
        for attr, value in validated_data.items():
            setattr(instance, attr, value)
        instance.save()
        return instance
```

```python
from rest_framework import generics, permissions
from .serializers import UserSerializer, AdminUserSerializer


class IsStaffOrAdmin(permissions.BasePermission):
    """Restrict admin operations to staff/superuser only."""

    def has_permission(self, request, view):
        return request.user and request.user.is_authenticated and request.user.is_staff


class UserViewSet(viewsets.ModelViewSet):
    """Regular users can only see/edit their own profile."""

    serializer_class = UserSerializer
    permission_classes = [permissions.IsAuthenticated]

    def get_queryset(self):
        # Users see only themselves; admins see all within their tenant
        if self.request.user.is_staff:
            return User.objects.filter(tenant=self.request.tenant)
        return User.objects.filter(id=self.request.user.id)

    def get_serializer_class(self):
        # Use restricted serializer for everyone by default
        return UserSerializer

    def get_queryset(self):
        if self.request.user.is_staff:
            return User.objects.filter(tenant=getattr(self.request, "tenant"))
        return User.objects.filter(id=self.request.user.id)


class AdminUserViewSet(viewsets.ModelViewSet):
    """Admin-only endpoint — manages all users."""

    serializer_class = AdminUserSerializer
    permission_classes = [IsStaffOrAdmin]

    def get_queryset(self):
        return User.objects.filter(tenant=getattr(self.request, "tenant"))
```

```python
# HARDENED — middleware/tenant_middleware.py
# Ensures every request carries a validated tenant
class TenantMiddleware:
    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        # Extract tenant from subdomain, header, or JWT claim — validated
        tenant_header = request.headers.get("X-Tenant-Slug")
        tenant_subdomain = request.get_host().split(".")[0]

        from .models import Tenant
        slug = tenant_header or tenant_subdomain
        try:
            tenant = Tenant.objects.get(slug=slug)
        except Tenant.DoesNotExist:
            from rest_framework.response import Response
            from rest_framework import status
            return Response(
                {"error": "Invalid tenant context."},
                status=status.HTTP_403_FORBIDDEN
            )

        request.tenant = tenant
        return self.get_response(request)
```

Key principles:
1. **Explicit allowlists** — every serializer lists exactly which fields are serializable/deserializable. `"__all__"` does not exist in production.
2. **Read/write separation** — `write_only=True` on password, `read_only=True` on timestamps and privilege flags.
3. **Serializer stratification** — `UserSerializer` (regular users), `AdminUserSerializer` (staff-only), each with distinct field lists. Role-based serializer selection in the view.
4. **Defensive `update()`** — strips admin fields in `save()` even if somehow bypassed.
5. **`create_user` / `set_password`** — never assign `password` directly; always hash it through Django's utilities.
6. **Tenant middleware** — attaches a validated `request.tenant` object on every request, preventing cross-tenant manipulation.
