## Vulnerability 1 — SQL Injection via Raw Query F-Strings

**CWE-89: Improper Neutralization of Special Elements used in an SQL Command**

### The Vulnerable Code

```python
# views.py (report endpoint)
from django.db import connection

def generate_report(request):
    tenant_id = request.query_params.get('tenant', 'default')
    start_date = request.query_params.get('start_date')
    end_date = request.query_params.get('end_date')
    report_type = request.query_params.get('type', 'summary')

    # DANGEROUS: f-string concatenation into raw SQL
    query = f"""
        SELECT * FROM report_data
        WHERE tenant_id = '{tenant_id}'
          AND created_at >= '{start_date}'
          AND created_at <= '{end_date}'
          AND type = '{report_type}'
    """
    with connection.cursor() as cursor:
        cursor.execute(query)  # ❌ No parameterization
        rows = cursor.fetchall()
    return Response(rows)
```

### Exploit Demonstration

```python
# An attacker sends:
GET /api/reports/?tenant=whatever' UNION SELECT password,username,null,null FROM users--&start_date=&end_date=&type=anything

# The resulting query becomes:
"""
SELECT * FROM report_data
WHERE tenant_id = 'whatever' UNION SELECT password,username,null,null FROM users--'
  AND created_at >= ''
  AND created_at <= ''
  AND type = 'anything'
"""

# Result: the `--` comments out the remaining clauses, and the UNION pulls
# every user's password hash into the report response.
```

### Hardened Implementation

```python
# views.py
import logging
from datetime import datetime

from django.conf import settings
from django.db import connection
from rest_framework.decorators import api_view, permission_classes
from rest_framework.permissions import IsAuthenticated
from rest_framework.response import Response
from rest_framework.exceptions import ValidationError

logger = logging.getLogger(__name__)

# Whitelist of allowed report types (prevents logic injection too)
ALLOWED_REPORT_TYPES = {'summary', 'detailed', 'export'}
DATE_FORMAT = '%Y-%m-%d'


@api_view(['GET'])
@permission_classes([IsAuthenticated])
def generate_report(request):
    tenant_id = request.query_params.get('tenant')
    start_date = request.query_params.get('start_date')
    end_date = request.query_params.get('end_date')
    report_type = request.query_params.get('type', 'summary')

    # 1. Validate tenant belongs to authenticated user (multi-tenant isolation)
    if not tenant_id or tenant_id != getattr(settings, 'TENANT_ID'):
        raise ValidationError({'tenant': 'Invalid or missing tenant ID.'})

    # 2. Whitelist report type
    if report_type not in ALLOWED_REPORT_TYPES:
        raise ValidationError({'type': f'Report type must be one of: {ALLOWED_REPORT_TYPES}'})

    # 3. Validate dates via Django's built-in validator
    from django.core.validators import RegexValidator
    date_validator = RegexValidator(r'^\d{4}-\d{2}-\d{2}$')
    for field_name, value in [('start_date', start_date), ('end_date', end_date)]:
        if not value:
            raise ValidationError({field_name: 'Required field'})
        try:
            date_validator(value)
            datetime.strptime(value, DATE_FORMAT)  # sanity-check parseable date
        except ValueError:
            raise ValidationError({field_name: 'Must be YYYY-MM-DD format'})

    # 4. PARAMETERIZED query — zero string interpolation of user input
    query = """
        SELECT id, title, amount, type, created_at
        FROM report_data
        WHERE tenant_id = %s
          AND created_at >= %s
          AND created_at <= %s
          AND type = %s
        ORDER BY created_at DESC
        LIMIT %s OFFSET %s
    """
    params = [
        tenant_id,
        start_date,
        end_date,
        report_type,
        int(request.query_params.get('limit', 100)),
        int(request.query_params.get('offset', 0)),
    ]

    try:
        with connection.cursor() as cursor:
            cursor.execute(query, params)  # ✅ Safe: parameters sent separately
            columns = [col[0] for col in cursor.description]
            rows = [dict(zip(columns, row)) for row in cursor.fetchall()]
    except Exception as exc:
        logger.warning('Report generation failed for tenant %s: %s', tenant_id, exc)
        raise ValidationError({'detail': 'Report generation failed.'})

    return Response(rows)
```

```python
# permissions.py
from rest_framework import permissions


class TenantObjectPermission(permissions.BasePermission):
    """
    Enforce object-level tenant isolation on the SERVER side.

    Allows safe methods (GET, HEAD, OPTIONS) ONLY after confirming the
    requested object belongs to the authenticated user's tenant.
    Write methods require the same ownership check plus IsAuthenticated.
    """

    def has_object_permission(self, request, view, obj):
        if not hasattr(obj, 'tenant_id'):
            # Some models may not have tenant isolation; allow pass-through
            # to Django's standard permission system.
            return True

        return obj.tenant_id == request.user.current_tenant_id


class ReadOnlyIfNotStaff(permissions.BasePermission):
    """Non-staff users get read-only unless they own the object."""

    def has_permission(self, request, _view):
        if not request.user or not request.user.is_authenticated:
            return False
        return True  # will refine at object level

    def has_object_permission(self, request, _view, obj):
        if request.method in permissions.SAFE_METHODS:
            return obj.tenant_id == request.user.current_tenant_id
        return (
            obj.tenant_id == request.user.current_tenant_id
            or request.user.is_staff
        )


class IsAdminOrReadOnly(permissions.BasePermission):
    """Allow admins to do anything, others read-only."""

    def has_permission(self, request, _view):
        if request.method in permissions.SAFE_METHODS:
            return True
        return bool(request.user and request.user.is_staff)
```

```python
# mixins.py
class TenantQuerysetMixin:
    """
    Automatically restrict querysets to the current user's tenant.
    Mix this into any ViewSet that deals with tenant-scoped objects.
    """

    def get_queryset(self):
        qs = super().get_queryset()
        # Staff/admin users see everything; everyone else is scoped to their tenant
        if self.request.user.is_staff:
            return qs
        return qs.filter(tenant_id=self.request.user.current_tenant_id)
```

```python
from myapp.permissions import TenantObjectPermission

    queryset = Report.objects.all()
    serializer_class = ReportSerializer

    # ✅ Server-side object-level authorization
    permission_classes = [
        permissions.IsAuthenticated,
        TenantObjectPermission,
    ]

    def perform_create(self, serializer):
        # Auto-assign the current user's tenant on creation
        serializer.save(tenant_id=self.request.user.current_tenant_id)

    def retrieve(self, request, *args, **kwargs):
        # Retrieve enforces object-level permissions (including tenant check)
        return super().retrieve(request, *args, **kwargs)

    def destroy(self, request, *args, **kwargs):
        # Destroy also enforces object-level permissions
        return super().destroy(request, *args, **kwargs)
```

## Vulnerability 4 — Mass Assignment on Staff Status

**CWE-284: Improper Access Control** (mass assignment / unsafe direct object reference variant)

### The Vulnerable Code

```python
# serializers.py
class UserSerializer(serializers.ModelSerializer):
    """❌ Fields='__all__' exposes every DB column to user-controlled input."""
    class Meta:
        model = User
        fields = '__all__'   # includes: is_staff, is_superuser, role, ...
        write_fields = '__all__'  # DRF doesn't have write_fields, but the intent
                                  # is clear — nothing is excluded from writes

# views.py
class UserViewSet(viewsets.ModelViewSet):
    queryset = User.objects.all()
    serializer_class = UserSerializer
    permission_classes = [IsAuthenticated]  # Any authenticated user can PUT themselves

# Exploit: any authenticated user sends a PATCH/PUT that elevates privileges

{
  "is_staff": true,
  "is_superuser": true
}
# ← Accepts silently because fields='__all__' passes them through the serializer.
```

### Exploit Demonstration

```bash

     -H "Authorization: Bearer <low_priv_token>" \
     -H "Content-Type: application/json" \
```

### Hardened Implementation

```python
# serializers.py
from django.contrib.auth import get_user_model
from rest_framework import serializers

User = get_user_model()


class UserRegistrationSerializer(serializers.ModelSerializer):
    """
    Used ONLY for POST /api/users/ (account creation).
    Password is written once at creation and never readable back out.
    """
    password = serializers.CharField(write_only=True, min_length=8,
                                     help_text='Minimum 8 characters')
    password_confirm = serializers.CharField(write_only=True, help_text='Repeat password')

    class Meta:
        model = User
        # ✅ Explicit whitelist — NOT __all__
        fields = ['id', 'email', 'username', 'password', 'password_confirm',
                  'first_name', 'last_name']

    def validate(self, attrs):
        if attrs['password'] != attrs.pop('password_confirm'):
            raise serializers.ValidationError(
                {'password_confirm': 'Passwords must match.'}
            )
        return attrs

    def create(self, validated_data):
        validated_data.pop('password_confirm')  # consumed by validate; strip before save
        user = User.objects.create_user(**validated_data)
        return user


class UserProfileSerializer(serializers.ModelSerializer):
    """
    Used for GET/PATCH on /api/users/me/.
    Explicitly excludes ALL privilege-changing fields.
    """
    class Meta:
        model = User
        # ✅ Strict whitelist: only profile fields, nothing privileged
        fields = ['id', 'email', 'username', 'first_name', 'last_name',
                  'date_joined', 'last_login']
        read_only_fields = ['id', 'email', 'username', 'date_joined', 'last_login']

    def update(self, instance, validated_data):
        # Double-check: if someone tries to sneak is_staff/is_superuser
        # through the wire despite serializer whitelist, reject it
        sensitive_keys = {'is_staff', 'is_superuser', 'is_active', 'role', 'groups', 'user_permissions'}
        unauthorized = set(validated_data.keys()) & sensitive_keys
        if unauthorized:
            raise serializers.ValidationError(
                {k: 'This field cannot be modified via this endpoint.'}
            )
        return super().update(instance, validated_data)


class AdminUserSerializer(serializers.ModelSerializer):
    """
    ONLY available to staff users for managing other accounts.
    Includes privilege fields intentionally — gate access with permissions.
    """
    class Meta:
        model = User
        fields = ['id', 'email', 'username', 'first_name', 'last_name',
                  'is_staff', 'is_superuser', 'is_active', 'date_joined']
        read_only_fields = ['id', 'date_joined']


class ChangePasswordSerializer(serializers.Serializer):
    """Explicit, safe password change endpoint."""
    old_password = serializers.CharField(required=True, write_only=True)
    new_password = serializers.CharField(required=True, write_only=True, min_length=8)

    def validate_old_password(self, value):
        if not self.instance.check_password(value):
            raise serializers.ValidationError('Current password is incorrect.')
        return value

    def save(self):
        self.instance.set_password(self.validated_data['new_password'])
        self.instance.save()
        return self.instance
```

```python
class RegisterView(generics.CreateAPIView):
    """Open registration — no authentication needed."""
    serializer_class = UserRegistrationSerializer
    permission_classes = [AllowAny]


class UserViewSet(viewsets.ModelViewSet):
    queryset = User.objects.all()

    # ✅ Different serializers for different actions
    def get_serializer_class(self):
        if self.action == 'create':
            return UserRegistrationSerializer
        if self.request.user.is_staff:
            return AdminUserSerializer
        return UserProfileSerializer

    # ✅ Permission gating on EVERY action
    permission_classes = [IsAuthenticated, IsOwnerOrStaff]

    # Staff-only actions stay staff-only regardless of serializer switch
    def get_queryset(self):
        if self.request.user.is_staff:
            return User.objects.all()
        return User.objects.filter(id=self.request.user.id)

    @action(detail=False, methods=['patch'], permission_classes=[IsAuthenticated])
    def change_password(self, request):
        user = request.user
        serializer = ChangePasswordSerializer(user, data=request.data)
        serializer.is_valid(raise_exception=True)
        serializer.save()
        return Response({'status': 'password changed'}, status=status.HTTP_200_OK)

    @action(detail=False, methods=['get'])
    def me(self, request):
        """Self-service profile lookup — returns read-only data."""
        serializer = UserProfileSerializer(request.user)
        return Response(serializer.data)
```

**Defense-in-depth summary for mass assignment:**

| Layer | Mechanism |
|-------|-----------|
| Serializer | Explicit `fields` whitelist — `__all__` eliminated |
| Serializer | Server-side `update()` rejection of privilege keys |
| ViewSet | Per-action `get_serializer_class()` routing |
| ViewSet | `get_queryset()` scopes results by role |
| Permission | `IsOwnerOrStaff` object-level checks |
| Middleware | Optional: middleware that strips unknown fields from `request.data` |

## Complete Patched Architecture Overview

```
┌─────────────┐     ┌──────────────────────────────────┐
│  React App   │     │     Django REST Backend           │
│              │     │                                   │
│ Filter UI    │────▶│ 1. Input validation (whitelist)  │
│ Edit form    │────▶│ 2. IsAuthenticated               │
│              │     │ 3. TenantQuerysetMixin → scope   │
│              │     │ 4. IsOwnerOrStaff perms          │
│              │     │ 5. Parameterized SQL             │
│              │     │ 6. Whitelisted serializer        │
│              │     │ 7. Secret-key from env           │
└─────────────┘     └──────────────────────────────────┘
```

Every vulnerability maps to a concrete layer of defense. Client-side checks are treated as UX features, never as security controls. Each patch stands alone but compounds into a robust multi-tenant hardening posture.
