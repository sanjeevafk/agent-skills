# Multi-Tenant Django REST Security Audit & Remediation

## Vulnerability 1: SQL Injection via f-string Concatenation

**CWE-89: Improper Neutralization of Special Elements used in an SQL Command (SQL Injection)**

### Exploit Demonstration

```python
# VULNERABLE CODE — reports/views.py
class ReportViewSet(viewsets.ModelViewSet):
    queryset = Report.objects.all()
    serializer_class = ReportSerializer

    def retrieve(self, request, pk=None):
        # Attacker-controlled parameters from query params
        start_date = request.query_params.get('start_date')
        end_date = request.query_params.get('end_date')
        status = request.query_params.get('status')

        query = "SELECT * FROM reports_report WHERE tenant_id = %s"
        params = [request.tenant_id]

        if start_date:
            query += f" AND created_at >= '{start_date}'"       # ← f-string injection
        if end_date:
            query += f" AND created_at <= '{end_date}'"          # ← f-string injection
        if status:
            query += f" AND status = '{status}'"                 # ← f-string injection

        with connection.cursor() as cursor:
            cursor.execute(query, params)                      # ← raw SQL with injected values
            rows = cursor.fetchall()
```

An attacker crafts a URL like:

```
GET /api/reports/42/?start_date=1' OR '1'='1'--&status=published
```

This produces:

```sql
SELECT * FROM reports_report WHERE tenant_id = 1 AND created_at >= '1' OR '1'='1'--'
```

Every record is returned — and the attacker can escalate further with subqueries or UNION-based extraction. For multi-tenant isolation breach:

```
GET /api/reports/42/?start_date=' UNION SELECT id, username, password_hash, email FROM auth_user WHERE role='admin' --
```

Now the application leaks other tenants' data.

### Corrected Code

```python
# reports/views.py — FIXED
from django.db import connection

class ReportViewSet(viewsets.ModelViewSet):
    queryset = Report.objects.all()
    serializer_class = ReportSerializer
    filterset_fields = ['status', 'created_at']   # Declarative filtering

    def retrieve(self, request, pk=None):
        report = self.get_object()

        # Use parameterized queries exclusively.
        # Option A — prefer ORM (no cursor needed):
        queryset = Report.objects.filter(tenant_id=request.tenant_id)

        start_date = request.query_params.get('start_date')
        end_date = request.query_params.get('end_date')
        status = request.query_params.get('status')

        if start_date:
            queryset = queryset.filter(created_at__gte=start_date)
        if end_date:
            queryset = queryset.filter(created_at__lte=end_date)
        if status:
            queryset = queryset.filter(status=status)

        # If you truly must use raw SQL, use parameterized placeholders:
        sql = """
            SELECT id, title, status, created_at
            FROM reports_report
            WHERE tenant_id = %(tenant_id)s
              AND status = %(status)s
        """
        raw_params = {
            'tenant_id': report.tenant_id,
            'status': status,
        }
        with connection.cursor() as cursor:
            cursor.execute(sql, raw_params)     # ← safe: values are bound separately
            rows = cursor.fetchall()

        return Response(rows)
```

## Vulnerability 2: Client-Side-Only Object-Level Authorization

**CWE-862: Missing Authorization**

### Exploit Demonstration

```python
# reports/models.py
class Report(models.Model):
    tenant = models.ForeignKey(Tenant, on_delete=models.CASCADE)
    owner = models.ForeignKey(User, on_delete=models.SET_NULL, null=True)
    title = models.CharField(max_length=255)
    confidential = models.BooleanField(default=False)
    content = models.TextField()
```

```javascript
// FRONTEND — React (VULNERABLE APPROACH)
function ReportDetail({ reportId }) {
  const [report, setReport] = useState(null);
  const [isAuthorized, setIsAuthorized] = useState(false);

  useEffect(() => {
    async function load() {
      const res = await fetch(`/api/reports/${reportId}`);
      const data = await res.json();
      
      // ← Trusting the client to enforce permissions!
      const myRole = localStorage.getItem('role');
      if (data.confidential && myRole !== 'admin') {
        setIsAuthorized(false);
        return;                       // "You don't have access."
      }
      setIsAuthorized(true);
      setReport(data);
    }
    load();
  }, [reportId]);

  return isAuthorized ? <ReportView report={report} /> : <Forbidden />;
}
```

A malicious user inspects the API with curl or Burp Suite:

```bash
curl https://app.example.com/api/reports/999 \
  -H "Authorization: Bearer <valid_but_non-admin_token>"
```

The endpoint returns the full confidential report because the **server does not re-check authorization**. The frontend gate is easily bypassed.

Additionally, cross-tenant leakage occurs: User from Tenant-A requests `reports/777` that belongs to Tenant-B, and since no server-side tenant boundary exists, the row leaks.

### Corrected Code

```python
# reports/permissions.py — Server-side permissions module
from rest_framework.permissions import BasePermission, SAFE_METHODS
from rest_framework.exceptions import PermissionDenied


class IsTenantMember(BasePermission):
    """Ensure the requesting user belongs to the same tenant as the resource."""

    def has_object_permission(self, request, view, obj):
        return obj.tenant_id == request.tenant_id


class CanAccessConfidential(BasePermission):
    """Only admins may access confidential objects."""

    def has_object_permission(self, request, view, obj):
        if not getattr(obj, 'confidential', False):
            return True           # Non-confidential — all authenticated users pass
        return request.user.is_staff or request.user.groups.filter(
            name='admins'
        ).exists()


class ReportPermissions(BasePermission):
    """Composite permission combining tenant isolation + role checks."""

    message = 'You do not have permission to access this resource.'

    def has_object_permission(self, request, view, obj):
        # Always allow read on public methods (GET, HEAD, OPTIONS) subject to
        # downstream checks below.
        if not obj:
            return False

        # Step 1: tenant isolation — non-negotiable
        if not IsTenantMember().has_object_permission(request, view, obj):
            return False

        # Step 2: confidentiality gates
        if not CanAccessConfidential().has_object_permission(request, view, obj):
            return False

        return True
```

```python
# reports/views.py — Wire up permissions
class ReportViewSet(viewsets.ModelViewSet):
    queryset = Report.objects.all()
    serializer_class = ReportSerializer
    permission_classes = [IsAuthenticated, ReportPermissions]

    def get_queryset(self):
        """Scope every query to the current tenant — prevents cross-tenant leak at the DB level."""
        return Report.objects.filter(tenant_id=self.request.tenant_id)

    def perform_create(self, serializer):
        """Auto-assign the correct tenant — prevents tenant confusion attacks."""
        serializer.save(tenant=self.request.tenant)
```

## Vulnerability 3: Hardcoded Secrets in Settings

**CWE-798: Use of Hard-coded Credentials**  
**CWE-321: Use of a Hard-coded Cryptographic Key**

### Exploit Demonstration

```python
# config/settings.py — COMMITTED TO GIT (VULNERABLE)
import os

DEBUG = env.bool("DEBUG", default=True)

SECRET_KEY = "django-insecure-f8#kz$9@x!m7r+1qv&wjg^h&t%2y*s&i$w7bq0u@l2j#5z+9f$"
                                          # ^^^ leaked when repo went public

DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": "production_db",
        "USER": "admin",
        "PASSWORD": "SuperSecret123!",       # ^^^ exfiltrable via git history
        "HOST": "db.internal.example.com",
        "PORT": "5432",
    }
}
```

Any developer who clones, any CI log that dumps env, any `.gitignore` mistake, and the credentials are permanently exposed. Worse, hardcoded keys mean:
- You cannot rotate without deploying
- All instances share identical secrets (a compromise is total)
- Static analysis tools flag nothing because the values are literals

### Corrected Code

```python
# config/settings.py — SECRETS MANAGED VIA ENVIRONMENT
import os
from pathlib import Path
from dotenv import load_dotenv
```

## Vulnerability 4: Mass Assignment via Serializer

**CWE-284: Improper Access Control (Mass Assignment)**

### Exploit Demonstration

```python
# reports/serializers.py — VULNERABLE
class ReportSerializer(serializers.ModelSerializer):
    class Meta:
        model = Report
        fields = '__all__'         # ← exposes every field including internals
        read_only_fields = []      # ← nothing is locked down


# views.py — permissive write
class ReportViewSet(viewsets.ModelViewSet):
    # ... defaults to serializer.save(**validated_data)

    def perform_update(self, serializer):
        serializer.save()        # No filtering of saved fields
```

A regular user sends a PATCH that elevates themselves:

```http
PATCH /api/reports/42/
Content-Type: application/json
Authorization: Bearer <user-token>

{
    "title": "Updated Report",
    "owner": 999,                   // hijack ownership
    "tenant": 2,                    // cross-tenant transfer
    "confidential": false,          // downgrade sensitivity
    "is_admin": true                // ← even admin flag on User model
}
```

Result: the user gains control of another tenant's resource and possibly escalates privileges.

Even more subtle — a PUT replaces the entire object, silently zeroing out audit fields (`updated_by`, `version`, `locked_at`) unless explicitly protected.

### Corrected Code

```python
# reports/serializers.py — LOCKED DOWN
from django.contrib.auth import get_user_model
from rest_framework import serializers
from reports.models import Report

User = get_user_model()


class ReadOnlyFieldMixin:
    """Helper to mark fields as write-protected."""
    pass


class ReportCreateSerializer(serializers.ModelSerializer):
    """Serializer for POST — only allows what a creator should set."""

    owner = serializers.PrimaryKeyRelatedField(
        queryset=User.objects.all(),
        required=False,
        default=serializers.CurrentUserDefault(),
    )

    class Meta:
        model = Report
        # Explicit allowlist — NEVER use '__all__' for writable serializers
        fields = ['id', 'title', 'content', 'status', 'owner', 'tags', 'confidential']
        # These can NEVER be written by the user
        extra_kwargs = {
            'id': {'read_only': True},
            'tenant': {'read_only': True},          # assigned server-side
            'created_at': {'read_only': True},
            'updated_at': {'read_only': True},
            'updated_by': {'read_only': True},
            'version': {'read_only': True},
        }

    def create(self, validated_data):
        validated_data['tenant'] = self.context['request'].tenant
        return super().create(validated_data)


class ReportUpdateSerializer(serializers.ModelSerializer):
    """Serializer for PATCH — narrower scope than create."""

    class Meta:
        model = Report
        fields = ['title', 'content', 'status', 'tags', 'confidential']
        extra_kwargs = {
            'id': {'read_only': True},
            'tenant': {'read_only': True},
            'owner': {'read_only': True},
            'created_at': {'read_only': True},
            'updated_at': {'read_only': True},
            'updated_by': {'read_only': True},
            'version': {'read_only': True},
        }

    def update(self, instance, validated_data):
        validated_data['updated_by'] = self.context['request'].user
        return super().update(instance, validated_data)


class ReportListSerializer(serializers.ModelSerializer):
    """Lightweight read-only serializer for list/detail endpoints."""

    owner_name = serializers.CharField(source='owner.get_full_name', read_only=True)

    class Meta:
        model = Report
        fields = ['id', 'title', 'status', 'confidential', 'created_at', 'owner_name']


# Choice-driven serializer dispatch based on HTTP method
def get_report_serializer_class():
    return {
        'create': ReportCreateSerializer,
        'update': ReportUpdateSerializer,
        'partial_update': ReportUpdateSerializer,
        'list': ReportListSerializer,
        'retrieve': ReportListSerializer,
    }


class ReportViewSet(viewsets.ModelViewSet):
    queryset = Report.objects.all()
    permission_classes = [IsAuthenticated, ReportPermissions]

    def get_serializer_class(self):
        """Return the narrowest serializer appropriate for the action."""
        mapping = get_report_serializer_class()
        return mapping.get(self.action, ReportListSerializer)

    def get_queryset(self):
        """Tenant-scoped at the database level."""
        return Report.objects.filter(tenant_id=self.request.tenant_id)

    def perform_create(self, serializer):
        serializer.save(tenant=self.request.tenant)

    def perform_update(self, serializer):
        serializer.save(updated_by=self.request.user)
```

## Summary Table

| # | Vulnerability | CWE | Root Cause | Fix Strategy |
|---|---|---|---|---|
| 1 | SQL Injection | CWE-89 | `f-string` into `cursor.execute()` | Parameterized queries / ORM filters |
| 2 | Missing Authorization | CWE-862 | Client-side permission gate only | Server-side `BasePermission` + tenant-scoped `get_queryset()` |
| 3 | Hard-coded Credentials | CWE-798 / CWE-321 | Literal secrets in committed settings | Environment variables + vault integration |
| 4 | Mass Assignment | CWE-284 | `fields = '__all__'` writable serializer | Explicit field allowlists + `extra_kwargs` read-only + action-specific serializer dispatch |

Each fix is applied at its proper layer: the **database layer** for parameterized queries, the **DRF permission layer** for server-side authorization, the **infrastructure layer** for secrets management, and the **serializer layer** for input allowlisting. This ensures defense-in-depth — disabling the frontend gate, dropping the DB connection, restarting with fresh secrets, or mutating the serializer payload would all still leave the application secure.
