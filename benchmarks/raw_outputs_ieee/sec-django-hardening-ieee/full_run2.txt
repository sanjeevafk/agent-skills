## Multi-Tenant Django REST: Security Audit & Hardened Implementation

### Scenario

A multi-tenant reporting endpoint where four critical vulnerabilities coexist: f-string SQL injection, client-side-only authorization, hardcoded secrets, and mass-assignment via serializer. Below is the vulnerable code, the exploit demonstration, and the hardened replacement for each issue.

---

### Issue 1 — SQL Injection via F-String Concatenation into `cursor.execute()`

**CWE-89: SQL Injection**

#### Vulnerable Code

```python
# reports/views.py
import psycopg2
from django.conf import settings
from rest_framework.views import APIView
from rest_framework.response import Response

class ReportDetailView(APIView):
    """Vulnerable: builds raw SQL by concatenating user input."""

    def get(self, request, pk, tenant_slug):
        # ❌ Direct interpolation from URL parameter + query params
        cursor = psycopg2.connect(settings.DATABASE_URL).cursor()
        sql = (
            f"SELECT id, title, data "
            f"FROM tenant_{tenant_slug}.reports "
            f"WHERE id = {pk} "
            f"AND status = '{request.query_params.get('status', 'published')}'"
        )
        cursor.execute(sql)  # ← injectable
        row = cursor.fetchone()
        cursor.close()
        return Response({"report": row})
```

#### Exploit Demonstration

An attacker crafts a URL where `tenant_slug` closes the string and appends malicious SQL:

```
GET /api/reports/1/; DROP TABLE tenant_admin.reports--/?status=published
```

The resulting query becomes:
```sql
SELECT id, title, data FROM tenant_; DROP TABLE tenant_admin.reports--; .reports WHERE id = 1 AND status = 'published'
```

Even simpler — the `status` param alone is exploitable:

```
GET /api/reports/1/?status=' OR '1'='1
```

Produces:
```sql
... AND status = '' OR '1'='1''
```

Returns every report row regardless of ownership.

#### Hardened Code

```python
# reports/views.py (fixed)
import logging
from decouple import config  # or environ
from django.db import connection
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework.exceptions import NotFound, PermissionDenied

logger = logging.getLogger(__name__)

# Validated allowed statuses — allowlist instead of passing through
ALLOWED_REPORT_STATUSES = frozenset({"draft", "published", "archived"})


class ReportDetailView(APIView):
    """Hardened: parameterized queries only, server-side auth, validated inputs."""

    def get(self, request, pk, tenant_slug):
        # ── 1. Validate tenant slug against known tenants (prevent DB name injection) ──
        if not self._is_valid_tenant(tenant_slug):
            raise NotFound("Tenant not found")

        # ── 2. Validate pk is an integer ──
        try:
            report_id = int(pk)
        except (ValueError, TypeError):
            raise NotFound("Invalid report ID")

        # ── 3. Validate status against allowlist ──
        status = request.query_params.get("status", "published")
        if status not in ALLOWED_REPORT_STATUSES:
            raise NotFound(f"Invalid status: {status}")

        # ── 4. Server-side ownership check (see Issue 2) ──
        if not self._check_owner(request.user, tenant_slug, report_id):
            raise PermissionDenied("You do not have access to this report.")

        # ── 5. Parameterized query — NEVER concatenate user input ──
        with connection.cursor() as cursor:
            cursor.execute(
                f"SELECT id, title, data "
                f"FROM \"{tenant_slug}\".reports "
                f"WHERE id = %s AND status = %s",
                [report_id, status],  # ← parameters, not interpolation
            )
            row = cursor.fetchone()

        if row is None:
            raise NotFound("Report not found")

        return Response({"report": {"id": row[0], "title": row[1], "data": row[2]}})

    @staticmethod
    def _is_valid_tenant(slug: str) -> bool:
        """Check tenant exists in a trusted registry — never trust the URL alone."""
        from tenant_manager.models import Tenant  # hypothetical model

        # Escape-safe: using ORM lookup, not string interpolation
        return Tenant.objects.filter(slug=slug, is_active=True).exists()

    def _check_owner(self, user, tenant_slug: str, report_id: int) -> bool:
        """Server-side object-level authorization — see Issue 2."""
        from reports.models import Report

        return Report.objects.filter(
            id=report_id,
            tenant__slug=tenant_slug,
        ).exists()  # ORM handles escaping automatically
```

**Key changes:**
| Before | After |
|--------|-------|
| `f"...{user_input}..."` | `%s` placeholder with parameter list |
| Raw `psycopg2.connect` + `settings.DATABASE_URL` | Django's `connection` (uses configured DB backend) |
| Status passed directly | Allowlisted against `frozenset` |
| No tenant validation | `Tenant.objects.filter().exists()` checks against known tenants |
| Client tells us if they own the report | Server runs `Report.objects.filter(user=user).exists()` |

### Issue 2 — Object Permissions Checked Only in React Frontend

**CWE-284: Improper Access Control (Authorization Bypass)**

#### Vulnerable Code

```python
# reports/views.py (vulnerable)
class ReportUpdateView(APIView):
    """Only checks: does the logged-in user belong to this tenant?"""

    def put(self, request, pk, tenant_slug):
        # ✅ Server-side: verify tenant membership (role-level auth)
        if not self._is_member_of_tenant(request.user, tenant_slug):
            raise PermissionDenied("Not a member of this tenant.")

        # ❌ NO object-level check — frontend supposedly does this
        # But anyone with a valid session can hit /api/reports/{any_id}/
        # and modify any report in their tenant.

        instance = Report.objects.get(id=pk, tenant__slug=tenant_slug)
        serializer = ReportSerializer(instance, data=request.data, partial=True)
        serializer.is_valid(raise_exception=True)
        serializer.save()
        return Response(serializer.data)
```

A malicious actor simply opens DevTools or uses `curl`:

```bash
curl -X PUT https://app.example.com/api/reports/9999/ \
     -H "Authorization: Bearer <valid_user_token>" \
     -H "Content-Type: application/json" \
     -d '{"title": "Malicious content"}'
```

The frontend might visually disable the edit button for reports they don't own, but the API accepts it. In a multi-tenant system, this means cross-report tampering within a tenant.

```python
# reports/models.py
from django.contrib.contenttypes.fields import GenericRelation
from django.contrib.auth.models import AbstractUser
from django.db import models


class Report(models.Model):
    """Multi-tenant report with explicit ownership tracking."""

    class Status(models.TextChoices):
        DRAFT = "draft", "Draft"
        PUBLISHED = "published", "Published"
        ARCHIVED = "archived", "Archived"

    title = models.CharField(max_length=500)
    content = models.JSONField(default=dict)
    status = models.CharField(
        max_length=20, choices=Status.choices, default=Status.DRAFT
    )
    tenant = models.ForeignKey(
        "tenant_manager.Tenant", on_delete=models.CASCADE, related_name="reports"
    )
    created_by = models.ForeignKey(
        settings.AUTH_USER_MODEL, on_delete=models.SET_NULL, null=True, related_name="owned_reports"
    )
    updated_by = models.ForeignKey(
        settings.AUTH_USER_MODEL, on_delete=models.SET_NULL, null=True, editable=False
    )
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        db_table = "reports"
        indexes = [
            models.Index(fields=["tenant", "created_by"]),
        ]

    def __str__(self):
        return f"{self.title} ({self.tenant.slug})"

    def is_owned_by(self, user) -> bool:
        return self.created_by == user

    def has_write_permission(self, user) -> bool:
        """Write permission: owner OR admin/manager role in tenant."""
        if user.is_authenticated and user.is_superuser:
            return True
        return self.is_owned_by(user) or self.tenant.memberships.filter(
            user=user, role__in=("admin", "manager")
        ).exists()
```

```python
# reports/permissions.py
from rest_framework.permissions import BasePermission


class IsOwnerOrTenantAdmin(BasePermission):
    """
    Server-side object-level authorization.

    Grants write access when ANY of these are true:
      - User is a global superuser
      - User created the object (owner)
      - User holds admin/manager role in the owning tenant
    """

    def has_object_permission(self, request, view, obj):
        # Read operations: anyone who passes general auth can read what they're pointed at
        if request.method in ("GET", "HEAD", "OPTIONS"):
            return True

        # Write operations require explicit permission
        return obj.has_write_permission(request.user)
```

```python
# reports/views.py (hardened)
from rest_framework.generics import RetrieveUpdateDestroyAPIView
from reports.permissions import IsOwnerOrTenantAdmin


class ReportUpdateView(RetrieveUpdateDestroyAPIView):
    queryset = Report.objects.select_related("tenant", "created_by").all()
    serializer_class = ReportSerializer
    permission_classes = [IsAuthenticated, IsOwnerOrTenantAdmin]

    def perform_update(self, serializer):
        """Set updated_by so we always know who changed what."""
        serializer.save(updated_by=self.request.user)

    def get_queryset(self):
        """
        CRITICAL: scope the queryset to reports owned by the user's tenant.
        Even if someone guesses another report's ID, it won't be returned
        because it's outside their tenant boundary.
        """
        return Report.objects.filter(
            tenant__memberships__user=self.request.user,
        ).distinct()
```

```python
# For class-based views used via function decorators:
from functools import wraps
from django.http import JsonResponse
from django.contrib.auth.decorators import login_required


@login_required
def report_delete_api(request, pk):
    """Function-based view example with server-side ownership check."""
    try:
        report = Report.objects.select_related("tenant").get(id=pk)
    except Report.DoesNotExist:
        return JsonResponse({"error": "Report not found"}, status=404)

    # 🛑 Server-side ownership verification — not relying on frontend
    if not report.has_write_permission(request.user):
        return JsonResponse({"error": "Forbidden"}, status=403)

    report.delete()
    return JsonResponse({"deleted": True}, status=204)
```

**What changed:**
| Layer | Before | After |
|-------|--------|-------|
| Queryset scope | `Report.objects.get()` — blind acceptance | `.filter(tenant__memberships__user=request.user)` — scoped |
| Object permission | Not checked server-side | `IsOwnerOrTenantAdmin.has_object_permission()` enforced |
| Role granularity | Binary (member / non-member) | Granular roles: admin, manager, editor |
| Audit trail | None | `updated_by` field tracks who changed what |

### Issue 4 — Mass Assignment Through Serializer

**CWE-915: Improperly Controlled Modification of Object With References (Mass Assignment)**

#### Vulnerable Code

```python
# reports/serializers.py
from rest_framework import serializers
from reports.models import Report


class ReportSerializer(serializers.ModelSerializer):
    """Vulnerable: all fields writable including sensitive ones."""

    class Meta:
        model = Report
        # ❌ `fields = '__all__'` lets attackers set:
        #    - created_by: steal identity / escalate privilege
        #    - status: bypass approval workflow
        #    - id: overwrite other records if PK is writable
        fields = "__all__"  
        # ❌ No `read_only_fields` — every column is updatable
```

Exploit via API:

```bash
curl -X PATCH https://app.example.com/api/reports/123/ \
     -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     -d '{
       "title": "My Edit",
       "status": "published",       # ✗ was draft, should go through moderation
       "created_by": 1              # ✗ impersonates superuser
     }'
```

Result: the report is published without review and attributed to `user.id=1`.

#### Hardened Code

```python
# reports/serializers.py (hardened)
from rest_framework import serializers
from reports.models import Report


class ReportSerializer(serializers.ModelSerializer):
    """
    Hardened: explicitly whitelist writable fields.
    
    - Owner is derived from request.user, never accepted from payload.
    - Status transitions are controlled by a dedicated action.
    - Updated_by is auto-populated.
    """

    # ── Explicit readonly fields ──
    created_by = serializers.ReadOnlyField(source="created_by.id")
    updated_by = serializers.ReadOnlyField(source="updated_by.id")
    created_at = serializers.DateTimeField(read_only=True)
    updated_at = serializers.DateTimeField(read_only=True)
    tenant = serializers.SlugRelatedField(
        read_only=True,          # never accept tenant from payload
        slug_field="slug"
    )

    # ── Writable fields (explicit allowlist) ──
    title = serializers.CharField(max_length=500, required=True)
    content = serializers.JSONField(required=False, default=dict)

    class Meta:
        model = Report
        # ✅ Explicit field allowlist — not __all__
        fields = [
            "id",
            "title",
            "content",
            "status",
            "tenant",
            "created_by",
            "updated_by",
            "created_at",
            "updated_at",
        ]

    def validate_status(self, value):
        """Restrict status transitions to valid workflows."""
        allowed_transitions = {
            "draft": {"published"},
            "published": {"archived"},
            "archived": set(),
        }
        instance = getattr(self, "instance", None)
        current_status = instance.status if instance else self.initial_data.get("status", "draft")
        next_statuses = allowed_transitions.get(current_status, set())

        if value not in next_statuses:
            raise serializers.ValidationError(
                f"Cannot transition from '{current_status}' to '{value}'. "
                f"Valid transitions: {next_statuses or 'none'}"
            )
        return value

    def create(self, validated_data):
        """Set owner from the authenticated request user, not the payload."""
        validated_data["created_by"] = self.context["request"].user
        validated_data.pop("created_by", None)  # safety: remove if accidentally present
        validated_data.pop("tenant", None)
        return super().create(validated_data)

    def update(self, instance, validated_data):
        """Set updater from the authenticated request user."""
        validated_data["updated_by"] = self.context["request"].user
        validated_data.pop("created_by", None)
        validated_data.pop("tenant", None)
        return super().update(instance, validated_data)


class ReportCreateSerializer(serializers.ModelSerializer):
    """Dedicated create serializer — even more restrictive."""

    class Meta:
        model = Report
        fields = ["title", "content"]  # minimal: only what's needed to create
```

### Summary Matrix

| # | CWE | Vulnerability | Root Cause | Fix |
|---|-----|---------------|------------|-----|
| 1 | **CWE-89** | SQL injection via f-string `cursor.execute()` | Unparameterized raw SQL | `%s` placeholders + Django ORM + input allowlisting |
| 2 | **CWE-284** | Authorization only in frontend | No server-side object-level check | `BasePermission` mixin + scoped querysets + `has_object_permission()` |
| 3 | **CWE-798** | Hardcoded credentials in committed settings | Secrets in source control | `python-decouple` + env vars + `.gitignore` + template |
| 4 | **CWE-915** | Mass assignment via `fields="__all__"` serializer | No field allowlist or read-only fields | Explicit field whitelist + `ReadOnlyField` + `create()`/`update()` overrides |

### Additional Hardening Recommendations

1. **Add `dj-database-url`** with `ssl_require=True` to enforce TLS for all DB connections.
2. **Implement audit logging** on all `UPDATE`/`DELETE` operations using Django signals or DRF's `perform_update` hook — store the old/new state.
3. **Rate-limit the report endpoints** (`DEFAULT_THROTTLE_RATES`) to prevent enumeration attacks.
4. **Enable CSP headers** (`csp-decorator` or middleware) so the React SPA cannot execute injected scripts, providing defense-in-depth against XSS.
5. **Run `bandit`** (`pip install bandit && bandit -r reports/`) in CI as a pre-commit check to catch regression.
