## Issue 1: SQL Injection in Report Endpoint

**CWE-89: Improper Neutralization of Special Elements used in an SQL Command ('SQL Injection')**

### Vulnerable Pattern

```python
# models.py / views.py — vulnerable
class ReportViewSet(viewsets.ModelViewSet):
    queryset = Transaction.objects.all()
    
    def retrieve(self, request, pk=None):
        # User-controlled tenant_id passed directly into SQL string
        tenant_id = request.query_params.get("tenant", "")
        cursor = connection.cursor()
        
        # F-string concatenation — SQL metacharacters are never escaped
        sql = f"SELECT * FROM transactions WHERE tenant_id = {tenant_id} AND id = %s"
        cursor.execute(sql, [pk])  # Only `pk` is parameterized; `tenant_id` is raw
        rows = cursor.fetchall()
        return Response(rows)
```

Also common in `filter_backends`:

```python
class ReportFilterBackend(BaseFilterBackend):
    def filter_queryset(self, request, queryset, view):
        tenant = request.query_params.get("tenant")
        sort_col = request.query_params.get("sort", "created_at")
        
        # Both values injected directly into SQL string
        sql = f"SELECT * FROM transactions WHERE tenant_id = {tenant} ORDER BY {sort_col}"
        return RawSQLQuery(sql)  # Or cursor.execute(sql)
```

### Exploit Demonstration

An attacker crafts a `tenant` parameter that closes the identifier context and appends arbitrary SQL:

```bash
# Bypass tenant isolation — returns ALL transactions
curl "https://api.example.com/api/reports/42/?tenant=0 UNION SELECT card_number,cvv,null,null FROM payment_credentials --"

# Stack-based extraction (MySQL/MariaDB)
curl "https://api.example.com/api/reports/42/?tenant=1 UNION SELECT username,password,null,null FROM auth_user WHERE username='admin'"

# Boolean blind injection (PostgreSQL/SQLite)
curl "https://api.example.com/api/reports/42/?tenant=1 OR substr((SELECT password FROM auth_user WHERE username='admin'),1,1)='a'"
```

In the first example, the executed SQL becomes:
```sql
SELECT * FROM transactions WHERE tenant_id = 0 
UNION SELECT card_number,cvv,null,null FROM payment_credentials -- AND id = %s
```

The `--` comment terminates the original predicate, and the UNION extracts data from a table the attacker shouldn't access. Because only `pk` is parameterized, `tenant_id` is evaluated as raw SQL.

### Root Cause

Parameterized queries protect bound parameters from being interpreted as SQL syntax. Here, the f-string embeds `tenant_id` into the query *before* execution, so it becomes SQL code, not data. No escaping occurs.

### Corrected Code — Parameterized Queries + Raw SQL

```python
from django.db import connection
from django.utils.decorators import method_decorator
from django.views.decorators.cache import cache_page


@method_decorator(cache_page(60), name="dispatch")
class ReportViewSet(viewsets.ReadOnlyModelViewSet):
    """Hardened report endpoint with parameterized queries."""
    queryset = Transaction.objects.all()
    serializer_class = ReportSerializer

    def retrieve(self, request, pk=None):
        # Validation: reject non-integer identifiers
        try:
            tenant_id = int(request.query_params.get("tenant", self.request.user.tenant.id))
        except (ValueError, TypeError):
            raise ValidationError({"tenant": "Must be an integer."})

        cursor = connection.cursor()

        # Placeholder for every user-supplied value — never concatenate
        cursor.execute(
            "SELECT * FROM transactions WHERE tenant_id = %s AND id = %s",
            [tenant_id, pk],
        )
        rows = cursor.fetchall()

        if not rows:
            raise Http404("Report not found.")

        return Response(rows)
```

Key principles:
- **Every** user-supplied value gets a `%s` placeholder and appears in the parameter tuple.
- Type coercion (`int()`) rejects non-numeric input *before* it touches SQL.
- `cache_page` is applied safely — caching defeats nothing related to injection.

### Corrected Code — ORM Alternative (Preferred)

```python
def retrieve(self, request, pk=None):
    try:
        tenant_id = int(request.query_params.get(
            "tenant", self.request.user.tenant.id
        ))
    except (ValueError, TypeError):
        raise ValidationError({"tenant": "Must be an integer."})

    try:
        transaction = Transaction.objects.get(tenant_id=tenant_id, id=pk)
    except Transaction.DoesNotExist:
        raise Http404("Report not found.")

    serializer = ReportSerializer(transaction)
    return Response(serializer.data)
```

The ORM handles parameterization automatically and eliminates the `cursor.execute` vector entirely. Prefer this approach whenever the query is not an aggregation too complex for the ORM.

## Issue 2: Client-Side-Only Object Authorization

**CWE-918: Server-Side Request Forgery (SSRF) — secondary concern**

### Problem Architecture

```
┌──────────┐      ┌───────────────┐      ┌───────────┐
│ React UI │──────│ Django API    │      │ Database  │
│           │      │               │      │           │
```

### Root Cause

Server-side authorization is missing at three levels:
1. **List views** don't filter by ownership — `GET /api/cases/` returns everyone's cases.
2. **Detail views** don't check object-level permission — `GET /api/cases/{id}/` serves any authenticated user.
3. **Write/delete views** lack `has_object_permission` — `PUT`/`PATCH`/`DELETE` succeed for anyone authenticated.

```python
import psycopg2
from psycopg2 import sql as pg_sql
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework.permissions import IsAuthenticated
from rest_framework.throttling import UserRateThrottle
from django.conf import settings

logger = logging.getLogger(__name__)


class ReportDataThrottle(UserRateThrottle):
    scope = 'sustained'
    rate = '500/day'


class ReportDataView(APIView):
    """Fetch filtered report data with parameterized queries."""

    permission_classes = [IsAuthenticated]
    throttle_classes = [ReportDataThrottle]

    # Whitelist of allowed column names to prevent identifier injection
    ALLOWED_SORT_FIELDS = frozenset({'id', 'title', 'amount', 'created_at'})

    def _validate_tenant_access(self, request, tenant_id: int) -> bool:
        """Server-side tenant isolation check — cannot be bypassed by client."""
        from .models import TenantMembership
        try:
            member = TenantMembership.objects.get(
                user=request.user,
                tenant_id=tenant_id,
            )
            return member.is_active
        except TenantMembership.DoesNotExist:
            logger.warning(
                "Unauthorized tenant access attempt: user=%s tenant=%s",
                request.user.pk, tenant_id,
            )
            return False

    def get(self, request):
        tenant_id_raw = request.query_params.get('tenant', '')
        start_date = request.query_params.get('start_date')
        end_date = request.query_params.get('end_date')
        sort_field = request.query_params.get('sort', 'created_at')

        # --- Input validation ---
        try:
            tenant_id = int(tenant_id_raw)
        except (ValueError, TypeError):
            return Response(
                {'detail': 'Invalid tenant ID.'}, status=400
            )

        # Server-side authorization: client claims cannot be trusted
        if not self._validate_tenant_access(request, tenant_id):
            return Response(
                {'detail': 'Access denied to this tenant.'},
                status=403,
            )

        # Validate sort field against whitelist (prevent identifier injection)
        if sort_field not in self.ALLOWED_SORT_FIELDS:
            sort_field = 'created_at'

        # Parameterized query: %s placeholders handled by psycopg2
        query = """
            SELECT id, title, amount, created_at
            FROM reports.report_entries
            WHERE tenant_id = %s
              AND created_at >= %s
              AND created_at <= %s
            ORDER BY {sort_col} ASC
            LIMIT 1000
        """.format(sort_col=pg_sql.Identifier(sort_field))  # safe: whitelist-checked

        params = [tenant_id, start_date, end_date]

        with psycopg2.connect(settings.DATABASE_URL) as conn:
            with conn.cursor() as cur:
                cur.execute(query, params)  # ← parameters safely escaped
                rows = cur.fetchall()

        # Serialize safely
        from .serializers import ReportEntrySerializer
        serialized = [
            ReportEntrySerializer(dict(row)).data
            for row in rows
        ]

        return Response(serialized)
```

```python
# reports/views.py — SECURE
import logging
from datetime import date
from rest_framework.views import APIView
from rest_framework.response import Response
from django.db import connection

logger = logging.getLogger(__name__)


def validate_date(value: str) -> date | None:
    """Parse and validate a YYYY-MM-DD date string."""
    if not value:
        return None
    try:
        return date.fromisoformat(value)
    except ValueError:
        return None


class ReportEndpoint(APIView):
    def get(self, request):
        tenant_id = request.query_params.get('tenant_id')
        start_date_str = request.query_params.get('start_date')
        end_date_str = request.query_params.get('end_date')

        # 1. Validate types at the application layer
        if not tenant_id or not tenant_id.isdigit():
            return Response(
                {'error': 'Valid integer tenant_id is required'},
                status=400,
            )
        tenant_id = int(tenant_id)

        start_date = validate_date(start_date_str)
        end_date = validate_date(end_date_str)

        if start_date is None or end_date is None:
            return Response(
                {'error': 'Valid start_date and end_date (YYYY-MM-DD) are required'},
                status=400,
            )

        # 2. Parameterized query — values are never interpolated into SQL text
        sql = (
            "SELECT id, name, revenue FROM orders "
            "WHERE tenant_id = %s "
            "AND order_date BETWEEN %s AND %s"
        )
        params = [tenant_id, start_date.isoformat(), end_date.isoformat()]

        with connection.cursor() as cur:
            cur.execute(sql, params)
            columns = [desc[0] for desc in cur.description]
            rows = [dict(zip(columns, row)) for row in cur.fetchall()]

        logger.info("Report generated for tenant_id=%d", tenant_id)
        return Response({'results': rows})
```

**Key changes:**
- Integer validation strips numeric strings before any DB use
- Dates are parsed by Python's `date.fromisoformat()`, then passed as `.isoformat()` strings
- `%s` placeholders + separate `params` list ensures the database driver handles escaping
- Column metadata is read from `cur.description` rather than trusting schema names from input

```python
from rest_framework import permissions
from django.core.exceptions import PermissionDenied


class IsTenantMemberOrReadOnly(permissions.BasePermission):
    """
    Object-level permission that enforces tenant membership and ownership.

    Only members of the same organization (tenant) can access objects.
    Ownership checks govern write operations.
    """

    def has_object_permission(self, request, view, obj):
        # Read access: allowed only if the requesting user belongs to
        # the same tenant/org as the object being accessed.
        if request.method in permissions.SAFE_METHODS:
            return getattr(obj, 'tenant', None) == request.user.tenant
        # Write/delete access: only the owner may mutate.
        if request.method in permissions.SAFE_METHODS:
            return True
        return obj.tenant == request.user.tenant and obj.author == request.user

    def has_object_permission(self, request, view, obj):
        if request.method in ('PUT', 'PATCH'):
```

## 1. SQL Injection via f-string in `cursor.execute()`

**CWE:89 (SQL Injection)**

### The Vulnerable Code

```python
# views.py or reports/models.py — TERRIBLE PATTERN
```

### How It's Exploited

A malicious client sends `tenant_id` as:

```json
{ "tenant_id": "1 OR 1=1 --", "start_date": "2024-01-01", "end_date": "2026-12-31" }
```

The resulting query becomes:

```sql
SELECT id, amount, status
FROM reports_transaction
WHERE tenant_id = 1 OR 1=1 --
  AND created_at BETWEEN '2024-01-01' AND '2026-12-31'
ORDER BY created_at DESC
```

This returns **every row in the table**, bypassing tenant isolation entirely. An attacker can also use `UNION`-based injection to extract data from unrelated tables like `auth_user`, or use time-based blind injection to exfiltrate column names.

### The Fix

```python
# reports/views.py — HARDENED

from rest_framework.views import APIView
from rest_framework.permissions import IsAuthenticated
from rest_framework.response import Response
from rest_framework import status


class ReportDataView(APIView):
    permission_classes = [IsAuthenticated]

    def get(self, request):
        # Validate types FIRST — integers must be integers
        try:
            tenant_id = int(request.query_params.get('tenant_id'))
            start_date = request.query_params.get('start_date')
            end_date = request.query_params.get('end_date')
        except (ValueError, TypeError):
            return Response(
                {"error": "Invalid parameters"},
                status=status.HTTP_400_BAD_REQUEST
            )

        if not (start_date and end_date):
            return Response(
                {"error": "start_date and end_date are required"},
                status=status.HTTP_400_BAD_REQUEST
            )

        # Use parameterized queries — the ONLY way to safely use raw SQL

            SELECT id, amount, status
            FROM reports_transaction
            WHERE tenant_id = %s
              AND created_at >= %s
              AND created_at <= %s
            ORDER BY created_at DESC
        """

                rows = cursor.fetchall()

            # Log but don't leak internal error details
            self._log_security_event(request, "query_error", str(e))
```

```python
# reports/permissions.py — OBJECT-LEVEL AUTHORIZATION
from rest_framework.permissions import BasePermission
from rest_framework.exceptions import NotFound, PermissionDenied


class IsTenantMember(BasePermission):
    """
    Allow access only if the requesting user is a member of the tenant
    associated with the requested object. Works for nested lookups
    (e.g., /api/tenants/<t>/reports/<r>) and direct FK lookups.
    """
    message = "You do not have access to this resource."

    def has_object_permission(self, request, view, obj):
        # Strategy A: obj has a .tenant attribute pointing to Tenant model
        if hasattr(obj, 'tenant'):
            return request.user.tenants.filter(id=obj.tenant_id).exists()

        # Strategy B: obj has a foreign key that traverses to a tenant
        #   e.g., Report.organization.tenant
        related_tenant_field = getattr(view, '_related_tenant_field', None)
        if related_tenant_field:
            try:
                tenant_id = self._resolve_tenant_id(obj, related_tenant_field)
                return request.user.tenants.filter(id=tenant_id).exists()
            except (AttributeError, ObjectDoesNotExist):
                raise NotFound()

        # Fallback: deny by default if we can't determine tenant membership
        return False

    @staticmethod
    def _resolve_tenant_id(obj, field_path):
        """Walk a dotted field path like 'organization.tenant'."""
        current = obj
        for field_name in field_path.split('.'):
            field = current._meta.get_field(field_name)
            if field.is_relation:
                current = getattr(current, field_name + '_id')
            else:
                current = getattr(current, field_name)
        return current


class IsReportOwnerOrTenantMember(BasePermission):
    """Allow if the user owns the report OR is a member of its tenant."""

    def has_object_permission(self, request, view, obj):
        if hasattr(obj, 'owner') and obj.owner == request.user:
            return True
        # Delegate remaining check to IsTenantMember
        return IsTenantMember().has_object_permission(request, view, obj)
```

```python
from rest_framework import permissions


class TenantObjectPermission(permissions.BasePermission):
    """
    Enforce object-level tenant isolation on the SERVER side.

    Allows safe methods (GET, HEAD, OPTIONS) ONLY after confirming the
    requested object belongs to the authenticated user's tenant.
    Write methods require the same ownership check plus IsAuthenticated.
    """

    def has_object_permission(self, request, view, obj):
        if not hasattr(obj, 'tenant_id'):
            # Some models may not have tenant isolation; allow pass-through
            # to Django's standard permission system.
            return True

        return obj.tenant_id == request.user.current_tenant_id


class ReadOnlyIfNotStaff(permissions.BasePermission):
    """Non-staff users get read-only unless they own the object."""

    def has_permission(self, request, _view):
        if not request.user or not request.user.is_authenticated:
            return False
        return True  # will refine at object level

    def has_object_permission(self, request, _view, obj):
        if request.method in permissions.SAFE_METHODS:
            return obj.tenant_id == request.user.current_tenant_id
        return (
            obj.tenant_id == request.user.current_tenant_id
            or request.user.is_staff

class IsAdminOrReadOnly(permissions.BasePermission):
    """Allow admins to do anything, others read-only."""

    def has_permission(self, request, _view):
        if request.method in permissions.SAFE_METHODS:
            return True
        return bool(request.user and request.user.is_staff)
```
