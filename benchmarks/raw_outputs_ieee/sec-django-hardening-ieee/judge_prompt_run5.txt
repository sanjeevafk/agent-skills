## Vulnerability 1: SQL Injection via Report Endpoint

**CWE-89: Improper Neutralization of Special Elements used in an SQL Command (SQL Injection)**

The report endpoint uses f-string interpolation to build dynamic SQL filters directly into `cursor.execute()`:

```python
# VULNERABLE CODE — reports/views.py
from django.db import connection

class ReportViewSet(viewsets.ModelViewSet):
    queryset = Report.objects.all()
    
    def retrieve(self, request, pk=None):
        filter_field = request.query_params.get('filter_by', 'created_at')
        filter_value = request.query_params.get('filter_value')
        tenant_id = request.user.tenant_id
        
        # CWE-89: User input concatenated directly into SQL string
        query = f"""
            SELECT * FROM reports
            WHERE tenant_id = {tenant_id}
            AND {filter_field} > '{filter_value}'
            ORDER BY created_at DESC
        """
        with connection.cursor() as cursor:
            cursor.execute(query)
            rows = cursor.fetchall()
        return Response(rows)
```

### Exploit

An attacker sends:
```
GET /api/reports/1/?filter_by=1; DROP TABLE users--&filter_value=anything
```

The f-string produces:
```sql
SELECT * FROM reports
WHERE tenant_id = 1
AND 1; DROP TABLE users-- > 'anything'
ORDER BY created_at DESC
```

Result: arbitrary SQL execution — data exfiltration, modification, or destruction across all tenants. With UNION-based injection, the attacker can also read arbitrary columns:
```
?filter_by=1 UNION SELECT username,password,email,is_staff FROM users--&filter_value=x
```

### Fix: Parameterized Queries + Allowlisted Field Names

`cursor.execute()` supports positional parameters (`%s`) but **only for values**, never identifiers. Column/table names must be allowlisted:

```python
# FIXED CODE — reports/views.py
REPORT_FILTER_ALLOWLIST = {
    'created_at': models.DateTimeField,
    'updated_at': models.DateTimeField,
    'title': models.CharField,
    'status': models.CharField,
    'author__email': models.EmailField,
}

def validate_filter_field(field_name: str) -> str:
    """Return validated field name from allowlist, raising ValueError otherwise."""
    if field_name not in REPORT_FILTER_ALLOWLIST:
        raise ValueError(f"Disallowed filter field: {field_name}")
    return field_name


class ReportViewSet(viewsets.ModelViewSet):
    queryset = Report.objects.all()
    serializer_class = ReportSerializer

    def retrieve(self, request, request_obj=None, *args, **kwargs):
        instance = self.get_object()  # handles object-level perms below

        filter_field = request.query_params.get('filter_by', 'created_at')
        filter_value = request.query_params.get('filter_value')
        tenant_id = request.user.tenant_id

        # Step 1: Validate identifier against allowlist (safe for %s escaping)
        validated_field = validate_filter_field(filter_field)

        # Step 2: Use parameterized query for VALUES only
        sql = (
            "SELECT id, title, status, content, created_at, updated_at "
            "FROM reports "
            "WHERE tenant_id = %s "
            "AND {} > %s "
            "ORDER BY created_at DESC"
        ).format(validated_field)  # .format() is safe here — validated_field is constant

        with connection.cursor() as cursor:
            cursor.execute(sql, [tenant_id, filter_value])
            rows = cursor.fetchall()

        column_names = [col[0] for col in cursor.description]
        results = [dict(zip(column_names, row)) for row in rows]
        return Response(results)
```

**Even better approach** — skip raw SQL entirely and use the ORM, which handles parameterization automatically:

```python
# BEST: Pure ORM approach — no raw SQL needed
class ReportViewSet(viewsets.ModelViewSet):
    queryset = Report.objects.all()
    serializer_class = ReportSerializer
    permission_classes = [IsAuthenticated]

    def get_queryset(self):
        tenant_id = self.request.user.tenant_id
        qs = Report.objects.filter(tenant_id=tenant_id)

        filter_field = self.request.query_params.get('filter_by')
        filter_value = self.request.query_params.get('filter_value')

        if filter_field and filter_field in REPORT_FILTER_ALLOWLIST:
            # Handle both model fields and related lookups (e.g., author__email)
            lookup = f"{filter_field}__gt" if '__' not in filter_field else f"{filter_field}_gt"
            qs = qs.filter(**{lookup: filter_value})

        return qs
```

**Key protections:**
| Layer | What it blocks |
|-------|---------------|
| Allowlist on field names | Identifier injection (`DROP`, `UNION`, `--`) |
| `%s` parameters | Value injection (`'; DROP...`, `' OR '1'='1`) |
| ORM `.filter()` | Entire class of injection — DRY and safe |

## Vulnerability 2: Client-Side Only Authorization (BOLA/IDOR)

**CWE-284: Improper Access Control (Broken Object Level Authorization)**

Object permissions are enforced only in the React frontend, meaning anyone can access any object simply by changing its ID in the API URL:

```python
# VULNERABLE CODE — reports/permissions.py
from rest_framework import permissions

class TenantPermission(permissions.BasePermission):
    """WRONG: Only exists in the frontend, missing from backend."""

class ReportPermission(permissions.BasePermission):
    """WRONG: Checks nothing at the view level."""
    def has_permission(self, request, view):
        return request.user.is_authenticated  # That's it
    
    # MISSING has_object_permission entirely
```

### Exploit

User Alice has `tenant_id=5`. She accesses her report fine:
```
GET /api/reports/100  →  200 OK  (her report)
```

She changes the ID:
```
GET /api/reports/100   →  still works because the backend never checks ownership
GET /api/reports/100   →  200 OK  (Bob's report from tenant 7 — data leak)
DELETE /api/reports/100 →  204 No Content  (data destruction)
PATCH /api/reports/100 →  200 OK  (arbitrary write)
```

Without server-side `has_object_permission`, **every CRUD operation is blind** to object ownership. The frontend check is trivially bypassed with `curl`, Burp Suite, or Postman.

### Fix: Server-Side Object-Level Permissions

```python
# FIXED CODE — reports/permissions.py
from rest_framework import permissions
from django.core.exceptions import PermissionDenied


class ObjectOwnerPermission(permissions.BasePermission):
    """
    Enforce object-level access control on the SERVER.
    
    Each request must verify that the authenticated user owns
    or is authorized for the specific object being accessed.
    """

    def has_permission(self, request, view):
        return request.user and request.user.is_authenticated

    def has_object_permission(self, request, view, obj):
        """
        Called after has_permission. Validates access to a SPECIFIC instance.
        
        Returns False → Django returns HTTP 403 Forbidden immediately.
        """
        # Case 1: Objects have a direct owner field
        if hasattr(obj, 'owner'):
            return obj.owner == request.user

        # Case 2: Objects belong to a tenant scope
        if hasattr(obj, 'tenant_id'):
            return obj.tenant_id == request.user.tenant_id

        # Case 3: Custom method (e.g., groups, roles)
        if callable(getattr(obj, 'user_can_access', None)):
            return obj.user_can_access(request.user)

        return False


class ReadOnlyIfNotStaff(permissions.BasePermission):
    """Non-staff can READ but not modify objects."""

    def has_object_permission(self, request, view, obj):
        if not request.user.is_staff:
            return request.method in permissions.SAFE_METHODS
        return True
```

Wire it into the viewset:

## 1. SQL Injection via f-string into `cursor.execute()`

**CWE-89: SQL Injection**

### The Vulnerable Code (`reports/views.py`)

```python
from django.db import connection
from rest_framework.views import APIView
from rest_framework.response import Response

class ReportEndpoint(APIView):
    """Builds filters by f-string concatenation — exploitable."""

    def get(self, request):
        # VULNERABLE: user input baked directly into SQL string
        category = request.query_params.get("category", "")
        tenant_id = request.query_params.get("tenant_id", "1")

        query = f"""
            SELECT id, title, created_at
            FROM reports
            WHERE tenant_id = {tenant_id}
              AND category = '{category}'
        """
        with connection.cursor() as cursor:
            cursor.execute(query)
            rows = cursor.fetchall()
        return Response({"data": rows})
```

### The Exploit

An attacker sends:

```
GET /api/reports/?category=' UNION SELECT password,username,email FROM users --&tenant_id=1
```

The f-string produces:

```sql
SELECT id, title, created_at FROM reports
WHERE tenant_id = 1 AND category = ''
  UNION SELECT password,username,email FROM users --'
```

Result: every user's credentials are returned in the report rows.

### The Fix

Always use parameterized queries. Django's ORM handles this automatically; when raw SQL is unavoidable, pass parameters as a second argument to `execute()`.

```python
from django.db import connection
from rest_framework.views import APIView
from rest_framework.response import Response


class ReportEndpoint(APIView):
    """Hardened — parameterized query, integer cast for safety."""

    def get(self, request):
        category = request.query_params.get("category", "")
        try:
            tenant_id = int(request.query_params.get("tenant_id", "1"))
        except (ValueError, TypeError):
            return Response(
                {"error": "Invalid tenant_id"}, status=400
            )

        # Parameterized — values are escaped by the DB driver
        query = """
            SELECT id, title, created_at
            FROM reports
            WHERE tenant_id = %s
              AND category = %s
        """
        with connection.cursor() as cursor:
            cursor.execute(query, [tenant_id, category])
            rows = cursor.fetchall()

        return Response({"data": rows})
```

**Even better** — ditch raw SQL entirely and use the ORM:

```python
from django.db.models import Q

# reports/permissions.py
from rest_framework.permissions import BasePermission


class IsReportOwnerOrTenantAdmin(BasePermission):
    """Server-side enforcement: user can only access their own reports."""

    def has_object_permission(self, request, view, obj):
        # Tenant admins may read all reports in their tenant
        if request.user.is_staff:
            return obj.tenant == request.user.tenant

        # Owners can always read/edit their own report
        return obj.author == request.user


# reports/views.py
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework.exceptions import NotFound
from .models import Report
from .serializers import ReportSerializer
from .permissions import IsReportOwnerOrTenantAdmin


class ReportDetailView(APIView):
    permission_classes = [IsAuthenticated, IsReportOwnerOrTenantAdmin]

    def get_object(self, pk):
        """Filter by user's tenant to prevent cross-tenant leakage."""
        try:
            return Report.objects.get(
                pk=pk,
                tenant_id=self.request.user.tenant_id,
            )
        except Report.DoesNotExist:
            raise NotFound("Report not found or access denied.")

    def get(self, request, pk):
        report = self.get_object(pk)
        # DRF will automatically call has_object_permission here if
        # using ModelViewSet, but for class-based views we gate manually:
        if not self.permission_classes[1].has_object_permission(
            request, self, report
        ):
            from django.http import JsonResponse
            return JsonResponse({"error": "Forbidden"}, status=403)
        serializer = ReportSerializer(report)
        return Response(serializer.data)
```

## Issue 1: SQL Injection via F-String in `cursor.execute()`

**CWE-89: Improper Neutralization of Special Elements used in an SQL Command ('SQL Injection')**

### Vulnerable Code

```python
# apps/reports/views.py — VULNERABLE
from django.db import connection

def report_endpoint(request):
    tenant_id = request.query_params.get('tenant', '')
    start_date = request.query_params.get('start_date', '')
    end_date = request.query_params.get('end_date', '')

    query = (
        f"SELECT id, name, total FROM orders "
        f"WHERE tenant_id = '{tenant_id}' "
        f"AND created_at BETWEEN '{start_date}' AND '{end_date}'"
    )
    with connection.cursor() as cursor:
        cursor.execute(query)  # f-string → raw SQL injection
        rows = cursor.fetchall()
    return Response(rows)
```

### Exploit

```bash
# Attacker injects arbitrary SQL via the tenant parameter
curl 'http://api.example.com/reports/?tenant=0%27%20UNION%20SELECT%20id,password,email,created_at%20FROM%20users%23'

# Decoded: tenant=' UNION SELECT id,password,email,created_at FROM users#
# Result: Every user credential set dumped into the report endpoint response.
```

### Remediated Code

```python
# apps/reports/views.py — HARDENED
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework.permissions import IsAuthenticated
from django.db import connection, transaction


class ReportEndpoint(APIView):
    """Parameterized queries protect against SQL injection."""

    permission_classes = [IsAuthenticated]

    def get(self, request):
        tenant_id = request.query_params.get('tenant')
        start_date = request.query_params.get('start_date')
        end_date = request.query_params.get('end_date')

        # Validate types before querying — rejects non-integer / malformed values early
        try:
            tenant_id = int(tenant_id)
        except (TypeError, ValueError):
            return Response(
                {'error': 'Invalid tenant_id. Must be an integer.'},
                status=400,
            )

        if not start_date or not end_date:
            return Response(
                {'error': 'start_date and end_date are required.'},
                status=400,
            )

        # PARAMETERIZED query — Django replaces %s placeholders with safely escaped values
        sql = (
            "SELECT id, name, total FROM orders "
            "WHERE tenant_id = %s "
            "AND created_at BETWEEN %s AND %s"
        )
        params = [tenant_id, start_date, end_date]

        with transaction.atomic():
            with connection.cursor() as cursor:
                cursor.execute(sql, params)  # ← safe parameter binding
                columns = [desc[0] for desc in cursor.description]
                rows = [dict(zip(columns, row)) for row in cursor.fetchall()]

        return Response(rows)
```

### Why This Is Secure

| Mechanism | What It Does |
|-----------|-------------|
| `%s` placeholders | Django's psycopg2 adapter parameterizes; values are never interpolated into the SQL string |
| `int()` coercion | Rejects anything that isn't a pure integer before it reaches the query |
| `transaction.atomic()` | Wraps the read in a savepoint for consistency if downstream writes are added |

The OWASP definition applies verbatim: the fix *prevents* special elements (`UNION`, comments, quote closures) from being interpreted as SQL syntax because they travel as data — bound parameters — separate from the command text. See the Django docs for [`raw()`](https://docs.djangoproject.com/en/stable/topics/db/sql/#performing-raw-querysets) and [`connection.cursor()` parameter binding](https://docs.djangoproject.com/en/stable/ref/databases/#third-party-database-notes).

# apps/common/permissions.py — Server-side object-level enforcement
from rest_framework import permissions
from django.core.exceptions import PermissionDenied


class IsTenantMember(permissions.BasePermission):
    """
    Enforce that the requesting user belongs to the requested tenant.

    Checks both:
      1. The URL parameter `tenant` maps to an object the user owns/is member of.
      2. The queryset itself is scoped to the user's tenants (DRF standard pattern).
    """

    def has_permission(self, request, view):

```python
# reports/views.py
from django.db import connection
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework.permissions import IsAuthenticated
from datetime import datetime, date

class ReportEndpoint(APIView):
    permission_classes = [IsAuthenticated]

    def get(self, request):
        tenant_id = request.query_params.get('tenant_id')
        start_date = request.query_params.get('start_date')
        end_date = request.query_params.get('end_date')

        if not all([tenant_id, start_date, end_date]):
            return Response({'error': 'Missing required parameters'}, status=400)

        try:
            start_dt = datetime.fromisoformat(start_date)
            end_dt = datetime.fromisoformat(end_date)
        except ValueError:
            return Response({'error': 'Invalid date format, use ISO 8601'}, status=400)

        # FIX: Use positional %s placeholders with a Python list (or tuple)
        query = """
            SELECT id, amount, created_at
            FROM transactions
            WHERE tenant_id = %s
              AND created_at BETWEEN %s AND %s
        """

        params = [int(tenant_id), start_dt, end_dt]

        with connection.cursor() as cursor:
            cursor.execute(query, params)   # <-- param list, never interpolated
            columns = [col[0] for col in cursor.description]
            rows = [dict(zip(columns, row)) for row in cursor.fetchall()]

        return Response(rows)
```

**Why this works:** PostgreSQL's psycopg2 driver replaces `%s` placeholders with properly escaped values at the protocol level. The query plan is compiled separately from the data — an attacker-controlled string can no longer alter the SQL structure.     tenant_id = request.query_params.get('tenant', 'default')
    date_from = request.query_params.get('date_from', None)

    if not tenant_id:
        return Response(
            {"error": "tenant parameter required"},

    sql = """
        SELECT id, title, content, created_at, updated_at
        FROM reports

    params = [tenant_id, date_from or '1970-01-01']

class ObjectPermissionRequiredMixin:
    """
    Mixin that enforces server-side object-level permissions.
    Each subclass implements has_object_permission(self, request, obj)
    for its own policy logic.
    """
    def has_object_permission(self, request, obj):
        raise NotImplementedError(
            "Subclasses must implement has_object_permission()"
        )

    def _check_permission(self, request, obj):
        if not self.has_object_permission(request, obj):
            logger.warning(
                "User %s denied access to %s id=%s",
                request.user.pk,
                type(obj).__name__,
                getattr(obj, "id", "?"),
            )
            raise PermissionDenied("You do not have permission to access this resource.")

    """
    Secure report detail with server-side tenant enforcement.
    """

        report = get_object_or_404(
            Report.objects.filter(tenant=request.user.tenant),
            id=report_id
        )

        self._check_permission(request, report)
        serializer = ReportSerializer(report)
        return Response(serializer.data)

    def has_object_permission(self, request, obj):
        # Role-based + ownership check on the server
        user = request.user
        if user.is_staff:
            return True
        return user.tenant == obj.tenant
