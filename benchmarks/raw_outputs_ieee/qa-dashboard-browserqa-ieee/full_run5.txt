## QA Plan — Analytics Dashboard Redesign

### Scope Summary

| Area | What we verify |
|---|---|
| **Smoke** | Console errors, network health, Core Web Vitals, LCP/CLS/INP thresholds |
| **Interactions** | Filter flows (date range, category, segment), drill-down clicks, table pagination/sorting |
| **Visual regression** | 3 viewports (1440px, 768px, 390px), dark-mode baselines, masked time-sensitive widgets, 0.1% diff threshold |
| **Accessibility** | Contrast ratios, focus order, ARIA roles on chart tooltips, keyboard nav end-to-end |

---

### Blast-Radius Rules

These are the guardrails the automation must enforce before executing any test run:

1. **Never run against production.** All automated runs target `staging` or `preview` URLs only. If a production URL is detected, abort with an error.
2. **Test credentials only.** Use seeded accounts (`qa-tester@example.com`) with no real data, no PII exposure, and auto-cleanup of any side-effects after the run.
3. **Read-only by default.** The following actions are never triggered automatically:
   - Deleting filters, segments, or saved views
   - Exporting data that hits external APIs or storage buckets
   - Triggering any backend mutation endpoint (POST/PUT/PATCH/DELETE)
4. **Opt-in mutator mode.** If a mutating flow *must* be tested (e.g., saving a custom filter), it requires:
   - An explicit flag passed at runtime (`--allow-mutating`)
   - The staging URL confirmed via environment variable (`TARGET_URL`)
   - Post-run cleanup scripts that reverse any state changes
5. **Redact sensitive data from artifacts.** Any screenshot, log, or console capture that contains tokens, emails, PII, or internal IDs must have them redacted before writing to disk.
6. **Rate-limit awareness.** No more than 2 concurrent browser contexts; throttle navigation to avoid hammering staging load balancers.

---

### Baseline Strategy for Dark Mode

Dark mode has its own baseline because color values shift entirely:

- Store two sets of baselines per page: `light.png` and `dark.png` under `visual-baselines/{page-name}/`.
- Before comparing, read the CSS media query `prefers-color-scheme` or toggle class (`[data-theme="dark"]`) programmatically, then snapshot.
- Diff each against its matched pair (light vs light, dark vs dark). Never cross-compare.
- Time-dependent elements (real-time counters, "last updated" timestamps, live sparklines) are masked with solid rectangles before diffing. The mask coordinates are computed once and stored in `mask-config.json` so regeneration is deterministic.

---

### Exit Criteria (Sign-Off Gates)

Every phase must pass its gate before the next phase runs:

| Phase | Exit Gate |
|---|---|
| Smoke | 0 critical console errors, 0 4xx/5xx network failures, LCP ≤ 2.5s, CLS ≤ 0.1 |
| Interactions | All filter flows return correct results within 2s; drill-down opens details without JS errors; pagination loads fully |
| Visual Regression | Diff ≤ 0.1% on all breakpoints across both themes; no layout shifts > 5px; no missing or overflowed elements |
| Accessibility | 0 WCAG 2.2 AA violations on contrast and labels; keyboard nav reaches every interactive element; chart tooltips expose ARIA role `figure` + `aria-label` |

**Verdict logic:**

- SHIP if all gates pass.
- DO NOT SHIP if any gate has blockers (console errors, failing accessibilities, visual diffs > 0.1%).
- SHIP WITH FIXES if non-blocking issues exist (minor contrast warnings, cosmetic overflow at smallest breakpoint).

```typescript
    });
    
    // Report findings — consider failing if too many low-contrast items
    if (contrastIssues.length > 0) {
      console.log('\nLow contrast elements found:');
      for (const issue of contrastIssues) {
        console.log(`  Text "${issue.text}" (${issue.foreground} on ${issue.background})`);
      }
    }
  });
});
```

### Verdict Framework

When the suite completes, classify the result:

| Scenario | Verdict | Rationale |
|---|---|---|
| All gates pass, zero blocking issues | **SHIP** | Clean across all domains |
| Non-critical issues only (cosmetic overflow, minor contrast warnings) | **SHIP WITH FIXES** | Document remaining items as follow-ups |
| Any critical WCAG violations, console errors, or diffs > 0.1% | **DO NOT SHIP** | Blockers require resolution before launch |
| Missing baselines for new pages | **INCONCLUSIVE** | Cannot determine regression status — generate baselines first |

This plan gives you a complete, executable test suite for the analytics dashboard redesign, all contained within strict safety boundaries that protect against unintended mutations during testing.
