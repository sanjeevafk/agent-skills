## QA Plan — Analytics Dashboard (Redesign)

### Phase 1: Read-Only Smoke Crawl

Goal: detect showstoppers before any interaction. No clicks beyond initial navigation.

```
Scope: All public routes of the analytics dashboard.
Method: headless browser → collect console logs + network requests → report only non-noise failures.

Filter noise by origin:
  - Skip: *.google-analytics.com, *.gtm.*, *.segment.com, *.hotjar.com,
          *.cloudfront.net/*webfont*, fonts.gstatic.com, recaptcha.*
  - Report: all console.error(), any 4xx/5xx from our own domains,
            any XHR/fetch that resolves >= 2000ms (slow endpoint warning).

Checks per route:
  1. Navigate → wait for `networkidle`
  2. Collect console messages (error/warn level only)
  3. Inspect request/response status codes
  4. Measure LCP, CLS, INP via PerformanceObserver / DevTools performance timeline
     Thresholds: LCP < 2.5s, CLS < 0.1, INP < 200ms
  5. Screenshot above-the-fold at 1440px
  6. Repeat viewport at 768px and 390px (no scroll screenshots yet)

Exit gate: If > 0 console.error or > 5% of requests are 4xx/5xx → halt interaction phase,
           return findings immediately. Do NOT proceed until fixed.
```

**Route inventory example:** `/analytics`, `/analytics/realtime`, `/analytics/reports/{id}`,
`/analytics/settings`, `/auth/login` (if unauthenticated route exists)

### Phase 2: Interaction Tests

Goal: verify filter logic, drill-down paths, state management across breakpoints.

**Safe-to-interact boundaries:**
All interactions are read-only journeys (filtering, drilling into existing data views).
No export, no share-link generation (side-effects), no settings changes (mutation).

#### 2a. Filter System

| Test | Steps | Expected |
|------|-------|----------|
| Single filter apply | Select date range → apply | Table/charts re-render, URL query params update |
| Multi-filter combo | Date + Category + Metric → apply | Results narrow correctly, "clear all" works |
| Empty result set | Pick invalid combination | Shows "No results" empty state (not crash/spinner forever) |
| Rapid-fire filters | Change filter rapidly 5x (debounce check) | Only last selection renders, no race conditions |
| Filter reset | Clear all → re-apply same combo | Idempotent — same data as first apply |
| URL sync | Apply filters → copy URL → paste in new tab | Same filtered state restored |
| Bookmark deep link | `/analytics?range=7d&category=email&metric=opens` | Page loads pre-filtered correctly |

Breakpoint variance check: run each test at 1440, 768, 390. At 390, verify filter drawer collapses/expands correctly on mobile.

#### 2b. Drill-Down Flows

| Flow | Path | Verify |
|------|------|--------|
| Chart segment click | Click bar in bar chart → detail panel opens | Panel shows subset data, breadcrumb updates, back navigates correctly |
| Table row expand | Click row chevron/arrow → expanded detail | Accordion opens without shifting unrelated rows |
| Pagination | Click page 3 → click page 1 | URL updates, correct data shown, "previous"/"next" disable at edges |
| Sort reversal | Click column header A→Z then Z→A | Arrow icon toggles, data order reverses correctly |
| Cross-filter | Drill from chart → table highlights matching rows | Highlight persists during sort/page |

#### 2c. State & Edge Cases

- **No-data states:** All charts show placeholder when dataset is empty (don't render SVG errors)
- **Slow connection:** Throttle to 3G in devtools → loading skeletons appear (not frozen UI)
- **Session expiry:** During long filter interaction → auth token expires → redirect to login, preserve filter params on return

### Phase 3: Visual Regression

#### Baseline Strategy

```
Strategy: Two-tier baselines.

Tier 1 — Structural baseline (required):
  Commit screenshots of CURRENT design as the new baseline.
  This is the FIRST run — everything will diff. That's expected.
  Mark these files with comment: // BASELINE v-redesign [date]
  After this pass, ALL future runs compare against this baseline.

Tier 2 — Historical baseline (if available):
  If prior redesign screenshots exist, compare both:
  old-vs-new (to document intentional changes) AND new-vs-newbaseline (regression detection).

Masking rules — DO NOT compare:
  - Timestamps / "Last updated: X minutes ago"
  - Real-time counters / live numeric values (use regex mask: `\d{1,3}(,\d{3})*`)
  - User avatars/profile pics (randomize/mask)
  - Any widget showing current time/date
  - Charts where underlying data is seeded differently (mask chart canvas, compare layout grid only)

Diff threshold: 0.1% pixel mismatch allowed (accounts for anti-aliasing, font rendering).
Anything above 0.1% flagged for manual review.

Tolerance config per element type:
  - Layout containers (divs, grids): 0.0% tolerance — exact match required
  - Charts/SVG: 0.3% — minor rendering variation acceptable
  - Text content: 0.0% — compare text nodes separately, not pixels
  - Icons/font glyphs: 0.2% — small anti-aliasing diffs expected
```

#### Screenshots per viewport

For each of ~10 key pages/states × 3 viewports = ~30 baseline images minimum.

Critical states to capture:
1. Default loaded state
2. Active filter state
3. Drill-down opened state
4. Empty state
5. Dark mode (all of the above, plus dark-specific states below)

#### Dark Mode Baseline

```
Approach: Parallel capture — screenshot each state in BOTH light and dark themes.

Rules:
  - Test system-level dark mode (prefers-color-scheme: dark)
  - Also test if the app has a manual toggle — switch it mid-session
  - Flag issues:
    * Contrast ratio < 4.5:1 (text/bg) or < 3:1 (large text/UI components)
    * Pure black (#000) backgrounds (should use elevated surface color like #1e1e1e)
    * Colors that become invisible in dark mode (dark gray on black)
    * Shadows visible on dark bg (shadow won't render — use outline/border instead)
    * Image assets that don't adapt (no @media prefers-color-scheme swap)
  - Check all chart colors remain distinguishable in dark mode
  - Verify tooltips/popovers maintain proper contrast on dark bg
```

### Phase 4: Accessibility Pass

#### Automated scan

Run axe-core (or equivalent) on every page state at every breakpoint. Target: **zero WCAG 2.2 AA violations**.

#### Manual checks (axe covers ~35% of WCAG — these require human eyes)

**Focus order:**
- Tab through every interactive element on each page
- Focus order matches visual reading order (top→bottom, left→right)
- No focus traps (can always Tab forward and backward)
- Custom dropdowns/filter menus: focus cycles within menu when open, escapes on Escape key
- Drill-down panels: focus moves into panel on open, returns to trigger on close

**Chart-specific ARIA:**
- Each chart has `role="img"` with `aria-label` describing what's shown
  - Example: `aria-label="Bar chart showing email opens by day for the last 7 days"`
- Data points/segments have accessible names via `title` elements or `aria-label`
- Chart legend is keyboard-focusable and describes each series
- Tooltips on hover: also appear on `focus` (keyboard users can't hover)
  - Tooltip HTML includes `role="tooltip"`
  - Trigger element has `aria-describedby` pointing to tooltip id
- Keyboard alternative for mouse-driven chart exploration (Tab through data points)

**Contrast verification:**
- Spot-check 20+ color pairs manually using contrast checker tool
  Critical areas: chart data labels, table cell text, filter button active states, disabled states, error messages, success banners
- Flag any data visualization color that doesn't meet 4.5:1 against its background (including dark mode variant)
- Verify color alone conveys meaning — redundant cues present (icon, pattern, label beside color)

**Screen reader landmarks:**
- `<main>` wraps dashboard content
- `<nav>` for filter sidebar / nav
- `<table>` with `<caption>` or `aria-label` for data tables
- `<button>` used for actions (not `<div onclick>`)
- Live regions (`role="status"`, `aria-live="polite"`) for dynamic chart/table updates
- Heading hierarchy logical (h1 for page title, h2 for section headers within dashboard)

**Reduced motion:**
- `@media (prefers-reduced-motion: reduce)` disables chart animations
- Transitions still function but aren't jarring

### Blast Radius Rules

**NEVER click (always read-only):**

| Domain | Reason |
|--------|--------|
| `/settings/*` | Mutates account/workspace configuration |
| Export/share buttons | Creates side effects (files sent, links generated) |
| User profile / account management | Changes identity state |
| Delete/archive actions | Destructive — even on staging, avoids polluting datasets |
| Payment/subscription flows | Money movement — off-limits unless explicit opt-in + staging |
| Admin/user invite flows | Sends real emails, creates accounts |
| Webhook/config endpoints | Modifies integrations |

**Allowed (safe read-only):**
- Filter interactions
- Navigation between dashboard views
- Drill-down into displayed data
- Theme toggle (light ↔ dark)
- Sort, paginate, resize tables
- Close/open panels/modals
