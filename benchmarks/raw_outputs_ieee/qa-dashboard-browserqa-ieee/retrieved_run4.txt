# Analytics Dashboard QA Plan

## Architecture Overview

Six interconnected phases, each gated by pass/fail criteria. Early phases are read-only; later phases introduce interaction and visual comparison. Each phase must sign off before advancing.

```

                                                    │

          │
```

## Phase 1: Read-Only Smoke Crawl

**Goal:** Establish baseline health — does the page load without noise?

### Browser Setup
- Use Playwright (or Puppeteer) with three browser contexts mimicking target viewports. No UI, headless or headed (`headed` recommended for screenshot accuracy).
- Block third-party tracking domains via `context.route()`:
  ```ts
  const NOISE_DOMAINS = ['google-analytics.com', 'segment.io', 'hotjar.*', 'doubleclick.net'];
  await context.route('**/*', route => {
    const url = new URL(route.request().url());
    if (NOISE_DOMAINS.some(d => d.replace('*','').some(s => url.hostname.includes(s))))
      return route.abort('blockedbyclient');
    route.continue();
  });
  ```

### Per-Viewport Execution (`1440px`, `768px`, `390px`)

For each viewport:

| Check | Method | Pass Criteria |
|-------|--------|---------------|
| **Navigation** | `page.goto(url)` | Response ≤ 3s, no crash |
| **Console errors** | Intercept `page.on('console')`, filter out `PerformanceObserver` and known lib warnings | Zero `error()` level entries; warn count recorded but non-blocking |
| **Network requests** | Collect all `request.finished()` responses; skip preflight/health/ping | Zero 4xx and 5xx status codes |
| **Above-fold rendering** | `page.screenshot({ clip: { x:0, y:0, width, height: 900 } })` per viewport | Image file exists, no blank regions |
| **Core Web Vitals** | Inject `performance Observer` script; extract LCP, CLS, INP | LCP < 2.5s, CLS < 0.1, INP < 200ms |

### Output Artifacts
- `smoke_results/{viewport}.json` — structured per-check results
- `smoke_screenshots/{viewport}_above_fold.png` — one image per viewport
- Summary table of console error counts by type

## Phase 2: Interaction Flow Tests

**Goal:** Verify user journeys — filtering, drill-down, and state persistence.

### Test Matrix

| Flow | Steps | Expected Outcome |
|------|-------|-----------------|
| **Filter → Re-render** | Open dashboard → select date range → pick metric dropdown → apply | Chart/table data updates within 1s; no stale artifacts visible |
| **Drill-down** | Click a chart segment or table row → navigate to detail view → back | Detail view loads; back returns to original filter state |
| **Multi-filter compose** | Apply date + metric + dimension filters → clear single filter → verify rest persist | Unchanged filters remain; only cleared filter resets |
| **Empty states** | Apply filter组合 with zero results | Graceful empty-state component renders (no raw error JSON) |
| **URL sync** | After applying filters, copy/paste URL into new tab | Same filtered view renders (state is URL-encoded) |

### Execution Approach
```ts
// Example: Filter → Re-render flow
test('filter updates chart data', async ({ page }) => {
  await page.setViewportSize({ width: 1440, height: 900 });
  await page.goto(DASHBOARD_URL);
  
  // Capture initial chart data
  const initialData = await page.locator('[data-testid="chart-canvas"]').evaluate(el => el.dataset.dataHash);
  
  // Apply filter
  await page.selectOption('[data-testid="date-range"]', { label: 'Last 7 days' });
  await page.click('[data-testid="apply-filters"]');
  
  // Wait for network settle
  await page.waitForLoadState('networkidle');
  
  // Chart should have re-rendered with new data
  const newData = await page.locator('[data-testid="chart-canvas"]').evaluate(el => el.dataset.dataHash);
  expect(newData).not.toBe(initialData);
  
  // Verify no overlay errors
  const errorToasts = await page.locator('[data-testid="error-toast"]').count();
  expect(errorToasts).toBe(0);
});
```

### Key Data Attributes to Target
- `[data-testid="chart-*"]` for chart containers
- `[data-testid="table-*"]` for data grids
- `[data-testid="filter-*"]` for controls
- `[data-testid="error-toast"]` for error popups
- `[data-testid="empty-state"]` for no-data placeholders

## Phase 3: Visual Regression

**Goal:** Detect unintentional layout/styling changes using pixel-level comparison with smart masking.

### Screenshot Strategy

Run after Phase 2 passes (post-interaction screenshots capture rendered charts):

| State | Description |
|-------|-------------|
| **Default loaded** | Fresh dashboard, default filters, above-fold + full-page scroll |
| **After each filter combo** | One screenshot per major filter combination |
| **After drill-down** | Detail views captured |
| **Resize transitions** | Screenshot while resizing from 1440 → 768 → 390 |

Three viewports × ~8 states = **~24 reference + 24 comparison images per run**.

### Masking Time-Dependent Widgets

Widgets showing dynamic data must be masked before diffing:

```ts
/**
 * Masks areas that change between runs due to time-sensitive content.
 * Returns a canvas mask with black rectangles over those regions.
 */
function createTimeMask(page, viewport) {
  const selectors = [
    '[data-testid="real-time-counter"]',    // live numbers
    '[data-testid="timestamp-badge"]',       // "updated X min ago"
    '[data-testid="sparkline-inline"]',      // tiny inline sparklines
    '[data-testid="current-value-label"]',   // live values in headers
  ];
  
  const maskCanvas = createCanvas(viewport.width, viewport.height);
  const ctx = maskCanvas.getContext('2d');
  ctx.fillStyle = '#000000';
  
  for (const sel of selectors) {
    const elements = page.locator(sel).all();
    for (const el of elements) {
      const box = await el.boundingBox();
      if (box) ctx.fillRect(box.x, box.y, box.width, box.height);
    }
  }
  return maskCanvas;
}
```

### Diff Threshold & Comparison Logic

- **Pixel diff threshold**: `0.1%` (1 in 1000 pixels allowed to differ)
- **Algorithm**: Structural similarity (SSIM) preferred over raw pixel diff; fallback to pixel diff if library unavailable
- **Per-pixel tolerance**: Allow ±2 luminance delta in masked regions (anti-aliasing margin)
- **Flaky rejection**: If >5% of comparisons hit the threshold automatically flag for human review rather than hard fail

```ts
import { PixelDiff } from '@example/diff-lib';

async function compareScreenshots(ref: Buffer, comp: Buffer, mask?: Buffer): Promise<{diffPercent: number, failed: boolean}> {
  const diff = new PixelDiff({ refWidth: ref.width, refHeight: ref.height, maxColorDiff: 2 });
  const result = diff.compare(ref, comp, mask);
  
  // Expressed as percentage of total pixels exceeding threshold
  const diffPercent = (result.differentPixels / (ref.width * ref.height)) * 100;
  return { diffPercent, failed: diffPercent > 0.1 };
}
```

### Baseline Management
- Baselines stored in `baseline/{viewport}/{state_name}.png`
- Intentional redesign diffs require explicit `baseline approve` command to overwrite
- CI blocks merge if unapproved regressions appear

## Phase 4: Accessibility Pass

**Goal:** Ensure the dashboard meets WCAG 2.1 AA for screen readers, keyboard navigation, and contrast.

### Contrast Verification

Check every text/background color combination against WCAG AA minimums:

```ts
/**
 * Extracts all computed style text elements and verifies contrast ratios.
 * Requires a headed browser instance for accurate CSSOM resolution.
 */
async function auditContrast(page) {
  const violations = await page.evaluate(() => {
    const elements = Array.from(document.querySelectorAll('*'));
    const results = [];
    
    for (const el of elements) {
      const style = window.getComputedStyle(el);
      if (style.color === 'transparent' || style.visibility === 'hidden') continue;
      
      const fg = rgbToHex(style.color);
      const bg = getEffectiveBackground(el);
      
      if (!fg || !bg) continue;
      
      const ratio = contrastRatio(fg, bg);
      const minRequired = isLargeText(el) ? 3.0 : 4.5; // WCAG AA
      
      if (ratio < minRequired) {
        results.push({
          element: `${el.tagName}.${el.className.split(' ').join('.')}`,
          fg, bg, ratio,
          required: minRequired,
          node: el.outerHTML.substring(0, 200),
        });
      }
    }
    return results;
  });
  
  return violations;
}
```

Focus order follows DOM order:
- Tab through entire page
- Focus indicator ≥ 2px outline, ≥ 3:1 contrast against adjacent color
- No focus traps modals/tooltips

### ARIA Role Audit

Critical interactive elements require correct roles. Target checklist:

| Element | Required Role/Property | What to Verify |
|---------|----------------------|----------------|
| **Chart container** | `role="img"` + `aria-label` describing the chart | Label includes title, metric, time range |
| **Chart tooltip** | Popover role pattern (`aria-describedby` linking to tooltip element) | Tooltip is programmatically associated with trigger point |
| **Table header** | `role="columnheader"` (or `<th>`) | Sortable columns expose `aria-sort` attribute |
| **Filter controls** | `role="group"` with `aria-labelledby` | Group labeled by adjacent heading/filter name |
| **Loading skeleton** | `role="status"` + `aria-live="polite"` | Announces loading state without interrupting reading |
| **Pagination** | `role="navigation"` + `aria-label="pagination"` | Links contain descriptive text ("Page 2 of 5") |
| **Dark mode toggle** | `role="switch"` + `aria-checked` + `aria-label="Dark mode"` | Toggle reflects true checked state |
| **Export button** | `aria-label` specifying export format | e.g., "Export as CSV" not just "Export" |

### Automated + Manual Coverage
- **Automated**: axe-core sweep (`axe.run()`) capturing violations categorized by rule ID
- **Manual keyboard traversal**: tester walks every flow using only Tab, Enter, Space, Escape
- **Screen reader spot-check**: VoiceOver (macOS) or NVDA on one representative flow (filter → table → drill-down)

## Phase 5: Dark Mode Baseline Strategy

**Goal:** Ensure all components render correctly in both light and dark themes with no hardcoded assumptions.

### Two-Baseline Strategy

Maintain **separate baselines** per theme. Never mix light/dark screenshots in the same comparison bucket.

```
baseline/
├── light/
│   ├── desktop/1440_default.png
│   ├── tablet/768_default.png
│   └── mobile/390_filter_applied.png
└── dark/
    ├── desktop/1440_default.png
    ├── tablet/768_default.png
    └── mobile/390_filter_applied.png
```

### Theme Switching Mechanism
Assume one of these patterns. Verify which applies and adapt:

| Pattern | Detection | Test Step |
|---------|-----------|-----------|
| **CSS class on `<html>`** | `document.documentElement.classList.contains('dark')` | Toggle button click → verify class swap → screenshot |
| **`prefers-color-scheme` media query** | `window.matchMedia('(prefers-color-scheme: dark)')` | Override via devtools or set `colorScheme` preference |
| **CSS custom properties injected** | `getComputedStyle(document.body).getPropertyValue('--bg-primary')` | Swap token values → assert colors shift |

### Specific Dark Mode Checks

| Check | Detail |
|-------|--------|
| **No white-on-white or near-black-on-black** | Every visible text element has sufficient contrast in both themes |
| **Chart color palettes** | All chart series distinguishable; palette swaps to dark-friendly variant |
| **Border visibility** | Borders use `border-color` that adapts (e.g., `rgba(255,255,255,0.1)` in dark) |
| **Icon opacity** | Icons maintain visibility, not lost against dark backgrounds |
| **Shadow/elevation** | Shadows visible on dark (use tinted shadows, not pure black `box-shadow`) |
| **Images/media** | Charts exported as PNG/SVG retain readability; no transparent backgrounds that blend |
| **Scrollbar** | Custom scrollbar styles adapt (webkit-scrollbar-thumb/track) |

## Phase 6: Sign-Off Exit Criteria

A dashboard release gets **QA approved** only when ALL exit gates pass simultaneously.

### Gate Checklist

| Gate | Condition | Owner |
|------|-----------|-------|
| **Smoke health** | Zero 4xx/5xx; zero console errors; CWV metrics within thresholds on all 3 viewports | Automated |
| **Interaction flows** | All 5 flows pass (filter, drill-down, multi-filter, empty state, URL sync) | Automated |
| **Visual regression** | No unapproved diff > 0.1%; all time-dependent widgets masked; resize transitions clean | Automated + manual review of flagged diffs |
| **Accessibility** | Zero WCAG AA violations (axe-core score 100/100); keyboard traversal completes entire funnel; screen reader confirms key labels | Automated + manual |
| **Dark mode** | All components render legibly; no forced-theme overrides leak; baseline passes separately for light AND dark | Visual regression (split baselines) |
| **Performance ceiling** | FCP < 1.5s on desktop, < 2.5s on mobile; TBT < 150ms; no jank during filter application (measured via Long Task API) | Automated (Lighthouse CI or puppeteer-performance) |

### Hard Gates — Nothing Gets Signed Off If…
- Any console error reaches `error()` level
- Any network request returns 5xx
- Any chart renders with broken axes, truncated labels, or overlapping series
- Keyboard trap detected (cannot escape a modal or tooltip)
- Color contrast violation affects more than one element
- Dark mode produces invisible text or hidden interactive elements
- Resize causes horizontal overflow (scrollbar appears at tablet/mobile breakpoints)

## Blast Radius Rules

These define what **never** gets touched by automation — the safe zones that protect stability.

### Immutable Targets (Never Auto-Click)

| Element Category | Why Protected | Examples |
|-----------------|---------------|----------|
| **Production API calls** | Irreversible side effects | `POST /api/export`, `POST /api/delete`, `POST /api/share` |
| **Auth operations** | Lockout/boundary conditions | Login form submissions, password reset |
| **Settings mutations** | Cross-test pollution | User preferences, saved layouts, theme persistence |
| **Payment/billing pages** | Real financial transactions | Checkout, subscription management, invoicing |
| **Third-party embeds** | Out-of-scope ownership | Embedded Slack widgets, external calendar feeds |

### Safe Interaction Boundaries

| Action | Scope Limit |
|--------|-------------|
| Filtering | Only pre-built filter chips/date ranges — never free-text API queries |
| Navigation | Dashboard internal links only — no outbound links |
| Sorting | Table column sorts only — no "Sort by custom" |
| Drill-down | Only paths that lead back to current dashboard hierarchy |

### Guardrails
- All API interceptors use `cy.intercept()` / `route.fetch.mockResponse()` for mutations — nothing hits production
- Export/share actions mocked with `Promise.resolve(true)` — no actual file generation
- Page reloads capped at 2x per flow to prevent infinite loop detection
- Rate limiting respected: inter-element clicks spaced ≥ 100ms apart
