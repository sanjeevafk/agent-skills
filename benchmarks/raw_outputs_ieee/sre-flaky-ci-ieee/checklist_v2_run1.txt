## Systematic Debugging Analysis: Intermittent Test Suite Flakiness

---

### PHASE 1 — Root Cause Investigation & Hypothesis Formation

| # | Suspect | Correlation Evidence | Likelihood |
|---|---------|---------------------|------------|
| 1 | **Timezone-dependent timestamp assertion** | Fails only on dev machines (various TZs), never in CI (UTC). Exact symptom: formatted string differs by ±hours or ±day. | **H1 — Highest** |
| 2 | **Race condition in async worker polling (`sleep(2)`)** | Fails under load (context switches slow the worker thread), reruns go green (race resolves on second try). Fixed-duration polling is inherently fragile. | **H2 — High** |
| 3 | **`set`/unordered-iteration fixture ID dependence** | `pytest_generate_tests` uses a plain `set` for fixture IDs; CPython hashes vary per-process via `PYTHONHASHSEED`, so iteration order changes between invocations. Under load the chance of a different order increases slightly due to allocator state. | **H3 — Medium** |

**Single hypothesis (top-ranked):** H1 explains both the *exact* environment correlation (timezone) and the determinism difference (CI=UTC vs dev=local). H2 explains the load correlation. H3 explains the "sometimes greys" (hash seed jitter between processes).

#### Reproducer 2: Force async-worker race by saturating the machine

```python
#!/usr/bin/env python3
"""Reproduction: starve the worker thread with noise processes."""
import multiprocessing, subprocess, sys

def _noise_worker():
    """Spin until parent kills us."""
    while True:
        pass

# Fork noise workers to match CPU cores → heavy scheduler contention.
cpu_count = multiprocessing.cpu_count()
noise = [multiprocessing.Process(target=_noise_worker) for _ in range(cpu_count)]
for p in noise:
    p.start()

try:
    result = subprocess.run(
        [sys.executable, "-m", "pytest",
         "tests/test_async_worker.py::test_worker_completes_in_time",
         "-v", "--tb=short", "-n", "4"],   # pytest-xdist parallelises too
        timeout=120, capture_output=True, text=True,
    )
    print("EXIT:", result.returncode)
    print(result.stderr[-800:])
finally:
    for p in noise:
        p.terminate()
    for p in noise:
        p.join(timeout=2)
```

This amplifies the `sleep(2)` window so the race becomes reproducible >90% of iterations.

### PHASE 4 — Deterministic Fixes

#### Fix 1 — Timestamp Assertion: Freeze time + enforce UTC

**Root cause:** Production code calls `datetime.now()` (naive → local TZ) and formats without offset information. In CI (UTC) this matches the expected string; on a dev machine in any other offset it drifts.

```python
# myapp/services.py  ← production fix
import datetime
from zoneinfo import ZoneInfo

def format_order_status(order_id: str, tz: ZoneInfo = None) -> str:
    """Return a human-readable status line containing an ORDERED timestamp.

    Parameters
    ----------
    order_id : str
    tz : ZoneInfo, optional
        Defaults to UTC. Callers may override for display purposes,
        but *assertion logic must never rely on caller passing anything
        other than ZoneInfo("UTC")*.
    """
    target_tz = tz or ZoneInfo("UTC")          # default is NEVER naive
    ts = datetime.datetime.now(tz=target_tz)   # aware, never naive
    return f"{order_id}: {ts.strftime('%Y-%m-%d %H:%M:%S')} {target_tz.key}"
```

#### Fix 2 — Async Worker: Replace `sleep(2)` with event-based polling

**Root cause:** The worker has no public readiness primitive, so the test polls with a fixed `sleep(N)`. Under CPU contention the worker finishes later → timeout → false negative. Reruns pass because the OS schedules the worker earlier that time.

```python
# myapp/workers.py  ← production fix
import asyncio

class AsyncOrderProcessor:
    """Worker that exposes an *awaitable* ready state."""

    def __init__(self, batch_size: int = 50):
        self.batch_size = batch_size
        self._ready = asyncio.Event()  # NEW: internal semaphore
        self.status: str = "pending"
        self.errors: list[str] = []

    @property
    def ready(self) -> bool:
        return self._ready.is_set()

    async def process_all(self):
        # ... existing processing logic ...
        self.status = "completed"
        self._ready.set()              # signal completion
```

```python
# myapp/workers.py  ← also add a helper for partial-readiness checks
    async def wait_for_completion(self, *, timeout: float = 30.0):
        """Block until the worker signals completion or raises asyncio.TimeoutError."""
        await asyncio.wait_for(self._ready.wait(), timeout=timeout)
```

```python
# tests/test_async_worker.py  ← test fix
import asyncio
import pytest

@pytest.mark.asyncio
async def test_worker_completes_and_is_ready():
    """Use the new Event-driven wait — zero arbitrary sleeps."""
    proc = AsyncOrderProcessor(batch_size=50)
    task = asyncio.create_task(proc.process_all())

    # Blocks ONLY until the worker actually signals; bounded safety net.
    await proc.wait_for_completion(timeout=30.0)

    assert proc.status == "completed"
    assert proc.errors == []

@pytest.mark.asyncio
async def test_worker_raises_on_stall():
    """Confirm we get a clean TimeoutError instead of silent hang."""
    proc = AsyncOrderProcessor(batch_size=50)
    task = asyncio.create_task(proc.process_all())

    with pytest.raises(asyncio.TimeoutError):
        await proc.wait_for_completion(timeout=0.001)  # immediately expire
```

#### Fix 3 — Fixture-ID Ordering: Sort before iterate, or use `frozenset` equality

**Root cause:** `ITEM_IDS` is declared as a literal `{"a","b","c"}`. In CPython ≤3.10 the hash seed (`PYTHONHASHSEED`) randomises per-process by default, producing different iteration orders. Pytest parametrisates over the iterable; therefore test function arguments appear in a nondeterministic sequence. If any test *depends* on previous parameters (e.g., stateful fixtures), order matters and some orders succeed while others don't.

```python
# myapp/config.py  ← production fix
ITEM_IDS = frozenset({"alpha", "beta", "gamma", "delta"})
# ↑ frozenset is hashable (usable as dict keys, set members) and
#   explicitly communicates "order-independent collection".

# But py.test parametrize needs a LIST-LIKE for deterministic expansion.
# Fix point-of-use, not declaration:

def ordered_item_ids():
    """Return fixture IDs in sorted order — deterministic across runs."""
    return sorted(ITEM_IDS)
```

```python
# tests/test_fixtures.py  ← test fix
import pytest

@pytest.mark.parametrize("item_id", ordered_item_ids())
def test_each_item_has_valid_name_v2(item_id):
    from myapp.config import validate_item_name
    assert validate_item_name(item_id) is True

# Option C — assert using set semantics, ignoring order entirely:
import itertools

def test_all_items_present():
    ids_collected = []
    # Simulate collecting from whatever order the worker yields them.
    for item_id in ["delta", "alpha", "gamma", "beta"]:  # reverse-alphabet
        ids_collected.append(item_id)
    assert set(ids_collected) == {"alpha", "beta", "gamma", "delta"}

def test_items_sorted_at_iteration_boundary():
    """Verify the boundary itself sorts."""

    assert sorted(raw) == ["alpha", "beta", "delta", "gamma"]
```

**Alternative approach — force `PYTHONHASHSEED` in CI and locally:**

```ini
# setup.cfg or pyproject.toml [tool:pytest] section
[tool:pytest]
addopts =
    --strict-markers
    -p no:warnings
    ; Ensures deterministic set/hash iteration during test discovery.
    --forked
env_append =
    PYTHONHASHSEED=0
```

Setting `PYTHONHASHSEED=0` makes set iteration *deterministic within one run*, but this is a band-aid — the true fix above (sorting at the parametrize call site) removes the dependency entirely.
