### Fix 2 — Async Worker Polling: Replace Sleep with Proper Wait

**Root cause:** `await asyncio.sleep(2)` is a bare delay with no knowledge of worker progress. Under load, the event loop can't run the worker task promptly, making the effective wait longer.

**Fix:** Use an `asyncio.Event`, `queue.Queue`, `asyncio.gather`, or `asyncio.wait_for` — i.e., a *completion signal* instead of a guess.

```python

class AsyncWorker:
    def __init__(self):
        self._ready = asyncio.Event()

    async def start(self, delay: float) -> str:
        await asyncio.sleep(delay)       # simulated work
        result = "done"
        self._ready.set()                # ← signals completion
        return result

    @property
    def ready(self) -> asyncio.Event:
        return self._ready


@pytest.mark.asyncio
async def test_async_worker_completes_within_deadline():
    worker = AsyncWorker()
    task = asyncio.create_task(worker.start(delay=1.5))

    # OPTION A — wait with timeout (best for "will it finish?")
    done, pending = await asyncio.wait(
        [task],
        timeout=10.0,          # generous deadline, not guess
    )
    assert pending == set(), f"worker timed out after 10s"
    assert task.result() == "done"


# OPTION B — await the event directly (best for "wait until ready")
@pytest.mark.asyncio
async def test_async_worker_signals_ready():
    worker = AsyncWorker()
    asyncio.create_task(worker.start(delay=1.5))

    # Waits indefinitely (or use asyncio.wait_for for a cap)
    await asyncio.wait_for(worker.ready.wait(), timeout=10.0)
    assert worker._ready.is_set()
    assert worker._event is None or worker._event.is_set()


# OPTION C — if you must keep the simple pattern, add a retry loop
@pytest.mark.asyncio
async def test_async_worker_retry_until_done():
    task = asyncio.create_task(_slow_worker(delay=0.5))
    max_attempts = 20
    for _ in range(max_attempts):
        if task.done():
            break
        await asyncio.sleep(0.1)   # small step, not a giant guess
    else:
        pytest.fail(f"worker did not complete after {max_attempts * 0.1}s")
    assert task.result() == "done"
```

| Why it works | What breaks if ignored |
|-------------|----------------------|

| Timeout provides a safety net (fail-fast instead of silent data loss) | Increasing the sleep number merely delays the failure; doesn't fix the race |
| Retry loop (Option C) is a minimal incremental fix | No approach using `asyncio.sleep` alone can be deterministic |

```python
def furniture(request):
```

#### Deterministic Fix

**Replace fixed `sleep` with a proper retry-with-deadline loop using `asyncio.wait_for`:**

```python
async def robust_poller(coro_or_task, *, timeout=30, interval=0.5):
    """Poll until done or timeout; adapts to actual wall-clock drift."""
    if not asyncio.isfuture(coro_or_task):
        coro_or_task = asyncio.create_task(coro_or_task)
    
    deadline = asyncio.get_event_loop().time() + timeout
    
    while asyncio.get_event_loop().time() < deadline:
        if coro_or_task.done():
            return coro_or_task.result()
        await asyncio.sleep(interval)
    
    raise TimeoutError(
        f"worker did not finish within {timeout}s"
    )
```

**Usage in the test:**

```python

    result = await robust_poller(my_worker_task(), timeout=15)
    assert result.status == "complete"
```

**Why this is better:**
- `interval=0.5s` gives faster feedback on fast machines without wasting cycles.
- Absolute deadline prevents indefinite hanging while allowing the worker to exceed the old 12-second budget.

### Failure 3: Dict Iteration Order Over a Set of Fixture IDs

**Symptom:** Non-deterministic assertion failures. Correlates with machine load (because higher CPU → more thread scheduler churn → changes hash seed assignment order). #### Root Cause Trace


### File 1: `conftest.py` — Shared Test Infrastructure

```python
"""Shared test infrastructure for eliminating non-deterministic test failures.

Provides three utilities that replace every source of flakiness found in the
intermittently-failing test suite:

    1. freeze_time(reference) — patch datetime everywhere a test imports it.
    2. poll_async_worker(func, *, timeout=5.0, interval=0.1) — condition-based
       polling that replaces fixed sleep(N) spin-loops.
    3. strict_ordered_dict(items) — collect iterable into an insertion-ordered
       dict, deduplicating by value while preserving the *first-seen* order
       regardless of whether items arrived via list, set, or generator.
"""

from __future__ import annotations

import functools
import sys
import time
from datetime import datetime, timezone
from typing import Any, Callable, Iterable, Sequence


class _FrozenTime:
    """Minimal clock-freeze context manager compatible with unittest.mock.patch."""

    def __init__(self, ref: datetime) -> None:
        self._ref = ref.astimezone(timezone.utc) if ref.tzinfo is None else ref

    def __enter__(self) -> "_FrozenTime":
        self._orig_datetime = datetime.datetime
        # Patch the most commonly imported name in every module that calls now()
        # We patch both the top-level name and the builtins entry so that
        # `from datetime import datetime; datetime.now()` and
        # `import datetime; datetime.datetime.now()` both resolve correctly.
        import datetime as dt_module

        class FrozenDatetime(dt_module.datetime):
            @classmethod
            def now(cls, tz=None):
                if tz is None:
                    return cls._ref.replace(tzinfo=timezone.utc).astimezone(tz)
                return cls._ref.astimezone(tz)

        FrozenDatetime.__module__ = "datetime"
        FrozenDatetime.__qualname__ = "datetime"
        FrozenDatetime._ref = self._ref  # type: ignore[attr-defined]

        dt_module.datetime = FrozenDatetime  # type: ignore[assignment]
        # Also patch if anyone did `from datetime import datetime`
        sys.modules[__name__]._patched_modules = {
            k: v
            for k, v in sys.modules.items()
            if k is not None and hasattr(v, "datetime") and v.datetime is dt_module.datetime
        }
        for mod_name, mod in list(sys.modules.items()):
            if mod_name is None:
                continue
            try:
                obj = getattr(mod, "datetime", None)
                if obj is not None and hasattr(obj, "now"):
                    setattr(mod, "datetime", FrozenDatetime)
            except Exception:
                pass

        return self

    def __exit__(self, *exc_info: Any) -> None:
        import datetime as dt_module

        dt_module.datetime = self._orig_datetime  # type: ignore[assignment]


def freeze_time(ref: datetime) -> _FrozenTime:
    """Return a context manager that freezes *all* datetime.datetime.now() calls.

    Parameters
    ----------
    ref : datetime
        The wall-clock value that ``now()`` will return for the duration of the
        context. If *ref* lacks timezone info it is treated as UTC.

    Usage
    -----
    >>> with freeze_time(datetime(2026, 8, 26, 12, 0, 0)):
    ...     assert datetime.utcnow() == datetime(2026, 8, 26, 12, 0, 0)
    """
    return _FrozenTime(ref)


def poll_async_worker(
    worker_fn: Callable[[], bool],
    *,
    timeout: float = 5.0,
    interval: float = 0.1,
) -> bool:
    """Condition-based polling replacement for ``sleep(N)`` spin-loops.

    Instead of waiting a *fixed* N seconds (which may be too short under load
    or waste time when work finishes early), this function:

    1. Checks *worker_fn()* immediately (zero-wait on fast path).
    2. Repeats every *interval* seconds until *timeout* expires or the worker
       reports completion (returns True).
    3. Returns True on success, False on timeout — same contract as the old
       ``await asyncio.sleep(2); assert ready`` pattern.

    Parameters
    ----------
    worker_fn : callable returning bool
        Should return True when the async work is complete.
    timeout : float
        Maximum wall-clock seconds to wait.
    interval : float
        Seconds between successive polls (default 100 ms).

    Returns
    -------
    bool
        True if the worker completed within *timeout*, False otherwise.

    Old broken pattern::

        await asyncio.sleep(2)           # might not be enough!
        assert worker_ready()             # crashes under load

    New deterministic pattern::

        assert poll_async_worker(
            lambda: check_completion(),
            timeout=5.0, interval=0.1,
        )
    """
    deadline = time.monotonic() + timeout
    while True:
        if worker_fn():
            return True
        remaining = deadline - time.monotonic()
        if remaining <= 0:
            return False
        # Sleep only as long as the interval demands, capped by remaining budget.
        wait = min(interval, remaining)
        if wait > 0:
            time.sleep(wait)


def strict_ordered_dict(iterable: Iterable[str]) -> dict[str, Any]:
    """Build an insertion-ordered dict from an iterable, deduplicating values.

    This eliminates the ``set()`` → dict-construction ordering bug: when fixture
    IDs travel through a set, insertion order is destroyed (hash randomization
    in CPython, set iteration protocol in PyPy). By collecting with this helper
    you get *deterministic* ordering equal to first-seen position in the original
    iterable, regardless of whether the input was a list, tuple, set, or generator.

    Parameters
    ----------
    iterable : Iterable[str]
        Source of item keys. Values default to an empty dict ``{}``.

    Returns
    -------
    dict[str, Any]
        Ordered dict keyed by unique items from *iterable*.

    Old broken pattern::

        fixture_ids = {"a", "b", "c"}       # set → non-deterministic order
        result = {fid: {} for fid in fixture_ids}  # crash: different order each run

    New deterministic pattern::

        result = strict_ordered_dict(fixture_ids)  # always same key order
    """
    result: dict[str, Any] = {}
    for item in iterable:
        if item not in result:
            result[item] = {}
    return result
```

### H3: `test_fixture_id_iteration_order` — set/dict non-determinism

**Likelihood: Medium-High**

Python's `dict` insertion order is guaranteed since 3.7+, BUT if the code constructs the key set from a `set()` literal or `set(...)` constructor, then iterates over it as keys in a dict, the iteration order is deterministic per-process but **not** consistent across runs or machines. Pytest fixture IDs derived from unordered sets will produce tests in varying order; if a test itself *asserts* something about the order of iteration (e.g., positional comparison against a list), it flakes.

```python
# --- REPRODUCTION: shows non-deterministic iteration ---
def test_fixture_id_order_repro():
    """Bug: iterating a set-derived dict expects positional match."""
    ids = {"alpha", "beta", "gamma"}          # set — no guaranteed order
    mapping = {fid: fid.upper() for fid in ids}
    labels = [mapping[k] for k in mapping.keys()]  # order is hash-randomized
    assert labels == ["ALPHA", "BETA", "GAMMA"]      # arbitrary order
    # Passes when CPython seed happens to sort them, fails otherwise.
```

Why does it correlate with machine load? Higher load → more memory pressure → different GC timing → different hash seeds for built-in `random` (PYTHONHASHSEED is `None` by default, i.e. randomized per process). CI typically pins `PYTHONHASHSEED=random` deterministically or the containers reuse the same seed.

**Fix:** Sort explicitly before any assertion that cares about order:

```python
# --- DETERMINISTIC FIX ---
@pytest.mark.parametrize("fixture_id", sorted({"alpha", "beta", "gamma"}))
def test_fixture_id_iteration_order(fixture_id):
    """Each ID tested individually in sorted order."""
    label = resolve_label(fixture_id)

```

Key rules:
- **If order matters, sort it.** Never trust set or dict-unordered iteration.
- When deriving pytest `@parametrize` IDs from a dynamic set, wrap it in `sorted(...)`.
- Set `PYTHONHASHSEED=0` in CI (pytest already does this implicitly in some versions) and document it so locals reproduce.
