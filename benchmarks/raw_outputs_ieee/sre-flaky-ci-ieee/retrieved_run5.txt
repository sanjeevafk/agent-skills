## Phase 3 — Deterministic Fixes for Each Test

### Fix A: Freeze Time + Capture Once

**Root cause:** Multiple calls to `datetime.now()` within the same logical operation yield different values when system time advances between calls.

**Fix pattern:** Use `freezegun` to freeze wall-clock time and inject timestamps explicitly rather than capturing inside assertions.

```python
"""tests/test_fix_a_timestamp.py"""
import pytest
from freezegun import freeze_time
from datetime import datetime


class ReportFormatter:
    """SUT: formats the current timestamp for a report header."""

    @staticmethod
    def get_report_timestamp():
        return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

    @classmethod
    def generate(cls, base_time=None):
        """Generate a formatted report entry."""
        ts = cls.get_report_timestamp()
        return {"timestamp": ts, "body": "report content"}


@freeze_time("2026-01-15 14:30:00")
def test_timestamp_format_is_deterministic():
    """FIX: Freezed time means datetime.now() always returns the same value,
    so multiple calls within formatting are consistent."""
    formatter = ReportFormatter()
    result = formatter.generate()

    # Now the assertion is fully deterministic — time never changes.
    assert result["timestamp"] == "2026-01-15 14:30:00"


@freeze_time("2026-01-15 14:30:00")
def test_multiple_calls_same_frozen_clock():
    """VERIFY: Even with simulated slow processing, frozen time stays fixed."""
    formatter = ReportFormatter()
    cap_t = formatter.get_report_timestamp()

    # Simulate slow processing that would normally advance the clock
    import time as _time
    _time.sleep(0.01)

    # Still the same because clock is frozen
    again = formatter.get_report_timestamp()
    assert cap_t == again == "2026-01-15 14:30:00"


@pytest.mark.parametrize("base_time,expected_ts", [
    ("2026-06-01 00:00:00", "2026-06-01 00:00:00"),
    ("2026-12-31 23:59:59", "2026-12-31 23:59:59"),
])
@freeze_time(lambda t: t)
def test_timestamp_boundary(base_time, expected_ts):
    """Edge-case: timestamps at day/month/year boundaries are still stable."""
    with freeze_time(base_time):
        ts = ReportFormatter.get_report_timestamp()
        assert ts == expected_ts
```

### Fix B: Replace Sleep-Based Polling with Proper Await + Timeout

**Root cause:** Hardcoded `sleep(2)` is neither adaptive nor bounded by a proper timeout. Under load, the worker takes longer than the polling window.

**Fix pattern:** Use `asyncio.wait_for` with an explicit timeout, awaiting the task directly instead of busy-polling. Eliminate synchronous `sleep()` from async contexts entirely.

```python
"""tests/test_fix_b_async_worker.py"""
import asyncio
import time

import pytest


class AsyncWorker:
    """SUT: an async worker with configurable latency."""

    def __init__(self, delay=0.5):
        self.delay = delay
        self._completed = False

    async def run(self):
        await asyncio.sleep(self.delay)
        self._completed = True
        return {"status": "complete", "processed_at": time.time()}

    @property
    def is_done(self):
        return self._completed


@pytest.mark.asyncio
async def test_async_worker_completes_within_timeout():
    """FIX: Replaced sleep(2) polling with asyncio.wait_for + explicit timeout.

    Previously:
        time.sleep(2)  # hardcoded — flakes under load

    Now:
        Result = await asyncio.wait_for(task, timeout=10.0)
        This adapts to the event loop state and fails deterministically
        if the worker exceeds its SLA.
    """
    # Simulate a slow worker (e.g., under heavy machine load)
    worker = AsyncWorker(delay=0.8)
    task = asyncio.create_task(worker.run())

    # Proper await with timeout — no arbitrary sleeps
    result = await asyncio.wait_for(task, timeout=10.0)

    assert result["status"] == "complete"
    assert worker.is_done


@pytest.mark.asyncio
async def test_async_worker_times_out_gracefully():
    """Verify the fix also catches genuine hangs deterministically."""
    worker = AsyncWorker(delay=30.0)  # Very slow — should timeout
    task = asyncio.create_task(worker.run())

    with pytest.raises(asyncio.TimeoutError):
        await asyncio.wait_for(task, timeout=2.0)


@pytest.mark.asyncio
async def test_async_worker_under_simulated_load():
    """Simulate CPU contention by injecting additional blocking tasks."""
    main_worker = AsyncWorker(delay=0.5)
    main_task = asyncio.create_task(main_worker.run())

    # Schedule dummy tasks to simulate a loaded event loop
    dummy_tasks = [asyncio.create_task(asyncio.sleep(0.1)) for _ in range(10)]

    # wait_for handles all scheduling automatically
    result = await asyncio.wait_for(main_task, timeout=10.0)
    assert result["status"] == "complete"
```

### Fix C: Sort Set Output Before Iteration

**Root cause:** Using a `set` as the source for iteration introduces non-determinism because `set` has no guaranteed order, and Python's hash randomization (`PYTHONHASHSEED`) shuffles iteration order between processes.

**Fix pattern:** Always convert unordered collections to ordered sequences before iteration. Prefer using lists from the fixture definition itself, or sort explicitly.

    for idx, tid in enumerate(ids):

    return results
