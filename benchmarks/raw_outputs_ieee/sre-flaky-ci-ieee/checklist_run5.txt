# Systematic Debugging Report: Intermittent Test Failures

## Evidence Summary

| Signal | Meaning |
|---|---|
| Passes in CI, fails locally (3/240) | Environment-specific, not logic error |
| Reruns go green | Timing/ordering race, not data corruption |
| Correlates with machine load | Real sleeps, not bounded waits |
| Correlates with timezone | System clock used directly |
| 3 distinct failure modes | Three independent bugs, not single systemic issue |

---

## Phase 1: Hypotheses Ranked by Likelihood

**H1 — All three tests share a dependency on external state rather than deterministic assertions.** Timestamp tests bind to wall-clock time, polling tests bind to real elapsed time, and iteration-order tests bind to interpreter internals. This is the #1 source of flakiness in Python test suites. *Likelihood: 95%*

**H2 — CI provides a stable baseline (single-threaded executor, UTC, consistent Python build) while dev machines vary in load, TZ, and hash seed.** CI passes because confounders are held constant, not because tests are robust. *Likelihood: 80%*

**H3 — No hidden shared-state bug.** Multiple independent developers, different machines, different timezones → rules out one corrupted file or fixture. *Likelihood: 60%*

## Phase 2: Analysis of Each Failure

### Test A: Formatted Timestamp Assertion

```python
# ❌ BROKEN: binds to wall-clock time
def test_order_expiry():
    from datetime import datetime, timedelta
    order = {"created_at": datetime.utcnow(), "ttl_hours": 1}
    expiry = order["created_at"] + timedelta(hours=order["ttl_hours"])
    assert f"Expires: {expiry.strftime('%Y-%m-%d %H:%M:%S')}" == expected_string
```

**Root cause:** `datetime.utcnow()` reads the system clock. When the test starts at `T` seconds and finishes at `T+δ` seconds, the formatted string may differ depending on when the test crosses a second boundary, minute boundary, hour boundary, or DST transition. Machine load increases δ, making cross-boundary hits more likely. Timezone differences shift the entire display.

**Fix:** Freeze time explicitly so the assertion compares against a known value.

```python
# ✅ FIXED: deterministic time
from freezegun import freeze_time

@freeze_time("2026-01-15 14:30:00")
def test_order_expiry():
    now = datetime.utcnow()
    assert now.hour == 14          # verified at compile/test-creation time
    assert now.minute == 30

    # If testing formatting of computed values:
    with freeze_time("2026-01-15 14:30:00"):
        result = format_expiry()   # function under test
    assert result == "Expires: 2026-01-15 15:30:00"
```

If you cannot use `freezegun`, mock it directly:

```python
from unittest.mock import patch
from datetime import datetime

def test_order_expiry():
    frozen = datetime(2026, 1, 15, 14, 30, 0)
    with patch("module.datetime", wraps=datetime) as mock_dt:
        mock_dt.utcnow.return_value = frozen
        result = format_expiry()
    assert result == "Expires: 2026-01-15 15:30:00"
```

### Test B: Async Worker Polling with `sleep(2)`

```python
# ❌ BROKEN: arbitrary sleep, no upper bound, no assertion on arrival time
def test_async_worker_completes():
    handle = start_worker()
    sleep(2)                          # "hope it finishes"
    result = get_result(handle)
    assert result is not None
```

**Root cause:** `sleep(2)` is a lower bound, not a wait condition. Under CPU load, context-switch delays push execution past the sleep + processing time. On fast machines the worker finishes in 0.1s (passes); under load it takes 2.5s (fails). There is zero connection between the sleep duration and the actual completion signal.

**Fix:** Replace `sleep(N)` with a bounded polling loop that exits on either success or a reasonable timeout.

```python
# ✅ FIXED: poll until done or timeout
import time
from typing import Optional

TIMEOUT_SECONDS = 10
POLL_INTERVAL = 0.1

def test_async_worker_compleves():
    handle = start_worker()

    deadline = time.monotonic() + TIMEOUT_SECONDS
    while time.monotonic() < deadline:
        result = get_result(handle)
        if result is not None:
            break                        # found it, move on
        time.sleep(POLL_INTERVAL)       # back off, don't spin

    assert result is not None           # fails loudly if truly stuck
    assert result["status"] == "done"   # assert content too
```

Even better — if the worker supports futures or callbacks:

```python
# ✅ BETTER: native async primitive
async def test_async_worker_completes():
    handle = start_worker()
    result = await asyncio.wait_for(handle.done_event(), timeout=TIMEOUT_SECONDS)
    assert result is not None
```

### Test C: Dict Iteration Order Over Fixture IDs

```python
# ❌ BROKEN: depends on hash-seed-dependent dict ordering
@pytest.mark.parametrize("fixture_id", generate_fixture_ids())
def test_fixture_metadata(fixture_id):
    metadata = collect_metadata(fixture_id)   # returns dict from unordered source
    for key, value in metadata.items():       # iteration order not guaranteed
        assert value is not None
```

**Root cause:** Prior to Python 3.7, dict ordering was implementation-defined. Even in 3.7+, if `collect_metadata` builds its dict from an `iterkeys()` call, a `set comprehension`, or a library that returns unsorted dicts, the iteration order is **non-deterministic across runs on different machines**. `PYTHONHASHSEED` defaults to randomized in modern Python, meaning every process gets a different seed → different dict ordering → sometimes an assertion depends on the order (e.g., comparing lists, checking "first element").

More subtly: if the test does a direct list/dict comparison:

```python
assert list(metadata.keys()) == ["a", "b", "c"]   # FAILS randomly
```

The comparison itself is order-sensitive. If the dict happened to iterate as `["c", "a", "b"]`, the assertion fails even though all keys are present.

**Fix:** Assert membership, not position. Sort before comparing. Or iterate over a deterministic sequence.

```python
# ✅ FIXED: order-independent assertions

# Option 1 — assert membership, not order
def test_fixture_metadata_sorted():
    metadata = collect_metadata("fixture_1")
    assert set(metadata.keys()) == {"a", "b", "c"}
    for key in metadata:
        assert metadata[key] is not None

# Option 2 — sort explicitly before comparison
def test_fixture_metadata_explicit_sort():
    metadata = collect_metadata("fixture_1")
    keys = sorted(metadata.keys())         # deterministic order
    assert keys == ["a", "b", "c"]
    for key in keys:                       # iterate in sorted order
        assert metadata[key] is not None

# Option 3 — sort the items returned from the collection function
def test_fixture_metadata_deterministic_iteration():
    metadata = collect_metadata("fixture_1")
    for key in sorted(metadata.keys()):    # force deterministic iteration
        value = metadata[key]
        assert_something(key, value)
```

If the source itself is a set that needs ordering:

```python
def collect_metadata(fixture_id: str) -> dict:
    raw = fetch_from_api(fixture_id)
    return {k: raw[k] for k in sorted(raw.keys())}   # stabilize at the source
```

# stress_polling.py
import concurrent.futures
import threading
import time

def slow_worker():
    time.sleep(0.5 + hash(threading.current_thread().name) % 3)  # variable delay
    return "done"

def test_under_load():
    """Simulates 3 cores at 100% — sleep(2) becomes insufficient."""
    executor = concurrent.futures.ThreadPoolExecutor(max_workers=os.cpu_count())
    for _ in range(os.cpu_count()):
        executor.submit(lambda: [None] * 10_000_000)  # burn CPU

    handle = executor.submit(slow_worker)
    time.sleep(2)  # original buggy code
    assert handle.result(timeout=0.1) == "done"  # raises TimeoutError under load

import os

def test_dict_iteration_stability():
    """Proves dict ordering depends on insertion order, not key identity."""
    # Build identical dicts via different paths
    a = {k: v for k, v in [("z", 1), ("a", 2), ("m", 3)]}
    b = {}
    for k, v in [("z", 1), ("a", 2), ("m", 3)]:
        b[k] = v

    assert list(a.keys()) == list(b.keys())  # same insertion, same order ✅

    # Now if one source returns unordered data:
    c = dict(sorted({"z": 1, "a": 2, "m": 3}.items()))
    d = dict({"a": 2, "z": 1, "m": 3})     # literal order differs from c

    assert list(c.keys()) == ["a", "m", "z"]   # sorted, stable ✅

|---|---|---|---|
| **Timestamp** | Binds to system clock | Freeze time with `@freeze_time` | `freezegun` |
| **Async poll** | `sleep(N)` ≠ bounded wait | Poll loop with `monotonic()` deadline + timeout | stdlib only |
| **Dict order** | Hash-seed-dependent iteration | `sorted()` keys before compare; assert membership, not position | stdlib only |

## Architectural Recommendation

These three failures share a common anti-pattern: **tests that depend on external reality rather than asserting internal behavior**. Every test that reads `datetime.utcnow()`, calls `time.sleep()`, or iterates an unspecified collection should be audited. In a 240-test suite, 3 failures suggest there may be 10-20 more latent flakes.

Run this audit:

```bash
# Find all potential sources of flakiness
grep -rn "datetime.utcnow\|datetime.now\|time\.sleep\b\|os.urandom\|random\." tests/ | grep -v "conftest\|fixtur" 
```

Replace each occurrence with a deterministic alternative.
