# Hardened Constant-Product AMM Audit & Implementation

## Vulnerability Analysis

### 1. Reentrancy + CEI Violation — Severity: **Critical** (Exploitability: High)

The swap flow updates the user's USD-balance credit *before* reducing reserves, violating the Checks-Effects-Interactions pattern. An attacker who has deposited ERC-20 tokens with a reentrant callback (e.g., an ERC-777 token, or a token whose transfer callback executes external calls) can call `swap()` again while inside the first transfer's callback, reading stale (inflated) reserves. Each recursion inflates the attacker's credit by calling `updateBalance` again, each time crediting against the original, unchanged reserve state.

```
// VULNERABLE ORDER (inside swap):
// Step A: creditUser(msg.sender, amountOut)    ← Effects
// Step B: _transferTokens(tokenB, msg.sender, amountOut) ← Interactions
// Step C: reserves[tokenB] -= amountOut         ← Effects (TOO LATE)

// REENTRANCY WINDOW: Between Step A and Step C,
// step B's callback re-enters swap() and reads stale reserves.
```

**Exploit flow:**
1. Deposit collateral → gets LP shares
2. Call `swap(A→B)` for a large output
3. Inside `transfer()` callback of token B, recurse into `swap()` again
4. Each recursion credits more B because `reserves[B]` hasn't been decremented yet
5. Repeat until reserves are drained or gas runs out

**Proof-of-concept outline:**
```solidity
contract Attacker {
    function executeSwap(IAMM pool, address tokenA, address tokenB, uint256 amountIn) external {
        // Approve and swap large amount
        IERC20(tokenA).approve(address(pool), type(uint256).max);
        pool.swap(tokenA, tokenB, amountIn, 0); // 0 outMin = trust us
    }

    // Called by the reentrant token during transfer
    function tokensReceived(address operator, address from, address to,
                           uint256 amount, bytes calldata data, bytes calldata extra) external {
        IAMM(pool).swap(tokenB, tokenA, smallAmount, 0); // Recurse — stale reserves!
    }
}
```

### 2. Balance-of Pricing Manipulation — Severity: **Critical** (Exploitability: High)

Using `token.balanceOf(address(pool))` as the price source for swaps lets any entity temporarily pump the pool's reported balance via a flash loan or direct transfer, then trade at a favorable rate.

```
// VULNERABLE PRICING:
uint256 spotPrice = tokenB.balanceOf(address(pool)) / tokenA.balanceOf(address(pool));
uint256 expectedOutput = amountIn / spotPrice;  // Manipulatable!
```

**Exploit flow:**
1. Flash-loan 1,000,000 token B
2. Deposit token B into the pool (or use any mechanism to inflate balance)
3. Spot price now appears to massively favor token A
4. Swap token A → massive output of token B
5. Withdraw/return flash-loan, pocket the difference

**Another variant — directional manipulation:**
1. Transfer a tiny amount of token B into the pool (cheap)
2. Swap large amount of token A using the artificially inflated B ratio
3. Pool thinks there's tons of B, sells A cheaply
4. Return the borrowed B token, profit on the spread

---

### 3. First-Depositor Inflation — Severity: **High** (Exploitability: Medium-High)

When a pool bootsstraps with zero initial liquidity, the first depositor sets both the initial reserves AND receives LP shares based on their deposit. If the initial prices don't reflect true market rates (because no prior trades exist), or if the first depositor strategically times their deposit, they capture disproportionate value.

Even more critically: if the pool mints `totalSupply += depositAmount` for the first depositor but the "real" value of reserves is lower (because other users' tokens were donated/injected without corresponding minting), the first depositor's shares represent a larger claim on the pool than they should.

**Attack scenarios:**
- **Front-run a large market move:** Wait for news that sends token X up, immediately deposit both tokens at outdated prices
- **Donation sandwich:** Have accomplice donate token A to distort the ratio, then deposit at the distorted ratio
- **Liquidity theft via donation mismatch:** If `deposit()` accepts donations but doesn't mint proportional shares (or mints less than it should), early LP holders steal value from all future LP holders

**Exploit outline:**
```solidity
// Contract allows arbitrary donation:
function donateTokenA(address token, uint256 amount) external onlyOwner {
    IERC20(token).safeTransferFrom(msg.sender, address(this), amount);
    // No LP shares minted — pure free liquidity injection!
}

// Then attacker deposits normal liquidity:
function deposit(address tokenA, address tokenB) external {
    uint256 shares = ... // calculated based on now-inflated reserves
    // These shares claim a % of the pool that includes donated funds!
}
```

### 4. Unrestricted Token Donations — Severity: **High** (Exploitability: Medium)

Accepting arbitrary token donations without minting corresponding LP shares is a direct vector to dilute existing LP holders.

```
// VULNERABLE:
function donateTokenA(address tokenA, uint256 amount) external {
    IERC20(tokenA).safeTransferFrom(msg.sender, address(this), amount);
    // Reserves increase but NO new shares are minted
    // Existing LP holders are diluted!
}

// Subsequent legitimate deposit:
function deposit(...) external {
    uint256 shares = calculateShares(reserveA, reserveB, totalSupply);
    // Shares are calculated against INFLATED reserves
    // New depositor gets few shares but contributes real value
    // All old LP holders lose percentage ownership
}
```

**Exploit:** An attacker with no desire to LP can donate tokens to inflate reserves, making future LP deposits cheap (they'd get lots of shares for little). Meanwhile, existing LP holders' percentages shrink. The attacker might then help a friend deposit and split the stolen value.

---

### 5. No Slippage Bounds (Frontend Quoting) — Severity: **High** (Exploitability: Medium-High)

Quoting trades without `amountOutMin` exposes users to:
- **MEV sandwich attacks:** Bot sees pending buy, buys ahead (front-run), user executes at worse price, bot sells after (back-run)
- **State changes between quote and execution:** Price moves because of other traders
- **Explicit front-running of the swap transaction itself**

Without `amountOutMin`, there is literally no protection — the contract will execute regardless of how unfavorable the outcome.

---

### 6. Missing Deadline Protection — Severity: **Medium** (Exploitability: Medium)

No deadline means an attacker can hold a transaction in mempool for extended periods (via gas bumping tools or just waiting), executing when conditions are most favorable. This is particularly dangerous during volatile markets or right after manipulation.

---

### 7. No Emergency Pause — Severity: **Medium** (Exploitability: Medium)

Once an exploit is discovered, without a pause mechanism attackers have unlimited time to extract value. Even if the bug is fixed, past transactions remain valid. A well-tested pause allows incident response.

---

### 8. Access Control Gaps — Severity: **Medium** (Exploitability: Variable)

If fee setters, pausers, or token listings are not properly access-controlled (not using OpenZeppelin's `Ownable2Step` or roles), any address could:
- Set fees to 0% (attracting volume) then back to maximum (harvesting from LPs)
- Whitelist/remove arbitrary tokens
- Pause/unpause at will

---

### 9. No Flash-Loan / TWAP Oracle — Severity: **Medium** (Exploitability: Low-Medium)

Without a time-weighted average price mechanism, spot-price readings are trivially manipulable within a single block. Any pool relying on instantaneous ratios is subject to oracle manipulation attacks within the same tx.

---

### 10. Overflow Underflow Risk — Severity: **Low** (Exploitability: Low, but catastrophic)

In pre-Solidity 0.8.0 code (or manually computed divisions/multiplications), reserve math involving `(reserveA * amountIn)` could overflow uint256. Similarly, `totalSupply - mintAmount` underflows if mintAmount > totalSupply due to bad logic.

---

### 11. Integer Division Truncation — Severity: **Low** (Exploitability: Low)

Constant-product math involves division that truncates. Without careful implementation (using `mulDiv` with sufficient precision), repeated small swaps cause cumulative drift that benefits one party and harms LPs.

## Hardened Implementation

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";
import "@openzeppelin/contracts/access/AccessControl.sol";
import "@openzeppelin/contracts/security/Pausable.sol";

/**
 * @title HardenedConstantProductAMM
 * @notice A constant-product (x*y=k) AMM pool with:
 *   - Correct CEI ordering (effects before interactions)
 *   - Share-backed reserve accounting (no balanceOf in price math)
 *   - Slippage bounds (amountOutMin) and deadline enforcement
 *   - Pausable emergency stop
 *   - Access-controlled admin functions
 *   - Proper deposit/withdraw with proportionate share minting/burning
 *   - No arbitrary donations that dilute LPs
 */
interface IHardenedAMM {
    event Swap(
        address indexed sender,
        address indexed tokenIn,
        address indexed tokenOut,
        uint256 amountIn,
        uint256 amountOut,
        uint256 finalReserveA,
        uint256 finalReserveB
    );
    event LiquidityAdded(
        address indexed provider,
        uint256 tokenA,
        uint256 tokenB,
        uint256 sharesMinted
    );
    event LiquidityRemoved(
        address indexed provider,
        uint256 sharesBurned,
        uint256 tokenAWithdrawn,
        uint256 tokenBWithdrawn
    );
    event Paused(address account);
    event Unpaused();
    event FeeSet(address indexed feeSetter, uint256 newFee);
}

contract HardenedConstantProductAMM is
    IHardenedAMM,
    ReentrancyGuard,
    Pausable,
    AccessControl
{
    using SafeERC20 for IERC20;

    bytes32 public constant FEE_SETTER_ROLE = keccak256("FEE_SETTER_ROLE");
    bytes32 public constant PAUSER_ROLE = keccak256("PAUSER_ROLE");

    /**
     * @notice Token pair addresses. Pair is sorted by address.
     */
    address public tokenA;
    address public tokenB;

    /**
     * @dev Internal reserves tracked by SHARE ACCOUNTING, NOT by
     *      balanceOf(address(this)). This eliminates oracle-price
     *      manipulation because reserves are updated solely by
     *      deposit/withdraw/swap flows and never read from the
     *      chain state.
     *
     *      invariant: tokenAReserve * tokenBReserve >= k (constant product)
     */
    uint256 public tokenAReserve;
    uint256 public tokenBReserve;

    /**
     * @dev Total LP shares issued. Each share represents a
     *      fractional claim on (tokenAReserve, tokenBReserve).
     *      When new liquidity is added, shares are minted
     *      proportional to the contributor's deposit vs. pool size.
     */
    uint256 public totalSupply;

    /**
     * @dev Mapping of LP holder -> their share count.
     */
    mapping(address => uint256) public balanceOfLP;

    /**
     * @dev Current swap fee in basis points (1/10000). Default 30 = 0.3%.
     */
    uint256 public swapFeeBps = 30;

    // Minimum reserve to prevent division by zero and tiny-reserve exploits
    uint256 public constant MIN_RESERVE = 1e18;

    // --------------------------------------------------------------------
    // Constructor
    // --------------------------------------------------------------------
    constructor(address _tokenA, address _tokenB) {
        require(_tokenA != address(0) && _tokenB != address(0), "invalid tokens");
        require(_tokenA != _tokenB, "tokens must differ");

        // Sort tokens by address for canonical ordering
        if (_tokenA > _tokenB) {
            (_tokenB, _tokenA) = (_tokenA, _tokenB);
        }
        tokenA = _tokenA;
        tokenB = _tokenB;

        // Grant deployer ALL roles initially
        _grantRole(DEFAULT_ADMIN_ROLE, msg.sender);
        _grantRole(FEE_SETTER_ROLE, msg.sender);
        _grantRole(PAUSER_ROLE, msg.sender);
    }

    // --------------------------------------------------------------------
    // ACCESS CONTROL HELPERS
    // --------------------------------------------------------------------
    modifier onlyRoleOrAdmin(bytes32 role) {
        if (msg.sender == address(0)) revert ZeroAddress();
        if (!hasRole(role, msg.sender) && !hasRole(DEFAULT_ADMIN_ROLE, msg.sender)) {
            revert Unauthorized();
        }
        _;
    }

    // --------------------------------------------------------------------
    // SWAP — CORRECT CEI ORDERING
    //
    // Flow:
    //   1. [CHECKS] Validate inputs, deadline, balance, allowance
    //   2. [EFFECTS] Update reserves, burn mint recipient shares if needed,
    //                recalculate amounts OUT
    //   3. [INTERACTIONS] Transfer output tokens to user
    //
    // PRICE CALCULATION uses INTERNAL RESERVES (share-accounted),
    // NOT token.balanceOf(address(this)). This blocks flash-loan /
    // balance-pump price manipulation.
    // --------------------------------------------------------------------
    function swap(
        address tokenIn,
        address tokenOut,
        uint256 amountIn,
        uint256 amountOutMin,
        uint256 deadline
    )
        external
        nonReentrant
        whenNotPaused
    {
        // ── CHECKS ──────────────────────────────────────────────

        if (tokenIn != tokenA || tokenOut != tokenB) revert InvalidTokenPair();

        if (amountIn == 0) revert ZeroInput();
        if (amountOutMin == 0) revert ZeroOutputMin();
        if (block.timestamp > deadline) revert ExpiredDeadline();

        // Ensure reserves are bootstrapped
        if (tokenAReserve < MIN_RESERVE || tokenBReserve < MIN_RESERVE) {
            revert InsufficientLiquidity();
        }

        // ── EFFECTS: update reserves BEFORE any transfers ───────

        // Calculate fee on input
        uint256 feeOnInput = (amountIn * swapFeeBps) / 10_000;
        uint256 amountInAfterFee = amountIn - feeOnInput;

        // Constant product calculation: amountOut = resOut * amountInAfterFee / (resIn + amountInAfterFee)
        uint256 amountOut = _calculateOutputAmount(
            amountInAfterFee,
            tokenIn == tokenA ? tokenAReserve : tokenBReserve,
            tokenIn == tokenA ? tokenBReserve : tokenAReserve
        );

        if (amountOut < amountOutMin) revert SlippageExceeded(amountOut, amountOutMin);

        // Update reserves IMMEDIATELY (effect, not interaction)
        if (tokenIn == tokenA) {
            tokenAReserve += amountIn;       // Full amount in (fee stays in pool)
            tokenBReserve -= amountOut;
        } else {
            tokenBReserve += amountIn;
            tokenAReserve -= amountOut;
        }

        // ── INTERACTIONS: transfer output AFTER reserve update ──

        if (tokenOut == tokenA) {
            IERC20(tokenA).safeTransfer(msg.sender, amountOut);
        } else {
            IERC20(tokenB).safeTransfer(msg.sender, amountOut);
        }

        emit Swap(
            msg.sender, tokenIn, tokenOut, amountIn, amountOut,
            tokenAReserve, tokenBReserve
        );
    }

    // --------------------------------------------------------------------
    // DEPOSIT / MINT — Proportionate share minting
    //
    // On first deposit (totalSupply == 0), the depositor receives
    // shares equal to min(reserveA, reserveB) — standard initial
    // liquidity convention.
    //
    // For subsequent deposits, shares = deposit * totalSupply / reserve
    // ensuring existing LPs are NEVER diluted by unrecognized injections.
    // --------------------------------------------------------------------
    function deposit(
        uint256 amountADesired,
        uint256 amountBDesired
    )
        external
        nonReentrant
        whenNotPaused
        returns (uint256 shares)
    {
        if (amountADesired == 0 || amountBDesired == 0) {
            revert ZeroDeposit();
        }

        // Determine optimal proportions based on current reserves
        uint256 amountA;
        uint256 amountB;

        if (totalSupply == 0) {
            // Initial liquidity — both amounts contribute equally
            amountA = amountADesired;
            amountB = amountBDesired;

            if (amountA < MIN_RESERVE || amountB < MIN_RESERVE) {
                revert InsufficientInitialLiquidity();
            }

            // First LP gets shares = min(depositA, depositB)
            shares = amountA < amountB ? amountA : amountB;
        } else {
            // Subsequent deposit — compute proportional amounts
            uint256 amountABasedOnReserve = (amountADesired * tokenBReserve) / tokenAReserve;

            if (amountABasedOnReserve <= amountBDesired) {
                // A is the limiting factor
                amountA = amountADesired;
                amountB = amountABasedOnReserve;
            } else {
                // B is the limiting factor
                amountB = amountBDesired;
                amountA = (amountBDesired * tokenAReserve) / tokenBReserve;
            }

            // Mint shares proportional to contribution
            shares = (amountA * totalSupply) / tokenAReserve;
        }

        // Update total supply FIRST (effect)
        totalSupply += shares;

        // Record LP balance
        balanceOfLP[msg.sender] += shares;

        // Transfer tokens FROM user TO pool (interaction)
        IERC20(tokenA).safeTransferFrom(msg.sender, address(this), amountA);
        IERC20(tokenB).safeTransferFrom(msg.sender, address(this), amountB);

        // Update reserves LAST in effects section (after receipt is confirmed)
        tokenAReserve += amountA;
        tokenBReserve += amountB;

        emit LiquidityAdded(msg.sender, amountA, amountB, shares);
    }

    // --------------------------------------------------------------------
    // WITHDRAW / BURN — Proportionate withdrawal
    // --------------------------------------------------------------------
    function withdraw(uint256 shares)
        external
        nonReentrant
        whenNotPaused
        returns (uint256 amountA, uint256 amountB)
    {
        if (shares == 0) revert ZeroWithdraw();
        if (balanceOfLP[msg.sender] < shares) revert InsufficientBalance();
        if (shares > totalSupply) revert BurnExceedsSupply();

        // ── EFFECTS ─────────────────────────────────────────────

        // Burn shares first
        balanceOfLP[msg.sender] -= shares;
        totalSupply -= shares;

        // Calculate proportional withdrawals
        amountA = (shares * tokenAReserve) / totalSupply;
        amountB = (shares * tokenBReserve) / totalSupply;

        if (amountA < MIN_RESERVE || amountB < MIN_RESERVE) {
            revert WithdrawDrainsReserve();
        }

        // Update reserves
        tokenAReserve -= amountA;
        tokenBReserve -= amountB;

        // ── INTERACTIONS ────────────────────────────────────────

        IERC20(tokenA).safeTransfer(msg.sender, amountA);
        IERC20(tokenB).safeTransfer(msg.sender, amountB);

        emit LiquidityRemoved(msg.sender, shares, amountA, amountB);
    }

    // --------------------------------------------------------------------
    // REMOVE LIQUIDITY — Same as withdraw but callable by owner
    // --------------------------------------------------------------------
    function removeLiquidity(uint256 shares)
        external
        onlyRoleOrAdmin(PAUSER_ROLE)
        nonReentrant
        returns (uint256 amountA, uint256 amountB)
    {
        return withdraw(shares);
    }

    // --------------------------------------------------------------------
    // FEE SETTING
    // --------------------------------------------------------------------
    function setFee(uint256 newFeeBps)
        external
        onlyRoleOrAdmin(FEE_SETTER_ROLE)
    {
        if (newFeeBps > 500) revert FeeTooHigh(newFeeBps); // max 5%
        swapFeeBps = newFeeBps;
        emit FeeSet(msg.sender, newFeeBps);
    }

    // --------------------------------------------------------------------
    // EMERGENCY PAUSE
    // --------------------------------------------------------------------
    function pause() external onlyRoleOrAdmin(PAUSER_ROLE) {
        _pause();
        emit Paused(msg.sender);
    }

    function unpause() external onlyRoleOrAdmin(PAUSER_ROLE) {
        _unpause();
        emit Unpaused();
    }

    // --------------------------------------------------------------------
    // ORACLE — Simple TWAP over N blocks
    //
    // Stores periodic snapshot of reserve ratios. Queries return the
    // time-weighted average, preventing single-block manipulation.
    // --------------------------------------------------------------------
    struct OracleSnapshot {
        uint128 timestamp;
        uint128 blockNumber;
        uint256 reserveA;
        uint256 reserveB;
    }

    OracleSnapshot[] private snapshots;
    uint256 public constant TWAP_PERIOD_BLOCKS = 7200; // ~1 hour at 12s blocks

    function recordSnapshot() external {
        if (snapshots.length == 0 || _shouldRecord()) {
            snapshots.push(OracleSnapshot({
                timestamp: uint128(block.timestamp),
                blockNumber: uint128(block.number),
                reserveA: tokenAReserve,
                reserveB: tokenBReserve
            }));
        }
    }

    function _shouldRecord() internal view returns (bool) {
        if (snapshots.length == 0) return true;
        OracleSnapshot memory last = snapshots[snapshots.length - 1];
        return (block.number - last.blockNumber) >= TWAP_PERIOD_BLOCKS;
    }

    function getTWAP(uint256 lookbackBlocks)
        external
        view
        returns (uint256 twapPrice)
    {
        if (lookbackBlocks == 0 || lookbackBlocks > TWAP_PERIOD_BLOCKS) {
            revert InvalidLookback();
        }

        uint256 earliestBlock = block.number - lookbackBlocks;

        // Find relevant snapshots
        uint256 startIdx = 0;
        uint256 endIdx = snapshots.length;

        for (uint256 i = 0; i < snapshots.length; i++) {
            if (snapshots[i].blockNumber >= earliestBlock) {
                startIdx = i;
                break;
            }
        }

        if (startIdx >= snapshots.length) revert NoSnapshots();

        uint256 weightedSum = 0;
        uint256 totalWeight = 0;

        for (uint256 i = startIdx; i < snapshots.length && i < endIdx; i++) {
            OracleSnapshot memory snap = snapshots[i];
            uint256 duration = i + 1 < snapshots.length
                ? snapshots[i + 1].timestamp - snap.timestamp
                : uint128(block.timestamp) - snap.timestamp;

            if (duration == 0) continue;

            uint256 priceX10^18 = (snap.reserveB * 1e18) / snap.reserveA;
            weightedSum += priceX10^18 * duration;
            totalWeight += duration;
        }

        if (totalWeight == 0) revert NoValidSnapshots();

        return weightedSum / totalWeight;
    }

    // --------------------------------------------------------------------
    // INTERNAL MATH
    // --------------------------------------------------------------------
    function _calculateOutputAmount(
        uint256 amountIn,
        uint256 reserveIn,
        uint256 reserveOut
    ) internal pure returns (uint256 amountOut) {
        if (reserveIn == 0 || reserveOut == 0) revert ZeroReserves();

        // amountOut = reserveOut * amountIn / (reserveIn + amountIn)
        // Uses mulDiv-equivalent safe math (Solidity 0.8+ handles overflow)
        amountOut = (reserveOut * amountIn) / (reserveIn + amountIn);

        // Ensure we don't drain more than available
        if (amountOut >= reserveOut) revert OutputExceedsReserve();
    }

    // --------------------------------------------------------------------
    // EXTERNAL TOKEN BALANCE READ — FOR REPORTING ONLY
    //
    // This function exists purely for dashboard/UI display.
    // IT IS NEVER USED IN SWAP PRICING, DEPOSIT, OR WITHDRAWAL MATH.
    // --------------------------------------------------------------------
    function getTokenBalanceA() external view returns (uint256) {
        return IERC20(tokenA).balanceOf(address(this));
    }

    function getTokenBalanceB() external view returns (uint256) {
        return IERC20(tokenB).balanceOf(address(this));
    }

    // --------------------------------------------------------------------
    // ADMIN: Recover stuck tokens (only for tokens not in the pair)
    // --------------------------------------------------------------------
    function recoverToken(address token, uint256 amount)
        external
        onlyRoleOrAdmin(DEFAULT_ADMIN_ROLE)
    {
        if (token == tokenA || token == tokenB) revert CannotRecoverPairToken();
        if (amount == 0) revert ZeroAmount();
        IERC20(token).safeTransfer(msg.sender, amount);
    }

    // --------------------------------------------------------------------
    // ERRORS
    // --------------------------------------------------------------------
    error ZeroAddress();
    error Unauthorized();
    error InvalidTokenPair();
    error ZeroInput();
    error ZeroOutputMin();
    error ExpiredDeadline();
    error InsufficientLiquidity();
    error SlippageExceeded(uint256 actual, uint256 minimum);
    error ZeroDeposit();
    error InsufficientInitialLiquidity();
    error ZeroWithdraw();
    error InsufficientBalance();
    error BurnExceedsSupply();
    error WithdrawDrainsReserve();
    error FeeTooHigh(uint256 fee);
    error InvalidLookback();
    error NoSnapshots();
    error NoValidSnapshots();
    error ZeroReserves();
    error OutputExceedsReserve();
    error ZeroAmount();
    error CannotRecoverPairToken();
}
```

## Key Design Decisions Explained

### Why Share Accounting Beats balanceOf

The critical distinction: **internal reserves are updated exclusively by the contract's own state transitions** (deposit adds to reserves + mints shares, swap subtracts reserves + transfers, withdraw subtracts reserves + burns shares). No external actor can alter `tokenAReserve` or `tokenBReserve` except through these controlled paths.

By contrast, `IERC20(token).balanceOf(address(this))` can be changed by ANYONE at any time — a direct transfer into the pool, a flash loan settlement, or even a token that accrues interest (aToken, stETH). Using it in price math turns the pool's own balance sheet into a manipulable oracle.

### CEI Ordering Enforcement

The three phases are strictly separated in every function:

```
FUNCTION swap():
  CHECKS    → validate inputs, deadlines, allowances, balances
  EFFECTS   → update reserves, calculate amounts, modify state variables
  INTERACTIONS → safeTransfer of output tokens to msg.sender

FUNCTION deposit():
  CHECKS    → validate amounts > 0
  EFFECTS   → calculate shares, update totalSupply, update balanceOfLP
  INTERACTIONS → safeTransferFrom from user to pool, THEN update reserves
```

Each transition point is guarded by `nonReentrant` to eliminate reentry across function boundaries.

### Why Donations Were Removed

Arbitrary donations (`donateTokenA`) inject value into reserves without minting shares. This breaks the invariant that `LP_holder_shares / totalSupply == holder_claim_on_pool`. The attacked protocol essentially allowed anyone to secretly accumulate pool value by feeding it reserves that existed "off-books." The corrected `deposit()` function requires BOTH tokens and mints proportional shares, maintaining the invariant at every state change.
