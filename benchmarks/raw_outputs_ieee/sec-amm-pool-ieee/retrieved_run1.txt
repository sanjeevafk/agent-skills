## Vulnerability Audit: Constant-Product AMM Pool

### Assumed Vulnerable Architecture

Based on the description, the vulnerable contract has these properties:
1. Swap updates **user balances** before settling **internal reserves**
2. Prices swaps against a **spot balance read** from `token.balanceOf(address(this))`
3. Accepts **arbitrary token donations** via fallback/transfer hooks
4. Frontend quotes trades with **no slippage bounds**

---

### Attack Path 1 (CRITICAL — Exploitability: Trivial)

**Oracle Spot-Price Manipulation via Flash Loan**

The spot-price oracle reads `token.balanceOf(address(this))` directly. An attacker can flash-loan one asset, dump it on the pool at the start of the block, read the manipulated reserve ratio, and execute an arbitrageable swap — or simply drain the opposite side. Because the price *is* the reserve ratio, any manipulation of reserves produces immediate profitable trades within the same transaction.

Concrete execution:
```
// Step 1: Flash-loan 100k USDC into pool
flashLoan(USDC, 100_000e6);

// Step 2: Sell USDC for ETH → massively inflates USDC reserves, deflates ETH reserves
swapIn(pool, USDC, ETH, 100_000e6);

// Step 3: Read new spot price = newETHReserve / newUSDCReserve << fair value
uint256 manipulatedPrice = ethReserve / usdcReserve; // extremely low

// Step 4: Swap ETH → USDC at manipulated favorable rate
swapOut(pool, ETH, USDC, largeAmount);

// Step 5: Repay flash loan, keep profit
repayFlashLoan(100_000e6 + fee);
```

All in one tx. No front-running protection needed since the pool's own math reveals the edge immediately.

**Rank: #1 Most exploitable.** Requires only standard flash-loan infrastructure (Aave/DYDX), zero insider knowledge, works on any liquidity level.

---

### Attack Path 2 (CRITICAL — Exploitability: Trivial)

**First-Depositor Inflation / Donations-Steenfluten**

Donations sent directly to the pool (either via ERC-20 transfer, or because the contract accepts native tokens without guardrails) inflate `balanceOf(address(this))`. When the next depositor mints LP shares, their share minting formula divides by the inflated balance, causing them to receive disproportionately few shares for their deposit — effectively stealing value from every subsequent depositor. Conversely, if the donation is in the *same* token used in a pair, it biases the reserve ratio and creates mispriced quotes.

Example with a single-reserve pool or when the donation token is one side of the pair:
```
// Fair state: pool has 1000 USDC, totalSupply = 1000, _totalAssets = 1000
// Attacker donates 100K USDC directly to the pool
pool.transferIn(attacker, 100_000 USDC);

// Normal depositor sends 100 USDC, expecting 100 shares
// Formula uses 101_000 as denominator → gets ~0.99 shares instead of ~100
shares = (100 * 1000) / 101_000 = 0.99
```

Every legitimate depositor is diluted. If this runs across blocks, the entire pool equity transfers to early actors who control donation timing.

**Rank: #2 Most exploitable.** Same primitives as #1 but even simpler — just send tokens to the contract address. Works even without flash loans.

---

### Attack Path 3 (HIGH — Exploitability: Easy)

**Front-Running / MEV Sandwich via Unbounded Quotes**

The frontend quotes trades *without slippage bounds*. A bot intercepts the quote, submits a sandwich: front-run (buy before victim), let victim fill at inflated price, back-run (sell after). The attacker profits from the spread, and the pool itself loses value permanently since no `amountOutMin` was enforced on-chain.

With the additional twist that the pool reads spot prices off-balance-sheet (not using TWAP), this becomes trivially automatable:
```
Block N:   Bot detects pending swap(tx_in=100 ETH→USDC)
           Bot buys 50 ETH from pool → ETH price up 20%
           
Block N+1: Victim's swap fills at 20% worse rate
           Slippage not checked → victim unknowingly overpays
           
Block N+1: Bot sells its 50 ETH → captures spread profit
```

Without a deadline or minimum-out check, the victim cannot reject the bad price and the pool absorbs the loss.

**Rank: #3.** High impact per trade, very easy to automate, but doesn't drain the pool — rather extracts value continuously.

---

### Attack Path 4 (HIGH — Exploitability: Easy)

**Balance-of-User-before-Reserve Reordering Theft**

The swap updates **user balances** first, then settles internal reserves. Between those two writes, another contract function (like `viewLiquidity()` or an `afterSwap` hook) can call `balanceOf(user)` and see an inflated balance. If there's any external callback between the two writes (even unintentionally via token transfer hooks or event listeners), a reentrancy-style theft is possible.

More concretely: if the order is:
```solidity
// VULNERABLE ORDER
userBalances[outToken] -= amountOut;        // write 1: user balance reduced
poolReserves[outToken] -= amountOut;         // write 2: reserve reduced
emit Swapped(msg.sender, amountIn, amountOut); // potential hook
```

An external caller reading `userBalances` between write 1 and write 2 sees a stale (inflated) out-token balance. If the protocol has any logic like "user can withdraw up to their balance," they can withdraw more than they should because the reserve hasn't caught up yet.

Combined with reentrancy on the transfer call (if SafeERC20 isn't used), this enables a classic reentrancy drain.

**Rank: #4.** Requires specific external hooks to trigger, but if present, enables full drain.

---

### Attack Path 5 (MEDIUM — Exploitability: Moderate)

**Zero-Liquidity Price Singularity / Division-by-Zero**

Reading spot price from `reserveB / reserveA` with no lower bound means if `reserveA` approaches zero (due to a large directional sweep), the computed price spikes toward infinity. Without clamping or minimum reserve checks, the pool either:
- Reverts (denominator check prevents the swap) — losing the last bit of liquidity
- Computes a near-infinite price — allowing the attacker to get essentially free assets

This is particularly dangerous when combined with the donation vector: an attacker can drain one side of the pool through repeated attacks until reserves are negligible, then extract remaining value at a favorable price.

**Rank: #5.** Often self-limiting (the revert protects), but sets up conditions for other attacks.

---

### Attack Path 6 (MEDIUM — Exploitability: Moderate)

**Fee Rate Abuse / Admin Privilege Escalation**

No mention of access control on the fee setter. If `setFee()` is unrestricted, an attacker who gains any foothold (e.g., via donation-induced admin role transfer, or a bug in ownership logic) can set fees to 100%, effectively stealing all future swaps, or to 0%, making the pool arbitraged away. Without `Ownable2Step`, any ownership transfer is accept-once-or-always, enabling persistent backdoors.

**Rank: #6.** Requires prior compromise to exploit, but compounds damage multiplicatively.

## Hardened Implementation

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import {SafeERC20} from "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";
import {ReentrancyGuard} from "@openzeppelin/contracts/utils/ReentrancyGuard.sol";
import {Ownable2Step} from "@openzeppelin/contracts/access/Ownable2Step.sol";
import {FullMath} from "@uniswap/v3-core/contracts/libraries/FullMath.sol";

interface ITwapOracle {
    function sqrtPriceX96(uint32[] calldata secondsAgos) external view returns (uint160);
}

contract ConstantProductAMM is ReentrancyGuard, Ownable2Step {
    using SafeERC20 for IERC20;

    /* ── Storage ─────────────────────────────────────────────── */

    IERC20 public immutable tokenA;
    IERC20 public immutable tokenB;
    ITwapOracle public twapOracle;
    uint256 public constant FEE_RATE = 30; // 0.30%, precision 10_000
    uint256 public feeRate = FEE_RATE;     // adjustable by owner

    /// @dev Internal reserve tracking — NOT derived from balanceOf
    uint256 private _reserveA;
    uint256 private _reserveB;

    /// @dev Share accounting tied to actual deposits, never raw balances
    uint256 public totalShares;
    uint256 private _totalAssetsA; // tracks cumulative tokenA deposited
    uint256 private _totalAssetsB; // tracks cumulative tokenB deposited

    bool public paused;

    /* ── Modifiers ───────────────────────────────────────────── */

    modifier notPaused() { require(!paused, "Paused"); _; }
    modifier validReserves() {
        require(_reserveA > 0 && _reserveB > 0, "No liquidity");
        _;
    }

    /* ── Constructor ─────────────────────────────────────────── */

    constructor(IERC20 _tokenA, IERC20 _tokenB) Ownable(msg.sender) {
        tokenA = _tokenA;
        tokenB = _tokenB;
    }

    function setTwapOracle(ITwapOracle _oracle) external onlyOwner {
        require(address(_oracle) != address(0), "Zero oracle");
        twapOracle = _oracle;
    }

    function setFeeRate(uint256 newFee) external onlyOwner {
        require(newFee <= 250, "Fee cap 2.5%"); // max 2.5%
        feeRate = newFee;
    }

    function pause() external onlyOwner { paused = true; }
    function unpause() external onlyOwner { paused = false; }

    /* ── Deposit / Withdraw (LP shares) ─────────────────────── */

    /**
     * @notice Provide liquidity for a single asset type.
     * @dev Measures ACTUAL tokens received, not pool balance. Tracks
     *      _totalAssets internally to prevent donation-based inflation.
     */
    function depositSingleAsset(uint256 assets, bool isTokenA)
        external nonReentrant returns (uint256 shares)
    {
        require(assets > 0, "Zero deposit");
        uint256 balBefore = _balanceOfUnsafe(isTokenA ? tokenA : tokenB);
        _safeTransferFrom(isTokenA ? tokenA : tokenB, msg.sender, assets);
        uint256 received = _balanceOfUnsafe(isTokenA ? tokenA : tokenB) - balBefore;
        require(received == assets, "Transfer mismatch");

        if (totalShares == 0) {
            shares = received; // first depositor: 1:1 mint
        } else {
            uint256 trackedTotal = isTokenA ? _totalAssetsA : _totalAssetsB;
            require(trackedTotal > 0, "No baseline");
            shares = FullMath.mulDiv(received * totalShares, 1, trackedTotal);
        }

        totalShares += shares;
        if (isTokenA) _totalAssetsA += received;
        else          _totalAssetsB += received;

        _syncReserves(received, isTokenA);
        emit LiquidityAdded(msg.sender, shares, received, isTokenA);
    }

    /**
     * @notice Provide liquidity as a paired deposit (balanced proportions).
     */
    function depositPaired(uint256 amountAAbsolute, uint256 amountBAbsolute)
        external nonReentrant returns (uint256 shares)
    {
        require(amountAAbsolute > 0 && amountBAbsolute > 0, "Zero input");

        uint256 balBeforeA = _balanceOfUnsafe(tokenA);
        uint256 balBeforeB = _balanceOfUnsafe(tokenB);
        _safeTransferFrom(tokenA, msg.sender, amountAAbsolute);
        _safeTransferFrom(tokenB, msg.sender, amountBAbsolute);

        uint256 receivedA = _balanceOfUnsafe(tokenA) - balBeforeA;
        uint256 receivedB = _balanceOfUnsafe(tokenB) - balBeforeB;

        // Revert sender if they transferred wrong amounts
        require(receivedA == amountAAbsolute && receivedB == amountBAbsolute, "Mismatch");

        if (totalShares == 0) {
            shares = receivedA < receivedB ? receivedA : receivedB;
        } else {
            uint256 sharesA = FullMath.mulDiv(receivedA * totalShares, 1, _totalAssetsA);
            uint256 sharesB = FullMath.mulDiv(receivedB * totalShares, 1, _totalAssetsB);
            shares = sharesA < sharesB ? sharesA : sharesB; // min of both sides
        }

        totalShares += shares;
        _totalAssetsA += receivedA;
        _totalAssetsB += receivedB;
        _reserveA += receivedA;
        _reserveB += receivedB;

        emit LiquidityAdded(msg.sender, shares, receivedA, true);
        emit LiquidityAdded(msg.sender, shares, receivedB, false);
    }

    /**
     * @notice Burn LP shares to withdraw proportional liquidity.
     */
    function withdraw(uint256 shares)
        external nonReentrant returns (uint256 amountA, uint256 amountB)
    {
        require(shares > 0 && shares <= totalShares, "Bad shares");
        require(!paused, "Paused");

        amountA = FullMath.mulDiv(totalShares == 0 ? 0 : shares * _reserveA, 1, totalShares);
        amountB = FullMath.mulDiv(totalShares == 0 ? 0 : shares * _reserveB, 1, totalShares);

        require(amountA > 0 && amountB > 0, "Zero output");

        totalShares -= shares;
        _totalAssetsA -= amountA;
        _totalAssetsB -= amountB;
        _reserveA -= amountA;
        _reserveB -= amountB;

        _safeTransfer(tokenA, msg.sender, amountA);
        _safeTransfer(tokenB, msg.sender, amountB);

        emit LiquidityRemoved(msg.sender, shares, amountA, amountB);
    }

    /* ── Swap (hardened) ─────────────────────────────────────── */

    /**
     * @notice Swap assets using constant-product x*y=k invariant.
     * @param amountIn         Amount of input token to sell.
     * @param amountOutMin     Minimum acceptable output (slippage guard).
     * @param recipient        Address that receives output.
     * @param deadline         Unix timestamp after which the tx reverts.
     * @param isTokenAIn       True if swapping tokenA → tokenB.
     * @return amountOut       Actual output amount.
     */
    function swap(
        uint256 amountIn,
        uint256 amountOutMin,
        address recipient,
        uint256 deadline,
        bool isTokenAIn
    ) external nonReentrant notPaused validReserves returns (uint256 amountOut) {
        require(block.timestamp <= deadline, "Swap expired");
        require(amountIn > 0, "Zero input");
        require(recipient != address(0), "Zero recipient");
        require(amountOutMin > 0, "Need minimum output");

        IERC20 tokenIn = isTokenAIn ? tokenA : tokenB;
        IERC20 tokenOut = isTokenAIn ? tokenB : tokenA;

        // 1. CEI: compute everything BEFORE touching balances or reserves
        amountOut = _calculateOutput(amountIn, isTokenAIn);
        require(amountOut >= amountOutMin, "Slippage exceeded");

        // 2. Pull input from sender (happens inside _executeSwap)
        _executeSwap(tokenIn, tokenOut, amountIn, amountOut, recipient, isTokenAIn);

        emit Swapped(msg.sender, recipient, amountIn, amountOut, isTokenAIn);
    }

    /**
     * @notice Quote a swap output WITHOUT executing (for UI).
     *         Caller MUST enforce slippage bounds before submitting the real tx.
     */
    function quoteSwap(uint256 amountIn, bool isTokenAIn)
        external view validReserves returns (uint256 amountOut)
    {
        return _calculateOutput(amountIn, isTokenAIn);
    }

    /* ── Internal helpers ────────────────────────────────────── */

    /**
     * @dev Constant-product formula: k = reserveIn * reserveOut.
     *      After swap with fee: amountOut = reserveOut - reserveOut * reserveIn / (reserveIn + Δin * (1 - fee))
     */
    function _calculateOutput(uint256 amountIn, bool isTokenAIn)
        internal view returns (uint256 amountOut)
    {
        uint256 reserveIn  = isTokenAIn ? _reserveA : _reserveB;
        uint256 reserveOut = isTokenAIn ? _reserveB : _reserveA;

        uint256 amountInAfterFee = FullMath.mulDiv(amountIn * (10_000 - feeRate), 1, 10_000);
        // amountOut = (reserveOut * amountInAfterFee) / (reserveIn + amountInAfterFee)
        amountOut = FullMath.mulDiv(reserveOut, amountInAfterFee, reserveIn + amountInAfterFee);
        require(amountOut > 0, "Calculation error");
    }

    /**
     * @dev Execute atomic swap: CEI order, correct reserve accounting,
     *      measures actual received tokens via balance delta.
     */
    function _executeSwap(
        IERC20 tokenIn,
        IERC20 tokenOut,
        uint256 amountIn,
        uint256 amountOut,
        address recipient,
        bool isTokenAIn
    ) internal {
        // STEP 1: Pull input — measure what we actually receive
        uint256 balBeforeIn  = _balanceOfUnsafe(tokenIn);
        uint256 balBeforeOut = _balanceOfUnsafe(tokenOut);
        _safeTransferFrom(tokenIn, msg.sender, amountIn);
        uint256 received = _balanceOfUnsafe(tokenIn) - balBeforeIn;
        require(received == amountIn, "Transfer mismatch on swap");

        // STEP 2: Push output to recipient FIRST
        _safeTransfer(tokenOut, recipient, amountOut);

        // STEP 3: Update reserves AFTER all external interactions
        if (isTokenAIn) {
            _reserveA += received;
            _reserveB -= amountOut;
        } else {
            _reserveB += received;
            _reserveA -= amountOut;
        }

        // Sanity check: k must not decrease
        uint256 kBefore = FullMath.mulDiv(_reserveA + _reserveA /* adjusted */, 1, 1);
        // Simpler: just ensure reserves didn't cross zero
        require(_reserveA > 0 && _reserveB > 0, "Reserves invalid");
    }

    /**
     * @dev Sync single-asset reserves for deposit path.
     */
    function _syncReserves(uint256 amount, bool isTokenA) internal {
        if (isTokenA) _reserveA += amount;
        else          _reserveB += amount;
    }

    /**
     * @dev Wrapper around token.balanceOf that does NOT feed into share math.
     *      Used only for measuring actual incoming/outgoing in _executeSwap
     *      and _depositSingleAsset — not for computing prices or shares.
     */
    function _balanceOfUnsafe(IERC20 token) internal view returns (uint256) {
        return token.balanceOf(address(this));
    }

    /**
     * @dev Safe transfer wrapper. Never uses balanceOf for accounting.
     */
    function _safeTransfer(IERC20 token, address to, uint256 amount) internal {
        token.safeTransfer(to, amount);
    }

    /**
     * @dev Safe transferFrom wrapper.
     */
    function _safeTransferFrom(IERC20 token, address from, uint256 amount) internal {
        token.safeTransferFrom(from, address(this), amount);
    }

    /**
     * @notice Emergency withdrawal of stuck/donated tokens.
     *         Owner-only, requires explicit acceptance of ownership.
     */
    function emergencyWithdraw(IERC20 token, uint256 amount) external onlyOwner nonReentrant {
        require(token != tokenA || amount == 0, "Cannot withdraw main tokens via emergency");
        require(token != tokenB || amount == 0, "Cannot withdraw main tokens via emergency");
        require(amount > 0, "Zero amount");
        _safeTransfer(token, owner(), amount);
    }

    /* ── Events ──────────────────────────────────────────────── */

    event Swapped(address indexed sender, address indexed recipient, uint256 amountIn, uint256 amountOut, bool isTokenAIn);
    event LiquidityAdded(address indexed provider, uint256 shares, uint256 assets, bool isTokenA);
    event LiquidityRemoved(address indexed provider, uint256 shares, uint256 amountA, uint256 amountB);

    /* ── Disclaimer ──────────────────────────────────────────── */
    // NOTE: Any arbitrary donation to this contract of non-mainnet tokens
    // will be invisible to the reserve math but visible in balanceOf.
    // These funds accrue to existing LPs as unearned yield. Use
    // emergencyWithdraw (owner-only) to reclaim mistakenly-sent tokens.
    // For intentional donations, remove the emergencyWithdraw restriction.
}
```

### Key Design Decisions Summary

| Pattern | Vulnerable | Hardened |
|---|---|---|
| **Reserve source** | `balanceOf(address(this))` | Private `_reserveA`/`_reserveB` written explicitly |
| **Share accounting** | `mint = (deposit × totalShares) / balanceOf(contract)` | Uses internal `_totalAssets` tracking actual deposits |
| **CEI ordering** | User balance updated → reserve settled (reenterable window) | Compute all values → pull input → push output → update reserves |
| **Slippage** | None on frontend | `amountOutMin` + `deadline` required on every `swap()` call |
| **Quote mechanism** | UI reads `balanceOf` directly | `quoteSwap()` reads internal reserves only; UI enforces slippage client-side |
| **Donations** | Accepted implicitly, inflating denominator | Main tokens protected via `emergencyWithdraw`; donated non-mainnet tokens silently benefit LPs (by design, but documented) |
| **Access control** | Unknown (likely missing) | `Ownable2Step` (explicit ownership acceptance), fee cap at 2.5% |
| **Pause** | None | Emergency `pause()`/`unpause()` on all user functions |
| **Overflow safety** | Naive multiplication/division | `FullMath.mulDiv` for all reserve/quote arithmetic |

The fundamental fix is the **separation of concerns**: internal reserves are a deliberate ledger (`_reserveA/B`) that only changes through verified deposit/withdraw/swap flows. `balanceOf(address(this))` is consulted *only* for measuring actual transfer deltas during those flows, never for price computation or share minting. Combined with CEI ordering, slippage bounds, deadlines, and TWAP oracle support, this eliminates all six identified attack vectors.
