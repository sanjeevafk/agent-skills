# Sliding-Window Rate Limiter — Red/Green/Refactor Cycles

## Architecture Overview

```
SlidingWindowRateLimiter(limit, window_seconds)
├── _keys: dict[str, deque[float]]     # key → sorted timestamps of accepted requests
├── allow(key, now=None) → bool        # check & consume if allowed
├── _purge(key, now)                   # remove expired entries outside window
└── _count(key, now) → int             # current request count within window
```

Clock injection via optional `now` parameter everywhere. No real sleeps in tests.

## INCREMENT 2: "Rejects at exact limit"

### RED — The Failing Test

```python
import asyncio
from sliding_window_limiter import SlidingWindowRateLimiter


async def test_rejects_at_exact_limit():
    """Once a key has reached its limit, further requests must be denied."""
    limiter = SlidingWindowRateLimiter(limit=2, window_seconds=10.0)
    base = 1_000_000.0

    assert limiter.allow("user:x", now=base) is True      # 1st → allowed
    assert limiter.allow("user:x", now=base + 1.0) is True # 2nd → allowed (AT limit)
    assert limiter.allow("user:x", now=base + 2.0) is False # 3rd → DENIED
```

**Current failure:** The implementation always returns `True`, so assertion 3 fires.

---

### GREEN — Minimal Fix

Add the limit check. The simplest correct logic given our existing structure:

```python
def allow(self, key: str, *, now: float | None = None) -> bool:
    ts = now if now is not None else self._tick()
    if key not in self._keys:
        self._keys[key] = deque()
    self._keys[key].append(ts)

    if len(self._keys[key]) > self._limit:
        return False
    return True
```

This works but has a flaw: the timestamp gets appended even on rejection, bloating the deque forever. Let's do slightly better for the refactor discussion. Actually — let's keep it dead-simple here for pure green, then address it in refactor.

Actually wait, there's a subtle issue. This appends the rejected request into the history, which means later window-expiry purges have to work harder, and it leaks memory. For incremental correctness, let's just add the conditional check:

```python
def allow(self, key: str, *, now: float | None = None) -> bool:
    ts = now if now is not None else self._tick()
    if key not in self._keys:
        self._keys[key] = deque()
    self._keys[key].append(ts)

    count = len(self._keys[key])
    return count <= self._limit
```

Same problem. Let's accept the minor defect here (it's surfaced for purge) and push the clean-up to refactor where we see the pattern emerge.

---

### REFACTOR 2

**Observation:** After writing both increments together, a clear smell emerges — every call to `allow` that results in `False` leaves a ghost timestamp in the deque. Also, the size check happens *after* appending, which is counter-intuitive. The right pattern becomes visible:

```python
def allow(self, key: str, *, now: float | None = None) -> bool:
    ts = now if now is not None else self._tick()
    if key not in self._keys:
        self._keys[key] = deque()
    self._keys[key].append(ts)

    if len(self._keys[key]) > self._limit:
        self._keys[key].pop()   # undo the rejected append
        return False
    return True
```

By popping the rejected timestamp, we keep the deque containing only accepted requests. The cost: O(1) amortized pop instead of growing unbounded.

**What this refactor improved:**
1. **Correctness of history** — only admitted requests persist in the timeline, so downstream logic (purge, count queries) operates on accurate data
2. **Memory boundedness** — rejected calls don't accumulate stale timestamps
3. **Semantic clarity** — the deque meaning shifted from "all requests received" to "all requests accepted," which is the natural invariant for a rate limiter

## INCREMENT 3: "Resets after window expires"

### RED — The Failing Test

```python
import asyncio
from sliding_window_limiter import SlidingWindowRateLimiter


async def test_resets_after_window_expires():
    """Once the window slides past old entries, new requests are allowed again."""
    limiter = SlidingWindowRateLimiter(limit=2, window_seconds=5.0)
    t0 = 1_000_000.0

    # Fill up the quota
    assert limiter.allow("key:a", now=t0) is True      # accepted, deque=[t0]
    assert limiter.allow("key:a", now=t0 + 1.0) is True # accepted, deque=[t0, t0+1]

    # Exhausted — denied
    assert limiter.allow("key:a", now=t0 + 2.0) is False # rejected

    # Advance past the window — t0's entry falls outside [t0+6, t0+11]
    assert limiter.allow("key:a", now=t0 + 6.0) is True  # t0 is > 5 seconds ago, should roll off
```

**Why this fails currently:** The implementation never removes old entries. The deque grows to 3 items `[t0, t0+1, t0+6]`, and since `len=3 > limit=2`, the rejected call at `t0+2.0` might correctly reject. But at `t0+6.0`, the deque has 4 items, so it keeps rejecting forever.

---

### GREEN — Add Purging Logic

Minimal change — insert the expiry filter before the limit check:

```python
def allow(self, key: str, *, now: float | None = None) -> bool:
    ts = now if now is not None else self._tick()
    if key not in self._keys:
        self._keys[key] = deque()

    # Remove entries older than the window
    cutoff = ts - self._window
    while self._keys[key] and self._keys[key][0] <= cutoff:
        self._keys[key].popleft()

    self._keys[key].append(ts)

    if len(self._keys[key]) > self._limit:
        self._keys[key].pop()  # undo rejected
        return False
    return True
```

This passes. The `while popleft` loop trims all expired entries from the front. Then we append, check against limit, and undo if rejected.

---

### REFACTOR 3

**Observation:** The purge logic sits inline inside `allow`. If we later expose a `remaining(key)` or `next_available_time(key)` query method (common in production rate limiters), it needs the same purge logic. Duplication risk is visible.

Extract it:

```python
def allow(self, key: str, *, now: float | None = None) -> bool:
    ts = now if now is not None else self._tick()
    if key not in self._keys:
        self._keys[key] = deque()

    self._purge(key, ts)
    self._keys[key].append(ts)

    if len(self._keys[key]) > self._limit:
        self._keys[key].pop()
        return False
    return True

def _purge(self, key: str, now: float) -> None:
    cutoff = now - self._window
    while self._keys.get(key) and self._keys[key][0] <= cutoff:
        self._keys[key].popleft()

@property
def remaining(self, key: str, *, now: float | None = None) -> int:
    """How many more requests this key can make."""
    ts = now if now is not None else self._tick()
    if key not in self._keys:
        return self._limit
    self._purge(key, ts)
    return max(0, self._limit - len(self._keys[key]))
```

**What this refactor improved:**
1. **Single source of truth for eviction** — the `_purge` method encapsulates the windowing rule, eliminating copy-paste risk
2. **New capability emerged naturally** — `remaining` property is trivial because it reuses `_purge`; this is something the test suite didn't mandate but production always needs
3. **Testability** — `_purge` could be unit-tested independently if we wanted to stress-test edge timing (e.g., all entries expiring simultaneously), though the current tests exercise it through `allow`
4. **Readability** — `allow` shrunk from ~12 lines to ~8 lines; the intent (record → check → maybe undo) reads cleanly

## INCREMENT 4: "Concurrent coroutines share quota"

### RED — The Failing Test

```python
import asyncio
from sliding_window_limiter import SlidingWindowRateLimiter


async def test_concurrent_coroutines_share_quota():
    """Two coroutines racing to acquire the same key must not exceed the limit."""
    limiter = SlidingWindowRateLimiter(limit=3, window_seconds=10.0)
    accepted_count = 0
    lock = asyncio.Lock()

    async def hammer(key: str, n: int, now_base: float):
        nonlocal accepted_count
        for i in range(n):
            result = limiter.allow(key, now=now_base + i * 0.001)
            if result:
                async with lock:
                    accepted_count += 1

    await asyncio.gather(
        hammer("shared", 10, now_base=1_000_000.0),
        hammer("shared", 10, now_base=1_000_000.0),
    )

    # Both hammered with 10 calls each = 20 total attempts, but only 3 allowed
    assert accepted_count == 3, f"Expected 3 accepts but got {accepted_count}"
```

**Note on semantics:** Since we inject clocks (`now=`) rather than using real sleep-based races, true concurrent interleaving isn't possible in the deterministic `now` mode. The meaningful test here uses a shared real-clock path. Let me reframe:

```python
async def test_concurrent_coroutines_share_quota():
    """Two coroutines racing to acquire the same key must not exceed the limit."""
    limiter = SlidingWindowRateLimiter(limit=3, window_seconds=10.0)
    accepted_count = 0
    lock = asyncio.Lock()

    async def hammer(key: str, n: int):
        nonlocal accepted_count
        for i in range(n):
            result = limiter.allow(key)  # real clock, actual race possible
            if result:
                async with lock:
                    accepted_count += 1

    # Spawn 6 coroutines simultaneously hammering 2 attempts each
    await asyncio.gather(*[hammer("shared", 2) for _ in range(6)])

    # 6 × 2 = 12 attempts, limit = 3, so at most 3 accepted
    # In practice with real clock, some calls land at the same second.
    # The deterministic equivalent: run sequentially with distinct clocks.
    assert accepted_count <= 3, f"Exceeded limit: {accepted_count} accepted"
```

Even better — use the clock-injection mode but simulate concurrency by running calls in an interleaved fashion:

```python
async def test_concurrent_coroutines_simulated_interleaving():
    """Simulate two coroutines interleave their calls — quota must hold."""
    limiter = SlidingWindowRateLimiter(limit=3, window_seconds=10.0)
    results_a = []
    results_b = []

    # Coroutine A fires at times 0, 2, 4
    # Coroutine B fires at times 1, 3, 5
    # Interleaved order: A@0, B@1, A@2, B@3, A@4, B@5
    # Only 3 should be allowed total
    events = [
        ("A", 0.0),  ("B", 1.0),  ("A", 2.0),
        ("B", 3.0),  ("A", 4.0),  ("B", 5.0),
    ]
    for coro_id, offset in events:
        result = limiter.allow("shared", now=offset)
        if coro_id == "A":
            results_a.append(result)
        else:
            results_b.append(result)

    total_accepted = sum(results_a) + sum(results_b)
    assert total_accepted == 3, f"Expected 3 accepts, got {total_accepted}"
    assert all(r in (True, False) for r in results_a + results_b)
```

This tests the concurrency property deterministically without needing real wall-clock races. The sequence simulates alternating coroutine execution.

---

### GREEN — Already passes

The current implementation (with purge, limit check, and undo-on-reject) handles this correctly because each `allow` call is a discrete operation on the deque state. With injected clocks, the interleaving is fully deterministic. The deque tracks all accepted timestamps; once 3 are recorded, subsequent calls find `len > limit` and deny.

---

### REFACTOR 4 — Observation on True Concurrency

The simulated-interleaving test works perfectly. But for **real asyncio concurrency** with actual `await` suspension points between calls, we'd need the limiter to be truly atomic under cancellation. Our current implementation has no `await` in `allow`, so asyncio's single-threaded event loop ensures no preemption mid-call. Therefore the real-concurrency test adds no additional coverage beyond the simulated one — *unless* the limiter spawns I/O internally.

For a pure-memory limiter like ours, **no await in the hot path = no preemption risk**. The refactor note is:

> If `allow` were to involve network calls, DB queries, or any `await`, we'd wrap the critical section (purge → read count → append/check → decide) in a mutex. For now, no mutex needed.

## Final Complete Implementation

```python
from __future__ import annotations

from collections import deque
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    pass


class SlidingWindowRateLimiter:
    """Per-key sliding-window rate limiter with clock injection for testing.

    Thread-safety: Not safe for multi-threaded access. Safe for asyncio
    because ``allow`` contains no ``await`` (single-threaded event loop
    guarantees atomicity). Use a ``asyncio.Lock`` around concurrent
    cross-process calls backed by external state.
    """

    __slots__ = ("_limit", "_window", "_keys")

    def __init__(self, limit: int, window_seconds: float) -> None:
        if limit < 1:
            raise ValueError("limit must be >= 1")
        if window_seconds <= 0:
            raise ValueError("window_seconds must be > 0")
        self._limit: int = limit
        self._window: float = window_seconds
        self._keys: dict[str, deque[float]] = {}

    # ------------------------------------------------------------------
    # Public API
    # ------------------------------------------------------------------

    def allow(self, key: str, *, now: float | None = None) -> bool:
        """Attempt to record a request for *key*.

        Returns ``True`` if the request is allowed, ``False`` if the
        sliding-window limit has been reached.
        """
        ts = self._tick(now)
        self._ensure_key(key)
        self._purge(key, ts)
        self._keys[key].append(ts)

        if len(self._keys[key]) > self._limit:
            self._keys[key].pop()       # undo rejected
            return False
        return True

    @property
    def remaining(self, key: str, *, now: float | None = None) -> int:
        """Number of additional requests allowed for *key* right now."""
        ts = self._tick(now)
        if key not in self._keys:
            return self._limit
        self._purge(key, ts)
        return max(0, self._limit - len(self._keys[key]))

    def reset(self, key: str) -> None:
        """Remove all recorded history for *key*, resetting its quota."""
        self._keys.pop(key, None)

    # ------------------------------------------------------------------
    # Internals
    # ------------------------------------------------------------------

    def _tick(self, now: float | None = None) -> float:
        if now is not None:
            return now
        import time
        return time.monotonic()

    def _ensure_key(self, key: str) -> None:
        if key not in self._keys:
            self._keys[key] = deque()

    def _purge(self, key: str, now: float) -> None:
        """Remove entries older than one full window."""
        cutoff = now - self._window
        k = self._keys.get(key)
        while k and k[0] <= cutoff:
            k.popleft()
```

    assert lim.remaining("k", now=base + 2.0) == 0
    lim.allow("k", now=base + 3.0)  # rejected
    assert lim.remaining("k", now=base + 3.0) == 0


@pytest.mark.asyncio
async def test_reset_clears_history():
    lim = SlidingWindowRateLimiter(limit=2, window_seconds=10.0)
    base = 0.0

    lim.allow("r", now=base)
    lim.allow("r", now=base + 1.0)
    assert lim.allow("r", now=base + 2.0) is False

    lim.reset("r")
    assert lim.allow("r", now=base + 3.0) is True
    assert lim.remaining("r", now=base + 3.0) == 1
