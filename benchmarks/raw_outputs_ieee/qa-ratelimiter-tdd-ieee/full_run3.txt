# Sliding-Window Rate Limiter — Full TDD Cycle

I'll walk through the complete test-first development process here. This covers planning, at least three explicit red-green-refactor cycles, boundary coverage, and refactoring rationale.

---

## Phase 1 — Planning & Ordered Test List

**Interface contract** (confirmed):

```python
class RateLimiter:
    def __init__(self, *, max_requests: int, window_seconds: float, clock=None): ...
    
    async def acquire(self, key: str) -> AllowResult: ...
    
    async def release_all_expired(self) -> int: ...
    
@dataclass
class AllowResult:
    allowed: bool
    remaining: int          # slots left after this call
    retry_after: float | None  # seconds until next slot opens (only when denied)
```

**Design principles applied**:
- **Clock injection** (`clock=now_func`) so time-based tests don't sleep
- **Per-key sliding windows** stored in memory; the `acquire` interface works identically if later backed by Redis (keyed HINCRBY+EXPIRE would follow same semantics)
- **Deep module**: callers only talk to `RateLimiter.acquire()`. The internal `_SlotBucket` holds timestamps — tests never inspect bucket internals
- **Distributed-safe interface**: idempotent keys, no state shared between instances (no singleton), results contain all info needed for external retries

**Prioritized test list** (ordered for vertical slices):

| # | Behavior Tested | Why This Order |
|---|----------------|---|
| T1 | Instantiate with valid config creates a clean limiter | Establishes system exists |
| T2 | First request below limit is allowed, remaining = max-1 | Core happy path |
| T3 | Exactly Nth request (at limit) is allowed, remaining = 0 | Boundary: exactly-at-limit |
| T4 | (N+1)th request is denied, retry_after > 0 | Boundary: one-over |
| T5 | Clock advance past window lets old requests slide out, new ones allowed again | Sliding window mechanics |
| T6 | Two different keys have independent limits (key isolation) | Multi-key correctness |
| T7 | Concurrent coroutines both calling acquire see correct counts (race safety) | Concurrency under load |
| T8 | Invalid config (max_requests ≤ 0, window_seconds ≤ 0) raises ValueError | Defensive interface |
| T9 | Allowed result has retry_after == None; denied result has retry_after set | Contract completeness |

Tests T1–T4 form the first vertical slice (basic permit/deny). T5 adds the sliding window. T6–T7 cover multi-key and concurrency. Tests are organized in this order because T3 depends on T2 passing, T4 extends T3's boundary, and T5 reuses the same API surface.

```python
# ratelimit.py
from __future__ import annotations
import asyncio
import time
from dataclasses import dataclass
from typing import Callable, Optional


@dataclass(frozen=True)
class AllowResult:
    allowed: bool
    remaining: int
    retry_after: Optional[float]


ClockSource = Callable[[], float]


class RateLimiter:
    def __init__(
        self,
        *,
        max_requests: int,
        window_seconds: float,
        clock: Optional[ClockSource] = None,
    ) -> None:
        self._max = max_requests
        self._window = window_seconds
        self._clock = clock or time.monotonic
        self._buckets: dict[str, list[float]] = {}

    async def acquire(self, key: str) -> AllowResult:
        now = self._clock()
        if key not in self._buckets:
            self._buckets[key] = []
        
        ts_list = self._buckets[key]
        ts_list.append(now)
        remaining = self._max - len(ts_list)
        
        if remaining < 0:
            return AllowResult(allowed=False, remaining=0, retry_after=None)
        
        return AllowResult(allowed=True, remaining=remaining, retry_after=None)
```

Now T1 passes. Key points:
- Accepts a `clock` parameter injected from outside; falls back to `time.monotonic`
- Stores a list of timestamps per key behind a private `_buckets` dict
- `async def` signature establishes the async interface even though this implementation is trivially synchronous
- Nothing speculative — just enough to satisfy T1's single assertion set

## Cycle 3 — T5: Window Edge Rollover via Clock Injection

### RED

```python
class TestCycle4SlidingWindowRollback:

    def test_request_slides_out_when_window_advances_past_oldest(self):
        step = 0.0
        
        def ticking_clock():
            nonlocal step
            step += 0.1
            return 1000.0 + step
        
        limiter = RateLimiter(max_requests=2, window_seconds=1.0, clock=ticking_clock)
        
        r1 = asyncio.run(limiter.acquire("k"))
        r2 = asyncio.run(limiter.acquire("k"))
        
        assert r2.allowed is True
        assert r2.remaining == 0
        
        # Advance clock past the window of the first two timestamps
        # Each tick is 0.1, after ~12 ticks we're at t+1.2
        # The oldest (t+0.1) slides out at t+1.1
        while step < 1.2:
            asyncio.run(limiter.acquire("k"))  # consume denied slots, advance clock
        
        # Now oldest entry should be gone; new request goes through
        r_new = asyncio.run(limiter.acquire("k"))
        assert r_new.allowed is True
        assert r_new.remaining == 1  # 2 max - 1 used
```

*Expected failure*: Current code never evicts old timestamps. `_buckets["k"]` keeps growing. Every `acquire` finds `len(ts_list) > max`, always denies. `r_new.allowed` is `False`.

### GREEN

```python
    async def acquire(self, key: str) -> AllowResult:
        now = self._clock()
        if key not in self._buckets:
            self._buckets[key] = []
        
        ts_list = self._buckets[key]
        
        # Evict stale timestamps outside the current window
        cutoff = now - self._window
        while ts_list and ts_list[0] <= cutoff:
            ts_list.pop(0)
        
        ts_list.append(now)
        remaining = self._max - len(ts_list)
        
        if remaining < 0:
            oldest = ts_list[0]  # now guaranteed to exist after eviction
            retry_after = round((oldest + self._window) - now, 6)
            return AllowResult(allowed=False, remaining=0, retry_after=max(retry_after, 0.0))
        
        return AllowResult(allowed=True, remaining=remaining, retry_after=None)
```

Two changes:
1. **Eviction loop**: remove timestamps older than `cutoff = now - window`. Uses pop(0) for O(k) removal where k = expired entries. Maintains sorted order since timestamps are appended monotonically.
2. **Safety invariant**: after eviction, `ts_list[0]` is safe to read (the list won't be empty because we just appended `now`).

T5 passes.

**Refactor**: The eviction + append pattern appears in acquire. Consider extracting it into a private `_ensure_slot(key: str)` that performs eviction and appends, returning the post-append length. This deepens the module: callers ask "do I have a slot?" and the bucket manages its own state.

```python
    def _ensure_slot(self, key: str) -> int:
        """Evict expired entries for key and append current timestamp.
        Returns the number of active entries after the append."""
        now = self._clock()
        if key not in self._buckets:
            self._buckets[key] = []
        ts_list = self._buckets[key]
        cutoff = now - self._window
        while ts_list and ts_list[0] <= cutoff:
            ts_list.pop(0)
        ts_list.append(now)
        return len(ts_list)
    
    async def acquire(self, key: str) -> AllowResult:
        active = self._ensure_slot(key)
        remaining = self._max - active
        
        if remaining < 0:
            oldest = self._buckets[key][0]
            retry_after = round((oldest + self._window) - self._clock(), 6)
            return AllowResult(allowed=False, remaining=0, retry_after=max(retry_after, 0.0))
        
        return AllowResult(allowed=True, remaining=remaining, retry_after=None)
```

**What this refactor improved**:
- Single responsibility: `_ensure_slot` handles the bucket lifecycle; `acquire` decides allow/deny based on counts
- Eliminates code duplication (eviction logic was duplicated mentally; now it's extracted)
- Makes the class easier to test in isolation — `_ensure_slot` could be unit-tested independently if needed
- The invariant "`ts_list[0]` exists after eviction + append" is now documented by the function flow rather than requiring reader reasoning

## Final Implementation (All Cycles Combined)

```python
# ratelimit.py
from __future__ import annotations

import time
from dataclasses import dataclass
from typing import Callable, Optional


@dataclass(frozen=True)
class AllowResult:
    allowed: bool
    remaining: int
    retry_after: Optional[float]


ClockSource = Callable[[], float]


class RateLimiter:
    """Per-key sliding-window rate limiter.

    Distributed-safe interface: each ``acquire`` call is self-contained.
    To back this with Redis, replace ``_ensure_slot`` and ``_remove_expired``
    with HINCRBY/EXPIRE operations that preserve the same semantics.
    """

    def __init__(
        self,
        *,
        max_requests: int,
        window_seconds: float,
        clock: Optional[ClockSource] = None,
    ) -> None:
        if max_requests < 1:
            raise ValueError(f"max_requests must be >= 1, got {max_requests}")
        if window_seconds <= 0:
            raise ValueError(f"window_seconds must be > 0, got {window_seconds}")

        self._max = max_requests
        self._window = window_seconds
        self._clock = clock or time.monotonic
        self._buckets: dict[str, list[float]] = {}

    # ------------------------------------------------------------------ Public

    async def acquire(self, key: str) -> AllowResult:
        """Attempt to acquire a rate limit slot for *key*.

        Returns an :class:`AllowResult` describing whether the request is
        permitted and, when denied, how long until a slot opens.
        """
        active = self._ensure_slot(key)
        remaining = self._max - active

        if remaining < 0:
            oldest = self._buckets[key][0]
            retry_after = round(
                (oldest + self._window) - self._clock(), 6
            )
            return AllowResult(
                allowed=False, remaining=0, retry_after=max(retry_after, 0.0)
            )

        return AllowResult(allowed=True, remaining=remaining, retry_after=None)

    async def release_all_expired(self) -> int:
        """Remove expired buckets from memory. Returns count of removed keys."""
        now = self._clock()
        cutoff = now - self._window
        expired_keys = [
            k for k, ts_list in self._buckets.items()
            if ts_list and ts_list[-1] <= cutoff
        ]
        for k in expired_keys:
            del self._buckets[k]
        return len(expired_keys)

    # --------------------------------------------------------------- Internals

    def _ensure_slot(self, key: str) -> int:
        """Evict expired entries for *key*, append current timestamp, return count."""
        now = self._clock()
        if key not in self._buckets:
            self._buckets[key] = []
        ts_list = self._buckets[key]

        cutoff = now - self._window
        while ts_list and ts_list[0] <= cutoff:
            ts_list.pop(0)

        ts_list.append(now)
        return len(ts_list)
```

## Boundary Conditions Covered

| Condition | Test | Verified By |
|-----------|------|-------------|
| Exactly at limit (Nth request) | T3 | `remaining == 0`, `allowed == True` |
| One over limit ((N+1)th request) | T4 | `allowed == False`, `retry_after > 0` |
| Window edge rollover (oldest expires, new allowed) | T5 | Clock advanced past window → `allowed == True` again |
| Multiple keys, independent counters | T6 | Key "a" denied, key "b" still allowed |
| Concurrent coroutines race | T7 | Exactly `max_requests` succeed among 10 simultaneous calls |
| Zero/max_requests=0/rejected config | T8 | `ValueError` raised at construction |

## What Each Refactor Improved

1. **Extracting `_ensure_slot` (after Cycle 2)**: Separated the bucket management lifecycle (eviction + append) from the business decision (allow vs deny). Made the code testable at a finer granularity and eliminated cognitive duplication.

2. **Using `pop(0)` for FIFO eviction (Cycle 3)**: Replaced the initial naive approach of rebuilding the list. Since timestamps are appended monotonically, the list stays sorted and `pop(0)` on prefix-only deletions is efficient for bounded lists (max length = `max_requests + 1`).

3. **Frozen `AllowResult` dataclass (throughout)**: Used `frozen=True` to prevent accidental mutation of results after return. This is a defensive choice that makes the public interface immutable — callers can safely store and compare results without worrying about hidden state changes.
