# Sliding Window Rate Limiter — Full Test-First Implementation

## Design Decisions

| Decision | Rationale |
|---|---|
| **Pattern** | Sliding Window Log — stores individual request timestamps, truncates those outside the window. Simple, precise, serializable for distributed use. |
| **Concurrency primitive** | `asyncio.Lock` per key — fine-grained locking avoids bottlenecks that a global lock would create. |
| **Clock injection** | `rate: float = None` parameter on `allow()` — the caller provides time; `None` defaults to `time.time()`. No wrapper class needed. |
| **Atomic allow+record** | Single `allow(key, rate=None)` method that both decides AND commits. Two-phase (`allow` + `record`) adds complexity without tangible benefit here. |
| **Data structure** | `deque` per key, FIFO order. Append-to-end for new timestamps, popleft for expired. Both O(1). |
| **Distributed hook** | The public interface is small enough that a Redis-backed implementation shares the exact same contract. Swap the backend, same API. |

### GREEN: Implement per-key isolation

This is mostly already done from the refactors above. The critical addition is **window trimming** — timestamps from before `(now - window_seconds)` must not count toward the limit, otherwise the bucket never refills:

```python
async def allow(self, key: str, rate: float = None) -> bool:
    lock = self._get_lock(key)
    now = rate if rate is not None else self.clock()
    
    async with lock:
        self._ensure_key(key)
        self._trim(key, now)
        if len(self._per_key[key]) >= self.max_requests:
            return False
        self._per_key[key].append(now)
        return True

def _trim(self, key: str, now: float) -> None:
    cutoff = now - self.window_seconds
    timestamps = self._per_key[key]
    while timestamps and timestamps[0] <= cutoff:
        timestamps.pop(0)

def _ensure_key(self, key: str) -> None:
    if key not in self._per_key:
        self._per_key[key] = []

def _get_lock(self, key: str) -> asyncio.Lock:
    if key not in self._per_key_lock:
        self._per_key_lock[key] = asyncio.Lock()
    return self._per_key_lock[key]
```

### Refactor (post-Green-3)

| Issue | Improvement |
|---|---|
| `_trim` uses `list.pop(0)` — O(n) for large lists | Replace `list` with `collections.deque`. `deque.popleft()` is O(1). Same algorithm, better asymptotic bound for high-volume keys. |
| Lock creation in `_get_lock` has no synchronization if somehow called from multiple threads | Acceptable for asyncio (single-threaded event loop), but document the assumption. Add type annotation. |
| `_ensure_key`, `_trim`, `_get_lock` all private — good. But `_trim` is only called from `allow` | No extraction needed; the method is short and focused. |

_per_key: Dict[str, deque] = {}

def _ensure_key(self, key: str) -> None:
    if key not in self._per_key:
        self._per_key[key] = deque()

def _trim(self, key: str, now: float) -> None:
    cutoff = now - self.window_seconds
    ts = self._per_key[key]

## Full Production Implementation

```python
"""Sliding-window rate limiter with per-key limits, clock injection, and asyncio concurrency safety."""

import asyncio
import time
from collections import deque
from typing import Deque, Dict, Optional


class RateLimiter:
    """Async sliding-window rate limiter.

    Uses a log-based sliding window: each request's timestamp is recorded,
    and timestamps older than ``window_seconds`` are discarded before
    evaluating the limit.

    Public API (one method)::

        allowed = await limiter.allow(key, rate=optional_clock_value)

    All state is keyed by ``key``, so different keys have independent
    quotas.  An ``asyncio.Lock`` per key guarantees correct concurrent
    behaviour when multiple coroutines call :meth:`allow` simultaneously.
    """

    def __init__(
        self,
        max_requests: int,
        window_seconds: int,
        clock,
    ) -> None:
        self.max_requests = max_requests
        self.window_seconds = window_seconds
        self.clock = clock
        self._per_key: Dict[str, Deque[float]] = {}
        self._per_key_lock: Dict[str, asyncio.Lock] = {}

    # ── Public interface ───────────────────────────────────────

    async def allow(self, key: str, rate: Optional[float] = None) -> bool:
        """Decide whether a request is allowed and, if so, record it.

        Parameters
        ----------
        key:
            Identifier for the entity being rate-limited
            (e.g. user ID, IP address, API key).
        rate:
            Injected timestamp.  When *None* the limiter calls
            :attr:`clock`.  Tests inject a fixed value to avoid
            real-time delays.

        Returns
        -------
        True if the request is allowed, False if the limit is
        exceeded for *key*.
        """
        lock = self._get_lock(key)
        now = rate if rate is not None else self.clock()

        async with lock:
            self._ensure_key(key)
            self._trim(key, now)
            if len(self._per_key[key]) >= self.max_requests:
                return False
            self._per_key[key].append(now)
            return True

    async def cleanup(self, key: str, rate: Optional[float] = None) -> int:
        """Purge expired entries for *key*, returning how many were removed.

        Useful for long-lived keys where stale timestamps would
        otherwise occupy memory indefinitely.
        """
        lock = self._get_lock(key)
        now = rate if rate is not None else self.clock()

        async with lock:
            self._ensure_key(key)
            before = len(self._per_key[key])
            self._trim(key, now)
            return before - len(self._per_key[key])

    # ── Internal helpers ───────────────────────────────────────

    def _ensure_key(self, key: str) -> None:
        if key not in self._per_key:
            self._per_key[key] = deque()

    def _trim(self, key: str, now: float) -> None:
        cutoff = now - self.window_seconds
        ts = self._per_key[key]
        while ts and ts[0] <= cutoff:
            ts.popleft()

    def _get_lock(self, key: str) -> asyncio.Lock:
        if key not in self._per_key_lock:
            self._per_key_lock[key] = asyncio.Lock()
        return self._per_key_lock[key]
```

## Summary of Refactoring Insights

| Cycle | What broke / changed | Refactor applied | Why it matters |
|---|---|---|---|
| **1→2** | Lock lazy-init (`if self._lock is None`) | Moved to `__init__`; per-key lock dict `_per_key_lock` | Eliminates a conditional branch on every call; per-key granularity avoids global bottleneck |
| **2→3** | Inline key init (`if key not in self._per_key`) | Extracted `_ensure_key()` | `allow()` reads like a specification: *trim → check → record*. Initialization is hidden behind a named method |
| **2→3** | Timestamps accumulate forever | Added `_trim()` with `cutoff = now - window_seconds` | Without trimming, buckets never refill — the sliding window collapses into a fixed counter |
| **3→4** | `list.pop(0)` is O(n) | Replaced `list` with `collections.deque` | `popleft()` is O(1); for a key with thousands of requests in a window, this saves meaningful CPU |
| **4+** | Unbounded `_per_key_lock` dict | Documented as acceptable (key count is application-bounded); `cleanup()` indirectly prunes | Explicitly acknowledged trade-off; for streaming systems, a TTL on lock entries could be added later if profiling demands it |

## Architecture Notes

1. **Why per-key locks over a global lock?** A global lock serializes *all* keys through a single mutex. If you're limiting 10,000 users, 9,999 of them block for a key that has nothing to do with them. Per-key locks mean unrelated keys proceed in parallel — a natural fit for asyncio's single-threaded event loop where the lock simply queues coroutines.

2. **Why `deque` over a sorted list or heap?** We only ever append to the tail and pop from the head (FIFO insertion order of requests). No random-access or reordering needed. `deque` gives O(1) at both ends.

3. **Distributed extension path.** The public method is `allow(key, rate=None) → bool`. A Redis-backed version swaps the in-memory `deque`/`Lock` for `Redis.ZREMRANGEBYSCORE` + `Redis.ZADD` + `Redis.XADD` / Lua scripts — same method signature, same return type. The interface is thin enough that the implementation swap costs days, not months.

4. **Clock injection over monkey-patching `time.time`.** Tests specify exact timestamps (`t=0`, `t=5`, `t=11`). Monkey-patching is fragile (thread-safety concerns, hard to restore). Passing `rate=` directly makes the test intent obvious and requires zero teardown.
