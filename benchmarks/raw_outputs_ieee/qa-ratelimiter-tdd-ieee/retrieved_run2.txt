## Domain Model & Interface Contract

**`SlidingWindowRateLimiter`** — the public API surface:

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from datetime import timedelta, datetime
from typing import Protocol

@dataclass(frozen=True)
class TokenBucketState:
    remaining: int
    limit: int
    retry_after_seconds: float | None  # None if not rate-limited

class RateLimitStore(Protocol):
    """Distributed-safe persistence contract — any backend must implement."""
    async def increment_and_count(self, key: str, window: timedelta,
                                   now: datetime) -> tuple[int, int]:
        """Atomically add one entry and return (total_count, unique_window_count)."""
        ...
    async def cleanup_expired(self, key: str, cutoff: datetime) -> int:
        """Delete entries before cutoff. Returns deleted count."""
        ...

class SlidingWindowRateLimiter:
    def __init__(self, store: RateLimitStore, limit: int = 10,
                 window: timedelta = timedelta(seconds=60),
                 clock=None):
        ...
    async def allow(self, key: str) -> TokenBucketState:
        """Returns state without modifying counters (inspection-only)."""
        ...
    async def record(self, key: str) -> TokenBucketState:
        """Atomically checks + increments. Rejects if over limit."""
        ...
```

```python
from dataclasses import dataclass
from datetime import timedelta, datetime
from typing import Protocol


@dataclass(frozen=True)
class TokenBucketState:
    remaining: int
    limit: int
    retry_after_seconds: float | None


class RateLimitStore(Protocol):
    async def increment_and_count(self, key: str, window: timedelta,
                                   now: datetime) -> tuple[int, int]:
        ...
    async def cleanup_expired(self, key: str, cutoff: datetime) -> int:
        ...


class SlidingWindowRateLimiter:
    def __init__(self, store, limit: int = 10,
                 window: timedelta = timedelta(seconds=60), clock=None):
        self._store = store
        self._limit = limit
        self._window = window
        self._clock = clock or (lambda: datetime.now(timezone.utc))

    async def record(self, key: str) -> TokenBucketState:

        total, window_count = await self._store.increment_and_count(key, self._window, now)
```

## Increment 3: `exactly_at_boundary` + `one_over_boundary`

### RED — Two failing tests

```python
@pytest.mark.asyncio
async def test_exactly_at_boundary(limiter, mock_store):
    """The Nth request (where N=limit) is accepted — remaining becomes 0."""
    mock_store.increment_and_count.return_value = (0, 4)  # 4 prior calls, limit=5

    result = await limiter.record("user:1")

    assert result.remaining == 0
    assert result.retry_after_seconds is None


@pytest.mark.asyncio
async def test_one_over_boundary(limiter, mock_store):
    """The (N+1)th request is rejected when all slots are used."""
    mock_store.increment_and_count.return_value = (0, 5)  # 5 prior calls, limit=5

    result = await limiter.record("user:1")

    assert result.remaining == 0
    assert result.retry_after_seconds is not None
```

**Expected failure:** The `>=` comparison in Increment 2 means the 5th call (index 4→5) would still hit the reject path because after incrementing, `window_count` becomes 5 which equals the limit. But the store already returns the *pre-increment* count in our model. Let me clarify the semantics:

The store's `increment_and_count` returns the count AFTER its own atomic increment. So `(0, 4)` means 4 entries exist including the one just inserted. At limit=5, 4 is fine — `4 < 5`, so it passes with `remaining = 5 - 4 = 1`. Wait — that gives `remaining=1` but we expect `remaining=0`.

I need to reconsider. The test `(0, 4)` represents the state *after* the atomic increment by the store. So if limit=5 and count=4, we have `remaining = 5 - 4 = 1`. That's wrong for the "at boundary" case where we want `remaining=0`.

**Fix:** The comparison needs to be `< self._limit - window_count` and remaining should reflect the final count:

```python
    async def record(self, key: str) -> TokenBucketState:
        now = self._clock()
        total, window_count = await self._store.increment_and_count(key, self._window, now)
        
        if window_count > self._limit:
            return TokenBucketState(
                remaining=0,
                limit=self._limit,
                retry_after_seconds=self._window.total_seconds(),
            )

        return TokenBucketState(
            remaining=self._limit - window_count,
            limit=self._limit,
            retry_after_seconds=None,
        )
```

**What changed in production code:**
- Comparison changed from `>=` to `>` — the limit-th request is allowed
- Remaining is computed as `limit - window_count` (not `limit - window_count - 1`) since the increment happened inside the store
- This single line change fixes both the boundary and over-boundary tests simultaneously

### Refactor notes

- **Changed the comparison from `>=` to `>`** — this was the subtle bug from Increment 2. The store does the increment atomically, so we compare the *post-increment* count against `limit`, not `limit - 1`.
- The formula `remaining = limit - window_count` is cleaner and correctly yields `remaining=0` when at the limit.
- Both tests share the same assertion pattern for `retry_after_seconds` — could extract a helper if it grows.

### GREEN — Make the check-and-increment truly sequential in the limiter

For a purely in-process test, we wrap the critical section in an asyncio lock at the limiter level:

```python
class SlidingWindowRateLimiter:
    def __init__(self, store, limit=10, window=timedelta(seconds=60), clock=None):
        self._store = store
        self._limit = limit
        self._window = window
        self._clock = clock or (lambda: datetime.now(timezone.utc))
        self._locks: dict[str, asyncio.Lock] = {}
        self._global_lock = asyncio.Lock()

    async def _get_lock(self, key: str) -> asyncio.Lock:
        async with self._global_lock:
            if key not in self._locks:
                self._locks[key] = asyncio.Lock()
            return self._locks[key]

    async def record(self, key: str) -> TokenBucketState:
        now = self._clock()
        cutoff = now - self._window
        await self._store.cleanup_expired(key, cutoff)
        
        lock = await self._get_lock(key)
        async with lock:
            total, window_count = await self._store.increment_and_count(key, self._window, now)
            
            if window_count > self._limit:
                return TokenBucketState(
                    remaining=0,
                    limit=self._limit,
                    retry_after_seconds=self._window.total_seconds(),
                )

            return TokenBucketState(
                remaining=self._limit - window_count,
                limit=self._limit,
                retry_after_seconds=None,
            )
```

**What changed:** Added per-key locks. The `_global_lock` protects the lock dictionary; the per-key lock serializes all operations on the same rate-limit key.

### Refactor notes

- **Per-key locking** means unrelated keys don't contend — "user:1" doesn't block "user:2"
- For a distributed system, the per-key lock is replaced by a Redis `SETNX` / RedLock — the interface stays identical, only the store changes. This is the key insight behind the `RateLimitStore` protocol: swapping backends doesn't touch the limiter logic
- Lock map leaks if keys are never reused — a production impl would TTL the locks or use LRU eviction. Documented as a known limitation

```python
class FakeRedisStore(RateLimitStore):
    """Simulates Redis ZADD/ZRANGEBYSCORE atomicity with a thread-local lock."""
    def __init__(self):
        self._data: dict[str, list[tuple[float, str]]] = {}  # (timestamp, member_id)
        self._mutex = asyncio.Lock()

    async def increment_and_count(self, key: str, window: timedelta,
                                   now: datetime) -> tuple[int, int]:
        async with self._mutex:
            cutoff_ts = now.timestamp() - window.total_seconds()
            if key not in self._data:
                self._data[key] = []
            member = f"{now.isoformat()}:{id(self)}"
            self._data[key].append((now.timestamp(), member))
            window_entries = [e for e in self._data[key] if e[0] > cutoff_ts]
            self._data[key] = window_entries
            return (len(self._data), len(window_entries))

    async def cleanup_expired(self, key: str, cutoff: datetime) -> int:
        async with self._mutex:
            if key not in self._data:
                return 0
            cutoff_ts = cutoff.timestamp()
            original_len = len(self._data[key])
            self._data[key] = [e for e in self._data[key] if e[0] >= cutoff_ts]
            return original_len - len(self._data[key])

    await limiter.record("k")
    result = await limiter.record("k")
    assert result.retry_after_seconds is not None
    
    tick(6)
    result = await limiter.record("k")
    assert result.remaining == 1
```

- **Interface segregation:** The `RateLimitStore` protocol defines the contract. A real `RedisStore` replaces `FakeRedisStore` in production with zero changes to `SlidingWindowRateLimiter`
- The store handles its own atomicity (mutex for in-process simulation; `MULTI/EXEC` for real Redis)
- The limiter remains dumb: it asks the store, reads the result, decides. No duplicated logic

```python
import asyncio
from dataclasses import dataclass
from datetime import datetime, timedelta, timezone
from typing import Protocol


@dataclass(frozen=True)
class TokenBucketState:
    remaining: int
    limit: int
    retry_after_seconds: float | None = None


class RateLimitStore(Protocol):
    async def increment_and_count(self, key: str, window: timedelta,
                                   now: datetime) -> tuple[int, int]:
        """Atomically append one entry and return (db_total_keys, window_entry_count)."""
        ...

    async def cleanup_expired(self, key: str, cutoff: datetime) -> int:
        """Remove entries before cutoff. Returns number deleted."""
        ...


class SlidingWindowRateLimiter:
    def __init__(self, store: RateLimitStore, limit: int = 10,
                 window: timedelta = timedelta(seconds=60),
                 clock=None):
        self._store = store
        self._limit = limit
        self._window = window
        self._clock = clock or (lambda: datetime.now(timezone.utc))
        self._locks: dict[str, asyncio.Lock] = {}
        self._global_lock = asyncio.Lock()

    async def _get_key_lock(self, key: str) -> asyncio.Lock:
        async with self._global_lock:
            if key not in self._locks:
                self._locks[key] = asyncio.Lock()
            return self._locks[key]

    async def record(self, key: str) -> TokenBucketState:
        now = self._clock()
        cutoff = now - self._window
        await self._store.cleanup_expired(key, cutoff)

        lock = await self._get_key_lock(key)
        async with lock:
            total, window_count = await self._store.increment_and_count(
                key, self._window, now
            )

            if window_count > self._limit:
                return TokenBucketState(
                    remaining=0,
                    limit=self._limit,
                    retry_after_seconds=self._window.total_seconds(),
                )

            return TokenBucketState(
                remaining=self._limit - window_count,
                limit=self._limit,
                retry_after_seconds=None,
            )

    async def allow(self, key: str) -> TokenBucketState:
        """Non-mutating inspection: shows current state without consuming a slot."""
        now = self._clock()
        cutoff = now - self._window
        _, window_count = await self._store.increment_and_count(key, self._window, now)
        # Don't actually insert — but store interface requires the call.
        # In a real implementation, `allow` would use a separate query method.
        # For now this is a simplification.
        remaining = max(0, self._limit - window_count)
        return TokenBucketState(
            remaining=remaining,
            limit=self._limit,
            retry_after_seconds=None if remaining > 0 else self._window.total_seconds(),
        )
```

> **Note:** The `allow()` method above is a convenience that shares the store interface. A cleaner design adds `count_active(key, window, now)` to `RateLimitStore` so `allow` doesn't do a phantom insert. This is a deliberate trade-off: simplicity vs. pure read. Adding `count_active` to the protocol is a backward-compatible change (it's a new optional method with a default no-op).

## Architectural Decisions & Trade-offs

**Why the store abstraction matters most:**
The `RateLimitStore` protocol is the distributed-safety mechanism. A local `InMemoryStore` uses `asyncio.Lock`. A production `RedisStore` wraps everything in `EVAL` with Lua scripts:

```lua
-- Redis Lua script for atomic increment_and_count
local cutoff = tonumber(redis.call('GET', KEYS[1] .. ':cutoff')) or 0
redis.call('ZREMRANGEBYSCORE', KEYS[1], '-inf', cutoff)
redis.call('ZADD', KEYS[1], ARGV[1], ARGV[2])
return redis.call('ZCARD', KEYS[1])
```

Both present the identical async interface — the limiter never knows which backend it talks to.

**Known limitations (acceptable for v1):**
- `retry_after_seconds` returns the full window duration, not a precise countdown. A refinement queries the oldest entry's timestamp within the window.
- The per-key lock map (`self._locks`) never evicts dead entries. Acceptable for bounded key populations; problematic for keys like UUID tokens. A TTL-ed cache or periodic cleanup loop would fix this.
- `allow()` (non-mutating) currently shadows the store's increment. A proper `count_active()` read-only method should be added to the protocol for a clean separation.
