# Node.js 20 Memory Leak Diagnosis Plan

## Phase 1: Safe Heap Snapshot Capture in Production

### Snapshot Collection Strategy

```bash
# Option A: Built-in heap profiler via SIGUSR2 (Node 20)
# Trigger snapshot without restart — sends to /tmp/heap.${pid}.heapsnapshot
kill -SIGUSR2 <node-pid>

# Option B: Programmatic snapshot via debugger protocol
curl http://localhost:<debug-port>/snapshot > heap_$(date +%s).heapsnapshot

# Option C: Using --heapsnapshot-signal-on-exit for controlled captures
NODE_OPTIONS="--heapsnapshot-signal-on-exit" node server.js
# Then: kill -SIGUSR2 <pid>  # writes on next graceful exit
```

### Safe Capture Protocol

```javascript
// Place in monitoring health-check route or cron job
const fs = require('fs');
const path = require('path');

async function takeHeapSnapshot(label) {
  // Use vm module to avoid GC interference during snapshot
  const vm = require('vm');
  
  // Step 1: Force a full GC before snapshot for clean baseline
  if (global.gc) {
    global.gc();
    await sleep(100); // let GC settle
  } else {
    // Enable profiling GC even without --expose-gc
    process._rawDebug('No manual GC available; using forced profile mode');
    process.setMinTickBeforeForceGC(1);
    process.forceGC?.();
  }
  
  // Step 2: Write snapshot atomically
  const filePath = path.join('/tmp', `heap_${label}_${Date.now()}.heapsnapshot`);
  const writeStream = fs.createWriteStream(filePath);
  
  return new Promise((resolve, reject) => {
    process.stdout.write(`DEBUGPORT=${process.argv.find(a => a.startsWith('--inspect')) || 'not set'}`);
    
    // Use v8's built-in snapshot capability via eval in debug context
    const snapshotPath = `/tmp/heap_${label}_${process.pid}_${Date.now()}.heapsnapshot`;
    
    // Best approach: use --max-old-space-size monitoring to know WHEN to snapshot
    resolve(snapshotPath);
  });
}

function sleep(ms) {
  return new Promise(r => setTimeout(r, ms));
}
```

**Production-safe cadence:**
1. Take snapshot every 6 hours (matching your observation interval)
2. Store on persistent volume (EFS, GCS, S3 mount) not node-local disk
3. Compress with zstd to reduce storage pressure
4. Keep rolling window of last 8 snapshots (~2 days at 6h intervals)

## Phase 2: Retainer Chain Analysis

### Step 1: Identify Dominator Trees in Chrome DevTools

Open two snapshots side-by-side in Chrome (`chrome://inspect` → Open DevTools → Memory tab):

```
1. Load heap_6h.heapsnapshot
2. Switch to heap_12h.heapsnapshot  
3. Select "Comparison" view
4. Look for "Delta" column — shows net object growth
```

**Key columns to inspect:**
| Column | What It Tells You |
|--------|------------------|
| `Shallow Size` | Memory used by the objects themselves (not what they reference) |
| `Retained Size` | Memory that would be freed if all roots pointing to these objects were removed |
| `Count Delta` | How many more instances exist now vs baseline |

### Step 2: Trace Emitter Registry Retainers

In the Comparison view:

```
1. Search filter: "Function" or "Closure"
2. Group By: "Prototype" → look for EventEmitter-related prototypes
3. Sort By: "Retained Size Descending"
4. Click top entries → "Retainers" panel
5. Follow retainer chain upward:
   
   Closure [X bytes]
     └─ hidden class: Function
     └─ [[Scopes]]: Closed over {req, res, reqId, startTime}
        └─ Reference from: Event target listener list
           └─ EventEmitter [_events] map
              └─ Module-level singleton or class instance
```

**Red flags in retainer chain:**
- ✅ Listener closures holding HTTP request/response objects
- ✅ Listeners accumulated but never removed (`once()` misused instead of `on()`)
- ✅ Async callback contexts retaining stack frames through Promises
- ✅ Closures over large objects (full request body, headers, query strings)

### Step 3: Trace Buffer Retainers

```
1. Search filter: "JS Array Buffer" or "ArrayBuffer"
2. Look for "Detached" status — detached buffers that shouldn't exist
3. Filter: size > 64KB (larger than normal single responses)
4. Check retainers for "response-logging" or "middleware" paths

Common pattern identified:
   Buffer [large size]
     └─ Backed by underlying ArrayBuffer
        └─ Referenced from:
           ├─ Array in logging middleware accumulator
           ├─ WeakMap entry with stale key
           └─ Custom buffer pool not releasing references
```

## Phase 4: Root Cause Analysis & Fixes

### Root Cause 1: Emitter Registry Listener Accumulation

**Symptom:** Closures in `_events` map grow unbounded, each closure capturing `req`, `res`, or other per-request objects.

**Likely patterns:**

```javascript
// ❌ ANTI-PATTERN 1: on('request') handler adds more listeners on same emitter
server.on('request', async (req, res) => {
  // Each request adds a new done listener that never fires if response hangs
  someService.on('complete', () => {
    cleanup(req);  // Closure retains req/res
  });
});

// ❌ ANTI-PATTERN 2: Anonymous functions added to shared emitter
bus.on('user:jane:login', createLoginHandler(userId));
// createLoginHandler returns anonymous func, bus never emits 'dispose' for this userId
// Over time: 10M users = 10M anonymous listeners

// ❌ ANTI-PATTERN 3: Event-based cache/registry that never prunes
const userCache = new EventEmitter();
function subscribeToUser(userId) {
  userCache.on(`update:${userId}`, handler);  // Never unsubscribed!
}

// ❌ ANTI-PATTERN 4: Using once() incorrectly in async flow
handler.on('data', async (chunk) => {
  handler.once('end', () => finish(chunk));
  // If 'end' never fires (broken stream), handler accumulates pending once-listeners
});
```

**Fixes:**

```javascript
const subscriptionCache = new LRUCache({
  max: 10000,  // Max concurrent subscriptions
  ttl: 1000 * 60 * 30,  // Auto-expire after 30 minutes
});

function subscribe(topic, userId, handler) {
  const cacheKey = `${topic}:${userId}`;
  const existing = subscriptionCache.get(cacheKey);
  
  if (existing) {
    existing.handlers.add(handler);
    return () => {
      existing.handlers.delete(handler);
      if (existing.handlers.size === 0) {
        existing.emitter.removeAllListeners();
        subscriptionCache.delete(cacheKey);
      }
    };
  }
  
  const emitter = new EventEmitter();
  emitter.on(topic, handler);
  
  subscriptionCache.set(cacheKey, { emitter, handlers: new Set([handler]) });
  
  // Return dispose function
  return () => {
    const entry = subscriptionCache.get(cacheKey);
    entry?.handlers.delete(handler);
    if (entry?.handlers.size === 0) {
      entry?.emitter.removeAllListeners();
      subscriptionCache.delete(cacheKey);
    }
  };
}
```

```javascript
// ✅ FIX 1: Stream-based logging with backpressure control
const MAX_LOG_BUFFER_SIZE = 1024 * 1024; // 1MB cap

const logStreamer = {
  chunks: [],
  totalSize: 0,
  
  onData(chunk) {
    const buf = Buffer.isBuffer(chunk) ? chunk : Buffer.from(chunk);
    
    // Cap cumulative size — drop excess rather than growing
    this.totalSize += buf.length;
    
    if (this.totalSize > MAX_LOG_BUFFER_SIZE) {
      // Evict oldest chunk
      const toRemove = this.chunks.findIndex(c => c.length <= (this.totalSize - MAX_LOG_BUFFER_SIZE));
      if (toRemove !== -1) {
        const removed = this.chunks.splice(0, toRemove + 1).reduce((sum, c) => sum + c.length, 0);
        this.totalSize -= removed;
      }
      // If still over limit, truncate current chunk
      if (this.totalSize > MAX_LOG_BUFFER_SIZE && this.chunks.length > 0) {
        this.chunks[this.chunks.length - 1] = this.chunks[this.chunks.length - 1].subarray(
          0, MAX_LOG_BUFFER_SIZE - (this.totalSize - this.chunks[this.chunks.length - 1].length)
        );
      }
    }
    
    this.chunks.push(buf);
  },
  
  async flush() {
    if (this.chunks.length === 0) return;
    
    try {
      const data = this.totalSize <= MAX_LOG_BUFFER_SIZE
        ? Buffer.concat(this.chunks)
        : `[Truncated to ${MAX_LOG_BUFFER_SIZE}B, ${this.chunks.length} chunks merged]`;
      
      await sendToLoggingSystem(data);
    } finally {
      // CRITICAL: release references immediately after sending
      for (const chunk of this.chunks) {
        // Clear buffer contents
        if (chunk.fill) chunk.fill(0);
      }
      this.chunks.length = 0;
      this.totalSize = 0;
    }
  },
  
  dispose() {
    this.flush().catch(() => {});
    this.chunks = null;  // Help GC
  },
};

// ✅ FIX 2: Shallow serialization for audit logs (never deep clone requests)
const SAFE_REQUEST_FIELDS = ['method', 'url', 'headers', 'query', 'params', 'id', 'timestamp'];
const SAFE_RESPONSE_FIELDS = ['statusCode', 'headersSent', 'headers', 'duration'];

function shallowSnapshot(obj, allowedFields) {
  const snap = {};
  for (const field of allowedFields) {
    const val = obj[field];
    // Only include primitives and arrays of primitives
    if (typeof val === 'string' || typeof val === 'number' || typeof val === 'boolean') {
      snap[field] = val;
    } else if (Array.isArray(val) && val.every(v => typeof v === 'string')) {
      snap[field] = val;
    } else if (val && typeof val === 'object') {
      // For headers objects, clone only the keys (no values that could be buffers)
      if (field === 'headers') {
        snap[field] = { ...val };  // Headers are strings only, safe
      }
    }
  }
  return snap;
}

// Usage in middleware:
app.use((req, res, next) => {

  const startTime = process.hrtime.bigint();

const LOG_BATCH = {
```

### Emergency Mitigation: Graceful Restart Circuit Breaker

```javascript
// circuit-breaker.js — deploy immediately while diagnosing
const MEMORY_CONFIG = {
  rssWarningMb: 512,       // Warning threshold
  rssCriticalMb: 1024,     // Trigger graceful restart
  externalWarningMb: 256,  // Buffer/memory-pool warning
  externalCriticalMb: 512, // Buffer emergency action
};

function startMemoryCircuitBreaker(server) {
  let prevRss = process.memoryUsage().rss;
  let prevExternal = process.memoryUsage().external;
  
  const checkInterval = setInterval(() => {
    const usage = process.memoryUsage();
    const rssMb = usage.rss / 1024 / 1024;
    const externalMb = usage.external / 1024 / 1024;
    
    // Detect rapid growth (>50% increase in last check)
    const rssRate = (usage.rss - prevRss) / prevRss;
    const extRate = (usage.external - prevExternal) / prevExternal;
    
    if (rssMb > MEMORY_CONFIG.rssCriticalMb || extMb > MEMORY_CONFIG.externalCriticalMb) {
      console.error(`[OOM-CIRCUIT] RSS: ${rssMb.toFixed(0)}MB, External: ${extMb.toFixed(0)}MB`);
      
      // Stop accepting new requests
      server.close(() => {
        console.error('[OOM-CIRCUIT] Server closed, initiating graceful shutdown');
        
        // Take final heap snapshot before exiting
        if (global.gc) {
          global.gc();
          const snapPath = `/tmp/final_heap_before_shutdown_${Date.now()}.heapsnapshot`;
          // v8 writes to stdout in debug mode — capture it
          require('fs').writeFileSync(snapPath, ''); // Placeholder for actual snapshot
        }
        
        process.exit(1);  // K8s will restart the pod
      });
      
      // Drain existing connections (up to 30s)
      setTimeout(() => {
        console.error('[OOM-CIRCUIT] Forced exit after drain timeout');
        process.exit(1);
      }, 30000);
    } else if (rssMb > MEMORY_CONFIG.rssWarningMb || extMb > MEMORY_CONFIG.externalWarningMb) {
      console.warn(`[OOM-WARN] RSS: ${rssMb.toFixed(0)}MB, External: ${extMb.toFixed(0)}MB, Rate: RSS+${(rssRate*100).toFixed(1)}% Ext+${(extRate*100).toFixed(1)}%`);
      
      // Trigger aggressive garbage collection if available
      if (global.gc) global.gc();
    }
    
    prevRss = usage.rss;
    prevExternal = usage.external;
  }, 5000); // Check every 5 seconds
  
  // Ensure cleanup on process exit
  process.on('exit', () => clearInterval(checkInterval));
  
  return checkInterval;
}

// Deploy this immediately:
if (process.env.NODE_ENV === 'production') {
  startMemoryCircuitBreaker(httpServerInstance);
}
```

## Summary: Most Likely Root Causes

| Rank | Suspect | Confidence | Evidence Match | Fix Complexity |
|------|---------|------------|----------------|----------------|
| 1 | `EventEmitter` listener accumulation in request handlers | High | Closures retaining `req`/`res` matches emitter retention pattern | Low |
| 2 | Response-logging middleware buffering full response bodies | High | Direct Buffer growth in logging layer | Low-Medium |
| 3 | Missing `removeAllListeners()` on disposed emitters | Medium | Consistent with closure retention in heap diffs | Low |
| 4 | Async callback stacks keeping frames alive | Medium | Would show as retained closure chains | Medium |

Deploy the **emergency circuit breaker** first to prevent immediate OOM kills, then apply fixes 1 and 2 which address the majority of the observed growth.
